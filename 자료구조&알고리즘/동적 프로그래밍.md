
동적 프로그래밍(Dynamic Programming)은 큰 문제를 여러 부분 문제로 나누고, 부분 문제의 결과를 저장하여 중복 계산을 피하면서 그 결과를 이용해 전체 문제의 답을 구하는 알고리즘 설계 기법
**조건**
- 중복 부분 문제 구조 : “같은 작은 문제를 여러 번 계산하게 되는가?”
- 최적 부분 문제 구조 : “작은 문제의 최적해를 이용해서 큰 문제의 최적해를 만들 수 있는가?”

[[재귀]]를 사용할 때 불필요한 재귀 호출을 피하는 것이 중요하다. 어떤 때에는 동일한 재귀 함수를 여러차례 호출하는 경우도 있을 수 있다. (하위 문제 중첩)
**동적 프로그래밍**은 하위 문제가 중첩되는 재귀 문제를 최적화하는 절차다.

>[!note]+ "동적"이라는 말에 너무 의미를 두지 말자, 로직과 큰 연관이 없이 지어진 이름이다.
> **리처드 벨만이 1950년대 다단계 의사결정 문제를 연구하면서 만든 용어로, `Dynamic`은 다단계적·시간에 따라 변하는 특성을, `Programming`은 계획·의사결정이라는 의미를 담고 있다.**


### 동적 프로그래밍 기법

#### 메모이제이션(memoization)
한번 연산한 함수 결과값을 저장해놓고 이후 호출 부턴 추가 연산 없이 찾아서 사용
```java
public class MemoizationExample {

    static long[] memo;

    public static long fibonacci(int n) {
        // 이미 계산한 값이면 바로 반환
        if (memo[n] != -1) {
            return memo[n];
        }

        // 계산한 결과를 저장
        memo[n] = fibonacci(n - 1) + fibonacci(n - 2);
        return memo[n];
    }

    public static void main(String[] args) {
        int n = 50;

        memo = new long[n + 1];

        // 아직 계산하지 않았다는 의미로 -1 설정
        for (int i = 0; i <= n; i++) {
            memo[i] = -1;
        }

        // 초기값
        memo[0] = 0;
        memo[1] = 1;

        System.out.println(fibonacci(n));
    }
}
```

> 이 방식은 추가적인 메모리 공간이 필요하고, 재귀 함수 호출로 인한 시스템 호출 스택을 사용하므로 실행 속도 저하 또는 오버 플로우가 발생할 수 있다.
> 아래 상향식으로 이를 보완할 수 있다.

#### 상향식
별건 아니고 그저 같은 문제를 재귀 대신 (루프 같은) 다른 방식으로 해결하는 것
```java
public static long fibonacci(int n) {
    if (n <= 1) {
        return n;
    }

    long prev2 = 0;
    long prev1 = 1;

    for (int i = 2; i <= n; i++) {
        long current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }

    return prev1;
}
```


재귀가 매우 직관적이지 않은 이상 일반적으로 상향식을 택하는 편이 더 낫다. 재귀가 더 직관적이면 재귀를 사용하되 메모이제이션으로 빠르게 만들어야 한다.

## DP 적용 접근 방법
- 문제의 부분 문제 구조를 파악하라
	전체 문제를 더 작은 하위 문제들로 나눈다.
- 문제의 해를 재귀적 관계(점화식)로 정의하라
	작은 부분 문제의 해를 바탕으로 더 큰 문제의 해를 정의한다. (점화식 도출)
- 상향식으로 부분 문제의 해를 계산하라
	가장 작은 부분 문제부터 해를 구한 뒤 테이블에 저장한다.
	테이블에 저장되어 있는 부분 문제의 해를 이용하여 점차적으로 상위 부분 문제의 해를 구한다.


## **대표 문제(0-1 Knapsack)**
*knapsack = 배낭, 자루*
`N`개의 물건이 있고, 각 물건마다 다음 정보가 주어진다.
배낭에는 최대 `W`만큼의 무게만 담을 수 있다.
각 물건은 **최대 한 번만 선택할 수 있을 때**, 배낭의 무게 제한을 넘지 않으면서 얻을 수 있는 **가치의 최댓값**을 구하는 문제다.

### 2차원 DP (로직 이해용)
```java

import java.io.*;
import java.util.*;

public class Main{
	public static void main(String[] args) throws Exception{
		BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
		StringTokenizer st = new StringTokenizer(br.readLine());
		
		int N = Integer.parseInt(st.nextToken());
		int W = Integer.parseInt(st.nextToken());
		
		int[] weight = new int[N + 1];
		int[] value = new int[N + 1];
		
		// 물건 입력
		for(int i = 1; i <= N; i++){
			st = new StringTokenizer(br.readLine());
			
			weight[i] = Integer.parseInt(st.nextToken());
			value[i] = Integer.parseInt(st.nextToken());
		}
		/*
		 * dp[i][w]
		 * 1 ~ i번 물건까지 고려했을 때 ( 1 ~ i번 물건을 모두 사용할 수도 , 부분만 사용할 수도 있음)
		 * 배낭 최대 무게가 w인 경우의 최대 가치
		 */
		 int[][] dp = new int[N + 1][W + 1];
		 
		 // 물건을 하나씩 고려
		 for(int i = 1; i <= N; i++){
			 // 배낭의 최대 허용 무게
			 for(int w = 0; w <= W; w++){
				 // 현재 물건을 넣을 수 없는 경우
				 if(weight[i] > w){
					 // 현재 물건 없이 직전 단계까지 사용한 물건만 넣을 수 있음
					 dp[i][w] = dp[i - 1][w];
				 }else{
					 // 현재 물건을 넣지 않는 경우
					 int notTake = dp[i - 1][w];
					 // 현재 물건을 넣는 경우
					 int take = dp[i - 1][w - weight[i]] + value[i];
					 
					 // 둘 중 더 가치가 큰 선택
					 dp[i][w] = Math.max(notTake, take);
				 }
			 }
		 }
		 System.out.println(dp[N][W]);
	}
}
```
>[!question]+ 현재 물건을 넣을 수 있는 경우, 물건을 넣는게 무조건 가치가 높은거 아닌가?
>현재 물건을 넣는 경우에는 남은 용량에서 이전 물건들로 만들 수 있는 최대 가치에 현재 물건의 가치를 더한다. 이때 현재 물건의 무게 때문에 기존에 포함될 수 있었던 물건 일부를 포기해야 할 수 있으므로, 반드시 더 큰 가치가 되는 것은 아니다.

### 1차원 DP (공간 복잡도 줄임)
```java
import java.io.*; 
import java.util.*;

public class Main{
	public static void main(String[] args) throws Exception{
		BufferedReader br = new BufferedReader(new InputSreamReader(System.in));
		StringTokenizer st = new StringTokenizer(br.readLine());
		
		int N = Integer.parseInt(st.nextToken());
		int W = Integer.parseInt(st.nextToken());
		
		int[] weight = new int[N];
		int[] value = new int[N];
		
		for(int i = 0; i<N; i++){
			st = new StringTokenizer(br.readLine());
			weight[i] = Integer.parseInt(st.nextToken());
			value[i] = Integer.parseInt(st.nextToken());
		}
		
		// dp[w] = 무게 한도가 w일 때 얻을 수 있는 치대 가치
		int[] dp = new int[W+1];
		
		for(int i = 0; i < N; i++){
			// 뒤에서부터 탐색해야함
			for(int w = W; w >= weight[i]; w--){
				dp[w] = Math.max(dp[w], dp[w-weight[i]] + value[i]);
			}
		}
		System.out.println(dp[W]);
	}
}
```

>[!question]+ 왜? 뒤에서부터 탐색해야 할까?
>만약, 앞에서부터 탐색한다면 같은 물건이 2번 사용됨 처리가 될 수 있기 때문이다.
>ex :
>```
>dp[3] = dp[0] + value[3] // dp[3] 먼저 처리했다고 가정
>...
>dp[6] = dp[3] + value[3] // 같은 물건을 2번 넣은 꼴이 된다.
>```


## 대표 문제 유형

이항 계수 구하기
```
combi(n,k)
	IF n==k or k==0 : RETURN 1
	ELSE : RETURN combi(n-1, k-1) + combi(n-1,k)
```

```
bino(n,k)
	B[][]
	FOR i in 0 -> n
		FOR j in 0 -> minimum(i,k)
			IF j = 0 OR j = i
				B[i][j] <- 1
			ELSE
				B[i][j] <- B[i-1][j-1] + B[i-1][j]
	RETURN B[n][k]
```

동전 거스름돈 구하기
1원, 4원, 6원이 있을 때 8원을 거슬러 주려면 최소 몇 개의 동전이 필요한가?
그리디 - 6원, 1원,1원 : 3개
최적 - 4원, 4원 : 2개
즉, 그리디가 항상 최적해를 보장하지 않는다. 
DP로 푼다면?
1원 동전 + 7원에 대한 최적해
	7원에 대한 최적해 = 1원 동전 + 6원에 대한 최적해, 4원 동전 + 3원에 대한 최적해, 6원 동전 + 1원에 대한 최적해 ... 로 쪼갤 수 있음
4원 동전 + 4원에 대한 최적해
6원 동전 + 2원에 대한 최적해

이 경우에도 상향식으로 하면 더 작은 단위 동전의 최적해부터 쌓아 올라갈 수 있음.

## 동적 계획법 vs 분할 정복

[[분할 정복]]과 동적계획법은 모두 큰 문제를 작은 부분 문제로 나누어 해결한다는 공통점이 있다.
분할정복은 부분 문제들이 서로 **독립적**이며, 각 부분 문제를 재귀적으로 해결한 뒤 그 결과를 결합해서 전체 문제를 해결한다. 대표적으로 [[Merge Sort]], [[Quick Sort]]가 있다. 

반면 동적 계획법은 부분 문제들이 서로 중복되거나 의존 관계를 가지며, 같은 부분 문제를 여러번 계산하지 않도록 결과를 저장해서 재사용한다. 따라서 분할정복은 주로 위에서 아래로 문제를 쪼개는 방식이고, DP는 작은 부분 문제의 해를 바탕으로 더 큰 문제의 해를 만들어가는 방식으로 이해할 수 있다.
