aka. 해시, 맵, 해시 맵, 딕셔너리, 연관 배열 등

배열처럼 처음부터 하나씩 찾는 것이 아니라 **해시를 이용해서 찾을 위치를 바로 좁히기 때문에**, 충돌이 심하지 않은 일반적인 경우 조회 시간 복잡도는 **평균 O(1)** 이다.

키가 아닌 값을 검색하려고 한다면 해시 테이블 내 모든 키/값 쌍을 검색해야 하기에 배열과 마찬가지로 **O(n)** 이 걸린다.

각 키는 해시 테이블 내에서 유니크하다.

해시 테이블 생성 및 값 추가 과정
1. 해시 테이블 생성 
	```java
	HashMap<String,Integer> map = new HashMap<>();
	```
	내부적으로 데이터를 저장할 버킷 배열을 사용할 준비
2. 값 추가 요청
	```java
	map.put("apple",100);
	```
3. 키의 해시값 계산
	```
	"apple"
	   ↓
	hashCode()
	   ↓
	해시값 생성
	```
4. 해시값으로 버킷 위치 결정
	```
	해시값
	  ↓
	버킷 index 계산
	  ↓
	table[index]
	```
5. 해당 버킷에 데이터 저장 (정확하게는 노드의 참조값 저장)
```
table[3]
  ↓
[ key="apple", value=100 ]
```
6. 같은 위치에 데이터가 이미 있다면 충돌 처리
	```
	"apple" → index 3
	"orange" → index 3
	
	// 같은 버킷 안에서 여러 노드를 관리합니다.
	table[3]
	    ↓
	[apple, 100]
	    ↓
	[orange, 200]
	```
7. 데이터가 너무 많아지면 배열 확장
	저장된 데이터가 일정 수준을 넘으면 더 큰 버킷 배열을 만들고 데이터를 새 위치에 다시 배치한다.


해시 테이블 값 룩업 과정
1. 찾고 싶은 key 전달 ("apple")
2. key의 해시값 계산
3. 해시값으로 버킷 인덱스 계산
4. 해당 버킷으로 이동
5. 버킷 안에서 key 비교
	충돌 때문에 여러 데이터가 있을 수 있으므로 실제 key가 "apple"인지 확인
6. 일치하는 key의 value 반환



극단적으로 한 셀에 모든 값이 충돌이 난다면 사실상 룩업 성능은 **O(n)** 이다.
	연결된 노드들을 선형 검색해야하기 때문에

해시 테이블은 다음 세 요인에 따라 효율성이 정해진다.
- 해시 테이블에 얼마나 많은 데이터를 저장하는가? 
	너무 많은 데이터 저장시 충돌이 잦아짐
- 해시 테이블에 얼마나 많은 셀을 쓸 수 있는가?
	너무 적은 셀을 사용 가능하다면 충돌이 잦아짐
- 어떤 해시 함수를 사용하는가?
	좋은 해시 함수를 사용해야 셀에 골고루 데이터 분포할 수 있음
