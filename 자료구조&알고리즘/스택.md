
스택이 데이터를 저장하는 방법은 [[배열]]과 같다. 즉, 단순히 원소들의 리스트다. 다만 한 가지, 스택에는 다음과 같은 세 가지 제약이 있다.
- 데이터는 스택의 끝에만 삽입 가능
- 데이터는 스택의 끝에서만 삭제 가능
- 스택의 마지막 원소만 읽을 수 있음

>[!note]
>배열은 대부분 프로그래밍 언어에 내장되어있고 컴퓨터 메모리와 직접 상호작용을 하지만 스택은 **추상 데이터 타입**이므로 배열을 쓰든 다른 내장 데이터 구조를 쓰든 중요하지 않다.

어차피 배열을 내부 구조에서 사용하는데 왜 굳이 스택을 써야 하는 건가?
1. 제약을 같고 있기에 잠재적 버그를 막을 수 있다.
2. 스택과 같은 데이터 구조는 문제 해결하는 새로운 사고 모델을 제공한다.

스택은 마지막에 들어 온 데이터부터 먼저 처리해야 할 때 이상적이다.
