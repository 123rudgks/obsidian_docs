
[[정렬]]

## 개념

**Tim Sort**는 실제 데이터에 이미 존재하는 **부분적으로 정렬된 구간**을 활용하여 정렬하는  
**안정적인(Stable) 적응형(Adaptive) 정렬 알고리즘**이다.

Tim Sort는 다음 두 정렬 알고리즘의 장점을 결합한다.

- [[Insertion Sort]]
- [[Merge Sort]]

핵심 아이디어는 다음과 같다.

> 배열에서 이미 정렬되어 있는 연속 구간인 **Run**을 찾고,  
> 짧은 Run은 Binary [[Insertion Sort]]로 보완한 뒤,  
> 여러 Run을 [[Merge Sort]] 방식으로 병합한다.

---

## 왜 Tim Sort를 사용하는가?

실제 데이터는 완전히 무작위인 경우보다  
이미 어느 정도 정렬되어 있는 경우가 많다.

예를 들어:

```text
[1, 2, 3, 4, 7, 6, 8, 9, 10]
```

이 배열은 대부분 정렬되어 있다.

일반적인 [[Merge Sort]]는 입력 상태와 관계없이 배열을 계속 절반으로 나누지만,  
Tim Sort는 이미 정렬된 부분을 찾아 그대로 활용한다.

```text
[1, 2, 3, 4, 7]  [6, 8, 9, 10]
        Run                Run
```

따라서 이미 정렬되어 있거나 거의 정렬된 데이터에서 효율적이다.

---

## 핵심 구조

Tim Sort의 전체적인 흐름은 다음과 같다.

```text
원본 배열
    ↓
정렬되어 있는 연속 구간(Run)을 찾는다.
    ↓
너무 짧은 Run은 Binary Insertion Sort로 확장한다.
    ↓
여러 Run을 스택에 저장한다.
    ↓
Run의 크기를 고려하여 적절한 순서로 Merge한다.
    ↓
전체 배열 정렬 완료
```

---

# Run

## Run이란?

**Run**은 배열에서 이미 정렬되어 있는 연속된 구간이다.

예를 들어:

```text
[1, 3, 5, 7, 9]
```

은 하나의 오름차순 Run이다.

```text
[9, 7, 5, 3, 1]
```

은 내림차순 Run이다.

Tim Sort는 내림차순 Run을 발견하면 해당 구간을 뒤집어  
오름차순 Run으로 만든다.

```text
[9, 7, 5, 3, 1]

        ↓ reverse

[1, 3, 5, 7, 9]
```

즉 Tim Sort는 기존 배열에 이미 존재하는 정렬 상태를 재사용한다.

---

## Run 탐색 예시

다음 배열이 있다고 하자.

```text
[1, 3, 5, 7, 4, 2, 6, 8, 9]
```

앞에서부터 정렬 상태를 확인하면:

```text
[1, 3, 5, 7]
```

은 오름차순 Run이다.

그 다음:

```text
[4, 2]
```

는 내림차순이므로 뒤집어서:

```text
[2, 4]
```

로 사용할 수 있다.

마지막:

```text
[6, 8, 9]
```

도 하나의 오름차순 Run이다.

개념적으로는:

```text
[1, 3, 5, 7] [2, 4] [6, 8, 9]
      Run       Run       Run
```

과 같은 정렬된 구간들을 만든 뒤 병합한다.

# MinRun

## 왜 Run의 최소 크기가 필요한가?

Run이 너무 작으면 다음과 같이 작은 Run이 지나치게 많이 생길 수 있다.

```text
[1, 3] [2] [5, 7] [4] [6] ...
```

작은 Run이 너무 많으면 Merge 횟수가 많아지고 효율이 떨어질 수 있다.

그래서 Tim Sort는 **minRun**이라는 최소 Run 크기를 정한다.

발견한 Run의 길이가 minRun보다 작다면  
뒤의 원소들을 추가하여 일정 크기까지 확장하고 정렬한다.

예를 들어 개념적으로:

```text
발견한 Run

[1, 3, 5]

minRun = 5라고 가정
```

뒤쪽 원소를 포함해서:

```text
[1, 3, 5, 2, 4]
```

Binary [[Insertion Sort]]를 적용하면:

```text
[1, 2, 3, 4, 5]
```

라는 하나의 Run을 만들 수 있다.

> 실제 Tim Sort의 minRun 값은 배열 크기에 따라 계산된다.

---

# Binary Insertion Sort 사용

Tim Sort는 작은 구간을 정렬할 때  
일반적인 [[Insertion Sort]]보다 **Binary Insertion Sort**를 활용한다.

앞쪽 Run은 이미 정렬되어 있기 때문에  
새로운 값이 들어갈 위치를 [[이진 탐색]]으로 찾을 수 있다.

예를 들어:

```text
정렬된 구간
[2, 4, 6, 8]

삽입할 값
5
```

일반 Insertion Sort는 뒤에서부터 순차적으로 비교한다.

```text
8 > 5
6 > 5
4 < 5
```

Binary Insertion Sort는 이진 탐색으로 삽입 위치를 찾는다.

```text
[2, 4, 6, 8]
       ↑

5 < 6
→ 왼쪽 구간 탐색

5 > 4
→ 4와 6 사이에 삽입
```

결과:

```text
[2, 4, 5, 6, 8]
```

삽입 위치 탐색은 빨라지지만,  
배열 원소를 실제로 오른쪽으로 이동하는 비용은 여전히 필요하다.

---

# Run 병합

Run을 찾고 정리한 뒤에는  
여러 Run을 [[Merge Sort]]의 Merge 방식으로 합친다.

예를 들어:

```text
Run A = [1, 4, 7]
Run B = [2, 3, 8]
```

두 Run의 앞쪽 값을 비교하면서 작은 값을 차례대로 선택한다.

```text
1 vs 2 → 1
4 vs 2 → 2
4 vs 3 → 3
4 vs 8 → 4
7 vs 8 → 7
남은 8
```

결과:

```text
[1, 2, 3, 4, 7, 8]
```

즉 Tim Sort의 병합 자체는  
정렬된 두 구간을 합치는 [[Merge Sort]]의 핵심 아이디어를 사용한다.

---

# Run Stack

Tim Sort는 발견한 Run을 바로 무조건 병합하지 않고  
**스택(Stack)** 형태로 관리한다.

예를 들어 Run의 길이가:

```text
Run A : 100
Run B : 20
Run C : 20
```

이라고 하자.

큰 Run과 작은 Run을 무작정 병합하면  
큰 배열을 반복해서 복사해야 하는 비효율이 생길 수 있다.

따라서 Tim Sort는 Run의 크기를 확인하면서  
균형 잡힌 형태로 병합되도록 관리한다.

개념적으로:

```text
Run 발견

A
B
C

↓ 스택에 저장

[A, B, C]

↓ 크기 조건 확인

B + C 병합

[A, BC]

↓ 다시 조건 확인

필요하면 A + BC 병합
```

이렇게 Run의 크기를 고려하여 병합 순서를 결정한다.

> 실제 Tim Sort는 Run 길이에 대한 병합 조건(invariant)을 유지하면서  
> 병합이 지나치게 한쪽으로 치우치지 않도록 한다.

---

# Galloping Mode

Tim Sort에는 Merge를 더 빠르게 하기 위한  
**Galloping Mode**라는 최적화가 있다.

예를 들어 두 Run이 다음과 같다고 하자.

```text
A = [1, 2, 3, 4, 5, 6, 7]
B = [100, 101, 102]
```

일반적인 Merge라면:

```text
1 vs 100
2 vs 100
3 vs 100
4 vs 100
...
```

처럼 계속 하나씩 비교한다.

그런데 한쪽 Run의 값이 연속해서 계속 선택된다면  
Tim Sort는 다음과 같이 판단할 수 있다.

```text
A의 값이 계속 더 작다.
→ 하나씩 비교하지 말고
  한 번에 어느 범위까지 가져올 수 있는지 탐색
```

이때 지수적으로 탐색 범위를 늘린 뒤  
필요한 위치를 찾는 방식으로 여러 원소를 한꺼번에 처리한다.

이 최적화를 **Galloping**이라고 한다.

Tim Sort를 처음 이해할 때는 구현 방법까지 외우기보다:

> 한쪽 Run에서 값이 연속해서 선택될 때  
> 비교 횟수를 줄이기 위한 병합 최적화

정도로 이해하면 충분하다.

# Merge Sort와의 차이

[[Merge Sort]]는 배열의 현재 정렬 상태와 관계없이  
계속 절반으로 나눈다.

```text
Merge Sort

원본 배열
    ↓
절반으로 분할
    ↓
다시 절반으로 분할
    ↓
작은 배열부터 Merge
```

반면 Tim Sort는:

```text
Tim Sort

원본 배열
    ↓
이미 정렬된 Run 탐색
    ↓
짧은 Run은 Binary Insertion Sort로 보완
    ↓
Run을 적절한 순서로 Merge
```

즉 가장 큰 차이는:

> Tim Sort는 입력 데이터에 이미 존재하는 정렬 상태를 활용한다.

는 점이다.

---

# Insertion Sort와의 차이

[[Insertion Sort]]는 전체 배열을 앞에서부터 하나씩 확장하면서  
각 값을 알맞은 위치에 삽입한다.

Tim Sort는 Insertion Sort를 전체 배열에 적용하지 않는다.

대신:

```text
작은 Run
또는
minRun 크기까지 확장해야 하는 구간
```

에 Binary [[Insertion Sort]]를 사용한다.

즉 작은 구간에서 효율적인 삽입 정렬의 장점만 활용한다.

---

# 시간복잡도

Tim Sort는 입력 배열의 정렬 상태를 활용하는 **Adaptive Sort**이다.

이미 정렬된 배열에서는 하나의 큰 Run을 발견할 수 있으므로  
매우 적은 작업만 필요하다.

| 경우 | 시간복잡도 |
|---|---:|
| Best | O(N) |
| Average | O(N log N) |
| Worst | O(N log N) |

---

# 공간복잡도

Run을 Merge할 때 임시 저장 공간이 필요하다.

최악의 경우 추가 공간은:

```text
O(N)
```

수준이 필요할 수 있다.

---

# Stable Sort

Tim Sort는 **Stable Sort**이다.

Stable Sort란 같은 값을 가진 원소들의  
기존 상대적인 순서를 유지하는 정렬을 의미한다.

예를 들어:

```text
(김, 90)
(이, 80)
(박, 90)
```

점수 기준으로 오름차순 정렬하면:

```text
(이, 80)
(김, 90)
(박, 90)
```

같은 `90`점을 가진 `김`과 `박`의 기존 순서가 유지된다.

---

# Tim Sort의 흐름 예시

다음 배열이 있다고 하자.

```text
[1, 3, 5, 7, 2, 4, 6, 8]
```

먼저 이미 정렬된 Run을 찾는다.

```text
[1, 3, 5, 7] [2, 4, 6, 8]
      A              B
```

두 Run은 각각 이미 정렬되어 있다.

이제 두 Run을 Merge한다.

```text
A = [1, 3, 5, 7]
B = [2, 4, 6, 8]

1 vs 2 → 1
3 vs 2 → 2
3 vs 4 → 3
5 vs 4 → 4
5 vs 6 → 5
7 vs 6 → 6
7 vs 8 → 7
남은 8
```

결과:

```text
[1, 2, 3, 4, 5, 6, 7, 8]
```

즉 이미 정렬되어 있던 두 구간을 다시 정렬할 필요 없이  
Run으로 그대로 활용하여 병합할 수 있다.

---

# 특징

- [[Merge Sort]]와 [[Insertion Sort]]를 결합한 하이브리드 정렬
- 이미 정렬된 연속 구간인 Run을 활용
- 작은 구간은 Binary [[Insertion Sort]]를 사용
- 여러 Run을 크기에 따라 적절한 순서로 병합
- 거의 정렬된 데이터에서 효율적
- Stable Sort
- Adaptive Sort
- 최악의 경우에도 `O(N log N)` 보장
