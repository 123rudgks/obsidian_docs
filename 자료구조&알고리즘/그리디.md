# 그리디

그리디(Greedy) 알고리즘은

> **매 순간 현재 상황에서 가장 좋아 보이는 선택을 하는 방식**

이다.

하지만 매 순간 최선으로 보이는 선택을 했다고 해서 항상 전체 최적해가 되는 것은 아니다.

따라서 그리디 문제에서는

```text
현재의 선택을 해도 전체 최적해를 놓치지 않는가?
```

를 확인해야 한다.

## 특징

- 현재 단계에서 가장 좋은 선택을 한다.
- 일반적으로 이미 내린 선택을 다시 되돌리지 않는다.
- 모든 문제에서 최적해를 보장하지 않는다.
- 그리디 전략이 최적해를 보장한다는 근거가 필요하다.

## Greedy Choice Property

현재 단계의 그리디 선택을 포함하는 최적해가 존재해야 한다.

즉

```text
지금 가장 좋아 보이기 때문에 선택한다
```

가 아니라

```text
이 선택을 해도 최적해를 놓치지 않는다
```

는 성질이 있어야 한다.

## Optimal Substructure

전체 문제의 최적해가 부분 문제의 최적해를 포함하는 구조이다.

즉 현재 선택 이후 남은 문제 역시 같은 방식으로 최적으로 해결할 수 있어야 한다.

## 대표 문제 — Knapsack

그리디 적용 여부는 단순히 분할 가능 / 불가능만 보는 것이 아니라

> **현재의 최선 선택이 미래의 더 좋은 조합을 방해하지 않는가?**

를 봐야 한다.

- Fractional Knapsack → 물건을 쪼갤 수 있으므로 가치/무게 비율이 높은 것부터 선택해도 최적해 보장 → 그리디 가능
- 0-1 Knapsack → 현재 선택이 이후 더 좋은 조합을 막을 수 있음 → 일반적인 비율 그리디로는 최적해 보장 불가

0-1 Knapsack은 보통 [[동적 프로그래밍]]으로 해결한다.

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.util.Arrays;
import java.util.StringTokenizer;

public class Main {
    static class Item {
        int weight;
        int value;
        double ratio;

        Item(int weight, int value) {
            this.weight = weight;
            this.value = value;
            this.ratio = (double) value / weight;
        }
    }

    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());

        int N = Integer.parseInt(st.nextToken());
        int W = Integer.parseInt(st.nextToken());

        Item[] items = new Item[N];

        for (int i = 0; i < N; i++) {
            st = new StringTokenizer(br.readLine());

            int weight = Integer.parseInt(st.nextToken());
            int value = Integer.parseInt(st.nextToken());

            items[i] = new Item(weight, value);
        }

        Arrays.sort(items, (a, b) -> Double.compare(b.ratio, a.ratio));

        int remain = W;
        double totalValue = 0;

        for (Item item : items) {
            if (remain == 0) {
                break;
            }

            if (item.weight <= remain) {
                remain -= item.weight;
                totalValue += item.value;
            } else {
                totalValue += item.ratio * remain;
                remain = 0;
            }
        }

        System.out.println(totalValue);
    }
}
```

## 핵심

> 그리디는 현재 최선의 선택을 반복하지만, 그 선택이 전체 최적해를 보장하는 문제에서만 사용할 수 있다.

## 대표 문제 — 동전 자판기

이 문제에서는 관점을

```text
최대한 많은 동전을 사용한다
```

에서

```text
사용하지 않을 동전의 개수를 최소화한다
```

로 바꾸어 그리디 선택을 적용한다.

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.util.StringTokenizer;

public class Main {
    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        int W = Integer.parseInt(br.readLine());
        int[] coins = {500, 100, 50, 10, 5, 1};
        int[] count = new int[6];

        StringTokenizer st = new StringTokenizer(br.readLine());

        int totalPrice = 0;
        int totalCount = 0;

        for (int i = 0; i < 6; i++) {
            count[i] = Integer.parseInt(st.nextToken());
            totalPrice += coins[i] * count[i];
            totalCount += count[i];
        }

        // 사용하지 않아야 하는 금액
        int remain = totalPrice - W;
        int[] used = count.clone();

        // 큰 동전부터 최대한 사용하지 않도록 제거
        for (int i = 0; i < 6; i++) {
            int removeCount = Math.min(count[i], remain / coins[i]);

            used[i] -= removeCount;
            totalCount -= removeCount;
            remain -= removeCount * coins[i];
        }

        System.out.println(totalCount);

        for (int i = 0; i < 6; i++) {
            System.out.print(used[i]);

            if (i < 5) {
                System.out.print(" ");
            }
        }
    }
}
```
