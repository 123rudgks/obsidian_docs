
## 1. 운영체제란 무엇인가?

운영체제(OS, Operating System)는 **CPU, 메모리, 저장장치, 입출력 장치 등의 하드웨어 자원을 관리하고, 여러 프로그램이 이러한 자원을 안전하고 효율적으로 사용할 수 있도록 추상화와 서비스를 제공하는 시스템 소프트웨어**다.

운영체제가 필요한 이유는 프로그램들이 하드웨어 자원을 직접 관리하도록 둘 경우 충돌과 보안 문제가 발생할 수 있기 때문이다.

예를 들어 여러 프로그램이 동시에 실행되고 있다면 다음과 같은 문제가 생길 수 있다.

- 여러 프로그램이 동시에 CPU를 사용하려고 함
    
- 한 프로그램이 다른 프로그램의 메모리를 침범할 수 있음
    
- 여러 프로그램이 같은 데이터를 동시에 수정할 수 있음
    
- 프로그램이 디스크나 하드웨어 장치를 마음대로 제어할 수 있음
    

따라서 운영체제가 프로그램과 하드웨어 사이에 위치하여 자원을 통제한다.

```text
Application
     ↓
Operating System
     ↓
Hardware
```

운영체제의 역할은 크게 두 가지 관점으로 볼 수 있다.

### 자원 관리

CPU, 메모리, 저장장치 등의 한정된 자원을 여러 프로그램에 적절하게 배분한다.

### 추상화 제공

프로그램이 복잡한 하드웨어 구조를 직접 알지 않아도 사용할 수 있도록 단순한 형태로 제공한다.

예를 들어 사용자는 디스크의 특정 블록 위치를 알 필요 없이 다음과 같이 파일을 사용할 수 있다.

```text
report.txt
```

이는 운영체제가 실제 저장장치를 **파일이라는 형태로 추상화**했기 때문이다.

# 2. 운영체제의 전체 구조

운영체제의 주요 역할을 크게 나누면 다음과 같다.

```text
운영체제
│
├─ CPU 관리
│  ├─ Process
│  ├─ Thread
│  └─ Scheduling
│
├─ Memory 관리
│  ├─ Virtual Memory
│  └─ Paging
│
├─ 동시 실행 관리
│  ├─ Synchronization
│  └─ Deadlock
│
├─ Hardware 접근 관리
│  ├─ Kernel
│  └─ System Call
│
└─ 저장장치 관리
   └─ File System
```

---

# 3. CPU 관리

CPU는 프로그램의 명령어를 실제로 실행하는 하드웨어다.

하지만 컴퓨터에서는 동시에 수많은 프로그램이 실행된다.

```text
Chrome
IDE
게임
음악 프로그램
백그라운드 프로그램
```

CPU의 수는 제한되어 있기 때문에 운영체제가 어떤 프로그램에게 언제 CPU를 사용할 기회를 줄 것인지 관리해야 한다.

## Process

**프로세스(Process)는 실행 중인 프로그램**이다.

디스크에 저장되어 있는 프로그램 자체는 아직 실행 중인 상태가 아니다.

```text
Program
   ↓ 실행
Process
```

프로그램을 실행하면 운영체제가 해당 프로그램을 위한 프로세스를 생성하고 메모리와 CPU 등의 자원을 관리한다.

```text
Process A
Process B
Process C
```

---

## Thread

하나의 프로세스 안에서도 여러 작업이 동시에 진행될 수 있다.

예를 들어 브라우저는 다음과 같은 작업을 함께 수행할 수 있다.

```text
화면 렌더링
네트워크 통신
사용자 입력 처리
```

이때 등장하는 것이 **Thread**다.

Thread는 **프로세스 내부에서 실제 실행 흐름을 담당하는 단위**라고 볼 수 있다.

```text
Process
├─ Thread 1
├─ Thread 2
└─ Thread 3
```

운영체제는 CPU를 특정 Thread에 할당하여 실행시킨다.

---

## Scheduling

실행해야 할 Thread는 여러 개인데 CPU 코어 수는 제한되어 있다.

```text
Thread A
Thread B
Thread C
Thread D
     ↓
    CPU
```

따라서 운영체제는 어떤 Thread를 먼저 실행할지 결정해야 한다.

이를 **CPU Scheduling**이라고 한다.

```text
Thread A 실행
↓
Thread B 실행
↓
Thread C 실행
↓
다시 Thread A 실행
```

즉 CPU 관리의 전체 흐름은 다음과 같다.

```text
프로그램 실행
↓
Process 생성
↓
Thread 실행
↓
Scheduler가 CPU 사용 순서 결정
```

# 4. Memory 관리

프로그램을 실행하려면 메모리가 필요하다.

```text
Chrome → Memory 필요
IDE    → Memory 필요
게임    → Memory 필요
```

하지만 실제 물리 메모리인 RAM은 제한되어 있다.

운영체제가 메모리를 관리하지 않는다면 서로 다른 프로그램이 같은 메모리 공간을 사용하거나 다른 프로그램의 메모리를 침범할 수 있다.

따라서 운영체제는 프로세스마다 사용할 수 있는 메모리 영역을 관리한다.

---

## Virtual Memory

**Virtual Memory(가상 메모리)**는 각 프로세스에게 독립적인 가상 주소 공간을 제공하는 메모리 관리 방식이다.

각 프로세스는 자신이 독립적인 메모리 공간을 사용하는 것처럼 동작한다.

```text
Process A
0x0000
0x0001
...

Process B
0x0000
0x0001
...
```

두 프로세스가 같은 가상 주소를 사용하더라도 실제 물리 메모리에서는 서로 다른 위치를 가리킬 수 있다.

```text
Virtual Address
      ↓
운영체제 / MMU
      ↓
Physical Address
```

가상 메모리를 사용하면 다음과 같은 장점이 있다.

- 프로세스 간 메모리를 격리할 수 있음
    
- 각 프로세스에게 독립적인 주소 공간을 제공할 수 있음
    
- 물리 메모리를 효율적으로 관리할 수 있음
    
- 필요한 데이터만 실제 RAM에 올릴 수 있음
    

---

## Paging

가상 메모리를 구현할 때 많이 사용하는 방식이 **Paging**이다.

가상 메모리를 일정 크기의 **Page**로 나눈다.

```text
Virtual Memory

Page 0
Page 1
Page 2
Page 3
```

물리 메모리도 같은 크기의 **Frame**으로 나눈다.

```text
Physical Memory

Frame 0
Frame 1
Frame 2
Frame 3
...
```

그리고 어떤 Page가 어떤 Frame에 들어 있는지를 연결한다.

```text
Page 0 → Frame 3
Page 1 → Frame 1
Page 2 → Frame 7
```

따라서 메모리 관리의 흐름은 다음과 같이 연결된다.

```text
Memory 관리
→ Virtual Memory
→ Paging
```

# 5. 동시 실행 관리

여러 프로세스나 Thread가 동시에 실행되면서 하나의 공유 데이터를 함께 사용하면 문제가 생길 수 있다.

예를 들어 다음과 같은 값이 있다고 하자.

```text
count = 0
```

두 Thread가 동시에 다음 코드를 실행한다.

```text
count++
```

우리는 결과가 `2`가 되기를 기대한다.

하지만 실제로는 다음과 같은 실행이 가능하다.

```text
Thread A: count 읽기 → 0
Thread B: count 읽기 → 0

Thread A: 0 + 1 → 1 저장
Thread B: 0 + 1 → 1 저장
```

결과는 `1`이 된다.

이처럼 실행 순서에 따라 결과가 달라지는 문제를 **Race Condition**이라고 한다.

---

## Synchronization

여러 실행 흐름이 공유 자원에 접근할 때 순서를 조정하는 것을 **Synchronization(동기화)**이라고 한다.

대표적인 동기화 방법으로 다음과 같은 것들이 있다.

- Mutex
    
- Semaphore
    
- Lock
    

예를 들어 Lock을 사용하면 다음과 같이 공유 자원에 한 번에 하나의 Thread만 접근하게 만들 수 있다.

```text
Thread A
Lock 획득
↓
공유 데이터 수정
↓
Lock 해제

Thread B
↓
그 후 접근
```

---

## Deadlock

동기화를 위해 Lock을 사용하다 보면 또 다른 문제가 발생할 수 있다.

```text
Thread A
Lock 1 보유
Lock 2 기다림

Thread B
Lock 2 보유
Lock 1 기다림
```

그러면 서로 상대방이 가진 자원을 기다리기 때문에 둘 다 작업을 진행할 수 없다.

```text
A → B를 기다림
B → A를 기다림
```

이 상태를 **Deadlock(교착 상태)**이라고 한다.

따라서 동시 실행 관리에서는 다음 두 가지가 중요한 문제가 된다.

```text
Synchronization
→ 공유 자원 접근을 안전하게 조정

Deadlock
→ 서로 자원을 기다리며 진행하지 못하는 상태
```

---

# 6. Hardware 접근 관리

일반 프로그램이 CPU, 메모리, 디스크 등의 하드웨어를 마음대로 제어할 수 있다면 시스템 전체가 위험해진다.

예를 들어 프로그램이 마음대로 다음 작업을 수행할 수 있다고 생각해보자.

```text
다른 프로세스의 메모리 수정
Disk 데이터 삭제
하드웨어 장치 직접 제어
```

이를 막기 위해 중요한 시스템 자원은 운영체제가 관리한다.

이때 운영체제의 핵심 부분이 **Kernel**이다.

---

## Kernel

Kernel은 **운영체제의 핵심 부분으로, CPU, 메모리, 저장장치, 장치 등의 주요 시스템 자원을 관리한다.**

```text
Application
     ↓
Operating System
     ↓
Kernel
     ↓
Hardware
```

조금 더 정확하게 표현하면 다음과 같다.

```text
Application
     ↓
System Call
     ↓
Kernel
     ↓
CPU / Memory / Disk / Device
```

Kernel은 대표적으로 다음 기능들을 담당한다.

- 프로세스 관리
    
- 메모리 관리
    
- 파일 시스템 관리
    
- 장치 관리
    
- 네트워크 관리
    
- 권한 관리
    

즉 **운영체제 전체와 Kernel은 완전히 같은 개념이 아니다.**

Kernel은 운영체제를 구성하는 가장 핵심적인 부분이다.

---

## System Call

일반 프로그램은 중요한 시스템 자원에 직접 접근할 수 없다.

따라서 운영체제의 기능이 필요하면 Kernel에게 요청해야 한다.

이때 사용하는 인터페이스가 **System Call**이다.

예를 들어 프로그램에서 파일을 읽으려고 한다.

```text
Application
"파일을 읽고 싶다"
```

Application이 디스크를 직접 제어하는 것이 아니라 다음과 같이 운영체제에게 요청한다.

```text
Application
   ↓
System Call
   ↓
Kernel
   ↓
Disk
```

System Call을 통해 요청할 수 있는 대표적인 작업에는 다음과 같은 것들이 있다.

- 파일 열기
    
- 파일 읽기
    
- 프로세스 생성
    
- 네트워크 통신
    
- 메모리 관련 작업
    

따라서 Kernel과 System Call의 관계는 다음과 같다.

```text
Kernel
→ 시스템 자원과 하드웨어를 관리

System Call
→ Application이 Kernel 기능을 요청하는 인터페이스
```

# 7. 저장장치 관리

Disk 같은 저장장치는 실제로는 여러 저장 공간으로 구성되어 있다.

```text
Block 0
Block 1
Block 2
Block 3
...
```

하지만 사용자가 매번 특정 디스크 블록의 위치를 직접 지정하면서 데이터를 저장하는 것은 매우 불편하다.

그래서 운영체제가 **File System**이라는 추상화를 제공한다.

---

## File System

File System은 저장장치의 데이터를 **파일과 디렉터리라는 형태로 조직하고 관리하는 방식**이다.

사용자는 다음과 같은 형태로 파일을 사용한다.

```text
/home/user/report.txt
```

사용자는 실제 디스크에서 이 파일이 어느 블록에 저장되어 있는지 알 필요가 없다.

운영체제가 내부적으로 처리한다.

```text
File
↓
File System
↓
Disk Block
```

즉 파일 시스템은 복잡한 저장장치를 사용자가 쉽게 사용할 수 있도록 추상화한다.

# 8. 전체 흐름 연결

하나의 프로그램을 실행한다고 생각하면 지금까지의 개념을 하나의 흐름으로 연결할 수 있다.

```text
1. 프로그램 실행
   ↓
운영체제가 Process 생성

2. Process 내부의 Thread 실행
   ↓
Scheduler가 CPU 할당

3. 프로그램이 Memory 사용
   ↓
Virtual Memory / Paging으로 관리

4. 여러 Thread가 공유 데이터에 접근
   ↓
Synchronization 필요
   ↓
잘못하면 Deadlock 발생 가능

5. 프로그램이 파일 등의 시스템 자원이 필요
   ↓
System Call 호출
   ↓
Kernel 실행

6. Kernel이 File System 등을 통해
   ↓
Disk와 Hardware 접근
```

# 9. 핵심 개념 정리

## Process

**실행 중인 프로그램**

```text
Program → 실행 → Process
```

## Thread

**Process 내부의 실제 실행 흐름**

```text
Process
├ Thread
├ Thread
└ Thread
```

## Scheduling

**여러 실행 대상 중 누구에게 CPU를 할당할지 결정하는 것**

## Virtual Memory

**프로세스에게 독립적인 가상 주소 공간을 제공하고 실제 물리 메모리를 추상화하는 방식**

## Paging

**가상 메모리와 물리 메모리를 일정한 크기의 Page와 Frame 단위로 관리하는 방식**

## Synchronization

**여러 실행 흐름이 공유 자원에 안전하게 접근하도록 순서를 조정하는 것**

## Deadlock

**여러 실행 주체가 서로 필요한 자원을 기다리면서 영원히 진행하지 못하는 상태**

## Kernel

**CPU, 메모리, 장치 등 핵심 시스템 자원을 관리하는 운영체제의 핵심 부분**

## System Call

**일반 프로그램이 Kernel의 기능을 요청하기 위한 인터페이스**

## File System

**저장장치의 데이터를 파일과 디렉터리 형태로 조직하고 관리하는 방식**

# 10. 면접 답변

> 운영체제는 CPU, 메모리, 저장장치, 입출력 장치 등의 하드웨어 자원을 관리하고, 애플리케이션이 이러한 자원을 안전하고 편리하게 사용할 수 있도록 추상화와 서비스를 제공하는 시스템 소프트웨어입니다.
> 
> 주요 역할로는 먼저 CPU 관리가 있습니다. 운영체제는 실행 중인 프로그램을 프로세스로 관리하고, 프로세스 내부의 스레드들을 스케줄링하여 CPU 사용 순서를 결정합니다.
> 
> 메모리 영역에서는 가상 메모리와 페이징을 이용해 각 프로세스에게 독립적인 주소 공간을 제공하고 실제 물리 메모리를 관리합니다.
> 
> 또한 여러 프로세스와 스레드가 동시에 실행되면서 발생할 수 있는 Race Condition을 방지하기 위해 동기화를 지원하며, 그 과정에서 발생할 수 있는 Deadlock과 같은 문제도 관리해야 합니다.
> 
> 일반 애플리케이션이 하드웨어에 직접 접근하지 않도록 Kernel이 핵심 시스템 자원을 관리하며, 애플리케이션은 System Call을 통해 Kernel의 기능을 요청합니다.
> 
> 마지막으로 저장장치는 File System을 통해 실제 디스크 구조를 파일과 디렉터리라는 형태로 추상화하여 관리합니다.

# 복습 질문

### Q1. 운영체제가 없다면 프로그램들이 CPU와 메모리를 사용할 때 어떤 문제가 발생할까?

운영체제가 없다면 프로그램들이 CPU 사용 순서를 직접 조정해야 하고 서로의 메모리를 침범할 수 있으며, 하드웨어를 마음대로 제어할 수 있기 때문에 안전하고 효율적인 실행이 어려워진다.

### Q2. Kernel과 System Call의 관계는 무엇인가?

Kernel은 CPU, 메모리, Disk 등의 핵심 시스템 자원을 관리하며, 일반 Application은 직접 하드웨어에 접근하지 않고 System Call을 통해 Kernel의 기능을 요청한다.

### Q3. Virtual Memory와 File System의 공통점은 무엇인가?

둘 다 운영체제가 복잡한 하드웨어 구조를 프로그램이 쉽게 사용할 수 있도록 **추상화한 것**이다.

Virtual Memory는 물리 메모리를 프로세스별 가상 주소 공간으로 추상화하고, File System은 실제 저장장치를 파일과 디렉터리라는 형태로 추상화한다.
