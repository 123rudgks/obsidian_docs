
##### 자바에서 변수가 가지는 메모리 공간의 크기는 타입에 따라 다르다.
파이썬에서 변수는 모두 참조형이라서 크기 개념이 없다. 실제 값과 타입 정보는 변수가 가리키는 그 객체 안에 있다.
반면에, 자바에서는 변수가 **타입**에 따라 메모리 공간의 크기를 달리 할당 받는다. 변수를 선언할 때 타입을 명시하고, 그 타입에 따라 메모리 크기가 컴파일 시점에 확정된다.

##### byte는 8비트인데 왜 2^7 만 값을 저장하는데 사용할까?
자바에서 숫자를 다루는 타입은 맨 앞 비트를 sign bit로 사용한다.

##### short vs char 
short는 맨 앞의 비트를 sign bit로 사용하는 반면 char는 문자를 표현하기 때문에 sign bit가 필요 없다. 

##### int의 범위는 대략적으로 기억하면 좋다.
가장 많이 사용하는 기본형이기에 코드짜면서 값을 할당시 허용하는 범위 초과(또는 미만) 할당하지 않도록 기억하면 좋다.
대충 -20억 ~ 20억 쯤

##### literal이란?
값 그 자체를 의미함.  아래 예시를 보면 감이 잡힐 것이다.
```java
int a = 10;         // 10은 리터럴 (값을 직접 씀)
int b = a;          // a는 리터럴이 아님 (변수를 참조)
int c = add(1, 2);  // add(1, 2)는 리터럴이 아님 (메소드 호출 결과)
```
문자열도 literal이다. "Hello" 그러나 new String("Hello") 로 생성되는 건 literal이 아니다.

```java
String str1 = "Hello"; // 이렇게 값 자체로 줄 경우 리터럴이다. 이 경우에는 값이 String Pool에 저장된다.
String str2 = new String("Hello"); // 이 경우에는 객체를 생성하는 것이기에 리터럴이 아니다. 값은 Heap에 저장이 된다.
```

Overflow
타입별 표현 가능한 값의 범위가 정의되어있다. 이를 벗어나면 overflow 발생
```java
int i = Integer.MAX_VALUE;
long l1 = i+1 // 이미 연산이 될때 오버플로우가 발생함
long l2 = (long) i + 1 // 이렇게 연산시에 바로 형변환을 해서 연산이 될 수 있도록 해야함

```

##### 2진수의 실수의 연산은 정확하지 않을 수 있다. 2진수로 저장시 값 손실이 발생 
실수를 2진수로 표현할 때 정확하게 표현이 되지 않는 경우가 있다.
ex : 0.1을 2진수로 바꾸는 경우
0.1 = 0.00011001100110011.. (무한 반복)
컴퓨터에서 이를 무한히 저장할 수 없으니 어느 지점에서 그냥 잘라 반올림을 한다. 이때 **값 손실**이 발생한다.
그래서 실수 연산 결과를 그대로 쓰지 않고, 의미 있는 자릿수까지만 반올림하여 오차를 제거한다.
```java
double result = 0.1 + 0.2; // 0.30000000000000004이 나옴. 왜? 0.1을 2진수로 변환 + 0.2를 2진수로 변환
System.out.printf("%.1f%n", result); // 0.3 (소수점 1자리로 반올림)
```

금융처럼 정밀도가 중요한 경우에는 아예 ```BigDecimal```을 쓴다.

그러면 개발할때 실수간 연산을 어떻게 다루어야 하는가?
- 실수 연산을 정수로 바꾸기 (가장 흔한 방법)
```java
// 0.1 + 0.2를 실수로 계산하는 대신
double result = (1 + 2) / 10.0;  // 정수끼리 더하고 마지막에 나눔
System.out.println(result);       // 0.3 정확하게 나옴
```
