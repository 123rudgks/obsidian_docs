	## Generics

제네릭은 **컴파일 타임**에 타입 체크를 하고 컴파일 이후 제거된다.

그러면 제네릭을 사용하지 않았을 때와 사용했을 때 타입은 어떻게 처리가 되는가?

일반(비제네릭) 타입은 컴파일때도, 런타임 때도 타입 정보를 체크할 수 있다. 
예시
```java
Object o = "hello";
Integer i = (Integer) o; // 컴파일은 통과함, but 실행시에 ClassCastException 발생
```
객체가 자신이 무슨 타입인지에 대한 정보를 간직하고 있기 때문에 가능함

예시
```java
Object[] arr = new String[3];
arr[0] = 10; // 컴파일은 통과, but 실행 시에 ArrayStoreException 발생
```
배열은 런타임시에도 자기 요소 타입 정보를 간직하고 있음. 엉뚱한 타입을 넣으려 하면 실행 중에 걸러낸다.

반면 제네릭은 이 런타임 체크가 불가능함.
```java
List<String> list = new ArrayList<>();
List raw = list; // raw type으로 (경고는 뜨지만 컴파일은 됨)
raw.add(100); // 정수를 몰래 넣음. 컴파일러가 막지 못함 (Ojbect.add(Object))

String s = list.get(0); // 여기서 터짐!, ClassCastException 
```
ArrayList 내부는 원래부터(제네릭이든 아니든) 그냥 Object[] 배열임. 제네릭은 단지 "컴파일러가 편하게 캐스팅 해주는 도구"일 뿐.
따라서 `raw.add(100)` 는 이상없이 통과. 왜냐면 Object 객체의 메소드이기 때문
그러나 `String s = list.get(0);`는 조금 다름. 컴파일 시에는 `List<String>`으로 해주었기 때문에 get()이 돌려주는 값이 String인줄 알고 통과가 되지만 실제로는 Object를 반환 하는 것이기 때문에 컴파일 시에 컴파일러가 몰래 캐스팅 코드를 끼워넣는다.
```java
// 실제 컴파일된 모습
Object tmp = list.get(0); // 실제로는 Object 반환
String s = (String) tmp; // 컴파일러가 몰래 형변환을 함
```
런타임 시에 JVM이 실제로 형변환이 된 이 `tmp`가 실제로 String인지 확인을 한다. 이때 걸려서 `ClassCastException`이 발생

그러면 제네릭을 왜 쓰는가?
제네릭이 없던 시절
```java
List list = new ArrayList();
list.add("hello");
list.add(100);              // ✅ 컴파일 통과! 막을 방법이 없음 (그냥 Object라서)

String s = (String) list.get(1);   // 💥 런타임에 ClassCastException
```

제네릭을 사용할 경우
```java
List<String> list = new ArrayList<>();
list.add("hello");
list.add(100);    // ❌ 컴파일 에러! 여기서 바로 막힘
```
그럼 위 예시에선 왜 통과 했지?
```java
List raw = list; // raw type으로 (경고는 뜨지만 컴파일은 됨)
```
일부러 raw 타입으로 만들어 탈출구를 만든 것.  중요한 것은 제네릭은 컴파일을 하면서 제거가 된다는 사실을 이해하는 것
>[!note] Raw Type이란? 
> 제네릭 클래스나 인터페이스를 타입 파라미터(\<T>, \<String> 등) 없이 그냥 쓰는 것
> List raw = new ArrayList(); // 이런게 로우 타입

제네릭은 컴파일 타임에만 존재하는 타입 정보이고, 그 정보는 항상 **인스턴스** 단위로 결정된다.


제네릭은 런타임 에러가 발생할 것을 컴파일 타임떄 검출 할 수 있도록 사전에 검사하기 위함. 컴파일 에러는 코드 짜는 도중 고칠 수 있지만 런타임 에러는 사용자가 실제로 실행을 할때 발견될 수 있어서 훨씬 비용이 비싸다.


한정형 형인자 (bounded type parameter)

```java
// Number나 Number를 상속 받는 클래스들만 허용
class NumberBox<T extends Number>{
	public void addSomes(T .. ts){
		double d = 0;
		for (T t : ts){
			d += t.doubleValue();
		}
		System.out.println();
	}
}

// 인터페이스로 제한할 때에도 extends 사용
class TypeRestrict1<T extends SomeInterface>{}
// 클래스와 함ㅁ께 인터페이스 제약 조건을 이용할 경우 &로 연결
class TypeRestrict2<T extends SomeClass & SomeInterface1 & SomeInterface2> {}
```


와일드카드 자료형
- 제네릭 타입 변수 선언 시 실제 type parameter가 무엇인지 모르거나 신경쓰고 싶지 않을 경우
```java
// unbounded wildcard type
Generic_type<?> // 타입에 제한이 없음(Object)
// bounded wildcard type
Generic_type<? extends T> // T 또는 T를 상속 받은 타입만 가능
Generic_type<? super T> // T 또는 T의 조상 타입만 사용 가능
```

제네릭의 PECS
**P**roducer **E**xtends, **C**onsumer **S**uper
와일드 카드 의 extends, super를 언제 사용해야할 지 헷갈릴 때 결정을 도와주는 암기 공식

해당 타입이 이 타입을 사용하는 곳으로 값을 produce 하는지, consume하는지를 보면 되 (방향 헷갈림 주의)

Producer Extends
아래 예시에서 src는 스택에게 값을 공급(produce)하는 쪽 즉, producer임
```java
public class Stack<E>{
	private List<E> items = new ArrayList<>();
	
	public void push(E e){
		items.add(e);
	}
	// src에서 값을 꺼내서(Produce) 스택에 넣음 → src는 Producer → extends
	public void pushAll(Iterable<? extends E> src){
		for(E e : src){
			push(e);
		}
	}
}

Stack<Number> numberStack = new Stack<>(); 
List<Integer> integers = List.of(1, 2, 3); 
numberStack.pushAll(integers); // ✅ extends 덕분에 가능
```

만약, extends가 없었으면 오직 Number 타입만 받을 수 있었을 것.
< ? extends E>가 있어야 E의 하위 타입까지 폭 넓게 받을 수 있음

Consumer Super
아래 예시에서 dst는 스택으로부터 꺼낸 값을 소비(consume) 하는 쪽, 즉 consumer임
```java
public class Stack<E>{
	...
	
	// 스택에서 꺼낸 값을 dst에 넣어줌(Comsume) -> dst는 consumer -> super
	public void popll(Collection<? super E> dst){
		while(!isEmpty()){
			dst.add(pop());
		}
	}

}

Stack<Integer> integerStack = new Stack<>(); 
integerStack.push(1); 
integerStack.push(2); 
Collection<Number> numbers = new ArrayList<>(); 
integerStack.popAll(numbers); // ✅ super 덕분에 가능
```

< ? super E>가 없었다면 popAll(Collection\<E> dst)는 오직 Collection\<Integer>만 받을 수 있고 Collection\<Number>나 Collection\<Object>에 담을 수 없을 것

>[!Note]
>자식 타입의 값을 부모 타입 변수에 대입하는 건 항상 안전하다 (업캐스팅). 
>헷갈릴 땐 "실제로 어떤 값이, 어떤 타입의 변수에 담기는가"를 따져보면 된다.
**Producer (`src`) 상황**
`Stack` 내부에서는 `src`의 원소를 꺼내 `E` 타입 변수에 담아 쓴다 (`for (E e : src)`). 이 대입이 안전하려면, `src`의 실제 원소 타입이 `E`의 **자식**이어야 한다. 즉 `E`가 부모, `src`의 원소 타입이 자식인 관계가 되어야 하므로, `src`의 타입 파라미터는 `E`의 하위 타입으로 제한해야 한다 → `extends`.
**Consumer (`dst`) 상황** 
`Stack` 내부의 `E` 타입 값을 꺼내서 외부의 `dst`에 담아준다 (`dst.add(pop())`). 이 대입이 안전하려면, `dst`의 실제 원소 타입이 `E`의 **부모**여야 한다. 즉 `dst`가 부모, `E`가 자식인 관계가 되어야 하므로, `dst`의 타입 파라미터는 `E`의 상위 타입으로 제한해야 한다 → `super`.




## Enum
java.lang.enum을 내부적으로 상속 받은 형태의 특별한 클래스
class 대시 enum 키워드 사용
```java
enum Grade{
	SALES, PART_TIME_JOB, NORMAL
}
```
enum 타입에 선언된 내용은 enum 상수라고 불림. 따라서 일반적인 상수 선언의 naming룰을 따라 대문자로 표기

enum 타입의 사용
```java
// 클래스와 동일하게 선언하며 할당 될 수 있는 값은 enum 상수, null만 가능
Grade grade = Grade.SALES;
```

활용 예시
```java
// 값 비교 시 사용
public void calcSalEnum(Grade grade){
	if(grade.equals(Grade.SALES)){
		...
	}else if(grade.equals(Grade.PART_TIME_JOB)){
		...
	}else if(grade.equals(Grade.NORMAL)){
		...
	}
}


// switch-case 사용시 case 문에는 enum 이름 적지 않고 상수 이름만 표시
public void enumSwitch(Season season){
	switch(season){
		case SPRING:
			break;
		case SUMMER:
			break;
		case FALL:
			break;
		default:
			
	}
}
```

enum 메소드 예시
```java
enum Grade {
    SALES, PART_TIME_JOB, NORMAL
}

public class EnumMethodsExample {

    public static void main(String[] args) {

        // ① values() - 선언된 모든 enum 상수를 배열로 리턴
        Grade[] grades = Grade.values();

        for (Grade g : grades) {
            // ② name() - 상수 이름을 문자열로
            // ③ ordinal() - 선언 순서(0부터)
            System.out.printf("name: %s, ordinal: %d%n", g.name(), g.ordinal());
        }

        System.out.println("---");

        // ④ valueOf(String) - 문자열 이름으로 enum 상수를 다시 얻어옴
        Grade g1 = Grade.valueOf("SALES");
        System.out.println("valueOf(\"SALES\") = " + g1);

        System.out.println("---");

        // ⑤ compareTo() - 두 상수의 ordinal 차이를 리턴
        Grade a = Grade.SALES;          // ordinal: 0
        Grade b = Grade.PART_TIME_JOB;  // ordinal: 1
        Grade c = Grade.NORMAL;         // ordinal: 2

        System.out.println("a.compareTo(b) = " + a.compareTo(b));   // 0 - 1 = -1
        System.out.println("c.compareTo(a) = " + c.compareTo(a));   // 2 - 0 = 2
        System.out.println("a.compareTo(a) = " + a.compareTo(a));   // 0 - 0 = 0
    }
}
```

```
// 실행 결과
name: SALES, ordinal: 0
name: PART_TIME_JOB, ordinal: 1
name: NORMAL, ordinal: 2
---
valueOf("SALES") = SALES
---
a.compareTo(b) = -1
c.compareTo(a) = 2
a.compareTo(a) = 0
```


생성자를 통한 enum 상수 초기화
```java
public enum HttpStatus {
    OK(200, "요청 성공"), // ← 여기서 생성자 호출됨!
    NOT_FOUND(404, "리소스를 찾을 수 없음"), // ← 여기서도 생성자 호출됨!
    INTERNAL_SERVER_ERROR(500, "서버 내부 오류"); // ← 여기서도 생성자 호출됨!

    private final int code;
    private final String message;

    HttpStatus(int code, String message) {
        this.code = code;
        this.message = message;
    }

    public int getCode() { return code; }
    public String getMessage() { return message; }
}
```
enum 상수는 프로그램 전체에서 딱 하나만 존재하는 싱글턴 객체. 다만 개발자가 직접 new를 작성하지 않았을 뿐 클래스가 로딩될 때 컴파일러가 new를 호출해 각 상수 객체를 생성한다.

따라서 enum은 private final로 멤버 변수를 두고 setter, getter로 다루는 것이 관례 (꼭 private, final이 아니어도 컴파일은 됨)
