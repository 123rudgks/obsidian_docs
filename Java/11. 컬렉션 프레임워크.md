## Collection
핵심 메소드들
```java
import java.util.*;

public class CollectionMethodsDemo {
    public static void main(String[] args) {
        Collection<String> c1 = new ArrayList<>();
        Collection<String> c2 = new ArrayList<>();

        c1.add("A");                          // add: 요소 하나 추가
        c1.addAll(List.of("B", "C"));         // addAll: 여러 요소 한번에 추가
        System.out.println("add/addAll 후: " + c1);

        System.out.println("contains(\"B\"): " + c1.contains("B"));           // 특정 요소 포함 여부
        System.out.println("containsAll(B,C): " + c1.containsAll(List.of("B", "C"))); // 전부 포함 여부

        c2.addAll(List.of("A", "B", "C"));
        System.out.println("equals: " + c1.equals(c2));                       // 내용 동일 비교

        System.out.println("isEmpty: " + c1.isEmpty());                       // 비어있는지
        System.out.println("size: " + c1.size());                            // 요소 개수

        Iterator<String> it = c1.iterator();                                  // iterator: 순회용 반복자
        System.out.print("iterator 순회: ");
        while (it.hasNext()) System.out.print(it.next() + " ");
        System.out.println();

        String[] arr = c1.toArray(new String[0]);                            // toArray: 배열로 변환
        System.out.println("toArray: " + Arrays.toString(arr));

        c1.remove("B");                                                       // remove: 요소 하나 제거
        System.out.println("remove(\"B\") 후: " + c1);

        c1.removeAll(List.of("C"));                                           // removeAll: 여러 요소 제거
        System.out.println("removeAll(C) 후: " + c1);

        c1.clear();                                                           // clear: 전체 비우기
        System.out.println("clear 후: " + c1 + ", isEmpty: " + c1.isEmpty());
    }
}
```

#### ArrayList
ArrayList는 내부적으로 Object[]로 데이터를 관리함. 그러면 어떻게 타입 안정성을 유지하지?
Object[] 멤버변수를 private으로 처리하고 값 추가는 add 함수를 통하여만 가능하게 했음. 따라서 제네릭으로 컴파일시에 타입체크를 마친 값들만 들어오도록 하여 타입안정성을 챙겼다.
```java
public class ArrayList<E> {
    transient Object[] elementData;   // private! 외부에서 절대 직접 못 건드림

    public boolean add(E e) {          // 외부는 오직 E만 넣을 수 있음
        elementData[size++] = e;
        return true;
    }

    @SuppressWarnings("unchecked") // Object로 관리하던걸 E 타입으로 return 하려니 warning이 뜨는걸 방지하기 위함. 
    public E get(int index) {
        return (E) elementData[index]; // 여기서만 캐스팅, 이 캐스팅은 항상 성공이 보장됨
    }
}
```
`@SuppressWarnings("unchecked")`가 있는 이유가 컴파일러 입장에선 명시적으로 캐스팅하는것이 안전한지 모르기 때문인데 add로만 데이터 추가를 관리하기 때문에 논리적으로 안전하다. 따라서 warning을 발생시키지 않아도 되는것

본래, 배열은 길이가 고정되어있지만 ArrayList는 내부적으로 Object[]의 길이를 조절한다. 
```java
if(oldCapacity > 0 || elementData != DEFAULTCAPCITY_EMPTY_ELEMENTDATA){
	int newCapacity = ArraysSupport.newLength(oldCapacity, minCapacity-oldCapacity, oldCapacity >> 1); // oldCapacity >> 1은 현재 용량의 1.5배를 하기 위함
	return elementData = Arrays.copyOf(elementData,newCapacity);
}else{
	return elementData = new Object[Math.max(DEFAULT_CAPACITY,minCapacity)]; 
	// 기본 생성자로 만들어서 아직 한 번도 요소가 안 들어간 `ArrayList`"인 경우
}
```



#### LinkedList
앞에서 또는 뒤에서 데이터를 찾아가도록 최적화 됨

LinkedList는 삽입/삭제에 들어가는 비용이 O(1)이라서 ArrayList보다 좋아보이지만 사실 삽입/삭제를 하려는 요소까지 이동하는 비용이 O(n)이라서 큰 차이가 없다.
그러면 언제 LinkedList가 빛이 나는가? 바로 찾아가는 비용 자체가 없는 경우. 
예 : `Iterator`로 이미 순회하고 있는 도중 삽입/삭제 하는 경우
```java
LinkedList<Integer> list = new LinkedList<>(List.of(1, 2, 3, 4, 5)); ListIterator<Integer> it = list.listIterator(); 
while (it.hasNext()) { 
	int val = it.next();
	if (val == 3) { 
		it.add(999); // O(1)! 이미 그 위치에 있으므로 순회가 필요 없음 
		it.remove(); // 마찬가지로 O(1) 
	} 
}
```



ArrayList vs LinkedList
- 소량의 데이터일 경우 큰 차이 없음
- 정적인 데이터 활용, 단순 조회 용 : ArrayList가 더 좋음
- 맨 앞에 데이터 추가한다 : LinkedList가 더 좋음
- 중간에 대량의 데이터를 연속적으로 넣고 뺀다 : ListIterator를 이용한 LinkedList가 더 좋음
- 그 외 대부분의 상황 : ArrayList가 성능,메모리 측면에서 이득


## Set
**입력 순서가 없는** 데이터 집합
중복 허락하지 않음 -> 효율적인 중복 데이터 제거 수단
ex : HashSet, TreeSet

Hash
- 임의의 길이를 가진 데이터를 고정된 길이로 변환한 고유의 값
- 특정 입력에 대해서는 항상 같은 값이 나옴
- 아주 많은 데이터 중에서 내가 원하는 데이터를 빠른 속도(O(1))로 찾기 위해 사용

Hash 충돌
- hashCode()는 int를 반환. int는 8바이트(32비트)+ -> 42억개의 배열을 메모리에 만드는건 불가능 -> hash 코드에 대한 압축이 필요
  ex : `index = (hashCode%배열의크기)` -> 충돌이 날 수 밖에 없음
- 그래서 내부적으로 LinkedList를 이용하여 관리
How to ?
- 충돌 나는 값들을 LinkedList로  줄줄이 이어 붙인다.
- 버킷까지는 hash 값으로 찾아가고 O(1) 그 이후 LinkedList를 순회하며 equals()로 진짜 일치하는 키를 찾는다.
왜 ArrayList 안쓰고 LinkedList?
- ArrayList는 인덱스로 접근할때 O(1)로 빠르다. 그러나 이 경우에는 인덱스가 아닌 값으로 찾아야 하기 때문에 마찬가지로 하나씩 순회하며 접근해야한다.
- ArrayList는 여유 메모리를 가지고 있는데 이게 오히려 낭비이다. LinkedList는 딱 필요한 만큼만 메모리를 가진다.

객체를 원소로 가지는 Set에서 중복처리를 하기 위해선 hashCode()와 equals()를 재정의하여 비즈니스 로직에 맞게 같은 원소 처리를 해야한다.

HashSet은 내부적으로 HashMap에 데이터 저장
- key에 value를 넣어 중복 방지하고 value에는 dummy값 사용한다.



## Map
key, value 쌍으로 데이터 관리
순서 없음
key는 중복 불가, value는 중복 가능
ex : HashMap, TreeMap

HashMap
HashMap의 Node 배열의 index는 hash

map에서는 add 대신 put으로 처리함. 그래서 사용시에 덮어쓰지 않도록 조심해야함
```java
public class MapTest {

    Map<String, String> hMap = new HashMap<>();

    private void addMethod() {
        System.out.println("추가 성공?: " + hMap.put("andy", "1234"));
        // 동일한 키의 사용 결과는?
        System.out.println("추가 성공?: " + hMap.put("andy", "4567"));

        hMap.put("kate", "9999");

        // 기존에 해당 키에 대한 값이 없을 때만 추가하기
        hMap.putIfAbsent("kate", "1234");

        hMap.put("henry", "4567");   // 동일한 값

        System.out.println("추가 결과: " + hMap);
    }

    public static void main(String[] args) {
        MapTest test = new MapTest();
        test.addMethod();
    }
}
```


불변(Unmodifiable) Collection 생성
- 생성 후 추가/삭제/수정 시도하면 에러 발생시킴
- null 허용 안함

List.of()
- 불변 List
- null 저장시 runtime 예외 발생
Set.of()
- 불변 Set
- 데이터 중복 또는 null 저장시 runtime 예외 발생
Map.of()
- 불변 Map
- 최대 10개의 엔트리(key-value 쌍)까지 지원되면 null 키/값 불가

객체에서 Collections.sort(..)을 사용하려면 Comparable 또는 Comparator를 구현해야한다.


Comparable
```java
public static <T extends Comparable<? super T>> void sort(List<T> list)
```

Comparator
```java
public static <T> void sort(List<T> list, Comparator<? super T> c)
```

Integer에는 compare()가 있지만 String에는 compare()가 없다.
why?
Integer는 기본형 int를 더 잘쓰기 위해 있는것, 두 int끼리 비교하려는데 compareTo 밖에 없다면 `Integer.valueOf(a).compareTo(b)`이렇게 불필요하게 a값을 호출해야한다.
반면에 String은 원래 기본형이 없기 때문에 compare가 굳이 있을 필요가 없다. 항상 객체로 있기 때문에 바로 compareTo 부르면 되기 때문
	Integer는 compareTo, compare 둘 다 있고 String은 compareTo만 있다.
