**문자열의 뒤의 n글자**
```java
public String solution(String my_string, int n) {
        String answer = my_string.substring(my_string.length() - n);
        return answer;
    }
```
>[!note]
>전체 길이 : length
>출력할 글자의 개수 : n
>`length - n` 번 인덱스에서 부터 마지막까지 출력하면 n개 출력
>- prove
>	배열의 마지막 인덱스는 `length - 1`
>	인덱스 구간의 원소 개수는 다음과 같다. `끝 인덱스 - 시작 인덱스 + 1`
>	`n`개의 원소를 가져오려면: (length - 1) - 시작 인덱스 + 1 = n
>	정리하면: `시작 인덱스 = length - n`

>[!note]
>(1)번
>Java의 배열의 크기는 고정적. 처음에 정해져야한다.
>`num_list.length - (n-1)` : 처음에 n-1대신 n을 뺐어서 틀렸었다. 
>배열의 크기를 `num_list.length - (n - 1)`로 계산하는 이유는 아래와 같다.
>자바 배열의 인덱스는 `0`부터 시작하므로:
>- `n`번째 원소의 인덱스 → `n - 1`
>- 마지막 원소의 인덱스 → `num_list.length - 1`
>따라서 필요한 배열의 크기는:
>```
>마지막 인덱스 - 시작 인덱스 + 1
= (length - 1) - (n - 1) + 1
= length - n + 1
= length - (n - 1)
>```
>처음에 `length - n`으로 계산하면 **n번째 원소부터 마지막까지의 개수에서 1개가 부족하다.**
>따라서 `n`번째 원소를 포함하기 위해 `+1`이 필요하다.
>```
>num_list.length - n + 1
= num_list.length - (n - 1)
>```
>
>(2)번
>`copyOfRange(원본배열, 시작인덱스, 끝인덱스)`
>**시작은 포함, 끝은 미포함(exclusive)** 이에요.

**수 조작하기1**
> [!note] 1. String 리터럴 == 비교
> 
> - `String`은 **참조 타입** → `==`는 참조(주소)를 비교
> - 코드에 직접 쓴 문자열 리터럴(`"w"`)은 **문자열 상수 풀(String Constant Pool)**에 저장되고, 같은 내용의 리터럴은 재사용됨 → `"w" == "w"`는 **true** (같은 객체를 참조)
> - `new String("w")`로 만들면 풀을 무시하고 **힙에 별도 객체** 생성 → `new String("w") == new String("w")`는 **false**, `.equals()`는 true
> - **결론: String 비교는 항상 `.equals()` 사용**
> 
> java
> 
> ```java
> String a = "w";
> String b = "w";
> a == b;              // true (풀 재사용)
> 
> String c = new String("w");
> String d = new String("w");
> c == d;               // false (별도 객체)
> c.equals(d);          // true (내용 비교)
> ```

> [!note] 2. charAt()으로 추출한 char와 == 비교
> 
> - `charAt()`은 `String`이 아니라 **`char`(원시 타입)**를 반환
> - 원시 타입(`char`, `int`, `double` 등)에는 문자열 상수 풀 개념 자체가 적용되지 않음
> - 원시 타입의 `==`는 **항상 값 비교** → `char` 비교에 `==`를 써도 안전함
> - 원시 타입은 메서드가 없으므로 `.equals()` 사용 불가
> 
> java
> 
> ```java
> char c1 = "hello".charAt(0);   // 'h'
> char c2 = "hello".charAt(0);   // 'h'
> c1 == c2;   // true (값 비교, 항상 안전)
> ```

> [!info] "s" vs 's'
> - `"s"` (큰따옴표) → **String** (참조 타입, 객체) — 상수 풀 규칙 적용
> - `'s'` (작은따옴표) → **char** (원시 타입) — 값 자체를 담는 타입
> - `"s" == 's'` → **컴파일 에러** (타입이 달라 비교 불가)
> - `"s".equals('s')` → 컴파일은 되지만 **항상 false** (String vs Character라 다른 클래스)
> - **결론: 따옴표 종류가 타입을 결정** (큰따옴표=String, 작은따옴표=char)

> [!question] 왜 멤버 변수는 자동 초기화, 지역 변수는 명시적 초기화?
> - **멤버 변수(인스턴스/static)**: 힙/메소드 영역에 메모리 할당될 때 JVM이 그 공간을 **자동으로 0/null로 초기화(zeroing)**함 → 객체 생성 과정 자체에 포함된 단계
> - **지역 변수**: 스택 프레임의 슬롯일 뿐, 이전 호출의 찌꺼기 값이 남아있을 수 있음 → 매번 zeroing하면 성능 손해라 JVM이 자동 초기화 안 함
> - 대신 자바는 **컴파일 타임 정적 분석(확정적 할당 분석)**으로 "모든 실행 경로에서 값이 대입됐는지" 검사 → 안 되면 컴파일 에러
>
> | 구분 | 저장 위치 | 초기화 |
> |---|---|---|
> | 멤버 변수 | 힙 / 메소드 영역 | 런타임 자동 zeroing |
> | 지역 변수 | 스택 프레임 | 없음 → 컴파일러가 강제 검증 |
