# 1. 비지도학습이란?

비지도학습은

> **Label 없이 데이터 자체에 존재하는 구조나 패턴을 찾아내는 학습**

이다.

지도학습과 가장 큰 차이는 **정답 Label의 존재 여부**다.

```text
Supervised Learning
→ Label 있음

Unsupervised Learning
→ Label 없음
```

비지도학습에서는 정답을 맞히는 것이 목적이 아니다.

대신 Feature들만 보고

- 어떤 Data들이 서로 비슷한가?
    
- 어떤 Data들이 서로 다른가?
    
- 데이터 내부에 어떤 집단 구조가 존재하는가?
    
- 데이터 표현을 어떻게 요약할 수 있는가?
    
- 이후 Downstream Analysis에 사용할 새로운 표현을 만들 수 있는가?
    

등을 분석한다.

---

# 2. 지도학습과 비지도학습 비교

## 지도학습

예를 들어 Data Point에 이미 색깔별 Label이 존재한다고 하자.

```text
● = Class A
▲ = Class B
```

모델은 이 Label을 이용해

> A와 B를 가장 잘 구분하는 Decision Boundary를 찾아라.

라는 문제를 해결한다.

즉 정답이 이미 존재한다.

---

## 비지도학습

비지도학습에서는 같은 Data가 있어도 색깔 Label이 없다.

우리가 알고 있는 것은 오직

```text
x₁, x₂, ...
```

같은 Feature 값뿐이다.

이때

> 서로 비슷해 보이는 Data Point들을 몇 개의 집단으로 묶어보자.

라는 문제가 Clustering이다.

중요한 것은

> **그렇게 나눈 결과가 유일한 정답이라는 의미는 아니다.**

라는 것이다.

---

# 3. Classification과 Clustering은 다르다

매우 헷갈리기 쉬운 구분이다.

## Classification

```text
정답 Label 있음
→ 지도학습
```

예:

```text
Image
↓
Dog / Cat
```

이미 Dog와 Cat이라는 정답 category가 정해져 있다.

---

## Clustering

```text
정답 Label 없음
→ 비지도학습
```

예:

여러 고객의 행동 데이터를 보고

```text
비슷한 고객끼리 묶어보자.
```

라고 한다.

어떤 고객 집단을 어떻게 정의해야 하는지가 처음부터 정답으로 주어져 있지 않다.

따라서

> **Classification = 분류**
> 
> **Clustering = 군집화**

로 구분해야 한다.

---

# 4. Clustering이란?

Clustering은

> **서로 유사한 Data Point들을 같은 집단으로 묶는 문제**

다.

이상적인 clustering은 직관적으로

```text
같은 Cluster 내부
→ 서로 가까움 / 유사함

다른 Cluster끼리
→ 서로 멂 / 다름
```

의 형태를 가진다.

즉

> **Cluster 내부 유사도는 높고, Cluster 사이 차이는 크게 만드는 것**

이 기본적인 방향이다.

---

# 5. 하지만 “유사하다”는 절대적인 개념이 아니다

Clustering에서 가장 어려운 부분 중 하나다.

어떤 두 Data가 비슷한지 판단하려면

- 어떤 Feature를 사용할 것인가?
    
- 어떤 Distance를 사용할 것인가?
    
- Feature별 중요도는 어떻게 설정할 것인가?
    

를 결정해야 한다.

따라서 문제와 Domain에 따라 결과가 달라질 수 있다.

예를 들어 고객을

```text
나이
소득
구매 빈도
구매 금액
관심 상품
```

중 어떤 기준으로 비교하느냐에 따라 서로 다른 Cluster가 만들어질 수 있다.

결국 비지도학습에서는 사람이 결정해야 하는 부분이 많다.

---

# 6. Clustering에는 절대적인 정답이 없다

같은 Data를

```text
2개 Cluster
3개 Cluster
4개 Cluster
```

로 나눌 수도 있다.

어느 것이 반드시 정답이라고 말하기 어렵다.

사용 목적이나 Domain Knowledge에 따라

```text
2개가 적합할 수도 있고
3개가 적합할 수도 있고
4개가 적합할 수도 있다.
```

따라서 Clustering에서는

> **“정답과 얼마나 일치했는가?”**

라는 지도학습식 평가를 그대로 사용할 수 없다.

---

# 7. Clustering 활용 예 — 고객 Segmentation

Marketing Campaign을 생각해보자.

모든 고객에게 하나의 광고를 보여주는 것보다

```text
Customer Data
      ↓
Clustering
      ↓
Customer Segment A
Customer Segment B
Customer Segment C
      ↓
각 Segment에 다른 Campaign
```

을 적용하는 것이 효과적일 수 있다.

따라서 고객의

- 구매 행동
    
- 소비 성향
    
- 관심 분야
    

등을 이용하여 비슷한 고객끼리 묶는 것이 Clustering의 대표적 활용 사례다.

---

# 8. 다른 Clustering 활용 사례

강의에서는 부동산 분석도 예로 든다.

여러 주택의 Feature를 가지고

```text
비슷한 특성을 가진 주택끼리 묶는다.
```

와 같은 문제로 볼 수 있다.

즉 Label 없이 데이터 자체의 구조를 탐색하려는 여러 분석에서 Clustering을 사용할 수 있다.

---

# 9. 대표적인 두 Clustering Algorithm

이번 강의에서는 두 가지를 다룬다.

```text
1. K-means Clustering
2. Hierarchical Clustering
```

가장 중요한 차이는 **Cluster 수 K를 언제 결정하는가**다.

|K-means|Hierarchical|
|---|---|
|K를 미리 결정|K를 미리 고정할 필요 없음|
|K를 입력으로 줌|전체 계층 구조를 만든 뒤 사후 결정 가능|
|비교적 단순하고 빠름|계산량이 더 큼|

---

# 10. K-means에서 K란?

K-means의 `K`는

> **만들고 싶은 Cluster의 개수**

다.

예를 들어

```text
K = 3
```

이라고 하면

> 이 Data를 3개의 Cluster로 나눠라.

라는 뜻이다.

즉 K는 Algorithm을 실행하기 **전에 사람이 지정해야 한다.**

---

# 11. K-fold의 K와 혼동하면 안 된다

앞선 Cross Validation 강의에서도 `K`가 등장했다.

하지만 둘은 완전히 다른 의미다.

```text
K-means의 K
→ Cluster 개수

K-fold Cross Validation의 K
→ Fold 개수
```

두 용어에 우연히 같은 문자 `K`가 들어가는 것이지 서로 관련된 개념은 아니다.

---

# 12. 같은 Data라도 K에 따라 결과가 달라진다

같은 Dataset에서

```text
K = 2
K = 3
K = 4
```

를 사용하면 서로 다른 군집 결과가 나온다.

그래프에서 Cluster마다 서로 다른 색깔을 사용할 수 있지만

> **색깔 자체에는 의미가 없다.**

예를 들어

```text
Blue Cluster
Yellow Cluster
Green Cluster
```

에서 Blue가 특별한 의미를 가진 것이 아니다.

단지

> 서로 다른 Cluster임을 눈으로 구별하기 위해 색을 다르게 사용했을 뿐이다.

---

# 13. Cluster 번호 자체에도 의미가 없다

마찬가지로

```text
Cluster 1
Cluster 2
Cluster 3
```

에서 숫자의 순서도 본질적인 의미가 없다.

어떤 실행에서는 같은 집단이 Cluster 1일 수도 있고 다른 실행에서는 Cluster 3일 수도 있다.

중요한 것은

> **어떤 Data들이 서로 같은 Cluster로 묶였는가**

이다.

---

# 14. Clustering의 수학적 조건

전체 Data를 `K`개의 Cluster

`C₁, C₂, ..., Cₖ`

로 나눈다고 하자.

Clustering 결과는 두 가지 중요한 조건을 만족해야 한다.

---

# 15. 조건 ① 모든 Data가 어떤 Cluster에는 속해야 한다

모든 Cluster를 합쳤을 때 전체 Dataset이 되어야 한다.

개념적으로

`C₁ ∪ C₂ ∪ ... ∪ Cₖ = 전체 데이터`

다.

즉

```text
어떤 Cluster에도 들어가지 않은 Data
```

가 존재해서는 안 된다.

---

# 16. 조건 ② 하나의 Data가 여러 Cluster에 동시에 들어가면 안 된다

서로 다른 두 Cluster는 겹치지 않아야 한다.

개념적으로

`Cₖ ∩ Cₖ' = ∅`

이다.

즉 하나의 Data Point가 동시에

```text
Cluster A
+
Cluster B
```

에 속할 수 없다.

이번 강의에서 다루는 Clustering에서는

> **모든 Data를 빠짐없이, 서로 겹치지 않도록 정확히 하나의 Cluster에 배정한다.**

---

# 17. 좋은 Cluster란?

같은 Cluster 안의 Data들이 서로 매우 멀리 흩어져 있다면 좋은 결과라고 보기 어렵다.

우리가 원하는 것은

```text
Cluster 내부
●●●●

다른 Cluster
        ▲▲▲▲
```

처럼 같은 Cluster의 Data들이 서로 가까이 모여 있는 것이다.

이를 **Within-Cluster Variation**과 연결한다.

---

# 18. Within-Cluster Variation

Within-Cluster Variation은

> **각 Cluster 내부의 Data들이 얼마나 퍼져 있는가**

를 나타낸다.

좋은 Clustering이라면

`Within-Cluster Variation ↓`

을 원한다.

즉 같은 Cluster 안의 관측치들이 서로 가깝게 모여 있어야 한다.

---

# 19. K-means의 전체 아이디어

K-means Algorithm은 놀라울 정도로 단순하다.

전체 구조는 다음과 같다.

```text
① Cluster를 Random하게 초기화

② 각 Cluster의 Centroid 계산

③ 각 Data를 가장 가까운 Centroid의
   Cluster로 재할당

④ Centroid 다시 계산

⑤ 다시 가장 가까운 Cluster로 재할당

⑥ 할당이 더 이상 바뀌지 않을 때까지 반복
```

핵심적으로

```text
Centroid 계산
↕
Cluster 재할당
```

두 작업을 반복한다.

---

# 20. K-means Step 1 — Random Initialization

먼저 Cluster의 개수 `K`를 정한다.

예:

`K = 3`

그다음 각 Data Point를 처음에는 Random하게 세 Cluster 중 하나에 할당한다.

```text
Data 1 → Cluster 2
Data 2 → Cluster 1
Data 3 → Cluster 3
...
```

처음 assignment에는 특별한 의미가 없다.

---

# 21. 초기 Cluster가 이상하게 섞이는 이유

처음 Cluster 번호를 Random하게 부여하면 실제 Data의 위치와 관계없이 여러 Cluster의 Data들이 뒤섞여 있다.

이 상태는 최종 clustering 결과가 아니다.

단지 Algorithm을 시작하기 위한 **Initialization**이다.

---

# 22. K-means Step 2 — Centroid 계산

각 Cluster 안에 들어 있는 Data Point들의 평균 위치를 계산한다.

이 평균점을 **Centroid**라고 한다.

2D Feature라면 예를 들어

```text
Cluster 1의 Point

(x₁, y₁)
(x₂, y₂)
(x₃, y₃)

Centroid
=
(x좌표 평균, y좌표 평균)
```

이다.

Cluster가 K개이면 Centroid도 K개 존재한다.

---

# 23. 처음 Centroid들이 서로 가까울 수 있는 이유

첫 Cluster assignment가 Random하게 이루어졌다면 각 색깔의 Data들이 Dataset 전체에 골고루 섞여 있게 된다.

따라서 각각의 평균 위치를 계산하면 Centroid들이 대체로 전체 Data의 중앙 부근에 모일 가능성이 크다.

그러나 Random assignment가 조금씩 다르기 때문에 Centroid의 정확한 위치 역시 조금씩 다르다.

---

# 24. K-means Step 3 — 가장 가까운 Centroid로 재할당

이제 각 Data Point를 보고

> 어떤 Centroid가 가장 가까운가?

를 계산한다.

예:

```text
Data Point A

Distance to Centroid 1 = 2
Distance to Centroid 2 = 7
Distance to Centroid 3 = 4
```

라면

```text
A → Cluster 1
```

로 다시 배정한다.

모든 Data Point에 대해 동일한 작업을 수행한다.

---

# 25. 한 번만 재할당하면 끝나는가?

아니다.

Cluster assignment가 바뀌면 각 Cluster 안의 Data 구성도 달라진다.

그러면 그 Cluster의 평균, 즉 Centroid 역시 달라진다.

따라서 다시

```text
Centroid 계산
↓
Cluster 재할당
↓
Centroid 계산
↓
Cluster 재할당
↓
...
```

을 반복해야 한다.

---

# 26. K-means의 종료 조건

어느 순간 재할당을 수행했는데 이전 iteration과 Cluster assignment가 동일해질 수 있다.

```text
이전 Assignment
=
새로운 Assignment
```

이면 더 이상 Centroid도 의미 있게 바뀌지 않는다.

따라서 Algorithm을 종료한다.

즉

> **Cluster Assignment가 더 이상 바뀌지 않을 때 K-means가 수렴한다.**

---

# 27. K-means의 핵심 반복 구조

시험에서 가장 중요하게 기억할 Algorithm이다.

```text
Random Cluster Assignment
        ↓
Centroid 계산
        ↓
Nearest Centroid 기준 재할당
        ↓
Centroid 재계산
        ↓
재할당
        ↓
...
        ↓
Assignment 변화 없음
        ↓
종료
```

---

# 28. 반복할수록 Within-Cluster Variation은 개선된다

K-means에서는 각 iteration에서 Data를 더 가까운 Centroid의 Cluster로 이동시킨다.

따라서 반복하면서

> **Cluster 내부의 거리 기준 목적값이 계속 개선되는 방향**

으로 진행된다.

강의에서는 iteration을 거듭할수록 Centroid와 관측치의 거리와 Within-Cluster Variation이 줄어드는 방향으로 진행된다고 설명한다.

---

# 29. 그렇다면 K-means는 항상 최적의 답을 찾는가?

아니다.

이것이 K-means의 매우 중요한 특징이다.

초기 Cluster Assignment가 Random하기 때문이다.

```text
Initialization A
→ Final Result A

Initialization B
→ Final Result B
```

처럼 같은 Dataset과 같은 `K`를 사용하더라도 최종 결과가 달라질 수 있다.

---

# 30. 같은 Dataset + 같은 K인데 결과가 달라지는 이유

Algorithm 자체의 반복 과정은 동일하다.

차이를 만드는 것은 시작점이다.

```text
Random Initialization
        ↓
다른 Centroid
        ↓
다른 Reassignment Path
        ↓
다른 Final Cluster
```

따라서 처음 Random Assignment가 최종 결과에 영향을 줄 수 있다.

---

# 31. 색깔이 다르다고 다른 Clustering은 아니다

여러 실행 결과를 비교할 때 색깔 이름에 속으면 안 된다.

예:

실행 A:

```text
왼쪽 집단 = Yellow
오른쪽 집단 = Pink
```

실행 B:

```text
왼쪽 집단 = Pink
오른쪽 집단 = Yellow
```

이면 실제 군집 구조는 동일하다.

단지 Cluster Label만 바뀐 것이다.

---

# 32. Local Minimum

K-means는 매 단계에서 Within-Cluster Variation을 줄이는 방향으로 움직인다.

하지만 그 과정이

> **전역적으로 가장 좋은 값(Global Minimum)**

에 반드시 도달한다는 보장은 없다.

초기화가 좋지 않으면 **Local Minimum**에 갇힐 수 있다.

즉

```text
더 좋은 Clustering이 존재하지만
현재 위치에서 더 이상 개선되지 않아
Algorithm이 종료
```

될 수 있다.

---

# 33. 그래서 K-means는 여러 번 실행해야 한다

실무적으로는 K-means를 한 번만 실행하고 결과를 그대로 사용하는 것이 좋지 않다.

대신

```text
Run 1
Run 2
Run 3
...
```

처럼 다른 Random Initialization으로 여러 번 실행한다.

그리고 각 결과의 **Within-Cluster Variation**을 비교한다.

그중 더 작은 값을 가진 결과를 선택한다.

```text
여러 번 Initialization
        ↓
여러 Clustering 결과
        ↓
Within-Cluster Variation 비교
        ↓
작은 값 선택
```

---

# 34. 2차원 예시만 보고 판단하면 안 된다

강의에서는 이해를 위해 2개의 Feature를 사용하여 Data를 시각화한다.

하지만 실제 Dataset은

```text
10 dimensions
100 dimensions
1000 dimensions
...
```

처럼 훨씬 높은 차원을 가질 수 있다.

이 경우 사람이 눈으로

> 이 clustering이 더 좋아 보인다.

라고 판단할 수 없다.

따라서 실제 분석에서는 Within-Cluster Variation 같은 정량적인 기준이 중요하다.

---

# 35. K-means의 장점

K-means Algorithm은 매우 단순하다.

핵심적으로

```text
평균 계산
+
거리 계산
+
재할당
```

을 반복한다.

따라서

- 이해하기 쉬움
    
- 구현하기 쉬움
    
- 계산이 비교적 빠름
    
- 큰 Data에도 상대적으로 적용하기 편리함
    

이라는 장점이 있다.

---

# 36. K-means의 치명적인 단점

가장 큰 문제는

> **Cluster 개수 K를 Algorithm 실행 전에 알아야 한다.**

는 것이다.

예를 들어 실제 Data 구조를 전혀 모르는 상태에서

```text
K = 3?
K = 5?
K = 10?
```

중 무엇을 사용해야 할지 결정해야 한다.

하지만 Clustering 자체가 Data 구조를 알아보기 위해 수행하는 분석인데 분석 전부터 Cluster 수를 결정해야 한다는 어려움이 생긴다.

---

# 37. Domain Knowledge가 있다면 K를 결정할 수도 있다

예를 들어 Business 목적상 고객을

```text
5개 Segment
```

로 반드시 나누겠다고 정했다면 `K=5`를 사용할 수 있다.

하지만 이러한 사전 요구사항이나 Domain Knowledge가 없다면 적절한 K를 결정하는 것은 어렵다.

특히 고차원 Data에서는 눈으로 Cluster 수를 판단하기 어렵다.

---

# 38. Hierarchical Clustering 등장

K-means의

> K를 미리 지정해야 한다.

라는 문제를 완화할 수 있는 방법 중 하나가 **Hierarchical Clustering(계층적 군집)** 이다.

Hierarchical Clustering에서는 처음부터 최종 Cluster 개수를 지정하지 않아도 된다.

대신 전체 Data가 어떻게 단계적으로 결합되는지를 먼저 만든다.

이 결과를 보고 나중에

```text
2개로 나눌지
3개로 나눌지
4개로 나눌지
```

결정할 수 있다.

---

# 39. Dendrogram

Hierarchical Clustering의 대표적인 결과 표현이 **Dendrogram**이다.

Dendrogram은 Data들이 점점 합쳐지는 과정을 나무 형태로 보여준다.

```text
A   B   C   D

│   │   │   │
└─┬─┘   │   │
  │     └─┬─┘
  └───┬───┘
      │
```

맨 아래에는 개별 Data Point가 있고 위로 올라갈수록 Cluster들이 점점 합쳐진다.

---

# 40. Dendrogram을 이용해 Cluster 수 결정

Dendrogram을 만든 뒤 원하는 높이에서 자를 수 있다.

예:

```text
여기서 자름
→ 2개 Cluster

더 아래에서 자름
→ 3개 Cluster
```

따라서 Hierarchical Clustering에서는 전체 구조를 먼저 확인한 뒤 **사후적으로 Cluster 개수를 선택할 수 있다.**

이 점이 K-means와 매우 큰 차이다.

---

# 41. Dendrogram의 높이

Dendrogram에서 branch가 결합되는 높이에도 의미가 있다.

높이가 크게 증가한 지점은

> **서로 꽤 떨어져 있던 Cluster들이 그 단계에서 합쳐졌다는 신호**

로 볼 수 있다.

따라서 큰 높이 차이가 발생하는 구간은 Cluster를 나누는 기준을 선택할 때 참고할 수 있다.

---

# 42. Hierarchical Clustering의 기본 방향

이번 강의에서 다루는 방법은 **Bottom-Up 방식**이다.

처음에는 Data가 `n`개라면

```text
Cluster도 n개
```

라고 생각한다.

각 Data Point가 자기 자신만 포함한 하나의 Cluster인 것이다.

```text
Data 1 → Cluster 1
Data 2 → Cluster 2
...
Data n → Cluster n
```

---

# 43. 이후 가장 가까운 Cluster부터 합친다

처음에는 모든 Cluster 사이의 거리를 계산한다.

그중 가장 가까운 두 Cluster를 찾는다.

```text
가장 가까운 Cluster A
+
가장 가까운 Cluster B
        ↓
하나의 Cluster로 Merge
```

한다.

그다음 다시 현재 존재하는 Cluster들의 거리를 계산하고 가장 가까운 두 Cluster를 합친다.

이를 반복한다.

---

# 44. Hierarchical Clustering 전체 과정

```text
n개의 Data
↓
각 Data를 각각 하나의 Cluster로 취급
↓
Cluster 사이 Pairwise Distance 계산
↓
가장 가까운 두 Cluster Merge
↓
다시 Cluster 사이 Distance 계산
↓
가장 가까운 두 Cluster Merge
↓
반복
↓
최종적으로 하나의 큰 Cluster
```

즉 강의에서 한 줄로 표현하는 핵심은

> **Hierarchical Clustering은 Cluster들을 점진적으로 합쳐가는 과정이다.**

---

# 45. 9개의 Data Point 예제

Data Point가 9개라면 처음에는

```text
Cluster = 9개
```

다.

가장 가까운 두 Data Point가 예를 들어 `7`과 `5`라면

```text
{7} + {5}
→ {7,5}
```

로 합친다.

이제 `{7,5}`는 하나의 Cluster다.

더 이상 7과 5를 별개의 Cluster처럼 취급하지 않는다.

다음으로 가장 가까운 Cluster를 찾아 계속 결합한다.

---

# 46. 여기서 새로운 문제가 발생한다

Cluster 하나에 Data가 한 개씩만 들어 있을 때는 두 Cluster 사이의 거리가 단순하다.

```text
Point A ↔ Point B
```

의 거리를 계산하면 된다.

그런데

```text
Cluster A = {5, 7}

Cluster B = {8}
```

이라면

> Cluster A와 8의 거리는 어떻게 정의해야 하는가?

라는 문제가 생긴다.

가능한 생각:

```text
8 ↔ 5 거리?
8 ↔ 7 거리?
8 ↔ {5,7}의 평균적인 거리?
```

즉 **Cluster와 Cluster 사이의 거리 정의**가 필요하다.

---

# 47. Linkage

Hierarchical Clustering에서 Cluster 사이의 거리를 정의하는 방식을 **Linkage**라고 한다.

강의에서는 대표적으로 세 가지를 설명한다.

```text
Single Linkage
Complete Linkage
Average Linkage
```

---

# 48. Single Linkage

두 Cluster에 포함된 모든 Pairwise Distance 중 **가장 가까운 거리**를 Cluster 간 거리로 사용한다.

```text
Cluster A    Cluster B

●              ▲
●──────────────▲  ← 가장 가까운 pair
●              ▲
```

즉

> **두 Cluster의 가장 가까운 두 Point 기준**

이다.

---

# 49. Complete Linkage

두 Cluster 사이의 모든 Pairwise Distance 중 **가장 먼 거리**를 사용한다.

```text
Cluster A    Cluster B

●──────────────▲  ← 가장 먼 pair
●          ▲
●      ▲
```

즉

> **두 Cluster의 가장 멀리 떨어진 두 Point 기준**

이다.

---

# 50. Average Linkage

두 Cluster 사이에 존재하는 Pairwise Distance들의 **평균**을 이용한다.

즉

```text
Cluster A의 모든 Point
↕
Cluster B의 모든 Point

거리들의 평균
```

을 Cluster 간 거리로 사용한다.

---

# 51. Linkage 비교

|Linkage|Cluster 간 거리 정의|
|---|---|
|Single|가장 가까운 Point 쌍의 거리|
|Complete|가장 먼 Point 쌍의 거리|
|Average|모든 Pairwise Distance의 평균|

어떤 Linkage를 선택하느냐에 따라 결과가 달라진다.

---

# 52. 같은 Data라도 Linkage가 다르면 Dendrogram이 달라진다

동일한 Dataset에

```text
Single Linkage
Complete Linkage
Average Linkage
```

를 적용하면 서로 다른 Cluster Merge 순서가 발생할 수 있다.

따라서 Dendrogram 역시 크게 달라질 수 있다.

즉 Hierarchical Clustering도

> **하나의 절대적인 Clustering 결과를 자동으로 알려주는 Algorithm**

은 아니다.

---

# 53. 비지도학습에서는 사람이 선택해야 하는 것이 많다

지도학습에서는 정답 Label을 이용해

```text
Accuracy
Loss
```

등으로 정량적인 비교가 가능하다.

하지만 비지도학습에는 Label이 없다.

따라서 Clustering에서는 사람이

- Feature
    
- Distance
    
- K
    
- Linkage
    
- 결과의 해석
    

등을 선택해야 한다.

강의에서

> “비지도학습은 결정할 것이 많다.”

고 설명하는 이유다.

---

# 54. 여러 방법을 시도해야 한다

K-means에서는 Random Initialization 때문에 여러 결과가 나올 수 있다.

Hierarchical Clustering에서는 Linkage에 따라 결과가 달라질 수 있다.

따라서

> **하나의 설정만 한 번 실행하고 그것을 정답이라고 생각해서는 안 된다.**

가능하면 여러 설정과 실행을 비교하고 문제에 가장 적합한 결과를 선택해야 한다.

---

# 55. 매우 중요 — Clustering 전에 Feature Scale을 맞춰야 한다

Clustering은 **Distance**를 이용한다.

따라서 Feature마다 Scale이 크게 다르면 문제가 발생한다.

예:

```text
Feature 1
0 ~ 1

Feature 2
-1,000,000 ~ 1,000,000
```

Euclidean Distance를 계산하면 Feature 2가 거리에 거의 모든 영향을 미칠 수 있다.

그러면 Feature 1의 정보가 사실상 무시될 수 있다.

---

# 56. Standardization의 필요성

이를 방지하기 위해 Clustering 전에 Feature Scale을 맞춰야 한다.

강의에서는

```text
각 값에서 평균을 빼고
표준편차로 나눈다.
```

는 방식의 Standardization을 설명한다.

즉 Feature마다 단위와 Scale이 달라서 Distance 계산을 지배하지 않도록 해야 한다.

```text
서로 다른 Scale
       ↓
Standardization
       ↓
Feature Scale 정렬
       ↓
Distance 기반 Clustering
```

---

# 57. Clustering에서 적절한 Cluster 개수는 자동으로 정답이 나오지 않는다

K-means에서는 K를 미리 선택해야 한다.

Hierarchical Clustering에서는 Dendrogram을 본 뒤 사후적으로 선택할 수 있다.

하지만 Hierarchical Clustering이라고 해서

> **올바른 Cluster 개수를 자동으로 알려주는 것은 아니다.**

Dendrogram이나 Linkage 결과를 보고 분석자가 판단해야 한다.

즉 여전히 합의된 절대적 정답은 없다.

---

# 58. 그럼 항상 Hierarchical Clustering을 사용하면 되지 않을까?

아니다.

Hierarchical Clustering에는 비용이 있다.

Cluster 사이의 Pairwise Distance를 계속 계산해야 하기 때문이다.

따라서 K-means보다 일반적으로 계산량이 더 크다.

---

# 59. K-means와 Hierarchical Clustering의 Trade-off

## K-means

장점:

- Algorithm 단순
    
- 빠름
    
- 구현 쉬움
    
- 비교적 계산 효율적
    

단점:

- K를 미리 지정
    
- Random Initialization에 따라 결과 달라질 수 있음
    
- Local Minimum 가능
    

---

## Hierarchical Clustering

장점:

- K를 미리 지정할 필요 없음
    
- Dendrogram으로 전체 계층 구조 확인
    
- Cluster 수를 사후적으로 결정 가능
    

단점:

- Pairwise Distance 계산이 많이 필요
    
- K-means보다 계산량이 큼
    
- Linkage 선택에 따라 결과가 크게 달라질 수 있음
    

---

# 60. “No Free Lunch” 관점

강의에서는 이 차이를 **No Free Lunch**의 관점과 연결한다.

즉

> **어떤 방법도 모든 장점을 공짜로 얻지는 못한다.**

K-means는 빠르고 단순하지만 K를 미리 알아야 한다.

Hierarchical Clustering은 사후적으로 Cluster 구조를 분석할 수 있지만 계산 비용이 더 크다.

즉 Algorithm 선택에는 Trade-off가 존재한다.

---

# 61. K-means와 Hierarchical Clustering 최종 비교

|항목|K-means|Hierarchical|
|---|---|---|
|지도 여부|비지도|비지도|
|Label 필요|X|X|
|K 사전 지정|필요|필요 없음|
|기본 동작|Centroid와 Assignment 반복|가까운 Cluster들을 반복적으로 Merge|
|결과|K개의 Cluster|Dendrogram|
|Cluster 수 결정|실행 전|실행 후 가능|
|초기화 영향|있음|강의에서 K-means처럼 Random Initialization 문제를 중심으로 다루지 않음|
|중요한 설정|K, Initialization|Linkage, Distance|
|계산량|상대적으로 작음|상대적으로 큼|

---

# 62. Classification과 Clustering 최종 비교

|Classification|Clustering|
|---|---|
|지도학습|비지도학습|
|정답 Label 있음|정답 Label 없음|
|정해진 Category 예측|Data의 집단 구조 탐색|
|정답과 Prediction 비교 가능|절대적인 정답이 없을 수 있음|
|Accuracy 등의 평가 가능|Distance·내부 변동·Domain 목적 등을 고려|

---

# 63. K-means에서 반드시 기억해야 할 4단계

시험 관점에서는 다음 순서를 확실히 기억해야 한다.

```text
1. K 결정

2. Cluster Random Initialization

3. 반복
   ├─ Centroid 계산
   └─ 가장 가까운 Centroid로 Data 재할당

4. Assignment가 변하지 않으면 종료
```

---

# 64. K-means에서 Centroid란?

Centroid는

> **현재 Cluster 내부 Data Point들의 평균 위치**

다.

즉 Centroid를 누군가 별도로 Labeling하는 것이 아니라 현재 Cluster assignment로부터 계산한다.

그리고 다시 이 Centroid를 이용해 Cluster assignment를 변경한다.

따라서

```text
Assignment
→ Centroid

Centroid
→ Assignment
```

가 서로 반복적으로 영향을 준다.

---

# 65. K-means의 핵심 목적

K-means의 기본적인 방향은

> **같은 Cluster 내부의 Data들이 서로 가까워지도록 만드는 것**

이다.

따라서 Within-Cluster Variation을 감소시키는 방향으로 반복한다.

그러나 이것이 항상 Global Optimum을 보장하지는 않는다.

---

# 66. Random Initialization이 중요한 이유

처음의 Random Cluster Assignment가 달라지면

```text
초기 Centroid
```

가 달라지고,

그 결과

```text
Reassignment 경로
```

가 달라질 수 있다.

결국 최종 Cluster도 달라질 수 있다.

따라서 K-means에서

> **여러 번 다른 Initialization으로 실행하고 좋은 결과를 고른다.**

가 중요한 실전 전략이다.

---

# 67. K-means에서 잘못 이해하기 쉬운 점

## “K-means는 실행할 때마다 결과가 항상 다르다.”

아니다.

Random Initialization 때문에 **달라질 수 있는 것**이지 반드시 매번 다른 것은 아니다.

서로 다른 Initialization에서도 같은 최종 Solution으로 수렴할 수 있다.

---

# 68. Hierarchical Clustering의 핵심 한 문장

> **처음에는 각 Data Point를 하나의 Cluster로 보고, 가장 가까운 Cluster끼리 계속 합쳐 최종적으로 하나의 Cluster가 될 때까지 진행한다.**

그리고 이 Merge history 전체가 Dendrogram에 기록된다.

---

# 69. Dendrogram을 왜 만드는가?

Dendrogram에는

> **Data들이 어떤 순서와 어느 정도의 거리에서 합쳐졌는가**

가 표현된다.

따라서 전체 계층 구조를 본 뒤

```text
여기서 자르면 2개
여기서 자르면 3개
```

처럼 원하는 Cluster resolution을 사후적으로 선택할 수 있다.

---

# 70. Hierarchical Clustering에서 중요한 질문

Cluster가 여러 Data Point를 가지고 있다면

> **Cluster A와 Cluster B 사이의 거리는 정확히 무엇인가?**

를 정의해야 한다.

이 질문에 대한 서로 다른 답이

```text
Single
Complete
Average
```

Linkage다.

따라서 **Linkage는 Hierarchical Clustering의 핵심 설정**이다.

---

# 71. 거리의 동점이 생긴다면?

강의 중 동일한 Cluster distance가 정확히 발생할 수 있는지에 대한 질문도 나온다.

연속적인 실수 Data에서 정확히 같은 거리가 발생할 확률은 매우 낮게 본다.

하지만 정수 Data 등에서는 같은 Distance가 나올 수 있다.

이 경우 강의에서는

> **Tie-break를 하면 된다.**

고 설명한다.

---
