## 시험 범위 포함 내용
| 시험 토픽                  | 강의 내용                                                            |
| ---------------------- | ---------------------------------------------------------------- |
| **회귀 문제**              | Output이 숫자인 지도학습 문제를 Regression으로 정의하고 다양한 사례를 설명                |
| **분류 문제**              | Output이 Category/Class인 지도학습 문제를 Classification으로 정의             |
| **정밀도 계산**             | Confusion Matrix의 TP/FP를 이용해 `Precision = TP/(TP+FP)` 계산         |

| **Distribution Shift** | Train과 Test의 분포가 다른 경우 성능 저하가 발생할 수 있으며 Overfitting과 구별해야 한다고 설명 |
# 0. 강의 전체 개요

이번 강의에서는 Machine Learning의 대표적인 학습 방식인 **Supervised Learning(지도학습)** 을 다룬다.

전체 흐름은 다음과 같다.

```text
지도학습이란?
    ↓
Feature + Label
    ↓
회귀 / 분류
    ↓
모델의 예측
    ↓
Loss Function
    ↓
회귀 평가
MSE / RMSE / R²
    ↓
분류 평가
Accuracy / Confusion Matrix
Precision / Recall / F1
    ↓
Cross Entropy
    ↓
학습의 진짜 목적
Generalization
    ↓
Overfitting / Underfitting
```

가장 중요한 출발점은 다음이다.

> **지도학습은 입력과 정답 label을 가지고 예측 규칙을 학습하는 방법이다.**

하지만 최종 목표는 훈련 데이터 자체를 잘 맞히는 것이 아니다.

> **훈련 과정에서 보지 못한 새로운 데이터에서도 잘 예측하는 것이 최종 목적이다.**

---

# 1. 지도학습의 목적

지도학습에서는 정답 label이 존재한다.

모델은 입력 `x`를 받고 출력값을 예측한 뒤 그 예측값이 실제 label에 가까워지도록 학습한다.

```text
Feature x
   ↓
 Model
   ↓
Prediction ŷ
   ↕
True Label y
```

그런데 훈련 데이터에서만 잘 맞는 모델을 만드는 것이 최종 목적은 아니다.

앞 차시에서 배운 표현으로 연결하면 우리의 목적은

> **미지의 참함수 `f*`에 가까운 함수를 학습하는 것**

이다.

그래야 학습할 때 본 적 없는 새로운 `x`가 들어와도 좋은 예측을 할 수 있다.

---

# 2. 새로운 데이터에서 잘해야 한다

강의에서는 고객 이탈 예측을 예로 든다.

현재까지 가지고 있는 것은 어제까지의 고객 데이터라고 하자.

이 데이터를 분석하는 이유는 이미 지나간 고객들을 다시 예측하기 위해서가 아니다.

진짜 목적은

```text
과거 Customer Data
       ↓
      학습
       ↓
앞으로 들어올 Customer
       ↓
이탈 가능성 예측
```

이다.

즉 아직 관측하지 않은 고객에게도 예측이 잘 되어야 한다.

---

# 3. 금융 거래 사기 예측도 같은 구조다

과거의

- 정상 거래
    
- 사기 거래
    
- transaction error
    

데이터를 이용해 학습했다고 하자.

우리가 원하는 것은 이미 알고 있는 과거 거래를 다시 맞히는 것이 아니다.

새로운 거래가 들어왔을 때

```text
정상 거래인가?
사기 거래인가?
```

를 제대로 판단하는 것이다.

따라서 지도학습의 핵심 목적은 항상

> **Training Data를 이용해서 아직 보지 않은 데이터에 대한 Prediction 능력을 얻는 것**

이다.

---

# 4. Supervised Learning에서 “지도”란 무엇인가?

Supervised Learning의 `Supervision`은 **정답 label이 존재한다는 것**을 의미한다.

예를 들어 고양이와 강아지 이미지를 학습시킨다고 하자.

Training Data:

```text
[고양이 이미지] → Cat
[강아지 이미지] → Dog
[고양이 이미지] → Cat
[강아지 이미지] → Dog
...
```

이미지와 함께 정답 label이 주어진다.

이 정답을 이용하여 모델을 학습한다.

---

# 5. Training Data와 Test Data

모델을 학습한 뒤에는 training에 사용하지 않은 새로운 data로 평가해야 한다.

```text
Training Data
   ↓
Model 학습
   ↓
Learned Model
   ↓
Test Data
   ↓
Prediction
```

Test Data는 모델이 학습할 때 사용하지 않은 데이터다.

왜 굳이 새로운 데이터를 사용할까?

우리가 알고 싶은 것은

> **모델이 이미 본 데이터를 외웠는지가 아니라 처음 보는 데이터에서도 제대로 예측하는가**

이기 때문이다.

---

# 6. 지도학습의 두 가지 대표 문제

지도학습은 출력의 형태를 기준으로 크게 두 가지로 나눌 수 있다.

```text
Supervised Learning
├─ Regression
└─ Classification
```

### Regression

출력값이 **숫자**다.

### Classification

출력값이 **범주(Category / Class)** 다.

---

# 7. Regression

Regression은

> **예측하고 싶은 Output이 숫자인 지도학습 문제**

다.

중요한 점은 input의 형태가 아니라 **output의 형태**를 기준으로 판단한다는 것이다.

---

# 8. Regression 예시 — 공부시간과 시험점수

다음 데이터가 있다고 하자.

```text
공부시간    시험점수

1시간   →   10점
2시간   →   20점
3시간   →   30점
```

질문:

```text
4시간 공부하면?
```

예측:

```text
40점
```

여기서

- 공부시간 = Feature
    
- 시험점수 = Label
    

이다.

Label인 시험점수가 숫자이므로 **Regression 문제**다.

---

# 9. Regression은 Output 기준이다

강의에서 반복적으로 강조한다.

```text
Input이 숫자인가?
```

가 기준이 아니다.

```text
Output이 숫자인가?
```

가 기준이다.

따라서

> **숫자 값을 출력하는 지도학습 문제는 Regression**

으로 이해하면 된다.

---

# 10. Classification

Classification은

> **예측하고 싶은 Output이 어떤 Category 또는 Class인 지도학습 문제**

다.

예:

```text
Image
 ↓
Dog / Cat / Hamster
```

여기서 이미지는 Input이고

```text
Dog
Cat
Hamster
```

가 출력 category다.

따라서 Classification이다.

---

# 11. Spam Classification

이메일을 예로 들면 Feature는

- 제목
    
- 발신자 주소
    
- 이메일 내용
    
- 단어 빈도
    

등일 수 있다.

Output은

```text
Spam
Normal
```

이다.

숫자를 예측하는 것이 아니라 두 class 중 하나를 선택하기 때문에 Classification이다.

---

# 12. Regression과 Classification 최종 구분

|문제|Output|
|---|---|
|Regression|숫자|
|Classification|범주 / Category|

즉 **Feature가 무엇인지는 Regression/Classification을 구분하는 기준이 아니다.**

---

# 13. 왜 Loss Function이 필요한가?

모델은 어떤 값을 예측한다.

그렇다면 모델이

> 잘했는가? 못했는가?

를 판단할 숫자가 필요하다.

이를 담당하는 것이 **Loss Function**이다.

Loss Function은

> **모델의 예측이 실제 정답에서 얼마나 벗어났는지를 숫자로 나타내는 함수**

다.

---

# 14. Prediction과 True Label

실제 Label:

`y`

모델의 Prediction:

`ŷ`

로 표현한다.

`ŷ`는 **y-hat**이라고 읽는다.

모자(hat)가 붙었다는 것은

> **실제 y가 아니라 y에 대한 추정값**

이라는 뜻이다.

```text
y  = 실제 정답
ŷ  = 모델의 예측값
```

---

# 15. 예측 오차

예측값과 실제값의 차이를 생각할 수 있다.

`ŷ - y`

또는

`y - ŷ`

이다.

예를 들어

```text
실제 점수 = 45
예측 점수 = 35
```

라면 차이가 존재한다.

이 차이가 클수록 모델이 잘못 예측했다는 뜻이다.

---

# 16. 단순히 차이를 모두 더하면 안 되는 이유

예측 오차에는

```text
+10
-10
```

처럼 양수와 음수가 존재할 수 있다.

그냥 더하면

```text
+10 + (-10) = 0
```

이 되어 실제로는 두 번 크게 틀렸는데도 error가 없는 것처럼 보일 수 있다.

따라서 부호를 제거하는 방법이 필요하다.

Regression에서는 대표적으로 **제곱**을 사용한다.

---

# 17. Mean Squared Error(MSE)

Regression에서 대표적으로 사용하는 Loss가 **Mean Squared Error**다.

개념적으로

`MSE = (1/n) Σ (yᵢ - ŷᵢ)²`

이다.

각 데이터에 대해

1. 실제값과 예측값의 차이를 계산
    
2. 그 차이를 제곱
    
3. 모든 데이터에 대해 합산
    
4. 데이터 수로 나누어 평균
    

한다.

---

# 18. 왜 제곱하는가?

강의에서는 세 가지 직관을 설명한다.

## 1. 부호 제거

Positive Error와 Negative Error 모두 틀린 것이다.

제곱하면 모두 양수가 된다.

## 2. 큰 Error에 더 큰 Penalty

```text
Error = 2
→ 4

Error = 10
→ 100
```

오차가 커질수록 penalty가 더 빠르게 증가한다.

따라서 크게 잘못된 prediction에 강한 penalty를 줄 수 있다.

## 3. 수학적으로 다루기 편리

제곱 함수는 이후 optimization에서 미분하기 편리하다는 장점도 있다.

강의에서는 현재 단계에서는 앞의 직관 정도를 이해하면 충분하다고 설명한다.

---

# 19. Loss는 작을수록 좋다

Loss의 기본 해석은 간단하다.

```text
Loss 큼
→ Prediction이 정답에서 멀다
→ 나쁨

Loss 작음
→ Prediction이 정답에 가깝다
→ 좋음
```

따라서 학습은

> **Loss Function의 값을 낮추는 방향으로 Model을 조정하는 과정**

이라고 볼 수 있다.

---

# 20. 매우 중요 — 예측 오차와 ε는 다르다

앞 차시에서 배운 식:

`y = f*(x) + ε`

가 있었다.

여기서 `ε`는 True Function과 실제 관측값의 차이다.

이번에 계산하는

`y - ŷ`

는 **Model Prediction과 실제 관측값의 차이**다.

둘은 전혀 다른 개념이다.

```text
True Function f*(x)
       ↓
       │ ε
       ↓
Observed y
       ↑
       │ Prediction Error
       ↑
Predicted ŷ
```

---

# 21. ε는 학습해서 줄일 수 없는 Error

`ε`는

- Measurement Noise
    
- 현실의 Randomness
    
- 관측되지 않은 요인
    

등으로 인해 이미 데이터에 존재한다.

따라서 우리가 학습을 아무리 잘하더라도 `ε` 자체를 없앨 수 없다.

심지어 이상적으로

`f = f*`

를 정확히 학습했다고 해도

`y = f*(x) + ε`

이므로 `ε`는 그대로 존재한다.

강의에서는 이를 **줄일 수 없는 오차(Irreducible Error)** 로 설명한다.

---

# 22. 반면 Prediction Error는 줄일 수 있다

예측 오차

`y - ŷ`

는 모델에 따라 달라진다.

나쁜 Model:

```text
ŷ가 y에서 멀다
→ Prediction Error 큼
```

좋은 Model:

```text
ŷ가 y에 가깝다
→ Prediction Error 작음
```

따라서 이 error는 학습을 통해 줄일 수 있다.

---

# 23. Regression 예시 — 집값 예측

집값을 예측한다고 하자.

Feature:

- 면적
    
- 방 개수
    
- 건물 연식
    
- 지역 등의 정보
    

Label:

- 실제 집값
    

이다.

집값은 숫자이므로 Regression 문제다.

---

# 24. Regression 예시 — 광고비와 매출

또 다른 예:

Feature:

- TV 광고비
    
- Radio 광고비
    
- Internet 광고비
    

Label:

- Sales
    

이다.

다음 달 광고 예산을 정했을 때

> 예상 매출이 얼마인가?

를 예측한다.

매출이 숫자이므로 역시 Regression이다.

---

# 25. MSE를 그림으로 이해하기

Linear Regression 모델이 다음과 같은 직선이라고 하자.

```text
       ● 실제 y
       │
       │ Error
       │
───────●────── Prediction ŷ on Model
```

Model이 직선이라면 모든 `ŷ`는 그 직선 위에 존재한다.

각 `xᵢ`에서

- 실제값 `yᵢ`
    
- 예측값 `ŷᵢ`
    

사이의 수직 차이가 예측 Error가 된다.

각 error를 제곱하고 평균한 것이 MSE다.

---

# 26. MSE 해석

MSE가 작다면

> 현재 모델이 주어진 데이터의 실제 y 값에 비교적 가까운 prediction을 만들었다.

는 의미다.

따라서

```text
MSE ↓
→ Data fitting 관점에서 좋음
```

이다.

---

# 27. RMSE

MSE에는 한 가지 특징이 있다.

Error를 제곱했기 때문에 원래 y의 단위와 달라진다.

예를 들어 y가 원 단위라면 MSE는

`원²`

단위가 된다.

이를 다시 원래 단위로 되돌리기 위해 제곱근을 취한다.

`RMSE = √MSE`

이를 **Root Mean Squared Error**라고 한다.

---

# 28. RMSE의 장점

RMSE는 원래 Label과 동일한 scale로 해석할 수 있다.

예를 들어 집값 prediction에서

```text
RMSE = 10,000,000원
```

이라면

> 실제 집값과 예측값이 대략 천만 원 정도의 규모로 차이가 난다.

는 식으로 해석할 수 있다.

---

# 29. 결정계수 R²

Regression에서 또 많이 사용하는 평가 지표가 **Coefficient of Determination**, 즉 **R²**다.

강의에서는 특히 Linear Regression뿐 아니라 일반적인 Regression 평가에서도 자주 사용하는 지표라고 설명한다.

기본 식:

`R² = 1 - (모델의 제곱오차 / 평균만 사용했을 때의 제곱오차)`

로 이해하면 된다.

---

# 30. R²의 핵심 — Benchmark가 평균 예측

R²를 이해하려면 가장 단순한 baseline을 생각해야 한다.

아무런 머신러닝 모델도 만들지 않았다고 하자.

그러면 가장 단순한 prediction은 모든 데이터에 대해

`ŷ = ȳ`

즉 **y의 평균값**만 예측하는 것이다.

```text
모든 x에 대해
Prediction = y 평균
```

이다.

---

# 31. R²가 비교하는 두 Error

R²에서는 크게 두 가지 error를 비교한다.

### Model Error

`Σ(yᵢ - ŷᵢ)²`

실제 모델의 prediction error다.

### Baseline Error

`Σ(yᵢ - ȳ)²`

아무 modeling 없이 평균만 prediction했을 때의 error다.

따라서 R²는

> **평균만 예측하는 가장 단순한 방법보다 우리가 만든 Model이 얼마나 잘했는가**

를 보여준다.

---

# 32. R² 해석

일반적으로

`R² → 1`

에 가까울수록 좋다.

Model Error가 매우 작아진다면

```text
Model Error / Baseline Error → 0
```

이므로

`R² → 1`

이 된다.

강의에서는 이를 데이터 y에 존재하는 variability를 모델이 얼마나 설명할 수 있는지를 나타내는 값으로 설명한다.

---

# 33. R²는 음수가 될 수도 있다

R²가 반드시 0과 1 사이인 것은 아니다.

만약 모델이 너무 형편없어서

```text
Model Error
>
평균만 prediction한 Error
```

라면

`R² < 0`

이 될 수 있다.

즉

> **복잡한 모델을 만들었지만 그냥 모든 값을 평균으로 예측하는 것보다 못하다**

는 뜻이다.

강의에서도 실제 모델에서 R²가 음수가 나오는 경우가 있을 수 있다고 설명한다.

---

# 34. MSE와 R²의 차이

두 지표는 서로 다른 장점이 있다.

## MSE / RMSE

실제 prediction error의 크기를 보여준다.

특히 RMSE는 원래 Label의 단위를 유지할 수 있어 실질적인 error 규모를 이해하기 좋다.

## R²

평균값 baseline과 비교했을 때 모델이 얼마나 설명력을 가지는지를 보여준다.

Scale이 비교적 직관적이고 서로 다른 모델의 성능을 비교하기 좋다.

강의에서는 한 가지만 사용하는 것보다 **둘을 함께 보고하는 것이 좋다**고 설명한다.

---

# 35. Regression 평가 정리

|지표|의미|좋은 방향|
|---|---|---|
|MSE|평균 제곱 예측 오차|작을수록 좋음|
|RMSE|MSE의 제곱근|작을수록 좋음|
|R²|평균 예측 대비 모델 설명력|1에 가까울수록 좋음|

---

# 36. Classification 다시 보기

Classification은 Feature를 입력받아 Category를 출력하는 지도학습 문제다.

예:

```text
Binary Classification
Dog / Cat
Spam / Normal
Disease / Healthy
```

Class가 두 개면 **Binary Classification**이다.

여러 개면 **Multi-class Classification**이다.

---

# 37. Binary Classification

Class가 두 개인 문제다.

예:

```text
Cat / Dog
Spam / Normal
Positive / Negative
```

---

# 38. Multi-class Classification

Class가 두 개보다 많은 문제다.

예:

```text
Dog
Cat
Hamster
```

또는 학생의 성적을

```text
A
B
C
D
F
```

로 예측하는 문제도 Classification이다.

입력으로

- 출석률
    
- 과제 점수
    
- 중간고사 점수
    
- 기말고사 점수
    

등의 숫자가 들어가더라도 Output이 letter grade라는 category이므로 Classification이다.

---

# 39. 반드시 기억 — Regression/Classification은 Label 기준

Feature가

- 숫자
    
- Text
    
- Image
    
- Category
    

중 무엇이든 상관없다.

문제 유형을 결정하는 것은 **Label의 형태**다.

```text
Label = 숫자
→ Regression

Label = Category
→ Classification
```

---

# 40. Classification에서는 MSE나 R²를 그대로 사용할 수 없다

예를 들어 실제 label이

```text
Cat
```

이고 예측이

```text
Dog
```

라고 하자.

```text
Cat - Dog
```

라는 숫자 차이를 계산할 수 없다.

따라서 Regression에서처럼 y값의 숫자 차이를 직접 이용하는 평가법만 사용할 수는 없다.

Classification에는 별도의 평가 방법이 필요하다.

---

# 41. 가장 단순한 Classification 평가 — Accuracy

가장 직관적인 지표는 **Accuracy**다.

예측 label과 실제 label이 같은지 확인한다.

```text
Prediction = Cat
Actual     = Cat
→ Correct

Prediction = Dog
Actual     = Cat
→ Wrong
```

따라서

`Accuracy = 맞힌 개수 / 전체 개수`

이다.

---

# 42. Indicator Function

강의에서는 Accuracy 식에서 **Indicator Function**을 소개한다.

조건이 참이면

`1`

조건이 거짓이면

`0`

을 출력하는 함수다.

예:

```text
I(ŷᵢ = yᵢ)

맞음 → 1
틀림 → 0
```

이를 모든 데이터에 대해 합하고 평균하면 Accuracy가 된다.

Indicator function은 머신러닝과 통계 수식에서 자주 사용되므로 기억할 필요가 있다.

---

# 43. Accuracy 99%면 항상 좋은가?

아니다.

그 이유가 **Imbalanced Data**다.

예를 들어 질병 진단 데이터가 다음과 같다고 하자.

```text
Healthy  = 99%
Disease  = 1%
```

모델이 아무 학습도 하지 않고 무조건

```text
Healthy
```

라고 prediction하면 Accuracy는

`99%`

다.

하지만 실제 환자를 단 한 명도 찾아내지 못한다.

따라서 높은 Accuracy만으로 좋은 classifier라고 판단할 수 없다.

---

# 44. Confusion Matrix

이 문제를 더 자세히 보기 위해 **Confusion Matrix**를 사용한다.

Binary Classification에서는

- 실제 Positive / Negative
    
- 예측 Positive / Negative
    

조합을 네 가지로 나눈다.

```text
                   Predicted
                Positive   Negative
Actual Positive    TP         FN
Actual Negative    FP         TN
```

---

# 45. True Positive(TP)

실제 값:

`Positive`

Prediction:

`Positive`

인 경우다.

```text
Actual: Disease
Predict: Disease
```

올바른 prediction이다.

---

# 46. True Negative(TN)

실제 값:

`Negative`

Prediction:

`Negative`

다.

```text
Actual: Healthy
Predict: Healthy
```

역시 올바른 prediction이다.

---

# 47. False Negative(FN)

실제 값은 Positive인데 모델이 Negative라고 잘못 prediction했다.

```text
Actual: Disease
Predict: Healthy
```

즉 실제 Positive를 놓친 것이다.

---

# 48. False Positive(FP)

실제 값은 Negative인데 Positive라고 prediction했다.

```text
Actual: Healthy
Predict: Disease
```

즉 없는 Positive를 있다고 판단한 것이다.

---

# 49. Confusion Matrix에서 좋은 방향

```text
TP ↑
TN ↑

FP ↓
FN ↓
```

가 이상적이다.

Confusion Matrix의 대각선에 있는

- TP
    
- TN
    

은 correct prediction이고

off-diagonal에 있는

- FP
    
- FN
    

은 error다.

---

# 50. Precision

Precision은

> **모델이 Positive라고 예측한 것들 중 실제 Positive가 얼마나 되는가**

를 나타낸다.

`Precision = TP / (TP + FP)`

예:

```text
모델이 암이라고 100명 진단
실제 암 환자 90명
```

이면 Precision은 높다.

질문 형태로 기억하면 쉽다.

> **“내가 Positive라고 한 것 중 몇 개가 진짜 Positive인가?”**

---

# 51. Recall / Sensitivity

Recall은

> **실제 Positive들 가운데 모델이 얼마나 찾아냈는가**

를 나타낸다.

`Recall = TP / (TP + FN)`

Sensitivity라고도 부른다.

질문 형태:

> **“실제로 존재하는 Positive 중 몇 개를 놓치지 않고 찾아냈는가?”**

---

# 52. Precision과 Recall 비교

```text
Precision
Prediction Positive 기준

Recall
Actual Positive 기준
```

|지표|기준 질문|
|---|---|
|Precision|내가 Positive라고 한 것 중 진짜는 얼마나 되는가?|
|Recall|진짜 Positive 중 내가 얼마나 찾아냈는가?|

둘 다 1에 가까울수록 좋다.

---

# 53. F1 Score

Precision과 Recall을 하나의 숫자로 결합한 지표가 **F1 Score**다.

강의에서는 Precision과 Recall의 조화평균으로 설명한다.

`F1 = 2PR / (P + R)`

여기서

- `P` = Precision
    
- `R` = Recall
    

이다.

F1 역시 높을수록 좋다.

---

# 54. Imbalanced Data에서는 Accuracy만 보면 안 된다

Class 비율이 불균형한 경우에는

- Accuracy
    
- Precision
    
- Recall
    
- F1 Score
    
- Confusion Matrix
    

를 함께 확인해야 한다.

Dominant class만 계속 prediction하는 모델은 Accuracy는 높을 수 있지만 Recall이나 F1이 매우 낮을 수 있다.

따라서

> **분류 성능은 하나의 숫자로만 판단하면 안 되는 경우가 많다.**

---

# 55. Evaluation Metric과 Training Loss는 다를 수 있다

Confusion Matrix, Precision, Recall, Accuracy 등은 모델의 결과를 평가하기 좋다.

하지만 실제 training 과정에서는 gradient를 이용해 parameter를 update해야 한다.

따라서 일반적으로

```text
Confusion Matrix 자체를 직접 최적화
```

하지는 않는다.

Classification training에서는 대표적으로 **Cross Entropy Loss**를 사용한다.

---

# 56. Cross Entropy의 핵심 직관

Classification model은 보통 각 class에 probability를 부여한다.

예를 들어 실제 정답이 Spam이라고 하자.

### 좋은 Prediction

```text
Spam   = 0.9
Normal = 0.1
```

### 나쁜 Prediction

```text
Spam   = 0.1
Normal = 0.9
```

정답 class인 Spam에 높은 probability를 줄수록 잘한 것이다.

Cross Entropy는 바로

> **정답 class에 얼마나 높은 probability를 부여했는가**

를 이용하여 loss를 계산한다.

---

# 57. Cross Entropy의 간단한 형태

정답 class에 모델이 부여한 probability를 `p`라고 하면 강의에서는 핵심적으로

`Loss = -log(p)`

로 설명한다.

정답 probability가 높으면 Loss가 작다.

정답 probability가 낮으면 Loss가 커진다.

---

# 58. 정답 확률 0.9인 경우

실제 Spam mail에

`p = 0.9`

를 주었다고 하자.

Cross Entropy:

`-log(0.9) ≈ 0.11`

정도로 작은 값이다.

모델이 정답에 높은 confidence를 주었기 때문이다.

---

# 59. 정답 확률 0.1인 경우

실제 Spam인데 Spam probability를

`0.1`

만 주었다면

`-log(0.1) ≈ 2.3`

이다.

잘한 경우의 약 `0.11`과 비교하면 손실이 매우 커진다.

즉 Cross Entropy는

> **정답에 낮은 확률을 준 잘못된 prediction을 강하게 penalize한다.**

---

# 60. Accuracy와 Cross Entropy의 차이

두 모델을 생각해보자.

### Model A

정답 class probability:

`0.51`

### Model B

정답 class probability:

`0.99`

둘 다 최종 class prediction은 맞았다고 할 수 있다.

Accuracy에서는 둘 다

```text
Correct = 1
```

이다.

하지만 Cross Entropy에서는 Model B의 loss가 훨씬 작다.

즉 Cross Entropy는 단순히 맞았는지뿐 아니라

> **얼마나 확신 있게 올바른 prediction을 했는지**

도 반영한다.

---

# 61. Regression과 Classification Loss

대표적으로 연결하면 다음과 같다.

```text
Regression
→ MSE

Classification
→ Cross Entropy
```

강의에서는 현재 단계에서 이 두 Loss의 수학적 세부사항을 모두 이해할 필요는 없고

> **Prediction이 잘못될수록 Loss가 커지고, 학습은 Loss를 줄이는 방향으로 진행된다.**

는 직관을 잡는 것이 중요하다고 설명한다.

---

# 62. 다시 학습의 진짜 목적

Regression과 Classification을 배운 뒤 강의에서는 다시 가장 중요한 질문으로 돌아간다.

> **학습의 목적은 무엇인가?**

답은

> **새로운 데이터에서 잘 Prediction하는 것**

이다.

---

# 63. 모델 평가는 Training Data로만 하면 안 된다

Training Data는 이미 Model을 학습시키는 데 사용했다.

따라서 그 데이터에서 좋은 성능이 나온다고 해서 실제 predictive performance가 좋다고 말할 수 없다.

모델을 평가하려면

> **학습에 사용하지 않은 Data**

를 사용해야 한다.

---

# 64. Generalization

훈련 데이터가 아닌 새로운 데이터에서도 좋은 성능을 내는 능력을 **Generalization**과 연결해서 이해한다.

```text
Training에서 잘함
+
새로운 Data에서도 잘함
        ↓
Good Generalization
```

실제 시스템에 필요한 것은 Training performance가 아니라 Generalization performance다.

---

# 65. 시험 공부 비유

강의에서는 이를 시험 공부에 비유한다.

```text
기출문제
= Training Data

실제 시험의 새로운 문제
= Test Data
```

기출문제 답을 전부 외웠다고 해서 실제 시험을 잘 보는 것은 아니다.

문제의 원리를 이해했다면 처음 보는 문제에도 대응할 수 있다.

머신러닝도 마찬가지다.

우리가 원하는 모델은 Training Data의 정답을 외운 모델이 아니라

> **그 뒤의 일반적인 규칙을 학습한 모델**

이다.

---

# 66. Overfitting

**Overfitting(과적합)** 은 Training Data의 우연한 pattern이나 noise까지 지나치게 학습하는 현상이다.

그 결과

```text
Training Performance
→ 매우 좋음

Test Performance
→ 나쁨
```

이 발생한다.

---

# 67. Classification에서의 Overfitting

두 class를 구분하는 Classification problem을 생각해보자.

Training Data가 다음과 같이 있다고 하자.

```text
● ● ●   ○ ○
 ● ●  ○ ○
```

모든 training point 하나하나를 완벽하게 구분하기 위해 Decision Boundary를 지나치게 복잡하게 만들 수 있다.

```text
~~~~~~
~ 복잡한 ~
~~경계~~~
```

그러면 Training Error는

`0`

이 될 수도 있다.

하지만 새로운 data point가 들어오면 잘못 분류할 수 있다.

---

# 68. Overfitting의 핵심 원인

강의에서 매우 강조하는 부분이다.

Overfitting을 단순히

> Train Error는 작고 Test Error는 크다.

라고만 외우면 충분하지 않다.

그것은 **나타나는 현상**이다.

더 근본적인 핵심은

> **Training Data 안의 우연한 noise까지 학습했다는 것**

이다.

---

# 69. 앞 차시의 ε와 Overfitting 연결

앞 차시에서

`y = f*(x) + ε`

라고 배웠다.

우리가 진짜 학습하고 싶은 것은

`f*(x)`

다.

그런데 Training Data를 하나도 틀리지 않도록 너무 정교하게 맞추면

`f*`

뿐 아니라

`ε`

까지 따라갈 수 있다.

```text
원하는 것
f*

원하지 않는 것
ε까지 암기
```

이것이 Overfitting의 중요한 직관이다.

---

# 70. Overfitting이 발생하면 왜 Test에서 흔들리는가?

Noise는 Training sample에 우연히 존재하는 특성이다.

다른 Sample을 뽑으면 다른 Noise가 나타날 수 있다.

따라서 Noise까지 학습한 모델은 Training sample이 조금만 바뀌어도 prediction이 크게 바뀔 수 있다.

강의에서는 이를

> **높은 Variance**

와 연결한다.

결과적으로 Generalization이 나빠진다.

---

# 71. 매우 중요 — Train 성능 좋고 Test 성능 나쁘면 무조건 Overfitting인가?

아니다.

이 부분을 강의에서 매우 강하게 강조한다.

예를 들어 Training Data가

```text
실제 Dog / Cat 사진
```

이고 Test Data가

```text
Cartoon Dog / Cat
```

이라고 하자.

모델이 Test에서 성능이 크게 떨어질 수 있다.

하지만 이것만 가지고 Overfitting이라고 하면 안 된다.

---

# 72. Distribution Shift와 Overfitting은 다르다

Training Data와 Test Data의 distribution 자체가 다르면 성능이 떨어지는 것은 자연스럽다.

```text
Train Distribution
≠
Test Distribution
```

인 상황이다.

예:

```text
Train
→ 실사 사진

Test
→ Cartoon
```

이것은 Training Noise를 외워서 실패한 것과는 다른 문제다.

즉

> **Distribution Shift로 인해 Test 성능이 떨어지는 것을 Overfitting과 혼동하면 안 된다.**

---

# 73. Overfitting을 말하기 위한 기본 전제

원칙적으로 Overfitting을 논할 때는

```text
Training Data
and
Test Data
```

가 **같은 underlying distribution에서 왔다고 가정**한다.

각각의 data point는 다르지만 같은 distribution에서 sampling되었다고 보는 것이다.

그 상태에서

```text
Train에서는 좋음
Test에서는 나쁨
```

이라면 Overfitting 여부를 논할 수 있다.

---

# 74. 현업에서도 먼저 Distribution을 확인해야 한다

실제 Model에서

> “Training 성능은 좋은데 Test 성능이 낮습니다.”

라는 상황이 발생했다고 하자.

무조건

> “Overfitting입니다.”

라고 결론 내리면 안 된다.

먼저

> **Train과 Test가 정말 같은 distribution인가?**

를 확인해야 한다.

강의에서는 이 개념을 제대로 구분하지 않으면 Overfitting을 잘못 해석하는 경우가 많다고 강조한다.

---

# 75. Underfitting

Overfitting의 반대편에는 **Underfitting(과소적합)** 이 있다.

모델이 데이터에 존재하는 실제 관계조차 충분히 학습하지 못한 상태다.

원인은 여러 가지가 있을 수 있다.

### Hypothesis Space가 너무 작음

표현할 수 있는 함수가 지나치게 제한적이다.

### 학습 Iteration 부족

아직 충분히 학습하지 않았다.

### Data 부족

충분한 학습 정보를 얻지 못했다.

---

# 76. Hypothesis Space와 Underfitting

앞 차시의 Hypothesis Space와 연결한다.

실제 True Function이 복잡한 곡선이라고 하자.

그런데 Hypothesis Space를

```text
직선만
```

으로 제한하면 아무리 최적의 직선을 찾아도 실제 관계를 충분히 표현할 수 없다.

```text
True Function
≈ 복잡한 곡선

Hypothesis Space
= 단순한 직선만

→ Underfitting
```

즉 모델의 표현 능력 자체가 부족할 수 있다.

---

# 77. Overfitting과 Underfitting

```text
Underfitting
←────── 적절한 모델 ──────→
                      Overfitting

너무 단순                      너무 복잡
관계도 못 배움               Noise까지 배움
```

둘 다 Prediction 성능을 떨어뜨리므로 좋지 않다.

우리가 원하는 것은 적절한 수준의 모델이다.

# 82. ε와 Prediction Error 비교

|구분|`ε`|`y - ŷ`|
|---|---|---|
|의미|True Function과 실제 Data 차이|Model Prediction과 실제 Data 차이|

# 83. Accuracy / Precision / Recall 비교

|지표|질문|
|---|---|
|Accuracy|전체 중 얼마나 맞혔는가?|
|Precision|Positive라고 예측한 것 중 실제 Positive는 얼마나 되는가?|
|Recall|실제 Positive 중 얼마나 찾아냈는가?|
|F1|Precision과 Recall을 하나로 종합하면 어떤가?|

# 84. Confusion Matrix 핵심

```text
               Prediction
              +          -
Actual +      TP         FN
       -      FP         TN
```

### Precision

`TP / (TP + FP)`

### Recall

`TP / (TP + FN)`

### Accuracy

`(TP + TN) / 전체`

### F1

`2 × Precision × Recall / (Precision + Recall)`

# 85. 이번 강의에서 자주 헷갈리는 점 ①

## Input이 숫자면 Regression인가?

아니다.

Regression / Classification은 **Output 기준**이다.

예:

```text
중간고사 점수
기말고사 점수
출석률
```

이 모두 숫자 Feature여도 Output이

```text
A / B / C / D / F
```

라면 Classification이다.

# 86. 자주 헷갈리는 점 ②

## Loss와 평가 지표는 항상 같은가?

아니다.

Classification에서 실제 Training Loss로 Cross Entropy를 사용할 수 있지만 최종 평가에서는

- Accuracy
    
- Precision
    
- Recall
    
- F1
    

등을 함께 볼 수 있다.

즉

```text
Training을 위한 Objective
≠
최종적으로 보고할 Evaluation Metric
```

일 수 있다.

---

# 87. 자주 헷갈리는 점 ③

## Accuracy가 높으면 좋은 Classification 모델인가?

항상 그렇지 않다.

특히 class imbalance가 심하면 dominant class만 예측해도 Accuracy가 높아질 수 있다.

따라서

```text
Imbalanced Data
→ Accuracy만 보면 위험
```

하고 Precision, Recall, F1 등을 함께 확인한다.

---

# 88. 자주 헷갈리는 점 ④

## Train Error를 0으로 만들면 최고인가?

아니다.

Training Data에 포함된 noise까지 학습하면 Overfitting이 발생할 수 있다.

궁극적으로 원하는 것은

```text
Training Error 최소화 자체
```

가 아니라

```text
Generalization Performance 향상
```

이다.

# 89. 자주 헷갈리는 점 ⑤

## Train은 좋은데 Test는 나쁘면 무조건 Overfitting인가?

아니다.

먼저

```text
Train Distribution
=
Test Distribution ?
```

을 확인해야 한다.

Distribution 자체가 달라졌다면 Overfitting과 다른 문제다.

# 90. 앞 차시와 이번 차시 연결

## 1차시

우리는

`y = f*(x) + ε`

라는 관점으로 머신러닝을 바라봤다.

목적:

> 미지의 `f*`를 학습한다.

## 2차시

그 아이디어를 실제 Supervised Learning으로 구체화한다.

```text
(x, y)가 있는 Training Data
      ↓
Prediction ŷ
      ↓
Loss(y, ŷ)
      ↓
Loss 최소화
      ↓
Learned Model
```

하지만 여기서 끝이 아니다.

```text
Train Loss 작음
```

이 목적이 아니라

```text
새로운 Data에서도 잘함
```

이 목적이다.

따라서 이번 차시에서 **Generalization / Overfitting / Underfitting**이 자연스럽게 등장한다.

# 92. 이번 강의의 핵심 문장

> **지도학습은 Feature와 정답 Label을 이용하여 Prediction Error를 줄이는 모델을 학습하지만, 궁극적인 목적은 Training Data의 Error를 최소화하는 것 자체가 아니라 같은 분포에서 새롭게 관측될 데이터에서도 정확하게 예측할 수 있는 일반화 성능을 얻는 것이다.**

그리고 앞 차시까지 연결해서 한 문장으로 표현하면 다음과 같다.

> **우리는 관측 데이터의 noise `ε`까지 외우는 것이 아니라 그 뒤에 존재하는 미지의 참함수 `f*`에 가까운 모델을 학습해야 하며, 그것이 새로운 데이터에 대한 좋은 예측과 Generalization으로 이어진다.**
