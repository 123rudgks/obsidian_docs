# 0. 강의 전체 개요

앞선 강의까지 머신러닝의 큰 구조에서

```text
Data
 ↓
Model
 ↓
Learning
 ↓
Evaluation
```

중 Data, Model, Learning을 살펴봤다.

이번 차시에서는 마지막 단계인 **Evaluation(평가)** 을 다룬다.

전체 흐름은 다음과 같다.

```text
학습의 목적
= Generalization
        ↓
Training Error와 Test Error
        ↓
Training Error만으로는
Test 성능을 알 수 없음
        ↓
Model Complexity와
Underfitting / Overfitting
        ↓
우리가 진짜 최소화하려는 것
= Test Error
        ↓
하지만 Test Data가 부족함
        ↓
Validation Set / Hold-out
        ↓
한 번 나누면 결과가 불안정
        ↓
K-fold Cross Validation
        ↓
여러 번 Train / Validation
        ↓
Validation Error 평균
        ↓
Test Error 추정
        ↓
좋은 Model Complexity 선택
```

---

# 1. 평가가 필요한 이유

앞 차시에서 학습의 궁극적인 목적은 **Generalization**이라고 배웠다.

즉 우리가 원하는 모델은

```text
Training Data에서 잘하는 모델
```

이 아니라

```text
Training에 사용하지 않은
새로운 Data에서도 잘하는 모델
```

이다.

따라서 평가에서도 단순히 Training Data에서 얼마나 잘했는지만 확인해서는 안 된다.

---

# 2. Training Error

**Training Error(훈련오류)** 는

> 학습에 사용한 Training Data에서 다시 모델의 오류를 계산한 값

이다.

```text
Training Data
     ↓
   학습
     ↓
Learned Model
     ↓
같은 Training Data에 Prediction
     ↓
Training Error
```

강의에서는 이를 시험 공부에 비유한다.

```text
기출문제로 공부
      ↓
같은 기출문제를 다시 풂
      ↓
기출문제 오답률
```

과 비슷하다.

충분히 학습했다면 Training Error는 보통 작아진다.

---

# 3. Test Error

**Test Error(테스트오류)** 는

> 학습에 사용하지 않은 새로운 데이터에서 모델을 적용했을 때 발생하는 평균적인 오류

다.

시험 비유에서는

```text
기출문제로 공부
      ↓
실제 시험의 새로운 문제
      ↓
실제 시험 오답률
```

과 같다.

---

# 4. Training Error와 Test Error는 일반적으로 다르다

모델은 Training Data를 직접 보고 학습한다.

따라서 일반적으로

```text
Training Error
<
Test Error
```

인 경우가 자연스럽다.

이미 여러 번 본 기출문제에서는 잘하지만 처음 보는 시험문제에서는 더 많이 틀릴 수 있는 것과 같다.

---

# 5. Training Error로 Test Error를 추정하면 안 된다

Training Error가 작다고 해서

> “새로운 데이터에서도 이 정도 Error가 나오겠지.”

라고 생각하면 안 된다.

Training Data는 이미 학습 과정에서 사용한 데이터이기 때문이다.

따라서 Training Error를 Test Error처럼 사용하면 실제 Test Error를 **심하게 과소평가**할 수 있다.

```text
Training Error 작음
        ≠
Test Error도 동일하게 작음
```

---

# 6. 우리가 궁극적으로 줄이고 싶은 것은 Test Error

물론 Training Error가 큰 모델을 원하는 것은 아니다.

하지만 최종 목표는 Training Error 자체를 최소화하는 것이 아니다.

우리가 진짜 원하는 것은

> **새로운 데이터에서 발생하는 Test Error를 작게 만드는 것**

이다.

---

# 7. Model Complexity

강의에서는 Test Error를 이해하기 위해 **Model Complexity(모델 복잡도)** 를 다시 가져온다.

### 낮은 Complexity

- 단순한 함수
    
- 평평한 함수
    
- Linear Model
    
- 유연성이 낮은 Model
    

### 높은 Complexity

- 구불구불한 함수
    
- 더 복잡한 곡선
    
- 유연성이 높은 Model
    

으로 생각할 수 있다.

---

# 8. Complexity가 증가하면 Training Error는 어떻게 되는가?

Model이 더 flexible해지면 Training Data의 각 점에 더 세밀하게 맞출 수 있다.

따라서 일반적으로

```text
Model Complexity ↑
       ↓
Training Error ↓
```

방향으로 움직인다.

아주 복잡한 Model을 사용하면 Training Data 각각의 Error를 거의 0까지 줄일 수도 있다.

---

# 9. 그러면 가장 복잡한 Model이 항상 좋은가?

아니다.

만약 우리의 목적이 오직

```text
Training Error 최소화
```

라면 무조건 가장 복잡한 Model을 선택하면 된다.

하지만 우리의 목적은

```text
Test Error 최소화
```

다.

Model Complexity가 지나치게 커지면 Training Data의 noise까지 학습하면서 새로운 데이터에서 오히려 Error가 증가할 수 있다.

---

# 10. Test Error와 Model Complexity

Test Error는 대략 다음과 같은 관계를 생각할 수 있다.

```text
Test Error
  ↑
  │ \            /
  │  \          /
  │   \________/
  │
  └────────────────→ Model Complexity

    Underfit    Overfit
```

너무 단순해도 Test Error가 크고, 너무 복잡해도 Test Error가 커질 수 있다.

따라서 가운데 어딘가에 Test Error를 최소화하는 적절한 복잡도가 존재한다.

---

# 11. Underfitting 영역

Model Complexity가 지나치게 낮으면 데이터의 실제 관계를 충분히 표현하지 못한다.

```text
Model이 너무 단순
      ↓
Training Error도 큼
      ↓
Test Error도 큼
```

이를 **Underfitting** 영역으로 볼 수 있다.

---

# 12. Overfitting 영역

반대로 Model Complexity가 지나치게 커지면 Training Data를 지나치게 세밀하게 맞춘다.

```text
Complexity ↑
      ↓
Training Error 계속 ↓
      ↓
Noise까지 학습
      ↓
Test Error ↑
```

이를 **Overfitting** 영역이라고 볼 수 있다.

---

# 13. 우리가 원하는 것은 적절한 Fit

결국 원하는 것은

```text
Underfitting X
Overfitting  X

적절한 Fit O
```

이다.

앞 차시의 관점으로 연결하면 이것은 미지의 참함수 `f*`에 가능한 가깝게 접근하는 것과 관련된다.

---

# 14. Training Error만 보고 Model을 선택할 수 없는 이유

Training Error만 본다면 Model Complexity가 높을수록 계속 좋은 것처럼 보인다.

하지만 실제 Test Error는 어느 지점을 지나면 다시 증가할 수 있다.

따라서

> **Training Error가 가장 작은 Model = 가장 좋은 Model**

이 아니다.

Model Selection을 위해서는 Test performance를 추정할 방법이 필요하다.

---

# 15. 가장 이상적인 평가 방법

가장 좋은 상황은 아주 단순하다.

### Training Data가 충분히 많고

또

### 별도의 Test Data도 충분히 많다면

Training Data로 학습한 뒤 Test Data로 평가하면 된다.

```text
Large Training Set
      ↓
    학습

Large Independent Test Set
      ↓
    평가
```

이것이 이상적인 상황이다.

---

# 16. 현실의 문제 — Data가 부족하다

현실에서는 Training Data 자체도 충분하지 않은 경우가 많다.

그런데 Test를 위해 많은 Data를 따로 빼놓는다면 Training에 사용할 수 있는 Data가 더 줄어든다.

```text
전체 Data 부족

Training에 많이 사용
→ Test Data 부족

Test에 많이 사용
→ Training Data 부족
```

라는 문제가 생긴다.

---

# 17. 우리가 해결하려는 문제

따라서 이번 강의의 핵심 질문은 다음과 같다.

> **별도의 충분한 Test Dataset이 없더라도 현재 가진 Data만 이용해서 실제 Test Error를 어느 정도 추정할 수 없을까?**

이를 위해 **Resampling Method**를 사용한다.

핵심 아이디어는

> **데이터를 나누고 Train과 Validation을 여러 방식으로 반복한다.**

는 것이다.

---

# 18. Validation Set Method / Hold-out

가장 간단한 방법은 전체 가용 데이터를 두 부분으로 나누는 것이다.

```text
전체 Data
   ↓
Shuffle
   ↓
┌───────────┬────────────┐
│ Training  │ Validation │
└───────────┴────────────┘
```

한쪽은 실제 학습에 사용하고 나머지는 학습 과정에서 사용하지 않은 채 Validation에만 사용한다.

이를 Validation Set 또는 Hold-out 방식으로 볼 수 있다.

---

# 19. 시험 문제 비유

지난 10년간 기출문제가 있다고 하자.

모든 문제를 공부해버리면 새로운 문제처럼 평가할 자료가 없다.

따라서

```text
과거 8년 문제
→ 공부

최근 2년 문제
→ 학습에 사용하지 않고 평가
```

처럼 일부를 남겨둘 수 있다.

이것이 Hold-out 방식의 직관이다.

---

# 20. Validation Set을 만드는 방법

전체 Data가 `n`개 있다고 하자.

먼저 데이터를 **Shuffle**한다.

그리고 일정한 비율로 나눈다.

예:

```text
50 : 50
60 : 40
70 : 30
80 : 20
```

어떤 비율이든 가능하며 강의에서는 정확히 절반으로 나누는 것이 핵심이 아니라

> **Training Set과 Validation Set으로 분리하는 것**

이 중요하다고 설명한다.

---

# 21. 왜 Shuffle이 중요한가?

Data의 원래 순서에 특정한 구조가 있을 수 있다.

따라서 단순히 앞부분을 Training, 뒷부분을 Validation으로 사용하면 한쪽에 특정 종류의 데이터가 몰릴 수 있다.

강의에서는 먼저 random하게 섞은 뒤 분할하는 것을 강조한다.

```text
Original Data
      ↓
Shuffle
      ↓
Random Split
```

---

# 22. Validation Data는 Training에 사용하면 안 된다

한번 Validation Set으로 분리한 데이터는 해당 학습 과정에서는 Model Training에 사용하지 않는다.

```text
Training Set
→ Parameter 학습

Validation Set
→ Evaluation만 수행
```

그래야 모델이 보지 않은 데이터에서의 performance를 확인할 수 있다.

---

# 23. 모델 복잡도 비교 예시

강의에서는 자동차 연비를 예측하는 dataset을 예로 든다.

다양한 Model Complexity를 비교한다.

예를 들어 Polynomial의 차수가 증가하면

```text
1차
2차
3차
4차
5차
6차
...
```

Model Complexity가 높아지는 것으로 생각할 수 있다.

각각의 모델을 Training Set으로 학습하고 Validation Set에서 MSE를 계산하여 어떤 Complexity가 적합한지 비교한다.

---

# 24. Hold-out의 첫 번째 문제 — Split에 따라 결과가 달라진다

문제는 Data를 한 번만 나누었다는 것이다.

같은 Dataset이라도 Shuffle 결과에 따라

```text
이번 Split:
Validation MSE = 24

다른 Split:
Validation MSE = 16
```

처럼 큰 차이가 발생할 수 있다.

즉 Test Error에 대한 추정치의 **Variance가 크다.**

---

# 25. 왜 결과가 크게 달라지는가?

어떤 Sample이

```text
Training에 들어가는가
```

그리고 어떤 Sample이

```text
Validation에 들어가는가
```

에 따라 모델과 평가 결과가 달라지기 때문이다.

따라서 한 번의 Hold-out 결과만 가지고

> “이 Model의 Test Error는 정확히 이 정도다.”

라고 말하기 어렵다.

---

# 26. Hold-out의 두 번째 문제 — 학습 Data가 줄어든다

예를 들어 전체 Data의 절반만 Training에 사용했다고 하자.

그러면 실제로 모든 Data를 사용해서 학습했을 때보다 Model의 성능이 낮을 가능성이 있다.

```text
전체 Training Data 사용
>
50%만 Training에 사용
```

이므로 Validation Error를 그대로 실제 최종 Model의 Test Error라고 보면 Error를 지나치게 크게 추정할 수도 있다.

---

# 27. Hold-out 방식의 두 한계

정리하면:

### 1. 높은 Variance

Split이 달라질 때마다 Evaluation 결과가 크게 바뀔 수 있다.

### 2. Training Data 감소

일부 Data를 Validation에 빼기 때문에 Model이 전체 Data를 충분히 활용하지 못한다.

이 문제를 개선하기 위해 **K-fold Cross Validation**을 사용한다.

---

# 28. K-fold Cross Validation

**K-fold Cross Validation(K-fold 교차검증)** 은 전체 Data를 `K`개의 Fold로 나눈 뒤 Train/Validation을 여러 번 반복하는 방법이다.

예를 들어

`K = 5`

라면 **5-fold Cross Validation**이다.

---

# 29. 5-fold Cross Validation — Step 1

먼저 데이터를 Shuffle한다.

```text
전체 Data
   ↓
Shuffle
```

그 다음 서로 겹치지 않는 5개의 Fold로 나눈다.

```text
Fold 1
Fold 2
Fold 3
Fold 4
Fold 5
```

---

# 30. Fold는 서로 겹치지 않는다

각 Data Point는 하나의 Fold에만 속한다.

```text
Fold 1 ∩ Fold 2 = ∅
Fold 1 ∩ Fold 3 = ∅
...
```

즉 Fold들은 서로 **교집합이 없는 Partition**이어야 한다.

이 원칙은 매우 중요하다.

---

# 31. 첫 번째 Cross Validation

첫 번째 반복에서는 Fold 1을 Validation으로 사용한다.

```text
Fold 1 → Validation

Fold 2
Fold 3
Fold 4
Fold 5
     ↓
Training
```

Training Fold 네 개를 이용해 Model을 학습하고 Fold 1에서 Error를 계산한다.

```text
Error₁
```

을 기록한다.

---

# 32. 두 번째 Cross Validation

이번에는 Fold 2가 Validation이 된다.

```text
Fold 2 → Validation

Fold 1
Fold 3
Fold 4
Fold 5
     ↓
Training
```

그리고

`Error₂`

를 계산한다.

---

# 33. 모든 Fold가 한 번씩 Validation이 된다

같은 과정을 반복한다.

```text
Iteration 1
Validation = Fold 1

Iteration 2
Validation = Fold 2

Iteration 3
Validation = Fold 3

Iteration 4
Validation = Fold 4

Iteration 5
Validation = Fold 5
```

결과적으로 Error가 5개 나온다.

```text
E₁
E₂
E₃
E₄
E₅
```

---

# 34. K개의 Validation Error를 평균낸다

5-fold라면 다섯 번 평가한 Error를 평균한다.

개념적으로 Fold 크기가 동일하다면

`CV Error ≈ (E₁ + E₂ + E₃ + E₄ + E₅) / 5`

이다.

이 평균값을 실제 Test Error에 대한 추정치로 사용한다.

---

# 35. K-fold의 핵심 구조

일반적인 `K`-fold의 구조는 다음과 같다.

```text
전체 Data
   ↓
Shuffle
   ↓
K개의 Fold로 분할
   ↓

1번째:
Fold 1 Validation
나머지 Train

2번째:
Fold 2 Validation
나머지 Train

...

K번째:
Fold K Validation
나머지 Train

   ↓
각 Validation Error 계산
   ↓
평균
   ↓
Test Error 추정
```

---

# 36. Shuffle은 언제 하는가?

강의에서는 한 번의 K-fold Cross Validation을 수행할 때

> **먼저 한 번 Shuffle한 후 Fold로 나눈다.**

고 설명한다.

각 Fold 평가를 할 때마다 다시 전체 데이터를 Shuffle해서 Fold를 새로 만드는 것이 아니다.

```text
Shuffle
 ↓
Fold 구성
 ↓
K번 Validation 반복
```

이다.

---

# 37. Data Leakage를 막아야 한다

Training Data에 들어간 Sample이 동시에 Validation Fold에도 포함되면 문제가 발생한다.

```text
Training에서 이미 본 Data
       ↓
Validation에도 등장
       ↓
평가가 지나치게 좋아짐
```

강의에서는 이를 Data가 새어 들어가는 문제로 설명한다.

따라서 Fold는 서로 겹치면 안 된다.

---

# 38. Fold 크기가 모두 같지 않을 수도 있다

전체 데이터 수 `n`이 `K`로 정확하게 나누어 떨어진다는 보장은 없다.

예:

```text
n = 101
K = 5
```

이면 모든 Fold의 크기를 완전히 동일하게 만들 수 없다.

한두 Fold에 데이터 하나가 더 들어갈 수 있다.

---

# 39. Fold 크기가 다르면 Error를 가중 평균한다

각 Fold에서 계산한 MSE를 단순히 똑같은 비중으로 평균내기보다 각 Fold의 Data 수를 고려할 수 있다.

Fold `k`의 크기를 `nₖ`, 전체 데이터 수를 `n`이라고 하면 강의에서 설명한 개념은

`CV Error = (1/n) Σ nₖ × MSEₖ`

처럼 이해할 수 있다.

즉

> **각 Fold가 전체 Data에서 차지하는 비율만큼 Error에 Weight를 준다.**

---

# 40. 나누어떨어지지 않는 Data를 버리지 않는다

예를 들어 Data 수가 Fold 수로 정확히 나누어지지 않더라도 남는 Sample을 버리지 않는다.

Fold 중 일부에 하나씩 더 배정하고 Fold Size에 맞게 가중해서 계산한다.

강의에서는

> **Data는 버리면 안 된다.**

고 강조한다.

---

# 41. K는 누가 결정하는가?

`K`는 사용자가 선택한다.

예:

```text
K = 3
→ 3-fold CV

K = 5
→ 5-fold CV

K = 10
→ 10-fold CV
```

---

# 42. K = n인 극단적인 경우

전체 데이터가 `n`개이고

`K = n`

으로 설정할 수도 있다.

예:

```text
Data = 100개
K = 100
```

그러면 각 Validation Fold에는 Data Point가 **1개**씩 들어간다.

---

# 43. Leave-One-Out Cross Validation

`K = n`인 경우를 **Leave-One-Out Cross Validation(LOOCV)** 이라고 한다.

각 반복에서

```text
Data 1개
→ Validation

나머지 n-1개
→ Training
```

을 수행한다.

즉 문자 그대로 **하나를 남겨두고(leave one out)** 나머지를 모두 Training한다.

---

# 44. LOOCV에서는 몇 번 학습하는가?

Data가 `n`개이므로 총 `n`번 학습해야 한다.

예:

```text
n = 100
→ 100번 Train

n = 1,000,000
→ 1,000,000번 Train
```

따라서 계산량이 매우 크다.

---

# 45. LOOCV의 장점

각 iteration에서 Training Data로

`n - 1`

개를 사용한다.

즉 가능한 거의 모든 Data를 학습에 사용한다.

따라서 Training Data 활용 측면에서는 매우 강한 방법이다.

---

# 46. LOOCV의 단점

가장 큰 문제는 계산량이다.

```text
Train 횟수 = n
```

이므로 Data가 커지면 현실적으로 사용하기 어렵다.

강의에서는 LOOCV를 실무에서 일반적으로 사용할 방법으로 권장하지 않고 개념적으로 알아둘 형태로 설명한다.

---

# 47. 실무에서는 K를 얼마나 사용하는가?

강의에서는 주로

- **5-fold Cross Validation**
    
- **10-fold Cross Validation**
    

을 많이 사용한다고 설명한다.

Empirical하게 5~10 정도만 사용해도 Test Error 추정 및 Model Selection에 충분히 유용한 경우가 많다는 것이다.

---

# 48. 반드시 5나 10이어야 하는 것은 아니다

5와 10이 절대적인 법칙은 아니다.

예를 들어

```text
K = 7
```

을 선택해도 된다.

다만 practical하게는 5 또는 10이 많이 사용된다는 설명이다.

---

# 49. K-fold Cross Validation의 중요한 목적 ①

첫 번째 목적은

> **실제 Test Error를 추정하는 것**

이다.

충분한 독립 Test Dataset이 없을 때 K-fold를 이용하여 새로운 Data에서 어느 정도 Error가 발생할지 추정한다.

---

# 50. K-fold Cross Validation의 중요한 목적 ②

두 번째 목적은

> **어떤 Model이 더 좋은지 선택하는 것**

이다.

예를 들어 Model Complexity가 서로 다른 여러 후보가 있을 때 각 후보에 대해 Cross Validation Error를 계산할 수 있다.

```text
Model A → CV Error
Model B → CV Error
Model C → CV Error
...
```

이를 바탕으로 적절한 Model을 선택한다.

---

# 51. True Test Error는 실제로 알 수 없다

강의에서는 여러 Model Complexity에 따른 **진짜 Test Error Curve**를 설명을 위해 보여준다.

하지만 실제 문제에서는 이 Curve를 볼 수 없다.

왜냐하면 그것은 미지의 실제 분포에서의 Test Error이기 때문이다.

```text
True Test Error
→ 관측 불가능
```

---

# 52. 우리가 관측할 수 있는 것은 CV Error

실제 Test Error는 모르지만

```text
5-fold CV Error
10-fold CV Error
LOOCV Error
```

등은 현재 가진 Data로 계산할 수 있다.

따라서 우리가 직접 관측할 수 없는 Test Error 대신 **Cross Validation Error를 이용하여 Model을 선택**한다.

---

# 53. 10-fold CV는 실제 Test Error와 비슷한 경향을 잡아낼 수 있다

강의에서 여러 dataset 사례를 비교하면

- True Test Error의 최소 구간
    
- 10-fold CV Error의 최소 구간
    

이 상당히 비슷하게 나타난다.

따라서 실제 True Test Error를 볼 수 없더라도

> **10-fold Cross Validation을 이용해 좋은 Model Complexity를 선택해도 충분히 유용하다.**

는 것이 강의의 결론이다.

---

# 54. 가장 Error가 작은 Model만 기계적으로 선택해야 하는가?

강의에서는 CV Error가 거의 비슷한 여러 Model이 있다면 지나치게 flexible한 Model보다 상대적으로 단순한 Model도 선택할 수 있다고 설명한다.

예를 들어

```text
Model A
Complexity 낮음
CV Error = 10.1

Model B
Complexity 높음
CV Error = 10.0
```

처럼 Error 차이가 거의 없다면 반드시 더 복잡한 Model을 선택할 필요는 없다는 관점이다.

즉 비슷한 Error를 낸다면 상대적으로 complexity가 낮은 모델도 충분히 고려할 수 있다.

---

# 55. Dataset마다 적절한 Complexity는 다르다

어떤 Dataset의 underlying relationship이 단순하면 낮은 Complexity에서도 Error가 충분히 작을 수 있다.

다른 Dataset이 복잡하면 더 flexible한 Model이 필요할 수 있다.

```text
단순한 Data Relationship
→ 단순 Model도 충분

복잡한 Data Relationship
→ 더 Flexible한 Model 필요
```

그러나 두 경우 모두 Cross Validation을 이용하면 적절한 Complexity 영역을 찾을 수 있다.

---

# 56. Hold-out vs K-fold Cross Validation

|항목|Hold-out|K-fold CV|
|---|---|---|
|Data 분할|한 번|K개 Fold|
|Training 횟수|1회|K회|
|Validation 횟수|1회|K회|
|Split 민감도|큼|상대적으로 감소|
|Data 활용|일부만 Training|각 반복에서 대부분 Training|
|Test Error 추정|불안정할 수 있음|더 안정적으로 추정 가능|
|계산량|적음|더 큼|

---

# 57. K-fold vs LOOCV

|항목|일반 K-fold|LOOCV|
|---|---|---|
|K|보통 5 또는 10|n|
|Validation Size|약 n/K|1|
|Training Size|약 (K-1)n/K|n-1|
|Training 횟수|K|n|
|계산량|상대적으로 적음|매우 큼|
|실전 활용|흔함|강의에서는 일반 실무 사용 비권장|

---

# 58. Training / Validation / Test 개념 구분

### Training Data

Model의 Parameter를 학습하는 데 사용한다.

### Validation Data

Model이나 Complexity의 성능을 비교하고 선택하는 데 사용한다.

### Test Data

최종적으로 학습 과정에서 보지 않은 Data에서 성능을 평가한다.

이번 강의에서는 충분한 Test Data를 확보하기 어려울 때 Validation 및 Cross Validation을 이용하여 **Test Error를 추정하는 방법**을 중심으로 설명한다.

---

# 59. 왜 한 번의 Validation보다 여러 번 Validation하는가?

한 번만 나누면 결과가 특정 Split에 지나치게 의존한다.

```text
Split A
→ Error 16

Split B
→ Error 24
```

그렇다면 어느 값이 실제 Test Error에 가까운지 알기 어렵다.

K-fold에서는 여러 Validation 결과를 평균내므로 한 번의 우연한 Split에 대한 의존도를 줄인다.

---

# 60. Cross Validation과 Generalization의 관계

교차검증을 사용하는 궁극적인 이유는 단순히 “Data를 여러 조각으로 나누기 위해서”가 아니다.

전체 논리는 다음과 같다.

```text
우리가 원하는 것
= Generalization
       ↓
Generalization을 알려면
새로운 Data에서의 Error가 필요
       ↓
Training Error로는 알 수 없음
       ↓
충분한 Test Data도 없음
       ↓
현재 가진 Data를
Train / Validation으로 반복 분할
       ↓
새로운 Data에서의 Error를 모사
       ↓
CV Error
       ↓
Test Error 추정
```

---

# 61. Cross Validation과 Model Selection의 관계

Model 후보가 다음과 같이 있다고 하자.

```text
Complexity 1
Complexity 2
Complexity 3
...
Complexity 10
```

Training Error만 본다면 가장 복잡한 Model이 가장 좋아 보일 수 있다.

하지만 각 Model에 대해 Cross Validation을 수행하면

```text
CV Error
  ↑
  │ \       /
  │  \_____/
  │
  └──────────→ Complexity
```

처럼 새로운 Data에서 어느 Complexity가 적절할지 추정할 수 있다.

따라서 **Cross Validation은 단순 Evaluation 도구이면서 Model Selection 도구이기도 하다.**

---

# 62. 이번 강의에서 자주 헷갈리는 점 ①

## Training Error가 가장 작은 Model이 가장 좋은 Model인가?

아니다.

복잡한 Model은 Training Data를 더 세밀하게 맞추므로 Training Error는 계속 감소할 수 있다.

하지만 일정 Complexity 이후에는 Test Error가 다시 증가할 수 있다.

따라서

```text
Training Error 최소
≠
Test Error 최소
```

이다.

---

# 63. 자주 헷갈리는 점 ②

## Validation Set은 Training에도 사용해도 되는가?

해당 평가 과정에서는 안 된다.

Validation performance를 새로운 Data에서의 performance처럼 사용하려면 Model Training 과정에서 그 데이터를 사용하지 않아야 한다.

---

# 64. 자주 헷갈리는 점 ③

## Cross Validation에서 Fold끼리 겹쳐도 되는가?

안 된다.

같은 Data Point가 Training과 Validation에 동시에 들어가면 평가 정보가 새어 들어가므로 정상적인 평가가 아니다.

한 번 구성한 Fold들은 서로 겹치지 않는 Partition이어야 한다.

---

# 65. 자주 헷갈리는 점 ④

## 5-fold CV에서는 데이터를 5번 Shuffle하는가?

강의 설명 기준으로는 아니다.

먼저 한 번 Shuffle하고 5개의 Fold로 나눈 뒤 각 Fold를 번갈아 Validation에 사용한다.

```text
Shuffle 1회
→ Fold 생성
→ K번 Train/Validation
```

---

# 66. 자주 헷갈리는 점 ⑤

## Fold Size가 완전히 같지 않으면 남는 Data는 버리는가?

아니다.

예를 들어 `n`이 `K`로 정확하게 나누어지지 않으면 일부 Fold에 하나의 Sample이 더 들어갈 수 있다.

그에 따라 Fold Size를 고려해서 Error를 평균한다.

Data를 버리는 것이 아니다.

---

# 67. 자주 헷갈리는 점 ⑥

## K가 클수록 무조건 좋은가?

강의에서는 그렇게 설명하지 않는다.

`K=n`인 LOOCV는 거의 모든 Data를 Training에 활용할 수 있지만 Train을 `n`번 해야 하기 때문에 계산량이 매우 커진다.

Practical하게는 주로 `K=5` 또는 `K=10`을 사용한다.

---

머신러닝의 목적:

```text
Data를 이용해

```

학습의 최종 목적:

```text
Training Error 최소화 자체가 아니라

= Generalization
```

## 3차시 — 교차검증

그렇다면 질문:

답:

```text

Test Error가 필요
        ↓
하지만 Test Data가 부족
        ↓

        ↓
Test Error 추정
        ↓
Model Selection
```

# 70. 이번 강의의 핵심 문장

> **모델 평가의 목적은 이미 학습한 데이터에서의 오류를 확인하는 것이 아니라 새로운 데이터에서 발생할 테스트 오류를 추정하는 것이며, 충분한 독립 테스트 데이터가 없을 때 K-fold Cross Validation을 이용해 데이터를 여러 Fold로 나누고 반복적으로 학습·검증함으로써 테스트 성능을 추정하고 적절한 모델 복잡도를 선택할 수 있다.**

그리고 앞선 강의의 Generalization까지 연결하면 다음과 같다.

> **훈련오류가 가장 낮은 모델을 찾는 것이 아니라, 교차검증을 통해 보이지 않는 테스트오류가 가장 낮을 것으로 예상되는 모델을 찾는 것이 핵심이다.**
