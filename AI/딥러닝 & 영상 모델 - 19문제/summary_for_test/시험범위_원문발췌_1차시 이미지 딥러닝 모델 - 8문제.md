# 3. CNN은 FC와 무엇이 다른가?

가장 중요한 차이는

> **CNN은 이미지의 공간 구조를 없애지 않는다.**

FC에서는 이미지를 1차원으로 flatten했지만 CNN에서는 원래의

`32 × 32 × 3`

구조를 유지한다.

그리고 거대한 `W` 행렬 하나를 사용하는 대신 **작은 필터(filter/kernel)** 를 이미지 위에서 움직인다.

예를 들어 필터가

`5 × 5 × 3`

이라고 하자.

이 작은 필터를 이미지의 특정 위치에 올린 뒤, 필터가 덮는 이미지 영역과 필터 사이의 내적을 계산한다.

그 다음 필터를 옆으로 이동시키고 같은 계산을 반복한다.

이 반복 연산이 **Convolution**이다.

```text
이미지
┌─────────────────┐
│  ┌─────┐        │
│  │filter│ → → → │
│  └─────┘        │
└─────────────────┘
```

Convolution 자체는 CNN과 함께 처음 등장한 개념은 아니다.

이미 오래전부터

- 이미지 처리
    
- 이미지 필터
    
- 신호 처리
    

등에서 사용되던 수학적 연산이며, CNN은 이를 신경망 구조에 활용한 것이다.

---
# 12. 왜 Convolution Layer를 여러 개 쌓는가?

CNN은 convolution layer 하나만 사용하지 않고 여러 layer를 깊게 쌓는다.

한 가지 이유는 **모델의 학습 파라미터를 증가시켜 더 복잡한 함수를 표현하기 위해서**다.

하지만 단순한 선형 layer만 여러 번 쌓는 것은 의미가 없다.

예를 들어

`W3(W2(W1x))`

라는 연산이 있다고 하자.

모두 선형 변환이라면

`W = W3W2W1`

이라는 하나의 행렬로 합칠 수 있다.

결국

`Wx`

와 동일하다.

즉,

> **선형 변환만 반복하면 아무리 layer를 많이 쌓아도 하나의 선형 변환과 본질적으로 같다.**

---

# 13. ReLU와 비선형성

이 문제를 해결하기 위해 layer 사이에 **non-linear activation function**을 넣는다.

대표적인 것이 ReLU다.

강의의 설명:

```text
x < 0 → 0
x > 0 → x
```

ReLU가 들어가면 여러 layer를 하나의 `W`로 합쳐 표현할 수 없게 된다.

따라서 여러 layer를 쌓는 것이 실제 모델의 표현 능력을 증가시키게 된다.

---
# 16. CNN의 Template은 FC와 어떻게 다른가?

CNN의 가장 중요한 특징은 **계층에 따라 서로 다른 수준의 특징을 학습한다는 것**이다.

## 입력에 가까운 Low-level Layer

매우 작은 지역적 특징을 학습한다.

예:

- 경계(edge)
    
- 색상 변화
    
- 격자 또는 방향성 패턴
    
- 몇 pixel 수준의 local pattern
    

## 중간 Layer

조금 더 큰 영역을 본다.

예:

- blob
    
- 부분적인 형태
    
- 객체의 일부
    

## 출력에 가까운 High-level Layer

훨씬 큰 영역을 보면서

- object 수준
    
- image 전체 수준
    
- semantic한 의미
    
- 문맥
    

을 표현한다.

즉 CNN은

```text
Local pattern
      ↓
Part / Blob
      ↓
Object
      ↓
Image / Semantic context
```

의 계층적 특징을 추출한다.

이것이 CNN이 이미지에 강한 핵심적인 이유다.

---

# 17. 왜 Local Feature가 중요한가?

### PCB 불량 검출

불량과 정상의 차이가 매우 작은 영역에 있다면 전체적인 대표 template보다 작은 local feature를 정확히 확인하는 CNN이 유리하다.

### 비슷한 새를 분류하는 문제

만약 클래스가

- 참새
    
- 비둘기
    
- 까치
    

처럼 모두 비슷한 형태라면 전체 실루엣만으로 구별하기 어렵다.

대신

- 부리 색깔
    
- 날개 색깔
    
- 비율
    
- 작은 형태 차이
    

를 확인해야 한다.

CNN은 작은 local difference부터 전체 semantic difference까지 여러 scale을 동시에 계층적으로 표현할 수 있다.

---

# 18. FC와 CNN 비교

|모델|특징|
|---|---|
|Linear FC|각 클래스의 대표적인 하나의 template|
|FC + nonlinear layers|여러 종류의 template|
|CNN|여러 template뿐 아니라 local → part → object → semantic으로 이어지는 계층적 특징|

---

# 19. Receptive Field(수용 영역)

CNN의 계층적 특징과 직접 관련되는 개념이 **Receptive Field**다.

Receptive Field란

> **특정 layer의 하나의 출력이 원본 입력 이미지에서 어느 정도 크기의 영역을 보고 만들어졌는가**

를 의미한다.

예를 들어 첫 convolution에서 3×3 kernel을 사용한다면 첫 번째 layer의 출력 하나는 입력 이미지의

`3 × 3`

영역을 보고 만들어진다.

따라서 초기 receptive field는 3×3이다.

그러나 layer가 깊어지면 이전 layer의 여러 출력값을 다시 조합하게 되므로 원본 이미지 기준으로 볼 수 있는 영역이 점점 커진다.

즉,

```text
초기 Layer
→ 작은 영역

깊은 Layer
→ 큰 영역

마지막 Layer
→ 이미지의 상당 부분 또는 전체
```

가 된다.

Receptive field는 일종의 **network의 시야**라고 생각할 수 있다.

이미지의 넓은 영역을 볼 수 있을수록 더 많은 문맥을 고려할 수 있기 때문에 network 설계에서는 receptive field를 넓히는 것이 중요하게 다뤄진다.

---

# 20. Layer를 깊게 쌓으면 Receptive Field가 넓어진다

강의에서는 여러 3×3 convolution을 순차적으로 적용하는 예로 이를 설명한다.

첫 layer의 출력은 입력 이미지의 작은 3×3 영역만 본다.

하지만 다음 layer의 하나의 출력은 첫 layer의 여러 출력값을 함께 본다.

각각의 첫 layer 출력이 다시 원본 이미지의 서로 다른 3×3 영역을 보고 있기 때문에 최종적으로 두 번째 layer는 원본 이미지의 훨씬 넓은 영역의 정보를 가지게 된다.

따라서

> **작은 kernel을 사용하더라도 여러 layer를 깊게 쌓으면 receptive field를 넓힐 수 있다.**

---
# 21. Pooling

Pooling은 activation map의 공간 해상도를 줄이는 연산이다.

여러 pooling 방법이 있지만 강의에서는 **Max Pooling**을 중심으로 설명한다.

예를 들어 2×2 max pooling이라면 2×2 영역에서 가장 큰 값 하나만 남긴다.

```text
[1 2]
[3 6]

→ 6
```

4×4 입력에 2×2 max pooling을 적용하면 각각의 2×2 영역에서 하나의 값만 남기므로 공간 크기가 크게 감소한다.

## Pooling의 장점

### 1. 연산량 감소

공간 해상도가 줄어들기 때문에 뒤의 layer에서 처리해야 하는 값이 줄어든다.

### 2. 위치 변화에 대한 강건성

이미지가 한두 pixel 정도 이동하더라도 pooling을 거치면 비슷한 결과가 남을 수 있다.

따라서 작은 좌우/상하 이동에 덜 민감해진다.

### 3. 학습 Parameter가 없다

Pooling은 정해진 규칙에 따라 수행되는 연산이다.

따라서 convolution처럼 학습할 weight를 가지고 있지 않다.

---

# 22. Pooling의 문제

Pooling은 값을 직접 버린다.

예를 들어 2×2 max pooling에서는 4개 중 하나만 남기므로 나머지 3개의 정보가 사라진다.

그리고 어떤 값을 버릴 것인지에 대해 모델이 학습할 수도 없다.

즉,

> **고정된 rule에 의해 정보가 손실된다.**

이 문제를 보완하면서 해상도를 줄이는 방법으로 **Strided Convolution**이 사용된다.

---
# 32. Activation Memory 계산

Convolution의 출력 activation이 얼마나 memory를 사용하는지를 계산할 수 있다.

먼저 출력 원소 개수를 계산한다.

AlexNet 첫 layer라면

`96 × 55 × 55`

이다.

각 값을 float32로 저장한다면 하나의 값이 4byte를 사용한다.

따라서

`96 × 55 × 55 × 4 bytes`

로 activation memory를 계산할 수 있다.

강의에서는 이를 약 1,134KB 수준으로 설명한다.

---

# 33. Convolution Parameter 수 계산

AlexNet 첫 layer의 하나의 filter는

`3 × 11 × 11`

개의 weight를 가진다.

Filter는 96개이므로 weight 수는

`3 × 11 × 11 × 96`

이다.

그리고 filter마다 bias가 존재하므로 bias 96개를 추가한다.

일반화하면

`Parameter = Cin × K × K × Cout + Cout`

로 이해할 수 있다.

여기서

- `Cin` : input channel
    
- `Cout` : output channel = filter 수
    
- `K` : kernel size
    

이다.

---

# 34. Convolution 연산량

강의에서는 곱셈만 고려해 연산량을 계산한다.

하나의 출력 위치를 계산하기 위해서는 kernel 전체와 input patch의 곱셈이 필요하다.

따라서 대략

`Hout × Wout × Cout × Cin × K × K`

의 곱셈이 필요하다.

덧셈까지 함께 계산한다면 추가적인 연산을 고려해야 한다.

이 수치를 FLOPs 관점에서 사용한다.

---

# 35. AlexNet의 Memory / Parameter / FLOPs 특성

AlexNet에서는 세 종류의 비용이 서로 다른 위치에 집중된다.

## Activation Memory

초기 layer에서 많이 사용된다.

초기에는 공간 해상도가 크기 때문이다.

## Parameter

후반 FC에서 매우 많다.

예를 들어

`4096 × 4096`

과 같이 거대한 weight matrix가 필요하다.

## FLOPs

Convolution layer에서 많이 발생한다.

Convolution은 동일한 kernel을 이미지의 여러 위치에서 반복적으로 적용하기 때문이다.

따라서

> **Parameter가 많다고 반드시 계산량도 가장 많은 것은 아니다.**

AlexNet에서는

- Parameter → FC에 집중
    
- Computation → Conv에 집중
    

되는 특징이 있다.

---
# 47. Bottleneck Residual Block

보다 발전된 residual block에서는 3개의 convolution을 사용한다.

```text
1×1 Conv
   ↓
3×3 Conv
   ↓
1×1 Conv
```

핵심은 **1×1 Convolution**이다.

## 첫 번째 1×1 Conv

공간 해상도는 유지하면서 channel 수를 줄인다.

```text
많은 Channel
     ↓ 1×1
적은 Channel
```

이렇게 가운데 channel이 좁아지는 모습을 **Bottleneck**이라고 부른다.

## 가운데 3×3 Conv

줄어든 channel에서 spatial feature를 처리한다.

## 마지막 1×1 Conv

Channel을 다시 증가시켜 residual input과 더할 수 있는 shape으로 복원한다.

```text
Wide
 ↓
Narrow     ← Bottleneck
 ↓
Wide
```

---

# 48. Bottleneck의 장점

## 1. 연산량 감소

가장 비싼 3×3 convolution을 적은 channel에서 수행하기 때문에 연산량이 크게 감소한다.

## 2. Network Depth 증가

Basic block에서는 2개 layer를 사용했다면 bottleneck에서는 3개 layer를 사용할 수 있다.

따라서 효율성을 유지하면서 network를 더 깊게 만들 수 있다.

강의에서는 이 구조 덕분에 ResNet이

- 100 layer
    
- 150 layer 이상
    

으로 확장될 수 있었다고 설명한다.

따라서 ResNet-50 같은 모델은 이후에도 매우 강력한 CNN baseline으로 사용된다.

---
# 56. 일반 Convolution의 문제

일반 convolution은 한 번의 연산에서

1. 공간 방향의 정보를 섞고
    
2. channel 방향의 정보도 섞는다.
    

예를 들어 input channel과 output channel이 모두 `C`, kernel이 3×3이라고 하면 연산량은 대략

`9C²HW`

가 된다.

Channel 수가 커질수록 `C²`에 비례하여 연산량이 크게 증가한다.

---

# 57. MobileNet 핵심 — Depthwise Separable Convolution

MobileNet의 핵심 아이디어는

> **공간 연산과 channel 연산을 분리한다.**

일반 convolution에서는 두 가지를 동시에 했다면 MobileNet에서는

1. Depthwise Convolution
    
2. Pointwise Convolution
    

으로 나눈다.

---

# 58. Depthwise Convolution

각 channel별로 독립적으로 3×3 convolution을 수행한다.

즉 서로 다른 channel을 섞지 않는다.

```text
Channel 1 → 3×3 Conv
Channel 2 → 3×3 Conv
Channel 3 → 3×3 Conv
...
```

따라서 이 단계에서는

> **각 channel 내부에서 공간적인 정보가 서로 섞인다.**

연산량:

`9CHW`

정도다.

---

# 59. Pointwise Convolution

Depthwise convolution 이후 1×1 convolution을 사용한다.

1×1 convolution에서는 같은 공간 위치의 여러 channel을 조합한다.

즉

> **공간은 그대로 두고 channel 사이의 정보를 섞는다.**

연산량:

`C²HW`

정도다.

따라서 두 연산을 합치면

`9CHW + C²HW`

가 된다.

---

# 60. 일반 Conv와 MobileNet 연산량 비교

일반 3×3 convolution:

`9C²HW`

Depthwise + Pointwise:

`9CHW + C²HW`

두 연산량의 비율을 비교하면 강의에서는

`9C / (9 + C)`

형태로 설명한다.

Channel `C`가 매우 커지면

`C >> 9`

이므로 이 값은 약 9에 수렴한다.

즉 조건에 따라

> **일반 convolution보다 연산량을 최대 약 9배 수준까지 줄일 수 있다.**

Parameter 역시 크게 감소한다.

---
# 65. 강의에서 다시 강조한 주요 개념

## Filter / Kernel

이미지의 local feature를 검출하는 학습 가능한 weight.

## Activation Map

Filter를 이미지 전체에 적용해서 얻은 출력 map.

## Receptive Field

특정 output이 원본 이미지에서 보고 있는 영역의 크기.

## Padding

경계를 추가하여 출력 해상도를 조절하는 방법.

## Stride

Filter가 한 번에 이동하는 pixel 수.

## Pooling

정해진 규칙으로 해상도를 축소하는 방법.

## Strided Convolution

Convolution 자체의 stride를 증가시켜 학습 가능한 방식으로 downsampling하는 방법.

## 1×1 Convolution

공간 해상도를 유지하면서 channel 방향의 정보를 조합하거나 channel 수를 조정하는 방법.

대표 활용:

- ResNet bottleneck의 channel reduction/expansion
    
- MobileNet의 pointwise convolution
    

---
# 67. 계산 공식 모음

## Flatten

`H × W × C → HWC`

예:

`32 × 32 × 3 = 3072`

---

## Padding 없는 Stride 1 Convolution

`Output = Input - Kernel + 1`

---

## 일반 Convolution 출력 크기

`Output = (Input - Kernel + 2P) / S + 1`

- `P`: padding
    
- `S`: stride
    

---

## 출력 Channel

`Cout = Number of Filters`

---

## Convolution Parameter

`Cin × K × K × Cout + Cout(bias)`

---

## Activation Memory

`Hout × Wout × Cout × bytes per element`

float32라면 element당 4byte.

---

## Convolution Multiplication Cost

`Hout × Wout × Cout × Cin × K × K`

---
