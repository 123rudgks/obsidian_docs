# 0. 강의 개요

앞선 강의에서는 CNN, RNN, LSTM, Transformer와 같은 **모델 구조**를 살펴봤다.

이번 강의의 관심사는 구조 자체가 아니라

> **좋은 모델을 실제로 어떻게 잘 학습시킬 것인가?**

이다.

동일한 모델 architecture를 사용하더라도 누가 어떻게 학습시키느냐에 따라 최종 성능은 크게 달라질 수 있다.

논문에 나온 architecture를 그대로 구현한다고 해서 논문의 성능이 자동으로 재현되는 것도 아니다. 논문에 모든 training detail이 기록되는 것은 아니며 실제 학습에서는 많은 세부적인 선택이 필요하다.

이번 강의에서 중요하게 다루는 요소는 다음과 같다.

- Activation Function
    
- Data Preprocessing
    
- Weight Initialization
    
- Regularization
    
- Learning Rate
    
- Learning Rate Scheduling
    
- Early Stopping
    
- Hyperparameter Search
    
- Loss Curve를 이용한 학습 상태 진단
    
- 실제 모델 학습을 시작할 때의 단계별 checklist
    

---

# 1. 좋은 모델 구조만으로는 충분하지 않다

CNN의 기본적인 구성 요소는 앞선 강의에서 다음과 같이 설명했다.

```text
Convolution
    ↓
Non-linear Activation
    ↓
Normalization
    ↓
Pooling
    ↓
Fully Connected Layer
```

RNN이나 Transformer에서는 convolution이나 pooling이 없어질 수 있지만

- FC
    
- nonlinear activation
    
- normalization
    

등의 요소는 여전히 사용된다.

그러나 모델 구조를 잘 선택했다고 해서 좋은 성능이 자동으로 나오는 것은 아니다.

실제 모델 학습에서는 크게 세 가지 문제가 발생할 수 있다.

```text
1. Training Instability
2. Overfitting
3. Slow Convergence
```

강의에서는 같은 모델이라도 training strategy에 따라 **5~10% 수준까지 성능 차이가 발생할 수 있다**고 강조한다.

따라서

> **Model Architecture + Training Strategy**

가 함께 맞아야 좋은 모델이 만들어진다.

---

# 2. 학습 과정에서 발생하는 대표적인 문제

## 2.1 Training Instability

학습이 불안정하면 다음과 같은 현상이 나타난다.

- Loss가 갑자기 폭발
    
- Loss가 더 이상 감소하지 않음
    
- Training이 수렴하지 않음
    
- Training이 발산함
    

이러한 경우에는

- Learning Rate
    
- Weight Initialization
    
- Model Depth
    
- Optimizer
    
- Activation Function
    

등을 점검해야 한다.

---

# 3. Overfitting

과적합에서는 training 성능과 validation/test 성능의 방향이 갈라진다.

예를 들어

```text
Training Loss     ↓
Validation Error  ↑
```

와 같은 현상이 나타난다.

Training에서는 계속 데이터를 잘 맞추고 있는데 처음 보는 데이터에서는 오히려 성능이 떨어지는 것이다.

이는

> **모델이 training data를 지나치게 외우고 일반화하지 못하고 있다는 증거**

다.

따라서 모델을 학습할 때는 training loss만 확인해서는 안 된다.

항상

```text
Training
+
Validation
```

을 함께 관찰해야 한다.

---

# 4. Slow Convergence

최종적인 좋은 성능에 도달할 수 있더라도 시간이 지나치게 오래 걸리면 좋은 학습이라고 할 수 없다.

Deep Learning의 학습 자체가

- GPU
    
- 시간
    
- 전력
    
- 비용
    

등 상당한 자원을 사용하기 때문이다.

따라서 목표는 단순히 정확도를 높이는 것이 아니라

> **가능한 적은 학습 자원으로 빠르게 좋은 성능에 도달하는 것**

이다.

특히 이 문제에서 중요한 것이 **Learning Rate**다.

---

# 5. Activation Function이 필요한 이유

신경망 layer를 여러 개 쌓더라도 모든 layer가 선형 변환만 수행한다면 의미가 없다.

예를 들어

```text
W3(W2(W1x))
```

는 결국

```text
Wx
```

라는 하나의 선형 변환으로 합칠 수 있다.

따라서 복잡한 형태의 decision boundary를 학습하려면 layer 사이에 **non-linearity**가 필요하다.

이를 담당하는 것이 Activation Function이다.

대표적으로 강의에서는 다음을 다룬다.

- Sigmoid
    
- tanh
    
- ReLU
    
- Leaky ReLU
    
- ELU
    

---

# 6. Sigmoid

Sigmoid는 입력을 0과 1 사이 값으로 변환한다.

개념적인 식은

`σ(x) = 1 / (1 + e^-x)`

이다.

출력 범위:

`0 < σ(x) < 1`

따라서 출력값을 확률처럼 해석하기 쉽다는 장점이 있다.

---

# 7. Sigmoid의 문제 ① Saturation과 Gradient Vanishing

Sigmoid에서 입력값의 절댓값이 커지면 출력이 거의 변하지 않는다.

```text
큰 음수 → 0 근처
큰 양수 → 1 근처
```

이 영역에서는 입력이 변해도 출력 변화량이 거의 없다.

즉 derivative가 거의 0이 된다.

```text
Gradient ≈ 0
```

그러면 backpropagation 과정에서 gradient가 전달되지 않는다.

결국

> **특정 영역에 들어간 neuron이 거의 학습되지 않는 문제**

가 발생한다.

Sigmoid의 실질적으로 학습 가능한 범위가 좁다는 것이 중요한 단점이다.

---

# 8. Sigmoid의 문제 ② 출력이 항상 양수

Sigmoid의 출력은 항상

`0 ~ 1`

사이에 존재한다.

따라서 output이 zero-centered되어 있지 않고 양수 방향으로 치우친다.

강의에서는 이 때문에 gradient 역시 특정 방향으로 치우치면서 학습 효율이 떨어질 수 있다고 설명한다.

---

# 9. Sigmoid의 문제 ③ 계산량

Sigmoid에는 exponential operation이 들어간다.

따라서 단순한 연산만 사용하는 activation에 비하면 계산 비용도 높다.

이러한 문제 때문에 hidden layer의 일반적인 activation으로는 Sigmoid보다 다른 함수를 많이 사용한다.

---

# 10. tanh

tanh의 출력 범위는

`-1 ~ 1`

이다.

Sigmoid와 달리 양수와 음수를 모두 표현하므로 zero-centered에 더 가깝다는 장점이 있다.

```text
Sigmoid : 0 ~ 1
tanh    : -1 ~ 1
```

따라서 Sigmoid의 한쪽으로 치우친 출력 문제를 일부 개선한다.

---

# 11. tanh의 한계

하지만 tanh 역시 입력의 절댓값이 커지면 saturation이 발생한다.

즉 gradient가 존재하는 유효한 구간이 제한적이다.

또 exponential operation의 조합을 사용하므로 계산 비용 역시 존재한다.

따라서 일반적인 CNN hidden layer에서는 ReLU가 더 많이 사용된다.

다만 tanh가 쓸모없는 것은 아니다.

강의에서는 특정 architecture에서 tanh가 적합하게 사용되는 사례가 있다고 설명한다.

예:

- Vanilla RNN
    
- 과거의 일부 generative model
    

즉 activation은 architecture와 task에 따라 선택될 수 있다.

---

# 12. ReLU

현대 neural network에서 가장 대표적인 activation 중 하나다.

ReLU는 매우 단순하다.

`ReLU(x) = max(0, x)`

즉

```text
x < 0 → 0
x > 0 → x
```

이다.

---

# 13. ReLU의 장점

## 13.1 양수 영역에서 Gradient가 유지된다

Sigmoid나 tanh처럼 양수 입력이 커졌다고 해서 saturation되지 않는다.

양수 영역에서는 계속 선형으로 증가하므로 gradient가 살아 있다.

따라서 deep network에서 gradient vanishing 문제를 크게 줄일 수 있다.

## 13.2 연산이 매우 단순하다

ReLU는 사실상

```text
max(0, x)
```

만 계산하면 된다.

exponential 등의 복잡한 연산이 필요하지 않다.

따라서 많은 activation layer를 반복해서 사용해도 계산 부담이 적다.

## 13.3 빠른 학습

강의에서는 ReLU가 Sigmoid 계열보다 일반적으로 훨씬 빠르게 수렴하는 것으로 알려져 있다고 설명한다.

그래서 특별한 이유가 없다면 기본 activation으로 ReLU를 사용하는 것을 권장한다.

---

# 14. ReLU의 문제 — Dying ReLU

ReLU도 완벽하지 않다.

입력이 음수가 되면

```text
Output = 0
Gradient = 0
```

이다.

어떤 neuron의 입력이 계속 음수 영역에 머무르면 해당 neuron은 계속 0만 출력하게 된다.

이를

**Dying ReLU**

문제로 볼 수 있다.

즉 neuron이 사실상 죽어버리는 것이다.

또 ReLU 역시 출력이 완전히 대칭적이지 않고 양수 방향에 치우쳐 있다는 특징이 있다.

---

# 15. Leaky ReLU

ReLU의 Dying ReLU 문제를 해결하기 위해 등장한 방법이다.

ReLU:

```text
x < 0 → 0
```

Leaky ReLU:

```text
x < 0 → αx
```

처럼 음수에서도 작은 gradient가 존재하도록 한다.

따라서 음수 영역으로 들어간 neuron이 완전히 죽는 것을 방지한다.

---

# 16. Leaky ReLU의 한계

이론적으로 ReLU의 단점을 일부 해결하지만 실제 성능에서는 ReLU와 큰 차이가 없는 경우가 많다고 강의에서는 설명한다.

또 음수 영역의 기울기 `α`를 얼마나 사용할지 결정해야 한다.

예를 들어

`α = 0.1`

같은 값을 사용하는데 이 값 역시 hyperparameter다.

너무 작으면 ReLU와 거의 차이가 없고, 너무 크면 activation distribution이 달라질 수 있다.

---

# 17. ELU

ELU는 음수 영역에서 단순한 직선 대신 곡선 형태를 사용한다.

즉 음수 방향으로 내려가다가 saturation되는 구조를 가진다.

이를 통해

- Dying ReLU 문제 완화
    
- 음수 activation 허용
    
- gradient의 급격한 변화 완화
    

등을 목표로 한다.

하지만

- exponential 연산 사용
    
- α 등의 추가 hyperparameter
    
- 반드시 큰 성능 향상이 보장되는 것은 아님
    

등의 문제가 있다.

---

# 18. Activation Function 선택에 대한 강의의 권장

강의에서의 실질적인 기본 권장은 매우 단순하다.

> **특별한 이유가 없다면 ReLU부터 사용한다.**

이유는

- 성능이 충분히 좋음
    
- 연산량이 적음
    
- 다양한 architecture에서 검증됨
    
- 학습이 빠름
    
- 사용하기 단순함
    

때문이다.

정말 작은 성능 차이가 중요한 상황이라면

- Leaky ReLU
    
- ELU
    
- SELU 등
    

을 추가적으로 시험해볼 수 있다.

Sigmoid나 tanh는 일반적인 hidden layer에서 기본적으로 선택하기보다는 특정 architecture나 목적에 맞게 사용하는 것이 좋다고 설명한다.

---

# 19. Data Preprocessing

좋은 모델을 학습하려면 데이터의 형식을 일관되게 맞춰야 한다.

Training / Validation / Test에서 서로 다른 조건의 데이터를 넣으면 제대로 된 비교가 어렵다.

주요 전처리 요소는 다음과 같다.

### Resolution

입력 이미지 크기를 모델이 요구하는 해상도로 맞춘다.

### Color Format

예:

- RGB
    
- BGR
    
- HSV
    
- Grayscale
    

어떤 color representation을 사용하는지 통일해야 한다.

### Brightness / Scale

입력값의 scale도 맞춰야 한다.

### Normalization / Standardization

강의에서는 일반적으로

```text
Mean = 0
Standard deviation = 1
```

정도의 형태로 입력값을 맞추는 방식을 설명한다.

Normalization이 제대로 되어 있지 않으면 성능이 크게 떨어질 뿐 아니라 학습 자체가 제대로 진행되지 않을 수 있다.

---

# 20. Training과 Test의 전처리 Protocol

Training과 Test에서 가능한 동일한 input protocol을 유지해야 한다.

예를 들어 특정 model에서

- resize
    
- center crop
    
- normalization
    

을 사용했다면 inference에서도 모델이 학습한 조건에 맞는 preprocessing을 적용해야 한다.

특히 pretrained model을 사용할 때는

> **해당 모델이 원래 어떤 preprocessing을 기준으로 학습되었는지 확인해야 한다.**

---

# 21. CNN 모델마다 사용한 전처리가 다르다

강의에서는 대표 CNN들의 차이를 다음과 같이 설명한다.

## AlexNet

평균 이미지를 빼는 방식 사용.

## VGG

채널별 평균을 제거하는 방식 사용.

## ResNet

평균을 빼고 channel별 standard deviation으로 나누어 scale까지 맞추는 방식 사용.

즉 pretrained model을 가져왔을 때 architecture만 그대로 가져오고 preprocessing을 다르게 해서는 원래 보고된 성능이 재현되지 않을 수 있다.

---

# 22. Weight Initialization이 필요한 이유

Neural network를 gradient descent로 학습하려면 학습을 시작하기 전에 parameter의 초기값이 필요하다.

즉

```text
Initial Weight
     ↓
Forward
     ↓
Loss
     ↓
Backward
     ↓
Weight Update
```

가 이루어진다.

초기값이 잘못되면 학습 전체가 불안정해질 수 있다.

---

# 23. 모든 Weight를 0으로 초기화하면?

가장 단순하게

`W = 0`

으로 초기화할 수 있을 것처럼 보인다.

그러나 모든 parameter를 0으로 초기화하면 각 neuron이 동일하게 동작하게 되고 제대로 된 학습이 일어나기 어렵다.

강의의 설명 흐름에서는

```text
Weight = 0
→ Output도 0에 가까움
→ Gradient도 제대로 만들어지지 않음
→ Weight update가 발생하지 않음
```

이라는 문제를 강조한다.

따라서 모든 weight를 동일하게 0으로 초기화하는 것은 좋은 방법이 아니다.

---

# 24. Random Initialization

이를 해결하기 위해 작은 random value로 초기화하는 방법을 사용할 수 있다.

예를 들어 평균 0의 Gaussian distribution에서 작은 variance를 가진 값을 sampling한다.

장점:

- 모든 neuron을 동일한 값으로 만들지 않음
    
- 지나치게 큰 초기값 방지
    
- 비교적 안정적으로 시작 가능
    

그러나 network가 깊어지면 또 다른 문제가 발생한다.

---

# 25. 작은 Weight와 Gradient Vanishing

초기 weight들이 모두 1보다 매우 작다고 하자.

Deep network에서는 backpropagation 과정에서 여러 weight가 반복적으로 곱해진다.

```text
small × small × small × ...
```

이 반복되면 gradient가 점점 작아지고 결국 0에 가까워진다.

```text
Gradient → 0
```

그러면 초기 layer까지 학습 신호가 전달되지 않는다.

---

# 26. 너무 큰 Weight와 Gradient Explosion

반대로 초기값을 너무 크게 만들면

```text
large × large × large × ...
```

가 반복되면서 gradient가 폭발한다.

따라서 initialization은 단순히

> “적당히 작은 random value를 넣자.”

정도로 해결할 수 있는 문제가 아니다.

---

# 27. Xavier Initialization

이 문제를 해결하기 위해 등장한 방법 중 하나가 **Xavier Initialization**이다.

핵심 아이디어는

> **입력 차원에 맞춰 weight의 분산을 조절한다.**

는 것이다.

강의에서는 표준편차를 대략 입력 dimension의 제곱근에 반비례하도록 설정하는 방식을 설명한다.

개념적으로

`std ∝ 1 / √Din`

이다.

목표는 layer를 지나더라도

```text
Input Variance
≈
Output Variance
```

를 유지하는 것이다.

그래야 network가 깊어져도 activation이

- 0으로 수렴하거나
    
- 지나치게 폭발하는 것
    

을 방지할 수 있다.

---

# 28. Xavier Initialization과 tanh

Xavier initialization은 좌우 대칭적인 activation과 잘 맞는다.

강의에서는 tanh와 함께 사용할 경우 layer가 깊어져도 output variance가 비교적 안정적으로 유지되는 예를 보여준다.

하지만 실제 CNN에서는 tanh보다 ReLU를 더 많이 사용한다.

여기서 문제가 생긴다.

---

# 29. Xavier와 ReLU의 문제

ReLU는 입력의 음수 부분을 모두 0으로 만든다.

즉 activation distribution이 대칭적이지 않다.

```text
Negative half → 제거
Positive half → 유지
```

따라서 대칭적인 activation을 전제로 계산한 Xavier initialization을 그대로 사용하면 깊어질수록 variance가 감소할 수 있다.

이를 ReLU에 맞게 수정한 것이 **He Initialization**이다.

---

# 30. He Initialization

ReLU는 activation의 절반 정도를 제거하는 특성이 있기 때문에 이를 보정하여 initialization variance를 더 크게 잡는다.

강의에서는 Xavier 계열의 scaling에 추가적으로 `√2`에 해당하는 보정을 사용하는 것으로 설명한다.

핵심은

> **ReLU를 사용한다면 He Initialization을 사용하는 것이 적합하다.**

는 것이다.

따라서 실전에서는 다음 연결을 기억하면 된다.

```text
tanh 계열
→ Xavier Initialization

ReLU 계열
→ He Initialization
```

---

# 31. ResNet의 초기화 전략

ResNet은 residual connection 때문에 initialization에서 조금 다른 전략이 사용될 수 있다.

Residual block:

```text
Output = x + F(x)
```

에서 처음부터 `F(x)`가 지나치게 크면 deep network에서 output variance가 커질 수 있다.

강의에서는 ResNet에서

- ReLU와 연결되는 convolution → He initialization
    
- residual branch의 특정 후반부 → 0 initialization
    

을 활용하는 방식을 설명한다.

후반 residual branch를 0에 가깝게 만들면 초기에는

`F(x) ≈ 0`

이므로

`Output ≈ x`

가 된다.

즉 network가 처음에는 거의 skip connection에 의존한다.

```text
초기:
x + 0 ≈ x

학습 진행:
x + F(x)
```

이후 학습이 진행되면서 `F(x)`가 조금씩 의미 있는 변환을 배우도록 만드는 것이다.

이는 매우 깊은 ResNet의 초기 학습을 안정화하는 데 도움이 된다.

---

# 32. 과적합을 판단하는 방법

Training error는 계속 감소하는데 validation 성능이 좋아지지 않는다면 과적합을 의심해야 한다.

```text
Training performance ↑

Validation performance
→ 정체 또는 ↓
```

이 경우 핵심 문제는

> **Generalization 부족**

이다.

강의에서는 일반화 문제에 대한 첫 번째 해결 방향으로 **Regularization**을 제시한다.

---

# 33. Regularization의 기본 아이디어

모델이 특정 input이나 특정 feature에 지나치게 의존하면 training data를 외우게 된다.

이를 parameter 관점에서 보면 특정 weight의 절댓값이 지나치게 커지는 현상으로 볼 수도 있다.

따라서

> **특정 weight가 지나치게 dominant해지지 못하도록 penalty를 주자.**

라는 아이디어를 사용할 수 있다.

---

# 34. L2 Regularization / Weight Decay

L2 regularization은 weight의 제곱을 loss에 추가한다.

개념적으로

`Total Loss = Data Loss + λΣW²`

이다.

Weight가 커질수록 penalty도 커진다.

따라서 모델은 training loss를 줄이는 동시에 가능한 weight 크기도 지나치게 커지지 않도록 학습한다.

이 방법은 **Weight Decay**와 연결해서 설명된다.

여기서 `λ`는 regularization의 강도를 조절한다.

너무 크게 설정하면 실제 task 학습보다 regularization penalty가 지나치게 중요해질 수 있으므로 적절히 조절해야 한다.

---

# 35. L1 Regularization

L1은 weight의 제곱 대신 절댓값을 사용한다.

`Total Loss = Data Loss + λΣ|W|`

L1은 weight들을 0으로 만드는 경향이 상대적으로 강하다.

따라서

> **Sparse Parameter**

를 만드는 데 도움이 될 수 있다.

즉 많은 weight가 0이 되고 일부 weight만 살아남는 형태가 만들어질 수 있다.

---

# 36. Elastic Net

L1과 L2를 함께 사용하는 방법도 있다.

```text
L1
+
L2
```

를 결합한 방식을 **Elastic Net**이라고 한다.

각 regularization의 특성을 동시에 활용할 수 있다.

---

# 37. Dropout

또 다른 강력한 regularization 방법이 **Dropout**이다.

Training 과정에서 일부 neuron을 random하게 끈다.

예:

```text
원래 network

● ● ● ● ● ●

Dropout

● X ● ● X ●
```

매 iteration마다 서로 다른 neuron이 제거될 수 있다.

---

# 38. Dropout이 Overfitting을 줄이는 이유

어떤 특정 neuron 하나에 과도하게 의존하는 network를 생각해보자.

Training 때 그 neuron이 dropout으로 사라질 수도 있기 때문에 network는

> **그 neuron이 없어도 정답을 맞출 수 있어야 한다.**

따라서 여러 feature에 정보를 분산해서 사용하게 된다.

결과적으로

- 특정 feature에 대한 과도한 의존 감소
    
- 특정 neuron에 대한 의존 감소
    
- generalization 향상
    

효과를 기대할 수 있다.

---

# 39. Dropout은 어디에 사용하는가?

강의에서는 전통적인 CNN에서는 convolution weight 자체에 일반적인 dropout을 적용하는 방식은 많이 사용하지 않는다고 설명한다.

대신 Dropout은 전통적으로 **Fully Connected Layer**에서 많이 사용된다.

CNN의 convolution feature에 regularization을 적용하고 싶다면 activation map을 다루는 다른 방법 등이 사용될 수 있다.

또 Batch Normalization 등이 사용되는 CNN에서는 일반적인 dropout의 필요성이 줄어드는 경우도 있다고 설명한다.

---

# 40. Training과 Test에서 Dropout이 다른 문제

Training에서는 일부 neuron을 제거한다.

예를 들어

`Dropout probability = 0.5`

라면 절반 정도만 활성화된 상태에서 학습한다.

하지만 inference에서는 모든 neuron을 사용한다.

그대로 사용하면 training과 inference의 activation scale이 달라진다.

이를 보정해야 한다.

---

# 41. Inverted Dropout

현대적으로 많이 사용하는 방식은 **Inverted Dropout**이다.

Training 과정에서 살아남은 neuron의 값을 미리 scale-up한다.

그러면 inference에서는 별도의 scaling 없이 모든 neuron을 그대로 사용할 수 있다.

핵심은

> **Training과 Inference에서 activation의 기대 scale이 비슷하게 유지되도록 보정한다.**

는 것이다.

---

# 42. Learning Rate는 가장 중요한 Hyperparameter 중 하나

강의에서는 학습률을 특히 강하게 강조한다.

같은 모델을 구현했는데 성능이 안 나오는 경우 가장 먼저 의심해야 할 요소 중 하나가 Learning Rate다.

또 단일 learning rate만 선택하는 것이 아니라

> **학습 과정에서 learning rate를 어떻게 변화시킬 것인가**

까지 중요하다.

이를 **Learning Rate Scheduling**이라고 한다.

---

# 43. Learning Rate의 기본 원칙

가장 기본적인 원칙은

```text
초기 → 크게
후반 → 작게
```

이다.

왜일까?

## 초반

아직 최적점에서 멀리 떨어져 있다.

따라서 큰 step으로 빠르게 이동해도 된다.

```text
큰 Learning Rate
→ 빠르게 이동
```

## 후반

이미 좋은 해에 가까워졌다.

큰 step을 사용하면 최적점을 지나쳐버릴 수 있다.

따라서 작은 learning rate로 세밀하게 조정한다.

```text
작은 Learning Rate
→ 미세 조정
```

즉

> **처음에는 빠르게 이동하고, 마지막에는 조심스럽게 움직인다.**

가 기본 철학이다.

---

# 44. 좋은 Learning Rate의 Loss Curve

적절한 learning rate를 선택하면 loss가

- 지나치게 요동치지 않고
    
- 지나치게 느리지도 않으며
    
- 안정적으로 감소
    

한다.

따라서 학습 중에는 항상 **Loss Curve**를 관찰해야 한다.

Loss curve는 단순한 결과 그래프가 아니라 학습 상태를 진단하기 위한 매우 중요한 도구다.

---

# 45. Step Decay

가장 전통적인 learning rate scheduling 방법 중 하나다.

일정 시점마다 learning rate를 계단처럼 줄인다.

예:

```text
0.1
 ↓
0.01
 ↓
0.001
```

강의에서는 일반적으로 일정 시점마다 약 1/10 수준으로 감소시키는 방식을 예로 든다.

Loss가 plateau에 들어가기 시작할 때 learning rate를 낮추면 더 세밀하게 학습할 수 있다.

---

# 46. Epoch

**1 Epoch**은 전체 training dataset을 한 번 모두 사용하는 것을 의미한다.

예를 들어 데이터가 10,000개라면 모든 데이터 10,000개를 한 번씩 사용하면 1 epoch다.

```text
전체 Dataset 1회 학습
= 1 Epoch
```

여러 epoch을 반복하면 동일한 training dataset을 여러 번 학습하는 것이다.

---

# 47. Step Decay의 단점

Step Decay에는 learning rate를 언제 줄일지 직접 선택해야 하는 문제가 있다.

또 learning rate가

```text
0.1 → 0.01
```

처럼 순간적으로 크게 바뀌기 때문에 학습 상태가 갑자기 변화할 수 있다.

경우에 따라 학습이 불안정해질 수도 있다.

그럼에도 구조가 단순하고 널리 사용되기 때문에 처음 시도하기 좋은 방법으로 강의에서는 소개한다.

---

# 48. Cosine Learning Rate Schedule

Learning rate를 계단식으로 갑자기 변경하는 대신 cosine curve처럼 부드럽게 감소시킨다.

```text
Large LR
  ╲
   ╲
    ╲__
       Small LR
```

장점은 learning rate의 급격한 변화로 인한 instability를 줄일 수 있다는 것이다.

기본 철학은 여전히 동일하다.

```text
초기에는 크게
후반에는 작게
```

Image model training에서도 많이 사용되는 scheduling 방식이다.

---

# 49. Linear Learning Rate Schedule

Learning rate를 일정한 비율로 선형 감소시키는 방식도 있다.

강의에서는 특히

- 매우 큰 데이터
    
- 대규모 pretraining
    
- 낮은 learning rate를 사용하는 fine-tuning
    

등의 시나리오와 연결하여 설명한다.

즉 task와 training scale에 따라 적합한 schedule이 달라질 수 있다.

---

# 50. Learning Rate Schedule 선택

강의에서는 하나의 schedule이 언제나 최고라고 정하지 않는다.

이미지 모델에서는

- Step Decay
    
- Cosine Decay
    

둘 다 흔히 사용된다.

따라서 pretrained architecture를 참고한다면 원 논문이나 공식 training recipe에서 사용한 schedule을 우선 확인하고 필요하면 여러 schedule을 시험한다.

다만 어떤 방식을 사용하든 핵심 원칙은 동일하다.

> **학습 후반으로 갈수록 Learning Rate를 줄인다.**

---

# 51. Early Stopping

Regularization 외에도 overfitting을 막는 방법이 있다.

바로 **학습을 적절한 시점에서 종료하는 것**이다.

Training을 계속한다고 validation 성능이 계속 좋아지는 것은 아니다.

따라서

```text
Training metric
+
Validation metric
```

을 함께 관찰한다.

Validation 성능이 가장 좋은 시점의 checkpoint를 저장한다.

이후 training을 더 진행하면서 validation 성능이 나빠진다면 이전의 best checkpoint를 사용한다.

이를 Early Stopping과 연결해서 이해할 수 있다.

---

# 52. Parameter와 Hyperparameter의 차이

둘을 명확하게 구분해야 한다.

## Parameter

모델이 학습하면서 자동으로 결정한다.

예:

- weight
    
- bias
    

Gradient descent를 통해 업데이트된다.

## Hyperparameter

학습 전에 사람이 결정한다.

예:

- Learning Rate
    
- Batch Size
    
- Epoch
    
- Optimizer
    
- Momentum
    
- Weight Decay
    
- Dropout Ratio
    
- Channel Size
    
- Activation Function
    
- Model Architecture
    
- Learning Rate Decay 시점
    

즉

```text
Parameter
→ Model이 학습

Hyperparameter
→ 사람이 설정
```

이다.

---

# 53. 가장 중요한 Hyperparameter — Learning Rate

강의에서는 여러 hyperparameter 중 특히 learning rate가 성능에 매우 큰 영향을 준다고 강조한다.

단순히 초기 learning rate뿐 아니라

- 어느 값에서 시작할 것인가
    
- 언제 decay할 것인가
    
- 몇 번 decay할 것인가
    
- 얼마나 감소시킬 것인가
    
- 어떤 decay schedule을 사용할 것인가
    

모두 중요한 hyperparameter다.

---

# 54. Grid Search

Hyperparameter를 찾는 가장 단순한 방법이다.

예를 들어

```text
Learning Rate:
0.1, 0.01, 0.001

Batch Size:
32, 64, 128
```

이라면 모든 조합을 시험한다.

```text
0.1   × 32
0.1   × 64
0.1   × 128
0.01  × 32
...
```

이를 grid 형태로 모두 탐색한다.

---

# 55. Grid Search의 문제

모든 hyperparameter가 성능에 동일한 영향을 주는 것은 아니다.

예를 들어

```text
Parameter A → 성능에 큰 영향
Parameter B → 거의 영향 없음
```

이라고 하자.

Grid Search에서는 B 방향으로도 동일한 수의 실험을 하므로 많은 실험이 낭비된다.

즉 hyperparameter dimension이 늘어날수록 모든 조합을 검사하는 방법은 비효율적이다.

---

# 56. Random Search

Grid를 일정하게 나누는 대신 hyperparameter space에서 random하게 조합을 sampling한다.

장점은 특정 hyperparameter가 별로 중요하지 않더라도 중요한 dimension에 대해 더 다양한 값을 시험할 가능성이 높다는 것이다.

따라서 동일한 experiment budget에서는 Grid Search보다 효율적일 수 있다.

강의에서도 practical한 hyperparameter search에서는 Random Search의 장점을 강조한다.

---

# 57. 모든 Hyperparameter 조합을 시험해서는 안 된다

많은 연산 자원이 있으면 모든 조합을 시험할 수 있을 것처럼 보인다.

하지만 현실적으로 hyperparameter가 많기 때문에 모든 실험을 수행하는 것은 지나친 자원 낭비다.

강의에서는 대규모 모델을 다루는 엔지니어일수록 오히려 hyperparameter search를 전략적으로 수행해야 한다고 강조한다.

즉 중요한 능력은

> **많은 GPU를 사용하는 것이 아니라 적은 실험으로 좋은 후보를 빠르게 찾는 것**

이다.

---

# 58. 실제 모델 학습 Checklist

강의 후반부에서 가장 실무적인 내용이다.

처음부터 전체 dataset으로 장시간 학습하지 않는다.

문제를 단계별로 좁혀가며

> **어디가 잘못되었는지 빠르게 확인한다.**

---

# 59. Checklist 1 — 첫 Iteration의 Loss 확인

모델을 load하고 처음 데이터를 넣은 뒤 첫 번째 iteration의 loss를 확인한다.

Cross Entropy를 사용하고 class가 `C`개이며 모델이 거의 random prediction을 하고 있다면 초기 loss는 대략

`log(C)`

수준을 기대할 수 있다.

예:

```text
C = 10
→ 초기 loss ≈ log(10)
```

이와 전혀 다른 이상한 값이 나온다면 먼저 다음을 의심해야 한다.

- Data가 제대로 load되었는가?
    
- Label이 잘못되었는가?
    
- Label distribution에 문제가 있는가?
    
- Data loader에 bug가 있는가?
    

즉 첫 loss만 확인해도 data pipeline의 큰 문제를 빠르게 발견할 수 있다.

---

# 60. Checklist 2 — 아주 작은 Dataset을 일부러 Overfit

처음부터 전체 training dataset을 사용하지 않는다.

아주 작은 일부 sample만 사용한다.

그리고 regularization을 제거한 상태에서 모델이 이 작은 dataset을 완전히 외울 수 있는지 확인한다.

목표:

`Training Accuracy ≈ 100%`

작은 dataset조차 외우지 못한다면 model pipeline 어딘가에 문제가 있다는 의미다.

---

# 61. 작은 Dataset조차 Overfit하지 못한다면?

다음을 확인한다.

### Initialization

초기 weight가 잘못되어 있을 수 있다.

### Learning Rate

처음부터 learning rate가 잘못 선택되었을 수 있다.

### Model Architecture

- Channel 구조
    
- Layer 구조
    
- Activation Function
    

등에 문제가 있을 수 있다.

예를 들어 activation이 모든 값을 0으로 만들어버릴 수도 있다.

### Optimizer

Optimizer 설정 자체에 문제가 있을 수 있다.

### Code Bug

구현 버그일 수도 있다.

핵심은 작은 실험부터 시작하면 원인을 훨씬 좁은 범위에서 찾을 수 있다는 것이다.

---

# 62. Loss가 폭발한다면?

Loss가 갑자기 폭발한다면 다음을 우선 확인한다.

### Learning Rate가 너무 큰가?

큰 learning rate 때문에 optimization이 적절한 범위를 벗어날 수 있다.

→ Learning Rate를 줄인다.

### Initialization Scale이 너무 큰가?

초기 weight 자체가 너무 클 수 있다.

→ Initialization range를 확인한다.

### Network가 너무 깊은가?

Deep network에서는 gradient explosion 가능성이 증가할 수 있다.

특히 RNN 계열에서는 반복적인 weight multiplication 때문에 이러한 문제가 나타날 수 있다.

---

# 63. Checklist 3 — 초기 Learning Rate 후보 찾기

작은 dataset을 정상적으로 overfit할 수 있는 것을 확인했다면 이제 전체 training dataset을 사용한다.

그러나 아직 긴 학습을 하지 않는다.

대략 **100 iteration 정도의 매우 짧은 training**만 수행한다.

여러 learning rate 후보를 시험하여

> **초기 loss를 가장 빠르게 안정적으로 감소시키는 learning rate 영역**

을 찾는다.

이 단계에서 나쁜 후보를 빠르게 제거한다.

---

# 64. Checklist 4 — Learning Rate와 Decay 후보 좁히기

앞 단계에서 가능성 있는 초기 learning rate 후보를 얻었다.

이제

- Initial Learning Rate
    
- Learning Rate Decay 방식
    

등의 조합을 시험한다.

처음부터 수십~수백 epoch을 학습하지 않고 약 1~5 epoch 정도만 학습하여 후보를 비교한다.

핵심 가정은

> **좋은 hyperparameter 조합은 학습 초반부터 어느 정도 좋은 징후를 보여준다.**

는 것이다.

초기부터 전혀 학습되지 않는 후보가 나중에 갑자기 최고의 결과가 되는 경우는 드물기 때문에 일찍 제거한다.

이 단계에서는 단순 training loss보다 **validation 성능**을 중요하게 본다.

---

# 65. Checklist 5 — 좋은 후보만 더 길게 학습

앞 단계에서 hyperparameter 후보가 상당히 줄어들었다.

그 후보들을 대상으로 약

`10 ~ 20 epoch`

정도로 학습을 늘린다.

즉 전체 전략은

```text
많은 후보 × 아주 짧은 학습
        ↓
후보 축소
        ↓
적은 후보 × 조금 긴 학습
        ↓
후보 축소
        ↓
최종 후보 × Full Training
```

이다.

이렇게 해야 GPU 자원을 크게 낭비하지 않는다.

---

# 66. Checklist 6 — Loss Curve를 보고 Learning Rate Schedule 조정

학습 과정에서는 curve의 모양을 보고 원인을 추론할 수 있다.

## Case 1. 초반부터 Loss가 너무 오래 줄지 않는다

```text
Loss
───────
       ╲
```

초기 learning rate가 적절하지 않을 가능성이 있다.

초반부터 더 빠르게 loss를 감소시킬 수 있도록 초기 learning rate를 다시 조정해야 한다.

---

# 67. Case 2. 처음에는 잘 줄다가 중간에 Plateau

```text
Loss
╲
 ╲______
```

초기 learning rate는 괜찮았지만 어느 순간 더 이상 loss가 줄지 않는다.

이 경우에는 해당 plateau 구간에서

> **Learning Rate를 decay할 시점**

일 가능성이 있다.

---

# 68. Case 3. Learning Rate를 너무 일찍 감소

Learning rate를 낮췄는데 그 이후부터 학습이 거의 진행되지 않는다면 decay 시점이 너무 빨랐을 수 있다.

원래 큰 learning rate로 더 학습해야 하는 구간에서 너무 일찍 작은 learning rate를 사용한 것이다.

```text
너무 빠른 Decay
→ Update 크기 부족
→ Training 정체
```

---

# 69. Training과 Validation Curve를 함께 보는 방법

Learning curve는 반드시 training과 validation을 같이 봐야 한다.

## Case 1. 둘 다 계속 좋아지고 있다

```text
Train ↑
Valid ↑
```

아직 학습을 종료할 필요가 없다.

더 학습할 수 있다.

---

# 70. Case 2. Training은 좋아지는데 Validation은 나빠진다

```text
Train ↑
Valid ↓
```

전형적인 Overfitting이다.

해결 방향:

- Regularization
    
- Data Augmentation
    
- Early Stopping
    
- Model capacity 조절
    

등을 고려한다.

강의에서는 특히 regularization을 도입해야 한다는 signal로 설명한다.

---

# 71. Case 3. Training과 Validation 성능 차이가 거의 없지만 둘 다 낮다

언뜻 보면 generalization이 좋은 것처럼 보일 수 있다.

하지만 training data에서조차 충분히 높은 성능을 내지 못한다면 다른 문제다.

즉 모델 자체가 너무 약할 수 있다.

```text
Train 낮음
Valid 낮음
Gap 작음
```

→ **Underfitting 가능성**

이 경우 model capacity를 늘리면 training 성능이 더 올라갈 수 있고, 그 결과 validation 성능도 향상될 여지가 있다.

따라서 training-validation gap이 작다는 것만으로 좋은 모델이라고 판단해서는 안 된다.

---

# 72. 모델 학습 문제를 Loss Curve로 진단할 수 있다

강의에서 강조하는 중요한 실전 메시지는 다음과 같다.

많은 training 문제가 완전히 새로운 문제가 아니다.

대표적인 loss curve pattern에는 이미 알려진 원인과 해결책이 있다.

따라서

> **Loss Curve를 보고 현재 모델이 어떤 상태인지 판단하는 능력**

이 중요하다.

단순히

> “성능이 안 나온다.”

라고 말하는 것이 아니라

```text
Loss가 폭발하는가?
Loss가 처음부터 줄지 않는가?
중간에 plateau가 있는가?
Train/Validation gap이 커지는가?
Train 자체도 낮은가?
```

를 구분해야 한다.

# 73. 실전 Training Workflow

강의 내용을 실제 작업 순서로 정리하면 다음과 같다.

```text
① Model 선택
      ↓
② Data preprocessing 확인
      ↓
③ Weight initialization 설정
      ↓
④ 첫 iteration의 loss 확인
      ↓
⑤ 작은 dataset으로 100% overfit 가능한지 확인
      ↓
⑥ 초기 learning rate 후보 탐색
      ↓
⑦ 전체 dataset으로 짧은 training
      ↓
⑧ Learning rate / decay 후보 축소
      ↓
⑨ Validation 기준으로 좋은 후보 선택
      ↓
⑩ 더 긴 training 수행
      ↓
⑪ Train / Validation curve 관찰
      ↓
⑫ 필요하면 regularization 적용
      ↓
⑬ Learning rate decay 시점 조정
      ↓
⑭ Validation 최고 checkpoint 저장
      ↓
⑮ 최종 full training
```

핵심은

> **처음부터 모든 설정을 완전히 학습해서 비교하지 않는다.**

짧은 실험으로 나쁜 후보를 빠르게 제거하면서 탐색 범위를 줄여간다.

# 75. Activation Function 비교

|Activation|출력 특징|장점|주요 한계|
|---|---|---|---|
|Sigmoid|0~1|확률 형태 해석 용이|Saturation, gradient vanishing, 양수 편향|
|tanh|-1~1|Sigmoid보다 zero-centered|Saturation, 계산 비용|

|Leaky ReLU|음수에서도 작은 기울기|Dying ReLU 완화|slope 선택 필요, 성능 차이 제한적|
|ELU|음수 영역 곡선|음수 gradient, smooth|계산 복잡, hyperparameter|

### 기본 선택

**ReLU**

### ReLU를 사용할 때 Initialization

**He Initialization**

### tanh 계열

**Xavier Initialization**

|방식|특징|
|---|---|

> **초기에는 큰 LR, 후반에는 작은 LR**

Architecture만 문제가 아니다.

다음과 같은 요소 때문에 실패할 수 있다.

## Sigmoid의 주요 문제

- 출력이 한쪽으로 치우침
    
- 유효한 gradient 영역이 제한적
    
- 많은 입력 영역에서 gradient가 거의 0
    

---

## ReLU와 Leaky ReLU의 차이

ReLU:

```text
Negative → 0
```

Leaky ReLU:

```text
Negative → 작은 gradient 유지
```

따라서 Leaky ReLU는 Dying ReLU 문제를 줄이려는 방법이다.

---

## Dropout에서 주의할 점

Training에서는 neuron 일부를 제거하지만 inference에서는 모두 사용하기 때문에 output scale 차이를 보정해야 한다.

현대적으로는 Inverted Dropout 방식이 많이 사용된다.

---

## Step Learning Rate의 어려움

- Learning Rate를 변경할 시점을 직접 결정해야 함
    
- 갑작스러운 LR 변화 때문에 학습이 불안정해질 수 있음
    

---

## Learning Rate 기본 전략

```text
처음은 크게
뒤에는 작게
```

---

## Hyperparameter Search

Grid Search와 Random Search가 있으며 제한된 자원에서는 Random Search가 더 효율적인 탐색을 제공할 수 있다.

# 81. 이번 강의에서 반드시 기억해야 할 핵심 관점

### 1. Architecture만 좋다고 성능이 나오는 것이 아니다.

같은 모델에서도 training recipe에 따라 상당한 성능 차이가 발생할 수 있다.

### 2. ReLU는 가장 먼저 고려할 기본 activation이다.

특별한 이유가 없다면 ReLU부터 시작하는 것이 practical하다.

### 3. Activation과 Initialization은 연결해서 생각한다.

```text
tanh → Xavier
ReLU → He
```

### 4. Pretrained Model을 사용할 때 preprocessing도 함께 가져와야 한다.

Architecture만 동일하고 preprocessing이 다르면 원래 모델 성능이 나오지 않을 수 있다.

### 5. Overfitting은 Training과 Validation을 함께 봐야 발견할 수 있다.

Training loss만 보는 것은 위험하다.

### 6. Learning Rate는 가장 중요한 training hyperparameter 중 하나다.

그리고 하나의 LR보다 **LR Schedule**이 중요하다.

### 7. Learning Rate의 기본 원칙은 단순하다.

```text
초반 → 크게
후반 → 작게
```

### 8. 모든 Hyperparameter 조합을 끝까지 학습하지 않는다.

짧은 실험으로 후보를 빠르게 제거한다.

### 9. 작은 Dataset을 일부러 Overfit시키는 것은 중요한 debugging 방법이다.

작은 dataset조차 외우지 못한다면 generalization을 고민하기 전에 training pipeline 자체를 확인해야 한다.

### 10. Loss Curve는 모델 상태를 진단하는 도구다.

Loss curve의 형태를 보고

- Learning Rate
    
- Decay timing
    
- Overfitting
    
- Underfitting
    
- Initialization

# 82. 세 강의를 연결해서 보면

앞선 1~3차시의 관계는 다음과 같다.

```text
[1차시: 이미지 딥러닝 모델]

CNN은 이미지를 어떻게 이해하는가?
AlexNet → VGG → ResNet → MobileNet
          ↓

[2차시: 다양한 신경망 모델]

CNN의 한계는 무엇인가?
Sequence / Long-range dependency
RNN → LSTM → Attention → ViT
          ↓

[3차시: 이미지 모델 학습 전략]

좋은 Architecture를 실제로
어떻게 제대로 학습시킬 것인가?

Activation
Preprocessing
Initialization
Regularization
Learning Rate
Hyperparameter Search
Training Debugging
```

즉 1·2차시가 **“어떤 모델을 만들 것인가?”**를 다뤘다면 이번 3차시는

> **“선택한 모델을 어떻게 안정적이고 효율적으로 학습시켜 실제 성능을 끌어낼 것인가?”**

를 다루는 강의라고 정리할 수 있다.
