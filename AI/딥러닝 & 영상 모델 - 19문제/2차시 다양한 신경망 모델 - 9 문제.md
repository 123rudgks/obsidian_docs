# 0. 강의 개요

## 이번 강의의 출발점

앞 차시에서는 CNN의 기본 구조와 AlexNet, VGG, ResNet, MobileNet으로 이어지는 CNN의 발전을 살펴보았다.

이번 차시에서는 CNN이 가진 한계를 출발점으로 삼아, 이를 해결하기 위해 등장한 다른 신경망 구조를 살펴본다.

전체 흐름은 다음과 같다.

```text
CNN
 │
 ├─ 한계 1. 순서가 있는 데이터를 잘 처리하지 못함
 │           ↓
 │          RNN
 │           ↓
 │       Gradient 문제
 │           ↓
 │          LSTM
 │
 └─ 한계 2. 멀리 떨어진 데이터 간 관계를 직접 다루기 어려움
             ↓
          Attention
             ↓
       Self-Attention
             ↓
      Vision Transformer
             ↓
     Swin Transformer
```

따라서 이번 강의의 핵심은 각 모델의 구조를 따로 암기하는 것이 아니라

> **CNN의 어떤 한계 때문에 RNN이 필요했고, RNN의 어떤 한계 때문에 LSTM이 등장했으며, 그럼에도 남은 장거리 관계 문제를 Attention과 Transformer가 어떻게 해결했는가**

를 연결해서 이해하는 것이다.

---

# 1. CNN만으로 부족한 이유

CNN은 이미지의 지역적인 특징을 매우 잘 추출한다.

그러나 강의에서는 크게 세 가지 한계를 지적한다.

## 1.1 순서가 있는 데이터를 처리하기 어렵다

CNN 자체에는 데이터의 **시간적 순서나 전후 관계를 명시적으로 기억하는 구조**가 없다.

예를 들어 비디오는

```text
Frame 1 → Frame 2 → Frame 3 → ...
```

처럼 시간의 흐름을 가진다.

이때 앞에서 일어난 사건이 뒤의 사건과 관계를 가지므로 단순히 각각의 frame을 독립적인 이미지처럼 보는 것만으로는 충분하지 않다.

### 텍스트 예시

강의에서는 순서의 중요성을 보여주기 위해 다음과 같은 예를 든다.

```text
약을 먹고 잠을 잔다.
잠을 자고 약을 먹는다.
```

두 문장은 사용된 단어 자체는 거의 같지만 **순서가 달라지면서 의미가 달라진다.**

영어에서도

```text
I am a boy, not a girl.
I am a girl, not a boy.
```

처럼 구성 요소가 같더라도 순서에 따라 의미가 완전히 바뀐다.

비디오 역시 frame의 순서에 따라

- 사건의 맥락
    
- 행동의 방향
    
- 행동 패턴
    

이 달라질 수 있다.

따라서 **sequence 자체를 모델링할 구조**가 필요하다.

---

# 2. CNN의 두 번째 한계 — Long-range Dependency

CNN은 작은 local feature부터 시작해 layer를 깊게 쌓으면서 점차 넓은 영역을 이해한다.

```text
Local
 ↓
Part
 ↓
Object
 ↓
Global context
```

하지만 이러한 방식에서는 매우 멀리 떨어져 있는 두 위치의 관계를 **한 번에 직접 비교하기 어렵다.**

예를 들어 이미지의 왼쪽 위에 있는 patch와 오른쪽 아래에 있는 patch가 의미적으로 매우 유사할 수 있다.

CNN에서는 물리적으로 가까운 pixel들의 관계는 쉽게 학습할 수 있지만,

```text
Patch A ─────────────────── Patch B
```

처럼 멀리 떨어진 두 영역의 강한 correlation을 직접 발견하기는 상대적으로 어렵다.

이미지에서는 같은 pattern이 반드시 가까운 위치에 반복되는 것도 아니다.

따라서

> **공간적으로 얼마나 떨어져 있는가와 관계없이 어떤 영역이 서로 관련되어 있는지를 판단할 방법**

이 필요하다.

이 문제에 대한 중요한 해결책이 이후 등장하는 **Attention**이다.

---

# 3. CNN에서 위치 정보가 손실될 수 있는 문제

CNN은 classification처럼 이미지 전체의 정보를 압축하는 작업에는 효과적이다.

그러나 layer가 깊어지면서 pooling이나 downsampling을 반복하면 공간 해상도가 계속 감소한다.

그 과정에서 정확한 위치 정보가 일부 손실될 수 있다.

이 때문에 CNN은

- 가벼운 이미지 모델
    
- classification
    

등에는 여전히 강력하지만, 매우 정확한 공간 정보를 요구하는 고성능 detection 등의 문제에서는 한계가 발생할 수 있다고 강의에서는 설명한다.

---

# 4. CNN 구조 다시 보기

앞 차시에서 살펴본 일반적인 CNN의 구조는 다음과 같다.

```text
Convolution
    ↓
Non-linear Activation
    ↓
Normalization
    ↓
Pooling / Downsampling
    ↓
...
    ↓
Fully Connected Layer
```

각 요소의 역할은 다음과 같다.

### Convolution

이미지의 feature를 추출한다.

### Pooling

공간 해상도를 줄인다.

### Non-linear Activation

여러 layer를 쌓았을 때 실제 표현 능력을 증가시킨다.

### Normalization

데이터의 분포를 조절하고 일반화 성능 및 안정적인 학습에 기여한다.

### Fully Connected Layer

classification 등 최종 task를 수행한다.

CNN은 여전히

- 이미지 분류
    
- 객체 탐지
    
- 위치 추정
    

등 다양한 image task에서 활용된다.

---

# 5. RNN — Sequence를 위한 Neural Network

CNN의 첫 번째 한계인 **순서 문제**를 해결하기 위해 등장한 대표적인 구조가 RNN(Recurrent Neural Network)이다.

RNN은 이미지에만 특화된 모델이 아니라

> **순서가 존재하는 sequential data를 처리하도록 설계된 neural network**

다.

대표적인 대상:

- 언어
    
- 시계열 데이터
    
- 음성
    
- 비디오
    

---

# 6. RNN의 핵심 — Hidden State

RNN의 가장 중요한 특징은 **이전 단계의 정보를 다음 단계에 전달한다는 것**이다.

이를 위해 **Hidden State**를 사용한다.

현재 시점을 `t`라고 하면 현재의 hidden state는 개념적으로

```text
현재 입력 x_t
     +
이전 Hidden State h_(t-1)
     ↓
현재 Hidden State h_t
```

의 영향을 받아 만들어진다.

그리고 현재 hidden state는

1. 현재 출력을 만드는 데 사용되고
    
2. 다음 시점의 hidden state에도 전달된다.
    

```text
x₁ → [RNN] → h₁ → y₁
             ↓
x₂ → [RNN] → h₂ → y₂
             ↓
x₃ → [RNN] → h₃ → y₃
```

따라서 이전 정보가 다음 시점의 계산에 영향을 줄 수 있다.

CNN에는 없던 명확한 **시간적 연결 구조**다.

---

# 7. RNN에서 문자 데이터를 입력하는 방법

강의에서는 문자 생성 문제를 예로 든다.

문자 자체는 그대로 neural network에 넣을 수 없기 때문에 숫자 vector로 바꿔야 한다.

예를 들어 사용 가능한 문자가

```text
H, E, L, O
```

라고 한다면 One-hot Encoding을 사용할 수 있다.

```text
H = [1, 0, 0, 0]
E = [0, 1, 0, 0]
L = [0, 0, 1, 0]
O = [0, 0, 0, 1]
```

각 문자를 vector로 변환한 후 RNN의 입력으로 사용한다.

이와 같은 방식은 문자뿐 아니라 다양한 discrete input을 vector화하는 데 사용할 수 있다.

---

# 8. RNN의 세 가지 주요 변환

강의에서 설명하는 RNN은 크게 세 종류의 학습 가능한 변환을 가진다.

## Input → Hidden

현재 입력을 hidden representation으로 바꾼다.

개념적으로

`W_xh`

에 해당하는 변환이다.

## Hidden → Hidden

이전 hidden state를 현재 hidden state에 전달한다.

`W_hh`

에 해당한다.

이 부분이 바로

> **이전 sequence의 정보를 현재 계산에 반영하는 핵심**

이다.

## Hidden → Output

현재 hidden state를 실제 출력으로 변환한다.

`W_hy`

에 해당한다.

따라서 전체적으로

```text
x_t
 │
 ↓ W_xh
 ┌───────────────┐
 │ Hidden State  │ ← W_hh ← h_(t-1)
 └───────────────┘
         │
         ↓ W_hy
        y_t
```

와 같은 흐름으로 이해할 수 있다.

---

# 9. RNN의 학습과 실행 단계 차이

강의에서는 문자 생성 문제를 통해 **학습 단계와 실제 실행 단계가 다르다**는 점을 강조한다.

## 학습할 때

모델이 현재 입력을 보고 다음 문자를 예측한다.

예측이 틀렸더라도 다음 step에서는 모델이 예측한 잘못된 문자를 사용하는 것이 아니라 **실제 정답 sequence의 다음 문자**를 입력한다.

예:

```text
정답 sequence: H → E → L → L → O

H 입력
↓
모델이 X라고 잘못 예측

다음 입력:
X가 아니라 실제 정답 E
```

이 방식으로 올바른 sequence를 제공하면서 `W`들을 학습한다.

## 실제 실행할 때

정답의 다음 문자를 알 수 없다.

따라서

```text
H
↓
예측: E
↓
예측한 E를 다음 입력으로 사용
↓
예측: L
↓
예측한 L을 다음 입력으로 사용
...
```

처럼 **자신의 이전 예측을 다시 입력으로 사용하는 반복 구조**가 된다.

---

# 10. Hidden State가 Context를 저장한다

예를 들어

```text
H → E → L → ...
```

을 처리한다고 하자.

두 번째 hidden state는 단순히 `E`만 보고 만들어지는 것이 아니다.

```text
현재 입력 E
+
H를 처리하고 남은 이전 hidden state
```

를 모두 반영한다.

따라서 hidden state는

> **지금까지 입력된 sequence의 context를 압축하여 가지고 있는 memory**

로 이해할 수 있다.

RNN cell은

1. 이전 정보를 기억하고
    
2. 현재 입력과 결합하며
    
3. 현재 출력을 만든다.
    

---

# 11. 시간마다 새로운 Weight를 학습하는 것은 아니다

RNN을 펼쳐서 보면

```text
t=1 → t=2 → t=3 → ... → t=T
```

마다 여러 RNN cell이 존재하는 것처럼 보인다.

하지만 각각이 서로 다른 parameter를 사용하는 것이 아니다.

같은 transformation `W`가 모든 time step에서 반복적으로 사용된다.

```text
W at t=1
=
W at t=2
=
W at t=3
...
```

Time step에 따라 바뀌는 것은 **hidden state**이지 `W` 자체가 아니다.

만약 시간마다 별도의 `W`를 학습한다면 parameter가 지나치게 많이 필요하고 각 시점마다 많은 데이터도 필요해진다.

따라서

> **RNN은 parameter를 time step 전체에서 공유한다.**

---

# 12. Vanilla RNN과 tanh

현재 hidden state는

- 현재 입력
    
- 이전 hidden state
    

를 결합해 계산한다.

그리고 단순한 선형 변환으로 끝내지 않고 nonlinear activation을 적용한다.

강의에서는 Vanilla RNN에서 대표적으로 **tanh**를 사용한다고 설명한다.

```text
현재 입력
+
이전 Hidden
      ↓
Linear transformation
      ↓
tanh
      ↓
현재 Hidden State
```

비선형 함수를 사용함으로써 더 복잡한 sequence pattern을 표현할 수 있다.

---

# 13. RNN의 다양한 입력·출력 구조

RNN은 task에 따라 입력과 출력의 sequence 형태를 다양하게 만들 수 있다.

## 13.1 One-to-One

```text
1 Input → 1 Output
```

예:

- 이미지 한 장 → class 하나
    

일반적인 classification과 유사하다.

---

# 14. One-to-Many

```text
1 Input → 여러 개의 Sequential Output
```

예:

### Image Captioning

```text
Image
 ↓
"A dog is running"
```

한 이미지로부터 여러 단어가 순서대로 생성된다.

다른 예:

- 이미지 → 음악 생성
    
- 이미지 → 문장 생성
    

---

# 15. Many-to-One

```text
Sequence Input → 1 Output
```

대표적으로 **Video Classification**이 있다.

```text
Frame 1
Frame 2
Frame 3
Frame 4
   ↓
 RNN
   ↓
"Running"
```

여러 video frame을 순서대로 입력받지만 최종 출력은

- 뛰고 있다
    
- 숨고 있다
    

와 같은 행동 class 하나가 된다.

---

# 16. Many-to-Many

```text
Sequence Input
      ↓
Sequence Output
```

이미지/비디오에서는 각 frame에 대해 각각의 action이나 object를 예측하는 문제가 가능하다.

언어에서는 대표적으로

- 번역
    
- 음성 → 텍스트
    

와 같은 task가 있다.

강의에서는 Many-to-Many를 구조적으로

```text
Many-to-One
+
One-to-Many
```

를 연결해서 구현할 수도 있다고 설명한다.

입력 sequence 전체를 hidden state에 반영한 후, 최종 hidden state에서 다시 output sequence를 생성하는 방식이다.

---

# 17. RNN을 이용한 문자 생성

실제 실행에서는

1. 현재 문자를 one-hot vector로 변환
    
2. Hidden state 계산
    
3. Hidden → Output 변환
    
4. Softmax 적용
    
5. 가장 확률이 높은 문자 선택
    
6. 선택된 문자를 다음 입력으로 사용
    
7. 반복
    

의 과정을 수행한다.

```text
Input
 ↓
Hidden
 ↓
Output
 ↓
Softmax
 ↓
Next Character
 ↓
다시 Input
```

이러한 반복을 통해

- 단어 생성
    
- 문장 생성
    
- sequence 예측
    

등이 가능하다.

---

# 18. RNN의 핵심 한계 — Gradient 문제

RNN은 sequence를 처리할 수 있지만 sequence가 길어지면 학습 과정에서 문제가 발생한다.

그 이유는 같은 `W`가 time step마다 반복적으로 사용되기 때문이다.

```text
t1
 ↓ W
t2
 ↓ W
t3
 ↓ W
t4
 ↓ W
...
```

Backpropagation 과정에서도 여러 time step을 거쳐 gradient가 계속 전달된다.

강의에서는 각 time step에서 발생한 gradient가 누적되고, 반복적인 weight의 영향으로 인해 gradient가 불안정해질 수 있다고 설명한다.

---

# 19. Exploding Gradient

반복적으로 영향을 주는 weight의 크기가 커지는 방향이라면 time step을 지나면서 값이 계속 커질 수 있다.

개념적으로

```text
1보다 큰 값
×
1보다 큰 값
×
1보다 큰 값
× ...
```

이 반복되면 값이 매우 빠르게 증가한다.

그 결과

> **Gradient가 지나치게 커지는 Exploding Gradient**

가 발생한다.

---

# 20. Vanishing Gradient

반대로 반복적으로 곱해지는 영향이 1보다 작다면

```text
0.5 × 0.5 × 0.5 × 0.5 × ...
```

처럼 값이 점점 작아진다.

오래된 time step까지 gradient가 전달되지 못하고 거의 0이 될 수 있다.

이를

> **Vanishing Gradient**

라고 한다.

따라서 Vanilla RNN은 긴 sequence를 학습할 때

```text
Gradient Explosion
또는
Gradient Vanishing
```

을 경험할 수 있다.

---

# 21. Gradient Clipping

Exploding Gradient를 완화하기 위한 방법으로 강의에서는 **Gradient Clipping**을 소개한다.

Gradient가 지나치게 커지면 일정 범위에서 잘라낸다.

```text
너무 큰 Gradient
      ↓
Clipping
      ↓
제한된 Gradient
```

이렇게 하면 모델의 update가 폭발하는 것을 방지할 수 있다.

하지만 문제가 있다.

원래 데이터로부터 계산된 gradient를 인위적으로 수정하는 것이므로 **실제 gradient와 다른 update를 수행하게 된다.**

따라서 폭발을 막는 데는 도움이 되지만 학습 자체를 방해할 가능성도 있다.

또한 gradient가 이미 0에 가까워진 **Vanishing Gradient는 clipping으로 복구할 수 없다.**

---

# 22. LSTM의 등장

RNN의 gradient 문제를 개선하기 위한 대표적인 구조가 **LSTM(Long Short-Term Memory)** 이다.

LSTM의 중요한 문제의식은

> 모든 과거 정보를 똑같이 계속 전달할 필요가 있는가?

이다.

긴 sequence에는

- 중요한 정보
    
- 불필요한 정보
    

가 함께 들어 있다.

RNN은 이를 충분히 선택적으로 관리하기 어렵다.

LSTM은 이를 위해

1. **Cell State**
    
2. **Gate**
    

를 추가한다.

---

# 23. RNN과 LSTM의 State 차이

Vanilla RNN에서는 주요 상태가 Hidden State 하나였다.

```text
RNN
→ Hidden State
```

LSTM에서는 이를 두 종류로 나눈다.

```text
LSTM
├─ Hidden State
└─ Cell State
```

### Hidden State

현재 step의 표현 및 출력과 직접 관련된 상태.

### Cell State

긴 sequence에 걸쳐 정보를 전달하고 보존하는 별도의 경로.

Cell State가 장기적인 memory의 역할을 담당한다.

---

# 24. Gate란 무엇인가?

Gate는 일종의 **정보 흐름을 제어하는 switch**다.

LSTM에서는

- 과거 정보 중 무엇을 버릴 것인가?
    
- 현재 입력 중 무엇을 저장할 것인가?
    
- 현재 상태 중 무엇을 출력할 것인가?
    

를 gate를 통해 조절한다.

즉 RNN이 이전 hidden state를 비교적 그대로 전달했다면 LSTM은

> **필요한 정보만 선택적으로 통과시키고 불필요한 정보는 제거하려 한다.**

---

# 25. Forget Gate

**망각 게이트(Forget Gate)** 는 과거 정보 중 얼마나 버릴지를 결정한다.

```text
Past Information
      ↓
Forget Gate
      ↓
유지할 정보 / 제거할 정보
```

즉

> **과거 정보 중 무엇을 잊을 것인가**

를 결정한다.

---

# 26. Input Gate

**입력 게이트(Input Gate)** 는 새로운 입력 중 무엇을 Cell State에 저장할지를 조절한다.

모든 현재 정보를 저장하는 것이 아니라 필요한 정보만 선택적으로 저장한다.

즉

> **현재 정보 중 무엇을 기억할 것인가**

를 결정한다.

---

# 27. Output Gate

**출력 게이트(Output Gate)** 는 현재 Cell State 중 얼마를 현재 Hidden State로 내보낼지를 결정한다.

즉

> **현재 기억 중 무엇을 실제 출력에 반영할 것인가**

를 조절한다.

이를 정리하면 다음과 같다.

|Gate|역할|
|---|---|
|Forget Gate|과거 정보 중 무엇을 버릴 것인가|
|Input Gate|현재 입력 중 무엇을 저장할 것인가|
|Output Gate|현재 Cell State 중 무엇을 출력할 것인가|

---

# 28. LSTM이 덧셈 경로를 사용하는 이유

RNN에서는 sequence를 따라 반복적인 곱셈이 계속 이루어졌다.

이것이 Gradient Explosion과 Vanishing의 원인이 될 수 있었다.

LSTM에서는 Cell State를 전달하는 과정에서 **덧셈 형태의 경로**를 적극적으로 활용한다.

강의에서는 이 경로를 이전 차시의 ResNet과 연결해서 설명한다.

ResNet에서도

```text
F(x) + x
```

처럼 별도의 additive path가 존재했고, 이 경로가 정보와 gradient를 직접 전달하는 데 도움을 주었다.

LSTM에서도 마찬가지로 Cell State가 별도의 경로를 따라 전달되기 때문에 gradient가 완전히 사라지는 것을 줄일 수 있다.

---

# 29. LSTM의 Highway Path

강의에서는 Cell State가 sequence를 따라 이어지는 경로를 일종의 **Highway Path**로 설명한다.

```text
C₁ ─────→ C₂ ─────→ C₃ ─────→ C₄
 │          │          │
Gate       Gate       Gate
```

일반적인 hidden transformation과 별개로 Cell State가 계속 전달된다.

따라서 중간에서 특정 transformation의 gradient가 약해지더라도 별도의 additive path를 통해 정보와 gradient가 보다 오래 살아남을 수 있다.

즉 LSTM은 Vanilla RNN보다 **Vanishing Gradient에 더 강하다.**

---

# 30. 그렇다고 LSTM이 장거리 문제를 완전히 해결하는 것은 아니다

LSTM은 RNN보다 과거 정보를 훨씬 잘 보존한다.

하지만 여전히 문제가 남는다.

예를 들어 현재가 `t=20`이라고 하자.

현재 판단에서

```text
t=8 정보는 매우 중요
t=19 정보는 중요하지 않음
```

일 수 있다.

LSTM의 gate는

> 바로 이전 정보에서 얼마나 가져올 것인가

를 잘 조절할 수 있지만,

> 수많은 과거 step 중 특정 시점 하나를 직접 찾아서 이것이 가장 중요하다고 판단하는 것

에는 한계가 있다.

따라서 LSTM 역시 sequence를 처리하도록 정교하게 설계된 모델이지만 **특정 과거 시점과 현재의 직접적인 관계를 정밀하게 모델링하기에는 한계**가 있다.

---

# 31. RNN 계열의 Recency 문제

강의 후반의 모델 비교에서도 이 문제를 다시 강조한다.

RNN의 hidden state에는 직전의 정보가 계속 반영된다.

따라서

```text
아주 오래전 입력
vs
바로 직전 입력
```

을 비교하면 최신 입력이 hidden state에 더 강한 영향을 미치기 쉽다.

LSTM은 gate를 이용해 이를 어느 정도 완화하지만

> “12 step 전의 특정 정보가 지금 특별히 중요하다.”

와 같이 **임의의 과거 시점에 직접 높은 중요도를 줄 수 있는 정교함은 부족하다.**

---

# 32. Attention이 필요한 이유

이 문제를 보다 직접적으로 해결하는 것이 **Attention Mechanism**이다.

Attention의 핵심 질문은 다음과 같다.

> 현재 내가 보고 있는 데이터와 다른 모든 데이터 사이에서 무엇이 가장 관련이 있는가?

중요한 점은 위치적으로 가까운가가 아니다.

```text
가까움 ≠ 의미적으로 유사함
```

이미지의 아주 멀리 떨어진 두 patch가 오히려 의미적으로 동일할 수도 있다.

Attention은 이런 **distance-independent relationship**을 직접 계산한다.

---

# 33. 이미지 노이즈 제거 예시

Attention의 유용성을 설명하기 위해 강의에서는 이미지 denoising 사례를 든다.

Noise를 제거하는 간단한 방법 중 하나는 주변 pixel들을 평균내는 것이다.

하지만 주변 모든 pixel의 평균을 사용하면 이미지가 흐려질 수 있다.

따라서 더 좋은 방법은

> 이미지에서 현재 pixel과 **유사한 pixel들만 찾아서** 평균을 계산하는 것

이다.

문제는 유사한 pixel이 바로 옆에만 있지 않을 수 있다는 것이다.

Attention을 이용하면 이미지에서 멀리 떨어져 있어도 유사한 patch를 찾을 수 있다.

이 아이디어는 denoising뿐 아니라

- classification
    
- robust representation
    
- image understanding
    

에도 활용될 수 있다.

---

# 34. Attention의 세 요소 — Query, Key, Value

Attention을 이해하려면 세 가지 개념이 중요하다.

```text
Query
Key
Value
```

## Query(Q)

> **내가 지금 알고 싶은 대상**

이미지에서는 현재 집중하고 있는 patch라고 생각할 수 있다.

## Key(K)

Query와 비교할 다른 patch들의 표현.

즉

> **Query와 얼마나 관련 있는지를 비교할 대상**

이다.

## Value(V)

각 Key가 실제로 가지고 있는 정보 또는 representation.

강의에서는 이를

- embedding
    
- 좋은 표현 vector
    
- feature
    

라고 설명한다.

---

# 35. Attention의 직관

Query 하나가 있다고 하자.

그리고 여러 Key가 있다.

```text
            Key 1
              ↑
Key 2 ← Query → Key 3
              ↓
            Key 4
```

Query와 각 Key가 얼마나 비슷한지를 계산한다.

```text
Query ↔ Key 1 : 매우 유사
Query ↔ Key 2 : 조금 유사
Query ↔ Key 3 : 거의 무관
...
```

이 유사도를 **Attention Weight**로 사용한다.

그리고 각 Key에 대응되는 Value에 그 weight를 곱한다.

```text
Output
=
Attention₁ × Value₁
+
Attention₂ × Value₂
+
Attention₃ × Value₃
+ ...
```

즉

> **Query를 다른 데이터들의 Value 조합으로 다시 표현한다.**

유사한 데이터의 정보는 많이 반영하고 관련 없는 데이터는 적게 반영한다.

---

# 36. Attention Weight는 어떻게 계산하는가?

강의에서는 Query와 Key의 **내적**을 이용하여 유사도를 계산한다고 설명한다.

전체적인 흐름:

```text
Query · Key
     ↓
Dimension 기준 정규화
     ↓
Softmax
     ↓
Attention Weight
```

Softmax를 적용하면 각 유사도를 비교 가능한 weight로 바꿀 수 있다.

Query와 더 유사한 Key에는 큰 attention 값이 부여되고, 덜 유사하면 작은 값이 부여된다.

그리고 이 attention을 Value에 곱하여 최종 출력을 만든다.

---

# 37. Attention에서 학습되는 것은 무엇인가?

Query, Key, Value가 처음부터 존재하는 것은 아니다.

입력 token으로부터

- Query를 만드는 transformation
    
- Key를 만드는 transformation
    
- Value를 만드는 transformation
    

이 학습된다.

즉 학습되는 주요 parameter는 개념적으로

```text
W_Q
W_K
W_V
```

이다.

이 transformation을 통해 하나의 입력 representation으로부터 Q, K, V를 만든 뒤 attention을 계산한다.

---

# 38. Self-Attention

Query와 Key, Value가 **같은 입력 데이터 안에서 만들어지는 경우**를 Self-Attention이라고 한다.

이미지 한 장이 있다고 하면

```text
같은 이미지
 ├─ Query
 ├─ Key
 └─ Value
```

가 모두 만들어진다.

따라서 한 이미지 내부에서

> **각 patch가 다른 모든 patch와 얼마나 관련 있는가**

를 계산할 수 있다.

---

# 39. Self-Attention과 자동적인 유사성 학습

Self-Attention을 반복적으로 학습하면 유사한 patch끼리 높은 attention을 가지게 될 수 있다.

결과적으로

```text
비슷한 Patch
     ↓
High Attention
     ↓
유사한 Representation
```

이 형성된다.

강의에서는 이를 일종의 **자연스러운 clustering 효과**로 설명한다.

중요한 점은 사전에

```text
"이 patch와 저 patch는 같은 그룹이다."
```

라는 label을 직접 주지 않아도 attention을 계산하는 과정에서 데이터 내부의 유사한 영역을 발견할 수 있다는 것이다.

따라서 Attention은 데이터 representation 자체를 강력하게 만드는 구조적 장점을 가진다.

---

# 40. Cross-Attention

Self-Attention은 Q, K, V가 같은 데이터에서 나온다.

반면 **Cross-Attention**에서는 서로 다른 종류의 데이터에서 Q와 K/V가 나올 수 있다.

예:

```text
Query → Image
Key   → Text
```

또는 반대로

```text
Query → Text
Key   → Image
```

와 같이 구성할 수 있다.

이를 통해

- 어떤 image patch와 어떤 text가 대응하는가?
    
- 어떤 text를 설명하는 image 영역은 무엇인가?
    

를 연결할 수 있다.

---

# 41. Cross-Attention과 Multimodal AI

예를 들어 이미지 patch를 Query로 두고 text representation을 Key로 사용하면

> 이 image patch를 가장 잘 설명하는 text는 무엇인가?

를 찾을 수 있다.

이를 통해 image captioning과 같은 task에 활용할 수 있다.

반대로 text를 Query로 만들면

> 이 문장을 가장 잘 설명하는 image 영역은 무엇인가?

를 찾을 수 있다.

따라서 Cross-Attention은

- Image
    
- Text
    
- 기타 서로 다른 modality
    

사이의 연결 관계를 학습할 수 있다는 점에서 multimodal model의 매우 중요한 도구다.

---

# 42. CNN / RNN / LSTM / Attention 비교

|모델|강점|주요 한계|
|---|---|---|
|CNN|이미지의 local feature에 강함|순서 반영 어려움, 장거리 관계 직접 모델링 어려움|
|RNN|sequence와 순서를 반영|gradient vanishing/explosion, 긴 과거 정보 희석|
|LSTM|gate와 cell state로 장기 정보 보존 개선|특정 먼 time step을 직접 선택하는 정교함 부족|
|Attention|임의의 데이터끼리 직접 관계 계산 가능|자체적으로 순서/위치를 알지 못함|

강의에서는 Attention이 특정 시점이나 멀리 떨어진 정보에 정교하게 반응할 수 있고 장기적인 context를 처리하는 데 강력하지만, **Attention 자체에는 순서 정보가 없다는 문제**가 있다고 설명한다.

---

# 43. Attention에는 순서 정보가 없다

Self-Attention은 token 사이의 유사성을 계산한다.

하지만 token이

```text
A B C D
```

순서인지

```text
D B A C
```

순서인지 Attention 자체만으로는 위치를 명시적으로 알 수 없다.

이미지 역시

- 왼쪽 위
    
- 오른쪽 아래
    
- 중앙
    

등의 공간적 위치가 중요하다.

따라서 Transformer에서는 **Positional Encoding**을 추가한다.

---

# 44. Vision Transformer의 입력 — Image Patch

Vision Transformer(ViT)는 이미지를 작은 patch로 나눈다.

예:

```text
┌───┬───┬───┬───┐
│ P1│ P2│ P3│ P4│
├───┼───┼───┼───┤
│ P5│ P6│ P7│ P8│
└───┴───┴───┴───┘
```

각 patch를 하나의 **Token**처럼 취급한다.

각 patch를 vector로 만들고 linear projection을 통해 embedding으로 변환한다.

그 뒤

> **이 patch가 원래 이미지의 어느 위치에서 왔는가**

를 나타내는 positional information을 embedding에 추가한다.

---

# 45. Learned Positional Encoding

첫 번째 방식은 위치 representation 자체를 **학습 가능한 parameter**로 만드는 것이다.

즉 각 위치의 embedding을 모델이 데이터로부터 직접 학습한다.

### 장점

특정

- dataset
    
- task
    

에 최적화된 위치 표현을 학습할 수 있다.

### 단점

학습할 때 사용한 이미지 해상도가 달라지면 위치 개수 역시 달라질 수 있다.

따라서 새로운 resolution을 사용할 때

- 다시 학습하거나
    
- interpolation 등의 별도 처리
    

가 필요할 수 있다.

강의에서는 resolution 변화에 대한 추가적인 고려가 필요하다는 점을 단점으로 설명한다.

---

# 46. Sinusoidal Positional Encoding

또 다른 방식은 **Sinusoidal Encoding**이다.

위치를 학습 parameter로 만들지 않고 sinusoidal function을 이용해 위치를 vector로 표현한다.

강의에서는 단일 주파수만 사용하는 것이 아니라

> 낮은 주파수부터 높은 주파수까지 여러 frequency를 이용하여 긴 position vector를 만든다

고 설명한다.

왜 이렇게 할까?

단순한 `(x, y)` coordinate는 매우 저차원 정보이기 때문에 neural network 깊은 곳에서 위치 정보가 충분히 구분되지 않거나 희석될 수 있다.

여러 frequency 성분으로 확장하면 각각의 위치를 보다 풍부한 고차원 표현으로 만들 수 있다.

### 장점

- 학습 가능한 위치 parameter가 필요하지 않음
    
- 비교적 범용적
    
- resolution이 바뀌어도 활용하기 쉬움
    
- 다른 데이터에도 적용 가능
    

---

# 47. Relative Positional Encoding

Learned/Sinusoidal 방식은 주로 **절대 위치**를 표현한다.

예:

```text
이 token은 위치 5에 있다.
```

Relative Positional Encoding은 대신

```text
Token A는 Token B보다 오른쪽으로 2칸 떨어져 있다.
```

처럼 **두 token 사이의 상대적인 위치**를 표현한다.

### 장점

절대적인 image size가 바뀌더라도 상대적인 관계 자체는 유지될 수 있기 때문에 resolution 변화에 보다 유연하다.

### 한계

절대적으로 이미지의 어느 모서리나 위치에 있는지를 직접 표현하는 능력은 줄어든다.

---

# 48. Rotary Positional Embedding

강의에서는 최근 foundation model에서 많이 사용되는 방법으로 **Rotary Positional Embedding(RoPE)** 을 소개한다.

기존 방식은 보통

```text
Token Embedding + Position Embedding
```

처럼 위치 vector를 token에 직접 더한다.

RoPE에서는 position vector를 단순히 더하기보다는 Query와 Key를 만들 때 **회전(rotation) 형태의 transformation**으로 위치 정보를 반영한다.

```text
Token
 ↓
Q / K 생성
 ↓
Position에 따른 Rotation 적용
```

이 방식 역시 상대적인 위치 관계를 표현하는 데 유리하며 resolution이 달라져도 사용할 수 있다는 설명이다.

다만 Q와 K를 계산하는 과정에서 추가적인 rotation 연산이 필요하다.

---

# 49. Positional Encoding 비교

|방법|핵심 아이디어|특징|
|---|---|---|
|Learned|위치 vector 자체를 학습|task 최적화 가능, resolution 변화에 고려 필요|
|Sinusoidal|여러 주파수의 sin 계열로 위치 표현|범용적이고 별도 학습 불필요|
|Relative|절대 위치 대신 token 간 상대 위치|resolution 변화에 유리|
|RoPE|Q/K에 위치에 따른 rotation 적용|최근 foundation model에서도 활용|

---

# 50. Vision Transformer(ViT)의 기본 입력 과정

전체 입력 과정은 다음과 같다.

```text
Image
 ↓
Patch 분할
 ↓
Patch Flatten / Embedding
 ↓
Linear Projection
 ↓
Positional Encoding 추가
 ↓
Transformer Encoder
```

즉 CNN처럼 convolution filter를 이미지 전체에서 이동시키는 것이 아니라 **이미지를 token sequence처럼 변환한 후 Transformer에 입력한다.**

---

# 51. ViT Encoder의 기본 구조

강의에서 설명하는 Transformer encoder는 크게 다음 구조를 반복한다.

```text
Input
 ↓
Normalization
 ↓
Multi-Head Attention
 ↓
Residual Addition
 ↓
Normalization
 ↓
MLP
 ↓
Residual 구조
```

Attention에서는 앞에서 설명한

```text
Q
K
V
```

를 만들고,

```text
Q-K similarity
      ↓
Attention Weight
      ↓
Weighted Value Sum
```

으로 새로운 token representation을 만든다.

그 후 MLP를 통해 representation을 다시 조합한다.

---

# 52. Residual Connection이 Transformer에도 사용된다

Multi-Head Attention의 결과만 다음 layer로 전달하는 것이 아니라 **원래 입력도 다시 더한다.**

즉 앞 차시에서 ResNet에서 보았던 것과 비슷하게

```text
Attention(x) + x
```

와 같은 residual path를 사용한다.

MLP block에서도 유사하게 이전 representation을 보존하면서 새로운 transformation을 더하는 구조를 사용한다.

따라서 residual connection은 CNN뿐 아니라 Transformer에서도 중요한 architecture 구성 요소다.

---

# 53. Multi-Head Attention

강의에서는 ViT encoder에 **Multi-Head Attention**이 사용된다고 설명한다.

하나의 attention 계산만 수행하는 것이 아니라 여러 attention head를 사용하여 서로 다른 Q/K/V representation을 만들어 다양한 관계를 볼 수 있게 한다.

각 encoder에는

- `W_Q`
    
- `W_K`
    
- `W_V`
    
- MLP의 weight
    

등의 학습 parameter가 존재한다.

ViT는 encoder 하나만 사용하는 것이 아니라 여러 encoder를 반복해서 쌓는다.

강의에서는 일반적인 Vision Transformer가 **12개 이상의 encoder layer**를 사용할 수 있다고 설명한다.

---

# 54. ViT를 이용한 Image Classification

전체적으로

```text
Image
 ↓
Patch
 ↓
Embedding
 ↓
Position Encoding
 ↓
Transformer Encoder
 ↓
Transformer Encoder
 ↓
...
 ↓
MLP Head
 ↓
Class Prediction
```

의 구조가 된다.

마지막 MLP head가 최종 classification을 수행한다.

강의에서는 최종적으로 class를 표현하기 위한 class token을 활용하는 구조도 설명한다.

---

# 55. ViT는 항상 CNN보다 좋은가?

강의에서 명확히 강조하는 부분이다.

> **ViT가 항상 CNN보다 좋은 것은 아니다.**

초기 ImageNet 실험에서는 ResNet이 ViT보다 더 좋은 결과를 보이는 경우도 있었다.

ViT가 강력한 성능을 보이기 시작한 것은 **매우 큰 dataset에서 pretraining을 수행한 후 ImageNet에 fine-tuning했을 때**였다.

즉 작은 데이터만 가지고 바로 학습하면 CNN이 오히려 유리할 수 있다.

---

# 56. ViT의 중요한 특징 — Scaling

ViT가 높게 평가된 중요한 이유는

> **Pretraining data가 증가할수록 성능이 지속적으로 개선되는 scaling 특성**

이다.

ResNet과 같은 CNN은 parameter 수와 구조적 capacity에 한계가 있기 때문에 데이터를 계속 늘린다고 해서 동일한 폭으로 성능이 증가하지 않을 수 있다.

반면 ViT는 매우 많은 parameter를 사용할 수 있고 큰 dataset을 이용해 더 많은 정보를 학습할 수 있다.

강의에서는 대규모 dataset에서 pretraining한 ViT가 성능을 지속적으로 높이는 모습 자체가 중요한 의미가 있다고 설명한다.

---

# 57. ViT 모델 크기와 Patch Size

ViT에는 모델 규모에 따라 여러 version이 존재한다.

강의에서

- Base
    
- Large
    
- Huge
    

등의 크기가 언급된다.

또 모델 이름의

- 32
    
- 16
    
- 14
    

등은 patch size를 나타낸다.

Patch size가 작아지면 같은 이미지에서도 더 많은 patch가 만들어진다.

```text
Large Patch
→ Token 수 적음

Small Patch
→ Token 수 많음
```

따라서 더 세밀한 정보를 다룰 수 있지만 모델의 계산량도 커질 수 있다.

---

# 58. ViT는 학습 Recipe가 특히 중요하다

ViT는 parameter가 매우 많기 때문에 **architecture뿐 아니라 어떻게 학습시키느냐가 성능에 매우 큰 영향을 준다.**

강의에서는 특히

- 대규모 pretraining
    
- 학습 제어/정규화 계열 기법
    
- Data Augmentation
    
- Knowledge Distillation
    
- 충분한 학습 시간
    
- 높은 이미지 resolution
    

등의 training detail이 중요하다고 설명한다.

---

# 59. Data Augmentation

Data Augmentation은 기존 이미지를 변형하여 학습 데이터를 다양하게 만드는 방법이다.

강의에서 예로 든 변형:

- 좌우 이동
    
- 변환
    
- noise 추가
    
- color jittering
    
- crop
    
- zoom in / zoom out
    

등이다.

```text
Original Image
 ├─ Crop
 ├─ Flip / Shift
 ├─ Color Change
 ├─ Noise
 └─ Zoom
```

ViT는 dataset이 작으면 일반화가 어렵기 때문에 강력한 augmentation이 특히 중요한 영향을 줄 수 있다.

강의에서는 ResNet 역시 적절한 augmentation으로 성능을 향상시킬 수 있지만 ViT에서는 이러한 학습 recipe의 영향이 훨씬 중요하다고 설명한다.

---

# 60. Knowledge Distillation

ViT 학습에 효과적인 또 다른 방법이 **Knowledge Distillation(KD)** 이다.

기본 구조:

```text
Teacher Model
      ↓
Teacher Prediction
      ↓
Student Model이 이를 따라 학습
```

일반적으로 Knowledge Distillation에서는 더 크고 강력한 모델을 Teacher로 사용한다.

Student가 Teacher의 예측 방식을 따라가면서 더 잘 학습하도록 만드는 것이다.

강의에서는 이 개념이 Hinton 교수의 Knowledge Distillation 연구 이후 널리 활용되었다고 설명한다.

---

# 61. ViT에서는 CNN을 Teacher로 사용할 수 있다

여기서 특이한 점이 있다.

ViT를 학습할 때 Teacher가 반드시 더 큰 Transformer인 것은 아니다.

강의에서는 **CNN을 Teacher로 사용하는 방법**을 설명한다.

왜 CNN인가?

CNN은 이미지에 특화된 inductive structure를 가지고 있기 때문이다.

즉 초기 ViT가 쉽게 배우기 어려운

- local image pattern
    
- image-specific feature relationship
    

을 이미 잘 학습한 CNN의 정보를 ViT가 배울 수 있다.

---

# 62. Hard Label과 Teacher의 Soft Prediction

실제 정답이 있다고 하자.

```text
정답:
Dog = 1
Cat = 0
```

이는 명확한 one-hot label이다.

하지만 Teacher CNN은 다음처럼 출력할 수 있다.

```text
Dog = 0.9
Cat = 0.1
```

이 정보에는 단순한 정답 이상의 의미가 있다.

Teacher는

> “이것은 개지만 고양이와 완전히 무관한 것은 아니다.”

라는 class 간의 관계 정보를 가지고 있다.

강의에서는 Teacher의 이러한 예측값을 pseudo/soft label처럼 사용한다고 설명한다.

---

# 63. ViT Distillation의 두 가지 목표

Student ViT는 동시에 두 가지를 학습한다.

## 1. 실제 정답 맞추기

Ground Truth와 비교한다.

강의에서는 Cross-Entropy Loss를 사용한다고 설명한다.

```text
Student Prediction
      ↕
Ground Truth
```

## 2. Teacher의 Prediction 따라가기

CNN Teacher의 soft prediction을 따라가게 만든다.

강의에서는 KL divergence 계열의 loss로 설명한다.

```text
Student Prediction
      ↕
Teacher Prediction
```

따라서 전체적으로

```text
Ground Truth
      ↓
Cross-Entropy
      ↓
   Student ViT
      ↑
KL-based Loss
      ↑
Teacher CNN
```

의 두 학습 신호를 동시에 사용한다.

---

# 64. 왜 Teacher의 Soft Prediction이 도움이 되는가?

One-hot label은

```text
Dog = 1
Cat = 0
```

만 알려준다.

하지만 Teacher prediction은

```text
Dog = 0.9
Cat = 0.1
```

처럼 class 사이의 관계까지 전달할 수 있다.

예를 들어 개와 고양이는

- 다리가 네 개
    
- 얼굴 구조가 비슷함
    
- 눈, 코, 입 등이 있음
    

등 공유되는 visual feature가 많다.

Teacher CNN의 output에는 이러한 image-specific similarity가 어느 정도 반영되어 있고, ViT가 이를 따라 학습하면 image representation을 보다 효과적으로 배울 수 있다는 것이 강의의 설명이다.

---

# 65. Distillation Token

Student ViT에는 기존 classification용 token과 별개로 **추가적인 학습 token**을 넣을 수 있다.

```text
[CLS Token]
→ 실제 정답 학습

[Distillation Token]
→ Teacher CNN output 학습
```

Distillation Token 역시 다른 token들과 Attention을 통해 서로 상호작용한다.

따라서 Teacher에서 배운 정보가 distillation token 하나에만 머물지 않고 다른 patch representation에도 영향을 줄 수 있다.

강의에서는 이러한 구조가 ViT 성능을 크게 향상시킨다고 설명한다.

---

# 66. DeiT

강의에서 설명한 이러한 Vision Transformer 학습 방식은 **DeiT 계열의 학습 아이디어**와 연결된다.

강의에서는 2021년 연구로 소개하며, Vision Transformer를 효과적으로 학습하기 위해

- 강한 augmentation
    
- distillation
    
- 여러 training detail
    

을 적극적으로 사용하는 방법을 보여주었다고 설명한다.

Knowledge Distillation을 추가했을 때 상당한 성능 향상이 나타났으며,

- 더 오래 학습
    
- 이미지 resolution 증가
    

도 추가적인 성능 개선에 도움을 줄 수 있다고 설명한다.

---

# 67. Self-Attention의 계산량 문제

Attention에는 매우 큰 장점이 있다.

모든 patch가 다른 patch와 직접 관계를 계산할 수 있다.

하지만 이것이 동시에 단점이 된다.

Patch 수가 `N`개라면 patch 관계를 대략

`N × N`

개 계산해야 한다.

예:

```text
10 patches
→ 약 100개의 관계

100 patches
→ 약 10,000개의 관계
```

이미지 resolution을 높이거나 patch size를 줄이면 patch 수가 크게 증가한다.

그 결과 Attention matrix가 매우 커져

- memory 사용량
    
- computation cost
    

가 병목이 될 수 있다.

---

# 68. CNN의 장점을 Transformer에 다시 가져오자

CNN이 가진 중요한 장점은

> **가까운 pixel끼리는 관련성이 높을 가능성이 크다**

라는 이미지의 지역적 특성을 활용한다는 것이다.

Attention은 모든 token끼리 비교하므로 매우 비싸다.

따라서

> 모든 patch를 한 번에 비교하지 말고 우선 가까운 영역끼리 Attention하면 어떨까?

라는 아이디어가 나온다.

이를 활용하는 대표적인 architecture로 강의에서는 **Swin Transformer**를 소개한다.

---

# 69. Swin Transformer — Window Attention

Swin Transformer에서는 전체 이미지의 모든 patch끼리 Attention하지 않는다.

이미지를 여러 **Window**로 나눈 뒤 같은 Window 안에서만 Self-Attention을 수행한다.

```text
┌─────────┬─────────┐
│ Window1 │ Window2 │
│         │         │
├─────────┼─────────┤
│ Window3 │ Window4 │
│         │         │
└─────────┴─────────┘
```

각 window 내부에서만 Attention을 수행하면 비교해야 할 token 수가 크게 감소한다.

따라서 일반적인 global attention보다 연산과 memory를 상당히 절약할 수 있다.

---

# 70. Window Attention의 문제

하지만 window 내부만 본다면 문제가 생긴다.

```text
Window 1의 Patch
↔
Window 4의 Patch
```

가 직접 정보를 교환하지 못한다.

그렇다면 Transformer의 중요한 장점인 **global relationship**을 잃게 된다.

---

# 71. Shifted Window

Swin Transformer의 핵심적인 해결책이 **Shifted Window**다.

첫 layer에서는

```text
┌─────┬─────┐
│  A  │  B  │
├─────┼─────┤
│  C  │  D  │
└─────┴─────┘
```

처럼 window를 나눈다.

다음 layer에서는 window를 이동시킨다.

```text
    ┌─────┬─────┐
    │     │     │
 ┌──┼─────┼──┐
 │  │     │  │
 └──┼─────┼──┘
```

그러면 이전에는 서로 다른 window에 있던 patch들이 다음 layer에서는 같은 window에 포함될 수 있다.

따라서 여러 layer를 거치면

> **각 layer에서는 local attention만 수행하지만 결과적으로 이미지 전체에 정보가 전달되는 효과**

를 얻는다.

강의에서는 이를 CNN에서 layer를 쌓으며 receptive field가 점점 넓어지는 것과 유사한 맥락으로 설명한다.

---

# 72. Swin Transformer가 강한 Task

Swin Transformer는 local image structure를 잘 보존하면서 Transformer의 관계 학습 능력을 활용한다.

# 73. Transformer가 Foundation Model의 표준이 된 이유

강의에서는 최근 frontier AI model 대부분이 Transformer를 사용하는 이유를 설명한다.

## 이유 1. 이미 많은 Foundation Model이 Transformer로 학습되어 있다

하나의 foundation model을 학습하려면

- 막대한 계산 비용
    
- 엄청난 데이터
    
- 많은 시간
    

이 필요하다.

따라서 더 나은 구조가 등장하더라도 이미 학습된 Transformer 기반의 거대한 생태계를 완전히 교체하는 데는 시간이 걸린다.

강의에서는 Attention의 높은 memory cost를 개선하려는 대안으로 Mamba 같은 구조도 언급하지만, 기존 foundation model의 규모 때문에 Transformer가 한동안 주요 architecture로 남을 것으로 전망한다.

## 이유 2. 여러 Modality에서 사용할 수 있다

Transformer는

- Language
    
- Vision
    

모두에 사용할 수 있다.

따라서 이미지와 언어를 동시에 다루는 Multimodal Foundation Model을 만들 때 하나의 공통 architecture를 사용하기 좋다.

# 79. 두 Multimodal 접근의 Trade-off

## Native Integration의 장점

모든 modality를 함께 학습하므로 modality를 넘나드는 전반적인 representation을 만드는 데 유리할 가능성이 있다.


# 80. ViT의 최종 장점

강의에서 정리한 ViT/Transformer 계열의 장점은 다음과 같다.

### 1. 전체 Context를 한 번에 고려할 수 있다

모든 token 사이의 Attention을 통해 멀리 떨어진 정보도 직접 연결할 수 있다.

### 2. Long-range Dependency 처리

CNN처럼 local feature를 여러 layer에 걸쳐 전달해야만 연결되는 것이 아니라 Attention으로 직접 관계를 학습할 수 있다.

### 3. Sequence / Position도 추가 가능

Attention 자체에는 순서가 없지만 Positional Encoding을 추가하면 순서와 위치 정보를 반영할 수 있다.

### 4. Scaling에 강하다

많은 parameter와 큰 dataset을 사용할수록 성능을 지속적으로 향상시킬 수 있는 가능성이 크다.

### 5. Multimodal에 적합

Image와 Language를 동일한 Transformer 계열 구조에서 처리할 수 있다.

### 6. 현재 Foundation Model의 핵심 Architecture

많은 최신 AI foundation model이 Transformer를 backbone으로 활용한다.

---

# 81. ViT의 단점

## 1. 많은 데이터가 필요하다

작은 dataset에서는 CNN보다 오히려 성능이 낮을 수 있다.

CNN은 이미지의 local structure라는 강한 구조적 가정을 가지고 있지만 ViT는 이러한 정보를 많은 데이터에서 학습해야 하기 때문이다.

## 2. 학습 Recipe가 중요하다

- Data Augmentation
    
- Distillation
    
- Regularization/Normalization 계열 학습 기법
    
- Pretraining
    
- Fine-tuning
    

등 많은 training detail이 성능에 큰 영향을 준다.

## 3. Attention의 높은 계산량

Token 수가 증가하면 모든 token pair의 relation을 계산해야 하므로 memory와 computation이 크게 증가한다.

## 4. Edge Device에 부담

대규모 Transformer는 높은 computation과 memory를 필요로 하기 때문에 edge/on-device 환경에서는 CNN에 비해 사용하기 어렵다.

# 84. 이번 강의에서 반드시 연결해서 이해해야 하는 핵심

## CNN → RNN

CNN에는 **sequence 기억 구조가 없다.**

RNN은 Hidden State를 추가하여 이전 정보가 다음 계산에 영향을 주도록 만들었다.

---

## RNN → LSTM

RNN은 같은 transformation을 긴 sequence에서 반복하므로 gradient vanishing/explosion 문제가 발생한다.

LSTM은

- Cell State
    
- Forget Gate
    
- Input Gate
    
- Output Gate
    
- additive highway path
    

를 사용하여 정보 흐름과 gradient를 보다 안정적으로 관리한다.

---

## LSTM → Attention

LSTM도 결국 순서대로 정보를 전달한다.

특정 먼 시점의 정보를 현재 시점에서 직접 골라내는 데는 한계가 있다.

Attention은 현재 Query가 모든 Key와 직접 관련도를 계산한다.

---

## Attention → Transformer

Attention 자체로는 위치를 알 수 없다.

따라서 Positional Encoding을 추가하고, Multi-Head Attention + MLP + Residual + Normalization을 여러 번 쌓아 Transformer를 구성한다.

---

## Transformer → ViT

이미지를 patch로 나누어 각각을 token으로 만들면 Language Transformer와 유사한 방식을 이미지에도 사용할 수 있다.

---

## ViT → Swin Transformer

ViT의 global self-attention은 token 수가 증가하면 비용이 급증한다.

Swin Transformer는 local window 안에서만 Attention하고 다음 layer에서 window를 shift하여 전체 이미지의 관계까지 전달한다.

---

# 85. 강의 마지막 확인 문제에서 강조한 내용

## Q1. CNN의 장점이 아닌 것은?

**텍스트·음성과 같은 순차 데이터를 직접 잘 처리한다**는 설명은 CNN의 장점이 아니다.

CNN에는 순서를 명시적으로 기억하는 구조가 없다.

---

## Q2. RNN의 특징이 아닌 것은?

강의에서는 **병렬 연산이 쉽다**는 설명이 RNN의 특징이 아니라고 강조한다.

RNN은 이전 hidden state가 현재 계산에 필요하기 때문에 time step을 순차적으로 진행해야 한다.

---

## Q3. RNN의 대표적인 한계

- Gradient Vanishing
    
- Gradient Explosion
    
- 순차 계산으로 인한 병렬 처리 어려움
    

등이 있다.

강의에서는 overfitting 자체를 RNN의 대표적인 구조적 한계로 분류하지 않는다.

---

## Q4. ViT의 특징이 아닌 것은?

> **적은 데이터에서도 항상 CNN보다 높은 성능을 낸다.**

는 설명은 틀린 설명이다.

ViT는 충분한 데이터와 적절한 학습 recipe가 있을 때 특히 강력하며, 데이터가 부족하면 CNN보다 성능이 낮을 수 있다.

# 86. 이번 강의 전체 핵심 문장

이번 강의를 하나의 문장으로 정리하면 다음과 같다.

> **CNN은 이미지의 지역적 구조를 효과적으로 학습했지만 순서와 장거리 관계에 한계가 있었고, RNN과 LSTM은 시간적 순서를 기억하는 구조를 추가했지만 긴 과거의 특정 정보를 직접 선택하는 데 한계가 있었다. Attention은 모든 데이터 사이의 관계를 직접 계산함으로써 이 문제를 해결했으며, 여기에 위치 정보를 추가하고 대규모로 확장한 Transformer와 Vision Transformer가 오늘날의 주요 Foundation Model 구조로 발전하였다.**

그리고 모델의 발전 방향을 더욱 압축하면 다음 네 단계로 볼 수 있다.

```text
CNN
"가까운 곳부터 계층적으로 이해한다."

RNN / LSTM
"이전의 정보를 기억하면서 순서대로 이해한다."

Attention
"어디에 있든 지금 중요한 정보와 직접 연결한다."

Transformer / ViT
"이 관계 계산을 대규모로 반복하여
전체 context를 학습한다."
```
