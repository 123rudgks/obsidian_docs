# 0. 강의 전체 개요

앞 차시까지는 Foundation Model을

```text
Pre-trained Foundation Model
      ↓
Zero-shot / Prompting
      ↓
바로 활용
```

하는 방법을 주로 살펴봤다.

하지만 실제 Service에서는 범용 Model을 그대로 사용하는 것만으로 충분하지 않을 수 있다.

```text
우리 회사만의 Domain

우리 제품

내 강아지

특정 사람

특수한 작업

새로운 최신 Data
```

처럼 **Model이 Pre-training에서 충분히 경험하지 못한 대상**에 맞춰야 할 수 있기 때문이다.

이번 차시는 이를 해결하는 두 축을 다룬다.

```text
Foundation Model 활용
│
├─ 1. Personalization / Adaptation
│     ├─ Fine-tuning
│     ├─ PEFT
│     ├─ Prompt Tuning
│     ├─ LoRA
│     └─ DreamBooth
│
└─ 2. Synthetic Data
      ├─ Knowledge Distillation
      ├─ InstructPix2Pix
      ├─ Semi-synthetic Data
      ├─ Copy-Paste / Simulation
      └─ Robot Simulation
```

그리고 마지막에는 이 흐름을

```text
World Model
Agent
Tool Use
Visual Programming
Multi-Agent
Model Serving
```

으로 확장한다.

---

# 1. 왜 Foundation Model을 개인화해야 하는가?

Foundation Model은 방대한 Data를 통해

- 다양한 Visual Pattern
    
- 일반 Knowledge
    
- 많은 Object
    
- 여러 Domain
    

을 학습한다.

따라서 새로운 Task에서도 좋은 출발점이 된다.

하지만 Pre-training Data가 아무리 많아도 모든 상황을 포함할 수는 없다.

---

# 2. Foundation Model의 한계

강의에서는 대표적으로 다음을 설명한다.

```text
Pre-training Data가 오래됨
→ 최신 정보 부족

특정 Domain Data 부족
→ 해당 분야 최적화 부족

특정 User / Product / Identity
→ 사전학습에 존재하지 않을 수 있음
```

따라서

> **이미 학습된 Knowledge를 유지하면서 필요한 부분만 조금 수정하는 능력**

이 중요하다.

---

# 3. AI를 단순히 사용하는 것에서 한 단계 더

강의에서는 실무적으로 Foundation Model 시대에 필요한 역량을

```text
AI를 사용한다.
```

보다 한 단계 확장해

```text
AI Model을
내 목적에 맞게 조금 수정한다.

여러 Model을
서로 연결한다.
```

정도의 능력으로 설명한다.

그리고 가장 기본적인 기술이 **Fine-tuning**이다.

---

# 4. Fine-tuning

Fine-tuning은

> **이미 학습된 Model을 새로운 Data를 이용해 조금 더 학습하여 Parameter를 수정하는 것**

이다.

```text
Pre-trained Model
      ↓
Small Task-specific Dataset
      ↓
Additional Training
      ↓
Adapted Model
```

이다.

---

# 5. 처음부터 Training과 원리는 같다

Fine-tuning도 결국

```text
Forward
↓
Loss
↓
Backpropagation
↓
Gradient Descent
↓
Parameter Update
```

를 수행한다.

즉 학습 Mechanism이 완전히 새로운 것은 아니다.

차이는 **출발점**이다.

---

# 6. From Scratch Training

```text
Random / Initial Parameters
↓
Large Dataset
↓
Long Training
```

---

# 7. Fine-tuning

```text
이미 좋은 Pre-trained Parameters
↓
Small Dataset
↓
Small Additional Update
```

이다.

따라서 일반적으로

- 적은 Data
    
- 적은 Compute
    
- 짧은 Training
    
- 적은 Code
    

로도 Task Adaptation을 할 수 있다는 것이 강의의 핵심이다.

---

# 8. Fine-tuning을 바로 시작하기 전에 해야 할 것

강의에서는 바로 Fine-tuning부터 하는 것을 권하지 않는다.

먼저

```text
Prompt Engineering
+
In-context Learning
```

을 시도한다.

---

# 9. 왜 Prompting부터 해 보는가?

Prompt를 바꾸면서

```text
현재 Model로
어디까지 가능한가?

어떤 부분에서 실패하는가?

Example을 주면
성능이 올라가는가?
```

를 먼저 확인할 수 있다.

즉 Fine-tuning이 정말 필요한지 판단하는 **Diagnostic 단계**다.

---

# 10. 추천 순서

강의의 흐름은 다음과 같다.

```text
Base Foundation Model
      ↓
Prompt Engineering
      ↓
Few-shot / In-context Learning
      ↓
성능 충분?
 ├─ Yes → 그대로 사용
 └─ No
      ↓
Fine-tuning 고려
```

---

# 11. Few-shot Prompting의 한계

Few-shot에서는 Example을 Prompt 안에 넣는다.

```text
Example 1

Example 2

Example 3

...

Current Query
```

문제는 Example도 모두 **Token**으로 들어간다는 것이다.

---

# 12. Context Window 문제

Example이 너무 많으면

```text
Examples ↑
↓
Input Token ↑
↓
Context Window 사용량 ↑
```

한다.

수백·수천 개 Example을 Prompt에 모두 넣을 수는 없다.

심하면 실제 User Query가 Context에서 상대적으로 중요하지 않게 처리될 수도 있다.

---

# 13. Fine-tuning의 직관 — Example을 Model 안에 녹인다

Few-shot:

```text
매 Request마다
Example을 Prompt로 전달
```

Fine-tuning:

```text
Example을 Training Data로 사용
↓
Model Parameter에 Pattern을 반영
↓
Inference 때 Example을
매번 전달할 필요 감소
```

이다.

---

# 14. Fine-tuning의 Service적 장점

Prompt가 짧아지면

```text
Input Token ↓
Processing Token ↓
API Cost ↓
Latency ↓
```

의 효과도 기대할 수 있다.

즉 Fine-tuning은 단순 Accuracy뿐 아니라 **Inference Efficiency**와도 연결될 수 있다.

---

# 15. Fine-tuning과 Gradient Descent

Fine-tuning도 Gradient Descent를 사용한다.

Gradient는

> **Loss를 Parameter에 대해 미분하여 얻은 변화 방향**

이다.

Model Parameter를 Loss가 낮아지는 방향으로 조금씩 이동시킨다.

---

# 16. 강의의 강아지 비유

강의에서는 강아지가

```text
"앉아"
```

라는 목표 자세를 학습한다고 생각한다.

강아지 관절의 각도:

```text
Model Parameters
```

관절을 움직여야 하는 방향:

```text
Gradient
```

한 번에 얼마나 움직일지:

```text
Learning Rate
```

와 대응시킨다.

---

# 17. Fine-tuning에서 Learning Rate가 특히 중요

이미 Model은 좋은 Parameter 위치에서 시작한다.

따라서 큰 Update로 기존 Knowledge를 크게 망가뜨릴 필요가 없다.

```text
Fine-tuning
→ Conservative Update
```

가 중요하다.

---

# 18. Learning Rate가 너무 작으면

```text
Update가 매우 작음
↓
Training 느림
↓
충분히 Adapt하지 못할 수 있음
```

강의에서는 지나치게 작은 Learning Rate 때문에 원하는 지점까지 이동하지 못하는 직관을 설명한다.

---

# 19. Learning Rate가 너무 크면

```text
Parameter가 크게 Jump
↓
좋은 기존 Parameter 영역 이탈
↓
Loss 증가 / Training 불안정
```

할 수 있다.

따라서 Fine-tuning에서는 적절하고 보수적인 Learning Rate 설정이 중요하다.

---

# 20. Full Fine-tuning의 문제

Foundation Model은 매우 크다.

모든 Parameter를 Update하면

```text
Trainable Parameters ↑
↓
GPU Memory ↑
Training Time ↑
Compute Cost ↑
```

한다.

그래서 등장한 것이 **PEFT**다.

---

# 21. PEFT

**PEFT = Parameter-Efficient Fine-Tuning**

즉

> **전체 Parameter를 바꾸지 않고 아주 일부 Parameter만 학습하여 Foundation Model을 Adapt하는 방법**

이다.

강의에서는 크게

```text
Prompt Tuning

Adapter / LoRA 계열
```

방향을 설명한다.

---

# 22. Prompt Engineering과 Prompt Tuning을 먼저 구분

두 개는 이름이 비슷하지만 완전히 다르다.

### Prompt Engineering

```text
사람이 Prompt 작성
Model Weight Update X
Gradient Training X
```

### Prompt Tuning

```text
Learnable Prompt Parameter 추가
Gradient Training O
Base Model Weight는 고정
```

이다.

---

# 23. Prompt Engineering

Input Text를 계속 바꿔 보면서 원하는 Output을 얻는다.

장점:

```text
Training 불필요
빠름
비용 낮음
```

단점:

```text
사람의 설계 필요
Model Weight가 고정되어
성능 향상에 한계
```

가 있다.

---

# 24. Prompt 자체를 AI가 개선할 수도 있다

강의에서는 사람이 모든 Prompt를 직접 만드는 것뿐 아니라

```text
현재 Prompt
↓
AI가 평가
↓
새 Prompt 생성
↓
Performance 평가
↓
반복
```

하여 Prompt를 자동으로 최적화하는 방향도 언급한다.

---

# 25. Prompt Detail이 Generation에 미치는 영향

예를 들어 단순하게

```text
강아지 사진을 만들어 줘.
```

라고 하는 것보다

카메라, Photography Quality 등의 표현을 더 구체적으로 작성하면 Image Generation Quality가 달라질 수 있다는 예를 든다.

핵심은

> **Prompt 자체도 Model Output Distribution을 크게 바꿀 수 있다.**

는 것이다.

---

# 26. Prompt Tuning

Prompt Tuning은 사람이 읽는 Text Prompt 앞에 **학습 가능한 Virtual Prompt**를 추가한다.

```text
[Learnable Prompt Tokens]
+
[User Text]
      ↓
Frozen Foundation Model
```

형태다.

---

# 27. 무엇을 학습하는가?

Base Model:

```text
Frozen
```

Virtual Prompt:

```text
Trainable
```

이다.

Loss에서 나온 Gradient를 Virtual Prompt Parameter에만 전달한다.

---

# 28. Virtual Prompt는 자연어가 아니다

학습된 Prompt Token은

```text
"이 Task를 이렇게 해라."
```

처럼 사람이 읽을 수 있는 Sentence일 필요가 없다.

그 자체가

```text
Continuous Vector Parameters
```

다.

따라서 사람이 해석하기 어려울 수 있다.

---

# 29. 오히려 이것이 장점이 될 수도 있다

사람이 자연어로 정확히 설명하기 어려운 Task Preference도

```text
Vector Representation
```

안에는 학습될 수 있다.

즉 인간이 말로 표현하지 못한 Pattern까지 Optimization을 통해 찾을 수 있다.

---

# 30. Prompt Tuning의 장점

```text
Base Model 고정
↓
기존 Knowledge 손상 감소

Trainable Parameter 매우 적음
↓
Memory ↓
Training Cost ↓

적은 Data로도 가능
```

하다.

---

# 31. 성능과 효율의 Trade-off

강의에서는 대략적인 관계를 다음처럼 설명한다.

```text
Performance
Full Fine-tuning
   >
Prompt Tuning
   >
Prompt Engineering
```

반면 Efficiency는 대체로 반대 방향이다.

```text
Efficiency
Prompt Engineering
   >
Prompt Tuning
   >
Full Fine-tuning
```

즉 목적에 따라 선택해야 한다.

---

# 32. 그 중간 — LoRA

강의에서는 효율성과 성능의 중간 영역에 있는 대표적인 방법으로 **LoRA**를 소개한다.

기존 Layer를 그대로 유지한다.

```text
Original Layer
→ Frozen
```

그리고 작은 Trainable Module을 추가한다.

```text
Original Layer
+
Small Trainable Update
```

형태다.

---

# 33. LoRA의 직관

전체 Weight Matrix를 통째로 수정하는 대신

> **기존 Model에 필요한 추가 변화량만 작은 Parameter로 학습한다.**

고 이해하면 된다.

---

# 34. LoRA가 효율적인 이유

Trainable Parameter가 매우 적어진다.

```text
Full Model
Billions of Parameters
```

중 일부 작은 Adapter Parameter만 학습할 수 있다.

따라서

```text
GPU Memory ↓
Training Time ↓
Storage ↓
```

가 가능하다.

---

# 35. Base Knowledge를 최대한 유지

기존 Model Weight를 직접 크게 바꾸지 않으므로 Foundation Model의 기존 Knowledge를 최대한 유지하면서 새로운 정보만 더하기 유리하다.

---

# 36. 그러나 LoRA도 지나치게 학습하면 문제가 될 수 있다

강의에서는 Trainable Module의 영향이 지나치게 커지면 기존 Layer의 Output을 **덮어버리는 것처럼** 동작할 수 있다고 설명한다.

예:

```text
Learning Rate 너무 큼

Training 너무 오래 함
      ↓
LoRA Update 영향 ↑↑
      ↓
Original Model Behavior 압도
```

따라서 PEFT라도 Training Hyperparameter 조정은 여전히 중요하다.

---

# 37. Fine-tuning 계열 비교

|방법|Base Model Weight|추가 학습|효율|특징|
|---|---|--:|--:|---|
|Prompt Engineering|고정|X|매우 높음|사람이 Prompt 설계|
|Prompt Tuning|고정|O|높음|Learnable Virtual Prompt|
|LoRA/Adapter|대부분 고정|O|높음|작은 추가 Module 학습|
|Full Fine-tuning|변경|O|낮음|전체 Model Update|

---

# 38. 개인화 사례 — DreamBooth

이제 Fine-tuning을 실제 개인화에 적용한다.

대표적인 방법으로 강의에서는 **DreamBooth**를 소개한다.

목표:

> **몇 장의 사진만으로 특정 대상의 Identity를 Image Generation Model에 학습시키는 것**

이다.

---

# 39. 예: 내 강아지 전용 Image Generator

Input:

```text
특정 강아지 사진
약 3~5장
```

을 제공한다.

그리고 기존 Text-to-Image Foundation Model을 Fine-tuning한다.

---

# 40. Unique Identifier

특정 강아지를 일반적인

```text
dog
```

와 구분해야 한다.

그래서 흔히 잘 사용하지 않는 독특한 Token/Identifier를 하나 정한다.

예:

```text
[V] dog
```

처럼 사용한다.

---

# 41. Identifier의 역할

`dog`:

```text
일반적인 강아지 Concept
```

`[V] dog`:

```text
내가 보여 준 바로 그 특정 강아지
```

가 되도록 학습한다.

즉 Identifier가 특정 Identity를 가리키는 **암호 같은 역할**을 한다.

---

# 42. Training

```text
3~5장의 특정 강아지 Image
+
"[V] dog"
      ↓
Text-to-Image Model Fine-tuning
```

한다.

그러면 Model은 `[V]`가 어떤 Visual Identity를 의미하는지 학습한다.

---

# 43. Inference

Training 이후에는 원본 Image가 없어도 된다.

예:

```text
[V] dog on a beach

[V] dog at the Acropolis

[V] dog getting a haircut
```

등을 입력하면

```text
특정 강아지의 Identity
+
새로운 Scene
```

을 결합해 생성할 수 있다.

---

# 44. DreamBooth의 핵심

```text
Foundation Model이 이미 알고 있는
Dog / Beach / Haircut / Art Knowledge
+
몇 장으로 새롭게 학습한
특정 Identity
```

를 조합한다.

이것이 Foundation Model Personalization의 힘이다.

---

# 45. 개인화의 본질

강의 표현을 구조화하면

```text
개인화
=
Fine-tuning의 한 활용
```

이다.

즉 새로운 Model을 처음부터 만드는 것이 아니다.

Foundation Model이 가진 넓은 Knowledge에 **작은 Personal Information**을 추가한다.

---

# 46. 이제 Synthetic Data로 이동

개인화에서도 결국 Data가 필요하다.

그러나 실제 Data를 충분히 구하기 어려운 경우가 많다.

예:

- 개인정보
    
- 특수 Sensor
    
- 3D Ground Truth
    
- Robot Motion
    
- 정밀 Image Editing Pair
    

등.

이때 **Synthetic Data**를 사용할 수 있다.

---

# 47. Synthetic Data 활용 ① Knowledge Distillation

강의에서 첫 번째 실용적 활용법으로 **Knowledge Distillation**을 소개한다.

다른 이름으로

```text
Teacher–Student Learning
```

이라고 이해할 수 있다.

---

# 48. Teacher Model

이미 성능이 높은 큰 Model을 준비한다.

```text
Large High-performance Model
=
Teacher
```

---

# 49. Student Model

우리가 실제로 배포하고 싶은 더 작은 Model을 준비한다.

```text
Small Model
=
Student
```

---

# 50. Training 구조

같은 Input을 두 Model에 넣는다.

```text
Input
├─→ Teacher → Teacher Prediction
│
└─→ Student → Student Prediction
```

그리고

```text
Student Output
≈
Teacher Output
```

이 되도록 Loss를 준다.

---

# 51. Transfer Learning과 차이

### Transfer Learning / Fine-tuning

```text
Pre-trained Model 자체를
새 Task에 Update
```

### Knowledge Distillation

```text
Teacher Model은
정답을 제공하는 역할

다른 Student Model이
Teacher Behavior를 학습
```

한다.

즉 **Teacher 자체를 Student로 바꾸는 것이 아니다.**

---

# 52. Hard Label만 사용하는 것과 차이

Ground Truth가

```text
Cat = 1
Dog = 0
```

처럼 Hard Label만 있다면 정보가 제한적이다.

Teacher는

```text
Cat 0.72
Dog 0.20
Fox 0.07
...
```

처럼 더 풍부한 Probability Distribution을 제공할 수 있다.

---

# 53. Soft Label

Teacher의 이런 Probability Output을 **Soft Label**이라고 볼 수 있다.

여기에는 단순 정답뿐 아니라

```text
Class 간 Similarity

Confidence

Teacher가 학습한 관계
```

가 포함될 수 있다.

---

# 54. 왜 작은 Student가 더 잘 배울 수 있는가?

Raw Training Data를 작은 Model이 직접 해석하는 것보다

```text
이미 큰 Teacher가
Data를 소화해서 만든 Output
```

을 따라가는 것이 쉬울 수 있다.

즉 Teacher Prediction 안에 숨은 Knowledge까지 Student가 전달받는다.

---

# 55. Distillation도 Synthetic Data 활용이다

Teacher가 만든

```text
Pseudo Label / Soft Label
```

은 원래 Human Ground Truth가 아니다.

Model이 생성한 Label이다.

따라서 강의에서는 이것도 **Synthetic Data의 한 형태**로 본다.

---

# 56. Distillation의 대표 목적

```text
Large Model
↓
Knowledge Distillation
↓
Small Model
```

로 압축하여

- Mobile
    
- Edge
    
- Low-latency Service
    

등에 활용할 수 있다.

# 57. Synthetic Data 활용 ② InstructPix2Pix

두 번째 사례는 **Instruction-based Image Editing**이다.

목표:

```text
Input Image
+
Natural Language Instruction
      ↓
Edited Image
```

이다.

예:

```text
"하늘에 불꽃놀이를 추가해."
```

라고 말하면 기존 Image의 나머지 부분은 유지하면서 하늘만 바꾸는 것이다.

---

# 58. 왜 이런 Model을 학습하기 어려운가?

Supervised Learning을 하려면 다음 Triplet이 필요하다.

```text
Input Image

Editing Instruction

Correct Edited Image
```

이다.

---

# 59. 문제는 Ground Truth Edited Image

예를 들어

```text

+
"불꽃놀이를 추가해."
```

사람이 정확하게

```text

+
하늘에만 자연스러운 Fireworks 추가
```

한 Target Image를 만들어야 한다.

대규모로 만들려면 매우 비싸다.

---

# 60. Dataset이 없으면 Supervised Learning을 할 수 없다

즉 문제는 Model Architecture 이전에


```text

```

Dataset이 많다.

# 62. Step 2 — Editing Instruction을 생성

기존 Caption을 가지고 LLM에게

```text

```

예:

```text

a misty night
```

처럼 만든다.

```text

```

을 만드는 것은 LLM으로 훨씬 쉽게 자동화할 수 있다.

# 85. 하지만 Synthetic Data에는 문제가 있다

Synthetic Data가 자동 생성되었다고 해서 무조건 신뢰할 수 있는 것은 아니다.

# 86. Label Inconsistency


등 서로 다른 방식으로 Labeling할 수 있다.


등이 필요할 수 있다.

---

# 88. Hallucination

Synthetic Data Generator가 실제로 존재하지 않는

- Object
    
- Attribute
    
- Relationship
    

을 만들어낼 수 있다.

그러면 잘못된 Data로 Student Model을 학습하게 된다.

---

# 89. Error Reinforcement 위험

```text
Teacher / Generator 오류
↓
Synthetic Dataset
↓
New Model Training
↓
오류가 다시 학습됨
```

이 발생할 수 있다.

따라서 Validation/Filtering이 중요하다.

---

# 90. Real + Synthetic을 섞는다


를 함께 사용하는 것이 더 좋은 경우가 많다고 설명한다.

# 91. 개인화와 Synthetic Data를 전체적으로 보면

```text
      ↓

[선택 2]

```

로 연결된다.

---

# 92. 이제 다음 단계 — Foundation Model + World Model

강의 후반에서는 지금까지의 내용을 넘어 Foundation Model이 앞으로 어디로 발전할지를 설명한다.

High-quality Video Generation Model이 등장하면서 질문이 생긴다.

> **이 Model이 단순 Pixel Generation을 넘어 Physical World의 Dynamics까지 어느 정도 이해하고 있는 것 아닐까?**

# 93. Video와 3D Consistency

```text
Object Motion

Geometry

Temporal Consistency
```

가 상당히 일관되어 있다는 의미로 볼 수 있다.

하는 것이다.

# 145. Fine-tuning에서 자주 헷갈리는 점 ①

**Fine-tuning은 완전히 다른 학습 Algorithm인가?**

아니다.

Backpropagation과 Gradient Descent 자체는 일반 Training과 동일하다.

이미 좋은 Parameter에서 적은 Data로 추가 학습한다는 점이 다르다.

---

# 146. 자주 헷갈리는 점 ②

**Prompt Engineering부터 해야 하나, Fine-tuning부터 해야 하나?**

강의에서는 먼저 Prompting/In-context Learning으로 Base Model의 가능성과 부족한 부분을 확인한 뒤 필요할 때 Fine-tuning하는 순서를 권한다.

---

# 147. 자주 헷갈리는 점 ③

**Few-shot Example을 많이 넣을수록 무조건 좋은가?**

아니다.

Context Window를 소비하고 Token Cost와 Latency가 증가한다.

너무 많은 Example이 필요하다면 Fine-tuning을 고려할 수 있다.

---

# 148. 자주 헷갈리는 점 ④

**Fine-tuning에서는 Learning Rate를 크게 해야 빨리 배우는가?**

아니다.

이미 좋은 Pre-trained Parameter에서 시작하므로 지나치게 큰 Update는 기존 Knowledge를 훼손할 수 있다.

강의에서는 보수적인 Fine-tuning을 강조한다.

---

# 149. 자주 헷갈리는 점 ⑤

**PEFT는 Training하지 않는 방법인가?**

아니다.

일부 Parameter에는 Gradient Training을 수행한다.

단지 전체 Model이 아니라 작은 Parameter 집합만 Update한다.

---

# 150. 자주 헷갈리는 점 ⑥

**Prompt Tuning = Prompt Engineering인가?**

아니다.

```text
Prompt Engineering
→ 사람이 Text 설계
→ Training X

Prompt Tuning
→ Virtual Prompt Vector 학습
→ Training O
```

이다.

---

# 151. 자주 헷갈리는 점 ⑦

**LoRA는 Base Model 전체 Weight를 수정하는가?**

기본 Idea는 Base Weight를 고정하고 작은 추가 Update Parameter를 학습하는 것이다.

---

# 152. 자주 헷갈리는 점 ⑧

**PEFT면 기존 Model을 절대로 망칠 수 없는가?**

아니다.

추가 Module의 영향이 지나치게 커지도록 학습하면 기존 Behavior를 압도할 수도 있으므로 Hyperparameter 관리가 필요하다.

---

# 153. 자주 헷갈리는 점 ⑨

**DreamBooth는 새로운 Image Generator Architecture인가?**

강의의 핵심 관점에서는 아니다.

기존 Text-to-Image Foundation Model을 몇 장의 특정 Subject Data로 개인화하는 Fine-tuning 방법이다.

---

# 154. 자주 헷갈리는 점 ⑩

**DreamBooth의 Unique Token이 원래부터 그 강아지를 의미하는가?**

아니다.

처음에는 특별한 의미가 없는 Identifier에 가깝다.

Fine-tuning을 통해 그 Token과 특정 Identity의 관계를 학습시킨다.

---

# 155. 자주 헷갈리는 점 ⑪

**Knowledge Distillation = Transfer Learning인가?**

아니다.

Transfer Learning에서는 Pre-trained Model 자체를 새로운 Task에 Adapt한다.

Distillation에서는 Teacher의 Output을 다른 Student Model이 따라 하도록 학습한다.

---

# 156. 자주 헷갈리는 점 ⑫

**Soft Label은 0/1 Ground Truth인가?**

아니다.

Teacher가 출력한 Probability/Confidence Distribution과 같은 연속적인 정보를 포함한다.

---

# 157. 자주 헷갈리는 점 ⑬

**Synthetic Data는 전부 AI Generator가 처음부터 만든 가짜 Data인가?**

아니다.

실제 Data를 기반으로 일부만 AI로 생성하거나 단순 Copy-Paste/Simulation을 이용하는 Semi-synthetic 방식도 있다.

---

# 158. 자주 헷갈리는 점 ⑭

**InstructPix2Pix의 핵심은 새로운 Architecture인가?**

이번 강의의 강조점은 오히려 **필요한 Instruction Editing Dataset을 Synthetic하게 구축했다는 Data Design**이다.

---

# 159. 자주 헷갈리는 점 ⑮

**Synthetic Data가 많으면 무조건 성능이 좋아지는가?**

아니다.

잘못된 Label, Hallucination, Bias가 들어갈 수 있으므로 Validation이 필요하다.

강의에서는 Real Data와 Synthetic Data를 섞어 쓰는 것을 좋은 전략으로 설명한다.

---

# 160. 자주 헷갈리는 점 ⑯

**RAG도 Fine-tuning인가?**

아니다.

RAG는 외부 Database에서 Knowledge를 Retrieval하여 Inference Context에 추가한다.

Parameter를 반드시 Update하지 않는다.

# 161. 자주 헷갈리는 점 ⑰

**개인화하려면 반드시 Fine-tuning해야 하는가?**

아니다.

개인 DB를 구축한 뒤 RAG로 Retrieval하면 추가 Training 없이도 Personalization이 가능할 수 있다.

강의에서 소개한 구조에서는 반드시 그렇지 않다.

LLM은 Tool을 이용할 **Program을 Planning**하고 실제 Visual Analysis는 Segmentation/Detection 등 외부 Tool이 수행할 수 있다.

반드시 아니다.

# 167. 이번 강의에서 반드시 기억할 핵심

### 1. Foundation Model은 대규모 Pre-training Knowledge를 가지고 있어 적은 추가 Training으로 새로운 Task에 Adapt하기 좋다.

### 2. 하지만 최신 정보, 특정 Domain, 개인 Identity 등은 Pre-training에 충분히 포함되지 않을 수 있다.

### 3. 따라서 Foundation Model을 개인화·적응시키는 Fine-tuning이 중요하다.

### 4. Fine-tuning도 기본적으로 Backpropagation과 Gradient Descent를 사용한다.

### 5. 일반 Training과의 차이는 이미 좋은 Pre-trained Parameter에서 출발하여 적은 Data와 작은 Update를 사용한다는 것이다.

### 6. 강의에서는 Fine-tuning 전에 Prompt Engineering과 In-context Learning을 먼저 시도하는 것을 권한다.

### 7. Prompting을 통해 Base Model이 어디에서 부족한지 먼저 파악할 수 있다.

### 8. Few-shot Example은 모두 Context Token을 사용한다.

### 9. Example이 많아지면 Context Window, Token Cost, Processing Time 문제가 생길 수 있다.

### 10. 많은 Example Pattern을 Fine-tuning으로 Parameter에 반영하면 매 Request마다 Example을 반복 입력할 필요를 줄일 수 있다.

### 11. Fine-tuning에서는 Learning Rate 설정이 중요하다.

### 12. 지나치게 큰 Learning Rate는 기존 Pre-trained Knowledge를 훼손할 수 있기 때문에 보수적인 Update가 중요하다.

### 13. Full Fine-tuning은 거대한 Model의 전체 Parameter를 학습하므로 Memory와 Compute가 많이 필요하다.

### 14. PEFT는 일부 Parameter만 학습하여 이를 효율화한다.

### 15. Prompt Engineering은 Parameter Training이 없다.

### 16. Prompt Tuning은 Base Model을 고정하고 Learnable Virtual Prompt를 학습한다.

### 17. Virtual Prompt는 사람이 읽을 수 있는 Natural Language일 필요가 없다.

### 18. Prompt Tuning은 적은 Trainable Parameter 때문에 효율적이다.

### 19. LoRA는 기존 Layer를 최대한 유지하면서 작은 Trainable Update Module을 학습한다.

### 20. LoRA는 Full Fine-tuning보다 적은 Memory와 Compute로 Adaptation할 수 있다.

### 21. PEFT라고 하더라도 Learning Rate나 Training을 과도하게 하면 Base Model Behavior를 압도할 수 있어 주의해야 한다.

### 22. DreamBooth는 소수의 Subject Image를 이용해 Text-to-Image Foundation Model을 특정 Identity에 개인화하는 방법이다.

### 23. Unique Identifier와 Class Name을 조합해 특정 Subject Concept을 Model에 학습시킨다.

### 24. 학습 이후에는 원본 Image 없이 Identifier를 Prompt에 넣어 새로운 Scene의 해당 Subject를 생성할 수 있다.

### 25. Knowledge Distillation은 큰 Teacher Model의 Output을 작은 Student Model이 따라 배우게 하는 방법이다.

### 26. Distillation은 Teacher 자체를 Fine-tuning하는 Transfer Learning과 구분해야 한다.

### 27. Teacher가 생성한 Soft Label에는 Hard Ground Truth보다 더 많은 Confidence와 Class 관계 정보가 포함될 수 있다.

### 28. Teacher-generated Label은 Synthetic Supervision의 한 형태로 볼 수 있다.

### 29. Distillation은 큰 Model의 Knowledge를 작은 Model에 전달하여 경량화하는 데 활용할 수 있다.

### 30. InstructPix2Pix는 Natural Language Instruction으로 Image를 Editing하는 Model 사례다.

### 31. Instruction-based Image Editing을 Supervised Learning하려면 Input Image + Instruction + Edited Image Triplet이 필요하다.

### 32. 이러한 Dataset을 사람이 대규모로 만드는 것은 매우 비싸다.

### 33. 기존 Caption Dataset과 LLM을 사용해 Editing Instruction 및 Edited Caption을 Synthetic하게 생성할 수 있다.

### 34. 강의에서는 소량의 Human Edit Data를 이용해 GPT를 조정한 뒤 약 45만 개 이상의 Text Pair를 생성한 흐름을 설명한다.

### 35. Text-to-Image 및 Editing Foundation Model을 이용해 실제 Image Pair까지 합성한다.

### 36. 최종적으로 Input Image + Instruction + Output Image Dataset을 구축한다.

### 37. 이 Dataset으로 일반적인 Model을 Training하여 Instruction-based Image Editing을 가능하게 할 수 있다.

### 38. LLaVA와 InstructPix2Pix 모두 기존 Real Dataset에 Synthetic Information을 추가해 새로운 Task Dataset으로 바꾸는 공통 Pattern이 있다.

### 39. Synthetic Data는 Generative AI뿐 아니라 Copy-Paste나 Simulation으로도 만들 수 있다.

### 40. Copy-Paste를 이용해 Detection, Motion 등의 Ground Truth Data를 자동 생성할 수 있다.

### 41. 실제로 존재하지 않는 Ground Truth가 필요한 Task에서 Simulation/Synthetic Data가 매우 유용할 수 있다.

### 42. Robotics에서도 실제 Robot Experience 대신 Simulation Data를 많이 사용할 수 있다.

### 43. Synthetic Data에는 Label Inconsistency 문제가 존재할 수 있다.

### 44. Label Normalization, Class Dictionary, Cross-model Validation, Human Verification 등으로 이를 보완할 수 있다.

### 45. Synthetic Data Generator의 Hallucination과 Bias가 새로운 Model에 다시 학습될 수 있으므로 Filtering이 필요하다.

### 46. 강의에서는 Synthetic Data만 쓰는 것보다 Real Data와 섞어 사용하는 것이 효과적일 수 있다고 설명한다.

### 47. High-quality Video Generation은 Physical World Dynamics를 학습한 World Model 가능성과 연결해 연구되고 있다.

### 48. World Model은 Action을 실제로 실행하기 전에 Future Result를 Simulation하는 데 활용할 수 있다.

### 49. Language Model이 Plan을 만들고 World Model이 결과를 상상한 뒤 Action Model이 실제 행동하는 구조를 생각할 수 있다.

### 50. Foundation Model은 Physical Action뿐 아니라 Software Tool 사용으로도 확장된다.

### 51. RAG는 Search/Retrieval Tool을 LLM에 연결하는 대표적인 Tool Augmentation이다.

### 52. RAG를 이용하면 최신 정보나 User-specific Database를 추가 Training 없이 사용할 수 있다.

### 53. Visual Programming에서는 Language Model이 Vision Tool을 직접 실행하는 Program을 생성할 수 있다.

### 54. LLM 자체가 Image를 직접 이해하지 않아도 Segmentation, Detection, Editing Tool을 조합할 수 있다.

### 55. 이러한 Program-generation 구조는 Computer-use Agent와 Robot Programming으로 확장될 수 있다.

### 56. Robot Program을 Simulation에서 먼저 실행하고 Feedback을 받아 개선한 뒤 실제 Robot에 적용하는 구조도 가능하다.

### 57. 복잡하고 느린 Agent의 행동을 Synthetic Data로 수집한 뒤 Distillation하여 빠른 Model로 만들 수도 있다.

### 58. Single Agent는 하나의 Context Window에 너무 많은 Task와 Memory가 섞이는 문제가 있을 수 있다.

### 59. Multi-Agent에서는 역할·Persona·Memory·Tool을 Agent별로 분리한다.

### 60. Multi-Agent는 AI Scientist나 AI for Science 같은 복잡한 자동화 System으로 확장될 수 있다.

### 61. 실제 AI Service를 위해서는 Model Serving이 필요하다.

### 62. Model Serving은 Model을 Server에 실행 상태로 유지하고 REST/gRPC 같은 Interface로 Request와 Response를 제공하는 것이다.

### 63. Hugging Face Inference API 등을 이용하면 별도 Server 구축 없이 일부 Hosted Model을 API로 사용할 수 있다.

### 64. Remote Server가 아니라 Smartphone 자체에서 Model을 실행하는 On-device Deployment도 가능하다.

### 65. On-device는 Privacy나 Offline Usage에서 장점이 있다.

### 66. Gradio 같은 Tool을 이용하면 Foundation Model의 Multimodal Demo Web Interface를 빠르게 만들 수 있다.

### 67. 강의 전체의 목적은 모든 기술을 깊게 암기하기보다 어떤 Concept과 Tool이 존재하는지를 알고 필요할 때 활용할 수 있는 기반을 만드는 것이다.

# 169. 이번 강의 핵심 한 문장

> **Foundation Model의 개인화는 방대한 Pre-training Knowledge를 유지하면서 Fine-tuning·Prompt Tuning·LoRA 같은 방법으로 특정 User·Identity·Domain에 필요한 정보만 추가하는 과정이며, 실제 Training Data가 부족할 때는 Teacher Model의 Soft Label을 이용하는 Knowledge Distillation, LLM과 Image Generator를 이용한 Instruction Dataset 생성, Copy-Paste와 Simulation 같은 Synthetic Data 기법으로 Training Supervision을 확장할 수 있고, 이러한 Foundation Model들은 이후 RAG·Tool Use·Visual Programming·World Model·Multi-Agent와 결합되어 실제 행동하고 서비스를 제공하는 더 큰 AI System으로 발전할 수 있다.**

가장 짧게 기억하면 다음과 같다.

```text
Fine-tuning
= 이미 배운 Model을
  조금 더 학습해서 내 Task에 맞춘다.

PEFT
= 전체를 바꾸지 말고
  작은 부분만 학습한다.

DreamBooth
= 몇 장의 사진으로
  특정 Identity를 Model에 가르친다.

Distillation
= 큰 Teacher의 지식을
  작은 Student에게 전달한다.

Synthetic Data
= 없는 Training Data를
  AI나 Simulation으로 만든다.

Agent
= Model 혼자 모든 걸 하지 않고
  Tool을 계획하고 조합한다.

World Model
= 행동하기 전에
  앞으로 일어날 일을 상상한다.
```
