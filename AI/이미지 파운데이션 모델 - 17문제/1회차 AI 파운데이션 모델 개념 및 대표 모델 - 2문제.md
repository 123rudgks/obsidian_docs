# 0. 강의 전체 개요

이번 「이미지 파운데이션 모델」 과정에서는 이미지를 위한 Model을 처음부터 Training하는 것보다

> **이미 잘 학습된 Foundation Model을 어떻게 이해하고 활용할 것인가**

에 초점을 맞춘다.

전체 과정에서는

```text
Foundation Model의 개념
        ↓
대표 Image Foundation Model
        ↓
Vision + Language Model
        ↓
기타 Image Foundation Model
        ↓
Fine-tuning / Synthetic Data 활용
```

등을 배운다.

이번 1차시는 그 출발점으로

```text
처음부터 AI Model을 만들기 어렵다.
        ↓
Foundation Model을 활용하자.
        ↓
Foundation Model이란?
        ↓
기존 AI와 무엇이 다른가?
        ↓
Pre-training
        ↓
Task Adaptation
        ↓
Fine-tuning
Prompt Tuning
Prompt Engineering
Zero-shot / Few-shot
        ↓
Image Domain으로 이동
        ↓
Vision + Language
        ↓
CLIP
        ↓
Image Encoder
+
Text Encoder
        ↓
Contrastive Learning
        ↓
Image-Text Shared Representation
        ↓
Zero-shot Image Classification
```

의 흐름으로 진행된다.

---

# 1. 왜 Foundation Model이 필요한가?

회사에 취업한 뒤

> “이미지 기반 AI Service를 만들어 달라.”

는 요청을 받았다고 생각하자.

전통적인 방식이라면 해야 할 일이 매우 많다.

```text
Data 수집
      ↓
Annotation / Labeling
      ↓
Model 구현
      ↓
GPU 확보
      ↓
Training
      ↓
Evaluation Dataset 제작
      ↓
평가
```

Data가 없다면 Data부터 수집해야 한다.

Label이 없다면 사람을 고용해 Annotation해야 한다.

GPU가 없다면 GPU Server도 준비해야 한다.

평가 Data가 없으면 그것도 별도로 만들어야 한다.

즉 처음부터 모두 구축하는 것은 매우 어렵다.

---

# 2. 새로운 개발 패러다임

그래서 질문이 바뀐다.

```text
어떻게 Model을 처음부터 만들까?
```

가 아니라

```text
이미 잘 만들어진 Model 중
무엇을 가져와서
어떻게 활용할까?
```

가 된다.

이때 중요한 것이 **Foundation Model**이다.

---

# 3. AI Model의 가장 단순한 정의

강의에서는 AI Model을 매우 단순하게

> **입력과 출력을 연결하는 함수 또는 프로그램**

이라고 본다.

```text
Input
 ↓
AI Model
 ↓
Output
```

이다.

---

# 4. 일반 Program과 AI Model의 차이

AI Model에는 중요한 특징이 있다.

그 연결 규칙을 사람이 직접 모두 Programming하는 것이 아니라

```text
Data
↓
Learning
↓
Model Function 결정
```

한다.

즉 **Data로부터 함수가 만들어진다.**

---

# 5. Generalization도 필요하다

AI Model은 Training Data에서 본 Input만 처리해서는 안 된다.

```text
Training에서 본 Data
+
Training에서 보지 못한 Data
```

모두에 대해 적절하게 동작해야 한다.

즉 **Generalization**이 필요하다.

---

# 6. 이상적인 AI Model을 상상해 보자

강의에서는 Foundation Model을 설명하기 위해 먼저 극단적인 이상적 Model을 상상한다.

만약 어떤 Model이

> **세상에 존재하는 모든 Data와 그 Data에 대한 설명을 전부 기억하고 있다.**

면 어떨까?

---

# 7. 모든 것을 기억한다면 Search만 해도 된다

새로운 문제가 들어왔을 때 이미 Database에 비슷한 사례가 있을 가능성이 매우 높다.

그러면

```text
새로운 Query
      ↓
거대한 Database
      ↓
가장 비슷한 Data 검색
      ↓
Answer
```

처럼 처리할 수 있다.

즉 이상적인 AI는 Search Engine과 비슷한 형태로 생각할 수도 있다.

---

# 8. 최근접 이웃 탐색과의 연결

고전적인 Machine Learning에서도 비슷한 Idea가 있다.

```text
새로운 Input
↓
Training Data 중
가장 비슷한 Sample 탐색
↓
그 Sample을 이용해 판단
```

하는 **Nearest Neighbor** 방식이다.

강의에서는 이것 역시 일종의 Search 관점으로 설명한다.

---

# 9. 하지만 모든 Data를 저장할 수는 없다

현실에서는

```text
세상의 모든 Data 저장
```

자체가 어렵다.

Storage가 엄청나게 필요하기 때문이다.

---

# 10. 모든 Data를 Search하는 것도 어렵다

Storage뿐 아니라 Search Cost도 문제다.

매 Query마다

```text
전 세계의 모든 Data
```

를 하나씩 비교한다면 계산 시간이 너무 많이 필요하다.

---

# 11. 미래 Data는 애초에 존재하지 않는다

아무리 큰 Database를 만들더라도

```text
아직 발생하지 않은 Data
```

를 저장할 수는 없다.

즉 단순한 Memorization + Search만으로 완벽한 AI를 만드는 것은 현실적으로 불가능하다.

---

# 12. 해결 아이디어 — Data를 압축한다

그렇다면 모든 Data를 그대로 저장하지 않고 **Pattern 형태로 압축**하면 어떨까?

```text
Massive Data
      ↓
Pattern Extraction
      ↓
Compact Representation
```

으로 바꾼다.

---

# 13. 단순 압축이 아니라 Pattern 기반 압축

중요한 것은 단순히 File 용량을 줄이는 압축이 아니다.

Model은 Data들 사이의

- Similarity
    
- Difference
    
- Statistical Pattern
    
- Structure
    

를 학습한다.

그리고 이러한 반복 Pattern을 이용해 Data를 압축한다.

---

# 14. 이것이 Learning이다

강의에서는 이 과정을

> **Data의 반복 Pattern을 파악해 압축하는 과정**

이라는 관점에서 Learning으로 설명한다.

Neural Network는 많은 Data를 Parameter 안에 Pattern으로 압축한다.

---

# 15. Representation Learning

이 과정에서 Neural Network는 단순한 Data 복사본이 아니라 Data를 설명할 수 있는 **Representation**을 학습한다.

```text
Raw Data
      ↓
Neural Network
      ↓
Representation
      ↓
Pattern 활용
      ↓
Generalization
```

한다.

---

# 16. 여기에서 Model과 Data를 모두 크게 키운다

이제

```text
엄청나게 많은 Data
+
그 Data Pattern을 담을 수 있는
엄청나게 큰 Neural Network
```

를 준비한다.

그리고 대규모로 Pre-training한다.

이것이 Foundation Model에 가까운 Idea다.

---

# 17. Foundation Model의 강의 정의

강의에서는 Foundation Model을

> **대규모 Data를 기억·표현할 정도로 큰 Model을 사용해 대규모 사전학습하고, 다양한 문제와 작업에 범용적으로 빠르게 적응할 수 있도록 만든 Model**

이라는 방향으로 설명한다.

즉 단순히

```text
큰 Model
```

만 의미하지 않는다.

```text
Large-scale Pre-training
+
Adaptability
+
Generality
```

가 중요하다.

---

# 18. Foundation Model은 엄밀한 기술 규격은 아니다

강의에서는 Foundation Model이라는 표현을

> 아주 엄밀하게 수식으로 정의된 기술 용어라기보다 하나의 연구·산업적 범주에 가까운 표현

이라고 설명한다.

즉

```text
Parameter가 정확히 N개 이상이면
Foundation Model이다.
```

같은 절대적인 경계가 있는 개념은 아니다.

---

# 19. 기존 Deep Learning 패러다임

기존에는 새로운 Task가 생길 때마다 Model을 처음부터 Training하는 경우가 많았다.

```text
Random Initialization
      ↓
Task-specific Data
      ↓
Training
      ↓
Task-specific Model
```

강의에서는 이를 사람이 아무것도 모르는 상태에서 매번 처음부터 모든 것을 배우는 것에 비유한다.

---

# 20. Foundation Model 패러다임

Foundation Model에서는 먼저

```text
Huge Model
+
Huge Data
      ↓
Pre-training
```

을 수행한다.

그다음 원하는 Task에 적응시킨다.

```text
Pre-trained Foundation Model
        ↓
Task Adaptation
        ↓
Downstream Task
```

이다.

---

# 21. 이미 많은 경험을 가진 상태에서 시작한다

강의의 직관은 다음과 같다.

기존 방식:

```text
아무것도 모르는 아이
→ 매번 처음부터 학습
```

Foundation Model:

```text
이미 많은 경험과 지식이 있는 사람
→ 새로운 일을 빠르게 배움
```

이다.

---

# 22. Foundation Model의 핵심 ① Large-scale Pre-training

Foundation Model의 출발점은 **대규모 사전학습**이다.

여기에서 중요한 것은 단순히

```text
Supervised인가?
Unsupervised인가?
```

가 아니다.

강의에서 더 중요한 기준은

```text
Large Scale
+
Pre-training
```

이다.

---

# 23. 반드시 비지도 학습이어야 하는 것은 아니다

대규모 Dataset을 전부 사람이 Labeling하려면

- Money
    
- Time
    
- Human Labor
    

가 엄청나게 필요하다.

그래서 현실적으로 Label 없는 Data를 활용하는 방식을 많이 사용한다.

하지만 강의에서는

> **Foundation Model은 반드시 Unsupervised Learning으로만 만들어야 하는 것은 아니다.**

라고 명시한다.

---

# 24. 비지도 또는 자동화된 학습이 많이 쓰이는 이유

핵심은

```text
Data를 쉽게 많이 모을 수 있어야 한다.
```

는 것이다.

Human Labeling이 반드시 필요하면 Data Scale을 크게 만드는 것이 매우 어렵다.

따라서

```text
대규모 Raw Data
+
Human Label을 최소화한 학습 방식
```

이 Foundation Model과 잘 맞는다.

---

# 25. Foundation Model의 핵심 ② Adaptability

Foundation Model은 Pre-training만 잘했다고 끝나는 것이 아니다.

다양한 **Downstream Task**에 쉽게 적응할 수 있어야 한다.

---

# 26. Downstream Task

Pre-training 이후 실제 사용자가 풀고 싶은 문제를 Downstream Task라고 한다.

예:

```text
Foundation Vision Model
        ↓
Downstream Task
├─ Classification
├─ Detection
├─ Segmentation
├─ Retrieval
└─ 기타 Domain Task
```

---

# 27. 이미 비슷한 Pattern을 많이 봤다면 바로 사용할 수도 있다

Foundation Model이 Pre-training 중 Downstream Task와 유사한 Pattern을 많이 봤다면

```text
추가 Training 거의 없음
```

에도 좋은 Performance를 낼 수 있다.

이것이 뛰어난 Adaptability다.

---

# 28. 적은 Data로도 적응할 수 있다

추가 Training이 필요한 경우에도

```text
Few Data
+
Small Adaptation
```

만으로 좋은 Performance가 나온다면 매우 유용하다.

이 때문에 Foundation Model을 실무적으로 활용하기 쉬워진다.

---

# 29. Foundation Model의 핵심 ③ Generality

Adaptability와 연결되는 또 다른 특성이 **범용성**이다.

다양한 Downstream Task를 처리할 수 있다는 의미도 있지만 강의에서는 한 Task 안에서도 Output 범위가 훨씬 넓다는 점을 강조한다.

---

# 30. 기존 Image Classification의 한계

기존 Image Classifier가

```text
1000 Classes
```

를 가지고 있다면 Output은 그 1000개 중 하나여야 한다.

```text
Input Image
↓
Classifier
↓
1000개 중 하나
```

다.

새로운 Object가 1000개 Class에 없다면 제대로 처리하기 어렵다.

---

# 31. Foundation Model은 Output 범위를 넓힐 수 있다

예를 들어 Image Captioning Model이라면 Output이 Natural Language다.

```text
Image
↓
"The dog is running on the beach."
```

처럼 표현할 수 있다.

Natural Language Vocabulary를 사용하기 때문에 Fixed Class Set보다 훨씬 넓은 Concept을 표현할 수 있다.

---

# 32. Open Vocabulary

즉 Foundation Model에서는

```text
정해진 Class ID
```

가 아니라

```text
Natural Language Concept
```

을 통해 새로운 Category까지 다루는 방향이 가능하다.

강의에서는 이런 한정되지 않은 Output 범위를 Foundation Model의 중요한 범용성으로 설명한다.

---

# 33. AI 개발 Paradigm의 변화

Foundation Model이 등장하면서

```text
과거

Task
↓
Dataset
↓
Model을 처음부터 Training
```

에서

```text
현재

Pre-trained Foundation Model
↓
조금의 Data / Prompt / Adaptation
↓
Task 해결
```

로 바뀐다.

---

# 34. 개발자의 핵심 능력도 바뀐다

강의에서는 이제

> **Model을 처음부터 Training하는 것보다 이미 잘 Training된 Model을 얼마나 잘 활용하는가**

가 중요해지고 있다고 설명한다.

---

# 35. Foundation Model 자체를 만드는 것은 매우 비싸다

Foundation Model Pre-training에는

- Huge Dataset
    
- GPU
    
- Data Center
    
- Electricity
    
- Engineering Resource
    

가 필요하다.

따라서 개인이나 일반 연구실 수준에서 직접 Foundation Model을 처음부터 만드는 것은 쉽지 않다.

---

# 36. 강의에서 강조하는 실무 방향

그래서 대부분의 Developer 입장에서는

```text
Foundation Model을 직접 만든다.
```

보다

```text
좋은 Foundation Model을 가져와
내 Task에 맞게 Adapt한다.
```

가 현실적이다.

---

# 37. Task Adaptation

Pre-trained Foundation Model을 Downstream Task에 맞추는 여러 방법을 강의에서는 **Task Adaptation** 관점에서 소개한다.

대표적으로

```text
Prompt Engineering

Prompt Tuning

Transfer Learning

Fine-tuning

Adaptation
```

등이 있다.

---

# 38. Transfer Learning / Fine-tuning

강의에서는 Transfer Learning과 Fine-tuning을 매우 유사한 개념으로 설명한다.

핵심은

> **Pre-trained Model의 Parameter를 Downstream Task Data로 다시 Update한다.**

는 것이다.

```text
Pre-trained Parameters
      ↓
Task Data
      ↓
Gradient Update
      ↓
Modified Parameters
```

---

# 39. Full Fine-tuning

Model Parameter 전체를 변경한다면 가장 직접적인 Fine-tuning이다.

```text
Foundation Model
↓
모든 Weight Update
↓
Task-specific Model
```

---

# 40. Prompt Tuning

Prompt Tuning에서는 Model의 본체 Parameter는 고정한다.

대신 Model 앞에 추가되는 Prompt Token Representation만 학습한다.

```text
Model Weights
→ Frozen

Prompt Representation
→ Trainable
```

이다.

---

# 41. Prompt Tuning의 Prompt는 사람이 읽을 수 있는 문장일 필요가 없다

Optimization을 통해 학습되는 Prompt Representation은 사람이 해석할 수 있는 자연어 Sentence라기보다

```text
Learnable Token Vector
```

형태일 수 있다.

즉 Model을 바꾸는 대신 입력 Prompt Representation을 학습한다.

---

# 42. Prompt Engineering

Prompt Engineering은 또 다르다.

```text
Model Training X
Prompt Parameter Training X
```

이다.

사람이 Input Prompt를 잘 작성한다.

예:

```text
이 이미지를 다음 Category 중 하나로 분류하라.
...
```

와 같이 설명을 조절한다.

---

# 43. 세 방법의 차이

|방법|Model Parameter|Prompt|Training|
|---|---|---|---|
|Fine-tuning|변경|일반 Input|O|
|Prompt Tuning|고정|Learnable Prompt Parameter|O|
|Prompt Engineering|고정|사람이 설계|X|

---

# 44. Zero-shot / Few-shot은 다른 분류 기준이다

여기에서 중요한 혼동을 정리한다.

`Fine-tuning`, `Prompt Tuning` 등은

> **무엇을 Update하느냐**

와 관련된 분류다.

반면

```text
Zero-shot
One-shot
Few-shot
```

은

> **Target Task에 대한 Example/Data를 얼마나 제공하느냐**

라는 관점이다.

---

# 45. Zero-shot

Target Task의 Example을 하나도 제공하지 않는다.

```text
Example = 0
```

이다.

대신 Task 설명만 제공할 수 있다.

```text
이 Image가 Dog인지 Cat인지 분류하라.
```

처럼 설명하고 바로 수행한다.

---

# 46. One-shot

Target Task Example을 하나 제공한다.

```text
Example = 1
```

이다.

---

# 47. Few-shot

Target Task Example을 몇 개 제공한다.

```text
Example = Few
```

이다.

---

# 48. Zero/Few-shot과 Parameter Update를 혼동하지 않는다

강의의 핵심은

```text
Fine-tuning
→ Model Parameter 변경 여부

Zero/Few-shot
→ Task Example 수
```

라는 서로 다른 Classification Axis라는 것이다.

---

# 49. Prompting과 In-context Learning

강의에서는 Prompt를 이용해 Model에 Task를 알려주는 과정도 **In-context Learning**과 연결한다.

Model Parameter 자체를 다시 Training하지 않더라도 Context를 통해 새로운 Task를 수행하는 것이다.

---

# 50. 이제 Image Foundation Model로 이동

지금까지 일반 Foundation Model의 개념을 배웠다.

이제 Computer Vision Domain으로 넘어간다.

대표 Model로 이번 강의에서 **CLIP**을 다룬다.

---

# 51. 왜 Vision과 Language를 결합하는가?

강의에서는 사람의 지능을 크게

```text
Perception
+
High-level Cognition
```

으로 나누는 관점을 제시한다.

---

# 52. Perception

세상을 감지하는 능력이다.

예:

- Vision
    
- Hearing
    
- Sensor Input
    

등이다.

쉽게 말해

```text
세상을 보는 눈과 귀
```

에 해당한다.

---

# 53. High-level Cognition

입력된 정보를 기반으로

- 이해
    
- 사고
    
- Reasoning
    
- Decision
    

하는 능력이다.

---

# 54. 과거 AI는 이 능력을 분야별로 따로 만들었다

예:

```text
Computer Vision Model

Language Model

Speech Model

Audio Model
```

처럼 각각 독립적으로 발전했다.

---

# 55. Large Language Model의 등장

강의에서는 ChatGPT 이후 대규모 Language Model이 강력한

- Reasoning
    
- Cognition
    
- Language Understanding
    

능력을 보여주면서

> **고차원적인 사고 부분을 Language Model에 맡길 수 있지 않을까?**

라는 관점이 강해졌다고 설명한다.

---

# 56. 그런데 Language만으로 실제 세계를 볼 수는 없다

Language Model에게 아무리 높은 Reasoning Ability가 있어도 Image를 입력할 수 없다면 실제 Visual World를 직접 볼 수 없다.

그래서 Idea가 나온다.

```text
Strong Language Model
+
Eyes
```

를 만들자.

---

# 57. Vision-Language Model

Language Model에 Image Encoder를 붙여

```text
Image
+
Text
      ↓
Vision-Language Model
      ↓
Understanding / Reasoning
```

을 가능하게 한다.

즉 AI에게 **눈을 붙이는 것**이다.

---

# 58. Multimodal Model

Text만 처리하지 않고

```text
Image
+
Text
```

등 여러 Modality를 함께 처리하기 때문에 Multimodal Model이라고도 한다.

---

# 59. 왜 Vision이 Agent에서도 중요한가?

강의에서는 Computer-use Agent 사례까지 연결한다.

기존 Software가 Agent API나 새로운 Protocol을 지원하지 않는 경우가 많다.

Legacy Software라면 더 어렵다.

---

# 60. 가장 범용적인 Interface — 화면

사람이 기존 Program을 사용하는 가장 기본적인 방법은

```text
Screen을 보고
+
Mouse를 Click
```

하는 것이다.

AI도 동일하게

```text
Screenshot
↓
Visual Understanding
↓
Button 위치 판단
↓
Click
```

할 수 있다면 오래된 Software까지 활용할 수 있다.

---

# 61. Vision은 Agent의 범용 Interface가 될 수 있다

API가 없어도 화면만 볼 수 있다면 Program을 조작할 가능성이 생긴다.

따라서 Vision Understanding은 Multimodal Assistant뿐 아니라 Agent System에서도 중요하다.

---

# 62. Language Model에 어떤 “눈”을 붙일 것인가?

Image를 Feature Vector로 바꾸는 Image Encoder는 매우 많다.

예:

- Classification Encoder
    
- Detection Encoder
    
- Segmentation Encoder
    
- DINO 계열 등
    

하지만 Vision-Language Model의 눈으로 사용하려면 한 가지 추가적인 특성이 유리하다.

> **Image Feature가 Language의 의미와 잘 연결되어 있어야 한다.**

---

# 63. 그래서 CLIP

이번 강의의 대표 Model이 **CLIP**이다.

CLIP은

```text
Image Encoder
+
Text Encoder
```

두 Encoder로 구성된다.

---

# 64. CLIP의 핵심 특징

Image와 Text를 각각 Vector로 바꾸는데

> **서로 의미가 같은 Image와 Text가 가까운 Representation을 갖도록 학습한다.**

따라서 Image Feature 자체가 Language Concept과 강하게 연결된다.

---

# 65. 왜 CLIP Image Encoder가 Vision-Language Model의 눈으로 적합한가?

일반 Image Encoder는 Image의 Visual Feature는 잘 표현할 수 있다.

CLIP Image Encoder는 추가로

```text
Image Semantic Meaning
↔
Natural Language Meaning
```

을 연결하도록 학습됐다.

따라서 Language Model과 연결하기 좋은 Representation을 제공한다는 것이 강의의 핵심 설명이다.

---

# 66. CLIP Idea는 다른 Modality로도 확장할 수 있다

Image ↔ Text뿐 아니라

```text
Audio ↔ Text

3D ↔ Text

Thermal Image ↔ Text

Sensor Data ↔ Text
```

등으로 Contrastive Alignment를 확장할 수 있다.

즉 Text를 공통 Semantic Interface처럼 사용할 수 있다.

---

# 67. CLIP이 Image Foundation Model다운 이유

강의에서는 CLIP이 다음과 같은 Foundation Model 특성을 가진다고 설명한다.

```text
Large-scale Pre-training

Zero-shot Transfer

Domain Generalization

Natural Language Interface

Open Vocabulary
```

---

# 68. 기존 ImageNet Model과 CLIP 비교

기존 Image Model은 ImageNet 같은 특정 Dataset에서 학습한다.

따라서 같은 Distribution의 ImageNet Test에는 잘 동작할 수 있다.

하지만

- Cartoon
    
- Sketch
    
- 다른 Image Style
    

등 Domain이 바뀌면 성능이 크게 떨어질 수 있다.

---

# 69. CLIP의 Robustness

CLIP은 Internet에서 매우 다양한 Image/Text Data를 학습했다.

따라서 Cartoon이나 Sketch처럼 Distribution이 바뀐 Data에서도 기존 특정 Dataset 전용 Model보다 Performance가 잘 유지되는 사례를 강의에서 설명한다.

즉

```text
Train Domain ≠ Test Domain
```

에서도 상대적으로 높은 Generalization을 보여준다.

---

# 70. CLIP의 Training Data

CLIP은 대규모 **Image–Text Pair**를 이용해 Training한다.

```text
Image
+
해당 Image를 설명하는 Text
```

가 하나의 Pair다.

---

# 71. 약 4억 개의 Image–Text Pair

강의에서는 OpenAI가 Internet에서 약

```text
400M Image–Text Pairs
```

를 수집해 CLIP Training에 활용했다고 설명한다.

중요한 것은 엄청난 Scale이다.

---

# 72. 사람이 직접 Caption을 새로 작성하지 않았다

4억 개 Image에 사람이 새로 Caption을 작성하게 하면 비용이 엄청나다.

CLIP에서는 Internet에 이미 존재하던 Text 정보를 활용했다.

---

# 73. Alt Text

대표적인 Source가 **Alternative Text(Alt Text)** 다.

HTML에서 Image가 정상적으로 표시되지 않거나 Accessibility Tool에서 Image 내용을 설명하기 위해 사용되는 Text다.

예:

```html
<img src="dog.jpg" alt="a dog running on grass">
```

처럼 Image와 설명 Text가 이미 함께 존재한다.

---

# 74. Internet 자체가 Image–Text Dataset이 된다

Web Page에는 이미

```text
Image
+
Alt Text
```

Pair가 많이 존재했다.

따라서 이를 Crawl하면 Human에게 새롭게 Labeling을 부탁하지 않고도 매우 많은 Paired Data를 얻을 수 있다.

---

# 75. CLIP Training의 지도/비지도 구분

강의에서는 CLIP Training을

> 지도학습인지 비지도학습인지 다소 애매하게 볼 수 있다.

고 설명한다.

Image와 대응하는 Text Pair라는 Supervision Signal은 존재하지만

```text
사람을 고용해서
Class Label을 새로 Annotate
```

한 것은 아니다.

즉 Internet에 자연스럽게 존재하는 Image–Text 관계를 이용한다.

---

# 76. 기존 ImageNet과 Data Scale 차이

ImageNet도 과거에는 매우 큰 Dataset이었다.

하지만 Internet-scale Image–Text Dataset은 그보다 훨씬 큰 Scale로 확장될 수 있다.

이 Data Scale이 Foundation Model의 Generalization과 연결된다.

---

# 77. CLIP Architecture

CLIP은 크게

```text
Image
↓
Image Encoder
↓
Image Embedding


Text
↓
Text Encoder
↓
Text Embedding
```

으로 구성된다.

목적은 두 Embedding을 **같은 Semantic Space에서 비교 가능하게 만드는 것**이다.

---

# 78. Text Encoder

강의에서는 CLIP의 Text Encoder를 Transformer Encoder 기반으로 설명한다.

Text를 Tokenization하여

```text
Token Embeddings
↓
Transformer Encoder
↓
Text Feature
```

로 바꾼다.

---

# 79. Image Encoder

원래 CLIP에서는 Image Encoder로 ResNet 계열과 Vision Transformer 계열 등을 사용할 수 있다.

강의에서는 ViT 구조를 다시 Reminder하며 Image Encoder가 어떻게 Image Feature를 만드는지 설명한다.

---

# 80. Vision Transformer Reminder

ViT에서는 Image를 작은 Patch로 나눈다.

예:

```text
Image
↓
16 × 16 Patch
↓
Flatten
↓
Linear Projection
↓
Patch Embedding
```

한다.

---

# 81. Patch가 Image의 Token이 된다

Text Transformer에서는

```text
Word / Subword Token
```

이 Input Token이었다.

ViT에서는

```text
Image Patch
```

가 Token 역할을 한다.

```text
Text
→ Word Token

Image
→ Patch Token
```

이다.

---

# 82. Position Embedding

Patch Sequence도 위치 정보가 필요하다.

그래서 각 Patch Embedding에 Position Information을 추가한 뒤 Transformer Encoder에 넣는다.

---

# 83. Class Token

ViT에서는 Patch 앞에 Learnable **Class Token**을 하나 추가할 수 있다.

```text
[CLS]
Patch 1
Patch 2
...
Patch N
```

형태다.

---

# 84. Class Token의 역할

Transformer를 통과한 뒤 Class Token Representation이 Image 전체 정보를 종합한 Representation으로 사용된다.

즉

> **“이 Image 전체가 무엇인가?”**

에 대응하는 대표 Vector로 사용할 수 있다.

강의에서는 이를 일종의 Question/Task Token 같은 직관으로 설명한다.

---

# 85. 기존 ViT Classification

기존 Image Classification ViT에서는

```text
CLS Representation
↓
MLP Head
↓
Class Probability
```

를 만든다.

---

# 86. Head를 바꾸면 다른 Task에 사용할 수 있다

Pre-trained Encoder가 이미 Image Representation을 잘 학습했다면

```text
Encoder
↓
기존 Classification Head 제거
↓
새 Head 부착
```

해서 새로운 Task에 활용할 수 있다.

---

# 87. Linear Probing

Encoder를 고정하고 새로운 Linear Head 정도만 Training하여 Representation의 Quality를 평가하거나 새로운 Task에 적용하는 방법을 강의에서는 **Linear Probing**과 연결한다.

```text
Pre-trained Encoder
→ Frozen

Linear Head
→ Train
```

이다.

---

# 88. 그런데 CLIP은 일반 Classification Head로 학습하지 않는다

CLIP은

```text
1000개 Class 중 정답
```

을 직접 맞히는 방식이 아니다.

대신 Image와 Text Representation의 **거리 관계**를 학습한다.

---

# 89. Contrastive Learning

CLIP의 핵심 Training 방법은 **Contrastive Learning(대조 학습)** 이다.

목표는 단순하다.

```text
Matching Image–Text Pair
→ 가까워지게

Non-matching Image–Text Pair
→ 멀어지게
```

학습한다.

---

# 90. Positive Pair

예를 들어

```text
강아지 Image
+
"a dog"
```

는 의미적으로 같은 Pair다.

이를 **Positive Pair**라고 한다.

Embedding Space에서 가까워져야 한다.

---

# 91. Negative Pair

```text
강아지 Image
+
"an elephant"
```

처럼 서로 대응하지 않는 Pair는 Negative Pair다.

Embedding Space에서 멀어지도록 학습한다.

---

# 92. Contrastive Learning의 목표

결국

```text
Semantic Meaning 같음
→ Vector Similarity ↑

Semantic Meaning 다름
→ Vector Similarity ↓
```

를 만드는 것이다.

---

# 93. Batch-based Contrastive Learning

CLIP은 한 번에 여러 Image–Text Pair를 Batch로 사용한다.

예를 들어 Batch Size가 `N`이라면

```text
Image 1 ↔ Text 1
Image 2 ↔ Text 2
Image 3 ↔ Text 3
...
Image N ↔ Text N
```

처럼 Pair가 있다.

---

# 94. 모든 Image와 모든 Text를 비교한다

Image Encoder가

```text
I₁
I₂
...
Iₙ
```

Embedding을 만들고

Text Encoder가

```text
T₁
T₂
...
Tₙ
```

Embedding을 만든다.

그다음 모든 조합의 Similarity를 계산한다.

```text
          T1  T2  T3 ... TN
I1
I2
I3
...
IN
```

즉 `N × N` Similarity Matrix가 만들어진다.

---

# 95. Diagonal = Positive Pair

원래 Pair는

```text
I₁ ↔ T₁
I₂ ↔ T₂
...
Iₙ ↔ Tₙ
```

이므로 Similarity Matrix의 **Diagonal**에 위치한다.

```text
S₁₁
S₂₂
S₃₃
...
Sₙₙ
```

이다.

---

# 96. Off-diagonal = Negative Pair

예:

```text
I₁ ↔ T₂
I₁ ↔ T₃
I₂ ↔ T₁
...
```

처럼 Matching하지 않는 Pair는 Off-diagonal에 위치한다.

이들이 Negative Pair다.

---

# 97. Similarity 계산

강의에서는 Image Embedding과 Text Embedding을 Normalization한 뒤 Inner Product를 계산하여 Cosine Similarity와 연결한다.

개념적으로

`S_ij = sim(I_i, T_j)`

이다.

---

# 98. Similarity Matrix에서 원하는 모양

Training이 잘되면

```text
Diagonal
→ 높은 Similarity

Off-diagonal
→ 낮은 Similarity
```

가 되어야 한다.

예:

```text
        T1    T2    T3

I1     높음   낮음   낮음
I2     낮음   높음   낮음
I3     낮음   낮음   높음
```

이다.

---

# 99. Softmax를 적용한다

한 Image를 기준으로 모든 Text Similarity를 Softmax에 넣는다.

예를 들어 Image `I₃`를 고정하면

```text
S₃₁
S₃₂
S₃₃
...
S₃N
```

을 Softmax한다.

---

# 100. Softmax Output

Softmax를 거치면 각 값은

```text
0 ~ 1
```

범위를 가지며 전체 합은 1이 된다.

따라서 Probability와 비슷하게 해석할 수 있다.

---

# 101. 정답 Pair Probability를 높인다

Image `I₃`의 실제 Matching Text가 `T₃`라면

```text
P(T₃ | I₃)
```

가 높아지도록 Loss를 준다.

궁극적으로

```text
P(correct pair) → 1
```

을 원한다.

---

# 102. Cross Entropy

정답 Pair의 Softmax Probability에 Cross Entropy Loss를 적용한다.

개념적으로

`L = -log P(correct pair)`

이다.

따라서 Correct Pair Probability가 1에 가까워질수록 Loss가 작아진다.

---

# 103. Positive가 올라가면 Negative는 내려간다

Softmax Output의 합은 항상 1이다.

따라서 Correct Pair Probability를 높이면 다른 Candidate의 Probability는 상대적으로 낮아진다.

```text
Positive Pair ↑
      ↓
Negative Pair ↓
```

가 된다.

즉 Cross Entropy만으로도 Contrastive 효과가 발생한다.

---

# 104. 양방향 Loss

CLIP에서는 한 방향만 계산하지 않는다.

### Image → Text

Image를 Anchor로 두고 어떤 Text가 Matching하는지 맞힌다.

### Text → Image

Text를 Anchor로 두고 어떤 Image가 Matching하는지 맞힌다.

---

# 105. 두 Loss를 합친다

개념적으로

```text
Image-to-Text Loss
+
Text-to-Image Loss
```

를 평균하여 사용한다.

따라서

```text
Image가 올바른 Text를 찾도록
+
Text가 올바른 Image를 찾도록
```

동시에 학습된다.

---

# 106. CLIP Contrastive Learning 전체 구조

```text
N개의 Image–Text Pair
        ↓

Image Encoder
→ N Image Embeddings

Text Encoder
→ N Text Embeddings
        ↓

모든 조합 Similarity
        ↓

N × N Similarity Matrix
        ↓

Diagonal
= Positive Pairs

Off-diagonal
= Negative Pairs
        ↓

Softmax
        ↓

Correct Matching Probability ↑
        ↓

Cross Entropy
        ↓

Image ↔ Text
Semantic Space Alignment
```

---

# 107. Temperature

CLIP Softmax에도 **Temperature**가 사용된다.

Softmax Input을 Temperature `T`로 조절한다.

개념적으로

`softmax(S / T)`

형태다.

---

# 108. Temperature가 높아지면

강의에서는 Temperature를 증가시키면 Softmax Distribution의 값들 사이 차이가 줄어드는 모습을 설명한다.

즉

```text
T ↑
→ Distribution flatter
```

해진다.

---

# 109. Temperature가 작으면

반대로

```text
T ↓
→ 높은 Score에 더 집중
→ Distribution sharper
```

해진다.

이는 앞 Text Foundation Model의 Decoding에서 배운 Temperature의 기본적인 Softmax 역할과 같은 방향으로 이해할 수 있다.

---

# 110. Contrastive Loss를 가장 직관적으로 보면

한 Image가 있다고 하자.

```text
강아지 Image
```

와 Batch 안의 Text들이 있다.

```text
"a dog"
"an elephant"
"a building"
"a car"
```

Training 목표는

```text
sim(dog image, "a dog")
↑↑↑

sim(dog image, other text)
↓↓↓
```

가 되도록 만드는 것이다.

---

# 111. 이 학습이 만들어내는 결과

Training이 끝나면 Image와 Text가 **같은 Semantic Vector Space**에 놓인다.

```text
Dog Image Vector
≈
"a dog" Vector

Car Image Vector
≈
"a car" Vector
```

처럼 된다.

---

# 112. 여기서 CLIP의 강력한 활용법이 나온다

Image와 Text Vector를 직접 비교할 수 있으므로

> **새로운 Classifier를 Training하지 않고도 Text Label을 Classification Target으로 사용할 수 있다.**

이것이 CLIP의 **Zero-shot Classification**이다.

---

# 113. Zero-shot Image Classification

먼저 분류하고 싶은 Class를 Text로 준비한다.

예:

```text
airplane

car

dog

bird
```

---

# 114. Prompt Template을 사용한다

단순 Class Name만 사용할 수도 있지만 강의에서는

```text
"a photo of a dog"
"a photo of a car"
```

같은 Template으로 자연어 표현을 만들어 Text Encoder에 넣는 방식을 설명한다.

---

# 115. Text Embedding을 미리 계산한다

```text
"a photo of an airplane"
↓
Text Encoder
↓
Embedding A

"a photo of a car"
↓
Embedding B
```

# 127. CLIP이 Foundation Model인 이유를 구조적으로 정리

### 1. 대규모 Pre-training

약 4억 개 규모의 Internet Image–Text Pair를 이용한다.

### 2. 별도의 Task-specific Label에 덜 의존

Web에 이미 존재하는 Image–Text 관계를 이용한다.

### 3. 다양한 Visual Concept 학습

Internet의 다양한 Domain과 Style을 접한다.

### 4. Zero-shot Transfer

새로운 Dataset을 별도 Fine-tuning하지 않고 사용할 수 있다.

### 5. Domain Robustness

Sketch, Cartoon 등 Distribution Shift에서도 강한 Generalization 사례를 보여준다.

### 6. Open Vocabulary

Text로 새로운 Category를 정의할 수 있다.

### 7. Transfer 가능성

Image Encoder를 다른 Vision-Language Architecture의 Visual Backbone으로 활용할 수 있다.

# 138. 자주 헷갈리는 점 ⑧ — CLIP Text는 사람이 4억 개를 직접 Labeling한 것인가?

아니다.

강의에서는 Web에 이미 존재하는 Alt Text 등 Image와 연결된 Text를 Crawl하여 대규모 Pair를 구성했다고 설명한다.

# 139. 자주 헷갈리는 점 ⑨ — Positive Pair는 같은 종류 Image끼리인가?

이번 CLIP 학습에서는

```text
Image
↔
그 Image와 Matching하는 Text
```

가 Positive Pair다.

---

# 140. 자주 헷갈리는 점 ⑩ — Negative Pair는 미리 별도 수집하는가?

Batch-based Contrastive Learning에서는 다른 Image와 Matching된 Text들이 현재 Image 관점에서는 Negative Candidate가 될 수 있다.

즉 Batch 안의 Off-diagonal Pair를 활용한다.

---

# 141. 자주 헷갈리는 점 ⑪ — Similarity Matrix의 Diagonal은 무엇인가?

원래 Image–Text Matching Pair다.

```text
I₁-T₁
I₂-T₂
...
```

이므로 Positive다.

---

# 142. 자주 헷갈리는 점 ⑫ — Off-diagonal은 무엇인가?

```text
I₁-T₂
I₁-T₃
I₂-T₁
...
```

같이 Matching하지 않는 Image/Text 조합이다.

Negative Pair다.

# 143. 자주 헷갈리는 점 ⑬ — Contrastive Learning은 Positive만 가깝게 하면 되는가?

아니다.

```text
Positive
→ Similarity ↑

Negative
→ Similarity ↓
```

를 동시에 학습하는 것이 핵심이다.

---

# 144. 자주 헷갈리는 점 ⑭ — Softmax는 Similarity 자체인가?

아니다.

먼저 Image/Text Embedding에서 Similarity Score를 계산한다.

그 Score들을 Softmax에 넣어 상대적인 Matching Probability처럼 변환한다.

---

# 145. 자주 헷갈리는 점 ⑮ — CLIP은 Image→Text 한 방향으로만 학습하는가?

아니다.

강의에서는

```text
Image → Text

Text → Image
```

두 방향 Cross Entropy Loss를 함께 사용한다고 설명한다.

---

# 146. 자주 헷갈리는 점 ⑯ — Zero-shot Classification인데 정말 Training이 전혀 없었는가?

Foundation Model 자체는 이미 대규모 Pre-training되어 있다.

여기서 Zero-shot이라는 뜻은

> **현재 새롭게 풀려는 Classification Task를 위해 추가 Example/Fine-tuning을 하지 않는다.**

는 의미다.

# 147. 자주 헷갈리는 점 ⑰ — CLIP Zero-shot에서 Classifier Weight를 새로 학습하는가?

기본 Zero-shot 방식에서는 아니다.

Text Prompt의 Embedding이 사실상 Class Prototype 역할을 한다.

# 153. 이번 강의에서 반드시 기억할 핵심

### 1. AI Model은 Data로 학습된 Input→Output 함수 또는 Program으로 볼 수 있다.

### 2. Training에서 보지 못한 Data에도 동작하는 Generalization이 필요하다.

### 3. 모든 Data를 그대로 저장하고 Search하는 이상적 Model은 Storage와 Compute 문제 때문에 현실적이지 않다.

### 4. Neural Network는 Data의 Pattern을 학습하여 정보를 Representation 형태로 압축한다고 이해할 수 있다.

### 5. Foundation Model은 대규모 Data와 큰 Model을 이용해 Pre-training하고 여러 Downstream Task에 빠르게 적응할 수 있는 범용 Model이다.

### 6. Foundation Model은 엄밀한 수치 기준이 정해진 용어라기보다 하나의 넓은 범주에 가깝다는 것이 강의의 설명이다.

### 7. 기존 Deep Learning은 Task마다 처음부터 Training하는 경우가 많았지만 Foundation Model은 먼저 대규모 Pre-training한 뒤 Task Adaptation한다.

### 8. Foundation Model의 중요한 특징은 Large-scale Pre-training, Adaptability, Generality다.

### 9. Foundation Model은 반드시 Unsupervised Learning으로만 학습해야 하는 것은 아니다.

### 10. Label 없는 Data 활용이 자주 등장하는 이유는 대규모 Data 수집과 Labeling Cost 때문이다.

### 11. 실제 업무에서는 Foundation Model 자체를 처음부터 만드는 것보다 이미 잘 학습된 Model을 활용하는 것이 현실적일 수 있다.

### 12. Task Adaptation 방법으로 Fine-tuning, Prompt Tuning, Prompt Engineering 등이 있다.

### 13. Fine-tuning은 Pre-trained Model Parameter를 Update한다.

### 14. Prompt Tuning은 Model을 고정하고 Learnable Prompt Representation을 학습한다.

### 15. Prompt Engineering은 Model을 Training하지 않고 사람이 Prompt를 설계한다.

### 16. Zero-shot/One-shot/Few-shot은 제공하는 Target Task Example 수에 따른 구분이다.

### 17. Fine-tuning과 Zero/Few-shot은 서로 다른 기준으로 구분해야 한다.

### 18. Vision-Language Model은 Language Model에 Visual Perception 능력을 연결하는 방향으로 이해할 수 있다.

### 19. Visual Understanding은 Multimodal Assistant뿐 아니라 Computer-use Agent의 Screen Interface에도 중요하다.

### 20. CLIP은 Image Encoder와 Text Encoder로 구성된다.

### 21. CLIP은 Image와 Natural Language의 의미 관계를 같은 Embedding Space에서 표현하도록 학습한다.

### 22. CLIP의 Image Encoder는 Language Semantic 정보와 연결된 Visual Representation을 제공한다.

### 23. CLIP은 약 4억 개 규모의 Internet Image–Text Pair를 활용했다고 강의에서 설명한다.

### 24. 대규모 Pair 확보에 Web의 Alt Text가 중요한 역할을 했다.

### 25. Text Encoder는 Transformer Encoder 계열로 설명된다.

### 26. Image Encoder에는 ResNet/ViT 계열을 사용할 수 있다.

### 27. ViT에서는 Image를 Patch 단위 Token으로 변환한다.

### 28. ViT의 Class Token은 Image 전체 Representation을 얻는 데 사용할 수 있다.

### 29. Pre-trained Image Encoder의 Head를 바꾸어 새로운 Task에 사용할 수 있으며 Linear Probing과 연결된다.

### 30. CLIP의 핵심 Training Objective는 Contrastive Learning이다.

### 31. Matching Image–Text는 Positive Pair다.

### 32. Non-matching Image–Text는 Negative Pair다.

### 33. Positive Pair는 Embedding Similarity를 높이고 Negative Pair는 낮춘다.

### 34. Batch 안의 모든 Image와 Text를 비교하여 N×N Similarity Matrix를 만든다.

### 35. Similarity Matrix의 Diagonal은 Positive Pair다.

### 36. Off-diagonal은 Negative Pair다.

### 37. Image/Text Embedding을 Normalization하고 Inner Product를 사용해 Cosine Similarity와 연결할 수 있다.

### 38. Softmax를 이용해 Matching Candidate 간 상대적인 Probability 형태를 만든다.

### 39. Cross Entropy는 Correct Pair Probability가 높아지도록 학습한다.

### 40. CLIP은 Image→Text와 Text→Image 두 방향의 Loss를 함께 사용한다.

### 41. Softmax Temperature를 이용해 Distribution의 Sharpness를 조절할 수 있다.

### 42. CLIP Training 결과 Image와 Text가 Shared Semantic Space에 정렬된다.

### 43. Zero-shot Classification에서는 새로운 Class 이름을 Text Prompt로 만들어 Text Embedding으로 사용한다.

### 44. 새로운 Image Embedding과 각 Class Text Embedding의 Similarity를 비교한다.

### 45. 가장 Similarity가 높은 Text Class를 Prediction으로 선택한다.

### 46. Zero-shot은 현재 Downstream Classification Task를 위한 추가 Training Example이 없다는 의미다.

### 47. Class는 Dog/Car 같은 Object뿐 아니라 Bright/Dark, Quality 같은 Semantic Concept도 가능하다.

### 48. CLIP Zero-shot Classification은 구조적으로 Vector Similarity Search와 매우 비슷하다.

### 49. Class 수가 매우 많아지면 Efficient Vector Search 문제와 연결할 수 있다.

# 154. 이번 강의 핵심 한 문장

> **이미지 Foundation Model은 대규모 Data와 큰 Model을 사전학습하여 다양한 Downstream Task에 적은 추가 학습 또는 추가 학습 없이 빠르게 적응할 수 있는 범용 Visual Model이며, 대표적인 CLIP은 Internet에서 대규모 Image–Text Pair를 수집하여 Matching Image와 Text의 Embedding은 가깝게, Matching하지 않는 Pair는 멀게 만드는 Contrastive Learning을 수행함으로써 Image와 Natural Language를 하나의 Semantic Space에 정렬하고, 새로운 Class를 Text Prompt로 표현하여 별도의 Task-specific Training 없이 Zero-shot Image Classification을 가능하게 한다.**

가장 짧게 기억하면 다음과 같다.

```text
Foundation Model
= 크게 먼저 배우고
  작은 비용으로 여러 Task에 적응

CLIP
= Image와 Text를
  같은 의미 공간에 연결

Contrastive Learning
= 맞는 Image–Text는 가깝게
  틀린 Pair는 멀게

Zero-shot CLIP
= Class 이름을 Text Vector로 만들고
  Image와 가장 가까운 Text를 고른다.
```
