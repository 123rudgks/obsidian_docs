# 1. Text Foundation Model을 이해하려면 Foundation Model부터

Text Foundation Model은 말 그대로

> **Text에 특화된 Foundation Model**

이다.

따라서 먼저 Foundation Model 자체를 정의해야 한다.

강의에서는 Foundation Model을 간단히

> **대량의 Data를 기반으로 사전학습된 대규모 AI Model**

이라고 설명한다.

---

# 2. Foundation이라는 이름의 의미

이 Model은 하나의 Task만 처리하기 위해 만들어지는 것이 아니다.

대규모 Data를 학습하면서 세상과 Data에 대한 광범위한 Knowledge를 습득한 뒤

```text
Task A
Task B
Task C
Task D
...
```

와 같이 여러 Downstream Task의 **기반(Foundation)** 으로 사용할 수 있다.

즉

```text
한 Task를 위한 Model
```

이 아니라

```text
여러 Task의 기반이 되는 Model
```

이라는 점이 중요하다.

---

# 3. 강의에서 말하는 “대규모”

강의에서는 LLM을 설명하기 위한 대략적인 규모의 예로

```text
Training Data
→ Trillion-scale

Parameters
→ Billion-scale 이상
```

을 이야기한다.

즉 Data만 큰 것이 아니다.

```text
큰 Data
+
큰 Model
```

두 요소가 동시에 존재한다.

강의에서도 이러한 기준은 시대에 따라 달라질 수 있다고 이후 다시 강조한다.

---

# 4. 왜 많은 Data를 보면 범용성이 생기는가?

Internet에는

- News
    
- Sports
    
- Programming
    
- History
    
- Science
    
- Conversation
    
- Culture
    
- Literature
    

등 다양한 종류의 정보가 존재한다.

Model이 매우 많은 Internet Text를 학습하면 특정 Domain 하나만이 아니라 다양한 지식과 Pattern을 학습하게 된다.

그 결과 하나의 Model을 여러 종류의 Task에 활용할 가능성이 생긴다.

---

# 5. Foundation Model은 Text에만 존재하지 않는다

Foundation Model이라는 개념은 Text에 한정되지 않는다.

강의에서는

- Text
    
- Image
    
- Video
    
- Audio
    

등으로 확장된다고 설명한다.

즉

```text
Text Foundation Model

Vision Foundation Model

Video Foundation Model

Audio Foundation Model
```

등이 존재할 수 있다.

---

# 6. Modality

AI가 처리하는 Data Type을 **Modality**라고 한다.

예:

```text
Text
Image
Audio
Video
```

### Unimodal

하나의 Modality만 처리.

### Multimodal

두 개 이상의 Modality를 처리.

---

# 7. Multimodal Foundation Model

최근 Model은 단순히

```text
Text → Text
```

만 수행하는 것이 아니라

```text
Text
Image
Audio
Video
     ↓
Foundation Model
     ↓
Text
Image
Audio
Video
```

처럼 여러 종류의 Input과 Output을 처리하는 방향으로 발전한다.

강의에서는 GPT 계열도 Text-only에서 점차 Multimodal Foundation Model로 확장되는 흐름으로 설명한다.

---

# 8. Foundation Model 이전의 AI 발전 흐름

Foundation Model이 갑자기 등장한 것은 아니다.

강의에서는 AI Model의 발전을 크게 다음처럼 설명한다.

```text
Feature-based Machine Learning
        ↓
Deep Learning
        ↓
Pre-training + Fine-tuning
        ↓
Foundation Model
```

---

# 9. 1단계 — Feature-based Machine Learning

과거 Machine Learning에서는 사람이 중요한 Feature를 직접 만들어야 했다.

예를 들어

```text
Dog vs Cat Classification
```

을 한다면 사람이

- Ear Shape
    
- Stripe
    
- Color
    
- Size
    

등을 Feature로 정의한다.

```text
Raw Data
      ↓
Human Feature Engineering
      ↓
Machine Learning Model
```

구조다.

---

# 10. 2단계 — Deep Learning

Deep Learning 시대에는 Feature 자체도 Model이 학습하도록 바뀐다.

```text
Raw Data
      ↓
Neural Network
      ↓
Feature Representation
      ↓
Prediction
```

즉 사람이 Feature를 하나씩 설계하는 부담이 크게 줄었다.

---

# 11. 3단계 — Pre-training

이후 등장한 중요한 개념이 **Pre-training**이다.

바로 Target Task를 Training하는 것이 아니라

```text
Large General Dataset
      ↓
Pre-training
      ↓
General Representation
      ↓
Target Task Data
      ↓
Fine-tuning
```

을 수행한다.

앞 자연어 처리 강의에서 배운 BERT 등이 대표적인 예다.

---

# 12. Pre-training 시대에도 Task-specific Training은 필요했다

예를 들어 감성 분석 Model을 만들고 싶다면

```text
Pre-trained BERT
      ↓
Sentiment Labelled Data
      ↓
Fine-tuning
      ↓
Sentiment Model
```

이 필요했다.

즉 Pre-training 덕분에 필요한 Data와 Training 비용이 줄어들었지만

> **새로운 Task마다 별도의 Fine-tuning**

이 여전히 필요했다.

---

# 13. Foundation Model 시대의 큰 변화

강의에서는 Foundation Model 시대의 중요한 차이를

> **많은 경우 새로운 Task를 위해 별도의 Training을 하지 않고 Prompt만으로 Task를 수행할 수 있다.**

는 것으로 설명한다.

```text
기존 방식

새로운 Task
↓
Data 수집
↓
Labeling
↓
Training / Fine-tuning
↓
Task Model
```

에서

```text
Foundation Model

새로운 Task
↓
Prompt 설명
↓
Output
```

으로 바뀐다.

---

# 14. Prompt가 Task Specification이 된다

예를 들어 4행시를 만들어야 한다고 하자.

과거에는

```text
4행시 Dataset 수집
↓
특정 Style Dataset 수집
↓
Training
```

이 필요할 수 있었다.

Foundation Model에서는

```text
"OO으로 4행시를 만들어줘.
이런 스타일로 만들어줘."

+
몇 개의 Example
```

만 제공해도 원하는 Task를 수행하도록 유도할 수 있다.

즉 Prompt가 일종의 **Task Specification** 역할을 한다.

---

# 15. Foundation Model을 사용하는 방식도 달라진다

기존 Machine Learning에서는

```text
Data 수집
→ Training
→ Model 변경
```

이 중요했다.

Foundation Model에서는 이미 Training된 Model을 사용하는 상황이라면

```text
Prompt 작성
      ↓
Output 관찰
      ↓
부족함 발견
      ↓
Prompt 수정
      ↓
다시 Output 확인
```

처럼 **Prompt Optimization**이 중요한 작업이 된다.
