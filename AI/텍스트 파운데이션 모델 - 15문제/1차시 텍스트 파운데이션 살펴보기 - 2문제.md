# 0. 이번 과정의 전체 목표

이번 「텍스트 파운데이션 모델」 과정에서는 크게 다음 내용을 다룬다.

```text
텍스트 파운데이션 모델이란?
        ↓
대표적인 LLM은 무엇인가?
        ↓
이 Model들은 어떻게 학습하는가?
        ↓
학습된 Model은
어떻게 실제 응답을 생성하는가?
        ↓
Inference / Decoding
        ↓
어떻게 평가하고 활용하는가?
        ↓
응용과 한계
```

강의에서는 전체 과정의 목표를 크게 세 가지로 제시한다.

1. **텍스트 파운데이션 모델이 무엇인지 이해**
    
2. **Model의 학습 및 추론 방식을 이해**
    
3. **응용과 한계를 파악하고 실제 사례에 적용**
    

GPT, Gemini 같은 이름을 아는 것이 목적이 아니라

> **“어떤 특성을 가진 AI Model을 Foundation Model이라고 부르는가?”**

를 이해하는 것이 출발점이다.

---

# 1. Text Foundation Model을 이해하려면 Foundation Model부터

Text Foundation Model은 말 그대로

> **Text에 특화된 Foundation Model**

이다.

따라서 먼저 Foundation Model 자체를 정의해야 한다.

강의에서는 Foundation Model을 간단히

> **대량의 Data를 기반으로 사전학습된 대규모 AI Model**

이라고 설명한다.

---

# 2. Foundation이라는 이름의 의미

이 Model은 하나의 Task만 처리하기 위해 만들어지는 것이 아니다.

대규모 Data를 학습하면서 세상과 Data에 대한 광범위한 Knowledge를 습득한 뒤

```text
Task A
Task B
Task C
Task D
...
```

와 같이 여러 Downstream Task의 **기반(Foundation)** 으로 사용할 수 있다.

즉

```text
한 Task를 위한 Model
```

이 아니라

```text
여러 Task의 기반이 되는 Model
```

이라는 점이 중요하다.

---

# 3. 강의에서 말하는 “대규모”

강의에서는 LLM을 설명하기 위한 대략적인 규모의 예로

```text
Training Data
→ Trillion-scale

Parameters
→ Billion-scale 이상
```

을 이야기한다.

즉 Data만 큰 것이 아니다.

```text
큰 Data
+
큰 Model
```

두 요소가 동시에 존재한다.

강의에서도 이러한 기준은 시대에 따라 달라질 수 있다고 이후 다시 강조한다.

---

# 4. 왜 많은 Data를 보면 범용성이 생기는가?

Internet에는

- News
    
- Sports
    
- Programming
    
- History
    
- Science
    
- Conversation
    
- Culture
    
- Literature
    

등 다양한 종류의 정보가 존재한다.

Model이 매우 많은 Internet Text를 학습하면 특정 Domain 하나만이 아니라 다양한 지식과 Pattern을 학습하게 된다.

그 결과 하나의 Model을 여러 종류의 Task에 활용할 가능성이 생긴다.

---

# 5. Foundation Model은 Text에만 존재하지 않는다

Foundation Model이라는 개념은 Text에 한정되지 않는다.

강의에서는

- Text
    
- Image
    
- Video
    
- Audio
    

등으로 확장된다고 설명한다.

즉

```text
Text Foundation Model

Vision Foundation Model

Video Foundation Model

Audio Foundation Model
```

등이 존재할 수 있다.

---

# 6. Modality

AI가 처리하는 Data Type을 **Modality**라고 한다.

예:

```text
Text
Image
Audio
Video
```

### Unimodal

하나의 Modality만 처리.

### Multimodal

두 개 이상의 Modality를 처리.

---

# 7. Multimodal Foundation Model

최근 Model은 단순히

```text
Text → Text
```

만 수행하는 것이 아니라

```text
Text
Image
Audio
Video
     ↓
Foundation Model
     ↓
Text
Image
Audio
Video
```

처럼 여러 종류의 Input과 Output을 처리하는 방향으로 발전한다.

강의에서는 GPT 계열도 Text-only에서 점차 Multimodal Foundation Model로 확장되는 흐름으로 설명한다.

---

# 8. Foundation Model 이전의 AI 발전 흐름

Foundation Model이 갑자기 등장한 것은 아니다.

강의에서는 AI Model의 발전을 크게 다음처럼 설명한다.

```text
Feature-based Machine Learning
        ↓
Deep Learning
        ↓
Pre-training + Fine-tuning
        ↓
Foundation Model
```

---

# 9. 1단계 — Feature-based Machine Learning

과거 Machine Learning에서는 사람이 중요한 Feature를 직접 만들어야 했다.

예를 들어

```text
Dog vs Cat Classification
```

을 한다면 사람이

- Ear Shape
    
- Stripe
    
- Color
    
- Size
    

등을 Feature로 정의한다.

```text
Raw Data
      ↓
Human Feature Engineering
      ↓
Machine Learning Model
```

구조다.

---

# 10. 2단계 — Deep Learning

Deep Learning 시대에는 Feature 자체도 Model이 학습하도록 바뀐다.

```text
Raw Data
      ↓
Neural Network
      ↓
Feature Representation
      ↓
Prediction
```

즉 사람이 Feature를 하나씩 설계하는 부담이 크게 줄었다.

---

# 11. 3단계 — Pre-training

이후 등장한 중요한 개념이 **Pre-training**이다.

바로 Target Task를 Training하는 것이 아니라

```text
Large General Dataset
      ↓
Pre-training
      ↓
General Representation
      ↓
Target Task Data
      ↓
Fine-tuning
```

을 수행한다.

앞 자연어 처리 강의에서 배운 BERT 등이 대표적인 예다.

---

# 12. Pre-training 시대에도 Task-specific Training은 필요했다

예를 들어 감성 분석 Model을 만들고 싶다면

```text
Pre-trained BERT
      ↓
Sentiment Labelled Data
      ↓
Fine-tuning
      ↓
Sentiment Model
```

이 필요했다.

즉 Pre-training 덕분에 필요한 Data와 Training 비용이 줄어들었지만

> **새로운 Task마다 별도의 Fine-tuning**

이 여전히 필요했다.

---

# 13. Foundation Model 시대의 큰 변화

강의에서는 Foundation Model 시대의 중요한 차이를

> **많은 경우 새로운 Task를 위해 별도의 Training을 하지 않고 Prompt만으로 Task를 수행할 수 있다.**

는 것으로 설명한다.

```text
기존 방식

새로운 Task
↓
Data 수집
↓
Labeling
↓
Training / Fine-tuning
↓
Task Model
```

에서

```text
Foundation Model

새로운 Task
↓
Prompt 설명
↓
Output
```

으로 바뀐다.

---

# 14. Prompt가 Task Specification이 된다

예를 들어 4행시를 만들어야 한다고 하자.

과거에는

```text
4행시 Dataset 수집
↓
특정 Style Dataset 수집
↓
Training
```

이 필요할 수 있었다.

Foundation Model에서는

```text
"OO으로 4행시를 만들어줘.
이런 스타일로 만들어줘."

+
몇 개의 Example
```

만 제공해도 원하는 Task를 수행하도록 유도할 수 있다.

즉 Prompt가 일종의 **Task Specification** 역할을 한다.

---

# 15. Foundation Model을 사용하는 방식도 달라진다

기존 Machine Learning에서는

```text
Data 수집
→ Training
→ Model 변경
```

이 중요했다.

Foundation Model에서는 이미 Training된 Model을 사용하는 상황이라면

```text
Prompt 작성
      ↓
Output 관찰
      ↓
부족함 발견
      ↓
Prompt 수정
      ↓
다시 Output 확인
```

처럼 **Prompt Optimization**이 중요한 작업이 된다.

---

# 16. 같은 LLM도 왜 답이 다른가?

강의에서는 ChatGPT, Gemini 등 비슷한 Foundation Model도 서로 다른 결과를 내는 이유를 높은 수준에서 다음 세 요소로 설명한다.

```text
Training Data가 다름

Model Architecture가 다름

Inference 방식이 다름
```

따라서 같은 범주의 LLM이라고 해도 실제 동작과 Output은 다를 수 있다.

---

# 17. Foundation Model의 세 핵심 구성 요소

이번 강의의 가장 중요한 구조 중 하나다.

강의에서는 Foundation Model 발전을 가능하게 한 세 요소를 다음과 같이 정리한다.

```text
1. Big Data

2. Self-supervised Learning

3. Transformer
```

이 세 가지가 서로 연결되어 Foundation Model을 만든다.

---

# 18. 첫 번째 요소 — Big Data

Internet과 Storage Technology가 발전하면서 Data가 빠르게 쌓이기 시작했다.

과거에는

```text
Paper
Local Document
개별 Storage
```

등에 흩어져 있던 Data가 Internet을 통해

```text
Digital Data
```

로 저장되고 공유되기 시작한다.

결과적으로 인간이 사용할 수 있는 Data의 규모가 급격하게 증가한다.

---

# 19. Big Data와 Deep Learning의 결합

Deep Learning 연구에서 중요한 관찰이 나타난다.

> **Training Data를 더 많이 사용하면 Model Performance도 계속 좋아지는 경향이 있다.**

즉

```text
Data ↑
→ Performance ↑
```

라는 관계가 관찰된다.

---

# 20. 그런데 Data가 많다고 바로 Training할 수 있는 것은 아니다

Internet에 Text가 아무리 많이 있어도 기존 Supervised Learning 방식이라면 사람이 Label을 붙여야 한다.

예를 들어

```text
Dog Image
→ Human: "Dog"

Cat Image
→ Human: "Cat"
```

처럼 Ground Truth를 사람이 만든다.

Data가 수십억 개라면 이 Labeling 과정 자체가 불가능에 가까워진다.

---

# 21. Human Labeling이 Bottleneck이 된다

```text
Internet Data 생성 속도
>>>>>>>>>
Human Labeling 속도
```

이기 때문에

```text
Raw Data는 많음

하지만
Supervised Training Data는 부족
```

한 문제가 발생한다.

즉 **사람의 Labeling이 Bottleneck**이 된다.

---

# 22. 두 번째 요소 — Self-supervised Learning

이 문제를 해결하기 위해

> **사람이 정답을 만들지 않아도 Raw Data 자체에서 Training Signal을 만들자.**

라는 아이디어가 등장한다.

이것이 **Self-supervised Learning**이다.

핵심은

```text
Raw Data
      ↓
Data 자체에서 Target 생성
      ↓
Training
```

이다.

---

# 23. Text Foundation Model의 대표 Self-supervised Task

강의에서는 Text Foundation Model에서 가장 대표적인 방법을

> **Next-token Prediction**

이라고 설명한다.

즉

```text
Previous Tokens
      ↓
다음 Token을 예측
```

한다.

---

# 24. Next-token Prediction 예

원래 Data:

```text
아까 밥 먹고 왔어
```

가 있다고 하자.

Training Problem을

```text
Input:
아까 밥 먹고

Target:
왔어
```

로 자동으로 만들 수 있다.

사람이 별도로

```text
정답은 "왔어"
```

라고 Labeling할 필요가 없다.

원래 Data에 이미 정답이 존재한다.

---

# 25. Model은 Probability Distribution을 출력한다

Input:

```text
아까 밥 먹고
```

를 주면 Model은

```text
왔어       0.20
왔거든     0.10
왔는데     0.08
왔군       0.05
...
```

처럼 가능한 다음 Token들에 대한 Probability Distribution을 예측한다.

---

# 26. Cross Entropy를 통해 정답 Probability를 높인다

Training Data의 실제 다음 Token이

```text
왔어
```

라면 Model이 `왔어`에 높은 Probability를 주도록 Loss를 계산한다.

강의에서는 이를 **Cross Entropy Loss**와 연결한다.

```text
Next-token Distribution
      ↓
Actual Next Token
      ↓
Cross Entropy
      ↓
Parameter Update
```

---

# 27. “왔거든도 맞는 말인데 왜 왔어만 정답인가?”

하나의 Sample만 보면 이런 의문이 생긴다.

```text
아까 밥 먹고 왔어

아까 밥 먹고 왔거든

아까 밥 먹고 왔는데
```

모두 자연스러울 수 있다.

하지만 핵심은 하나의 Sentence가 아니라 **엄청나게 많은 Text에서 이 Training을 반복한다는 것**이다.

---

# 28. 대규모 Data에서 Language Distribution을 학습한다

수많은 문장을 Training하면 다양한 표현이 모두 등장한다.

따라서 Model은 전체적으로

```text
어떤 Context에서
어떤 Token이 얼마나 자주 등장하는가
```

라는 Language Pattern을 학습하게 된다.

즉 Model이 특정 문장 하나를 절대적 진리로 배우는 것이 아니라 방대한 Corpus에서 반복적으로 관측되는 Pattern을 학습한다는 것이 강의의 직관이다.

---

# 29. LLM의 기본 학습 목표

가장 단순하게 말하면

> **다음 Token을 잘 맞히도록 학습한다.**

이다.

굉장히 단순해 보이지만 대규모 Data와 대규모 Model을 결합하면 이 Objective에서 매우 다양한 능력이 발생한다는 것이 이후 강의의 핵심 흐름이다.

---

# 30. Self-supervised Learning은 Next-token만 있는 것은 아니다

강의에서는 다른 예도 연결한다.

### Masked Token Prediction

BERT에서 배운

```text
I [MASK] you
→ love
```

### Denoising

손상된 Input에서 Original Data를 복원.

### Diffusion

Noise에서 Data를 복원하는 방향의 학습.

즉 핵심은

> **Data 자체에서 Training Signal을 만들어낼 수 있다.**

는 것이다.

---

# 31. Training과 Decoding은 다르다

Training이 끝난 LLM은 다음 Token에 대한 **Probability Distribution**을 출력한다.

그러나 실제 Output을 만들려면

> 이 Probability Distribution에서 구체적으로 어떤 Token을 선택할 것인가?

라는 문제가 남는다.

이 과정을 강의에서는 **Decoding**이라고 한다.

```text
Model
↓
Probability Distribution
↓
Decoding
↓
실제 Token
```

Decoding은 이후 추론 강의에서 다시 다룬다.

---

# 32. 세 번째 요소 — Transformer

Big Data를 확보하고 Self-supervised Learning Algorithm까지 만들었다.

이제 필요한 것은

> **그 많은 Data에서 실제로 Pattern을 학습할 수 있을 만큼 강력한 Model Architecture**

다.

강의에서는 이 역할을 Transformer가 수행했다고 설명한다.

---

# 33. Attention

Attention은 Input 중

> **현재 계산에 중요한 부분에 Model이 더 집중할 수 있게 하는 Mechanism**

이다.

Transformer는 Attention을 기반으로 한 Neural Network Architecture다.

---

# 34. 왜 Transformer가 Foundation Model에 중요했는가?

Foundation Model이 성립하려면

```text
Huge Data
+
Scalable Training Objective
+
Huge Data를 소화할 Model
```

이 모두 필요하다.

Transformer는 대규모 Data와 Self-supervised Learning을 이용해 Model Scale을 크게 확장할 수 있는 Architecture로 자리 잡았다.

---

# 35. Foundation Model의 세 요소 다시 정리

```text
[Big Data]

Internet에
엄청난 Raw Data 축적
        ↓

[Self-supervised Learning]

Human Label 없이
그 Data 자체로 학습 가능
        ↓

[Transformer]

그 방대한 Data를
대규모 Model로 학습
        ↓

Foundation Model
```

이 세 개를 하나로 묶어서 기억해야 한다.

---

# 36. 그런데 BERT도 이 세 조건을 만족하지 않는가?

중요한 질문이다.

BERT도

```text
Big Data
+
Self-supervised MLM
+
Transformer
```

를 사용한다.

그렇다면 BERT와 오늘날 우리가 이야기하는 LLM/Foundation Model은 무엇이 다른가?

강의는 이 질문에서 **Scaling**으로 넘어간다.

---

# 37. BERT와 GPT-1

강의에서는 비슷한 시기 등장한 Model을 비교한다.

### BERT

```text
Transformer Encoder
Bidirectional
Masked Token Prediction
```

### GPT-1

```text
Transformer Decoder
Unidirectional / Causal
Next-token Prediction
```

두 Model은 Architecture와 Objective의 차이가 있었지만 모두 Pre-trained Language Model의 흐름에 속한다.

---

# 38. GPT-1 역시 Fine-tuning이 필요했다

GPT-1이 Decoder 구조라고 해서 처음부터 현재의 ChatGPT처럼 Prompt만으로 모든 Task를 잘 수행한 것은 아니다.

Pre-training 후 Target Task에 맞게 Fine-tuning하는 방식이 사용됐다.

즉

```text
GPT-1
= Decoder-only

하지만
Foundation Model 시대의
Prompt-only Task Adaptation은 아직 제한적
```

이었다.

---

# 39. GPT-2에서 중요한 실험

GPT-2에서는 기본적인 학습 방향을 크게 바꾸기보다 **Scale을 키운다.**

강의에서는

```text
Model Size ↑

Training Data ↑
```

를 크게 증가시킨 것이 핵심이라고 설명한다.

---

# 40. Scale을 키우자 새로운 현상이 보이기 시작했다

Model을 키우자 단순히 Language Modeling 성능만 좋아진 것이 아니다.

추가 Fine-tuning 없이도 Prompt만 보고 어느 정도 새로운 Task를 수행하는 모습이 나타나기 시작한다.

```text
Prompt
      ↓
"이게 어떤 Task인지"
어느 정도 파악
      ↓
Task 수행
```

이전 Model에서는 뚜렷하지 않았던 능력이다.

---

# 41. GPT-2의 의미

강의에서는 GPT-2 연구를

> **Language Model이 Unsupervised Multitask Learner처럼 동작하기 시작할 가능성을 보여준 단계**

로 설명한다.

즉 아직 오늘날 수준으로 잘하는 것은 아니지만

```text
Scale ↑
→ 새로운 Task Adaptation 가능성
```

이 관찰되기 시작했다.

---

# 42. Perplexity

강의에서는 Language Modeling Performance를 설명하면서 **Perplexity**를 언급한다.

강의의 핵심 설명:

```text
Perplexity 낮음
→ Language Modeling을 더 잘함
```

으로 이해한다.

즉 다음 Token Prediction의 불확실성이 상대적으로 낮다는 방향이다.

---

# 43. Model을 키우면 Training Performance가 좋아지는 것은 당연해 보인다

더 큰 Model은 더 많은 Parameter를 가지고 있다.

따라서 Training Data를 표현할 Capacity가 높아져 Training Performance가 좋아지는 것은 예상할 수 있다.

하지만 중요한 관찰은 **Test Performance도 계속 좋아졌다는 것**이었다.

---

# 44. 대규모 Data에 비해 Model이 여전히 작을 수 있다

일반적인 Machine Learning에서는 Model을 지나치게 크게 만들면

```text
Overfitting
```

을 우려한다.

그러나 강의에서는 당시의 대규모 Language Modeling Experiment 결과를 보며

> 가지고 있는 방대한 Data를 충분히 소화하기에는 오히려 Model Capacity가 부족할 수 있다.

는 관점을 설명한다.

즉 더 큰 Model을 실험할 동기가 생긴다.

---

# 45. 하지만 큰 Model Experiment는 매우 비싸다

Model Size를 증가시키면 Training Cost 역시 크게 증가한다.

대규모 Transformer Training은

- GPU
    
- Time
    
- Electricity
    
- Infrastructure
    

등 막대한 Resource를 요구한다.

따라서

> **“Model을 10배 키우면 성능이 얼마나 좋아질까?”**

를 매번 실제 Full-scale Experiment로 확인하기 어렵다.

---

# 46. Scaling Law

이 문제에서 **Scaling Law**가 등장한다.

핵심 아이디어는

```text
작은 Scale의 여러 Experiment 수행
        ↓
Performance Trend 측정
        ↓
Trend Line Fitting
        ↓
아직 해보지 않은
더 큰 Experiment의 Performance 예측
```

이다.

---

# 47. Scaling Law가 적용되는 축

강의에서는 다음 요소들을 증가시켰을 때 Performance 변화를 예측하는 방향으로 설명한다.

```text
Model Size

Data Size

Compute
```

즉 큰 Experiment를 실제로 수행하기 전에 작은 Experiment들의 추세를 이용해 결과를 예측한다.

---

# 48. Scaling Law의 실질적인 의미

예를 들어

```text
100배의 Training Cost
```

가 필요한 Experiment를 바로 수행하기 전에

> 그 돈을 썼을 때 Performance Improvement가 어느 정도일지를 작은 Experiment에서 예측할 수 있다.

따라서 대규모 AI 개발에서 투자 의사결정의 Risk를 줄이는 데 중요한 역할을 한다는 강의의 설명이다.

---

# 49. Scaling Law의 더 중요한 결과

Scaling Law 자체는 기본적으로 Language Model의 다음 Token Prediction Performance가 Scale에 따라 어떻게 좋아질지를 설명한다.

그런데 Model을 계속 키우면서 예상하지 못했던 현상이 나타난다.

바로 **Emergent Capability(창발성)** 이다.

---

# 50. Emergent Capability

강의에서는 Model Scale이 증가하면서 어떤 능력이 단순히 조금씩 개선되는 것이 아니라

> **어떤 Scale 부근에서 이전에는 뚜렷하지 않았던 Capability가 강하게 나타나는 현상**

을 창발성으로 설명한다.

```text
Model Size
   ↑

Capability
거의 없음
   ↓
어느 Scale 이상
   ↓
갑자기 크게 향상
```

---

# 51. 대표적인 창발성 — In-context Learning

가장 대표적인 예로 **In-context Learning**을 설명한다.

Model Parameter를 다시 Training하지 않고

```text
Task Description
+
Examples
+
새로운 Input
```

을 Context로 제공하면 Model이 해당 Pattern을 파악해 Task를 수행한다.

---

# 52. Fine-tuning과 In-context Learning 비교

## 과거

영어 → 한국어 번역 Model을 만들고 싶다.

```text
영어-한국어 Pair
수십만~수백만 개
      ↓
Training / Fine-tuning
```

## In-context Learning

```text
"영어를 한국어로 번역해"

Example 1
Example 2
Example 3

새 문장
      ↓
Model Output
```

Parameter Update 없이 수행한다.

---

# 53. Few-shot Prompting

Prompt 안에 몇 개의 Example을 제공하면 **Few-shot** 방식으로 Task를 알려줄 수 있다.

```text
Example 1

Example 2

Example 3

Target Input
```

Model은 Example Pattern을 보고 무엇을 해야 하는지 추론한다.

---

# 54. 작은 Model에서는 Example을 줘도 효과가 적을 수 있다

강의에서는 Model Scale에 따라 In-context Learning 성능을 비교하는 예를 설명한다.

작은 Model에서는

```text
Example 수 ↑
```

를 해도 Task를 제대로 파악하지 못해 Performance가 크게 오르지 않는다.

---

# 55. 더 큰 Model에서는 Example을 활용하기 시작한다

Scale이 증가하면

```text
Examples
      ↓
Task Pattern 파악
      ↓
Performance 향상
```

이 가능해진다.

그리고 매우 큰 Model에서 이런 능력이 크게 증가하는 현상을 창발성과 연결한다.

---

# 56. Reasoning도 창발성의 예

강의에서는 **Reasoning Capability** 역시 LLM Scale 증가와 연결되는 대표적인 Capability로 소개한다.

즉 단순히 문장을 유창하게 만드는 능력을 넘어

```text
Problem
↓
Information Interpretation
↓
Reasoning
↓
Answer
```

같은 복잡한 행동이 나타나는 것이 Foundation Model의 중요한 특징이라고 본다.

---

# 57. 그렇다면 LLM은 정확히 어디부터 LLM인가?

절대적인 기준은 없다.

강의에서도 시대에 따라 기준이 달라질 수 있다고 명시한다.

다만 강의의 대략적인 설명은

```text
Billion-scale Parameters

Trillion-scale Training Data

+
Emergent Capabilities
```

를 가진 Language Model이다.

---

# 58. 단순히 Parameter 개수만으로 정의하기 어렵다

예전에는 7B Model도 매우 큰 LLM으로 인식될 수 있었다.

시간이 지나면서 더 작고 효율적인 Model들도 다양한 Capability를 가지기 시작한다.

따라서

```text
"몇 B 이상이면 무조건 LLM"
```

이라는 고정된 수치보다는

> **Scale + Data + Capability**

를 함께 보는 것이 강의의 관점이다.

---

# 59. Foundation Model과 LLM 관계

```text
Foundation Model
        ↓
여러 Modality 가능
        ↓
Text에 특화
        ↓
Text Foundation Model
        ↓
매우 큰 Language Model
        ↓
LLM
```

이라고 큰 범주를 생각할 수 있다.

---

# 60. LLM의 두 큰 종류

강의에서는 실제 활용 관점에서 LLM을 크게

```text
Closed LLM

Open LLM
```

으로 나누어 설명한다.

---

# 61. Closed LLM

대표적인 강의 예:

- ChatGPT 계열
    
- Claude 계열
    
- Gemini 계열
    

이러한 Model은 내부 Weight나 Architecture 등이 전부 공개되지 않는 형태다.

---

# 62. Closed Model을 사용하는 방식

보통 두 가지 방식이 있다.

### 1. 직접 서비스 사용

```text
Web
Desktop App
Mobile App
```

### 2. API

Developer가 Code에서

```text
Prompt
↓
API
↓
Model
↓
Response
```

형태로 사용할 수 있다.

---

# 63. Closed LLM의 장점 ① Performance

강의에서는 일반적인 경향으로 Closed Model이

- Performance
    
- 기능
    

측면에서 강한 경우가 많다고 설명한다.

상업적 Product로 지속적으로 개발되고 있기 때문에 높은 수준의 Model과 Infrastructure를 직접 사용할 수 있다는 장점이 있다.

---

# 64. Closed LLM의 장점 ② Usability

상업적 Service이므로

- UI
    
- API
    
- Infrastructure
    
- 사용 편의성
    

등이 잘 구축되어 있다.

따라서 사용자가 복잡한 Deployment 없이 바로 활용할 수 있다.

---

# 65. Closed LLM의 단점 ① Cost

Service에 따라

```text
Subscription

또는

API Query / Token Cost
```

가 발생할 수 있다.

즉 많이 사용할수록 비용이 커질 수 있다.

---

# 66. Closed LLM의 단점 ② 내부 정보 부족

Closed Model에서는 일반적으로

- Exact Architecture
    
- Parameter
    
- Training Data
    
- Detailed Inference Pipeline
    

등이 공개되지 않는다.

강의에서는 이 점이 Model의 동작 원인을 분석하거나 Debugging할 때 문제될 수 있다고 설명한다.

---

# 67. 왜 Transparency가 Debugging과 연결되는가?

예를 들어 특정 한국어 표현을 계속 잘못 처리한다고 하자.

Open Model이라면

- Tokenization
    
- Representation
    
- Parameter
    
- Internal Activation
    
- Inference Flow
    

등을 조사할 가능성이 있다.

Closed Model에서는 내부 구조를 볼 수 없기 때문에

> **왜 그런 Error가 발생하는지 깊이 분석하기 어려울 수 있다.**

---

# 68. Closed Model별 특징에 대한 강의의 설명

강의에서는 당시 일반적인 인식을 예로 들어

- ChatGPT: 전반적인 성능과 높은 사용량
    
- Claude: Safety와 Coding
    
- Gemini: Multimodal 및 Input/Output 지원
    

등의 특성을 언급한다.

이는 **강의에서 제시한 당시의 상대적 특징**으로 이해해야 한다.

---

# 69. Open LLM

강의에서 언급한 예:

- Llama
    
- Gemma
    
- Qwen
    
- DeepSeek
    
- Mistral
    
- Kimi 계열
    

등이다.

또 국내에서 개발되는 개방형 Foundation Model 사례들도 언급한다.

---

# 70. Open Model의 가장 큰 특징

Model Weight나 Architecture 등 필요한 자원이 공개되어 사용자가 직접 Model을 내려받아 활용할 수 있는 형태다.

다만 실제 가능한 이용 범위는 각각의 **License 조건**에 따라 달라질 수 있다.

---

# 71. Open LLM의 장점 ① 직접 사용할 수 있다

Model을 Download해 자신이 가진 Hardware에서 직접 실행할 수 있다.

```text
External API
```

를 반드시 거칠 필요가 없다.

---

# 72. Open LLM의 장점 ② Customize 가능

License가 허용한다면

```text
Open Model
      ↓
Additional Training
      ↓
My Domain Model
```

처럼 자신만의 Model로 추가 Training하거나 수정할 수 있다.

---

# 73. Open LLM의 장점 ③ Transparency

Architecture와 Source Code 등이 공개되어 있다면

```text
Input
↓
Processing
↓
Model
↓
Output
```

의 흐름을 직접 조사할 수 있다.

---

# 74. Privacy 측면의 활용

Model을 자신이 관리하는 Environment에서 직접 실행한다면 Query를 외부 Model Provider로 보내지 않고 처리할 수 있는 Deployment를 구성할 수 있다.

강의에서는 이 점을 Open Model을 활용할 때의 중요한 장점 중 하나로 설명한다.

---

# 75. Interpretability / Debugging

Model Weight를 직접 볼 수 있기 때문에 Research 관점에서

```text
어떤 Parameter
어떤 Layer
어떤 Representation
```

이 특정 Behavior에 영향을 주는지를 분석할 수 있다.

강의에서는 사람의 Brain을 들여다보듯 Model의 내부를 분석하는 연구의 가능성과 연결한다.

---

# 76. Open LLM의 가장 큰 단점 — Compute

Model File이 무료라고 해도

> **실행 비용까지 무료인 것은 아니다.**

좋은 LLM을 직접 구동하려면 매우 큰 GPU Memory와 Compute가 필요할 수 있다.

강의에서는 일반적인 Consumer GPU 하나만으로 대형 Open LLM을 원활하게 사용하기 어려울 수 있다고 설명한다.

---

# 77. Model을 가볍게 만드는 방법

강의에서는 Compute 문제를 완화하기 위한 예로

- Pruning
    
- Quantization
    
- CPU용 Conversion
    

등을 언급한다.

하지만 이러한 Technique을 사용하더라도 일정 수준 이상의 Compute Resource가 필요할 수 있다.

---

# 78. Open LLM의 또 다른 단점 — Performance Gap

강의에서는 일반적인 경향으로 최상위 Closed Model과 Open Model 사이에 Performance 차이가 존재할 수 있다고 설명한다.

다만 최근 Open Model들이 발전하면서 이러한 Gap이 크게 줄어드는 사례들도 언급한다.

---

# 79. 무조건 가장 강력한 Model이 필요한 것은 아니다

중요한 실무 관점이다.

Task가 매우 어려운 Reasoning을 요구하지 않는다면

```text
작은 Open Model
```

만으로도 충분할 수 있다.

반대로 복잡한 Reasoning이나 높은 Quality가 필요하다면 강력한 Closed Model을 쓰는 것이 유리할 수 있다.

---

# 80. Model 선택은 Task 요구사항에 따라 달라진다

즉 단순하게

```text
Closed = 좋음
Open = 나쁨
```

또는 그 반대로 볼 수 없다.

다음 요소를 고려해야 한다.

```text
Required Intelligence

Cost

Latency

Privacy

Customization

Hardware

Transparency

Maintenance
```

강의의 결론도 **풀고 싶은 Task가 어느 정도의 능력을 요구하는지를 먼저 판단해야 한다**는 것이다.

---

# 81. Closed vs Open 비교

|항목|Closed LLM|Open LLM|
|---|---|---|
|대표 이용|Web/App/API|직접 Download/Deploy|
|내부 구조|대체로 비공개|상대적으로 공개|
|Model Weight|접근 어려움|공개되는 경우 많음|
|사용 편의성|높음|직접 구축 필요|
|최고 성능|강한 경우 많음|모델에 따라 차이|
|사용 비용|Subscription/API 비용|Model은 무료 가능하지만 Compute 필요|
|Hardware|Provider가 관리|사용자가 준비|
|Customization|제한적|License 내에서 가능|
|Debugging|어려움|상대적으로 가능|
|Privacy 통제|Provider 환경 의존|Local Deployment 가능|
|유지보수|Provider 담당|사용자 담당|

---

# 82. 기존 AI와 Foundation Model의 가장 큰 차이

전체 발전 과정을 다시 보면 다음과 같다.

### Classical ML

```text
Task
↓
Feature Engineering
↓
Model Training
```

### Deep Learning

```text
Task
↓
Large Dataset
↓
Feature도 Model이 학습
```

### Pre-trained Model

```text
General Pre-training
↓
Task-specific Fine-tuning
```

### Foundation Model

```text
Huge General Pre-training
↓
Prompt / Examples
↓
새로운 Task 수행
```

---

# 83. Foundation Model에서 “학습”의 위치가 바뀐다

과거에는 새로운 Task가 생기면 User/Developer가 Model을 새로 Training해야 했다.

Foundation Model에서는 엄청난 Training을 Model Provider가 **한 번 앞단에서 수행**한다.

```text
[Provider]

Huge Data
+
Huge Compute
↓
Foundation Model


[User]

Prompt
↓
Task 수행
```

즉 Task별 Training 비용을 사용자 쪽에서 크게 줄이는 구조라고 볼 수 있다.

---

# 84. Foundation Model이 가능한 원리의 연결

```text
Internet
      ↓
Big Data 축적
      ↓
Human Labeling으로
전부 처리 불가능
      ↓
Self-supervised Learning
      ↓
Data 자체에서
Training Signal 생성
      ↓
엄청난 Data를
학습할 Model 필요
      ↓
Transformer
      ↓
Model/Data/Compute Scale 증가
      ↓
Performance 증가
      ↓
Scaling Law
      ↓
더 큰 Scale 실험
      ↓
In-context Learning 등
Emergent Capability
      ↓
Fine-tuning 없이
Prompt로 여러 Task 수행
      ↓
Foundation Model 시대
```

---

# 85. BERT와 현대 LLM의 차이를 구조적으로 이해하기

BERT도

```text
Big Data
+
Self-supervised Learning
+
Transformer
```

를 가지고 있었다.

따라서 Foundation Model의 기반 아이디어는 이미 존재했다.

강의가 이후 GPT 발전에서 강조하는 변화는

> **Scale을 더욱 크게 확장하면서 Prompt만으로 Task를 수행하는 Capability가 강하게 나타났다는 것**

이다.

---

# 86. “Decoder라서 LLM이 됐다”로만 이해하면 부족하다

강의는 BERT와 GPT-1의 차이를 소개하지만 핵심 발전을 단순히

```text
Encoder → Decoder
```

로만 설명하지 않는다.

GPT-1도 처음에는 Fine-tuning이 필요했다.

GPT-2 이후 중요한 관찰은

```text
Model Scale ↑
+
Data Scale ↑
```

에 따라 Fine-tuning 없이도 Prompt를 활용하는 능력이 나타나기 시작했다는 것이다.

---

# 87. Scaling과 Foundation Model의 핵심 관계

```text
더 큰 Model
+
더 많은 Data
+
더 많은 Compute
      ↓
Language Modeling Performance 향상
      ↓
예상하지 못한 Capability도 나타남
      ↓
General-purpose Model
```

이라는 연결이 Foundation Model의 핵심 발전 과정이다.

---

# 88. Scaling Law와 Emergence는 같은 개념이 아니다

구분해야 한다.

### Scaling Law

```text
Scale 증가
→ 성능 변화의 추세를 예측
```

### Emergent Capability

```text
Scale 증가 중
이전에는 뚜렷하지 않았던
새로운 능력이 나타나는 현상
```

이다.

---

# 89. In-context Learning과 Fine-tuning도 구분

### Fine-tuning

```text
Task Data
↓
Backpropagation
↓
Parameter 변경
```

### In-context Learning

```text
Prompt
+
Examples
↓
현재 Context에서 Pattern 파악
↓
Parameter 변경 없음
```

이다.

---

# 90. Prompting이 중요한 이유

Foundation Model의 핵심 Capability 중 하나가

```text
Prompt
→ Task Specification
```

이기 때문이다.

따라서 User가 원하는 Task를 정확하게 설명하고 필요한 Example과 Context를 제공하는 것이 Output Quality에 직접적인 영향을 줄 수 있다.

---

# 91. Next-token Prediction과 실제 Chatbot Response의 연결

Training:

```text
Context
→ Next Token Probability
```

Inference:

```text
Prompt
      ↓
Next Token Probability
      ↓
Token 선택
      ↓
새 Token을 Context에 추가
      ↓
다음 Token Probability
      ↓
반복
```

결국 긴 ChatGPT Response도 기본적으로 이 과정을 반복해서 생성할 수 있다.

---

# 92. 아직 해결되지 않은 문제 — 어떤 Token을 선택할 것인가?

Model은

```text
A 30%
B 20%
C 10%
...
```

라는 Distribution을 만들 뿐이다.

실제로

```text
A를 선택할지
B를 선택할지
```

는 별도의 **Decoding / Inference Strategy**가 결정한다.

그래서 같은 Model이라도 Inference 방식이 달라지면 Output이 달라질 수 있다.

이는 이후 차시로 이어진다.

# 94. 자주 헷갈리는 점 ① — Foundation Model = ChatGPT인가?

아니다.

ChatGPT는 Foundation Model을 기반으로 만든 대표적인 Service/Model 계열의 예다.

Foundation Model은 더 넓은 개념이다.

---

# 95. 자주 헷갈리는 점 ② — Foundation Model은 Text Model인가?

아니다.

Text뿐 아니라

- Image
    
- Video
    
- Audio
    
- Multimodal
    

Foundation Model도 존재한다.

---

# 96. 자주 헷갈리는 점 ③ — Big Data만 많으면 Foundation Model이 되는가?

강의에서는 세 요소가 함께 필요하다고 본다.

```text
Big Data
+
Self-supervised Learning
+
Transformer
```

이다.

---

# 97. 자주 헷갈리는 점 ④ — Self-supervised는 정답이 없는 학습인가?

정확히는 **사람이 별도로 Label을 붙이지 않는다.**

Data 자체에서 Target을 만들어낸다.

예:

```text
아까 밥 먹고 왔어
```

에서

```text
Input = 아까 밥 먹고
Target = 왔어
```

를 자동으로 만들 수 있다.

---

# 98. 자주 헷갈리는 점 ⑤ — Next-token Prediction에서는 정답 하나만 무조건 맞는가?

한 Sample의 Ground Truth Token은 하나지만, 매우 많은 Data에서 다양한 표현을 반복적으로 학습한다.

따라서 전체적으로 Language의 Statistical Pattern을 학습한다는 것이 강의의 설명이다.

---

# 99. 자주 헷갈리는 점 ⑥ — Training에서 Token을 예측하는 것과 실제 생성은 같은가?

관련은 있지만 구분한다.

```text
Training
→ Probability를 잘 예측하도록 학습

Decoding
→ 그 Probability에서 실제 Token 선택
```

이다.

---

# 100. 자주 헷갈리는 점 ⑦ — BERT는 Foundation Model이 아닌가?

강의에서는 BERT도 Foundation Model의 핵심 세 요소를 이미 갖고 있었다는 점을 강조한다.

다만 현대 LLM에서 기대하는 Prompt 기반 범용 Capability가 Scale 증가와 함께 훨씬 강하게 나타났다는 발전 과정을 구분한다.

---

# 101. 자주 헷갈리는 점 ⑧ — GPT가 강한 이유는 Decoder이기 때문인가?

Decoder Architecture도 중요하지만 이번 강의의 중심 설명은 **Scaling**이다.

GPT-1도 Decoder-only였지만 Task별 Fine-tuning이 필요했다.

GPT-2 이후 Scale 증가와 함께 In-context 능력이 관찰되기 시작한다.

---

# 102. 자주 헷갈리는 점 ⑨ — Scaling Law = 무조건 크게 만들면 된다?

강의의 Scaling Law는

> 작은 Experiment들의 추세로 큰 Experiment의 성능을 예측하는 법칙

이라는 의미가 핵심이다.

실제 Model Scaling에는 막대한 Compute Cost가 따른다.

---

# 103. 자주 헷갈리는 점 ⑩ — Emergence와 Scaling Law는 동일한가?

아니다.

Scaling Law는 Performance Trend와 관련되고,

Emergence는 Scale 증가 과정에서 새로운 Capability가 나타나는 현상이다.

---

# 104. 자주 헷갈리는 점 ⑪ — In-context Learning은 Training인가?

Model Parameter를 Update하는 의미의 Training은 아니다.

Prompt와 Example을 현재 Context로 주고 그 Pattern을 활용한다.

---

# 105. 자주 헷갈리는 점 ⑫ — Open Model은 완전히 무료인가?

Model을 Download하는 비용 자체는 없을 수 있지만

```text
GPU
Server
Electricity
Deployment
Maintenance
```

비용이 필요하다.

특히 대형 Model은 상당한 Compute Resource를 요구한다.

---

# 106. 자주 헷갈리는 점 ⑬ — Closed Model은 항상 더 좋은가?

아니다.

Task가 단순하거나

- Privacy
    
- Customization
    
- Local Deployment
    
- Transparency
    

가 중요하다면 Open Model이 더 적합할 수 있다.

반대로 최고 수준의 Performance와 사용 편의성이 필요하면 Closed Model이 유리할 수 있다.

# 109. 이번 강의에서 반드시 기억할 핵심

### 1. Foundation Model은 대량의 Data를 기반으로 사전학습된 대규모 범용 AI Model이다.

### 2. Text Foundation Model은 Text를 중심으로 하는 Foundation Model이다.

### 3. Foundation Model은 Text 외에도 Image, Video, Audio 등으로 확장된다.

### 4. 여러 Modality를 처리하는 Model을 Multimodal Model이라고 한다.

### 5. 기존 AI는 새로운 Task마다 별도 Training이 필요했다.

### 6. Foundation Model에서는 많은 Task를 Prompt만으로 수행할 수 있다.

### 7. Foundation Model의 핵심 세 구성 요소는 Big Data, Self-supervised Learning, Transformer다.

### 8. Big Data는 Internet과 Storage 발전을 통해 축적됐다.

### 9. 기존 Supervised Learning은 Human Labeling이 Data Scale의 Bottleneck이었다.

### 10. Self-supervised Learning은 Raw Data 자체에서 Training Signal을 만든다.

### 11. Text Foundation Model의 대표적인 Self-supervised Objective는 Next-token Prediction이다.

### 12. Next-token Prediction에서는 Context를 보고 다음 Token Probability Distribution을 예측한다.

### 13. 실제 Target Token에 높은 Probability를 주도록 Cross Entropy를 이용해 학습한다.

### 14. 매우 많은 Data에서 이를 반복하여 Language Pattern을 학습한다.

### 15. Prediction Distribution에서 실제 Token을 선택하는 과정은 Decoding이다.

### 16. Transformer는 대규모 Data와 Self-supervised Learning을 효과적으로 활용할 수 있는 핵심 Architecture다.

### 17. BERT 역시 Big Data + Self-supervised Learning + Transformer라는 기반 요소를 가지고 있었다.

### 18. 현대 LLM의 중요한 발전 요인은 Model/Data/Compute의 Scaling이다.

### 19. GPT-1은 Decoder-only였지만 여전히 Task별 Fine-tuning이 필요했다.

### 20. GPT-2에서 Scale을 크게 증가시키면서 Fine-tuning 없이 Prompt로 Task를 일부 수행하는 능력이 관찰되기 시작했다.

### 21. Scaling Law는 작은 Experiment를 기반으로 더 큰 Scale에서의 Performance를 예측하는 개념이다.

### 22. Scaling Law는 Model Size, Data Size, Compute와 연결된다.

### 23. Model Scale이 증가하면서 이전에는 뚜렷하지 않았던 Capability가 나타나는 현상을 강의에서는 Emergence라고 설명한다.

### 24. 대표적인 Emergent Capability가 In-context Learning이다.

### 25. In-context Learning은 Parameter를 Update하지 않고 Prompt의 설명과 Example을 이용해 Task를 수행한다.

### 26. Reasoning Capability 역시 강의에서 중요한 창발성의 예로 소개된다.

### 27. 강의에서는 LLM을 대략 Billion-scale Model, Trillion-scale Data, Emergent Capability 관점에서 설명하지만 기준은 시대에 따라 변할 수 있다고 강조한다.

### 28. LLM은 Closed Model과 Open Model로 크게 구분할 수 있다.

### 29. Closed Model은 사용 편의성과 높은 Performance가 장점이지만 비용과 내부 구조의 불투명성이 단점이 될 수 있다.

### 30. Open Model은 Download, Customization, Transparency, Local Deployment가 장점이다.

### 31. Open Model은 직접 실행하기 위한 큰 Compute Resource가 필요할 수 있다.

### 32. Closed/Open 중 어떤 Model이 좋은지는 Task의 요구 성능, Cost, Privacy, Hardware, Transparency 등에 따라 달라진다.

# 110. 이번 강의 핵심 한 문장

> **텍스트 파운데이션 모델은 인터넷에 축적된 방대한 Text를 사람의 별도 Label 없이 Next-token Prediction과 같은 Self-supervised Objective로 학습하고, 이를 대규모로 소화할 수 있는 Transformer Architecture의 Model·Data·Compute Scale을 지속적으로 확장함으로써 In-context Learning과 Reasoning 같은 범용 Capability를 획득하여 새로운 Task를 별도 Fine-tuning보다 Prompt 중심으로 수행할 수 있게 된 대규모 Language Model이다.**

가장 짧게 기억하면 다음과 같다.

```text
Big Data
+
Self-supervised Learning
+
Transformer
        ↓
Scale Up
        ↓
Better Language Model
        ↓
Emergent Capability
        ↓
In-context Learning
        ↓
Prompt 하나로
여러 Task 수행
        ↓
Text Foundation Model / LLM
```

그리고 활용 관점에서는

```text
Closed LLM
= 편하고 강력하지만
  비용·불투명성 존재

Open LLM
= 직접 통제·수정 가능하지만
  Compute와 운영 부담 존재
```

로 정리하면 된다.
