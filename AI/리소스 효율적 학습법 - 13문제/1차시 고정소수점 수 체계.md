## 시험 범위에 포함되는 내용

# 0. 이 강의를 왜 배우는가?

머신러닝 Model이 커질수록 Parameter 하나를 어떻게 표현하는지가 매우 중요해진다.

예를 들어 같은 값을

```text
8 bit
```

로 저장할 수도 있고

```text
32 bit
```

로 저장할 수도 있다.

Parameter가 몇 개뿐이라면 차이가 작다.

하지만 Parameter가

```text
수십억 개
수천억 개
조 단위
```

까지 늘어나면 **Parameter 하나당 몇 bit를 사용하느냐**가 전체 Memory와 연산 비용을 크게 바꾼다.

강의의 전체 문제의식은 다음과 같다.

```text
AI Model이 너무 커졌다.
↓
Memory 사용량 ↑
Memory Access ↑
연산량 ↑
Energy ↑
Latency ↑
↓
숫자를 꼭 높은 Precision으로
표현해야 하는가?
↓
더 적은 Bit로 표현할 수 없을까?
↓
Number Representation
↓
Quantization / Model Compression
```

강의에서는 차량용 AI, On-device AI, GPU의 저정밀 연산 지원 등을 이러한 흐름의 산업 사례로 소개한다.

# 2. 수 체계(Number System)란?

수 체계란

> **어떤 Symbol과 어떤 규칙을 이용하여 숫자를 표현할 것인가를 정의한 약속**

이다.

예를 들어 Decimal에서는

```text
0 ~ 9
```

라는 10개의 Symbol을 사용한다.

각 자리의 Weight는

```text
...
10³
10²
10¹
10⁰
```

처럼 10의 거듭제곱이다.

---

# 3. Binary Number System

컴퓨터에서는 Binary가 자연스럽다.

Binary의 Symbol은

```text
0
1
```

두 개뿐이다.

각 자리의 Weight는

```text
...
2³
2²
2¹
2⁰
```

이다.

---

# 4. 왜 컴퓨터는 Binary를 사용하는가?

전자회로에서는 두 상태를 만들기 쉽다.

예:

```text
전압 높음 / 낮음

전류 흐름 / 흐르지 않음

ON / OFF
```

따라서

```text
0 / 1
```

두 Symbol을 사용하는 Binary Number System이 전자식 Computer Hardware와 잘 맞는다.

---

# 5. Binary → Decimal

예를 들어

```text
1011₂
```

은

```text
1 × 2³
+ 0 × 2²
+ 1 × 2¹
+ 1 × 2⁰
```

이므로

```text
8 + 0 + 2 + 1
= 11
```

이다.

---

# 6. 2의 거듭제곱을 알아두면 좋은 이유

Computer System에서는 Memory와 Bit가 2의 거듭제곱으로 등장한다.

대표적으로

```text
2¹⁰ ≈ 1 thousand

2²⁰ ≈ 1 million

2³⁰ ≈ 1 billion
```

정도로 빠르게 어림할 수 있다.

따라서

```text
2²⁴ ≈ 16 million

2³² ≈ 4 billion
```

정도로 Number Range를 빠르게 추정할 수 있다.

---

# 7. Hexadecimal

Binary는 Computer에게 편하지만 사람이 읽기에는 길다.

예:

```text
1110101011010110...
```

이를 짧게 표현하기 위해 Hexadecimal을 많이 사용한다.

Hexadecimal은

```text
0 ~ 9
A ~ F
```

총 16개의 Symbol을 사용한다.

---

# 8. Binary와 Hexadecimal 관계

```text
16 = 2⁴
```

이므로 Binary 4자리와 Hexadecimal 한 자리가 정확히 대응한다.

```text
Binary 4 bit
↔
Hex 1 digit
```

예:

```text
1111₂
=
F₁₆
```

---

# 9. Bit, Nibble, Byte

기본 단위는 다음과 같다.

```text
1 bit
= Binary 한 자리

4 bit
= 1 nibble

8 bit
= 1 byte
```

따라서

```text
1 nibble
↔ Hexadecimal 1자리

1 byte
↔ Hexadecimal 2자리
```

이다.

---

# 10. LSB와 MSB

Binary Pattern에서 가장 낮은 Weight를 가진 Bit를

**LSB(Least Significant Bit)**

라고 한다.

가장 높은 Weight를 가진 Bit를

**MSB(Most Significant Bit)**

라고 한다.

```text
MSB                 LSB
 ↓                   ↓
1 0 1 1 0 0 1 0
```

문맥에 따라 Bit가 아니라 Byte 단위의 Least/Most Significant Byte를 의미하기도 한다는 점도 강의에서 언급한다.

---

# 11. Number Representation에서 가장 중요한 질문

강의가 반복해서 강조하는 질문은 이것이다.

> **“내가 사용하는 Bit 수로 어느 범위까지 표현할 수 있는가?”**

이것이 Resource Efficiency와 직접 연결된다.

---

# 12. n자리 Decimal의 표현 개수

각 자리에 10개의 선택지가 있다.

따라서 n자리라면 가능한 Pattern은

```text
10ⁿ개
```

이다.

Unsigned로 해석하면

```text
0 ~ 10ⁿ - 1
```

을 표현할 수 있다.

예:

```text
3자리 Decimal

0 ~ 999
```

---

# 13. n-bit Binary의 표현 개수

Binary 한 자리에는

```text
0
1
```

두 가지 선택지가 있다.

n개의 Bit가 있다면 가능한 Pattern은

```text
2 × 2 × ... × 2
= 2ⁿ개
```

이다.

따라서 Unsigned Integer로 해석하면

```text
0 ~ 2ⁿ - 1
```

을 표현한다.

---

# 14. 예: 3-bit Unsigned

가능한 Pattern:

```text
000
001
010
011
100
101
110
111
```

총

```text
2³ = 8개
```

이다.

값은

```text
0 ~ 7
```

이다.

---

# 15. 이것이 Resource Efficiency와 연결되는 이유

어떤 Algorithm에서 실제 값이

```text
0 ~ 7
```

만 나온다고 하자.

이론적으로 3 bit면 충분하다.

그런데 안전하다는 이유로 무조건

```text
32-bit int
```

를 사용하면 훨씬 많은 Memory를 사용한다.

강의에서는 이러한 Number Range와 Bit-width의 관계를 이해하지 못하면 필요 이상으로 큰 자료형을 선택하게 되고, 대규모 ML Model에서는 이 차이가 거대한 Memory 차이가 된다고 강조한다.

---

# 16. AI Model에서는 왜 더 심각한가?

Parameter 하나의 차이가

```text
8 bit
vs
32 bit
```

라면 4배 차이다.

Parameter가 매우 많으면

```text
Parameter 하나 × 4배
↓
전체 Model × 4배
```

가 된다.

따라서

> **실제 필요한 Range와 Precision을 알고 최소한의 Bit를 사용하는 것**

이 중요하다.

---

# 17. Bit-width를 줄이면 얻는 효과

강의에서는 단순 Memory 용량만 보지 않는다.

Bit 수가 줄어들면

```text
저장해야 할 Data ↓

DRAM / Storage Access ↓

Memory Bandwidth 부담 ↓

연산 Hardware 규모 ↓

Energy ↓

Latency ↓
```

까지 연결될 수 있다.

---

# 18. Binary Addition

Binary도 Decimal과 마찬가지로 자리 올림(Carry)이 존재한다.

예:

```text
1 + 1
```

은 Decimal로 2다.

하지만 Binary 한 자리에는 `2`라는 Symbol이 없다.

따라서

```text
1 + 1
=
10₂
```

처럼

```text
현재 자리 = 0
Carry = 1
```

이 된다.

---

# 19. 표현 범위를 넘어가는 경우

고정된 n-bit Hardware에서는 결과가 n bit를 넘을 수 있다.

예를 들어 결과가

```text
1 001
```

처럼 4-bit Hardware 범위를 넘어간다면 Hardware가 정해진 Bit만 취하고 나머지가 버려질 수 있다.

이러한 Range 초과 여부를 알아야 한다.

---

# 20. Carry-out

Unsigned 연산에서는 가장 높은 자리 밖으로 나온 Carry를 이용하여 표현 범위 초과 여부를 판단할 수 있다.

즉

```text
Arithmetic Result
↓
n-bit 범위 초과
↓
Carry-out
```

을 확인한다.

---

# 21. 이제 문제 — 음수는 어떻게 표현할까?

지금까지는

```text
0
1
2
3
...
```

만 다뤘다.

하지만 Computer에서는

```text
-1
-2
-3
...
```

도 표현해야 한다.

대표적인 Signed Number 표현 방식으로 강의에서는

```text
Sign-Magnitude

Complement Representation
```

을 소개한다.

---

# 22. Sign-Magnitude

가장 직관적인 방법이다.

n bit 중

```text
MSB 1개
→ Sign

나머지 n-1 bit
→ Magnitude
```

로 사용한다.

---

# 23. Sign Bit

약속:

```text
0
→ Positive

1
→ Negative
```

이다.

---

# 24. 4-bit Sign-Magnitude 예

+6:

```text
0 110
```

-6:

```text
1 110
```

앞 Bit만 바꾸면 된다.

---

# 25. Sign-Magnitude Range

Magnitude를 표현할 수 있는 Bit가

```text
n - 1개
```

이므로 최대 Magnitude는

```text
2^(n-1) - 1
```

이다.

따라서 Range는

```text
-(2^(n-1)-1)
~
+(2^(n-1)-1)
```

이다.

---

# 26. Sign-Magnitude의 장점

사람에게 매우 직관적이다.

```text
MSB
→ Sign

나머지
→ Absolute Value
```

이므로 Pattern만 보고 부호와 크기를 쉽게 알 수 있다.

---

# 27. 하지만 치명적인 문제 — Arithmetic

Sign-Magnitude Bit Pattern에 일반 Binary Adder를 그대로 사용하면 우리가 원하는 Signed Arithmetic이 나오지 않는다.

예를 들어

```text
-6 + 6
```

은 당연히

```text
0
```

이어야 한다.

하지만 Sign-Magnitude Pattern을 일반 Binary Addition으로 더한다고 해서 자동으로 0이 되지는 않는다.

---

# 28. 결국 별도의 Arithmetic Logic이 필요하다

따라서 Sign-Magnitude를 사용하면

```text
Sign 확인

Magnitude 비교

부호에 따라
덧셈 / 뺄셈 선택
```

같은 추가 Hardware Logic이 필요해진다.

---

# 29. 또 하나의 문제 — 0이 두 개다

Sign-Magnitude에서는

```text
+0
-0
```

두 Pattern이 존재한다.

즉 동일한 값 0에 Pattern 두 개를 소비한다.

강의에서는 이러한 직관성과 연산상의 불편함을 Sign-Magnitude의 핵심 특징으로 설명한다.

---

# 30. 그래서 Two's Complement

오늘날 일반적인 Signed Integer 표현에서는 **2의 보수(Two's Complement)** 를 사용한다.

가장 직관적인 해석법은

> **MSB만 음수 Weight를 주고 나머지는 일반 Binary Weight를 준다.**

는 것이다.

---

# 31. n-bit Two's Complement의 Weight

Bit를

```text
a_(n-1) ... a₂ a₁ a₀
```

라고 하면

최상위 Bit의 Weight:

```text
-2^(n-1)
```

나머지 Weight:

```text
2^(n-2), ..., 2², 2¹, 2⁰
```

이다.

---

# 32. 4-bit 예

```text
Bit:     a3   a2   a1   a0

Weight: -8   +4   +2   +1
```

따라서

```text
1110
```

은

```text
-8 + 4 + 2
= -2
```

다.

---

# 33. Two's Complement에서 Sign

여전히 MSB를 보고 대략 부호를 알 수 있다.

```text
MSB = 0
→ Non-negative

MSB = 1
→ Negative
```

이다.

---

# 34. Two's Complement Range

n-bit Two's Complement는

```text
-2^(n-1)
~
2^(n-1)-1
```

을 표현한다.

예를 들어 4 bit면

```text
-8 ~ +7
```

이다.

---

# 35. 왜 음수 쪽이 하나 더 많은가?

총 Pattern은

```text
2ⁿ개
```

다.

Two's Complement에는 `+0`과 `-0`을 따로 두지 않고

```text
0
```

을 하나만 사용한다.

따라서 4 bit의 16 Pattern은

```text
-8 ~ -1
= 8개

0 ~ +7
= 8개
```

로 배분된다.

---

# 36. Two's Complement의 가장 큰 장점

**Unsigned Binary Addition에서 사용하던 Adder를 그대로 Signed Addition에도 사용할 수 있다.**

즉 별도의 복잡한 Signed Adder를 만들 필요가 줄어든다.

```text
Unsigned Integer
   ↓
같은 Binary Adder

Signed Two's Complement
   ↑
```

이것이 Hardware 관점에서 매우 큰 장점이다.

---

# 37. Two's Complement의 음수 만들기

강의에서는 익숙한 방법도 설명한다.

어떤 n-bit 양수 `x`에서 `-x`를 만들려면

```text
1. 모든 Bit 반전

2. 1을 더함
```

한다.

---

# 38. 예: +3 → -3

4 bit에서

```text
+3
=
0011
```

모든 Bit 반전:

```text
1100
```

1을 더함:

```text
1101
```

따라서

```text
-3
=
1101
```

이다.

---

# 39. 반대로도 동일

`-3`에서 `+3`으로 갈 때도

```text
Bit 반전
+
1
```

을 적용하면 된다.

---

# 40. 같은 Bit Pattern도 “어떻게 해석하느냐”에 따라 값이 달라진다

이 강의에서 매우 중요한 관점이다.

예를 들어

```text
1111
```

이라는 4 bit Pattern 자체에는 사실

```text
15
```

또는

```text
-1
```

이라는 의미가 붙어 있는 것이 아니다.

---

# 41. Unsigned로 해석하면

```text
1111
=
8 + 4 + 2 + 1
=
15
```

---

# 42. Two's Complement로 해석하면

```text
1111
=
-8 + 4 + 2 + 1
=
-1
```

이다.

즉 핵심은

> **Bit Pattern 자체와 우리가 그 Pattern에 부여한 Number Representation 규칙을 구분해야 한다.**

는 것이다.

---

# 43. Number System의 본질

4 bit가 있다면 물리적으로 존재하는 것은

```text
0000
~
1111
```

16개의 Pattern뿐이다.

그 Pattern을

```text
Unsigned

Sign-Magnitude

Two's Complement

Fixed Point
```

중 무엇으로 해석할지는 **약속**이다.

---

# 44. Bit-width Extension

연산할 두 값의 Bit-width가 다를 수도 있다.

예:

```text
A = 8 bit

B = 32 bit
```

두 값을 연산하려면 일반적으로 작은 값을 큰 Bit-width에 맞춰 확장해야 한다.

---

# 45. Zero Extension

가장 단순한 방법:

```text
상위 Bit를 모두 0으로 채움
```

이다.

예:

```text
4 bit:
0011

8 bit:
00000011
```

이다.

---

# 46. Zero Extension의 특징

원래의 `0/1 Pattern` 위치는 그대로 유지된다.

Unsigned Number에서는 값을 보존한다.

---

# 47. Signed Number에 Zero Extension을 하면 문제가 생길 수 있다

4-bit Two's Complement에서

```text
1011
```

은

```text
-5
```

다.

이를 단순 Zero Extension하면

```text
00001011
```

이 된다.

8-bit Two's Complement로 읽으면

```text
+11
```

이다.

값이 바뀌어버렸다.

---

# 48. 그래서 Sign Extension

Signed Two's Complement 값을 확장할 때는 **Sign Bit를 복제한다.**

```text
MSB = 0
→ 0으로 확장

MSB = 1
→ 1로 확장
```

한다.

---

# 49. +3 예

4 bit:

```text
0011
```

Sign Extension:

```text
00000011
```

여전히

```text
+3
```

이다.

---

# 50. -5 예

4 bit:

```text
1011
```

Sign Extension:

```text
11111011
```

8-bit Two's Complement로 읽어도

```text
-5
```

다.

---

# 51. Zero Extension과 Sign Extension의 핵심 차이

### Zero Extension

```text
Bit Pattern의 의미를
Unsigned 관점으로 유지
```

### Sign Extension

```text
Signed Value 자체를 유지
```

한다.

강의에서는 결국 **패턴을 보존하려는가, 값을 보존하려는가**에 따라 적절한 Extension이 달라진다고 설명한다.

---

# 52. Programming Language에서도 이미 사용한다

High-level Language에서 작은 Integer Type을 큰 Integer Type으로 Casting할 때 Compiler/Hardware가 이러한 Extension을 내부적으로 수행한다.

개념적으로

```text
signed small integer
→ sign extension

unsigned small integer
→ zero extension
```

과 연결된다.

---

# 53. 결국 같은 4 bit에서도 여러 Number System이 가능하다

4 bit를 예로 들면 총 Pattern은 항상

```text
16개
```

다.

하지만 Mapping은 다르다.

### Unsigned

```text
0 ~ 15
```

### Sign-Magnitude

```text
-7 ~ +7
(+0, -0)
```

### Two's Complement

```text
-8 ~ +7
```

이다.

---

# 54. Resource Efficiency의 핵심 원칙

강의가 여기까지 반복해서 강조하는 것은 다음이다.

> **내가 실제로 필요한 Value Range를 알고, 그 Range를 표현하는 데 충분한 최소 Bit-width를 선택하라.**

왜냐하면 Bit-width가 줄어들면

```text
Model Size ↓

Memory Traffic ↓

Computation ↓

Energy ↓

Latency ↓
```

의 가능성이 생기기 때문이다.

강의에서는 4-bit 연산과 8-bit 연산을 비교하면서 더 작은 Bit-width가 Memory 및 연산 효율 측면에서 유리할 수 있음을 연결한다.

---

# 55. Integer Type의 역사에 대한 강의 Side Note

강의에서는 `char`, `short`, `int`, `long`, `long long`과 Computer Architecture 발전의 역사도 길게 설명한다.

핵심 취지는

> **Programming Language의 자료형 크기 역시 Hardware Architecture 역사와 독립적이지 않다.**

는 것이다.

---

# 56. 초기 Computer

초기 Computer에서는

```text
8 bit
16 bit
```

System도 일반적이었다.

Computer Architecture가 발전하면서

```text
8 bit
↓
16 bit
↓
32 bit
↓
64 bit
```

로 확대되었다.

---

# 57. C 자료형과 Platform

강의에서는 역사적 이유로 C의 일부 Integer Type 크기가 Platform과 ABI에 따라 달라질 수 있다는 점을 설명한다.

따라서 실제 Portable Software에서는

```text
32-bit가 정확히 필요하다.

64-bit가 정확히 필요하다.
```

면 Bit-width가 명확하게 정해진 Integer Type을 사용하는 방향이 안전하다는 것이 이 Side Note의 핵심이다.

# 58. 이제 진짜 핵심 — 소수는 어떻게 표현할까?

지금까지는

```text
0
1
2
3

-1
-2
-3
```

같은 Integer만 다뤘다.

하지만 현실에서는

```text
0.5

1.25

3.14159
```

같은 Fractional Number도 필요하다.

가장 단순한 아이디어 중 하나가 **Fixed-Point Number System**이다.

---

# 59. Fixed Point의 핵심 아이디어

n개의 Bit가 있다고 하자.

그중 일부는 Integer Part로, 나머지는 Fractional Part로 사용하기로 약속한다.

예:

```text
xxxx.xxxx
```

처럼

```text
앞 4 bit
→ Integer Part

뒤 4 bit
→ Fractional Part
```

라고 약속할 수 있다.

---

# 60. Binary Point

Integer Part와 Fractional Part 사이에 있다고 생각하는 소수점을

**Binary Point**

라고 한다.

예:

```text
0011.1000
```

이다.

---

# 61. “Fixed” Point인 이유

Binary Point의 위치가 숫자마다 바뀌는 것이 아니라

```text
항상 같은 위치
```

에 있다고 약속한다.

따라서

**Fixed-Point**

다.

---

# 62. 중요한 사실 — Binary Point는 실제 Bit에 저장되지 않는다

이 부분이 이 강의에서 가장 중요하다.

예를 들어 8-bit가

```text
00111000
```

이라고 하자.

Hardware에는 사실 이것만 있다.

```text
00111000
```

그 사이에 실제로

```text
0011.1000
```

이라는 `.` Bit가 저장되어 있는 것이 아니다.

---

# 63. Binary Point는 Programmer의 약속이다

Programmer가

```text
앞 4 bit = Integer

뒤 4 bit = Fraction
```

라고 **해석**할 뿐이다.

Hardware 입장에서는 여전히 그냥 Integer Bit Pattern이다.

강의에서는 고정소수점의 Binary Point 위치가 저장되는 것이 아니라 Programmer가 정하는 해석상의 약속이라는 점을 강조한다.

---

# 64. 이것을 한 문장으로

> **Fixed Point는 정수 Bit Pattern을 일정한 Scaling Factor를 곱한 값으로 해석하여 소수를 표현하는 방식이다.**

---

# 65. Scaling Factor

Hardware가 Integer

```text
X
```

를 저장한다고 하자.

Programmer는 실제 값을

```text
Real Value = αX
```

라고 해석한다.

여기서

```text
α
```

가 **Scaling Factor**다.

---

# 66. Fractional Bit가 F개라면

Binary Point 오른쪽에 F개의 Fraction Bit를 둔다면 Scaling Factor는

```text
α = 2^(-F)
```

형태가 된다.

---

# 67. 예: Fraction Bit = 4

```text
α = 2^-4
  = 1/16
```

이다.

Hardware Integer가

```text
56
```

이라면 우리가 해석하는 값은

```text
56 × 1/16
=
3.5
```

이다.

---

# 68. Hardware와 Programmer가 보는 값

### Hardware

```text
00111000
→ 56
```

### Programmer

```text
0011.1000
→ 3.5
```

이다.

하지만 **Bit Pattern은 동일하다.**

---

# 69. Fixed Point의 대원칙

```text
Hardware
→ Integer X를 계산

Programmer
→ αX로 해석
```

한다.

이 구조 하나를 잡으면 뒤의 연산을 이해할 수 있다.

---

# 70. Fixed-Point Addition

두 실제 값이

```text
x = αX

y = αY
```

라고 하자.

더하면

```text
x + y
=
αX + αY
```

이다.

공통 Scaling Factor `α`를 묶으면

```text
x + y
=
α(X + Y)
```

이다.

---

# 71. 여기서 중요한 구조

Hardware는 그냥

```text
X + Y
```

를 계산한다.

Programmer는 결과에 다시

```text
α
```

를 적용해서 해석한다.

따라서 Scaling Factor가 그대로 유지된다.

---

# 72. 그래서 Fixed-Point 덧셈이 쉬운 것이다

```text
αX + αY
=
α(X+Y)
```

이므로

```text
Hardware Integer Addition
```

을 그대로 사용할 수 있다.

별도의 Scaling Correction이 필요하지 않다.

---

# 73. 실제 예 — 3.5 + 1.25

Fraction Bit가 4개라면

```text
α = 1/16
```

이다.

3.5를 저장하면

```text
3.5 × 16
=
56
```

이다.

1.25를 저장하면

```text
1.25 × 16
=
20
```

이다.

Hardware는

```text
56 + 20
=
76
```

을 계산한다.

우리가 해석하면

```text
76 × 1/16
=
4.75
```

이다.

정답과 같다.

---

# 74. Fixed-Point Subtraction

뺄셈도 동일하다.

```text
αX - αY
=
α(X-Y)
```

이다.

따라서

```text
Hardware
→ X - Y

Programmer
→ α(X-Y)
```

로 해석하면 된다.

---

# 75. 결론 — 덧셈과 뺄셈

같은 Scaling Factor를 사용하는 Fixed-Point끼리라면

```text
Addition
Subtraction
```

은 일반 Integer Arithmetic과 거의 동일하게 사용할 수 있다.

---

# 76. 그런데 Multiplication은 다르다

이제

```text
x = αX

y = αY
```

를 곱해보자.

실제 원하는 값:

```text
xy
```

이다.

대입하면

```text
(αX)(αY)
```

이므로

```text
xy
=
α²XY
```

가 된다.

---

# 77. 왜 문제가 생겼는가?

덧셈에서는

```text
α
```

가 하나로 유지됐다.

하지만 곱셈하면

```text
α × α
=
α²
```

가 된다.

즉 **Scale이 변해버렸다.**

---

# 78. 그런데 결과도 원래 Scale α로 저장하고 싶다

우리는 출력 Integer `Z`도 기존 Fixed-Point Format으로 해석하고 싶다.

즉

```text
실제 결과
=
αZ
```

가 되어야 한다.

그런데 실제 계산 결과는

```text
α²XY
```

이므로

```text
αZ
=
α²XY
```

가 되어야 한다.

양변에서 α 하나를 제거하면

```text
Z
=
αXY
```

가 된다.

---

# 79. 이것이 Multiplication 보정이 필요한 이유

Hardware가 그냥

```text
XY
```

를 계산한 결과를 그대로 Fixed-Point로 읽으면 안 된다.

결과를 한 번 더

```text
α
```

만큼 Scaling해야 한다.

---

# 80. Fraction Bit가 4개라면

```text
α = 2^-4
```

이므로

```text
Z = 2^-4 XY
```

이다.

Binary에서는 `2^-4`를 곱하는 것이

```text
Right Shift 4 bit
```

와 연결된다.

---

# 81. 예: 1.5 × 0.5

Fraction Bit = 4.

따라서

```text
α = 1/16
```

이다.

1.5의 Hardware Integer:

```text
1.5 × 16
=
24
```

0.5의 Hardware Integer:

```text
0.5 × 16
=
8
```

---

# 82. Hardware가 그냥 곱하면

```text
24 × 8
=
192
```

이다.

그런데 192를 기존 Fixed-Point Scale로 바로 해석하면

```text
192 × 1/16
=
12
```

가 된다.

원하는 답

```text
0.75
```

와 다르다.

---

# 83. Scale을 보정

곱셈 결과에 Scaling Factor를 한 번 적용한다.

```text
192 × 1/16
=
12
```

을 **저장 Integer** 값으로 만들어야 한다.

즉 Hardware 수준에서는

```text
192 >> 4
=
12
```

와 같은 보정이 들어간다.

---

# 84. 최종적으로 다시 Fixed-Point 해석

Integer 12를 Fixed-Point로 읽으면

```text
12 × 1/16
=
0.75
```

가 된다.

정답이다.

강의에서는 이처럼 Fixed-Point Multiplication에서는 동일한 Binary Point 위치를 유지하려면 실제 Program/Hardware 연산에서 추가 Scaling, 일반적으로 Shift가 필요함을 강조한다.

---

# 85. “Shift를 두 번 하는 것 아닌가?”에 대한 강의 설명

강의 Q&A에서 이 부분을 따로 설명한다.

사람이

```text
24
```

를

```text
1.5
```

라고 생각하는 것은 **해석**이다.

실제로 Hardware 안에서 처음부터 24를 1.5로 바꾸는 Shift가 수행된 것이 아니다.

---

# 86. Physical Bit Pattern은 그대로다

```text
24
```

라는 Pattern을 두고 Programmer가

```text
"이건 1.5야."
```

라고 해석한 것이다.

따라서 실제 Multiplication 구현에서 필요한 추가 연산은

```text
곱한 결과를
Right Shift F
```

하는 보정이다.

강의 Q&A에서도 실제 Coding에서 필요한 것은 곱셈 결과를 Fractional Bit 수만큼 오른쪽으로 Shift하는 작업이라고 설명한다.

---

# 87. 이제 Division

다시

```text
x = αX

y = αY
```

라고 하자.

나누면

```text
x / y
=
αX / αY
```

이다.

Scaling Factor가 약분된다.

```text
x / y
=
X / Y
```

---

# 88. 이번에는 α가 사라졌다

Multiplication:

```text
α²
```

가 되어 Scale이 하나 늘었다.

Division:

```text
α / α
```

가 되어 Scale이 아예 사라졌다.

---

# 89. 하지만 결과는 다시 α Scale로 저장해야 한다

결과 Integer를 `Z`라고 하자.

Fixed-Point Format에서 실제 값은

```text
αZ
```

로 해석된다.

우리가 원하는 실제 값은

```text
X/Y
```

이므로

```text
αZ
=
X/Y
```

여야 한다.

따라서

```text
Z
=
(X/Y) / α
```

이다.

---

# 90. Fraction Bit가 F개라면

```text
α = 2^-F
```

이므로

```text
1/α = 2^F
```

이다.

따라서 Division에서는 결과를

```text
Left Shift F
```

하는 방향의 보정이 필요하다.

---

# 91. 예: 1.5 ÷ 0.5

Fixed-Point Integer:

```text
1.5
→ 24

0.5
→ 8
```

Hardware에서 그냥 나누면

```text
24 / 8
=
3
```

이다.

---

# 92. 그런데 Integer 3을 기존 Fixed-Point 방식으로 해석하면

```text
3 × 1/16
=
0.1875
```

가 된다.

원하는 값

```text
3.0
```

이 아니다.

---

# 93. 그래서 Scale 복원

원래 Scale로 저장하려면

```text
3 × 16
=
48
```

이라는 Integer Pattern이 필요하다.

즉

```text
3 << 4
=
48
```

에 해당한다.

---

# 94. 48을 Fixed-Point로 해석

```text
48 × 1/16
=
3
```

이다.

원하는 결과가 나온다.

강의 후반에서는 나눗셈의 경우 곱셈과 반대로 Scale이 사라지므로 결과를 왼쪽으로 Shift하여 원래 Fixed-Point Scale을 복원해야 한다고 설명한다.

---

# 95. Fixed-Point 연산을 구조적으로 정리

두 값이

```text
x = αX
y = αY
```

라고 하자.

### Addition

```text
x + y
=
α(X+Y)
```

→ 추가 Scale 보정 필요 없음.

### Subtraction

```text
x - y
=
α(X-Y)
```

→ 추가 Scale 보정 필요 없음.

### Multiplication

```text
xy
=
α²XY
```

→ α 하나가 추가됨.

따라서 결과를 다시 α Format으로 만들려면

```text
Z = αXY
```

로 보정.

### Division

```text
x/y
=
X/Y
```

→ α가 사라짐.

따라서 다시 α Format으로 만들려면

```text
Z = (X/Y)/α
```

로 보정.

---

# 96. 가장 중요한 표

|연산|Scale 변화|같은 Fixed-Point Format으로 만들기|
|---|---|---|
|`+`|`α` 유지|그대로|
|`-`|`α` 유지|그대로|
|`×`|`α²`가 됨|`α`만큼 축소|
|`÷`|`α`가 사라짐|`1/α`만큼 확대|

Fractional Bit가 `F`개이고

```text
α = 2^-F
```

라면

|연산|대표 보정|
|---|---|
|덧셈|없음|
|뺄셈|없음|
|곱셈|Right Shift `F`|
|나눗셈|Left Shift `F`|

---

# 97. 왜 Shift를 사용할 수 있는가?

Scaling Factor를 보통

```text
2의 거듭제곱
```

형태로 잡기 때문이다.

예:

```text
2^-4
```

를 곱하는 것은 Binary에서

```text
Right Shift 4
```

와 연결된다.

반대로

```text
2^4
```

를 곱하는 것은

```text
Left Shift 4
```

와 연결된다.

복잡한 Floating-Point Arithmetic보다 단순한 Integer/Shift Hardware로 처리할 수 있다는 것이 Fixed Point의 큰 장점이다.

---

# 98. Binary Point의 위치는 자유롭게 정할 수 있다

8 bit라고 해서 반드시

```text
4 bit Integer
+
4 bit Fraction
```

으로 나눠야 하는 것은 아니다.

예:

```text
7 Integer + 1 Fraction

5 Integer + 3 Fraction

3 Integer + 5 Fraction

1 Integer + 7 Fraction
```

등으로 Programmer가 선택할 수 있다.

강의 마지막에서도 Binary Point의 위치는 Programmer가 원하는 Range와 Precision에 맞춰 결정하며, 고정된 중앙 위치가 아니라는 점을 강조한다.

---

# 99. Binary Point 위치가 바뀌면 무엇이 달라지는가?

전체 Bit 수를 고정했다고 하자.

Integer Bit를 늘리면

```text
큰 값 표현 가능
↓
Range ↑

하지만
Fraction Bit ↓
↓
Precision ↓
```

이다.

---

# 100. 반대로 Fraction Bit를 늘리면

```text
Fraction Resolution ↑
↓
작은 차이를 더 세밀하게 표현

하지만

Integer Bit ↓
↓
큰 값 표현 Range ↓
```

이다.

---

# 101. 결국 Fixed Point의 핵심 Trade-off

정해진 Bit Budget을

```text
Range
vs
Precision
```

어디에 배분할 것인지 결정하는 문제다.

```text
Integer Bit ↑
→ Range ↑

Fraction Bit ↑
→ Precision ↑
```

이다.

---

# 102. 이것이 이후 Quantization과 연결된다

Machine Learning에서는 Weight와 Activation이 실제로 어떤 Range에 분포하는지 보고

```text
얼마나 넓은 Range가 필요한가?

얼마나 높은 Precision이 필요한가?
```

를 판단한다.

그다음 더 적은 Bit로 Mapping한다.

즉 이번 강의에서 계속 말한

> **“필요한 Range를 알고 적절한 Number Representation을 선택한다.”**

는 원리가 그대로 Quantization으로 이어진다.

---

# 103. Fixed Point와 Floating Point

강의 마지막에서는 다음 차시와 연결한다.

Floating Point는 Fractional Number를 매우 편리하고 넓은 Range에서 표현할 수 있다.

하지만 강의에서는 일반적으로 Fixed-Point/Integer 기반 연산에 비해 Hardware Complexity와 Energy·Latency 비용이 커질 수 있다는 점을 강조한다.

---

# 104. Fixed Point를 선택할 수 있는 상황

만약

```text
내가 필요한 Range가 충분히 작고

제한된 Bit 안에서
필요한 Precision도 확보 가능하다.
```

면 굳이 더 복잡한 높은 Precision Representation을 사용할 필요가 없을 수 있다.

---

# 105. 이것이 Resource-Efficient Computing의 기본 사고방식

```text
무조건 더 많은 Bit
=
무조건 더 좋음
```

이 아니다.

실제 문제에서 필요한

```text
Range

Precision
```

을 파악하고

```text
필요한 만큼만 Resource를 사용
```

하는 것이 중요하다.

---

# 106. 강의에서 가장 자주 헷갈릴 부분 ①

## Bit Pattern 자체가 숫자인가?

정확히는 아니다.

```text
1111
```

은 하나의 Bit Pattern이다.

이를

```text
Unsigned
→ 15

Two's Complement
→ -1
```

중 무엇으로 볼지는 Representation 규칙에 달려 있다.

---

# 107. 헷갈릴 부분 ②

## MSB가 1이면 항상 음수인가?

아니다.

Two's Complement나 Sign-Magnitude처럼 Signed Number System으로 **해석할 때** 그런 의미를 가진다.

Unsigned에서는 가장 높은 Weight의 Positive Bit일 뿐이다.

---

# 108. 헷갈릴 부분 ③

## n bit면 최대값이 2ⁿ인가?

Unsigned 기준 최대값은

```text
2ⁿ - 1
```

이다.

왜냐하면 가능한 Pattern이

```text
2ⁿ개
```

이고 `0`도 하나의 Pattern을 차지하기 때문이다.

---

# 109. 헷갈릴 부분 ④

## Two's Complement 범위는 왜 대칭이 아닌가?

```text
-2^(n-1)
~
2^(n-1)-1
```

이다.

0을 하나만 사용하기 때문에 음수 쪽이 하나 더 있다.

# 110. 헷갈릴 부분 ⑤

## Sign-Magnitude의 가장 큰 문제는 무엇인가?

사람이 읽기는 쉽지만 기존 Binary Adder를 그대로 사용하기 어렵다.

또

```text
+0
-0
```

이 따로 존재한다.

# 111. 헷갈릴 부분 ⑥

## Zero Extension과 Sign Extension의 차이

```text
Unsigned
→ Zero Extension

Signed Two's Complement
→ Sign Extension
```

을 기본 구조로 기억하면 된다.

Sign Extension은 **값을 유지하기 위해 Sign Bit를 복제**한다.

# 112. 헷갈릴 부분 ⑦

## Fixed Point에서는 실제 소수점도 저장하는가?

아니다.


에서 `.`은 실제 Memory Bit가 아니다.

실제 저장:

```text

```

```text

```

이라는 Integer를 처리한다.

Programmer가

```text
56 × 2^-4
=
3.5
```

라고 해석한다.

# 114. 헷갈릴 부분 ⑨

## 왜 덧셈은 Shift가 필요 없나?

두 값이

```text

αY
```

이면

```text
αX + αY
=
α(X+Y)
```

이다.

Scale `α`가 그대로 유지되기 때문이다.

# 115. 헷갈릴 부분 ⑩

## 왜 곱셈에서는 Shift가 필요한가?

```text
(αX)(αY)
=
α²XY
```

가 되어 Scale이 하나 더 생긴다.

원래 Scale `α`로 되돌려야 하므로 하나를 보정해야 한다.

---

# 116. 헷갈릴 부분 ⑪

## 왜 나눗셈에서는 반대로 보정하는가?

```text
αX / αY
=
X/Y
```

가 되어 Scale이 사라진다.

따라서 결과를 다시 `α` Scale로 저장하기 위해 `1/α`만큼 확대해야 한다.

---

# 117. 헷갈릴 부분 ⑫

## 곱셈할 때 Shift를 두 번 하는가?

Programmer가 Integer Pattern을 소수로 **해석하는 것**은 실제 Hardware Shift가 아니다.

실제 Fixed-Point Multiplication 구현에서 같은 Scale로 결과를 유지하기 위한 추가 Hardware/Program 연산이 한 번 들어간다고 이해하면 된다.

Fraction Bit가 4개라면 대표적으로

```text
Product >> 4
```

이다.

# 118. 헷갈릴 부분 ⑬

## Fixed Point는 항상 4비트/4비트로 나누는가?

아니다.

Binary Point의 위치는 Programmer가 원하는 Range와 Precision에 따라 선택한다.

까지 연결한다.

# 120. 이번 강의에서 반드시 기억할 핵심

### 1.

Computer의 Number System은 Bit Pattern을 어떤 규칙으로 해석할 것인지에 대한 약속이다.

### 2.

Binary는 전자회로의 두 상태와 잘 맞기 때문에 Computer에서 기본 Number System으로 사용된다.

### 3.

n-bit에는 총 `2ⁿ`개의 서로 다른 Pattern이 존재한다.

### 4.

n-bit Unsigned Integer의 Range는 `0 ~ 2ⁿ-1`이다.

### 5.

실제 필요한 Range보다 지나치게 큰 Bit-width를 사용하면 Memory를 낭비한다.

### 6.

대규모 ML Model에서는 Parameter 하나의 몇 Bit 차이가 전체 Model Memory에 매우 큰 영향을 줄 수 있다.

### 7.

작은 Bit-width는 Memory뿐 아니라 Memory Access, 연산 속도와 Energy Efficiency에도 영향을 줄 수 있다.

### 8.

Sign-Magnitude는 MSB를 Sign, 나머지를 Magnitude로 사용하는 직관적인 Signed Representation이다.

### 9.

Sign-Magnitude는 `+0`, `-0` 두 종류의 0이 존재하며 일반 Binary Addition을 그대로 사용하기 어렵다.

### 10.

Two's Complement는 MSB에 `-2^(n-1)`의 Weight를 부여한다고 보면 쉽게 해석할 수 있다.

### 11.

n-bit Two's Complement Range는 `-2^(n-1) ~ 2^(n-1)-1`이다.

### 12.

Two's Complement의 중요한 장점은 기존 Binary Adder를 Signed Arithmetic에도 활용하기 쉽다는 것이다.

### 13.

Two's Complement에서 부호를 반대로 만들 때는 모든 Bit를 뒤집고 1을 더하는 방법을 사용할 수 있다.

### 14.

같은 Bit Pattern도 Unsigned와 Two's Complement 중 어떤 Number System으로 해석하느냐에 따라 값이 달라진다.

### 15.

서로 다른 Bit-width의 수를 연산하려면 작은 Bit-width를 확장할 필요가 있다.

### 16.

Unsigned Value는 일반적으로 Zero Extension을 통해 높은 Bit를 0으로 채울 수 있다.

### 17.

Two's Complement Signed Value는 Sign Extension을 이용해 기존 값을 유지할 수 있다.

### 18.

Sign Extension은 기존 MSB를 새로 추가되는 상위 Bit에 복제한다.

### 19.

Fixed Point는 Integer Bit Pattern을 Scaling Factor를 이용해 Fractional Number로 해석한다.

### 20.

Fixed Point의 Binary Point는 실제 Memory에 저장되는 것이 아니라 Programmer가 정한 약속이다.

### 21.

Fraction Bit가 `F`개이면 Scaling Factor를 `α = 2^-F` 형태로 둘 수 있다.

### 22.

Hardware Integer가 `X`라면 실제 Fixed-Point Value를 `αX`로 해석할 수 있다.

### 23.

같은 Scale을 가진 Fixed-Point Addition은 `αX + αY = α(X+Y)`이므로 일반 Integer Addition을 그대로 사용할 수 있다.

### 24.

Subtraction도 동일한 이유로 추가 Scaling Correction이 필요하지 않는다.

### 25.

Multiplication에서는 `(αX)(αY)=α²XY`가 되어 Scaling Factor가 하나 더 생긴다.

### 26.

같은 Fixed-Point Format으로 결과를 저장하려면 Multiplication Result의 Scale을 다시 조절해야 한다.

### 27.

`α=2^-F`라면 대표적으로 Product를 `F` bit Right Shift하여 Scale을 보정한다.

### 28.

Division에서는 `αX/αY=X/Y`가 되어 기존 Scaling Factor가 사라진다.

### 29.

따라서 같은 Fixed-Point Format으로 저장하려면 결과에 `1/α`만큼 Scale을 다시 만들어야 한다.

### 30.

`α=2^-F`라면 대표적으로 Division Result를 `F` bit Left Shift하는 방향의 보정이 필요하다.

### 31.

Fixed-Point의 Binary Point 위치는 자유롭게 선택할 수 있다.

### 32.

Integer Bit를 많이 할당하면 표현 Range가 넓어진다.

### 33.

Fraction Bit를 많이 할당하면 Fractional Precision이 높아진다.

### 34.

고정된 Bit Budget에서는 Range와 Precision 사이에 Trade-off가 존재한다.

### 35.

필요한 Range와 Precision을 파악한 뒤 최소 Bit로 표현하는 사고방식이 이후 Quantization과 Model Compression의 기반이다.

### 36.

Floating Point는 사용하기 편하고 넓은 Range를 제공하지만 강의에서는 Fixed-Point/Integer Arithmetic에 비해 Hardware Cost와 Energy 측면의 부담이 클 수 있다고 설명한다.

### 37.

따라서 제한된 Range와 Precision으로 충분한 Application에서는 Fixed Point가 Resource Efficiency 측면에서 유리할 수 있다.
