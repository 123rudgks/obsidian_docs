# 0. 강의 전체 개요

이번 강의에서는 **Logistic Regression(로지스틱 회귀)** 을 다룬다.

이름에는 Regression이 들어가지만 실제 해결하려는 문제는 **Classification(분류)** 이다.

전체 흐름은 다음과 같다.

```text
Classification
      ↓
왜 Linear Regression을
그대로 사용할 수 없는가?
      ↓
확률은 반드시 0~1이어야 함
      ↓
Sigmoid Function
      ↓
Linear Function을 Sigmoid에 입력
      ↓
Logistic Regression
      ↓
P(Y=1 | X=x)
      ↓
Odds
      ↓
Logit = Log Odds
      ↓
Logit은 다시 Linear Function
      ↓
그렇다면 β를 어떻게 학습하는가?
      ↓
Least Squares가 아니라 Likelihood
      ↓
Maximum Likelihood Estimation
      ↓
Log-Likelihood
      ↓
β 추정
      ↓
Coefficient / Standard Error / p-value 해석
      ↓
Multiple Logistic Regression
```

---

# 1. Logistic Regression은 Classification을 위한 방법이다

앞서 배운 Regression에서는 Label `y`가 숫자였다.

예:

```text
집값
매출
시험 점수
```

Logistic Regression에서는 예측 대상이 **Category**다.

예:

```text
Yes / No
Spam / Normal
Positive / Negative
Default / Non-default
```

즉

> **Logistic Regression은 범주형 Target을 예측하기 위한 Classification 방법이다.**

---

# 2. Classification의 기본 구조

Classification에서는 Input Feature `x`를 받아 정해진 Category 중 하나로 Mapping한다.

예:

```text
Email 정보
     ↓
Spam / Normal
```

또는

```text
의료 정보
     ↓
Positive / Negative
```

출력 Category에는 일반적으로

```text
더 크다
더 작다
```

라는 숫자적 의미가 없다.

각각 서로 다른 Category일 뿐이다.

---

# 3. 단순히 Category만 출력하는 것보다 확률이 유용하다

예를 들어 두 Model이 모두

```text
Default
```

라고 예측했다고 하자.

하지만

```text
Model A
P(Default) = 0.51

Model B
P(Default) = 0.99
```

라면 두 Prediction에는 큰 차이가 있다.

따라서 단순히 Class만 출력하는 것보다

> **각 Class에 속할 Probability를 계산하는 것**

이 더 유용할 수 있다.

---

# 4. 강의 예제 — Credit Card Default

강의에서는 Credit Card 연체 여부를 예제로 사용한다.

Feature:

```text
Balance
Income
```

Target:

```text
Default = Yes / No
```

여기서 반드시 주의해야 한다.

```text
Balance = x₁
Income  = x₂
```

둘 다 Feature다.

`y`는

```text
연체 여부
```

다.

---

# 5. Data에서 보이는 관계

Dataset을 보면 강의에서는 다음 관계가 관찰된다.

### Balance

카드 사용량인 Balance가 증가할수록 연체자가 많아지는 경향이 보인다.

```text
Balance ↑
→ Default 가능성 ↑
```

### Income

Income과 Default 사이에는 눈으로 보았을 때 뚜렷한 관계가 잘 보이지 않는다.

```text
Income
→ Default와 뚜렷한 관계가 잘 보이지 않음
```

---

# 6. Classification을 Linear Regression으로 풀면 안 될까?

Binary Classification이라면 Label을 숫자로 바꿀 수 있다.

예:

```text
Default    → 1
Nondefault → 0
```

그러면 얼핏 보면 Linear Regression을 적용할 수 있을 것 같다.

```text
x
↓
Linear Regression
↓
숫자 Prediction
↓
0.5 이상 → 1
0.5 미만 → 0
```

실제로 계산 자체는 가능하다.

하지만 중요한 문제가 있다.

---

# 7. Linear Regression의 가장 큰 문제

Linear Regression의 출력 범위에는 제한이 없다.

직선은 계속 뻗어나가기 때문에

```text
ŷ > 1
```

도 가능하고

```text
ŷ < 0
```

도 가능하다.

그런데 이를 Probability라고 해석하려고 하면 문제가 된다.

확률은 반드시

`0 ≤ P ≤ 1`

이어야 하기 때문이다.

---

# 8. 우리가 원하는 함수

Classification을 Probability로 표현하려면

Input이 아무리 크거나 작아져도 Output이 항상

```text
0 ~ 1
```

사이에 존재하는 함수가 필요하다.

이 역할을 하는 대표적인 함수가 **Sigmoid Function**이다.

---

# 9. Sigmoid Function

Sigmoid Function은 다음과 같다.

`σ(z) = 1 / (1 + e^(-z))`

동일하게

`σ(z) = e^z / (1 + e^z)`

로 표현할 수도 있다.

형태는 S자 곡선이다.

```text
1 |            ______
  |          /
  |        /
0.5|------/
  |     /
  |   /
0 |___
    z
```

---

# 10. Sigmoid의 중요한 성질

어떤 실수 `z`를 입력하더라도

`0 < σ(z) < 1`

이다.

따라서 Probability로 사용하기에 적합하다.

### z가 매우 커지면

`σ(z) → 1`

### z가 매우 작아지면

`σ(z) → 0`

이다.

---

# 11. Logistic Regression은 어떻게 만들어지는가?

앞 시간에 배운 Simple Linear Regression은

`z = β₀ + β₁x`

형태였다.

Logistic Regression에서는 이 Linear Function을 Sigmoid의 `z`에 그대로 넣는다.

즉

`p(x) = σ(β₀ + β₁x)`

이다.

풀어서 쓰면

`p(x) = 1 / (1 + e^(-(β₀+β₁x)))`

이다.

---

# 12. 핵심 구조

따라서 Logistic Regression을 가장 직관적으로 보면

```text
Linear Function
β₀ + β₁x
      ↓
Sigmoid
      ↓
0~1 Probability
```

이다.

즉

> **선형회귀식에 Sigmoid Function을 씌운 형태**

라고 이해할 수 있다.

---

# 13. 왜 이름에 Regression이 들어가는가?

최종적으로 해결하는 문제는 Classification이지만 내부적으로

```text
β₀ + β₁x
```

라는 Linear Regression과 유사한 선형식을 사용한다.

그리고 여전히 학습하려는 대상은

```text
β₀
β₁
```

같은 Regression Coefficient다.

따라서 Logistic **Regression**이라는 이름을 사용한다.

---

# 14. Binary Classification에서 y 표현

Binary Classification에서는 일반적으로

`y ∈ {0,1}`

로 표현한다.

예를 들어

```text
y = 1
→ Default

y = 0
→ Non-default
```

라고 정의할 수 있다.

하지만 반드시 Default를 1로 해야 한다는 철학적 규칙이 있는 것은 아니다.

중요한 것은

> **어느 Event를 1로 정의했는지 일관되게 사용하는 것**

이다.

---

# 15. Logistic Regression이 예측하는 것

보통

`p(x) = P(Y=1 | X=x)`

로 정의한다.

즉 Feature `x`가 주어졌을 때

> **Y가 1일 조건부 Probability**

를 예측한다.

예:

`P(Default=1 | Balance=x)`

이다.

---

# 16. Probability에서 Class로 변환

예측된 Probability를 이용해 최종 Class를 결정할 수 있다.

예를 들어 Threshold를 `0.5`로 설정하면

```text
p(x) ≥ 0.5
→ Class 1

p(x) < 0.5
→ Class 0
```

으로 분류할 수 있다.

즉 Logistic Regression Model이 직접적으로 만드는 중요한 값은 먼저 **Probability**다.

---

# 17. Logistic Regression에서도 학습 대상은 β다

모델이

`p(x) = σ(β₀ + β₁x)`

라면 우리가 모르는 것은

```text
β₀ = Intercept
β₁ = Coefficient
```

이다.

따라서 Logistic Regression의 Learning 역시

> **Data를 이용해서 적절한 β를 찾는 문제**

다.

이 점은 Linear Regression과 동일하다.

---

# 18. Logistic Regression과 Linear Regression의 공통점

```text
Linear Regression
β₀ + β₁x

Logistic Regression
σ(β₀ + β₁x)
```

둘 다 결국 β를 학습한다.

차이는 Logistic Regression에서는 Linear Function을 Probability로 바꾸기 위해 Sigmoid를 추가했다는 것이다.

---

# 19. Odds

Logistic Regression의 계수를 이해하기 위해 강의에서는 **Odds**를 소개한다.

성공 Probability가 `p`라면 실패 Probability는

`1-p`

이다.

따라서 Odds는

`Odds = p / (1-p)`

이다.

즉

> **실패할 Probability 대비 성공할 Probability**

를 나타낸다.

---

# 20. Odds 예시

예를 들어

`p = 0.8`

이라면

```text
Success = 0.8
Failure = 0.2
```

이므로 Odds는

`0.8 / 0.2`

와 같은 형태로 표현된다.

강의에서는 스포츠 등의 상황에서

> 이길 Probability / 질 Probability

와 같은 개념으로 설명한다.

---

# 21. Logit

Odds에 Log를 취한 것을 **Logit**, 또는 **Log Odds**라고 한다.

`logit(p) = log(p / (1-p))`

이다.

즉

```text
Probability
↓
Odds
↓
Log
↓
Logit
```

이다.

---

# 22. Logistic Regression의 중요한 관계

Logistic Regression의 Probability를 Logit으로 변환하면 매우 재미있는 결과가 나온다.

`log(p(x)/(1-p(x))) = β₀ + β₁x`

즉 Sigmoid 형태였던 Probability를 Logit으로 변환하면 다시 **Linear Function**이 된다.

```text
Probability
Sigmoid 형태
      ↓ Logit Transformation
β₀ + β₁x
Linear 형태
```

---

# 23. 왜 Logit을 사용하는가?

Probability 자체와 `x`의 관계는 Linear하지 않다.

```text
x ↑
→ Probability가 S자 형태로 변화
```

하지만 Log Odds로 변환하면

```text
x
↕
Log Odds

Linear Relationship
```

으로 표현할 수 있다.

따라서 Regression Coefficient를 해석하기 쉬워진다.

---

# 24. Logistic Regression의 β₁을 어떻게 해석하는가?

Simple Logistic Regression에서

`logit(p) = β₀ + β₁x`

이다.

따라서 `x`가 1만큼 증가하면

> **Log Odds가 β₁만큼 변화한다.**

---

# 25. 매우 중요 — β₁은 Probability의 변화량이 아니다

예를 들어

`β₁ = 0.0055`

라고 하자.

잘못된 해석:

```text
x가 1 증가
→ Probability가 0.0055 증가
```

이것은 틀렸다.

올바른 해석은

```text
x가 1 증가
→ Log Odds가 0.0055 증가
```

이다.

---

# 26. 왜 Probability가 일정하게 증가하지 않는가?

Probability는 Sigmoid Function을 따라 움직이기 때문이다.

따라서 같은 `x` 증가량이라도 현재 `x`가 어느 영역에 있는지에 따라 Probability 변화량이 달라진다.

```text
Sigmoid 양 끝
→ Probability 변화 작음

Sigmoid 중앙
→ Probability 변화 큼
```

즉 Probability는 Linear하게 증가하지 않는다.

---

# 27. β의 부호는 방향을 알려준다

### β₁ > 0

`x`가 증가하면

```text
Log Odds ↑
→ Y=1 Probability도 증가하는 방향
```

### β₁ < 0

`x`가 증가하면

```text
Log Odds ↓
→ Y=1 Probability도 감소하는 방향
```

따라서 Coefficient의 부호를 통해 관계의 방향을 해석할 수 있다.

---

# 28. 이제 β를 어떻게 학습할 것인가?

Linear Regression에서는 **Least Squares**를 사용했다.

```text
Residual
= y - ŷ

RSS
= Σ(y-ŷ)²

RSS 최소화
→ β 추정
```

그런데 Logistic Regression은 Probability Model이다.

따라서 단순한 Residual Square 방식 대신 다른 기준을 사용한다.

그 기준이 **Likelihood(우도)** 다.

---

# 29. Likelihood란?

강의에서는 Likelihood를

> **현재 Probability Model이 관측된 Data를 얼마나 잘 설명하는가를 나타내는 값**

으로 설명한다.

좋은 Model:

```text
Observed Data를
높은 Probability로 설명
→ Likelihood 높음
```

나쁜 Model:

```text
Observed Data를
낮은 Probability로 설명
→ Likelihood 낮음
```

따라서 우리가 원하는 것은

> **Likelihood를 최대화하는 β**

다.

---

# 30. Likelihood를 가장 직관적으로 이해하는 방법

Dataset을 열어 실제 `y`를 확인한다고 하자.

Binary Classification이므로

```text
y = 1인 Data

y = 0인 Data
```

두 종류가 있다.

좋은 Model이라면 어떻게 예측해야 할까?

```text
실제 y=1
→ p(x)가 1에 가까움

실제 y=0
→ p(x)가 0에 가까움
```

이어야 한다.

---

# 31. 실제 y=1인 Data

실제 Label이 1인 Data들만 생각한다.

```text
y₁ = 1
y₂ = 1
y₃ = 1
...
```

좋은 Model이라면 각각에 대해

```text
p(x₁)
p(x₂)
p(x₃)
...
```

가 모두 `1`에 가까워야 한다.

따라서 이 Probability들을 모두 곱한 값도 최대한 크게 만들고 싶다.

---

# 32. 실제 y=0인 Data

이번에는 실제 Label이 0인 Data를 생각한다.

좋은 Model이라면

`p(x) = P(Y=1|x)`

가 `0`에 가까워야 한다.

그렇다면

`1-p(x)`

는 `1`에 가까워진다.

따라서 실제 `y=0`인 Data에서는

```text
1-p(x)
```

를 크게 만들고 싶다.

---

# 33. Likelihood의 구조

따라서 Binary Logistic Regression의 Likelihood는 직관적으로

`L(β) = ∏[yᵢ=1] p(xᵢ) × ∏[yᵢ=0] (1-p(xᵢ))`

형태다.

즉

```text
실제 1인 Data
→ 1이라고 예측할 Probability들을 곱함

실제 0인 Data
→ 0이라고 예측할 Probability들을 곱함
```

이다.

---

# 34. Likelihood를 최대화한다는 의미

Likelihood를 크게 만든다는 것은

```text
실제 y=1
→ Prediction Probability → 1

실제 y=0
→ Prediction Probability → 0
```

이 되도록 β를 찾는다는 의미다.

즉 Classification 관점에서 매우 자연스럽다.

---

# 35. Maximum Likelihood Estimation(MLE)

따라서 우리가 해결하려는 문제는

> **Likelihood를 최대화하는 β를 찾는 것**

이다.

이를 **Maximum Likelihood Estimation(MLE, 최대우도추정)** 이라고 한다.

```text
Data
 ↓
Likelihood L(β)
 ↓
L(β)를 가장 크게 만드는
β 찾기
 ↓
MLE
```

---

# 36. Linear Regression과 Logistic Regression의 학습 비교

### Linear Regression

```text
RSS 최소화
→ β 추정
```

### Logistic Regression

```text
Likelihood 최대화
→ β 추정
```

즉 둘 모두 β를 찾는 문제지만 **좋은 β를 판단하는 Objective가 다르다.**

---

# 37. 그런데 Likelihood는 계산하기 불편하다

Likelihood에는 많은 Probability의 **곱**이 들어간다.

Dataset이 크면

```text
p₁ × p₂ × p₃ × ...
```

라는 복잡한 곱을 다뤄야 한다.

최적화와 미분을 하기 불편하다.

그래서 Log를 취한다.

---

# 38. Log-Likelihood

Likelihood에 Log를 적용한 것을 **Log-Likelihood**라고 한다.

Log의 중요한 성질:

`log(ab) = log(a) + log(b)`

이다.

즉

```text
곱
↓ Log
합
```

으로 바뀐다.

따라서 계산과 최적화가 훨씬 편해진다.

---

# 39. 왜 Likelihood 대신 Log-Likelihood를 최대화해도 되는가?

Log Function은 **Monotonically Increasing Function**이다.

즉

```text
A > B
이면
log(A) > log(B)
```

다.

따라서 Likelihood가 최대가 되는 `β`와 Log-Likelihood가 최대가 되는 `β`의 위치는 같다.

```text
argmax L(β)
=
argmax log L(β)
```

Maximum Value 자체는 달라지지만 **그 Maximum을 만드는 β는 같다.**

---

# 40. Logistic Regression 학습 흐름

따라서 실제 사고 과정은 다음과 같다.

```text
Likelihood 정의
      ↓
Likelihood를 최대화하고 싶음
      ↓
곱이라 계산하기 불편
      ↓
Log 적용
      ↓
Log-Likelihood
      ↓
Log-Likelihood 최대화
      ↓
최적 β 추정
```

---

# 41. Linear Regression과 달리 Closed-form Solution이 없다

Linear Regression의 Least Squares에서는

```text
β를 한 번에 계산하는 공식
```

을 만들 수 있었다.

하지만 강의에서는 Logistic Regression의 MLE에는 이와 같은 간단한 Closed-form Solution이 없다고 설명한다.

따라서 Numerical Optimization을 반복적으로 수행해야 한다.

---

# 42. 이후 Gradient Descent와 연결된다

β를 한 번에 계산할 수 없으므로

```text
현재 β
 ↓
조금 수정
 ↓
Objective 개선
 ↓
다시 수정
 ↓
...
```

처럼 반복적으로 최적의 β를 찾아간다.

강의에서는 이후 **Gradient Descent**에서 이 원리를 다시 다룰 예정이라고 연결한다.

---

# 43. Logistic Regression 결과표

Logistic Regression을 실제 Library나 통계 Package로 수행하면 선형회귀와 비슷한 정보를 얻을 수 있다.

대표적으로

- Coefficient Estimate
    
- Standard Error
    
- 통계량
    
- p-value
    

등이다.

---

# 44. Coefficient

Coefficient는 추정된 `β`다.

즉 Data를 이용해 학습한

```text
β̂₀
β̂₁
β̂₂
...
```

이다.

Logistic Regression에서도 여전히 Model이 학습하는 핵심 Parameter다.

---

# 45. Standard Error

추정된 Coefficient 역시 Dataset이 조금 달라지면 변할 수 있다.

Standard Error는 강의에서

> **Coefficient 추정치가 Data에 따라 얼마나 변할 수 있는지를 나타내는 정도**

로 설명한다.

---

# 46. Coefficient의 숫자만 보고 판단하면 안 된다

예를 들어

```text
β̂ = 0.001
```

이라고 해서

> 관계가 약하다.

라고 단정하면 안 된다.

Coefficient의 크기는 Feature의 단위에 영향을 받기 때문이다.

또 통계적으로 의미 있는지를 판단하려면 Coefficient와 Standard Error의 **상대적인 크기**를 같이 봐야 한다.

---

# 47. p-value

강의에서는 선형회귀와 마찬가지로

> **해당 Coefficient가 실제로 0이라고 보는 가설에 비해 현재 관측된 결과가 얼마나 유의미한가**

를 p-value로 해석한다.

Coefficient가 Standard Error에 비해 충분히 크다면 관련 통계량의 절댓값이 커지고 p-value는 작아진다.

---

# 48. p-value 기준

강의에서는 통상적인 기준으로

`p-value < 0.05`

이면 통계적으로 유의미하다고 설명한다.

즉

```text
p-value 작음
→ β=0이라는 가설과 현재 Data가 잘 맞지 않음
→ 해당 Feature와 Target의 관계가 유의미하다고 판단할 근거
```

로 이해한다.

---

# 49. Balance 결과 해석

Credit Card Default 예제에서 Balance의 Coefficient가 Positive로 나온다.

따라서

```text
Balance ↑
→ Default의 Log Odds ↑
→ Default Probability가 증가하는 방향
```

이라고 해석한다.

하지만

> Balance가 1 증가할 때 Default Probability가 Coefficient만큼 증가한다.

라고 해석하면 안 된다.

---

# 50. 실제 Probability 변화는 Non-linear하다

강의 예에서는 Balance가 다른 구간으로 변할 때 Default Probability의 변화 폭이 크게 달라지는 사례를 제시한다.

즉

```text
x 변화량 일정
≠
Probability 변화량 일정
```

이다.

그 이유는 Probability가 직선이 아니라 Sigmoid를 따라 변화하기 때문이다.

---

# 51. Simple Logistic → Multiple Logistic Regression

Simple Logistic Regression에서는 Feature가 하나였다.

`logit(p) = β₀ + β₁x`

Feature가 여러 개라면 선형회귀와 동일하게 확장한다.

`logit(p) = β₀ + β₁x₁ + β₂x₂ + ... + βₚxₚ`

이다.

즉 달라지는 것은

> **Linear Function 안에 여러 Feature와 여러 β가 들어가는 것**

뿐이다.

---

# 52. Multiple Logistic Regression의 학습 대상

Feature가 `p`개라면

```text
β₀
β₁
β₂
...
βₚ
```

를 학습한다.

즉

```text
Input
x₁, x₂, ..., xₚ

Linear Combination
β₀ + β₁x₁ + ... + βₚxₚ

Sigmoid
↓

P(Y=1 | X)
```

구조다.

---

# 53. Multiple Logistic Regression의 계수 해석

다른 Feature들이 모두 고정되어 있다고 생각한다.

그 상태에서 `xⱼ`가 1 증가하면

> **Log Odds가 `βⱼ`만큼 변화한다.**

따라서 각 Coefficient를 해석할 때도 다른 변수들의 영향을 함께 고려해야 한다.

---

# 54. Income 예제

강의의 Default Dataset에서 Income은 눈으로 Data를 살펴봤을 때도 Default와 뚜렷한 관계가 잘 보이지 않았다.

Multiple Logistic Regression 결과에서도 Income의 p-value가 크게 나타난다.

즉 이 Model과 Dataset에서는 Income의 유의한 관계를 강하게 확인하기 어렵다는 방향으로 설명한다.

---

# 55. Student 변수

Multiple Logistic Regression에서는 Student 여부도 Feature로 추가한다.

분석 결과 강의에서는 Student 변수의 p-value가 `0.05`보다 작게 나타난 사례를 설명한다.

따라서 통계적으로 유의미한 Feature로 해석한다.

---

# 56. Student Coefficient가 Negative라는 의미

Student Coefficient가 Negative라면 다른 변수들이 동일하다는 조건에서

```text
Student
→ Default Log Odds 감소 방향
```

으로 해석한다.

강의에서는 같은 Balance 등을 가진 사람을 비교했을 때 Student인 경우 Default할 가능성이 낮아지는 방향이라고 설명한다.

---

# 57. 왜 “다른 조건이 동일할 때”가 중요한가?

Multiple Regression에서는 여러 Feature를 한꺼번에 사용한다.

따라서 `β₂`를 해석할 때는

```text
x₁, x₃, ..., xₚ를 고정
```

한 상태에서 `x₂`만 변화시키는 관점으로 해석해야 한다.

이는 Multiple Linear Regression에서 배운 Coefficient 해석과 같다.

---

# 58. Linear Regression과 Logistic Regression 비교

|항목|Linear Regression|Logistic Regression|
|---|---|---|
|문제|Regression|Classification|
|Target|숫자|Category|
|기본 함수|Linear|Linear + Sigmoid|
|출력|실수|Probability|
|출력 범위|제한 없음|0~1|
|학습 대상|β|β|
|학습 기준|RSS 최소화|Likelihood 최대화|
|대표 추정법|Least Squares|MLE|
|Closed-form|강의에서 가능|강의에서 없음|
|계수 기본 해석|y 변화량|Log Odds 변화량|

# 59. Sigmoid / Probability / Logit 관계

전체 구조를 반드시 연결해서 기억해야 한다.

```text
z
=
β₀ + β₁x
      ↓
Sigmoid
      ↓
p
=
P(Y=1|x)
      ↓
Odds
p/(1-p)
      ↓
Log
      ↓
Logit
=
log[p/(1-p)]
      ↓
다시
β₀ + β₁x
```

즉

> **Probability는 Sigmoid 형태이지만 Log Odds 공간에서는 Linear하다.**

---

# 60. Least Squares와 MLE의 구조적 차이

## Linear Regression

실제 숫자 `y`와 예측 숫자 `ŷ` 사이의 거리가 중요하다.

```text
Prediction Error
↓
Square
↓
RSS
↓
Minimum
```

## Logistic Regression

실제 Label에 Model이 얼마나 높은 Probability를 주었는지가 중요하다.

```text
실제 Label
↓
Model Probability
↓
Likelihood
↓
Maximum
```

---

# 61. 왜 Logistic Regression에 MLE가 자연스러운가?

실제 `y=1`인 Data에

```text
P(Y=1|x) = 0.99
```

를 주었다면 Model이 잘 설명한 것이다.

반대로

```text
P(Y=1|x) = 0.01
```

이라면 잘못 설명한 것이다.

따라서

> **실제로 관측된 결과에 높은 Probability를 부여하도록 Model Parameter를 결정한다.**

는 MLE의 사고방식이 Classification Probability Model과 잘 연결된다.

---

# 62. Likelihood에서 반드시 잡아야 할 직관

수식을 먼저 외우지 않고 다음만 기억해도 된다.

```text
실제 y=1
→ Model도 1 Probability를 높게

실제 y=0
→ Model도 0 Probability를 높게

모든 Data에서
이 Probability들을 함께 크게
      ↓
Likelihood 최대화
```

---

# 63. 자주 헷갈리는 점 ① — Logistic Regression은 Regression 문제인가?

최종 Task 기준으로는 **Classification**이다.

Regression이라는 이름은 내부적으로 Linear Predictor와 Coefficient를 이용하는 형태와 관련된다.

---

# 64. 자주 헷갈리는 점 ② — y를 0과 1로 바꾸면 Linear Regression으로 Classification하면 되지 않는가?

적절하지 않다.

Linear Regression Prediction은

```text
< 0
> 1
```

이 가능하기 때문에 Probability로서 유효한 범위를 보장하지 않는다.

Logistic Regression은 Sigmoid를 사용해서 Output을 항상 0~1로 제한한다.

---

# 65. 자주 헷갈리는 점 ③ — Logistic Regression은 0이나 1을 바로 출력하는가?

먼저 Probability를 계산한다.

```text
x
→ p(x)
```

그다음 Threshold를 적용해서

```text
p ≥ threshold
→ Class 1

p < threshold
→ Class 0
```

으로 변환할 수 있다.

---

# 66. 자주 헷갈리는 점 ④ — β=0.005면 Probability가 0.005씩 증가하는가?

아니다.

`β`는 **Log Odds 공간에서의 변화량**이다.

Probability는 Sigmoid를 거치므로 동일한 `x` 변화에도 위치에 따라 Probability 변화폭이 달라진다.

---

# 67. 자주 헷갈리는 점 ⑤ — Coefficient가 작으면 관계가 약한가?

그 숫자만으로 판단하면 안 된다.

Feature의 Unit에 따라 Coefficient의 수치는 크게 달라질 수 있다.

또 통계적 유의성은 Standard Error와 함께 보고 p-value 등을 확인해야 한다.

---

# 68. 자주 헷갈리는 점 ⑥ — Likelihood는 작게 해야 하는가?

아니다.

Likelihood는

> **현재 Model이 실제 관측 Data를 얼마나 그럴듯하게 설명하는가**

의 관점이므로 **크게 만들고 싶다.**

```text
RSS
→ 최소화

Likelihood
→ 최대화
```

를 구분해야 한다.

---

# 69. 자주 헷갈리는 점 ⑦ — Log를 씌우면 최적의 β가 바뀌지 않는가?

바뀌지 않는다.

Log는 Monotonic Increasing Function이므로

```text
Likelihood를 가장 크게 만드는 β
=
Log-Likelihood를 가장 크게 만드는 β
```

다.

그래서 계산하기 편한 Log-Likelihood를 사용한다.

---

# 70. 선형회귀에서 로지스틱회귀로의 연결

## 선형회귀

`ŷ = β₀ + β₁x`

문제:

```text
숫자 Prediction
```

---

## Classification에 그대로 사용

`ŷ = β₀ + β₁x`

문제:

```text
ŷ < 0 가능
ŷ > 1 가능

→ Probability로 부적절
```

---

## Sigmoid 추가

`p(x) = σ(β₀ + β₁x)`

이제

`0 < p(x) < 1`

이므로 Probability로 사용할 수 있다.

이것이 Logistic Regression의 출발점이다.

# 72. 선형회귀와 로지스틱회귀에서 β의 공통점과 차이

## 공통점

둘 다

```text
β₀, β₁, ...
```

이라는 Parameter를 Data로부터 학습한다.

## 차이

Linear Regression:

```text
β₁
→ x 1 증가 시 y의 평균적인 변화
```

Logistic Regression:

```text
β₁
→ x 1 증가 시 Log Odds의 변화
```

즉 Parameter는 비슷해 보여도 **Output Space가 다르기 때문에 해석이 다르다.**

# 74. 이번 강의에서 반드시 기억할 핵심

### 1. Logistic Regression은 Classification 방법이다.

이름에 Regression이 있지만 Target은 Category다.

### 2. Linear Regression을 Binary Classification에 그대로 쓰면 Output이 0~1을 벗어날 수 있다.

따라서 Probability Model로 부적절하다.

### 3. Sigmoid는 모든 실수 Input을 0~1 사이로 변환한다.

`σ(z)=1/(1+e^-z)`

### 4. Logistic Regression은 Linear Function에 Sigmoid를 적용한다.

```text
β₀ + β₁x
→ Sigmoid
→ Probability
```

### 5. `p(x)`는 일반적으로 `P(Y=1|X=x)`다.

### 6. Odds는 `p/(1-p)`다.

### 7. Log Odds가 Logit이다.

`log[p/(1-p)]`

### 8. Logistic Regression의 Logit은 Linear하다.

`logit(p)=β₀+β₁x`

### 9. β는 Probability의 직접 변화량이 아니다.

`x`가 1 증가하면 Log Odds가 β만큼 변화한다.

### 10. Logistic Regression은 RSS가 아니라 Likelihood를 사용한다.

### 11. Likelihood는 실제로 관측된 Label에 높은 Probability를 주도록 만든다.

```text
실제 1 → p ↑
실제 0 → 1-p ↑
```

### 12. MLE는 Likelihood를 최대화하는 β를 찾는다.

### 13. 계산 편의를 위해 Log-Likelihood를 사용한다.

Log는 곱을 합으로 바꾼다.

### 14. Likelihood와 Log-Likelihood의 최적 β는 같다.

Log가 단조증가하기 때문이다.

### 15. Logistic Regression에는 선형회귀와 같은 단순 Closed-form Solution이 없다.

반복적인 Numerical Optimization이 필요하며 이후 Gradient Descent와 연결된다.

### 16. Multiple Logistic Regression은 Linear Predictor 안에 여러 Feature를 넣으면 된다.

`β₀ + β₁x₁ + ... + βₚxₚ`

# 76. 이번 강의의 핵심을 한 문장으로

> **로지스틱 회귀는 범주형 Target을 예측하기 위해 선형식 `β₀+β₁x`를 Sigmoid 함수로 0~1의 확률로 변환하는 분류 모델이며, Logit 공간에서는 이 관계가 다시 선형이 되고, 실제 1에는 높은 확률을, 실제 0에는 낮은 확률을 부여하도록 Likelihood를 최대화하는 β를 Maximum Likelihood Estimation으로 학습한다.**

가장 짧게 선형회귀와 대비하면

```text
선형회귀
직선 + RSS 최소화

로지스틱회귀
직선 + Sigmoid + Likelihood 최대화
```

라고 잡으면 된다.
