## 0. 학습 시작

**머신러닝의 순환(loop)**: 데이터를 이용해 모델을 학습하고, 평가 결과를 바탕으로 데이터·모델·학습 방법을 반복적으로 개선하는 과정

$$\text{데이터} \to \text{모델} \to \text{학습} \to \text{평가} \to (\text{다시 모델로 피드백})$$

- **데이터**: 학습에 쓸 원재료
- **모델**: 데이터를 어떤 함수 형태로 표현할지 정의 (선형회귀, shallow/deep network 등)
- **학습**: 정의한 모델의 파라미터를 데이터에 맞게 최적화 (경사하강법 등)
- **평가**: 학습된 모델의 성능 측정

→ 평가 결과가 다시 모델 단계로 피드백되는 구조 — 한 번 돌리고 끝나는 게 아니라 **반복적 개선 과정**이라는 게 핵심

## 1. AI, ML, DL의 정의

- **AI (Artificial Intelligence)**: 주어진 환경/데이터를 인지·학습·추론을 통해 목표 달성을 하도록 예측·행동 선택·계획하는 시스템 (가장 넓은 범주)
- **ML (Machine Learning)**: AI 범주 내에서 **데이터로부터 학습**하여 목적을 달성하는 접근 방법론
    - 예: 생성형 AI, 언어 모델, 이미지 분류 모델, 추천 시스템
- **DL (Deep Learning)**: ML 범주 내에서 **신경망(Neural Network) 함수**를 사용한 학습 방법론
- 포함 관계: $AI \supset ML \supset DL$ (동심원 구조)

> [!question]+ ML이 아닌 AI도 있다? — ML을 가르는 진짜 기준
> 
> **ML이 아닌 AI 시스템의 예**: 규칙 기반 시스템, 휴리스틱 기반(최적화) 알고리즘
> 
> - 이런 시스템도 "지능적으로 문제를 해결"하니까 AI는 맞지만, **사람이 규칙·전략을 직접 설계**해서 동작함 → ML이 아님
> - 즉 ML을 가르는 기준은 "얼마나 똑똑한가"가 아니라 **"데이터로부터 스스로 학습하느냐"** — 이게 ML의 정의적 특징
> - 지금까지 정리한 선형회귀·로지스틱회귀·shallow/deep network는 모두 이 ML(그중 신경망을 쓰는 건 DL) 원 안에 속하는 구체적 사례들

## 2. 데이터와 학습의 이해

### 2.1 데이터 구성 요소(Feature/Label)

- **데이터가 왜 중요한가**: 머신러닝은 규칙을 직접 코딩하지 않고 **데이터에서 규칙을 학습** → 데이터(Feature, Label)의 분포와 관계가 학습 결과 자체를 결정
- **Feature (피처, 특성)**: 모델이 예측에 사용하는 입력정보. 예측·판단의 근거/단서
- **Label (라벨, 목표값)**: 모델이 예측하려는 정답. 학습의 목표값

**학습된 모델의 활용 흐름** ([그림2-1])

1. 학습된 ML 모델에 새 데이터(Feature)를 넣어 값을 예측
2. **Predicted Values**(예측값)를 **Actual Values**(실제값)와 비교해 얼마나 맞았는지 확인

→ Feature = "모델에 넣는 것", Label = "모델이 맞혀야 하는 것(+ 나중에 예측과 비교하는 기준)"

### 2.2 ML 실생활 예시

|예시|Feature|Label|
|---|---|---|
|유튜브 추천|영상 정보(장르, 크리에이터, 조회수, 좋아요 수 등) + 사용자 정보(시청 이력, 구독 채널 등)|영상에 대한 사용자 피드백(시청 여부, 좋아요 클릭 여부)|
|스팸메일 분류|메일 제목, 발신자, 단어 빈도|스팸 / 정상|

- 유튜브 예시를 더 풀어보면, 시청 이력·시청 시간·좋아요 여부 같은 **여러 Feature가 "좋아하는지/싫어하는지"라는 Label 하나에 동시에 기여**하는 구조
- cf. 여러 Feature → 하나의 Label로 수렴하는 이 구조는, 다중선형회귀에서 여러 $x$가 하나의 $\hat y$를 만드는 것과 같은 원리 (18장 참고)

## 3. 단일 피쳐 기반 학습

### 3.1 1D 피쳐 기반 학습

- 1D = 1차원, Feature가 하나일 때 학습하는 가장 단순한 형태
- $\text{Income}_i = f^*(\text{Years of Education}_i) + \epsilon_i$
    - 데이터셋 $D={(\text{Years of Education}_i, \text{Income}_i)}_{i=1}^{30}$
    - $f^*$(미지의 참 함수): Feature-Label 사이 **실제 평균 관계**. 직접 관측 불가 — 오차 섞인 데이터(점)만 관측 가능
    - $\epsilon$(측정 오차): 측정기기 한계·환경 요인 등으로 섞이는 노이즈
    - 즉 **데이터 = 참 함수 + 오차**
- 질문: "관계를 잘 나타낸 함수 $f$는 무엇일까?" → 후보 함수 여러 개 중 가장 잘 맞는 걸 찾아야(학습해야) 함
    - 후보모델 1, 2(직선): 양 끝 구간에서 실제 데이터와 벌어짐
    - 후보모델 3(S자 곡선, 비선형): 양 끝의 평평해지는 패턴까지 포착 → 셋 중 데이터에 가장 밀착
- → 직선 하나로 못 잡는 곡률을 표현력 큰 함수가 잡아낸다는 구체적 예시 (선형→비선형/신경망으로 넘어가는 이유)

### 3.2 모델과 가설공간

- **학습(Learning)**: "입력(Feature) → 출력(Label)" 관계를 찾는 과정. 평균 관계를 하나의 함수로 표현하지만, 그런 함수 후보는 무수히 많음
- **가설 공간(Hypothesis Space, $\mathcal F$)**: 관계를 표현할 수 있는 **모든 후보 함수들의 모음** — 피쳐 공간과 라벨 공간 위에서 정의된 함수들의 집합
- **모델(Model)**: 가설공간 $\mathcal F$에 **속한 특정 함수 $f$** 하나

→ 가설공간 = "선택 가능한 함수 전체의 집합", 모델 = "그중 실제로 고른 함수 하나" (3.1의 "후보 함수들" = 가설공간, 그중 학습으로 고른 하나 = 모델)

- 그림 예시: 가설 공간의 예 = 무수히 많은 선형 함수들의 집합 $\mathcal F$ (연한 파란 직선들) / 모델의 예 = 그중 하나로 고정된 특정 선형 함수 $f$ (보라색 직선)

### 3.3 학습이란

- **학습**: 주어진 데이터에서 정답을 가장 잘 맞출 수 있도록 모델의 규칙을 조금씩 조정해가는 과정
- 흐름: 데이터 $D$ → 가설공간 $\mathcal F$ → 선택된 모델 $f$

**학습에 필요한 3가지**

|요소|설명|
|---|---|
|① 데이터(Data)|학습할 예시들(학력-수입 쌍 30개). 입력(특성)과 정답(라벨) 쌍으로 된 정답 모음|
|② 가설 공간(Hypothesis Space)|선택할 수 있는 모든 후보 함수들의 집합. "이 중에서 가장 좋은 함수를 찾아야 해"|
|③ 선택 기준(손실 함수)|어떤 함수가 더 좋은지 판단하는 척도. 예측값과 실제값의 차이를 측정|

**학습 과정 (5단계)**

1. 가설공간에서 하나의 함수를 선택
2. 그 함수로 데이터의 모든 예시를 예측
3. 손실함수로 틀린 정도 계산
4. 더 적게 틀리도록 함수의 파라미터 조정
5. 반복하여 최적의 모델 완성

**"데이터 → 가설공간 → 모델" 관점 정리**: 데이터가 제시한 문제를, 가설공간이 제공한 선택지 중에서, 가장 잘 푸는 함수를 찾는 것이 학습

1. 데이터 $D$가 문제를 제시 — "교육 연수 12년 → 수입 2200만원" 같은 입력-출력 관계를 보여주는 데이터들
2. 가설공간 $\mathcal F$가 선택지를 제공 — 예: "$y=ax+b$" 형태의 모든 1차 함수(무수히 많은 후보 함수들의 집합)
3. 학습이 최적의 $f$를 선택 — $\mathcal F$ 내 후보 함수들을 데이터로 테스트해 예측 오차를 계산하고, 오차가 가장 작은 함수 하나를 찾아냄

→ **학습 전**: 가설공간 안의 여러 후보 직선이 뒤섞여 있는 상태 / **학습 후**: 예측 오차가 최소인 직선 하나로 수렴

cf. 여기서 말하는 "손실함수로 틀린 정도 계산 → 파라미터 조정"이 바로 17~21장에서 다룬 손실함수(MSE)·경사하강법의 흐름과 동일한 과정

## 4. 복수 피쳐 기반 학습

### 4.1 2D 피쳐 기반 학습

- $\text{Income} = f^_(\text{Years of Education}, \text{Seniority}) + \epsilon$ — 3.1의 1D 구조를 **피쳐 2개**로 확장, 참함수 $f^_$가 곡선이 아니라 3D **곡면(surface)**
- 파란 surface(참함수)는 관측 불가, 빨간 점(데이터)만 관측 가능 — "데이터 = 참함수 + 오차" 구조는 동일
- 학습 전: 어떤 가설공간 $\mathcal F$을 쓸까 / 학습 후: 데이터로 어떤 모델 $f$을 선택할까

**가설공간 비교 (핵심)**

|가설공간|표현 가능한 모델 형태|
|---|---|
|선형함수 가설공간|어떤 모델을 골라도 결국 평평한 판(plane) → 데이터의 굴곡을 못 잡음|
|비선형함수 가설공간|굽어지는 곡면까지 표현 가능 → 데이터에 훨씬 잘 밀착|

→ **가설공간을 무엇으로 고르느냐 자체가 표현력의 한계를 결정**한다는 포인트 — 선형 가설공간 안에서 아무리 최선을 찾아도 평면 이상은 못 넘음 (20~22장 "표현력" 논의와 연결)

### 4.2 일반적 용어 정리 및 모델 가정

- 표기 일반화: $\text{Income}=f^_(\text{Years of Education}, \text{Seniority}, \ldots)+\epsilon ;\to; Y=f^_(X)+\epsilon$

|기호|의미|
|---|---|
|$Y$|예측하려는 라벨(반응/목표) 변수 (예: Income)|
|$X_1, X_2, \ldots, X_i$|첫 번째, 두 번째, … $i$번째 피쳐(입력) 변수|
|$\boldsymbol X=[X_1,X_2,\ldots,X_p]^\top\in\mathbb R^p$|일반적인 $p$차원 피쳐 벡터 (총 $p$개 피쳐)|
|$f^*:\mathbb R^p\to\mathbb R$|모델(함수형). $Y=f^*(\boldsymbol X)+\epsilon$|
|$\epsilon$|측정오차. **피쳐 $\boldsymbol X$와 독립**이고 $\mathbb E[\epsilon]=0$으로 가정|

→ 지금까지 1D(피쳐 1개)·2D(피쳐 2개) 예시로 봐온 것들이 사실 이 $Y=f^*(\boldsymbol X)+\epsilon$ 하나의 일반식의 특수 사례(p=1, p=2)였을 뿐

### 4.3 왜 $f(X)$를 학습하는가?

$f$를 학습하는 이유는 크게 세 가지:

- **예측**: 잘 학습된 $f$가 있으면, 새로운 입력 $X=x$에서 반응/목표 $Y$를 예측할 수 있음
- **중요 특성 파악**: 피쳐들 $\boldsymbol X=(X_1,X_2,\ldots,X_p)$ 중 어떤 특성이 $Y$를 설명하는 데 중요하고, 어떤 건 덜 중요(무관)한지 알 수 있음
    - 예: 근속 연수, 교육 연수는 소득에 큰 영향을 줄 수 있지만, 혼인 여부는 영향이 거의 없을 것
- **해석 가능성**: $f$의 복잡도에 따라 각 구성요소 $X_i$가 $Y$에 어떻게 영향을 미치는지(증가/감소 방향, 민감도 등) 이해할 수 있음

## 5. 지도학습의 개념

### 5.1 지도학습의 정의와 특징

- **지도학습(Supervised learning)**: 정답 라벨이 있는 훈련 데이터를 사용해 예측 모델을 학습하는 방법
- **목표**: 훈련 데이터로 학습한 모델이 **새로운 데이터**에서도 정확한 예측을 수행
- 데이터: 입력(feature, $X$)과 정답(label, $Y$)이 항상 쌍으로 존재, 여러 개가 축적돼 있음

**흐름** ([그림1-1])

훈련 데이터(Train Set, 레이블링) → 학습(신경망 등 알고리즘) → 모델 생성 및 적용 → 테스트 데이터(Test Set)에 적용 → 결과 확인(새로운 데이터에서도 정답을 맞춤)

### 5.2 지도학습의 종류 (회귀 vs 분류)

|구분|사용 시점|예시|
|---|---|---|
|**회귀(Regression)**|예측하고 싶은 결과값이 **숫자**일 때|가격, 점수, 온도 (예: 공부시간→시험점수, 4시간 → ?점 예측)|
|**분류(Classification)**|예측하고 싶은 결과값이 **범주**일 때|스팸/정상, 질병 유/무 (예: 이메일 스팸분류, 고양이/강아지/햄스터 분류)|

### 5.3 손실 함수(Loss Function)

- **손실 함수**: 모델의 예측이 정답에서 얼마나 벗어났는지 하나의 숫자로 나타내는 함수
- **학습**: 이 숫자(손실)가 작아지는 방향으로 모델을 조금씩 고쳐 나가는 과정

**문제 유형에 따라 쓰는 손실이 다르다**

|문제 유형|손실함수|수식|의미|
|---|---|---|---|
|회귀|평균제곱오차(MSE)|$\text{MSE}=\frac1n\sum(y-\hat y)^2$|정답과 예측의 차이를 제곱해서 평균낸 값. 많이 틀릴수록 제곱 때문에 손실이 크게 커짐|
|분류|교차 엔트로피(Cross Entropy)|$CE=-\sum y\log(\hat y)$|정답 범주에 얼마나 높은 확률을 주었는지 측정. 정답을 확신할수록 0에 가까워짐|

cf. MSE는 6장(회귀), 교차 엔트로피는 7장(분류)에서 자세히 다룸

### 5.4 지도학습 용어

- **특성(Feature, $x$)**: 예측에 사용되는 설명 변수, 예측 함수 $f$의 input으로 들어가는 변수
    - 예: 집값 예측의 feature {지역, 평수, 방수, 연식} / 이메일 스팸 필터링의 feature {제목, 내용 텍스트, 송신인}
- **라벨(Label, $y$)**: 맞춰야 하는 정답(실제값). 예: 집값, 스팸/정상 이메일
- **예측값($\hat y$)**: 학습 과정에서 모델이 내놓은 결과(숫자 또는 범주) — $y$의 추정치
- **오류(Error)**: 손실 함수로 계산, $\hat y - y$

> [!question]+ 오류(Error) ≠ 측정오차($\epsilon$)
> 
> - 오류는 **예측값과 실제값의 차이**($\hat y - y$)로, 손실함수로 계산해 학습 과정에서 줄여나가는 대상
> - 측정오차 $\epsilon$은 데이터 자체에 이미 섞여 있는 노이즈(3~4장 참고)로, 아무리 학습을 잘 해도 줄이거나 제거할 수 없음
> - 즉 지도학습의 목표는 예측값과 실제값의 차이(오류)를 줄이는 것이지, 데이터에 내재된 측정오차를 없애는 게 아님

## 6. 회귀(Regression)

### 6.1 회귀의 정의와 예시

> [!info] 슬라이드 추가되면 정리 예정

### 6.2 MSE

- 예측이 얼마나 정확한지 판단하려면 모델의 예측 정확도를 **숫자로 측정하는 지표**가 필요
- 오류 $e_i=y_i-\hat y_i$ (실제 값 − 예측 값)
- **MSE(평균제곱오차)** $=\dfrac1n\sum_{i=1}^n(y_i-\hat y_i)^2$: 각 데이터에서 정답($y_i$)과 예측($\hat y_i$)의 평균 제곱 차이값
    - 틀린 정도를 제곱해서 더 큰 오류에 패널티 부여 → 전체 평균 오류 수준을 한눈에 볼 수 있음
    - 오류가 작을수록 정확한 예측 → **오류를 줄이는 것이 학습의 목표**

> [!question]+ MSE 단위가 제곱이라 해석이 어렵다면?
> 
> 원래 데이터와 같은 단위라서 해석이 쉬운 **RMSE(MSE의 제곱근)**도 사용 $$\text{RMSE}=\sqrt{\text{MSE}}=\sqrt{\frac1n\sum_{i=1}^n(y_i-\hat y_i)^2}$$ (R은 root를 의미)

### 6.3 $R^2$

- **결정계수($R^2$)**: Label($y$)의 분산 중에서 Feature로 설명되는 비율
- "평균만 쓰는 단순한 예측"보다 모델이 실제값을 얼마나 더 잘 맞추는지를 **0~1 사이 값**으로 나타냄
- 1에 가까울수록 설명력이 높고, 낮을수록 설명력이 낮음

$$R^2=1-\frac{\sum_{i=1}^n(y_i-\hat y_i)^2}{\sum_{i=1}^n(y_i-\bar y)^2}\qquad(\bar y = y_i\text{들의 평균값})$$

- 분자: 모델의 예측 오차 제곱합 / 분모: 평균값만으로 예측했을 때의 오차 제곱합(=데이터 자체의 분산)

> [!question]+ $R^2$가 음수가 나올 수 있을까?
> 
> 나올 수 있음. 예측값($\hat y_i$)들이 **평균값 $\bar y$보다도 못하다면** — 즉 모델이 그냥 평균으로 찍는 것보다도 예측을 못하면, 분자(모델 오차)가 분모(평균 예측 오차)보다 커져서 $R^2=1-(\text{1보다 큰 값})$이 음수가 됨

### 6.4 MSE vs $R^2$

- MSE, $R^2$ 둘 다 모델의 정확도를 평가하기 위한 정량 지표

|항목|MSE|$R^2$|
|---|---|---|
|정의|예측값과 실제값 차이의 제곱 평균|평균 예측 대비 모델의 상대적 성능|
|값 범위|$0\sim\infty$|$0\sim1$|
|단위|실제 데이터 단위$^2$|단위 없음|
|해석|절댓값(구체적 오차 크기)|상대적 비율(성능 정도)|
|좋은 값|0에 가까울수록 좋음|1에 가까울수록 좋음|
|장점|구체적 오차 크기를 알 수 있음|직관적 해석, 모델 간 비교 쉬움|
|단점|직관적 해석이 어려움|구체적 오차 크기는 모름|

**예시**: 집값 예측에서 "$\text{MSE}=(1000\text{만원})^2$"만으로는 좋은 모델인지 애매하지만, "$R^2=0.8$"이면 "모델이 데이터 변동의 80%를 설명한다"는 뜻이라 곧바로 "꽤 좋은 모델"이라고 판단할 수 있음

**언제 쓸까**

- **MSE**: 구체적인 오차 크기가 중요할 때, 실제 손실 비용을 계산할 때
- **$R^2$**: 모델 성능을 직관적으로 평가할 때, 여러 모델을 비교할 때, 모델이 전반적으로 얼마나 좋을지 알고 싶을 때

→ 둘은 경쟁 지표가 아니라, 필요에 따라 **상호 보완적으로 함께 사용**

## 7. 분류(Classification)

### 7.1 분류의 정의와 특징

- **분류(Classification)**: 입력 특성(Feature)으로부터 출력이 **범주값(카테고리)**으로 나타나는 예측 문제
- 특징: 범주 라벨(이진/다중) — 분류 모델에서 라벨은 미리 정해진 범주(카테고리) 중 하나의 값을 가짐

**이진 라벨 예시**

|예시|Feature|Label|
|---|---|---|
|스팸메일 분류|내용, 메일주소, 작성자|스팸 / 정상|
|의학 예시(종양 진단)|종양 반경, 면적, 색상|악성 / 양성|

**다중 라벨 예시** — 학점 예측: Feature(출석률, 과제 점수, 중간고사 점수) → Label(학점 A/B/C)

- **결정 경계(Decision Boundary)**: 서로 다른 클래스(범주)를 구분하는 경계선. 분류모델은 이 선을 기준으로 데이터를 구분함 ([그림3-1])

### 7.2 분류 정확도(Accuracy)

- 분류모델은 Label이 범주로 돼 있어서 MSE나 $R^2$를 그대로 사용하기 어려움
- **정확도(Accuracy)**: 전체 예측 중에서 올바르게 맞춘 예측의 비율

$$\text{Accuracy}=\frac1n\sum_{i=1}^n\mathbb I(y_i=\hat y_i)$$

- $\mathbb I$(지시함수, indicator function): 조건이 참이면 1, 거짓이면 0을 반환
    - $\mathbb I(y_i=\hat y_i)=1$ (실제값=예측값, 맞춤) / $\mathbb I(y_i\neq\hat y_i)=0$ (실제값≠예측값, 틀림)
- 예: 실제=고양이, 예측=고양이 → $\mathbb I(\text{고양이}=\text{고양이})=1$(맞춤) / 실제=고양이, 예측=강아지 → $\mathbb I(\text{고양이}\neq\text{강아지})=0$(틀림)

> [!question]+ 정확도 99%면 좋은 모델일까? — 정확도의 함정(불균형 데이터 문제)
> 
> 아니다. **불균형 데이터**에서는 정확도가 높아 보여도 실제로는 쓸모없는 모델일 수 있음
> 
> - 질병 진단 데이터 1000명 (실제 환자 10명=1%, 건강한 사람 990명=99%)
> - 무조건 모든 사람을 "건강하다"고만 예측하는 문제 있는 모델이라도: 질병 환자 10명은 전부 틀리고, 건강한 990명은 다 맞음 → $\text{Accuracy}=990/1000=99\%$
> - 정확도는 99%지만 **질병 환자를 전부 놓침** — 실제로 중요한 "질병 발견" 능력이 전혀 없는 모델
> - 결론: 정확도는 단순히 "전체 중 맞춘 비율"만 계산하는 지표라, 불균형 데이터에서는 다른 지표(혼동행렬, 7.3 참고)도 함께 봐야 안전

### 7.3 혼동행렬

- **혼동행렬(Confusion Matrix)**: 예측과 실제 값 사이의 관계를 행렬 형태로 표현 ([그림3-2])
- **TP**(True Positive): 실제 양성, 예측도 양성
- **TN**(True Negative): 실제 음성, 예측도 음성
- **FP**(False Positive, Type I Error): 실제는 음성인데 양성이라 함 (오탐)
- **FN**(False Negative, Type II Error): 실제는 양성인데 음성이라 함 (누락)

| 파생 지표            | 수식                  | 의미                    | 비고                                                                                        | 상황                                                            |
| ---------------- | ------------------- | --------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Sensitivity(재현율) | $TP/(TP+FN)$        | 진짜 양성 가운데 잡아낸 비율      | FN를 줄이는게 목표(틀리지 않는것)<br>FP는 어느정도 용서<br>실수로 잡는건 괜찮아 놓치지는 마                                 | 암 진단 모델에서 실제 암 환자를 정상이라고 하면 치명적. 즉 "의심 되면 걸러내라" -> 재현율 중요     |
| Specificity      | $TN/(TN+FP)$        | 진짜 음성 가운데 맞춘 비율       |                                                                                           |                                                               |
| Precision(정밀도)   | $TP/(TP+FP)$        | 맞추려고 의도한 것 중 맞은 것의 비율 | 정밀도가 낮으면 오탐 비율이 큰 것. FP를 줄이는게 목표(정확하게 맞추는것)<br>FN는 어느정도 용서<br>좀 놓치는건 괜찮아, 한번 잡을 때 정확하게 잡아 | 스팸 필터가 너무 강하면 정상 메일이 스팸으로 갈 수 있음. 즉 "확실할 때만 스팸처리해라" -> 정밀도 중요 |
| Accuracy(정확도)    | $(TP+TN)/\text{전체}$ | 전체 중 맞춘 비율            | 찍어서 맞춘 것도 포함, 단순하게 많이 맞추었는지 봄                                                             |                                                               |

- **정밀도(Precision)**: "양성이라 판정한 것 중" 진짜 양성의 비율 = $TP/(TP+FP)$
- **재현율(Sensitivity, Recall)**: "진짜 양성 가운데" 잡아낸 예측 양성의 비율 = $TP/(TP+FN)$


- **F1-score**: 정밀도와 재현율의 조화평균

$$F1=2\times\frac{\text{정밀도}\times\text{재현율}}{\text{정밀도}+\text{재현율}}$$

→ 7.2의 "정확도의 함정"(불균형 데이터)을 보완하는 지표들: 정확도만으론 놓치는 걸 재현율로 잡아낼 수 있음

> [!question]+ 정확도 99%의 함정, 재현율로 확인하면?
> 
> 7.2의 질병진단 시나리오(1000명 중 환자 10명, 건강 990명, 모델이 전원을 "건강"으로 예측)를 혼동행렬로 보면
> 
> - TP(실제 환자, 예측도 환자) = 0 — 모델이 애초에 아무도 "환자"로 예측하지 않음
> - FN(실제 환자인데 건강으로 예측, 누락) = 10 — 환자 10명을 전부 놓침
> - TN(실제 건강, 예측도 건강) = 990
> 
> $$\text{Recall}=\frac{TP}{TP+FN}=\frac{0}{0+10}=0\%$$
> 
> **정확도는 99%였지만 재현율은 0%** — 환자를 단 한 명도 잡아내지 못했다는 사실이 재현율에서는 그대로 드러남. 정확도 하나만 보면 숨겨지던 문제가 재현율을 같이 보면 바로 노출됨

>[!question]+ 재현율 100%의 함정
>**재현율만 보는 경우의 함정**: 반대로 모델이 무조건 전부 "양성(환자)"이라고 찍으면 어떻게 될까요?
>FN=0FN=0 FN=0이니 $$\text{재현율} = \dfrac{TP}{TP+0} = 100\%$$ 
>완벽해 보임 하지만 실제로는 건강한 990명까지 전부 환자로 오진 → 정밀도는 바닥을 침

>[!question]+ 정밀도 100%의 함정
>**아주 확실할 때만** "환자"라고 판정하고, 조금이라도 애매하면 전부 "건강"으로 넘겨버리는 극도로 보수적인 모델.
>그 결과 실제 환자 10명 중 **단 1명**만 자신 있게 "환자"로 잡아내고, 나머지 9명은 애매해서 "건강"으로 분류. 대신 확실한 그 1명은 진짜 환자였고, 건강한 990명 중 단 한 명도 잘못 환자로 찍지 않았다고 하면:

즉 정밀도와 재현율은 **트레이드오프 관계**(하나를 올리면 보통 다른 하나가 내려감 — 예: 판정 기준을 낮추면 재현율은 오르지만 정밀도는 떨어짐)라서, 둘 중 하나만 보면 그 지표를 극단적으로 밀어붙여서 "좋아 보이게" 만들 수 있는 여지가 있습니다.

>[!question]+ 왜 정밀도+재현율을 분모로 가지나요?
>왜 곱이 아니라 조화평균인지 물어보는것.
>핵심은 결과값을 정밀도와 재현율과 같은 스케일을 유지하면서 둘이 불균형할때 확실하게 낮게 나오도록 하기 위함
>ex : 곱만 쓰면 ${0.8}\times{0.8} = 0.64$ 로 나옴. 우리가 원하는건 0.8 그대로 나오길 원함
>그래서 조화평균을 사용





### 7.4 분류 손실: 교차 엔트로피(Cross Entropy)

- 정확도·혼동행렬은 학습이 **끝난 결과를 "평가"**하는 지표 — 맞음/틀림만 세므로, 예측 확률이 0.51에서 0.95로 좋아져도 값은 그대로임
- 학습 중에는 "정답을 얼마나 확신했는지"까지 반영하는 손실이 필요 → **교차 엔트로피(Cross Entropy)**
- 정답에 준 확률이 높을수록 손실이 작아지고, 확률이 낮으면 손실이 급격히 커짐

$$\text{손실}=-\log(\text{정답 범주에 준 확률})$$

|실제 정답|스팸일 확률 예측|손실 $-\log(p)$|
|---|---|---|
|스팸|0.9|0.11 (작음)|
|스팸|0.6|0.51|
|스팸|0.1|2.30 (큼)|

- cf. 회귀의 MSE에 해당하는, 분류의 대표 손실 함수 (5.3에서 이미 예고된 공식)
- 정리: **정확도·정밀도·재현율** = 결과를 "평가"하는 지표 / **교차 엔트로피** = 학습에서 "줄여나가는" 손실

## 8. 학습의 목적

### 8.1 학습의 목적

- **목적**: 훈련 데이터로 학습한 모델이 **새로운 데이터에서도 정확한 예측**을 수행하도록 하는 것
- 훈련이 잘 됐는지 확인하려면: 모델이 **처음 보는(학습에 사용되지 않은) 데이터**로 평가 — "이 모델이 훈련 상황 외에 새로운 상황에서도 잘 동작할까?"(**일반화**)를 검증
- 훈련 데이터에서 성능이 아무리 좋아도, 새로운 데이터에서 성능이 떨어지면 실전엔 사용할 수 없음 → **일반화(generalization) 오류의 최소화**를 지향
- cf. 일반화 성능을 추정(검증/교차검증)하는 방법은 다음 차시에서 다룰 예정

### 8.2 오버피팅(Overfitting)이란?

- **오버피팅**: 훈련 데이터의 **우연한 패턴/잡음까지 외워버려서**, 훈련에서는 잘 맞지만 **테스트에서는 성능이 나빠지는** 현상
- 현상: 훈련 오류는 급격히 낮아지는데, 테스트 오류는 높거나 요동침 ([그림4-1] — 초록색 함수가 데이터 잡음까지 구불구불 따라감)

**오버피팅이 왜 안 좋은가**

- **표본(sample) 의존·불안정**: 훈련 데이터는 모집단의 일부 표본이라 우연한 잡음이 섞여 있음. 여기에 과하게 맞춰 학습하면 샘플 몇 개만 바뀌어도 예측이 크게 흔들림(분산↑)
- **일반화 실패**: 보지 못한 데이터(테스트)에서 오류가 커지고, 모집단(population) 성능과의 격차가 벌어짐

### 8.3 오버피팅에 대한 오해

- **오버피팅 ≠ 분포 변화(distribution shift)로 인한 에러 증가**
- **분포 변화로 인한 오류**: 훈련 데이터 분포와 테스트 데이터 분포가 다름(환경·계절·센서 변경 등)으로 성능이 떨어지는 현상
- 이런 오류 증가는 **모델이 과적합하지 않아도** 발생 가능

> [!question]+ 오버피팅과 분포 변화, 뭐가 다른가?
> 
> 둘 다 "테스트 성능이 나쁘다"는 결과는 같지만 원인이 다름
> 
> - **오버피팅**: 모델이 훈련 데이터의 잡음까지 과하게 외워서 생기는 문제 — 모델 쪽 원인
> - **분포 변화**: 애초에 훈련 데이터와 테스트 데이터의 **성격 자체가 다름**(예: 훈련은 실사 고양이/강아지 사진, 테스트는 일러스트 그림체) — 데이터 쪽 원인
> - 아무리 모델이 훈련 데이터에 적당히만 맞춰졌어도(과적합이 아니어도), 테스트 데이터가 애초에 다른 분포에서 왔다면 성능이 떨어질 수 있음
> - 즉 테스트 성능이 나쁘다고 무조건 오버피팅으로 단정하면 안 되고, 두 데이터의 분포가 같은 조건에서 왔는지도 함께 확인해야 함

### 8.4 오버피팅 vs 언더피팅

- **오버피팅**: 모델이 너무 복잡 → 잡음까지 학습 (테스트 성능 나쁨)
- **언더피팅**: 모델이 단순하거나 학습이 완료되지 않음 → 중요한 패턴을 놓침 (오류 큼)
- [그림4-2]: 분류·회귀 각각에서 Overfitting(구불구불 과하게 복잡) / Right Fit(적당) / Underfitting(너무 단순) 비교

**해결 실마리**: 더 많은 데이터, 테스트 데이터를 활용한 모델 선정, 교차 검증(다음 차시에서 다룰 예정)

## 9. 테스트 성능 평가

**훈련 오류 vs 테스트 오류**

- **훈련 오류**: 모델을 학습시킨 **같은 데이터**에 다시 적용해 계산한 오류
- **테스트 오류**: 학습에 쓰지 않은 **새 관측치**에 대해 모델을 적용했을 때의 평균 예측오류
- 비유: 훈련 오류 = 문제집 점수, 테스트 오류 = 시험 점수 — **문제집만 잘 본다고 시험을 잘 본다고 장담할 수 없음**
- 보통 훈련 오류는 테스트 오류와 다르며, 특히 훈련 오류는 테스트 오류를 (심하게) 과소평가하는 경우가 많음 (예: 암기 vs 응용 시험)
- 예시로 떠올려보면: 모델이 학습에 쓰인 강아지/고양이 사진들은 이미 본 데이터라 잘 분류하지만, 학습에 쓰이지 않은 새로운 고양이 사진을 넣으면 "개"로 잘못 예측하는 경우가 생길 수 있음 — 이렇게 **같은 모델이라도 훈련 데이터에서 잰 오차와 테스트 데이터에서 잰 오차는 서로 다르다**는 걸 보여주는 예시

**훈련오류 vs 테스트오류의 관계 (그래프로 보면)**

- 가로축을 모델 복잡도, 세로축을 오류(Prediction Error)로 두고 두 개의 선을 그리면: **훈련 오류 선**은 모델이 복잡해질수록 계속 낮아지기만 하고, **테스트 오류 선**은 처음엔 낮아지다가 어느 지점부터 다시 높아지는 **U자 모양**을 그림
- 모델이 단순한 쪽(왼쪽 구간)은 High Bias·Low Variance, 모델이 복잡한 쪽(오른쪽 구간)은 Low Bias·High Variance 특성을 보임
- **목적**: 테스트 오류 U자형의 **바닥**이 되는 적절한 모델 찾기 — 너무 많이 답을 외우지도(과적합) 않고, 너무 대충 공부하지도 않은(과소적합) 딱 적당한 지점

cf. 이 U자 곡선이 8.4의 오버피팅(오른쪽 끝)·언더피팅(왼쪽 끝) 개념을 하나의 그래프로 종합해서 보여주는 것 — 딱 맞는 지점(Right Fit)이 U자의 바닥

**테스트 예측 오류 계산의 현실적 문제와 대안**

- 이상적 케이스: 충분히 큰 별도 테스트 데이터셋 → 현실에선 구하기 어려움
- 현실에서는 테스트만을 위한 데이터를 따로 갖기에 데이터 자체가 부족할 수 있음
- **대안: 재표본화(resampling)를 통한 테스트 오류 추정**
    - 데이터를 나눠 여러 번 "훈련→평가"를 반복해 테스트 오류를 가늠
    - 비유: "시험용 문제가 따로 없다면? → 기존 문제집의 문제들을 활용해 모의고사를 보자!"
    - 방법: 검증셋(hold-out), K겹 교차검증(K-fold Cross-Validation) — 각각 10장, 11장에서 다룰 예정
    - 장점: 별도의 테스트 데이터 없이 **데이터를 더 효율적으로 사용**하여 일반화 오차 추정

## 10. 검증셋(validation set) 접근

### 10.1 검증셋(Validation Set) 방법

- **검증셋(홀드아웃) 방법**: 가용 샘플들을 무작위로 **훈련셋**과 **검증셋(hold-out)**으로 분할
    - 비유: 문제집의 문제들을 모의고사용과 학습용으로 나누고, 모의고사는 딱 1번만 보기
- **훈련셋**으로 모델 적합, **검증셋**으로 예측 후 **검증 오류**를 계산
- 검증 오류는 보통 정량 반응은 **MSE**, 범주 반응은 **오분류율(또는 F1-score)**을 측정
- 예시로 떠올려보면: 고양이 사진 8장이 있을 때 이 중 절반은 파란색(훈련셋)으로, 나머지 절반은 주황색(검증셋)으로 나눠서 — 훈련셋으로 학습하고 검증셋으로 성능을 재는 홀드아웃 방식

### 10.2 검증셋 절차

- 데이터 순서를 무작위로 **셔플링**한 후, 앞부분은 훈련셋(파랑)으로, 나머지 뒷부분은 검증셋(주황)으로 두 부분으로 분할
- 학습은 **훈련셋**에서, 성능평가는 **검증셋**에서 수행
- 예시로 떠올려보면: 1번부터 n번까지 순서대로 놓인 데이터를 셔플링하면 순서가 뒤섞이고(예: 7, 22, 13, ...), 뒤섞인 데이터 중 앞부분은 훈련셋으로, 나머지 뒷부분(예: 91번 등)은 검증셋으로 나눔

### 10.3 검증셋 방법 예시

- 예시: 자동차 데이터 — 목표: **선형(1차)모델**부터 **고차항(다항식) 모델**까지 비교
- 392개 데이터를 무작위로 196개 훈련셋 / 196개 검증셋으로 분할 (일반적으로 반으로 나눌 필요는 없음)
- 단 한 번만 분할해서 MSE를 그려보면: 다항식 차수가 2 정도 되는 지점에서 MSE가 급격히 떨어진 뒤 완만해지는 **곡선 하나**가 나옴
- 그런데 셔플을 바꿔가며 이 분할을 **여러 번 반복**해서 나온 MSE 곡선들을 겹쳐 그려보면, 곡선마다 절대적인 MSE 값과 모양이 상당히 다르게 나타남 — 즉 어떻게 나누느냐에 따라 결과가 요동침

### 10.4 검증셋 접근의 한계

- 예시에서 보이는 검증셋 방법의 단점: 어떤 표본이 훈련/검증에 들어가느냐에 따라 **검증 기반 테스트 오류 추정치가 매우 가변적**(10.3에서 본 것처럼, 분할을 바꿀 때마다 MSE 곡선이 들쭉날쭉하게 달라짐)
- 검증 접근에서는 훈련셋(=전체의 일부)만으로 모델을 적합하므로, 전체 데이터로 학습했을 때보다 **성능이 낮게 추정**(즉, 테스트 오류를 과대 추정)될 수 있음

> [!question]+ 왜 전체 데이터로 학습한 모델의 테스트 오류를 과대 추정하는 경향이 있을까?
> 
> → 학습에 데이터를 **부분만** 사용하기 때문
> 
> 예: 훈련셋을 전체의 1/2만 사용한 경우, 전체 데이터로 학습한 경우보다 예측 성능이 매우 낮을 것임 — 데이터가 적을수록 모델이 패턴을 덜 학습하므로, 검증셋으로 잰 오류가 "전체 데이터로 학습했다면 나왔을 진짜 성능"보다 나쁘게(과대) 나옴

cf. 이 두 가지 한계(추정치가 가변적, 오류가 과대 추정됨)를 보완하는 방법이 다음 11장의 K-겹 교차검증

---

## 11. K-겹 교차검증 (K-fold Cross-Validation)

### 11.1 K-겹 교차검증 개념과 절차

- 10.4에서 본 검증셋(홀드아웃)의 한계 — 추정치가 가변적이고 테스트 오류를 **과대 추정**하는 문제(= 훈련용 데이터를 일부만 써서 학습하다 보니, 전체 데이터로 학습했을 때보다 오류가 더 크게 측정되는 것) — 를 보완하는 **테스트 오류 추정의 표준적 접근**
- 비유: 문제집을 5등분해서 서로 다른 모의고사를 5번 보는 것 (홀드아웃이 "모의고사 딱 1번"이었다면, K-겹은 "모의고사를 여러 번, 매번 다른 조합으로")
- 추정치는 **모델 선택**과 **최종 모델의 테스트 오류 규모 파악**에 활용

**절차**

1. 데이터를 먼저 **셔플링**한 뒤, 총 $n$개의 데이터를 겹치지 않는 $K$개의 동일한 크기 그룹("폴드")으로 분할
2. 폴드 $k\in{1,2,\ldots,K}$ 하나를 **검증셋**으로, 나머지 $K-1$개 폴드 전부를 **훈련셋**으로 사용해 학습·평가
3. $k=1,\ldots,K$에 대해 이 과정을 **반복** — 매번 다른 폴드가 돌아가며 검증셋이 되고, 나머지가 훈련셋이 됨 (예: $K=5$면 5번 반복하면서 폴드1이 검증셋인 경우, 폴드2가 검증셋인 경우, ... 순서로 진행)
4. $K$개의 MSE를 **평균**해서 테스트 오류를 추정

한 번만 나누는 홀드아웃과 달리 모든 데이터가 결국 한 번씩은 검증에 쓰이고, 여러 번의 평가를 평균 내기 때문에 추정치가 훨씬 안정적임

### 11.2 K-겹 교차검증 오류 계산

$$\text{CV}(K)=\sum_{k=1}^K \frac{n_k}{n}\text{MSE}_k$$

- $\text{MSE}_k=\dfrac{1}{n_k}\sum_{i\in C_k}(y_i-\hat y_i)^2$: $k$번째 폴드 $C_k$(크기 $n_k$)를 검증셋으로 두고, 나머지로 적합한 모델의 예측 오차
- 각 폴드의 MSE를 폴드 크기 비율($n_k/n$)로 가중평균 — 폴드 크기가 다 같으면 단순 평균과 동일

> [!question]+ $K=n$이면? — LOOCV
> 
> 폴드 개수를 데이터 개수만큼(즉 $K=n$) 늘리면 **Leave-One-Out 교차검증(LOOCV)**이 됨. "100개 문제로 100개의 서로 다른 모의고사를 만드는 것"과 같은 비유 — 검증셋 크기가 정확히 **1**인 극단적인 K-fold

### 11.3 Leave-One-Out 교차검증 (LOOCV)

- **훈련셋**: 관측치 하나만 제외한 나머지 전부
- **검증셋**: 제외한 딱 1개 관측치
- 이 과정을 **$n$번** 반복 — 매번 정확히 하나의 관측치만 검증셋이 되고 나머지 전부가 훈련셋이 됨 (1번째 반복은 첫 번째 관측치, 2번째 반복은 두 번째 관측치, ... 순서로)
- $n$개의 MSE를 평균해서 테스트 오류를 추정

거의 모든 데이터를 써서 학습하니 편향은 적지만, 모델을 $n$번이나 다시 학습시켜야 해서 연산량이 크다는 트레이드오프가 있음

### 11.4 K-겹 교차검증 비교

**LOOCV vs 10-겹 CV (실측 비교)**

- 자동차 데이터에서 LOOCV(1문제짜리 모의고사 100개)와 10-겹 CV(10문제짜리 모의고사 10개)로 다항식 차수에 따른 MSE 곡선을 각각 그려 비교
- 두 방법의 **경향과 최적 차수가 거의 비슷**하게 나옴
- LOOCV는 모든 데이터를 검증에 활용하지만 연산량이 많아 학습 시간이 오래 걸림
- → LOOCV가 10-겹 CV 대비 **큰 성능 향상이 없으므로**, 적절한 $K$를 골라 K-겹 CV를 쓰는 게 실용적으로 더 좋음

**시뮬레이션: 참(진짜) 테스트 MSE vs 추정 MSE**

- 세 가지 서로 다른 데이터 상황에서, "진짜 테스트 MSE"와 "LOOCV로 추정한 MSE", "10-겹 CV로 추정한 MSE"를 겹쳐서 비교
- 세 상황 모두에서 LOOCV 추정 곡선과 10-겹 CV 추정 곡선이 거의 겹치고, 최솟값이 나오는 위치(최적 모델 복잡도)도 거의 일치
- 결론: **10-겹 CV 추정이 진짜 테스트 성능을 잘 근사하면서도 계산은 훨씬 가벼운, 실전에서 좋은 대안**

**전체 흐름 정리**: 홀드아웃(10장, 1번만 분할) → K-겹 CV(11장, 여러 번 나눠 평균) → LOOCV(K=n인 극단 케이스) → 실전에서는 계산 효율 때문에 보통 $K=5$나 $10$ 정도의 K-겹 CV를 사용

## 12. 비지도 학습

**비지도학습이란?**

- **정의**: 레이블(정답) 없이 데이터의 구조·패턴·집단(잠재 서브그룹)을 찾아내는 학습
- **대표 과제**: 군집화(clustering), 차원축소(PCA 등), 밀도추정/이상치 탐지
- **출력**: "정답 예측"이 아니라 **구조/요약/표현(embedding)**

**핵심 질문 3가지**

- 무엇을 비슷함/다름으로 볼 것인가 (거리·유사도를 어떻게 정의할지)
    
- 전처리(스케일 표준화 등)를 어떻게 할 것인가
    
- 결국 출력은 "정답"이 아니라 구조/요약/표현이라는 점
    
- 예시로 떠올려보면: 붓꽃(iris) 데이터를 원래 변수 개수보다 훨씬 적은 2~3개의 주성분(PC1, PC2, PC3) 축으로 압축(PCA)해서 시각화하면, 원래 서로 다른 품종이었던 데이터들이 압축된 공간에서도 자연스럽게 구역이 나뉘어 보임. 품종 색깔은 사람이 이해를 돕기 위해 나중에 칠한 것일 뿐, PCA 자체는 이 라벨을 전혀 보지 않고 **입력 데이터의 분산 구조만으로** 압축을 수행
    

**비지도 vs 지도학습**

| 구분    | 정의                    | 예시              |
| ----- | --------------------- | --------------- |
| 지도학습  | 입력 + 라벨(정답)로 예측 모델 학습 | 가격 예측, 악성 종양 예측 |
| 비지도학습 | 입력만으로 구조 학습           | 고객 세그먼트         |

- 비지도학습의 대표 예 — **클러스터링**: 서로 비슷한 데이터끼리 묶어 동질 그룹 만들기 (예: 비슷한 뉴스를 라벨 없이 자동으로 묶기)

> [!question]+ 지도학습과 비지도학습, 그림으로 보면 뭐가 다를까?
> 
> 같은 위치에 흩어진 점들을 놓고 비교하면:
> 
> - **지도학습**: 점들에 처음부터 빨강/초록 두 가지 색(=라벨)이 칠해져 있음 → 이 라벨을 바탕으로 모델이 평면을 빨간 영역과 초록 영역으로 나누는 **경계선**을 학습 → 새 점이 오면 어느 영역에 속하는지로 라벨을 예측
> - **비지도학습**: 똑같은 배치의 점들이지만 전부 회색 — 라벨 정보가 아예 없는 상태 → 그런데도 위치상 가까운 점들끼리 자연스럽게 뭉쳐 있는 걸 보고, 5개 그룹(파랑·주황·초록·빨강·노랑)으로 모델이 **스스로 묶어냄**
> 
> 즉 지도학습은 "이미 정해진 정답 경계를 학습"하는 것이고, 비지도학습은 "정답 없이 데이터 스스로의 뭉침을 찾아내는" 것이라는 게 핵심 차이

## 13. 클러스터링(Clustering)

**클러스터링이란?**

- **클러스터링**: 데이터 안에서 하위 집단(클러스터)을 찾는 기법들의 총칭
- **집단 내부는 서로 유사, 집단 간은 상이**하도록 데이터를 분할
    - 집단 내부: 비슷한 성격끼리 묶이도록 만드는 것 (예: 쇼핑몰에서 "비슷한 취향의 고객 그룹" 만들기)
    - 집단 사이: 서로 다른 부류는 확실히 다르게 구분 (예: 고가 제품만 사는 고객 vs 할인 제품만 사는 고객)
- 유사/상이는 문제·도메인에 따라 달라짐
- 특성에 따라 클러스터가 잘 안 보이거나, 알고리즘마다 결과가 달라질 수 있음

**예시: 마케팅 세그먼테이션**

- 가구 소득, 직업, 도심 거리 등 다수의 지표를 가진 많은 사람들에 대해, 특정 광고/상품에 더 반응할 하위집단을 식별하고자 함
- **시장 세분화 작업 자체가 클러스터링**에 해당 — 뒤섞여 있던 고객들을 클러스터링을 거쳐 색깔·크기가 다른 몇 개의 뚜렷한 세그먼트(그룹)로 재정리

**두 가지 대표 클러스터링 기법**

- **K-평균(K-means)**: K(클러스터 수)를 **미리 정해서** 분할 — 각 클러스터마다 "중심점"이 하나씩 있고, 점들을 가장 가까운 중심에 소속시키는 방식
- **계층적 군집(Hierarchical)**: K를 사전에 고정하지 않음 — 비슷한 데이터끼리 먼저 작은 가지로 합쳐지고, 그 가지들이 점점 더 큰 덩어리로 뭉쳐 올라가 결국 하나의 뿌리로 합쳐지는 나무(덴드로그램) 구조. 이 나무를 어느 높이에서 자르느냐에 따라 클러스터 개수가 나중에 결정됨

cf. K-means는 14장, 계층적 군집은 15장에서 각각 자세히 다룰 예정

## 14. K-means 클러스터링

**결과 예시**: 같은 데이터를 K=2, 3, 4로 다르게 설정해서 클러스터링하면, K가 커질수록 같은 데이터가 점점 더 잘게 나뉨. 여기서 **특정 색상 자체는 의미가 없고**, 점들이 다른 색이라는 건 그냥 "서로 다른 클러스터에 속한다"는 것만 의미

**K-means의 표기(군집 집합)**: 관측치 인덱스 집합을 $C_1,\ldots,C_K$라 하면

- $C_1\cup\cdots\cup C_K={1,\ldots,n}$ (각 관측치는 적어도 하나의 군집에 속함)
- 서로 다른 클러스터끼리는 $C_k\cap C_{k'}=\emptyset$ → 하나의 데이터가 여러 그룹에 동시에 속할 수 없음
- $i$번째 관측치가 $k$번째 군집이면 $i\in C_k$ (비중첩 분할)
- 정리하면: 모든 데이터를 **겹치지 않게, 빠짐없이, 정확히 하나의 군집에만** 나눔

**핵심 아이디어**: 좋은 군집화 = **클러스터 내부 변동(Within-Cluster Variation)**이 작은 분할. 목표는 클러스터 거리·차이의 합이 최소가 되도록 데이터를 나누는 것 — "그룹 안에서 얼마나 모여있는지"를 기준으로 K개의 그룹을 만드는 알고리즘

**K-means 알고리즘**

1. **초기화**: 관측치들에 무작위로 $1\ldots K$ 클러스터를 임시 부여
2. **반복** (할당이 더 이상 바뀌지 않을 때까지):
    - 2a. 각 클러스터의 **중심(centroid)** 계산 (특성 평균 벡터)
    - 2b. 각 관측치를 **가장 가까운 중심**의 클러스터에 재할당 (거리는 보통 유클리드 거리)

**알고리즘 특성**

- 중심점과의 평균 거리가 계속 줄어들기 때문에 매 반복마다 결과는 더 좋아짐
- 하지만 **최적 해를 항상 찾는 건 아님** → 초기값에 따라 **지역 최솟값(Local minimum)**으로 수렴 가능

이 과정을 실제 데이터에 적용해보면, 처음엔 무작위로 뒤섞여 있던 임시 색상이 반복을 거듭할수록 점점 뚜렷하게 정리되고, 중심점도 점점 정확한 위치로 이동하면서 최종적으로 안정된 클러스터로 수렴하는 흐름을 보임

> [!question]+ 초기값에 따라 결과가 정말 달라질까?
> 
> 같은 데이터로 초기 무작위 시드만 다르게 해서 K-means를 여러 번 돌려보면, 어떤 시도는 더 낮은(좋은) 목표값에 도달해서 깔끔하게 클러스터가 나뉘지만, 다른 시도는 더 높은(나쁜) 목표값에 갇혀서 클러스터가 부자연스럽게 나뉨 — 이게 바로 **지역 최솟값(local minimum)**에 실제로 빠진 경우
> 
> → **초기화의 중요성**: 그래서 K-means는 보통 **여러 번 시도**해서 그중 가장 좋은(목표값이 가장 낮은) 결과를 채택하는 방식으로 사용됨

> [!info]+ 참고: K-Fold·PCA·K-means 한눈에 정리
> 
> - **K-Fold 교차검증**: 데이터를 K개의 하위 집합(폴드)으로 균등하게 나눈 뒤, 총 K번의 반복 학습을 수행하며 매회 서로 다른 폴드 하나를 검증 데이터로, 나머지를 훈련 데이터로 사용한다. (11장 참고)
> - **PCA(주성분분석, Principal Component Analysis)**: 데이터셋의 특성(feature) 수가 수십~수백 개 이상으로 늘어나면 계산 복잡도가 급격히 커지고 모델의 해석과 학습도 어려워진다. PCA는 원본 데이터가 가진 정보(분산)를 최대한 보존하면서 차원을 축소하는 비지도 학습 기법이다.
> - **K-means 군집화**: 사전에 레이블이 없는 데이터셋을 물리적 거리가 가까운 데이터끼리 K개의 동질한 그룹(클러스터)으로 자동 분류하는 비지도 학습 알고리즘. 군집 중심점(centroid)과 데이터 간 오차가 최소화될 때까지, 중심의 위치를 소속 데이터들의 평균 위치로 반복 재조정하며 군집을 개선한다.

>[!info]+ **왜 PCA에는 표준화를 쓰는가**  
PCA는 12장에서 "입력 데이터의 **분산 구조**만으로 압축을 수행"한다고 나와 있죠. PCA는 분산이 큰 방향을 주성분으로 잡는 알고리즘이라, 만약 어떤 변수가 단위 때문에 원래부터 분산이 크면(예: 연소득처럼 숫자 자체가 큰 변수) PCA가 그 변수를 "정보가 많다"고 착각해서 주성분이 그쪽으로 쏠려버립니다. 표준화를 하면 모든 변수의 분산이 1로 맞춰져서, 이런 단위 차이에 의한 왜곡 없이 순수하게 변수들 간의 상관관계 구조만 가지고 주성분을 찾을 수 있어요. (정규화보다 표준화가 선호되는 이유는, 정규화는 범위만 맞출 뿐 분산 자체를 표준 스케일로 통일해주진 않기 때문입니다.)

## 15. 계층적 군집(Hierarchical Clustering)

**K-means와의 비교**

- K-means는 클러스터 수 **K를 미리 지정**해야 하는 단점이 존재
- **계층적 군집**은 K를 고정하지 않고 전체 구조를 **덴드로그램**으로 제공
- 이번 강의에서는 **상향식(agglomerative)**을 다룸: 잎→몸통으로 병합해가는 방식

**덴드로그램 구조와 자르기**

- 덴드로그램은 나무를 뒤집어놓은 모양 — 맨 아래 **잎(leaf)**은 실제 데이터 하나하나, 위로 올라가면서 비슷한 것들이 **가지(branch)**로 합쳐지고, 맨 위 **몸통(root)**에서 결국 전부 하나로 합쳐짐
- 원하는 높이에서 수평으로 **가위질(자르기)**하면, 그 높이에서 걸리는 가지 개수만큼 클러스터 개수(K)가 정해짐 — 높은 곳에서 자르면 적은 수(더 큰) 클러스터, 낮은 곳에서 자르면 많은 수(더 작은) 클러스터

**계층적 군집 알고리즘 (상향식)**

1. $n$개 관측에 대해 **쌍별 비유사도**를 계산, 각 관측치를 하나의 클러스터로 시작
2. $i$개 클러스터 간 쌍별 비유사도를 모두 계산해 **가장 유사한 두 클러스터를 병합**
3. 병합 후 남은 $i-1$개 클러스터 사이의 새 비유사도를 다시 계산
4. $i=n, n-1,\ldots,2$에 대해 반복

- 데이터들이 점차 큰 클러스터로 합쳐지는 과정 — 매 단계에서 클러스터들끼리의 병합이 이루어지고, **1개의 단일 클러스터가 될 때까지** 진행
- **계산량**: 매 단계에서 모든 클러스터 쌍 간의 거리를 계산해야 함 → 데이터 수가 많으면 K-means에 비해 계산량이 많음

> [!question]+ 쌍별 거리(pairwise distance)란?
> 
> 데이터 포인트 하나하나를 서로 짝지어서(쌍으로 묶어서) 각 짝마다 거리를 재는 것 — "모든 두 점 사이의 거리를 다 계산한다"는 뜻
> 
> - 데이터가 $n$개면 쌍의 개수는 $\binom{n}{2}=\dfrac{n(n-1)}{2}$개 → 데이터가 늘어날수록 계산할 쌍이 제곱에 비례해서 빠르게 늘어남 (계층적 군집의 계산량이 큰 이유)
> - 두 가지 층위에서 쓰임:
>     1. **알고리즘 1단계**: 클러스터가 나뉘기 전, 개별 데이터 $n$개 사이의 쌍별 거리 → 누구랑 누구를 가장 먼저 묶을지 정하는 데 사용
>     2. **링크 유형**: 이미 여러 데이터를 포함한 두 클러스터 사이의 거리를 정할 때, 그 두 무리에 속한 데이터들을 하나씩 다 짝지어서 거리를 재고, 그중 최솟값(single)/최댓값(complete)/평균(average) 중 뭘 쓸지로 방식이 갈림
> - 예: 무리 X에 점 3개, 무리 Y에 점 2개 있으면 3×2=6개의 쌍이 나오고, 이 6개 거리 중 최솟값/최댓값/평균을 그 두 무리 사이의 "거리"로 삼음

**계층적 군집의 링크 유형**

- **Single(최소 거리) 링크**: 두 클러스터 내 데이터 쌍별 거리 중 **최솟값**을 군집 간 거리로
- **Complete(최대 거리) 링크**: 두 클러스터 내 데이터 쌍별 거리 중 **최댓값**을 군집 간 거리로
- **Average(평균 거리) 링크**: 두 클러스터 내 데이터 쌍별 거리의 **평균**을 군집 간 거리로

**링크 유형에 따른 결과**

- 같은 데이터라도 **링크 선택에 따라 클러스터링 결과(덴드로그램)가 달라질 수 있음**
- 하나의 링크만 시도하는 게 아니라 **다른 종류의 링크도 사용 권장**
- Average와 Complete linkage는 비교적 균형 잡힌 나무 모양이 나오는 반면, **Single linkage는 한쪽으로 계속 길게 늘어지는(체인처럼 이어지는) 불균형한 나무 모양**이 나오는 경향 — single-link의 잘 알려진 "chaining effect(연쇄 효과)" 문제

## 16. 클러스터링 주의점

**클러스터링 체크리스트**

- **스케일링**: 표준화(평균 0, 표준편차 1로 입력 변수 변환)가 필요한가? → **Yes, 변수 단위 차이 영향이 큼**
- **몇 개의 클러스터가 적합한지?** → K-means·계층적 모두 어려운 문제, 합의된 정답 없음
- 단일 시도가 아닌 **여러 번 시도 권장**

> [!question]+ 스케일링(표준화)이 왜 필요할까?
> 
> - **스케일링**: 서로 다른 단위·범위를 가진 변수들을 비교 가능한 크기로 맞춰주는 것. 가장 흔한 방법이 **표준화(standardization)**
> - 표준화 공식: $z=\dfrac{x-\text{평균}}{\text{표준편차}}$ — 원래 값에서 그 변수의 평균을 빼고 표준편차로 나눔 → 모든 변수가 평균 0, 표준편차 1인 공통 척도로 통일됨
> - **왜 필요한가**: 클러스터링은 점들 사이의 거리(예: 유클리드 거리)로 가까운 것끼리 묶는 방식인데, 변수마다 단위·범위가 다르면 거리 계산이 왜곡됨
>     - 예: 연소득(수백만~수천만 단위)과 나이(수십 단위)를 그대로 거리 공식에 넣으면, 숫자 자체가 훨씬 큰 소득이 거리값을 거의 독차지 → 사실상 "소득만 보고" 클러스터를 나누는 셈이 됨(나이가 똑같이 중요한 정보였더라도)
>     - 표준화하면 모든 변수가 같은 척도로 맞춰져서, 어느 한 변수가 숫자 크기 때문에 부당하게 거리 계산을 지배하는 일이 없어짐

> [!question]+ "여러 번 시도"는 구체적으로 뭘 의미할까?
> 
> 지도학습이면 정답 라벨과 비교해 검증할 수 있지만, 클러스터링은 애초에 정답이 없는 비지도학습이라 "몇 개의 클러스터가 적합한가"에 합의된 정답 자체가 없음. 그래서:
> 
> - K값을 여러 가지로 바꿔가며 시도 (14장에서 K=2,3,4로 결과가 달라지는 걸 봤던 것처럼)
> - K-means·계층적 군집처럼 알고리즘 자체를 바꿔가며 시도
> - 매번 나온 결과를 보고 "실제 문제 상황에서 말이 되는 그룹핑인가"를 사람이 판단
> 
> cf. 14장에서 K-means를 초기값 바꿔가며 여러 번 돌리라고 했던 조언을, 여기서는 K값·알고리즘 선택까지 포함해 더 일반적으로 확장한 것

## 17. 선형 회귀 (Linear Regression)

- 정의: 데이터 포인트에 가장 가까운 직선을 찾는 것. $y = wx + b$
- 손실 함수(loss function): 예측값과 실제값의 차이를 측정 → 이 차이를 최소화하는 방향으로 w, b를 찾음
    - 단순 오차합: $\sum(y-\hat y)$
    - **MSE(평균제곱오차)**: $\frac{1}{N}\sum(y-\hat y)^2$ ← 가장 널리 씀
    - MAE(평균절대오차): $\frac{1}{N}\sum|y-\hat y|$

> [!question]+ 단순선형회귀는 왜 반복(경사하강법) 없이 공식으로 바로 구해지는가
> 
> - 손실함수로 잔차제곱합(RSS)을 사용: $RSS(w,b)=\sum(y-(wx+b))^2$
> - RSS는 w, b에 대한 **2차식** → 그래프가 아래로 볼록한 그릇 모양 → 최솟값이 유일하게 존재하고, 그 지점은 미분(기울기)=0인 지점
> - 따라서 미분해서 0이 되는 지점을 **공식으로 바로 계산** 가능
> - cf. 다중선형회귀에서도 이 원리는 똑같이 적용되지만, 변수가 많아지면 "공식으로 한번에" 방식이 현실적으로 어려워짐 → 경사하강법이 등장하는 이유 중 하나 (18장 참고)

### 회귀 결과 해석

|통계량|의미|
|---|---|
|Coefficient|기울기/절편의 추정치|
|Std. Error|추정치의 불확실성 (새 데이터가 오면 값이 얼마나 바뀔 수 있는지)|
|t-statistic|Coefficient / Std.Error. 0에 가까울수록 통계적으로 유의하지 않을 가능성↑|
|p-value|계수가 실제로는 0일 확률(=x,y 관계없음). 보통 ≤0.05면 유의미|

⚠️ Coefficient **크기만** 보고 "영향력이 크다/작다"를 판단하면 안 됨 → Std.Error, t-statistic, p-value를 같이 봐야 함

## 18. 다중 선형 회귀

- $\hat y = w_1x_1+w_2x_2+\cdots+w_nx_n+b$
- Loss(MSE)도 동일한 형태로 확장
- 행렬로 표현하면 $\mathbf y=\mathbf X\boldsymbol\beta+\boldsymbol\epsilon$, 최소제곱법 공식: $\hat{\boldsymbol\beta}=(\mathbf X^\top\mathbf X)^{-1}\mathbf X^\top\mathbf y$ (역시 RSS가 2차식이라 공식으로 한번에 구해짐)

> [!question]+ 회귀 가중치 ≠ 상관계수
> 
> - **상관계수**: 두 변수가 얼마나 "함께" 움직이는지 (단순 2변수 관계)
> - **회귀 가중치**: 나머지 변수를 고정한 채, 확인하려는 변수 하나만 바꿨을 때 결과값에 미치는 영향
> - 예) 평수-방개수-집값: 방개수와 집값의 상관계수는 높게 나오지만, 이는 평수와 방개수가 서로 얽혀있기 때문. 평수를 고정하고 보면 방개수의 실제 영향력(가중치)은 다르게 나타남

> [!question]+ 공식(닫힌 형태)이 있는데 왜 경사하강법이 또 필요한가
> 
> - $\hat{\boldsymbol\beta}=(\mathbf X^\top\mathbf X)^{-1}\mathbf X^\top\mathbf y$는 이론적으로는 가능하지만, 변수(차원)가 많아질수록 행렬 연산량이 폭발적으로 증가
> - AI 모델은 변수가 수천만 개에 달하기도 해서 **물리적으로 이 공식을 계산하는 게 불가능** → 반복적으로 값을 조금씩 개선해나가는 경사하강법이 필요해짐

### 해석 시 주의점

- 변수들이 서로 독립적이지 않으면(상관되어 있으면) 계수 추정이 불안정 + 해석 혼동
- 상관관계 ≠ 인과관계 (ex: 아이스크림 판매량↑, 상어 물림 사건↑ → 둘 다 "여름"이라는 공통원인 때문이지 서로 인과관계는 아님)

## 19. 분류(Classification)와 로지스틱 회귀

- 분류: y가 숫자가 아니라 범주(카테고리)인 문제. 범주 자체보다 "각 범주에 속할 확률"을 구하는 게 더 유용할 때가 많음
- 선형회귀는 출력값이 $-\infty\sim+\infty$ → 확률(0~1) 범위를 벗어날 수 있어서 분류에 부적절
- 시그모이드 함수로 해결: $y=\frac{1}{1+e^{-z}}$ (항상 0~1 사이 값만 나오도록 강제)
- 선형식 $z=\beta_0+\beta_1x$를 시그모이드에 대입 → $p(X;\beta)=\dfrac{1}{1+e^{-(\beta_0+\beta_1x)}}$ = 로지스틱 회귀 모형식
- 오즈(Odds) = 성공확률/실패확률 = $p/(1-p)$ → 로짓(logit) = log(오즈)
- 신기한 점: 로지스틱 모형식을 로짓 변환하면 다시 **선형식**이 됨 → $\text{logit}(p)=\beta_0+\beta_1x$ (로지스틱 회귀 = 선형모형 + 시그모이드 결합)

> [!question]+ 파라미터(β) 추정 방식이 선형회귀와 다른 이유 — 우도(Likelihood)와 MLE
> 
> - 선형회귀는 **MSE**로 최적 파라미터를 찾았지만, 확률을 다루는 로지스틱회귀는 **우도(Likelihood)**를 지표로 사용 (현재 확률모형이 데이터를 얼마나 잘 설명하는지)
> - 목표: 우도를 최대화하는 β를 찾음 (MLE, Maximum Likelihood Estimation)
> - 문제: 우도식은 곱셈(Π)으로 구성 → 미분이 어려움 → 양변에 log를 취해 곱을 합으로 바꾼 **log-likelihood** 사용 (log 변환해도 최댓값의 위치는 동일)
> - 결과적으로 이 경우엔 선형회귀처럼 **닫힌 형태(공식)로 β를 바로 구할 수 없음** → 경사하강법 같은 반복적 최적화가 필요 (경사하강법 등장의 두 번째 이유)

## 20. 회귀 → 신경망으로의 연결

> [!question]+ 왜 회귀 얘기하다가 갑자기 "신경망" 얘기로 넘어가는가 선형회귀와 로지스틱 회귀는 둘 다 결국 **"입력 x들의 가중합(weighted sum) + 편향(bias)"** 하나로 결과를 표현하는 모델이다. $$y=\phi_0+\phi_1x$$ 이 구조는 직선(또는 평면) 하나만 표현할 수 있다는 근본적 한계가 있다.
> 
> **Shallow 네트워크(얕은 신경망)**는 "가중합 하나" 대신 **여러 개의 미니 선형회귀**를 만들고, 각각에 비선형 함수(활성화 함수)를 씌운 뒤, 그 결과들을 다시 가중합해서 최종 출력을 만든다: $$y=\phi_0+\phi_1a[\theta_{10}+\theta_{11}x]+\phi_2a[\theta_{20}+\theta_{21}x]+\phi_3a[\theta_{30}+\theta_{31}x]$$
> 
> - $\theta_{j0}+\theta_{j1}x$: 은닉 유닛(hidden unit)마다 수행하는 **미니 선형회귀** (지금까지 배운 것과 똑같은 구조)
> - $a[\cdot]$: 활성화 함수. 비선형성 부여. **시그모이드가 활성화 함수의 한 예시**
> - $\phi_1,\phi_2,\phi_3$: 은닉 유닛들의 결과를 최종 출력으로 합칠 때의 가중치
> 
> **연결고리**: 선형회귀(가중합 1개) → 로지스틱 회귀(가중합 1개 + 시그모이드) → 신경망(가중합+활성화함수 단위를 여러 개 만들어 병렬 조합). 신경망은 새로운 개념이 아니라 **선형회귀 구조를 여러 개 겹쳐 쌓은 확장판**.

> [!question]+ "표현력(expressive power)"이란? 모델이 **얼마나 다양하고 복잡한 형태의 함수(관계)를 표현/근사할 수 있는가**를 뜻함.
> 
> - 단순선형회귀: 파라미터 2개 → 오직 "직선 1개"만 표현 가능 → 표현력 낮음
> - Shallow network: 은닉유닛+활성화 함수 덕분에 꺾이고 휘어지는 비선형 형태까지 표현 가능 → 표현력이 더 높음
> - 은닉 유닛 수를 늘릴수록(파라미터↑) 더 복잡한 함수까지 표현 가능 → "표현력이 커진다"

### 파라미터 개수 비교

||단순선형회귀|Shallow network (은닉유닛 3개)|
|---|---|---|
|은닉유닛 수|없음|3개|
|활성화 함수|없음|있음|
|파라미터 수|2개|10개|
|표현 가능한 형태|직선 1개|비선형 곡선|

### Shallow 네트워크 구조 정의

- 입력층 - 은닉층 1개 - 출력층으로 구성된, 은닉층이 1개뿐인 신경망
- 장점: 표현력↑ / 학습 빠르고 구현 쉬움 / 데이터 적어도 과적합 위험 비교적 낮음
- 회귀(연속값)에선 출력층에 활성화 함수 없이 가중합만, 분류에선 마지막에 시그모이드를 한 번 더 씌움

## 21. 경사하강법(Gradient Descent)과 발전 과정

> [!question]+ Convex(볼록) 문제란?
> 
> - 손실함수가 아래로 볼록(convex)한 형태 → **2차 미분이 모든 구간에서 항상 양수이거나 0**
> - 이 경우 어떤 국소 최솟값(local minimum)도 항상 전역 최솟값(global minimum)과 동일 → 어디서 출발해도 경사하강법으로 결국 최적해에 도달 가능
> - cf. 17장의 RSS(잔차제곱합)가 정확히 이 convex 형태(2차식) → 미분=0인 지점이 유일한 최솟값이었던 이유가 바로 이 성질

**경사하강법 단계**

1. 파라미터를 무작위로 초기화 (최초 1회)
2. 현재 파라미터에서 손실함수의 기울기(미분값)를 계산
3. 기울기의 반대 방향으로 파라미터 업데이트
4. 손실이 충분히 작아질 때까지(또는 정해진 반복 횟수만큼) 2~3 반복

$$w\leftarrow w-\eta\cdot\frac{\partial L}{\partial w}$$ "새 위치 ← 현재 위치 − 학습률 × 기울기"

- **η(학습률)**: 보폭. 너무 크면 최솟값을 지나침, 너무 작으면 수렴 느림
- **∂L/∂w(기울기)**: 반대 방향으로 이동해야 손실 감소

### 확률적 경사하강법(SGD)

- 데이터 중 무작위 1개만 골라 기울기 계산 → 이동: $w\leftarrow w-\eta\cdot\frac{\partial L_i}{\partial w}$
- 장점: 계산량 적음(스텝당 비용↓), 노이즈 덕분에 지역 최솟값 탈출 가능성 / 단점: 경로가 불안정(요동)

> [!question]+ SGD가 GD(full-batch)보다 항상 수렴 속도가 빠른가? 아니다. SGD가 빠른 건 **"매 스텝의 계산 비용"**이 적다는 뜻이지, **"최종 수렴까지 걸리는 속도"**가 항상 빠르다는 뜻이 아님
> 
> - Convex 문제(또는 convex에 가까운 경우)에서는 오히려 GD(full-batch)의 수렴이 더 빠를 수 있음 — 매 스텝 정확한 방향(전체 데이터 기준 기울기)으로 이동하기 때문
> - SGD는 노이즈 섞인 기울기로 움직이므로 경로가 요동쳐서, 오히려 더 많은 스텝이 필요할 수 있음
> - 정리: 계산 비용(스텝당) ≠ 수렴 속도(전체적으로) — 이 둘을 혼동하지 않기

### 미니배치 경사하강법

- 데이터를 배치로 나눠 평균 기울기로 업데이트 + 배치 단위 병렬 연산 → 안정성 + GPU 활용도↑ $$w\leftarrow w-\eta\cdot\frac{1}{B}\sum_{i\in batch}\frac{\partial L_i}{\partial w}$$
- **에포크(Epoch)**: 전체 데이터셋을 한 번 다 학습에 사용한 상태 (매 에포크마다 셔플 후 배치로 학습)

### 발전 흐름

1. **단순선형회귀** — 공식으로 한 번에 계산
2. **다중선형회귀** — 공식(행렬) 가능하지만 변수↑ 시 연산량 폭증
3. **경사하강법** — 반복 계산이지만 매 스텝 전체 데이터 사용 → 여전히 부담
4. **SGD** — 데이터 1개로 계산 → 빠르지만 노이즈로 불안정
5. **미니배치** — 배치 단위 평균 + 병렬 → 안정성·속도 개선

### 22.1 Shallow 네트워크

#### 22.1.1 구조 및 활성화함수

> [!question]+ 신경망 얘기 전에 왜 "모수적 함수"부터 다시 짚고 가는가 신경망도 결국 선형모델과 똑같이 "파라미터로 완전히 결정되는 함수"라는 틀 안에 있다는 걸 먼저 각인시키기 위함. 이후 이 함수 형태가 점점 복잡해지는 과정(shallow → deep)을 보여주려는 구성.
> 
> **모수적 함수(parametric function)**: 함수의 형태(뼈대)는 고정, 파라미터(모수) 값에 따라 함수가 완전히 결정됨
> 
> - 예: $y=\phi_0+\phi_1x$ → "직선"이라는 형태는 고정, $\phi_0,\phi_1$만 정하면 어떤 직선인지 100% 결정
> - 선형회귀·로지스틱회귀·신경망 모두 "모수적 함수"라는 같은 틀 안에 있음 — 파라미터 개수와 함수의 복잡도만 다를 뿐
> - cf. 비모수적(non-parametric): 함수 형태 자체가 고정 안 되고 데이터에 따라 유연 (ex: k-NN, 결정트리)
> 
> **표기 $f[x_i,\phi]$의 의미**: "파라미터 φ를 가진 함수 f에 i번째 입력 $x_i$를 넣었을 때 나오는 예측값" ($\hat y_i$와 동일). 모델 종류(선형모델/Shallow/Deep network)에 상관없이 공통으로 쓰는 일반 표기이며, 실제로는 그 자리에 각 모델의 구체적 식이 들어감
> 
> - 단순 선형모델: $f[x_i,\phi]=\phi_0+\phi_1x_i$
> - Shallow network: $f[x_i,\phi]=\phi_0+\phi_1a[\theta_{10}+\theta_{11}x_i]+\phi_2a[\theta_{20}+\theta_{21}x_i]+\phi_3a[\theta_{30}+\theta_{31}x_i]$
> - 손실함수 $L[\phi]=\sum(f[x_i,\phi]-y_i)^2$ 형태("최소제곱 손실함수")는 모델이 뭐든 동일하게 유지됨

- 회귀와의 연결고리: 파라미터를 점진적으로 업데이트하며 손실을 줄여나가는 원리는 선형/로지스틱 회귀 때와 동일 (경사하강법은 이미 21장에서 다룸)
- **Shallow network 정의**: 입력층 - 은닉층(Hidden Layer) 1개 - 출력층으로 구성된, 1개의 은닉층만 가진 신경망 구조 / (비교) Deep network: 은닉층 2개 이상
- **장점**: 복잡한 비선형 패턴까지 학습 가능(단순 선형모델 대비 표현력 향상) / 구조가 간단해 학습 속도 빠르고 구현 쉬움 / 데이터 충분하지 않아도 과적합 위험 비교적 낮음

> [!question]+ "표현력이 향상된다"는 게 정확히 무슨 뜻이고, 왜 과적합 위험은 낮은가
> 
> **표현력(expressive power)이 향상된다는 것** = 모델이 나타낼 수 있는 함수의 "종류(모양)"의 범위가 넓어진다는 뜻
> 
> - 단순 선형모델: 표현 가능한 함수 = "직선 1개"뿐
> - Shallow network: 꺾인 구간을 여러 개 가진 비선형 곡선, 변수 간 상호작용/조합까지 표현 가능
> - 은닉 유닛을 늘릴수록 더 많이 꺾을 수 있어서 더 복잡한 모양까지 흉내 낼 수 있음 (XOR을 풀 수 있게 된 것도 "직선 하나"라는 좁은 표현력에서 "곡선/꺾인 경계선"이라는 넓은 표현력으로 확장됐기 때문)
> 
> **그런데 왜 과적합 위험은 낮다고 하는가 — 비교 대상에 주의** 이 비교는 **선형모델과의 비교가 아니라 Deep network(은닉층 여러 개)와의 비교**
> 
> - 모델의 표현력(capacity)이 커질수록 → 학습 데이터의 "진짜 패턴"뿐 아니라 "노이즈"까지 외워버릴 위험(과적합) 증가
> - Deep network: 파라미터 수 훨씬 많고 표현력도 훨씬 큼 → 데이터 적으면 노이즈까지 외우기 쉬움 (과적합 위험↑)
> - Shallow network: 파라미터 수가 상대적으로 제한적 → 표현력이 "적당히" 커서, 데이터 적어도 노이즈까지 다 외울 여력은 없음 → 상대적으로 과적합 위험 낮음
> 
> → **편향-분산 트레이드오프(bias-variance tradeoff)**의 한 단면: 선형모델(표현력 낮음, 과소적합 위험) < Shallow(적당한 지점) < Deep(표현력 매우 큼, 데이터 적으면 과적합 위험↑, 데이터 충분하면 가장 잘함)
> 
> ⚠️ "과적합 위험 낮음"은 **"선형모델보다"가 아니라 "Deep network보다"**라는 상대적 비교. 선형모델과 비교하면 오히려 Shallow network가 표현력이 크므로 과적합 여지는 더 있는 셈

- **사용 예시**: 간단한 분류·회귀 문제 / **XOR 같은 비선형 결정 boundary가 필요한 문제**
    
    > XOR은 단순 선형모델(직선 하나)로는 절대 분류할 수 없는 대표 사례(두 클래스가 대각선으로 엇갈려 있어 직선 하나로 못 나눔). 은닉층 하나만 추가해도 풀 수 있게 됨 — Shallow network가 선형모델보다 표현력이 좋다는 걸 보여주는 구체적 사례
    

> [!question]+ 왜 "복잡한 비선형 패턴"이 필요한가 — 다중회귀와는 뭐가 다른가
> 
> **비선형/조합 패턴이 필요한 실제 예시**
> 
> - XOR: 단순 선형모델(직선 하나)로는 절대 분류 불가능한 대표 사례 (두 클래스가 대각선으로 엇갈려 있음)
> - 자연어의 부정 표현: "나쁘다"=부정, 근데 "나쁘지 않다"="않다"가 붙으며 결과가 뒤집힘 → 단어 하나가 아니라 **조합**에 따라 결과가 달라지는 XOR 구조
> - 약물 상호작용: A도 안전, B도 안전한데 A+B를 같이 먹으면 위험 → 개별로는 영향 없다가 조합될 때만 튀는 패턴
> - 집값의 한계효용 체감: 방 3→4개는 값이 확 오르지만 10→11개는 거의 안 오름 → 구간마다 기울기가 다른 관계는 직선 하나로 표현 불가
> 
> **다중회귀도 여러 변수를 다루는데, 뭐가 다른가?**
> 
> - 다중선형회귀: $\hat y=w_1x_1+w_2x_2+\cdots+b$ → 변수들의 영향을 **그냥 더함**(가중합). 각 변수가 서로 독립적으로 영향을 준다고 가정 = "**교호작용(interaction) 없음**"
> - XOR·약물상호작용처럼 "한 변수의 효과가 다른 변수 값에 따라 달라지는" 경우는 이 가중합 구조로 표현 불가
> 
> **그럼 다중회귀로 XOR을 못 푸나? → 사실 풀 수는 있음**
> 
> - 교호작용항 $x_1x_2$를 사람이 직접 변수로 추가하면 됨: $f=w_1x_1+w_2x_2+w_3(x_1x_2)+b$
> - $w_1=1,w_2=1,w_3=-2,b=-0.5$로 두면 (0,0)→낮음, (0,1)→높음, (1,0)→높음, (1,1)→낮음 → XOR과 정확히 일치
> 
> **그럼 신경망은 왜 필요한가? (진짜 차이)**
> 
> - 다중회귀: "$x_1x_2$ 항이 필요하다"는 걸 **사람이 미리 알고 손으로 설계**해줘야 함 (feature engineering)
> - 이미지(픽셀 수백만 개)·자연어처럼 변수가 많으면 **어떤 조합이 중요한지 사람이 미리 알 수 없음**
> - 신경망(hidden unit + 활성화 함수)은 이런 조합/교호작용 항을 **데이터로부터 자동으로 학습**함
> 
> → 결론: 다중회귀가 "여러 변수"를 못 다루는 게 아니라, **상호작용을 사람이 직접 설계해줘야만 다룰 수 있다**는 게 한계. 신경망의 "표현력"은 이 상호작용/비선형 조합을 자동으로 찾아낸다는 데 있음

- 파라미터: 네트워크를 완전히 결정하는 값들. **활성화 함수는 파라미터가 아님**

> [!question]+ $\phi$와 $\theta$는 각각 무엇을 의미하나 — 결국 다 "가중치 아니면 절편"
> 
> Shallow network 수식을 두 단계(레이어)로 쪼개서 보면, 단순선형회귀와 같은 구조가 두 번 겹쳐 있는 것뿐.
> 
> $$y=\phi_0+\phi_1a[\theta_{10}+\theta_{11}x]+\phi_2a[\theta_{20}+\theta_{21}x]+\phi_3a[\theta_{30}+\theta_{31}x]$$
> 
> **1단계 — 은닉층 (입력 → 은닉 유닛)**: 각 은닉 유닛은 그 자체로 미니 선형회귀
> 
> - $\theta_{j0}$: j번 은닉 유닛의 절편(bias) / $\theta_{j1}$: j번 은닉 유닛의 가중치(x에 곱해짐)
> - $\theta_{10}+\theta_{11}x$ 는 $\phi_0+\phi_1x$와 구조가 완전히 동일. 다만 결과가 바로 출력되지 않고 활성화 함수 $a[\cdot]$를 거쳐 "은닉 유닛의 출력(activation)"이 됨
> 
> **2단계 — 출력층 (은닉 유닛 → 최종 출력)**: 은닉 유닛 출력들을 다시 가중합
> 
> - $\phi_0$: 최종 출력의 절편 / $\phi_1,\phi_2,\phi_3$: 각 은닉 유닛 출력에 곱하는 가중치
> - 이것도 $\phi_0+\phi_1x$와 같은 구조인데, 입력이 원래 $x$가 아니라 "은닉 유닛들의 출력값"으로 바뀐 것
> 
> $$\underbrace{\theta_{j0}+\theta_{j1}x}_{\text{미니 선형회귀}\times 3} ;\xrightarrow{a[\cdot]}; \text{은닉 유닛 출력} ;\xrightarrow{\phi_0+\phi_1(\cdot)+\phi_2(\cdot)+\phi_3(\cdot)}; y$$
> 
> **정리**: θ는 "입력→은닉 유닛" 사이의 가중치·절편(1층), φ는 "은닉 유닛→최종 출력" 사이의 가중치·절편(2층). 둘 다 본질은 같고, 어느 층에 속하냐로 이름만 다름
> 
> **표기 단축**: 은닉 유닛의 출력(activation)을 $h_1,h_2,h_3$로 따로 이름 붙이면 $h_j=a[\theta_{j0}+\theta_{j1}x]$, 전체 식은 $y=\phi_0+\phi_1h_1+\phi_2h_2+\phi_3h_3$로 훨씬 간결해짐. 이 h 표기는 이후 Deep network에서 "이번 층의 h(출력)가 다음 층의 입력이 된다"는 식으로 계속 재사용되는 핵심 표기

- 손실함수(예: 최소제곱)를 최소화하는 방향으로 파라미터를 업데이트 → 결국 신경망 학습 = 파라미터 최적화 문제

#### 22.1.2 조각별 선형(piecewise linear) 표현

- 은닉 유닛 3개 예시 구조 / 계산 자체는 단순 가중합(sum)

> [!question]+ 활성화 함수를 쓰는 이유 — 핵심: 비선형성을 부여하기 위해
> 
> **활성화 함수의 역할**: 각 은닉 유닛의 출력에 "꺾임(비선형성)"을 강제로 부여하는 것
> 
> **왜 비선형성을 부여해야 하는가** 활성화 함수가 없다면, 은닉 유닛을 아무리 쌓아도 수식이 이렇게 붕괴됨: $$y=\phi_0+\phi_1(\theta_{10}+\theta_{11}x)+\phi_2(\theta_{20}+\theta_{21}x)+\phi_3(\theta_{30}+\theta_{31}x)$$ 괄호를 풀어 정리하면: $$y=(\phi_0+\phi_1\theta_{10}+\phi_2\theta_{20}+\phi_3\theta_{30})+(\phi_1\theta_{11}+\phi_2\theta_{21}+\phi_3\theta_{31})x = A+Bx$$ → 그냥 단순선형회귀와 완전히 동일. 은닉 유닛이 3개든 3000개든 결과는 똑같음 (**선형함수를 아무리 합성해도 결국 선형함수** — 선형결합의 선형결합은 여전히 선형결합) → 즉 비선형성이 없으면 은닉층을 추가하는 행위 자체가 아무 의미가 없어짐
> 
> **비선형성을 부여하면 생기는 일** ReLU 기준, 은닉 유닛마다 "꺼지는 x 구간"이 서로 다르게 생김 → 구간마다 살아있는 유닛 조합이 달라짐 → 구간별로 기울기가 다른 함수(piecewise-linear)가 만들어짐 → XOR 같은 문제도 풀 수 있게 됨
> 
> **정리**: 활성화 함수는 "은닉층을 쌓는 행위를 의미 있게 만들어주는 장치". 이게 없으면 층을 아무리 깊게 쌓아도 신경망은 사실상 선형회귀와 다를 게 없음

- **활성화 함수(ReLU) 정의** — 활성화 함수의 대표적인 예: $$a[z]=\text{ReLU}[z]=\begin{cases}0 & z<0\ z & z\geq0\end{cases}$$
    - $z<0$ 구간: 출력이 완전히 평평하게 0 (flat) / $z\geq0$ 구간: 기울기 1인 직선(입력값을 그대로 통과)
    - "구부러진 직선(꺾인 직선)" 모양이라 Rectified(정류된) Linear Unit
- 활성화 함수(ReLU) 적용 전후: 입력이 0보다 작은 구간은 출력이 0으로 flat해짐
- 히든 유닛마다 활성화되는 영역이 서로 다르기 때문에, 조합하면 복잡한 piecewise-linear 형태가 됨
- 최종 근사 함수: 1D 입력 → piecewise-linear / 2D 이상 입력 → piecewise-planar (각 조각은 특정 파라미터로 결정)

> [!question]+ Hidden unit은 어떤 역할을 하고, 실제로 어떤 값이 들어가나
> 
> **역할**: 각 hidden unit은 입력 x의 특정 구간에서만 켜지는(활성화되는) 미니 선형 조각 — "x가 어떤 범위에 있는지"를 감지하는 스위치. 켜지는 지점(breakpoint)이 유닛마다 다르게 배치되면 조합했을 때 piecewise-linear 함수가 됨. 유닛이 많을수록 breakpoint가 많아져 표현력↑
> 
> **예시(회귀, 1D)**: $\theta$ 값에 따라 $h_1$은 $x\geq0.5$, $h_2$는 $x\leq1.0$, $h_3$는 $x\geq1.5$에서 켜짐 → 이 3개를 조합하면 x=0.5, 1.0, 1.5 세 지점에서 꺾이는 4구간짜리 함수가 만들어짐 (유닛 3개 = breakpoint 최대 3개)
> 
> **실제 데이터에서 x는 뭐가 들어가나 — 텍스트 예시(리뷰 감정분석)** hidden unit의 x는 항상 숫자여야 함. 단어처럼 숫자가 아닌 데이터는 먼저 숫자로 변환 필요:
> 
> - 단어 등장 여부를 0/1로 (예: "나쁘다" 등장=1, "않다" 등장=1)
> - 또는 임베딩(embedding) 벡터로 (단어 하나를 수십~수백 차원의 실수 벡터로 표현, 이 벡터 값 자체도 학습 대상) → hidden unit 입장에서는 x가 가격이든 단어 등장여부든 임베딩 값이든 전부 "숫자"일 뿐. 텍스트·이미지는 신경망에 넣기 전 숫자로 바꾸는 전처리 단계가 하나 더 필요하다는 게 회귀 예시와의 차이

**단계별 계산 흐름 (예시: 은닉 유닛 3개)**

|단계|내용|그래프|
|---|---|---|
|a, b, c|**선형 변환**: 각 은닉 유닛의 선형식 $\theta_{j0}+\theta_{j1}x$ 계산 (서로 기울기·절편이 다른 직선 3개)|직선 3개|
|d, e, f|**활성화 함수 적용**: $h_j=a[\theta_{j0}+\theta_{j1}x]$ — ReLU를 씌워 각 직선의 음수 구간을 0으로 flat 처리|꺾인 직선(반직선) 3개|
|g, h, i|**출력 가중치 적용**: $\phi_jh_j$ — 활성화된 출력에 각자의 $\phi$를 곱해 기울기·부호 재조정|재조정된 꺾인 직선 3개|
|j|**최종 합산**: $y=\phi_0+\phi_1h_1+\phi_2h_2+\phi_3h_3$ — g,h,i를 다 더해서 하나의 함수로 합침|여러 번 꺾인 하나의 piecewise-linear 곡선|

→ "히든 유닛마다 활성화되는 영역이 서로 다르기 때문에 조합하면 piecewise-linear가 된다"는 원리를, 4단계(선형→활성화→가중치→합산)로 쪼개서 시각적으로 보여주는 예시

#### 22.1.3 표현력/보편적 근사 정리

**일반화된 공식 (hidden unit D개)** $$h_d=a[\theta_{d0}+\theta_{d1}x] \quad (d=1,\dots,D)$$ $$y=\phi_0+\sum_{d=1}^{D}\phi_dh_d$$ 지금까지 예시로 쓴 "hidden unit 3개" 공식은 이 D개짜리 일반 공식의 한 특수 사례(D=3)였을 뿐.

**보편적 근사(Universal Approximation)**

- 충분히 많은 hidden unit이 있으면, 임의의 1차원 함수를 원하는 정확도로 근사할 수 있음
- linear region(hidden unit) 개수가 늘수록(5→10→20) 실제 함수(점선)와의 오차가 줄어듦 — 20개면 거의 완벽히 겹침
- 이게 **"은닉층 1개짜리 shallow network도, hidden unit 수만 충분하면 이론적으로 어떤 연속함수든 근사 가능하다"**는 보편적 근사 정리의 직관적 버전

> [!question]+ Hidden unit이 많아지면 입력값 종류가 늘어나는 건가?
> 
> 아니다. **입력의 종류/차원과 hidden unit 개수는 완전히 별개**.
> 
> - 입력 차원(x가 몇 개인지)은 문제 자체가 정함 — hidden unit을 몇 개 쓰든 입력 개수는 그대로
> - hidden unit 개수(D)는 정해진 입력에 대해 **"출력 함수를 얼마나 정교하게 표현할 수 있는가"(해상도/정밀도)**를 결정
> - 비유: 원을 직선 몇 개로 그릴 때, 변 4개=사각형, 20개=원에 가까워짐. "그릴 수 있는 도형의 종류"가 아니라 "같은 대상을 얼마나 정밀하게 표현하냐"가 늘어나는 것
> 
> **텍스트 예시로 보면**: hidden unit 하나 = "애매한 경우 하나를 구분해내는 판단 기준(경계선) 하나"
> 
> - unit 1개: "나쁘다"는 있는데 "않다"는 없음 → 순수 부정 감지
> - unit 2개: "나쁘다"+"좋다" 공존 → 혼재된 감정 감지
> - unit 3개: "하지만/그런데" 뒤 표현에 가중 → 반전 구조 감지
> - unit 4개: 강조부사+부정어 조합 → 강한 부정 vs 약한 부정 구분
> 
> → hidden unit이 늘수록 입력(볼 단어 수)이 늘어나는 게 아니라, **동시에 구분해낼 수 있는 미묘한 패턴의 개수**가 늘어나는 것. 5→10→20 linear region 그래프와 같은 원리가 "얼마나 섬세한 뉘앙스까지 잡아내는가"로 확장된 것

#### 22.1.4 다중 입력/출력으로의 일반화

**출력이 여러 개인 경우** (예: 1 input, 4 hidden units, 2 outputs)

- hidden unit들은 **공유**되고, 출력마다 조합 가중치(φ)만 다름
- $y_1=\phi_{10}+\phi_{11}h_1+\phi_{12}h_2+\phi_{13}h_3+\phi_{14}h_4$
- $y_2=\phi_{20}+\phi_{21}h_1+\phi_{22}h_2+\phi_{23}h_3+\phi_{24}h_4$
- 그래프상 $y_1,y_2$는 같은 x지점(breakpoint)에서 함께 꺾이지만 서로 다른 형태를 가짐

**입력이 여러 개인 경우** (예: 2 inputs, 3 hidden units, 1 output)

- $h_1=a[\theta_{10}+\theta_{11}x_1+\theta_{12}x_2]$ — 다중선형회귀가 hidden unit 안에 들어간 구조

**2입력에서의 단계별 계산 → piecewise-planar**

- 선형변환: 2D 평면(기울어진 판) / 활성화함수: 어떤 직선(fold line) 기준으로 한쪽은 평평, 한쪽은 기울어짐
- 3개를 합산: 여러 fold line이 2D 입력 평면을 여러 조각으로 나누고, 조각마다 다른 기울기의 평면 → **piecewise-planar** (22.1.2에서 예고했던 개념의 실제 그림)
- 이 3D 그래프가 **종이접기(folding) 비유**와 정확히 같은 모양 (22.2.1에서 다시 등장 예정)

**완전 일반화 공식** (입력 $D_i$개, hidden unit $D$개, 출력 $D_o$개) $$h_d=a\Big[\theta_{d0}+\sum_{i=1}^{D_i}\theta_{di}x_i\Big],\qquad y_j=\phi_{j0}+\sum_{d=1}^{D}\phi_{jd}h_d$$ 지금까지 배운 모든 버전(1입력-1출력, 1입력-다출력, 다입력-1출력)이 이 공식의 특수 사례

> [!question]+ 다중 출력은 어떻게 가능한가 — "분기 처리"가 있는 건가? 결론: 분기(if-else 조건 선택)가 아니라, **같은 계산된 값을 여러 독립적인 수식에 동시에 대입**하는 것
> 
> **hidden unit이 가진 두 종류의 가중치**
> 
> - 입력 쪽(θ): hidden unit 본인 소유, 1세트뿐 → $h_d$는 숫자 하나로 딱 정해짐
> - 출력 쪽(φ): hidden unit이 아니라 "hidden unit-출력 사이 연결선"의 소유 → 출력마다 다른 φ를 곱해 재사용
> - 비유: $h_d$(계산된 값)는 "원재료", 각 출력은 그 원재료를 자기만의 배합비(φ)로 쓰는 "요리"
> 
> **왜 분기가 아닌가**: $y_1,y_2$ 두 식은 조건에 따라 선택되는 게 아니라 항상 동시에, 각자 독립적으로 계산됨
> 
> **실제 정체는 행렬 곱셈**: $$\begin{bmatrix}y_1\y_2\end{bmatrix}=\begin{bmatrix}\phi_{10}\\phi_{20}\end{bmatrix}+\begin{bmatrix}\phi_{11}&\phi_{12}&\phi_{13}&\phi_{14}\\phi_{21}&\phi_{22}&\phi_{23}&\phi_{24}\end{bmatrix}\begin{bmatrix}h_1\h_2\h_3\h_4\end{bmatrix}$$ 행렬 Φ의 각 행이 "그 출력을 만드는 조합 방식". h 벡터는 공유하되, 행렬곱이 자동으로 각 행별 결과를 만들어냄. "다중출력"은 로직이 복잡해지는 게 아니라 출력층 뉴런 개수를 늘리는 것뿐

### 22.2 Deep Network

#### 22.2.1 네트워크 합성과 층별 출력, "접기(folding)" 직관

**2개의 네트워크를 하나로 합성 (가장 단순한 Deep network)**

- **Network 1**: 입력 x → hidden unit 3개($h_1,h_2,h_3$, 파라미터 θ) → 출력 y (지금까지 다룬 shallow network 그대로) $$h_1=a[\theta_{10}+\theta_{11}x],\ h_2=a[\theta_{20}+\theta_{21}x],\ h_3=a[\theta_{30}+\theta_{31}x],\quad y=\phi_0+\phi_1h_1+\phi_2h_2+\phi_3h_3$$
- **Network 2**: 입력 **y** → hidden unit 3개($h_1',h_2',h_3'$, 파라미터 θ') → 출력 y' (역시 shallow network, 단 입력이 x가 아니라 **Network 1의 출력 y**) $$h_1'=a[\theta_{10}'+\theta_{11}'y],\ h_2'=a[\theta_{20}'+\theta_{21}'y],\ h_3'=a[\theta_{30}'+\theta_{31}'y],\quad y'=\phi_0'+\phi_1'h_1'+\phi_2'h_2'+\phi_3'h_3'$$
- 핵심: **Network 1의 출력(y)이 그대로 Network 2의 입력**이 됨. 두 네트워크는 완전히 독립적인 파라미터 세트(θ vs θ', φ vs φ')를 가짐
- 흐름: $x \to (h_1,h_2,h_3) \to y \to (h_1',h_2',h_3') \to y'$
- 즉 **Deep network = Shallow network 두 개를 이어붙인 것(layer-wise composition)**. 이걸 은닉층이 2개인 네트워크라고 통합해서 부르기 전에, 일단 "네트워크 1 + 네트워크 2"로 나눠서 이해하는 단계

**층별 출력을 실제로 계산하는 과정 & "종이접기(folding)" 직관**

- b), c): 각 네트워크(Network1, Network2)가 만드는 개별 함수 그래프
- d): 그 둘을 실제로 이어붙였을 때 나오는 최종 합성 함수 (x → y' 직접 매핑) — 특정 x를 b)에 넣어 y를 구하고, 그 y를 c)에 넣어 y'을 구하는 과정을 모든 x에 반복해서 그린 것
- **핵심 원리("종이접기")**: b)가 오르락내리락(비단조)하기 때문에, 서로 다른 x구간 여러 개가 같은 y값으로 "접혀서" 이후 층(c)의 처리를 공유하게 됨 → 층을 쌓을수록 이런 접힘이 반복돼서, 최종 함수(d)는 개별 층보다 훨씬 많은 꺾임을 가진 복잡한 형태가 됨 → 이게 "깊어질수록 표현력이 폭발적으로 증가한다"는 말의 실제 메커니즘

**2D 입력으로 확장**

- 구조: $x_1,x_2 \to (h_1,h_2,h_3) \to y \to (h_1',h_2') \to y'$ (Network1: 입력 2개·유닛 3개, Network2: 입력 1개(y)·유닛 2개)
- b) $y$ as function of $(x_1,x_2)$: piecewise-**planar** 표면 (여러 fold line으로 나뉜 평면 조각들 — 22.1.4의 2D shallow network 결과와 동일한 형태)
- c) $y'$ as function of $y$ (1D): 삼각형(텐트) 모양 — 올라갔다 다시 내려오는 **비단조(non-monotonic)** 함수
- d) $y'$ as function of $(x_1,x_2)$: 최종 합성 결과 — b)보다 훨씬 더 많은 fold line(구획)을 가진 복잡한 패턴
- **의미**: 1D에서 본 folding 원리가 2D에서도 동일하게 작동함을 실제 등고선 그림으로 확인. c)가 비단조(텐트 모양)이기 때문에, b)에서 같은 y값을 갖는 여러 영역(등고선)들이 서로 "접혀서" 같은 y'값으로 매핑됨 → 최종 결과 d)는 b)의 조각들이 c)의 접힘을 따라 여러 번 반사(mirror)된 것처럼 훨씬 촘촘한 패턴이 됨

#### 22.2.2 Shallow vs Deep 비교

**비교 대상**

- **Deep network**: Network1+Network2 합성 구조 (은닉유닛 3개짜리 shallow network 2개를 이어붙임) — 파라미터 20개, 조각적 선형 구역 최대 16개
- **Shallow network**: 은닉층 1개, 은닉유닛 6개로 늘려 Deep과 파라미터 수를 비슷하게 맞춤 — 파라미터 19개, 조각적 선형 구역 최대 7개

**핵심 메시지**: 파라미터 개수가 거의 같은데도(20 vs 19), Deep network가 만들어낼 수 있는 구간 수(16개)가 Shallow network(7개)보다 훨씬 많음 → **Deep 네트워크의 표현력이 높음**

- 단순히 "hidden unit을 늘리면 표현력이 늘어난다"(22.1.3)는 사실이지만, **"같은 파라미터 예산이면 옆으로 넓히기(shallow, unit 늘리기)보다 위로 쌓기(deep, layer 늘리기)가 훨씬 효율적"**이라는 게 새로운 포인트

**왜 이런 차이가 나는가 (22.2.1 "종이접기"와 연결)**

- Shallow network: hidden unit들이 서로 "병렬"로만 작동 → 구간 수가 unit 개수에 비례해 **선형적으로**만 증가
- Deep network: 층을 거칠 때마다 "접힘"이 반복됨 → 구간 수가 층 깊이에 대해 **훨씬 빠르게(거듭제곱적으로)** 증가
- 그래서 파라미터 수는 비슷해도 표현 가능한 구간 수는 Deep 쪽이 압도적으로 많음

#### 22.2.3 행렬·벡터 수식화와 도식

- Layer-wise 구조를 수학적으로 조립, 레이어별로 히든 유닛 적용 + 활성화 함수 반복 적용
- 표기법 정리: 가중치/바이어스 표기는 교재·강의마다 다를 수 있음 (일원화 필요)

### 22.3 역전파(Backpropagation)

> [!info] 본격적인 설명 전에 — 왜 지금 이 내용을 배우는가
> 
> **21장(경사하강법)과의 관계**: 21장의 경사하강법 $w\leftarrow w-\eta\cdot\frac{\partial L}{\partial w}$은 "**기울기 $\partial L/\partial w$가 이미 있다는 가정 하에**, 그걸로 파라미터를 업데이트하는 방법"이었음. 신경망처럼 층이 여러 개면 "이 기울기를 대체 어떻게 계산하냐"는 문제가 남는데, 그 답이 역전파. 즉 **역전파 = 21장이 필요로 하는 재료(기울기)를 실제로 만들어주는 알고리즘**
> 
> **22.2.3(행렬·벡터 수식화)와의 관계**: $\mathbf{h}_1,\mathbf{h}_2,\ldots,\mathbf{h}_K$처럼 각 층을 $(\boldsymbol\Omega_k,\boldsymbol\beta_k)$로 반복 계산하는 **층별 연쇄 구조**가 있어야, 역전파의 핵심인 **연쇄법칙(chain rule)**을 이해할 수 있음. "순방향으로 층을 거쳐 값을 계산한다"는 걸 알아야, "역방향으로 층을 거슬러 기울기를 계산한다"는 역전파 원리가 자연스럽게 이어짐
> 
> **한 줄 요약**: 순전파(forward, 22.2.3)로 값을 앞으로 계산했다면, 역전파(backward)는 그 계산을 거슬러 올라가며 각 파라미터가 손실에 얼마나 영향을 줬는지(기울기)를 계산하는 것 → 이 기울기를 21장의 경사하강법에 넘겨줘서 파라미터를 업데이트

**역전파란**: 출력 오차를 기준으로, 계산 그래프를 **거꾸로**(출력층→입력층) 따라가며 연쇄법칙으로 각 층의 미분값을 구하는 절차

**핵심 원리**: 연쇄법칙(합성함수의 변화율 = 바깥의 변화율 × 안쪽의 변화율)을 층마다 반복 적용

**흐름**

- **시작점은 출력층**: 손실함수 정의로부터 "출력이 살짝 바뀌면 손실이 얼마나 바뀌는가"를 **직접** 계산할 수 있음 (예: MSE라면 손실식만 미분하면 바로 나옴)
- 이 마지막 층 기울기를 "이미 아는 값"으로 두고, 연쇄법칙으로 그 앞 층 → 또 그 앞 층... **입력 방향으로 거슬러 가며** 나머지를 구함
- **핵심(효율성의 이유)**: 각 층은 바로 다음 층에서 이미 계산해둔 기울기를 재사용. 처음부터 다시 계산하지 않음
- **특정 층만 타겟하지 않고, 한 번의 역전파로 전체 층의 기울기를 다 구함** — 연쇄법칙 구조상 어차피 출력층부터 순서대로 거쳐와야 하므로, 지나가는 김에 모든 층을 다 계산해두는 게 자연스러움
- 이렇게 층마다 구해지는 기울기가, 그 층의 파라미터를 얼마나/어느 방향으로 조정해야 하는지 알려주는 재료가 됨 — 21장(경사하강법)이 필요로 하는 최종 결과물

> [!question]+ 역전파 = "기울기 계산"까지만. 가중치 수정은 별도 단계 역전파와 경사하강법을 하나로 뭉뚱그리기 쉬운데, 둘은 **분리된 두 단계**:
> 
> 1. **역전파(1번의 backward pass)**: 출력층→입력층으로 거슬러 가며 **모든 층의 기울기를 다 계산** — 여기서 끝, 아직 아무것도 수정 안 함
> 2. **파라미터 업데이트(그 다음, 경사하강법)**: 계산해둔 기울기들로 **모든 층의 가중치를 동시에** 조정 (일부 층을 "얼려서" 제외하는 전이학습 같은 특수한 경우도 있지만, 기본적으로는 전체 층이 다 업데이트됨)
> 
> "한 층 미분 구하고 → 그 층만 수정하고 → 다음 층으로" 처럼 번갈아 하는 게 아니라, **"계산 다 끝내고 → 한 번에 업데이트"**. 역전파는 재료(기울기)만 만들고, 그 재료로 실제 수정을 하는 건 경사하강법의 몫
> 
> **이 조정은 사람이 직접 하지 않고 완전히 자동화됨** — 경사하강법 업데이트 식이 고정된 수학 공식이라 코드가 매 스텝마다 자동 실행. 사람은 학습률 같은 하이퍼파라미터를 미리 정하고, 손실 그래프로 학습이 잘 되고 있는지 모니터링할 뿐, 파라미터 값 자체를 손대지는 않음

**한 문장 요약**: 순전파가 "왼쪽→오른쪽으로 값을 계산하며 만든 계산 그래프"라면, 역전파는 그 그래프를 "오른쪽→왼쪽으로 거슬러 가며, 각 정거장마다 그 지점의 파라미터 기울기를 캐내는" 과정
