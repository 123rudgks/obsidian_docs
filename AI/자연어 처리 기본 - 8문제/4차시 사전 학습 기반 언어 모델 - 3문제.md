# 자연어 처리 기본 — 4차시: 사전 학습 기반 언어 모델

# 0. 강의 전체 개요

앞 차시까지는

```text
Word Embedding
      ↓
RNN / LSTM
      ↓
Seq2Seq
      ↓
Attention
      ↓
Transformer
```

의 흐름으로 자연어를 표현하고 생성하는 Architecture를 배웠다.

이번 강의에서는 Transformer를 이용해 **대규모 Text를 먼저 학습한 뒤 다양한 Task에 재사용하는 Pre-trained Language Model**을 배운다.

전체 흐름은 다음과 같다.

```text
Transformer
      ↓
대용량 Text로
일반적인 언어 능력을 먼저 학습
      ↓
Pre-training
      ↓
특정 Task에 맞게 추가 학습
      ↓
Fine-tuning
      ↓
Transformer의 어떤 구조를 쓰는가?
      ↓
──────────────────────────
Encoder-only
→ BERT
→ Text Understanding

Encoder–Decoder
→ T5
→ Text-to-Text

Decoder-only
→ GPT
→ Autoregressive Language Modeling
──────────────────────────
      ↓
Model Scale 증가
      ↓
GPT-2 / GPT-3
      ↓
Parameter를 다시 학습하지 않고도
Context에서 Task를 파악
      ↓
In-context Learning
      ↓
예제와 중간 추론 과정 제공
      ↓
Chain-of-Thought
```

---

# 1. Pre-trained Language Model이란?

이번 강의에서는 본격적인 Large Language Model로 넘어가기 전에 일반적인 **Pre-trained Language Model**의 개념을 다룬다.

핵심 아이디어는

> **처음부터 특정 Task 하나만 학습하지 말고, 대규모 Text를 이용해 언어 자체에 대한 일반적인 능력을 먼저 학습하자.**

이다.

그다음 필요한 Task가 주어졌을 때 이 Model을 재사용한다.

---

# 2. 사전학습의 두 단계

강의에서는 기본적인 Pre-trained Model 활용을 크게 두 Step으로 설명한다.

```text
Step 1
Pre-training

대규모 Text
↓
일반적인 Language Model 학습


Step 2
Fine-tuning

Pre-trained Model
+
특정 Task Data
↓
Task에 맞게 추가 학습
```

---

# 3. Pre-training

**Pre-training(사전학습)** 은 대규모 Data를 사용하여 Model에게 먼저 일반적인 언어 구조를 학습시키는 것이다.

예를 들어 Model은 Text를 통해

- Word 관계
    
- Context
    
- Sentence 구조
    
- 의미 관계
    
- Language Pattern
    

등을 넓게 학습한다.

즉 처음부터

```text
긍정 / 부정
```

같은 특정 Label만 배우는 것이 아니다.

---

# 4. Fine-tuning

Pre-training된 Model을 특정 Task Data에 맞춰 추가로 Training하는 것을 **Fine-tuning(미세조정)** 이라고 한다.

예:

```text
Pre-trained Language Model
      ↓
감성 분석 Data
      ↓
Fine-tuning
      ↓
Sentiment Model
```

또는

```text
Pre-trained Model
      ↓
문서 분류 Data
      ↓
Fine-tuning
```

으로 사용할 수 있다.

강의에서는 기존 Parameter가 특정 Task에 맞게 조금씩 수정되기 때문에 이를 미세조정이라고 설명한다.

---

# 5. 왜 Pre-training을 하는가?

과거에는 Task마다 별도의 Model을 만들고 별도로 Training하는 방식이 일반적이었다.

예:

```text
Sentiment Model
→ 별도 Architecture

NER Model
→ 별도 Architecture

Sentence Similarity Model
→ 별도 Architecture
```

하지만 이것은

- Architecture를 매번 설계해야 하고
    
- 각 Task마다 별도로 Training해야 하며
    
- Labelled Data도 많이 필요하다.
    

Pre-training은 이 구조를 바꾼다.

```text
하나의 거대한 General Model
      ↓
Task마다 조금씩 Fine-tuning
```

하는 방향이다.

---

# 6. Transformer는 세 가지 방식으로 사용할 수 있다

Transformer에는

```text
Encoder
+
Decoder
```

가 있었다.

하지만 Pre-trained Language Model에서는 반드시 둘을 모두 사용해야 하는 것은 아니다.

대표적으로

```text
Encoder-only

Encoder–Decoder

Decoder-only
```

세 가지가 가능하다.

---

# 7. 세 구조의 대표 모델

이번 강의의 중심 Model은 다음과 같다.

|Transformer 사용 방식|대표 모델|기본 방향|
|---|---|---|
|Encoder-only|BERT|Text 이해|
|Encoder–Decoder|T5|Text → Text|
|Decoder-only|GPT|다음 Token 생성|

이 세 Model의 차이는 단순히 이름을 외우기보다

> **어떤 Training Problem을 만들었고, 그 때문에 어떤 능력을 학습했는가**

로 연결해서 이해해야 한다.

---

# 8. Encoder-only란?

Encoder는 Input Sequence 전체를 받아 각 Token에 대한 Contextual Representation을 만든다.

```text
Input Text
      ↓
Transformer Encoder
      ↓
Context-aware Hidden Vectors
```

Decoder가 없으므로 기본적으로

```text
다음 Text를 Autoregressive하게 생성
```

하는 것보다는 Text를 **이해하고 표현하는 역할**에 초점이 맞는다.

---

# 9. Encoder-only의 활용

Encoder에서 얻은 Hidden Vector 뒤에 Task-specific Layer를 붙일 수 있다.

예:

```text
Encoder
↓
Sequence Representation
↓
Classifier
↓
Positive / Negative
```

또는 Token별 Hidden Vector를 이용해서

```text
Token Classification
```

을 수행할 수도 있다.

대표적인 Encoder-only Model이 **BERT**다.

---

# 10. BERT

BERT는 Transformer의 **Encoder 구조를 중심으로 사용하는 Pre-trained Language Model**이다.

강의에서는 BERT가 일반적인 다음 Word Prediction과 다른 방식으로 Pre-training한다는 점을 강조한다.

그 방법이 **Masked Language Modeling(MLM)** 이다.

---

# 11. 일반 Language Modeling과 BERT의 차이

앞서 배운 일반적인 Language Model은

```text
I like
      ↓
다음 Word?
      ↓
you
```

처럼 **이전 Context를 보고 다음 Token을 예측**했다.

반면 BERT의 Masked Language Modeling은

```text
I [MASK] you
      ↓
[MASK]에 들어갈 Word?
      ↓
love
```

처럼 문장 중간의 일부 Token을 가리고 원래 Token을 맞힌다.

---

# 12. Masked Language Modeling

MLM의 기본 구조는

```text
원래 Sentence
      ↓
일부 Token Masking
      ↓
문장 전체를 Encoder에 입력
      ↓
[MASK] 위치의 Representation
      ↓
원래 Word Prediction
```

이다.

즉 일종의 **빈칸 맞히기 문제**다.

---

# 13. BERT가 Bidirectional한 이유

빈칸이 문장 중간에 있으면 그 Word를 맞히기 위해

```text
왼쪽 Context
+
오른쪽 Context
```

를 모두 사용할 수 있다.

예:

```text
The [MASK] is barking loudly.
```

라면 `[MASK]` 앞쪽뿐 아니라 뒤쪽의

```text
is barking loudly
```

정보도 활용할 수 있다.

따라서 BERT는 특정 Token을 표현할 때 **양쪽 Context를 모두 이용하는 Bidirectional Representation**을 학습한다.

---

# 14. 왜 모든 Word를 Masking하지 않는가?

모든 Token을 가려버리면 Context 자체가 사라진다.

```text
[MASK] [MASK] [MASK] [MASK]
```

만 보고 원래 Sentence를 맞히기는 어렵다.

반대로 너무 적게 Mask하면 한 Sentence에서 얻을 수 있는 Training Signal이 줄어든다.

따라서 적당한 비율만 Prediction Target으로 선택한다.

---

# 15. 강의에서 설명한 BERT의 15%

강의에서는 BERT Pre-training에서 약 **15%의 Token을 Prediction Target으로 선택**한다고 설명한다.

그리고 그 선택된 Token 중

```text
80%
→ [MASK]로 변경

10%
→ Random Word로 변경

10%
→ 원래 Word 그대로 유지
```

하는 구조를 설명한다.

---

# 16. 80% — 실제 Mask

가장 일반적인 경우다.

```text
I love pizza
      ↓
I [MASK] pizza
```

처럼 원래 Word를 `[MASK]` Token으로 바꾸고 원래 Word를 Prediction한다.

---

# 17. 10% — Random Word

일부 Token은 `[MASK]`가 아니라 전혀 다른 Word로 바꾼다.

강의에서는 예를 들어 맥락과 상관없는 `pizza` 같은 Word를 넣는 사례를 든다.

강의의 설명에서는 이런 Training이 입력에 예상하지 못한 Word나 Noise가 존재하는 상황에서도 Context를 활용하게 만드는 Engineering 효과가 있다고 설명한다.

---

# 18. 10% — 원래 Word 유지

선택된 Token 중 일부는 Input을 그대로 둔다.

즉

```text
Input Word
=
Target Word
```

가 된다.

겉으로 보면 너무 쉬운 문제처럼 보일 수 있다.

강의에서는 실제 활용 시에는 `[MASK]`라는 Token이 존재하지 않고 일반 Word들이 들어오기 때문에, Training에서도 일반 Token 상태의 Representation을 학습하도록 일부를 그대로 유지한다고 설명한다.

---

# 19. MLM은 사람이 Label을 만들 필요가 없다

Pre-training을 대규모로 할 수 있는 결정적인 이유다.

원래 Text가

```text
The dog is running.
```

이라면

```text
The [MASK] is running.
```

이라는 Training Input을 자동으로 만들 수 있다.

정답 `dog`도 이미 원문에 존재한다.

즉 별도의 사람이

```text
정답 = dog
```

라고 Labeling할 필요가 없다.

---

# 20. 대규모 Text 자체가 정답을 제공한다

감성 분석에서는 사람이

```text
이 Review = Positive
```

라고 Label을 붙여야 한다.

하지만 MLM은 Text 자체에서

```text
Input
Target
```

을 자동으로 만들 수 있다.

따라서 웹 등에 존재하는 방대한 Text를 Pre-training에 사용할 수 있다.

강의에서는 이것을 대규모 사전학습이 가능해지는 핵심 이유로 설명한다.

---

# 21. BERT의 Output

BERT Encoder의 마지막 Layer에는 각 Token마다 Context가 반영된 Hidden Vector가 있다.

Masked Position의 Vector를 Vocabulary Dimension으로 변환한 뒤

```text
Softmax
```

를 적용하면 어떤 Word가 원래 Token이었는지 Probability Distribution을 얻을 수 있다.

Prediction과 원래 Word를 비교해 Loss를 계산한다.

---

# 22. BERT의 [CLS] Token

BERT에서는 Sentence 맨 앞에 **[CLS]**라는 Special Token을 추가할 수 있다.

```text
[CLS] I love this movie
```

`CLS`는 Classification을 의미하는 Special Token으로 설명된다.

이 Token의 최종 Hidden Representation은 Sentence 전체를 대표하는 Representation으로 활용할 수 있다.

---

# 23. Token Representation과 Sequence Representation

BERT에서는 둘 다 중요하다.

### Token별 Representation

```text
각 Word의 Contextual Representation
```

→ NER 등의 Token-level Task

### [CLS] Representation

```text
전체 Sequence를 종합한 Representation
```

→ Sentence Classification 등의 Sequence-level Task

---

# 24. BERT의 두 번째 Pre-training Task — NSP

강의에서는 BERT의 또 다른 Pre-training Task로 **Next Sentence Prediction(NSP)** 을 소개한다.

요즘에는 덜 사용하는 방식이라고 언급하지만 시험 가능성을 고려해 개념을 설명한다.

---

# 25. NSP의 기본 문제

두 Sentence를 Model에 입력한다.

그리고

```text
Sentence A
[SEP]
Sentence B
```

형태로 구분한다.

두 Sentence가 실제 문서에서 서로 이어지는 관계인지 판단한다.

---

# 26. NSP의 Label

두 가지 Label이 있다.

```text
IsNext
→ 실제로 이어지는 Sentence

NotNext
→ 이어지지 않는 Sentence
```

즉 Binary Classification 문제다.

---

# 27. NSP에서는 [CLS] Representation을 사용한다

두 Sentence 전체의 관계를 판단해야 하므로 특정 Token 하나만 봐서는 안 된다.

따라서 `[CLS]` Token의 최종 Representation을 이용해

```text
IsNext
vs
NotNext
```

를 Classification한다.

---

# 28. [SEP] Token

`[SEP]`는 Sequence나 Sentence 사이의 경계를 나타내는 Special Token이다.

예:

```text
[CLS]
Sentence A
[SEP]
Sentence B
[SEP]
```

와 같은 구조로 사용할 수 있다.

---

# 29. 왜 전체 Sequence Representation이 필요한가?

실제 NLP Task에는 Word 하나를 이해하는 것만 필요한 것이 아니다.

예:

- Sentiment Classification
    
- Sentence Similarity
    
- Natural Language Inference
    
- Document Classification
    

등은 전체 Sequence를 종합한 Representation이 필요하다.

강의에서는 NSP 등을 통해 이런 전체 Sequence 표현의 필요성을 설명한다.

---

# 30. BERT Downstream Task ① — Sequence Classification

예:

```text
Review
↓
BERT
↓
[CLS]
↓
Classifier
↓
Positive / Negative
```

같은 Sentiment Analysis다.

전체 Sentence에 하나의 Label을 예측한다.

---

# 31. BERT Downstream Task ② — Sentence Pair

두 Sentence를 입력해서

- 서로 유사한가?
    
- 논리적으로 관련되는가?
    
- 서로 모순되는가?
    

등을 판단할 수 있다.

즉 Sentence Pair 전체의 Representation을 이용한 Classification/Regression 문제로 활용할 수 있다.

---

# 32. BERT Downstream Task ③ — Token Classification

이번에는 Sentence 전체에 Label 하나를 붙이는 것이 아니라 **각 Token마다 Label을 예측**한다.

대표적인 예가 **Named Entity Recognition(NER)** 이다.

---

# 33. Named Entity Recognition

Sentence 안에서

- Person
    
- Organization
    
- Location
    
- 기타 Entity
    

등을 찾아내는 문제다.

예:

```text
Microsoft Research Asia
```

라는 여러 Token이 하나의 Organization Name을 구성할 수 있다.

---

# 34. BIO Tagging

강의에서는 간단한 NER Labeling 방식으로 **BIO Tag**를 설명한다.

```text
B = Begin
→ Entity의 시작

I = Inside
→ Entity 내부

O = Outside
→ Entity가 아님
```

예:

```text
Microsoft   B
Research    I
Asia        I
is          O
...
```

---

# 35. Entity 종류까지 구분할 수도 있다

단순히 Entity 여부만 판단하는 대신

```text
B-PER
I-PER

B-LOC
I-LOC

B-ORG
I-ORG
```

처럼 Entity Type까지 구분하는 방식도 가능하다.

강의에서는 Person, Location, Organization 등의 종류를 예로 든다.

---

# 36. BERT가 가지는 큰 변화

BERT 이전에는 각각의 Dataset과 Domain에 따라 별도의 Architecture를 만드는 경우가 많았다.

BERT가 보여준 중요한 변화는

```text
하나의 Transformer Encoder
      ↓
대규모 Pre-training
      ↓
여러 Task에 동일 Model 재사용
      ↓
Task별 Fine-tuning
```

만으로 다양한 NLP Task에서 높은 성능을 얻을 수 있다는 것이었다.

---

# 37. Model Design의 패러다임 변화

기존:

```text
Task A
→ Architecture A

Task B
→ Architecture B

Task C
→ Architecture C
```

Pre-trained Model:

```text
One Pre-trained Model
          ↓
    Fine-tuning
 ┌────────┼────────┐
Task A  Task B   Task C
```

즉 NLP Architecture의 범용화가 이루어진다.

---

# 38. Encoder-only 핵심 정리

```text
Transformer Encoder
      ↓
Bidirectional Context
      ↓
Language Understanding Representation
      ↓
Task-specific Head
      ↓
Classification / Regression / Token Prediction
```

대표:

```text
BERT
```

---

# 39. 이제 Encoder–Decoder Model

다음은 Transformer의 Encoder와 Decoder를 모두 사용하는 Pre-trained Model이다.

이 구조는 원래 Seq2Seq에서 배웠듯이

```text
Input Sequence
      ↓
Encoder
      ↓
Decoder
      ↓
Output Sequence
```

형태다.

대표적인 Model로 강의에서는 **T5**를 설명한다.

---

# 40. Encoder–Decoder는 생성 Task에 자연스럽다

Encoder는 Input Text를 읽고 Representation을 만든다.

Decoder는 이를 Condition으로 Output Text를 생성한다.

따라서

- Translation
    
- Summarization
    

같은 Seq2Seq Task와 자연스럽게 연결된다.

---

# 41. Encoder–Decoder를 어떻게 Pre-training할까?

단순하게 생각하면

```text
앞부분 Text
→ Encoder

뒷부분 Text
→ Decoder Target
```

으로 만들 수도 있다.

즉 이전 Context로 다음 Context를 생성하게 하는 일반 Language Modeling이다.

강의에서는 그러나 이런 방식만 사용하는 것이 Encoder 학습 관점에서 좋지 않을 수 있다고 설명한다.

---

# 42. 단순 Next-context Generation의 문제

긴 Document가 있다고 하자.

예를 들어 앞 600페이지를 읽고 601페이지를 생성한다면 실제 다음 Text를 만드는 데

```text
599페이지
600페이지
```

가 매우 중요하고

```text
1페이지
2페이지
```

는 상대적으로 덜 직접적인 영향을 줄 수 있다.

그러면 Encoder가 Input 전체의 정보를 고르게 잘 이해하도록 학습되지 않을 가능성이 있다.

---

# 43. 그래서 Denoising Pre-training

Encoder–Decoder Pre-training에서는 Input의 일부를 의도적으로 Corruption시킨 뒤 원래 Text를 복원하는 **Denoising** 문제를 사용할 수 있다.

```text
Original Text
      ↓
일부 Span 손상
      ↓
Corrupted Input
      ↓
Encoder–Decoder
      ↓
원래 Content 복원
```

이다.

---

# 44. Span Corruption

강의에서는 연속된 Text 일부를 `X`, `Y` 같은 Special Symbol로 바꾼 뒤 Decoder가 원래 Span을 복원하도록 하는 구조를 설명한다.

예를 들어 원문이

```text
Thank you for inviting me
to your party last week.
```

라면 일부 구간을 가리고 이를 다시 생성하도록 Training한다.

---

# 45. 왜 Denoising이 도움이 되는가?

문장 중간의 여러 부분을 복원하려면 Encoder는 특정 마지막 부분만 보면 안 된다.

```text
앞
중간
뒤
```

전체 Context를 종합적으로 파악해야 한다.

즉

> **Input 전체를 잘 이해하도록 Encoder에 강한 Training Signal을 줄 수 있다.**

는 것이 강의의 설명이다.

---

# 46. Denoising의 단점으로 생각할 수 있는 점

자연어 Generation은 보통

```text
앞 Context
→ 자연스러운 다음 Text
```

형태다.

Denoising은 인위적으로 Text를 망가뜨린 뒤 복원하는 문제이므로

> 실제 자연스러운 Text Generation과 조금 다른 Task 아니냐?

라는 의문이 생길 수 있다.

강의에서는 이런 직관적인 우려를 언급하지만, Denoising 방식이 실제로 좋은 성능을 보였다고 설명한다.

---

# 47. T5

대표적인 Encoder–Decoder Pre-trained Model로 **T5**를 설명한다.

T5의 중요한 아이디어는

> **서로 다른 NLP Task를 모두 Text Input → Text Output 문제로 통일하자.**

이다.

그래서 **Text-to-Text Transfer Transformer**라는 이름을 사용한다.

---

# 48. 기존에는 Task마다 Output 형식이 달랐다

예:

### Translation

```text
Text → Text
```

### Summarization

```text
Text → Text
```

### Classification

```text
Text → Class Label
```

### Regression

```text
Text Pair → Numeric Score
```

즉 Problem Type이 서로 달랐다.

---

# 49. T5는 모두 Text Generation으로 바꾼다

예를 들어 Classification도

```text
Input:
문장

Output:
acceptable
```

처럼 Class를 나타내는 **Text 자체를 생성**한다.

Regression 역시

```text
Output:
"3.8"
```

처럼 숫자를 Text Token으로 생성하는 방식으로 표현할 수 있다.

---

# 50. 모든 Task를 하나의 형식으로

따라서

```text
Translation
Summarization
Classification
Regression
...
```

을 모두

```text
Text
↓
Transformer
↓
Text
```

라는 하나의 Framework로 통일할 수 있다.

---

# 51. Prefix

그런데 여러 Task를 같은 Model로 동시에 학습하면 Model이

> 지금 Translation을 해야 하는가?  
> Summarization을 해야 하는가?

를 알아야 한다.

그래서 Input 앞에 Task를 구별하는 **Prefix**를 붙인다.

예:

```text
translate:
...

summarize:
...
```

와 같은 개념이다.

---

# 52. Prefix의 역할

강의에서 이 시점의 Prefix는

> **Task를 구별하기 위한 일종의 Tag**

로 설명한다.

즉 현대 LLM의 복잡한 Instruction과 완전히 같은 단계의 개념으로 보지는 않는다.

하지만 이후 더 구체적인 자연어 설명으로 발전하면 Instruction과 연결될 수 있다고 설명한다.

---

# 53. Multi-task Learning

T5는 여러 Task를 동시에 Training할 수 있다.

```text
Translation
+
Grammar Classification
+
Sentence Similarity
+
Summarization
+
...
```

을 하나의 Model에서 Training한다.

Task들은 Prefix로 구별한다.

---

# 54. Multi-task의 기대 효과

각 Task가 완전히 독립적이지 않고 공유할 수 있는 Language Knowledge가 있다면

```text
Task A에서 배운 정보
↔
Task B에 도움
```

이 될 수 있다.

즉 하나의 Model 안에서 다양한 Task가 서로 Representation 학습을 보조할 가능성이 있다.

---

# 55. T5와 요약

강의에서는 T5 같은 Encoder–Decoder Pre-trained Model이 요약과 같은 Task에 잘 맞는 이유를 연결한다.

요약에서는 긴 Input의

- 앞
    
- 중간
    
- 뒤
    

전체 정보를 이해해야 한다.

Denoising Pre-training 역시 Input 전체의 Context를 활용하도록 Encoder를 학습시키므로 이런 Task와 잘 연결된다고 설명한다.

---

# 56. Encoder–Decoder 핵심 정리

```text
Input 전체를 이해
      ↓
Encoder
      ↓
생성
      ↓
Decoder
```

대표:

```text
T5
```

Pre-training:

```text
Denoising / Span Corruption
```

Task 표현:

```text
Everything → Text-to-Text
```

---

# 57. 마지막은 Decoder-only

세 번째 구조는 **Transformer Decoder만 사용하는 Model**이다.

대표적인 계열이

```text
GPT
```

다.

강의에서는 현대 Language Model에서 Decoder-only 방식이 매우 중요한 구조가 되었다고 설명한다.

---

# 58. 그런데 Encoder–Decoder도 생성할 수 있다

따라서

> “Decoder-only를 쓰는 이유는 생성이 가능해서다.”

만으로는 충분한 설명이 아니다.

T5 같은 Encoder–Decoder도 Text를 생성할 수 있기 때문이다.

강의에서는 다른 관점으로 Decoder-only의 장점을 설명한다.

---

# 59. 같은 Resource를 어디에 집중할 것인가?

원래 Transformer가

```text
Encoder 6 Blocks
+
Decoder 6 Blocks
```

이라고 하자.

총 12개의 Block에 Resource를 사용한다.

만약 Decoder-only라면 같은 정도의 Resource로

```text
Decoder 12 Blocks
```

처럼 한쪽에 모든 Depth를 집중할 수 있다.

강의에서는 Model Depth가 증가하며 성능이 좋아지는 흐름과 연결해 이를 설명한다.

---

# 60. Decoder-only에서도 Context를 이해한다

`Decoder-only`라는 이름 때문에

> 입력을 이해하는 Encoder 기능이 전혀 없다.

고 오해하면 안 된다.

Decoder 내부에도 **Masked Self-Attention**이 있다.

이미 주어진 이전 Context Token들끼리는 Attention을 수행한다.

```text
Context Tokens
      ↓
Masked Self-Attention
      ↓
Contextual Representation
```

즉 Decoder 내부에서도 Context를 Encoding하는 과정이 일어난다.

---

# 61. 차이는 미래를 못 보는 것

Encoder의 Self-Attention:

```text
왼쪽 + 오른쪽 Context
모두 참조 가능
```

Decoder의 Masked Self-Attention:

```text
현재보다 이전 Context만 참조
미래 Token은 참조 불가
```

따라서 Decoder는 **Autoregressive Generation**에 최적화된 구조다.

---

# 62. Decoder-only도 Classification할 수 있다

Decoder가 생성에 적합하다고 해서 생성만 가능한 것은 아니다.

강의에서는 GPT-1도

- Sentence 관계
    
- Sentiment
    
- Text Classification
    

같은 Understanding Task에 활용되었다고 설명한다.

즉 마지막 Representation 등에 Classification Layer를 붙여 다른 Task에도 사용할 수 있다.

---

# 63. GPT-1

강의에서는 GPT-1을 상대적으로 작은 Decoder-only Transformer로 설명한다.

초기 GPT는 오늘날의 거대한 Generative AI와 달리 BERT와 유사하게 여러 NLP Understanding Task에 활용되었다.

---

# 64. GPT-2 — Scale-up

GPT 구조의 Size를 크게 확장했더니 Text Generation 능력이 크게 향상됐다.

강의에서는 GPT-2에서

> **Model을 Scale-up했더니 자연스러운 문장을 훨씬 잘 생성한다.**

는 점을 Generative AI 발전의 중요한 단계로 연결한다.

---

# 65. GPT-3 — 더 큰 Scale

강의에서는 GPT-3의 약 **175B(1,750억) Parameter** 규모를 예로 들며 Model을 더 크게 확장했을 때 새로운 능력들이 나타나는 흐름을 설명한다.

그중 중요한 것이 **In-context Learning**이다.

---

# 66. 기존 Fine-tuning

기존에는 새로운 Task가 있으면

```text
Pre-trained Model
      ↓
Task Dataset
      ↓
Backpropagation
      ↓
Parameter Update
      ↓
Fine-tuned Model
```

이 필요했다.

즉 Model Parameter를 실제로 바꿨다.

---

# 67. In-context Learning

In-context Learning에서는 Parameter를 다시 Training하지 않는다.

대신 Input Context에

- Instruction
    
- Example
    
- Task Pattern
    

등을 제공한다.

Model이 이를 보고

> **지금 어떤 문제를 풀어야 하는지**

를 파악한다.

---

# 68. Training과 Learning을 강의에서 구분하는 방식

강의에서는 다음과 같이 구분한다.

### Training

```text
Model Parameter를 실제로 Update
```

### Learning

더 넓은 의미에서

```text
Pattern이나 Task를 파악하고
그에 맞는 행동을 하는 것
```

으로 설명한다.

따라서 In-context Learning은

```text
Parameter Update 없이
Forward Process만으로
Task Pattern을 파악
```

하는 Learning으로 설명한다.

---

# 69. In-context Learning 예

예를 들어 Prompt에

```text
English: hello
Korean: 안녕하세요

English: apple
Korean: 사과

English: book
Korean:
```

같은 Pattern을 주면 Model이

> 이것은 영어를 한국어로 번역하는 Task구나.

라고 Context에서 파악할 수 있다.

Parameter를 새로 Training하지 않아도 된다.

---

# 70. Example을 주는 이유

Task 설명만 제공할 수도 있고 Example을 같이 제공할 수도 있다.

```text
Instruction
+
Examples
```

가 있으면 Model이 Input Pattern을 더 명확하게 파악할 수 있다.

이것이 이후

- Zero-shot
    
- Few-shot
    

같은 Prompting 방식과 연결된다.

---

# 71. Chain-of-Thought

강의에서는 In-context Learning에서 단순히 정답 Example만 주는 것보다

> **문제를 해결하는 중간 사고/생성 과정의 Example**

까지 제공할 수 있다고 설명한다.

이를 **Chain-of-Thought(CoT)** 와 연결한다.

---

# 72. CoT의 직관

단순 Example:

```text
Question
→ Answer
```

보다

```text
Question
→ 중간 풀이 과정
→ Answer
```

형태의 Pattern을 제공한다.

그러면 Model이 수학·코딩 등의 문제에서 비슷한 중간 추론 Pattern을 생성하며 문제를 해결하도록 유도할 수 있다는 설명이다.

---

# 73. BERT / T5 / GPT 구조 비교

|모델|Transformer 구조|핵심 Pre-training 방향|강의에서 강조한 용도|
|---|---|---|---|
|BERT|Encoder-only|Masked Language Modeling|Text Understanding|
|T5|Encoder–Decoder|Denoising / Text-to-Text|Generation + Understanding|
|GPT|Decoder-only|Autoregressive LM|Generation / In-context Learning|

---

# 74. 세 Model을 구조적으로 이해하기

## BERT

```text
앞 Context ← Token → 뒤 Context
         ↓
     Representation
```

양방향 Context를 이용해 **현재 Text를 이해**한다.

---

## T5

```text
Input Text
    ↓
Encoder
    ↓
Decoder
    ↓
Output Text
```

Input을 이해하고 **다른 Text를 생성**한다.

---

## GPT

```text
Previous Tokens
      ↓
Masked Self-Attention
      ↓
Next Token
      ↓
다시 Context에 추가
```

한 방향으로 Context를 읽으며 **계속 다음 Token을 생성**한다.

---

# 75. Pre-training Objective가 Model의 성격을 만든다

Architecture만 보고 끝내지 말고 Training Objective까지 연결해야 한다.

```text
BERT
→ 중간 빈칸 맞히기
→ 양방향 Context 이해


T5
→ 손상된 Text 복원
→ Input 전체 이해 + Generation


GPT
→ Next Token Prediction
→ Autoregressive Generation
```

즉

> **Model이 어떤 문제를 반복해서 풀며 사전학습했는지가 이후 Model의 강점과 연결된다.**

---

# 76. 왜 Pre-training은 강력한가?

핵심은 대규모 Data다.

특정 Task의 Labelled Dataset은 제한적일 수 있다.

하지만 일반 Text는 매우 많다.

그리고 Language Modeling은 Text 자체에서 Target을 만들 수 있다.

```text
대규모 Unlabelled Text
        ↓
자동으로 Training Target 생성
        ↓
General Language Knowledge
        ↓
작은 Task Dataset으로 Fine-tuning
```

이라는 구조가 가능하다.

---

# 77. Fine-tuning의 효율

처음부터 Task Model을 새로 Training하면 작은 Task Dataset만으로 모든 Language Representation까지 배워야 한다.

Pre-trained Model에서는 이미

- Syntax
    
- Semantic Pattern
    
- Word Relation
    
- Context
    

등을 어느 정도 학습했다.

따라서 특정 Task에서는

> **이 Language Knowledge를 해당 목적에 맞게 조정하는 것**

에 집중할 수 있다.

---

# 78. BERT의 Token-level vs Sequence-level

BERT에서는 두 Representation을 구분해 기억해야 한다.

```text
각 Token Hidden Vector
→ Token-level Task
→ NER 등


[CLS] Hidden Vector
→ Sequence-level Task
→ Sentiment / Sentence Classification
```

---

# 79. BERT의 Masking을 외우는 핵심

시험에서는 다음 구조가 중요하다.

```text
전체 Token 중 약 15%
→ Prediction Target

그 15% 중
├─ 80% [MASK]
├─ 10% Random Token
└─ 10% Original Token
```

그리고 목적은

> **양방향 Context를 이용해 원래 Token을 예측한다.**

이다.

---

# 80. NSP를 반드시 MLM과 구분

### MLM

```text
Token-level Prediction
```

### NSP

```text
Sentence Pair-level Prediction
```

즉

```text
MLM
→ 어떤 Word인가?

NSP
→ 두 Sentence가 실제로 이어지는가?
```

다.

---

# 81. T5의 핵심을 한 줄로

```text
모든 NLP Task를
Text → Text로 통일한다.
```

이것이 T5를 기억할 때 가장 중요한 특징이다.

Classification조차 Class ID가 아니라 Text Label을 생성하게 만들 수 있다.

---

# 82. T5 Prefix와 현대 Instruction의 연결

강의에서는 T5의 Prefix가 처음에는

```text
어떤 Task인가?
```

를 구별하는 Tag 역할이었다고 설명한다.

그리고 이러한 Task Description이 점점 더 자연어적이고 구체적인 형태가 되면 현대 Language Model의 **Instruction**과 연결해 볼 수 있다고 설명한다.

---

# 83. GPT의 핵심을 한 줄로

```text
앞에 있는 Context를 보고
다음 Token을 계속 예측한다.
```

이다.

이 단순한 Objective를 매우 큰

- Model
    
- Data
    
- Compute
    

규모로 확장하면서 다양한 능력이 나타난다는 흐름으로 연결된다.

---

# 84. Decoder-only에서 “Encoder가 없다”의 정확한 강의 맥락

매우 헷갈리기 쉬운 부분이다.

`Decoder-only`는 Transformer의 별도 Encoder Stack이 없다는 뜻이다.

그렇다고 Input Context를 Representation으로 바꾸는 계산 자체가 없다는 것은 아니다.

Decoder의 Self-Attention Layer 역시

```text
현재까지 주어진 Context
```

를 계속 Contextualize한다.

강의에서는 이런 의미에서 Decoder 내부에서도 일종의 Encoding은 일어난다고 설명한다.

---

# 85. Encoder–Decoder와 Decoder-only의 차이를 강의식으로 보기

Encoder–Decoder:

```text
Input 이해용 Parameter
+
Output 생성용 Parameter
```

를 명시적으로 분리한다.

Decoder-only:

```text
하나의 Decoder Stack
```

안에서 Context 이해와 Next-token Generation을 수행한다.

강의에서는 이를 분리된 Parameter를 쓰느냐 통합된 Parameter를 쓰느냐의 차이로도 직관적으로 설명한다.

---

# 86. Multilingual 상황

강의 Q&A에서는 Encoder–Decoder에서는 서로 다른 언어의 Representation을 별도로 다룰 수도 있다고 설명한다.

반면 여러 언어를 같은 Token/Embedding Space에서 표현할 수 있도록 Model이 학습된다면 Decoder-only Model에서도

```text
English Input
→ French Output
```

같은 Text-to-Text Task를 수행할 수 있다고 설명한다.

---

# 87. 실전 학습 우선순위에 대한 강의자의 언급

강의 마지막 Q&A에서 무엇을 중점적으로 공부해야 하는지 질문이 나온다.

강의자는 실전 관점에서

```text
RNN
Transformer
GPT / Decoder-only Language Model
```

의 중요성을 상대적으로 높게 이야기한다.

그리고 이번 과정에서

```text
Word Embedding
LSTM
```

은 상대적으로 우선순위가 조금 낮다고 언급한다.

다만 이것은 **강의자의 학습 우선순위에 대한 의견**이지 해당 개념이 불필요하다는 의미는 아니다.

---

# 88. Transformer가 유일한 Architecture인가?

강의 Q&A에서는 Transformer 이외의 Architecture 연구도 언급된다.

대표적으로 **Mamba**와 **State Space Model(SSM)** 을 이야기한다.

강의에서는 여전히 Transformer가 표준적인 기반이라고 설명하면서, Transformer의 한계를 해결하려는 다른 방식도 연구되고 있다고 소개한다.

---

# 89. Transformer와 Mamba의 강의식 비교

강의에서는 매우 높은 수준에서

### Transformer

```text
Token Representation들을
직접 유지하고
Attention으로 필요한 Token을 직접 참조
```

### RNN / State-space 계열

```text
이전 정보를
State라는 압축된 표현으로 유지
```

라는 차이로 설명한다.

Mamba는 후자의 State 기반 표현을 보다 고도화한 방향으로 소개된다.

---

# 90. 왜 다른 Architecture를 연구하는가?

Transformer Attention은 Sequence가 길어질수록 계산 부담이 커진다.

강의에서는

- Linear Attention
    
- Flash Attention
    
- State Space Model
    
- Transformer + Mamba Hybrid
    

등 계산 및 Architecture 측면에서 여러 개선 연구가 진행되고 있다고 언급한다.

---

# 91. 강의에서의 학습 순서 권장

Mamba/SSM 같은 Model은 훨씬 수학적으로 어렵기 때문에 강의에서는 먼저

```text
Transformer
↓
Transformer-based Language Model
↓
Decoder-only / GPT
```

를 충분히 이해한 뒤 다른 Architecture를 공부할 것을 권장한다.

---

# 92. Output Layer와 Word Embedding 관련 Q&A

강의 마지막에는 Language Model의 Output에서 Vocabulary Probability를 만들 때 Input Embedding을 다시 활용할 수 있는지에 대한 질문도 나온다.

강의에서는 실제로 Input Embedding Parameter를 Output 쪽에서도 재활용하는 Engineering 방식이 존재할 수 있다고 설명한다.

즉 Input Embedding과 Output Projection을 완전히 별개의 Parameter로 두는 것만이 유일한 방식은 아니다.

---

# 93. Ground Truth를 실제 거대한 One-hot Vector로 저장해야 하는 것은 아니다

Vocabulary Size가 매우 커도

```text
[0,0,0,...,1,...,0]
```

이라는 전체 Vector를 항상 실제로 명시적으로 만들어야 하는 것은 아니다.

정답 Token의 **Index**를 알고 있으면 된다.

Cross Entropy 계산에서도 결국 정답 Token 위치의 Prediction Probability가 중요하다.

강의에서는 구현 방식에 따라 효율적으로 처리할 수 있다고 설명한다.

# 94. 세 Architecture의 전체 비교

|구분|Encoder-only|Encoder–Decoder|Decoder-only|
|---|---|---|---|
|대표|BERT|T5|GPT|
|Attention|양방향 Self-Attention|Encoder + Masked Decoder + Cross Attention|Masked Self-Attention|
|핵심 목적|Text 이해|Input→Output 변환|Next Token 생성|
|대표 Pre-training|MLM|Denoising|Autoregressive LM|
|Input 전체 참조|가능|Encoder에서 가능|미래 Token 제외|
|Generation|기본 중심 아님|가능|매우 자연스러움|
|Classification|강함|Text 출력 형태 가능|가능|
|대표 활용|분류, NER, 이해|번역, 요약|생성, ICL|

# 95. Pre-training / Fine-tuning / In-context Learning 비교

|방식|Parameter Update|추가 Task Data|핵심|
|---|---|---|---|
|Pre-training|O|대규모 일반 Text|일반 언어 능력 학습|
|Fine-tuning|O|Task-specific Data|특정 Task에 적응|
|In-context Learning|X|Prompt 안의 Instruction/Example|Context에서 Task 파악|

# 96. Fine-tuning과 In-context Learning의 결정적 차이

### Fine-tuning

```text
Data
 ↓
Loss
 ↓
Backpropagation
 ↓
Parameter Update
```

### In-context Learning

```text
Instruction / Examples
 ↓
Forward Pass
 ↓
Task Pattern 파악
 ↓
Output
```

즉 Parameter가 바뀌지 않는다.

```text

      ↓
Model 스스로 Training Problem 생성

BERT
→ 일부 Word 가림

T5
→ 일부 Span 손상

GPT
→ 다음 Token을 Target으로 사용
      ↓
원래 Text 자체가 정답
```

따라서 사람의 대규모 수동 Labeling 없이 방대한 Corpus를 학습할 수 있다.

# 102. 자주 헷갈리는 점 ① — Pre-training과 Fine-tuning은 같은가?

아니다.

```text
Pre-training
→ 일반 언어 능력

Fine-tuning
→ 특정 Task에 맞게 조정
```

이다.

둘 다 Parameter를 Training한다는 점에서는 같지만 목적과 Data가 다르다.

---

# 103. 자주 헷갈리는 점 ② — BERT는 다음 Word를 예측하는가?

이번 강의에서 중심으로 설명하는 BERT Pre-training은 **Masked Word Prediction**이다.

즉 문장 중간의 가려진 Token을 양쪽 Context를 이용해 예측한다.

---

# 104. 자주 헷갈리는 점 ③ — BERT의 15%를 전부 [MASK]로 바꾸는가?

아니다.

강의에서 설명하는 원래 BERT 구조는 선택된 약 15% 중

```text
80% [MASK]
10% Random
10% 그대로
```

다.

---

# 105. 자주 헷갈리는 점 ④ — [CLS]는 일반 Word인가?

아니다.

특별한 목적을 가진 Special Token이다.

전체 Sequence Representation을 모아 Classification 등에 사용할 수 있다.

---

# 106. 자주 헷갈리는 점 ⑤ — MLM과 NSP는 같은 Task인가?

아니다.

```text
MLM
→ Token Prediction

NSP
→ Sentence Pair Classification
```

이다.

---

# 107. 자주 헷갈리는 점 ⑥ — BERT는 Token-level Task만 가능한가?

아니다.

Token Representation으로 NER 등을 할 수 있고 `[CLS]` Representation으로 Sequence Classification도 수행할 수 있다.

---

# 108. 자주 헷갈리는 점 ⑦ — T5는 생성 Task만 학습하는가?

T5의 중요한 특징은 **원래 Classification/Regression인 문제까지 Text Output Generation 형태로 바꾼다**는 것이다.

그래서 하나의 Text-to-Text Framework로 여러 Task를 통합한다.

---

# 109. 자주 헷갈리는 점 ⑧ — Prefix가 곧 현대의 Instruction인가?

강의에서는 이 시점의 Prefix는 주로 Task를 구별하기 위한 Tag라고 설명한다.

다만 이것이 더 구체적인 자연어 설명으로 발전하면 현대의 Instruction과 연결해서 볼 수 있다.

---

# 110. 자주 헷갈리는 점 ⑨ — Decoder-only는 Input을 이해하지 않는가?

아니다.

별도의 Transformer Encoder Stack이 없다는 뜻이다.

Decoder 내부의 Self-Attention으로 이전 Context의 Representation을 학습한다.

---

# 111. 자주 헷갈리는 점 ⑩ — Decoder-only는 생성에만 사용할 수 있는가?

아니다.

강의에서는 GPT-1 같은 Decoder-only Model도 Classification 등 Text Understanding Task에 사용할 수 있다고 설명한다.

---

# 112. 자주 헷갈리는 점 ⑪ — In-context Learning은 Fine-tuning인가?

아니다.

Fine-tuning:

```text
Parameter 변경
```

In-context Learning:

```text
Parameter 변경 없이
Prompt Context에서 Pattern 파악
```

이다.

---

# 113. 자주 헷갈리는 점 ⑫ — CoT는 Model Parameter를 새로 학습시키는 것인가?

강의에서 설명한 문맥에서는 아니다.

Prompt에 중간 풀이 과정의 Example을 제공하여 Model이 그 Pattern을 Context에서 활용하도록 하는 방식으로 설명한다.

---

# 114. 이번 강의에서 반드시 기억할 핵심

### 1. Pre-trained Language Model은 대규모 Text로 먼저 일반적인 Language Knowledge를 학습한다.

### 2. 이후 특정 Task Data로 추가 Training하는 것을 Fine-tuning이라고 한다.

### 3. Transformer 기반 Pre-trained Model은 Encoder-only, Encoder–Decoder, Decoder-only로 구분할 수 있다.

### 4. 대표적인 Encoder-only Model은 BERT다.

### 5. BERT의 핵심 Pre-training은 Masked Language Modeling이다.

### 6. BERT는 Masked Token을 예측할 때 왼쪽과 오른쪽 Context를 모두 활용한다.

### 7. 강의에서 설명한 BERT Masking은 전체 Token의 약 15%를 Target으로 선정한다.

### 8. 그중 80%는 [MASK], 10%는 Random Token, 10%는 원래 Token을 유지한다.

### 9. Text 자체에서 정답을 만들 수 있기 때문에 별도의 대규모 Human Labeling 없이 Pre-training할 수 있다.

### 10. BERT의 [CLS] Token은 Sequence-level Classification 등에 활용할 수 있다.

### 11. NSP는 두 Sentence가 실제로 연속되는지 판단하는 Binary Classification Task다.

### 12. BERT는 Sequence Classification뿐 아니라 NER 같은 Token Classification에도 사용할 수 있다.

### 13. BIO에서 B=Begin, I=Inside, O=Outside다.

### 14. BERT의 중요한 변화는 하나의 Pre-trained Architecture를 여러 Task에 Fine-tuning하여 재사용할 수 있게 한 것이다.

### 15. 대표적인 Encoder–Decoder Model은 T5다.

### 16. T5는 손상된 Input을 복원하는 Denoising 방식으로 Pre-training할 수 있다.

### 17. Span을 일부 손상시키면 Encoder가 Input 전체 Context를 이해하도록 유도할 수 있다.

### 18. T5는 다양한 NLP Task를 모두 Text→Text 문제로 통일한다.

### 19. Prefix를 사용해 현재 수행할 Task를 구별할 수 있다.

### 20. 대표적인 Decoder-only 계열이 GPT다.

### 21. Decoder-only라고 해서 Context Representation을 학습하지 않는 것은 아니다.

### 22. Masked Self-Attention으로 이전 Context를 이해하면서 다음 Token을 예측한다.

### 23. Decoder-only는 생성뿐 아니라 Classification 등에도 사용할 수 있다.

### 24. 강의에서는 같은 Resource를 한쪽 Stack의 Depth에 집중할 수 있다는 점을 Decoder-only의 한 직관으로 설명한다.

### 25. GPT 계열은 Model Scale이 커지면서 Generation 능력이 크게 향상됐다.

### 26. GPT-3 규모에서는 Prompt의 Instruction이나 Example을 이용한 In-context Learning이 중요한 능력으로 등장한다.

### 27. Fine-tuning은 Parameter를 Update하지만 In-context Learning은 Parameter를 Update하지 않는다.

### 28. Chain-of-Thought는 중간 풀이 과정을 Prompt Pattern으로 제공하여 보다 정교한 문제 해결을 유도하는 방식으로 강의에서 설명한다.

# 116. 이번 강의의 핵심 한 문장

> **사전학습 기반 언어 모델은 방대한 Text에서 자동으로 만들 수 있는 Language Modeling 문제를 이용해 먼저 일반적인 언어 Representation과 Pattern을 학습한 뒤 이를 다양한 Task에 재사용하는 방식이며, Transformer의 Encoder만 사용하는 BERT, Encoder–Decoder를 사용하는 T5, Decoder만 사용하는 GPT는 각각 서로 다른 사전학습 Objective와 정보 처리 구조를 통해 Text 이해·Text-to-Text 변환·Autoregressive Generation에 특화된 방향으로 발전했다.**

가장 짧게 정리하면 다음과 같다.

```text
BERT
= 가리고 맞힌다.
= 양방향으로 이해한다.

T5
= 망가뜨리고 복원한다.
= 모든 문제를 Text→Text로 푼다.

GPT
= 앞을 보고 다음 Token을 맞힌다.
= 크게 만들수록 강력한 생성과
  In-context Learning이 나타난다.
```
