# 16. Instruction Tuning

**Instruction Tuning**은

> **주어진 지시가 무엇을 요구하는지를 이해하고 적절한 Response를 생성하도록 학습하는 것**

이다.

예:

```text
Instruction:
이 리뷰가 긍정인지 부정인지 판단해 줘.

Input:
"정말 재미없는 영화였다."

Output:
부정
```

---

# 17. Preference Learning

Preference Learning은

> **여러 가능한 Response 중 어떤 Response를 사람이 더 선호하는지 학습하는 것**

이다.

예:

```text
Response A
Response B
Response C
Response D
```

가 모두 존재할 때

```text
D > C > A > B
```

처럼 사람의 Preference를 알려준다.

---

# 18. 두 방법의 역할 차이

### Instruction Tuning

질문:

> **“무엇을 해야 하는가?”**

를 배운다.

### Preference Learning

질문:

> **“여러 가능한 답 중 어떤 답이 더 좋은가?”**

를 배운다.

---

# 19. Instruction Tuning은 기본적으로 Supervised Fine-tuning이다

학습 방법 자체는 완전히 새로운 것은 아니다.

```text
Instruction
+
Input
↓
Expected Output
```

이라는 Pair를 이용한 **Supervised Fine-tuning(SFT)** 방식이다.

즉 Ground Truth Response를 주고 그 Response를 생성하도록 학습한다.

---

# 20. 기존 Fine-tuning과 Instruction Tuning의 결정적인 차이

과거 BERT 시대의 Fine-tuning:

```text
Task A
→ Task A 전용 Fine-tuned Model

Task B
→ Task B 전용 Fine-tuned Model

Task C
→ Task C 전용 Fine-tuned Model
```

이다.

---

# 21. 기존 방식의 문제

만약 10,000개의 Task를 수행하고 싶다면 극단적으로

```text
10,000개 Task Dataset

10,000번의 Fine-tuning

10,000개의 Task-specific Model
```

이 필요할 수 있다.

사용할 때도 Task에 따라 Model을 바꿔야 한다.

---

# 22. Instruction Tuning의 핵심 변화

Instruction Tuning은

> **많은 서로 다른 Task를 하나의 Model에 동시에 학습시킨다.**

즉

```text
Sentiment
Translation
Question Answering
Inference
Classification
...
        ↓
One Model
```

이다.

---

# 23. 그런데 Task마다 Input/Output Format이 다르다

예:

### Sentiment Classification

```text
Input = Sentence
Output = Class
```

### Translation

```text
Input = Text
Output = Text
```

### Question Answering

```text
Input = Context + Question
Output = Answer
```

각 Task의 Data Format이 다르다.

---

# 24. 해결 — 모든 Task를 Natural Language Instruction으로 통일

Instruction Tuning의 핵심 아이디어는

> **서로 다른 Task를 모두 자연어 기반 Instruction 형태로 표현한다.**

는 것이다.

---

# 25. Sentiment Task 예

기존 Data:

```text
Input:
This movie was terrible.

Label:
0
```

를

```text
Instruction:
다음 Review가 긍정인지 부정인지 판단하라.

Input:
This movie was terrible.

Output:
Negative
```

와 같은 Text Format으로 바꾼다.

---

# 26. Translation Task 예

```text
Instruction:
다음 Sentence를 영어로 번역하라.

Input:
오늘 날씨가 좋다.

Output:
The weather is nice today.
```

처럼 만든다.

---

# 27. 모든 NLP Task를 공통 Template으로

결국

```text
Instruction
+
Input
→
Text Output
```

이라는 동일한 Interface를 사용한다.

즉 Instruction 자체가

> **현재 Model이 어떤 Task를 해야 하는지 알려주는 Meta Information**

역할을 한다.

---

# 28. Instruction Tuning이 진짜 배우기를 원하는 것은?

단순히

```text
Task 1 외우기
Task 2 외우기
Task 3 외우기
...
```

가 아니다.

수천 종류의 Task를 동시에 보여주면 Model은 모든 Task를 개별적으로 암기하기 어렵다.

그래서 더 근본적으로

> **Instruction을 읽고 “지금 무엇을 해야 하는지” 파악하는 능력**

을 학습하도록 유도한다.

---

# 29. Meta-level Learning

강의에서는 이를 일종의 **Meta Knowledge**로 설명한다.

```text
"번역하라"
→ Translation을 해야 함

"분류하라"
→ Classification해야 함

"요약하라"
→ Summarization해야 함
```

처럼 Instruction과 행동의 관계 자체를 배운다.

---
# 57. RLHF 전체 단계

강의의 구조는 다음 네 단계로 기억하면 된다.

```text
Step 0
Pre-training

Step 1
Instruction Tuning / SFT

Step 2
Reward Model Training

Step 3
Reinforcement Learning
```

---

# 58. Step 0 — Pre-training

먼저 기본 LLM을 만든다.

예:

```text
Large Text Corpus
↓
Next-token Prediction
↓
GPT-3
```

이 단계에서

- Language
    
- Knowledge
    
- Pattern
    
- General Capability
    

를 학습한다.

하지만 아직 User Instruction과 Human Preference에는 충분히 정렬되어 있지 않다.

---

# 59. Step 1 — Supervised Instruction Tuning

Pre-trained GPT-3에 Instruction Data를 이용하여 Supervised Fine-tuning한다.

```text
Prompt / Instruction
+
High-quality Response
↓
SFT
↓
Instruction-following Model
```

---

# 60. InstructGPT Step 1의 Data

강의에서는 FLAN과 달리 OpenAI가 InstructGPT를 만들 때 **실제 User Query와 사람이 작성한 적절한 Response** 등을 Curate하여 Instruction Data로 활용했다고 설명한다.

목적은 같다.

> **여러 Instruction을 이해하고 적절하게 대답하도록 만든다.**

---

# 61. Step 1이 끝나면 무엇을 얻는가?

```text
Prompt
↓
SFT Model
↓
Reasonable Response
```

즉 User가 무언가 시켰을 때 어느 정도 원하는 형태로 응답할 수 있는 **Initial Policy Model**이 만들어진다.

---

# 62. 그런데 여전히 Preference 판단이 필요하다

Step 1 Model이 Prompt 하나에 대해

```text
A
B
C
D
```

와 같은 여러 Response를 만들었다고 하자.

어느 것이 가장 좋은지 Model 자체는 아직 충분히 판단하지 못할 수 있다.

따라서 Step 2에서 사람의 Preference를 수집한다.

---

# 63. Step 2 — Human Preference Data 수집

SFT Model에게 같은 Prompt에 대해 여러 Response를 생성하게 한다.

```text
Prompt
↓
SFT Model
↓
A
B
C
D
```

Human Labeler가 Ranking한다.

```text
D > C > A > B
```

---

# 64. 그런데 모든 RL Step마다 사람에게 물으면 너무 비싸다

매번

```text
Model Response 생성
↓
사람 평가
↓
Model Update
```

를 한다면 사람을 계속 대기시켜야 한다.

이것은 매우 느리고 비용도 크다.

그래서

> **사람의 Preference 자체를 모방하는 Model**

을 하나 더 만든다.

---

# 65. Reward Model

이것이 **Reward Model**이다.

Reward Model의 Input:

```text
Prompt
+
Response
```

Output:

```text
Scalar Reward Score
```

예:

```text
Response D → 100
Response C → 50
Response A → -5
Response B → -20
```

처럼 이해할 수 있다.

---

# 66. Reward Model의 목적

절대적인 Score 숫자가 중요한 것이 아니다.

중요한 것은

```text
Human Preference Ranking
```

과

```text
Reward Model Ranking
```

이 같아지게 하는 것이다.

사람이

```text
D > C > A > B
```

를 선호한다면 Reward Model도

```text
R(D) > R(C) > R(A) > R(B)
```

가 되도록 Training한다.

---

# 67. Reward Model은 결국 Human Preference Simulator

즉

> **“사람이라면 이 Response를 얼마나 좋아할까?”**

를 대신 판단하는 Model이다.

```text
Human Feedback
↓
Preference Dataset
↓
Reward Model
```

로 사람의 평가 기준을 근사한다.

---

# 68. Step 2가 끝난 시점

이제 두 Model이 있다.

### 1. Instruction-following Model

```text
Prompt
→ Response 생성
```

### 2. Reward Model

```text
Prompt + Response
→ 얼마나 좋은 Response인지 평가
```

---

# 69. Step 3 — Reinforcement Learning

이제 Human Labeler가 매 Iteration마다 직접 개입할 필요가 없다.

```text
Prompt
↓
Policy Model
↓
Response
↓
Reward Model
↓
Reward
↓
Policy Update
```

를 반복한다.

---

# 70. Reward가 높으면

```text
이 Response는 좋다.
↓
이런 Response를
앞으로 더 많이 만들도록
Model Parameter Update
```

한다.

---

# 71. Reward가 낮으면

```text
이 Response는 좋지 않다.
↓
이런 Response의
생성 Probability를 낮추도록
Update
```

한다.

---

# 72. 이것이 Reinforcement Learning

Supervised Learning에서는 직접

```text
정답 Output
```

을 알려준다.

Reinforcement Learning에서는

```text
이 행동은 좋다 / 나쁘다
```

에 해당하는 **Reward**를 제공한다.

Model은 Reward를 높이는 방향으로 행동 Policy를 학습한다.

---

# 73. RLHF라는 이름의 의미

```text
Human
↓
Preference Feedback
↓
Reward Model 학습
↓
Reward Model이
사람 대신 Feedback 제공
↓
Reinforcement Learning
```

이기 때문에

**Reinforcement Learning from Human Feedback**

이라고 부른다.

---

# 74. PPO

강의에서는 InstructGPT Step 3에서 구체적으로 **PPO(Proximal Policy Optimization)** 라는 Reinforcement Learning Algorithm을 사용한다고 설명한다.

다만 강의자는 현재 단계에서는

> PPO의 세부 Algorithm보다 **Reward Model을 이용해 Policy Model을 좋은 Response 방향으로 Update한다는 구조**

가 더 중요하다고 강조한다.

---

# 75. RLHF에서 사람은 어디에 개입하는가?

중요한 시험 포인트다.

강의 흐름:

### Step 1

사람이 좋은 Demonstration / Instruction Response Data를 제공.

### Step 2

사람이 Model Response들의 Preference를 Ranking.

### Step 3

매 Training Sample마다 사람이 직접 Reward를 주지는 않는다.

```text
Reward Model
```

이 대신 평가한다.

---

# 76. 그렇다고 Step 3에서 사람이 완전히 사라지는 것은 아니다

강의에서는 Reinforcement Learning이 잘못된 방향으로 발산할 수도 있다고 설명한다.

따라서 실제 Training 중에는

```text
Checkpoint
Evaluation
Monitoring
```

등을 통해 사람이 중간중간 Training 상태를 점검할 수 있다.

즉

> **모든 Training Step에 사람이 직접 Labeling하지 않는다는 의미이지 전체 관리 과정에서 사람이 전혀 개입하지 않는다는 뜻은 아니다.**

---

# 77. 왜 Reward를 어떻게 정의하느냐가 중요한가?

Reinforcement Learning의 방향은 Reward에 의해 결정된다.

```text
Reward Function이 선호하는 것
      ↓
Model도 점점 그것을 잘함
```

---

# 78. Safety Preference를 Reward로 사용하면

사람이

```text
Safe Response
>
Unsafe Response
```

를 지속적으로 선호하도록 Preference Data를 만들면 Reward Model도 Safety를 중요하게 평가한다.

그 Reward로 Policy를 학습하면

```text
Safer Model
```

을 만들 수 있다.

---

# 79. Reasoning Reward를 사용하면

예를 들어 수학 Problem이 있다고 하자.

```text
Correct
→ 100

Wrong
→ 0
```

처럼 Reward를 만들면 Model은 더 높은 Reward를 받기 위해 Problem-solving 능력을 발전시키는 방향으로 Training될 수 있다.

강의에서는 최근 Reasoning Post-training과 연결해서 이 예를 든다.

---

# 80. 결국 RL의 핵심은 Reward Design

같은 Reinforcement Learning Algorithm을 사용하더라도

```text
무엇을 Reward하는가?
```

에 따라 최종 Model 특성이 달라진다.

```text
Safety Reward
→ Safer Model

Reasoning Reward
→ Better Problem Solver

Human Preference Reward
→ More Helpful / Preferred Responses
```

이다.

---

# 81. Instruction Learning과 Preference Learning 비교

|구분|Instruction Tuning|Preference Learning|
|---|---|---|
|핵심 질문|무엇을 해야 하는가?|어느 Response가 더 좋은가?|
|Data|Instruction + Target Response|여러 Response + Human Ranking|
|기본 학습|Supervised Fine-tuning|Preference/Reward 기반|
|정답 형태|비교적 명시적인 Target|상대적 선호|
|장점|지시 수행 능력 향상|Open-ended Response 품질 조정|
|대표 역할|Instruction Following|Human Alignment|

---

# 82. SFT와 RLHF 비교

### Supervised Fine-tuning

```text
이 질문에는
이렇게 답해.
```

를 직접 알려준다.

### Reinforcement Learning

```text
네가 답을 만들어 봐.
↓
이 답은 좋았어 / 나빴어.
↓
더 좋은 답을 만들어.
```

라는 구조다.

---

# 83. 왜 Open-ended Generation에서는 Preference가 특히 유용한가?

Natural Language에서는 같은 질문에

```text
Correct Response A
Correct Response B
Correct Response C
```

가 모두 가능하다.

한 개의 정답만 Supervised Target으로 지정하면 나머지 유효한 Response를 활용하기 어렵다.

Preference 방식에서는

```text
모두 가능하지만
A가 B보다 더 좋다.
```

라는 더 섬세한 Signal을 제공할 수 있다.
