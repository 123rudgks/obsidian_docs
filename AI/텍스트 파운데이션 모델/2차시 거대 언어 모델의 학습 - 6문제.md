# 0. 강의 전체 개요

앞 차시에서는 Text Foundation Model이 가능해진 핵심 요소를

```text
Big Data
+
Self-supervised Learning
+
Transformer
```

로 정리했다.

그리고 Text Foundation Model의 대표적인 Pre-training Objective가

```text
Next-token Prediction
```

이라는 것도 배웠다.

이번 차시에서는 그다음 질문을 다룬다.

> **“그렇다면 엄청나게 큰 Transformer를 엄청난 Text로 Next-token Prediction만 시키면 ChatGPT 같은 Model이 바로 만들어지는가?”**

강의의 답은

```text
아니다.
```

이다.

전체 흐름은 다음과 같다.

```text
대규모 Pre-training
      ↓
GPT-3
      ↓
Next-token Prediction 능력은 매우 강함
      ↓
하지만 문제가 있음
 ├─ User Instruction을 제대로 안 따름
 └─ Harmful / Unsafe Response 가능
      ↓
Pre-training만으로 부족
      ↓
Post-training
      ↓
Alignment Training
      ↓
────────────────────
Instruction Tuning
+
Preference Learning
────────────────────
      ↓
Instruction Following 향상
+
Human Preference 반영
      ↓
RLHF
Reinforcement Learning
from Human Feedback
      ↓
Step 0. Pre-training
Step 1. Supervised Instruction Tuning
Step 2. Reward Model
Step 3. Reinforcement Learning
      ↓
사람이 더 선호하고
안전하며 유용한 응답 생성
```

---

# 1. GPT-3 — 본격적인 LLM의 출발점

강의에서는 일반적으로 **GPT-3를 거대 언어 모델의 본격적인 시작점**으로 설명한다.

가장 큰 GPT-3 Model은

```text
175 Billion Parameters
= 약 1,750억 Parameters
```

를 가지고 있었다.

당시 이전 Model들과 비교해 매우 큰 규모였고, Model Scale이 증가하면서 **In-context Learning** 능력이 본격적으로 관찰되기 시작했다.

---

# 2. 그런데 GPT-3의 학습 방법 자체가 완전히 새로웠던 것은 아니다

놀라운 Capability가 나타났지만 Training Objective 자체는 단순했다.

```text
Context
↓
Next-token Prediction
```

이다.

즉

> **GPT-3의 중요한 변화는 새로운 특별한 학습 문제라기보다 Model과 Data의 Scale 증가였다.**

---

# 3. GPT-3의 Training Data도 매우 컸다

강의에서는 GPT-3가 당시 매우 큰 규모의 Token과 Text Data를 사용했다고 설명한다.

핵심은 정확한 숫자 자체보다

```text
Model Scale ↑↑
+
Training Data Scale ↑↑
```

가 동시에 일어났다는 것이다.

또 GPT-3는 한 번에 175B Model만 바로 만든 것이 아니라 여러 규모의 Model을 차례대로 만들어가며 Scale-up 가능성을 확인했다.

```text
Small
↓
Medium
↓
Larger
↓
...
↓
175B
```

---

# 4. Data는 양만 많으면 되는가?

아니다.

Internet Data는 양을 확보하기에는 매우 좋다.

하지만

```text
Noise
Low-quality Text
Duplicated Content
Unreliable Information
```

등 Quality 문제가 존재할 수 있다.

따라서 강의에서는 GPT-3 Training에서

- Common Crawl 같은 대규모 Web Data
    
- Book Data
    
- Wikipedia
    

등 여러 Source를 함께 사용했다고 설명한다.

---

# 5. High-quality Data는 상대적으로 더 적극적으로 활용

Raw Web Data는 Data Volume은 매우 크지만 Quality는 상대적으로 낮을 수 있다.

반대로

```text
Books
Wikipedia
```

와 같이 사람이 어느 정도 정제한 Data는 양은 적지만 Quality가 높을 수 있다.

강의에서는 이런 Data Quality 차이를 고려하여

```text
Low-quality Data
→ 상대적으로 적은 반복

High-quality Data
→ Data 양 대비 더 많이 학습
```

하도록 구성했다고 설명한다.

---

# 6. 중요한 질문 — Next-token Prediction만 잘하면 ChatGPT가 되는가?

GPT-3는 매우 강한 Language Model이었다.

그렇다면

```text
더 많은 Data
+
더 큰 Transformer
+
Next-token Prediction
```

만 계속하면 자연스럽게 ChatGPT, Claude, Gemini 같은 Model이 만들어질까?

강의에서는

> **Pre-training만으로는 부족하다.**

고 설명한다.

---

# 7. Pre-trained GPT-3의 문제 ① Instruction Following

GPT-3는 Language Pattern은 잘 학습했지만

> **User가 무엇을 원하는지 정확하게 이해하고 지시대로 행동하는 능력**

은 부족할 수 있었다.

예를 들어 User가

```text
"6살 아이에게 달 착륙을
몇 문장으로 설명해 줘."
```

라고 요청하더라도 Model이

- 질문을 되풀이하거나
    
- 관계없는 내용을 생성하거나
    
- 원하는 형식과 다르게 응답
    

하는 등의 Failure가 발생할 수 있었다.

---

# 8. 왜 이런 문제가 생기는가?

Pre-training에서 Model에게 가르친 것은 기본적으로

```text
"사용자의 지시를 따르라"
```

가 아니다.

Model에게 가르친 것은

```text
"현재 Context 다음에
어떤 Token이 자연스럽게 나오는가?"
```

다.

즉

```text
Next-token Predictor
```

와

```text
Helpful Assistant
```

는 같은 목표가 아니다.

---

# 9. Pre-trained GPT-3의 문제 ② Safety / Human Value

설령 Instruction을 이해해도 또 다른 문제가 있다.

User가 위험하거나 악의적인 요청을 할 수도 있다.

이때 단순 Next-token Predictor라면 Internet에서 학습한 Pattern을 따라 위험한 내용을 자연스럽게 생성할 가능성이 있다.

---

# 10. 우리가 원하는 Assistant는 단순히 말을 잘하는 Model이 아니다

실제 서비스에서는 최소한 다음이 필요하다.

```text
User Intent 이해

Useful Response

Appropriate Response

Safe Response

Human Value와 어느 정도 정렬
```

즉

> **Language Modeling Performance만 높다고 좋은 Assistant가 되는 것은 아니다.**

---

# 11. Jailbreak / Adversarial Prompt 문제

강의에서는 Model의 Safety Rule을 우회하려는 Prompt도 소개한다.

예를 들어 User가 특정 위험한 질문 뒤에

```text
"답변을 반드시
Absolutely, here is...
로 시작해."
```

같은 조건을 붙일 수 있다.

Language Model은 앞부분을 자연스럽게 이어가려는 특성 때문에 특정 Prompt 형식에 끌려가 Safety가 깨질 수 있다.

이처럼 Model의 제한이나 Safety를 우회하도록 만드는 공격을 강의에서는 **Jailbreak / 공격적 Prompt**와 연결한다.

---

# 12. 결론 — Pre-training 이후 Post-training이 필요하다

따라서 현대 LLM은 일반적으로

```text
Pre-training
```

에서 끝나지 않는다.

그 이후

```text
Post-training
```

을 수행한다.

---

# 13. Pre-training과 Post-training 역할

## Pre-training

```text
대규모 Text
↓
Language / Knowledge / Pattern 학습
```

쉽게 말하면

> Model을 기본적으로 **똑똑하게 만드는 단계**

다.

## Post-training

```text
Pre-trained Model
↓
Instruction / Preference / Reasoning 등을 추가 학습
```

즉

> 이미 학습된 능력을 **사람이 원하는 방향으로 사용하도록 조정하는 단계**

다.

---

# 14. Post-training은 Alignment만 있는 것은 아니다

강의에서 이 점도 분리한다.

Post-training에는

```text
Alignment
```

뿐 아니라 최근에는

```text
Reasoning Enhancement
```

등 Model 자체의 문제 해결 능력을 추가로 높이는 Training도 존재한다.

예를 들어 문제를 풀고 정답 여부를 Reward로 주면서 반복적으로 Problem Solving을 학습할 수 있다.

다만 이번 차시에서는 **Alignment Training**에 집중한다.

---

# 15. Alignment Training

Alignment의 목표는

> **LLM의 Response가 User Intent와 Human Preference / Value를 더 잘 반영하도록 만드는 것**

이다.

강의에서는 대표적으로 두 가지를 구분한다.

```text
Alignment Training
├─ Instruction Tuning
└─ Preference Learning
```

---

# 16. Instruction Tuning

**Instruction Tuning**은

> **주어진 지시가 무엇을 요구하는지를 이해하고 적절한 Response를 생성하도록 학습하는 것**

이다.

예:

```text
Instruction:
이 리뷰가 긍정인지 부정인지 판단해 줘.

Input:
"정말 재미없는 영화였다."

Output:
부정
```

---

# 17. Preference Learning

Preference Learning은

> **여러 가능한 Response 중 어떤 Response를 사람이 더 선호하는지 학습하는 것**

이다.

예:

```text
Response A
Response B
Response C
Response D
```

가 모두 존재할 때

```text
D > C > A > B
```

처럼 사람의 Preference를 알려준다.

---

# 18. 두 방법의 역할 차이

### Instruction Tuning

질문:

> **“무엇을 해야 하는가?”**

를 배운다.

### Preference Learning

질문:

> **“여러 가능한 답 중 어떤 답이 더 좋은가?”**

를 배운다.

---

# 19. Instruction Tuning은 기본적으로 Supervised Fine-tuning이다

학습 방법 자체는 완전히 새로운 것은 아니다.

```text
Instruction
+
Input
↓
Expected Output
```

이라는 Pair를 이용한 **Supervised Fine-tuning(SFT)** 방식이다.

즉 Ground Truth Response를 주고 그 Response를 생성하도록 학습한다.

---

# 20. 기존 Fine-tuning과 Instruction Tuning의 결정적인 차이

과거 BERT 시대의 Fine-tuning:

```text
Task A
→ Task A 전용 Fine-tuned Model

Task B
→ Task B 전용 Fine-tuned Model

Task C
→ Task C 전용 Fine-tuned Model
```

이다.

---

# 21. 기존 방식의 문제

만약 10,000개의 Task를 수행하고 싶다면 극단적으로

```text
10,000개 Task Dataset

10,000번의 Fine-tuning

10,000개의 Task-specific Model
```

이 필요할 수 있다.

사용할 때도 Task에 따라 Model을 바꿔야 한다.

---

# 22. Instruction Tuning의 핵심 변화

Instruction Tuning은

> **많은 서로 다른 Task를 하나의 Model에 동시에 학습시킨다.**

즉

```text
Sentiment
Translation
Question Answering
Inference
Classification
...
        ↓
One Model
```

이다.

---

# 23. 그런데 Task마다 Input/Output Format이 다르다

예:

### Sentiment Classification

```text
Input = Sentence
Output = Class
```

### Translation

```text
Input = Text
Output = Text
```

### Question Answering

```text
Input = Context + Question
Output = Answer
```

각 Task의 Data Format이 다르다.

---

# 24. 해결 — 모든 Task를 Natural Language Instruction으로 통일

Instruction Tuning의 핵심 아이디어는

> **서로 다른 Task를 모두 자연어 기반 Instruction 형태로 표현한다.**

는 것이다.

---

# 25. Sentiment Task 예

기존 Data:

```text
Input:
This movie was terrible.

Label:
0
```

를

```text
Instruction:
다음 Review가 긍정인지 부정인지 판단하라.

Input:
This movie was terrible.

Output:
Negative
```

와 같은 Text Format으로 바꾼다.

---

# 26. Translation Task 예

```text
Instruction:
다음 Sentence를 영어로 번역하라.

Input:
오늘 날씨가 좋다.

Output:
The weather is nice today.
```

처럼 만든다.

---

# 27. 모든 NLP Task를 공통 Template으로

결국

```text
Instruction
+
Input
→
Text Output
```

이라는 동일한 Interface를 사용한다.

즉 Instruction 자체가

> **현재 Model이 어떤 Task를 해야 하는지 알려주는 Meta Information**

역할을 한다.

---

# 28. Instruction Tuning이 진짜 배우기를 원하는 것은?

단순히

```text
Task 1 외우기
Task 2 외우기
Task 3 외우기
...
```

가 아니다.

수천 종류의 Task를 동시에 보여주면 Model은 모든 Task를 개별적으로 암기하기 어렵다.

그래서 더 근본적으로

> **Instruction을 읽고 “지금 무엇을 해야 하는지” 파악하는 능력**

을 학습하도록 유도한다.

---

# 29. Meta-level Learning

강의에서는 이를 일종의 **Meta Knowledge**로 설명한다.

```text
"번역하라"
→ Translation을 해야 함

"분류하라"
→ Classification해야 함

"요약하라"
→ Summarization해야 함
```

처럼 Instruction과 행동의 관계 자체를 배운다.

---

# 30. 처음 보는 Task도 수행할 가능성이 생긴다

만약 Training 중에 아주 많은 종류의 Instruction을 경험했다면, Training에서 직접 보지 못한 새로운 Task라도

```text
새로운 Instruction
↓
Instruction 의미 해석
↓
Pre-training에서 가진 Knowledge 활용
↓
새로운 Task 수행
```

을 기대할 수 있다.

---

# 31. 강의의 비유

기존 Task-specific Fine-tuning이

> **물고기를 직접 잡아주는 방식**

이라면

Instruction Tuning은

> **물고기를 잡는 방법 자체를 가르치는 방식**

으로 설명한다.

---

# 32. FLAN

강의에서는 대표적인 Instruction Tuning 연구로 Google의 **FLAN** 계열을 소개한다.

핵심은

```text
다양한 NLP Dataset
      ↓
Natural Language Instruction Format으로 변환
      ↓
하나의 LLM에 Multi-task Instruction Tuning
```

이다.

---

# 33. 하나의 Task에도 Instruction은 여러 방식으로 쓸 수 있다

예를 들어 Sentence Pair 관계를 판단하는 동일한 Task라도

```text
"두 문장이 같은 의미인가?"

"Premise를 바탕으로 Hypothesis를
결론 내릴 수 있는가?"

"두 문장의 관계를 선택하라."
```

처럼 다양한 방식으로 표현할 수 있다.

---

# 34. Instruction에는 정답 Template이 하나뿐인 것이 아니다

즉

```text
Task
→ Instruction Template 1
→ Instruction Template 2
→ Instruction Template 3
...
```

처럼 여러 표현이 가능하다.

강의에서는 이 다양성이 오히려 중요하다고 설명한다.

---

# 35. 왜 Instruction Diversity가 좋은가?

실제 User도 모두 같은 표현으로 질문하지 않는다.

같은 요청도

```text
한국어
영어

짧은 문장
긴 문장

격식 있는 표현
구어체 표현
```

등 다양하게 주어진다.

따라서 Training에서도 다양한 Instruction Template을 보여주면 Model이 특정 표현 하나에 Overfitting하지 않고 더 강하게 Generalize할 수 있다.

---

# 36. Task Diversity도 중요하다

단순히 한 Task의 Example을 많이 보여주는 것보다

```text
다양한 종류의 Task
```

를 경험시키는 것이 중요하다.

왜냐하면 Instruction-following이라는 Meta Skill을 학습하려면 여러 Instruction과 Task의 관계를 봐야 하기 때문이다.

---

# 37. Instruction Tuning 평가에서 중요한 문제 — Data Leakage

Instruction-following Ability를 평가하고 싶은데 Test Task와 거의 같은 Task를 Training에서 이미 보여줬다면 문제가 된다.

예를 들어

```text
Training:
IMDB Sentiment

Test:
SST-2 Sentiment
```

라고 하자.

Dataset은 다르지만 둘 다 실제로는

```text
Sentiment Classification
```

이다.

---

# 38. Dataset-level Split만으로는 충분하지 않다

SST-2 Dataset 자체를 Training에서 제외했다고 하더라도 IMDB를 Training했다면 Model이 이미

```text
"Sentiment Classification을 어떻게 푸는지"
```

를 학습했을 수 있다.

그러면 Test 성능이

```text
새 Instruction을 이해했기 때문인지

이미 같은 종류의 Task를 외웠기 때문인지
```

구분하기 어렵다.

---

# 39. 해결 — Task-level Train/Test Split

FLAN 연구에서는 Dataset만 나누는 것이 아니라 더 큰 **Task Category 수준**에서도 Train/Test를 분리한다.

예를 들어 Test에서 Translation Ability를 평가한다면 Training에서는 Translation 계열 Task 자체를 제외하는 방식이다.

---

# 40. 왜 Task-level Split을 하는가?

목표는

> **Training 때 본 적 없는 종류의 Task도 Instruction을 보고 수행할 수 있는가?**

를 평가하는 것이다.

즉 진짜 Instruction Generalization을 보려는 것이다.

---

# 41. Instruction Tuning은 실제로 효과가 있었는가?

강의에서는 FLAN 계열 Experiment에서 Instruction Tuning을 한 Model이 하지 않은 Model보다 다양한 Task에서 상당한 성능 향상을 보였다고 설명한다.

특히

```text
Example 없이
Instruction만 주는 Zero-shot Setup
```

에서도 큰 개선이 나타났다.

---

# 42. Instruction Tuning에서 중요하게 관찰된 요소 ① Task 수

```text
Training에 포함된 Task 종류 ↑
→ Generalization Performance ↑
```

라는 경향이 관찰됐다.

즉 다양한 Instruction을 많이 경험하는 것이 중요하다.

---

# 43. 중요 요소 ② Model Scale

Instruction Tuning 효과가 모든 크기의 Model에서 동일하게 나타나는 것은 아니었다.

강의에서는 작은 Model에서는 Instruction Tuning 후 오히려 성능이 떨어지는 사례도 있었고,

어느 정도 큰 Billion-scale Model에 도달했을 때 Instruction Tuning의 효과가 크게 나타났다고 설명한다.

---

# 44. Instruction Following도 Scale과 관련된 Capability

강의에서는 이를

> **Instruction을 이해해서 처음 보는 Task까지 수행하는 능력 역시 Scale이 충분히 커졌을 때 강하게 나타나는 창발적 Capability로 볼 수 있다.**

고 연결한다.

---

# 45. 중요 요소 ③ 자연어 Instruction

Dataset Name이나 Artificial ID를 알려주는 것보다

```text
"다음 문장의 감정을 판단하라."
```

와 같이 **사람이 실제로 사용하는 자연어 Instruction**을 제공하는 것이 더 효과적이었다고 설명한다.

즉 사람에게 말하듯 Model에게 Task를 설명하는 것이 유리했다.

---

# 46. Instruction Tuning만 하면 모든 문제가 해결되는가?

아니다.

Instruction을 잘 따르는 Model이 만들어졌다고 하자.

User가

```text
"위험한 행동 방법을 알려줘."
```

라고 요청하면 Instruction-following Model은 오히려 그 Instruction을 너무 잘 따를 수도 있다.

즉

```text
Instruction Following
≠
Human-aligned Response
```

다.

---

# 47. 그래서 Preference Learning이 필요하다

이제 Model에게

> **“어떤 Response가 더 좋은가?”**

를 알려줘야 한다.

Instruction Tuning은 정답 Example을 직접 제공한다.

Preference Learning에서는 두 개 이상의 Response를 비교한다.

---

# 48. Preference Learning이 특히 필요한 이유 — Open-ended Task

수학 문제처럼 정답이 하나라면

```text
Input
→ Correct Answer
```

를 주기 쉽다.

하지만 자연어 Generation에는 정답이 여러 개일 수 있다.

예:

```text
Translation A
Translation B
```

둘 다 문법적으로 맞고 의미도 맞을 수 있다.

그러나 사람은 A를 더 자연스럽다고 느낄 수도 있다.

---

# 49. 이때 필요한 정보

우리가 알려주고 싶은 것은

```text
A = 맞음
B = 틀림
```

이 아니다.

오히려

```text
A도 가능
B도 가능

하지만
A를 더 선호
```

다.

이것이 Preference Data다.

---

# 50. Preference Learning Dataset 만들기

먼저 LLM이 하나의 Prompt에 대해 여러 Response를 생성한다.

```text
Prompt
 ↓
Model
 ↓
Response A
Response B
Response C
Response D
```

---

# 51. 그다음 Human Labeler가 평가

사람이 Response들을 보고 Ranking한다.

예:

```text
D > C > A > B
```

이렇게

- Helpfulness
    
- Quality
    
- Safety
    
- Relevance
    

등을 암묵적으로 종합해 Preference를 제공한다.

---

# 52. 중요한 구조

Response Candidate는 **Model이 생성**한다.

사람은 모든 Response를 직접 처음부터 작성하는 것이 아니라

> **Model이 만든 Response 중 어떤 것이 더 좋은지를 판단한다.**

이 구조가 이후 RLHF의 핵심으로 연결된다.

---

# 53. Preference Learning의 목적

Model이 반복적으로

```text
Human이 좋아하는 Response
```

를 더 높은 확률로 만들도록 학습한다.

그 결과

```text
Helpfulness ↑
Safety ↑
Response Quality ↑
Human Preference Alignment ↑
```

를 기대할 수 있다.

---

# 54. ChatGPT와 RLHF

강의에서는 ChatGPT를 이해하기 위한 핵심 기술로 **RLHF**를 소개한다.

RLHF:

**Reinforcement Learning from Human Feedback**

즉

```text
Human Feedback
+
Reinforcement Learning
```

이다.

---

# 55. 강의에서 설명하는 ChatGPT와 InstructGPT 관계

강의에서는 공개된 설명을 바탕으로

```text
InstructGPT 방식
+
새로운 Dialogue Data
↓
ChatGPT
```

라는 흐름으로 이해할 수 있다고 설명한다.

즉 ChatGPT를 만드는 데 사용된 기본적인 Alignment Framework는 InstructGPT에서 사용된 RLHF 방식과 연결된다.

---

# 56. Instruction Tuning과 Preference Learning은 둘 다 Post-training

정리하면

```text
Pre-training
↓
Post-training
   ├─ Instruction Tuning
   └─ Preference Learning / RLHF
```

이다.

Pre-training이 끝난 뒤 진행한다.

---

# 57. RLHF 전체 단계

강의의 구조는 다음 네 단계로 기억하면 된다.

```text
Step 0
Pre-training

Step 1
Instruction Tuning / SFT

Step 2
Reward Model Training

Step 3
Reinforcement Learning
```

---

# 58. Step 0 — Pre-training

먼저 기본 LLM을 만든다.

예:

```text
Large Text Corpus
↓
Next-token Prediction
↓
GPT-3
```

이 단계에서

- Language
    
- Knowledge
    
- Pattern
    
- General Capability
    

를 학습한다.

하지만 아직 User Instruction과 Human Preference에는 충분히 정렬되어 있지 않다.

---

# 59. Step 1 — Supervised Instruction Tuning

Pre-trained GPT-3에 Instruction Data를 이용하여 Supervised Fine-tuning한다.

```text
Prompt / Instruction
+
High-quality Response
↓
SFT
↓
Instruction-following Model
```

---

# 60. InstructGPT Step 1의 Data

강의에서는 FLAN과 달리 OpenAI가 InstructGPT를 만들 때 **실제 User Query와 사람이 작성한 적절한 Response** 등을 Curate하여 Instruction Data로 활용했다고 설명한다.

목적은 같다.

> **여러 Instruction을 이해하고 적절하게 대답하도록 만든다.**

---

# 61. Step 1이 끝나면 무엇을 얻는가?

```text
Prompt
↓
SFT Model
↓
Reasonable Response
```

즉 User가 무언가 시켰을 때 어느 정도 원하는 형태로 응답할 수 있는 **Initial Policy Model**이 만들어진다.

---

# 62. 그런데 여전히 Preference 판단이 필요하다

Step 1 Model이 Prompt 하나에 대해

```text
A
B
C
D
```

와 같은 여러 Response를 만들었다고 하자.

어느 것이 가장 좋은지 Model 자체는 아직 충분히 판단하지 못할 수 있다.

따라서 Step 2에서 사람의 Preference를 수집한다.

---

# 63. Step 2 — Human Preference Data 수집

SFT Model에게 같은 Prompt에 대해 여러 Response를 생성하게 한다.

```text
Prompt
↓
SFT Model
↓
A
B
C
D
```

Human Labeler가 Ranking한다.

```text
D > C > A > B
```

---

# 64. 그런데 모든 RL Step마다 사람에게 물으면 너무 비싸다

매번

```text
Model Response 생성
↓
사람 평가
↓
Model Update
```

를 한다면 사람을 계속 대기시켜야 한다.

이것은 매우 느리고 비용도 크다.

그래서

> **사람의 Preference 자체를 모방하는 Model**

을 하나 더 만든다.

---

# 65. Reward Model

이것이 **Reward Model**이다.

Reward Model의 Input:

```text
Prompt
+
Response
```

Output:

```text
Scalar Reward Score
```

예:

```text
Response D → 100
Response C → 50
Response A → -5
Response B → -20
```

처럼 이해할 수 있다.

---

# 66. Reward Model의 목적

절대적인 Score 숫자가 중요한 것이 아니다.

중요한 것은

```text
Human Preference Ranking
```

과

```text
Reward Model Ranking
```

이 같아지게 하는 것이다.

사람이

```text
D > C > A > B
```

를 선호한다면 Reward Model도

```text
R(D) > R(C) > R(A) > R(B)
```

가 되도록 Training한다.

---

# 67. Reward Model은 결국 Human Preference Simulator

즉

> **“사람이라면 이 Response를 얼마나 좋아할까?”**

를 대신 판단하는 Model이다.

```text
Human Feedback
↓
Preference Dataset
↓
Reward Model
```

로 사람의 평가 기준을 근사한다.

---

# 68. Step 2가 끝난 시점

이제 두 Model이 있다.

### 1. Instruction-following Model

```text
Prompt
→ Response 생성
```

### 2. Reward Model

```text
Prompt + Response
→ 얼마나 좋은 Response인지 평가
```

---

# 69. Step 3 — Reinforcement Learning

이제 Human Labeler가 매 Iteration마다 직접 개입할 필요가 없다.

```text
Prompt
↓
Policy Model
↓
Response
↓
Reward Model
↓
Reward
↓
Policy Update
```

를 반복한다.

---

# 70. Reward가 높으면

```text
이 Response는 좋다.
↓
이런 Response를
앞으로 더 많이 만들도록
Model Parameter Update
```

한다.

---

# 71. Reward가 낮으면

```text
이 Response는 좋지 않다.
↓
이런 Response의
생성 Probability를 낮추도록
Update
```

한다.

---

# 72. 이것이 Reinforcement Learning

Supervised Learning에서는 직접

```text
정답 Output
```

을 알려준다.

Reinforcement Learning에서는

```text
이 행동은 좋다 / 나쁘다
```

에 해당하는 **Reward**를 제공한다.

Model은 Reward를 높이는 방향으로 행동 Policy를 학습한다.

---

# 73. RLHF라는 이름의 의미

```text
Human
↓
Preference Feedback
↓
Reward Model 학습
↓
Reward Model이
사람 대신 Feedback 제공
↓
Reinforcement Learning
```

이기 때문에

**Reinforcement Learning from Human Feedback**

이라고 부른다.

---

# 74. PPO

강의에서는 InstructGPT Step 3에서 구체적으로 **PPO(Proximal Policy Optimization)** 라는 Reinforcement Learning Algorithm을 사용한다고 설명한다.

다만 강의자는 현재 단계에서는

> PPO의 세부 Algorithm보다 **Reward Model을 이용해 Policy Model을 좋은 Response 방향으로 Update한다는 구조**

가 더 중요하다고 강조한다.

---

# 75. RLHF에서 사람은 어디에 개입하는가?

중요한 시험 포인트다.

강의 흐름:

### Step 1

사람이 좋은 Demonstration / Instruction Response Data를 제공.

### Step 2

사람이 Model Response들의 Preference를 Ranking.

### Step 3

매 Training Sample마다 사람이 직접 Reward를 주지는 않는다.

```text
Reward Model
```

이 대신 평가한다.

---

# 76. 그렇다고 Step 3에서 사람이 완전히 사라지는 것은 아니다

강의에서는 Reinforcement Learning이 잘못된 방향으로 발산할 수도 있다고 설명한다.

따라서 실제 Training 중에는

```text
Checkpoint
Evaluation
Monitoring
```

등을 통해 사람이 중간중간 Training 상태를 점검할 수 있다.

즉

> **모든 Training Step에 사람이 직접 Labeling하지 않는다는 의미이지 전체 관리 과정에서 사람이 전혀 개입하지 않는다는 뜻은 아니다.**

---

# 77. 왜 Reward를 어떻게 정의하느냐가 중요한가?

Reinforcement Learning의 방향은 Reward에 의해 결정된다.

```text
Reward Function이 선호하는 것
      ↓
Model도 점점 그것을 잘함
```

---

# 78. Safety Preference를 Reward로 사용하면

사람이

```text
Safe Response
>
Unsafe Response
```

를 지속적으로 선호하도록 Preference Data를 만들면 Reward Model도 Safety를 중요하게 평가한다.

그 Reward로 Policy를 학습하면

```text
Safer Model
```

을 만들 수 있다.

---

# 79. Reasoning Reward를 사용하면

예를 들어 수학 Problem이 있다고 하자.

```text
Correct
→ 100

Wrong
→ 0
```

처럼 Reward를 만들면 Model은 더 높은 Reward를 받기 위해 Problem-solving 능력을 발전시키는 방향으로 Training될 수 있다.

강의에서는 최근 Reasoning Post-training과 연결해서 이 예를 든다.

---

# 80. 결국 RL의 핵심은 Reward Design

같은 Reinforcement Learning Algorithm을 사용하더라도

```text
무엇을 Reward하는가?
```

에 따라 최종 Model 특성이 달라진다.

```text
Safety Reward
→ Safer Model

Reasoning Reward
→ Better Problem Solver

Human Preference Reward
→ More Helpful / Preferred Responses
```

이다.

---

# 81. Instruction Learning과 Preference Learning 비교

|구분|Instruction Tuning|Preference Learning|
|---|---|---|
|핵심 질문|무엇을 해야 하는가?|어느 Response가 더 좋은가?|
|Data|Instruction + Target Response|여러 Response + Human Ranking|
|기본 학습|Supervised Fine-tuning|Preference/Reward 기반|
|정답 형태|비교적 명시적인 Target|상대적 선호|
|장점|지시 수행 능력 향상|Open-ended Response 품질 조정|
|대표 역할|Instruction Following|Human Alignment|

---

# 82. SFT와 RLHF 비교

### Supervised Fine-tuning

```text
이 질문에는
이렇게 답해.
```

를 직접 알려준다.

### Reinforcement Learning

```text
네가 답을 만들어 봐.
↓
이 답은 좋았어 / 나빴어.
↓
더 좋은 답을 만들어.
```

라는 구조다.

---

# 83. 왜 Open-ended Generation에서는 Preference가 특히 유용한가?

Natural Language에서는 같은 질문에

```text
Correct Response A
Correct Response B
Correct Response C
```

가 모두 가능하다.

한 개의 정답만 Supervised Target으로 지정하면 나머지 유효한 Response를 활용하기 어렵다.

Preference 방식에서는

```text
모두 가능하지만
A가 B보다 더 좋다.
```

라는 더 섬세한 Signal을 제공할 수 있다.

---

# 84. InstructGPT의 전체 Pipeline

```text
[Step 0]

Large Corpus
      ↓
Next-token Prediction
      ↓
Pre-trained GPT-3


[Step 1]

Prompt
+
Human-written Demonstration
      ↓
Supervised Fine-tuning
      ↓
Instruction-following Model


[Step 2]

Prompt
      ↓
Model이 여러 Response 생성
      ↓
Human Ranking
      ↓
Preference Dataset
      ↓
Reward Model Training


[Step 3]

Prompt
      ↓
Policy Model
      ↓
Response
      ↓
Reward Model
      ↓
Reward
      ↓
Reinforcement Learning / PPO
      ↓
Human Preference에 더 맞는 Model
```

---

# 85. RLHF를 한 문장으로

> **사람이 모든 Response를 일일이 작성하는 대신 일부 Response에 대한 사람의 선호를 먼저 수집해 Reward Model이 그 선호를 모방하게 하고, 이후 Reward Model의 평가를 이용해 LLM이 사람이 더 좋아하는 Response를 많이 생성하도록 Reinforcement Learning하는 방법이다.**

---

# 86. RLHF의 “Human Feedback”은 무엇인가?

강의에서 핵심적인 Human Feedback은

```text
Model Response에 대한
Human Preference Ranking
```

이다.

즉

```text
D가 가장 좋다.
C가 그다음이다.
A는 덜 좋다.
B가 가장 나쁘다.
```

와 같은 상대 평가다.

---

# 87. Reward Model을 왜 따로 만드는가?

이유를 구조적으로 기억한다.

```text
Human Preference는 좋지만
매 Training Step마다
사람에게 물어볼 수 없음
        ↓
사람의 평가 방식을
Model로 학습
        ↓
Reward Model
        ↓
빠르게 많은 Response 평가 가능
        ↓
RL Loop 가능
```

---

# 88. Instruction Tuning과 In-context Learning은 다르다

헷갈리기 쉽다.

### Instruction Tuning

```text
Training 과정
↓
Parameter Update O
```

### In-context Learning

```text
Inference 과정
↓
Prompt의 Instruction/Example 활용
↓
Parameter Update X
```

이다.

Instruction Tuning은 In-context Instruction Following 능력을 더 좋게 만들기 위한 Post-training 방법 중 하나라고 볼 수 있다.

---

# 89. Instruction Tuning과 기존 Task-specific Fine-tuning 차이

### 기존

```text
Task A
→ Fine-tune Model A

Task B
→ Fine-tune Model B
```

### Instruction Tuning

```text
Task A
Task B
Task C
...
↓
Natural Language Instruction으로 통일
↓
One Model
```

이다.

---

# 90. Preference Learning과 Reward Model도 구분해야 한다

### Preference Learning

더 넓은 개념.

```text
Human Preference를 이용해
Model 행동을 조정
```

### Reward Model

RLHF에서 그 Preference를 **Scalar Reward로 근사하는 Model**.

즉 Reward Model은 Preference Learning을 구현하기 위한 핵심 구성 요소다.

---

# 91. RLHF와 Post-training 관계

```text
Post-training
      ↓
여러 방법 존재

Alignment Post-training
      ↓
Instruction Tuning
+
Preference Learning
      ↓
대표적인 구현
RLHF
```

처럼 연결해서 이해할 수 있다.

---

# 92. InstructGPT Training의 결과

강의에서는 Human Evaluator가 여러 Model의 Response를 평가했을 때 대체로

```text
Prompt-only GPT-3
        <
Instruction-tuned Model
        <
RLHF까지 적용한 InstructGPT
```

순으로 사람이 더 좋은 Response라고 평가하는 결과가 나타났다고 설명한다.

---

# 93. Alignment가 단순 만족도만 높인 것은 아니다

강의에서는 InstructGPT가 GPT-3에 비해

- Hallucination
    
- Harmful Response
    
- Untruthful Response
    

등에서도 개선된 결과가 보고되었다고 설명한다.

즉 Alignment는

```text
Instruction Following
+
Helpfulness
+
Safety
+
Reliability
```

를 개선하는 방향으로 사용된다.

# 94. RLHF가 LLM Post-training의 표준 방식으로 확산

InstructGPT와 ChatGPT에서 RLHF Framework의 효과가 알려지면서 이후 여러 LLM 개발에서도

```text
Pre-training
↓
SFT / Instruction Tuning
↓
Preference Data
↓
Reward / RL
```

과 같은 Post-training Framework가 널리 활용되는 흐름으로 이어졌다.

---

# 95. Llama 2 Chat 사례

강의 후반에서는 Meta의 Llama 2 Chat도 InstructGPT와 유사하게

```text
Pre-training
↓
Instruction / Supervised Fine-tuning
↓
Human Feedback
↓
Reward Model
↓
Reinforcement Learning
```

Framework를 사용한 사례로 설명한다.

즉 RLHF가 Closed LLM뿐 아니라 Open LLM 계열에서도 활용되는 대표적인 Post-training 구조가 되었음을 보여주는 사례다.

# 96. “Pre-training으로 똑똑하게, Post-training으로 잘 행동하게”

이번 차시의 가장 중요한 직관이다.

```text
Pre-training
→ 세상과 언어를 많이 배움

Post-training
→ 그 능력을 User가 원하는 방식으로 사용
```

으로 구분할 수 있다.

조금 더 자세히 하면

```text
Pre-training
→ Knowledge / Language / General Capability

Instruction Tuning
→ Instruction Following

Preference Learning / RLHF
→ Human Preference / Safety / Helpfulness
```

이다.

---

# 97. 하지만 이 구분을 너무 절대적으로 보면 안 된다

Post-training은 단순히 예절이나 Safety만 학습하는 과정은 아니다.

강의에서도 최근에는 Reinforcement Learning 기반 Post-training을 이용해

```text
Reasoning
Problem Solving
```

자체를 강화할 수 있다고 설명한다.

따라서 현대 Post-training은

```text
Alignment
+
Capability Improvement
```

모두에 사용될 수 있다.

# 98. 이번 강의에서 등장한 “사람”의 역할

사람은 여러 단계에서 다르게 개입한다.

### Pre-training

대규모 Text 자체에서 Target 생성.

→ Human Labeling을 거의 요구하지 않음.

### Instruction Tuning

사람이 좋은 Instruction/Response Demonstration을 제공.

### Preference Collection

사람이 여러 Response를 Ranking.

### RL

Reward Model이 매 Training Sample을 자동 평가.

### Monitoring

사람이 Training이 이상하게 진행되지 않는지 중간 점검.

# 99. Human Effort가 점점 추상화된다

초기의 Supervised Learning:

```text
Sample마다
정답을 직접 작성
```

RLHF:

```text
일부 Candidate의
좋고 나쁨을 평가
      ↓
Reward Model이
사람 평가를 학습
      ↓
이후 수많은 Sample을
자동 평가
```

즉 Human Feedback을 더 Scalable하게 사용하는 구조다.

---

# 100. 자주 헷갈리는 점 ① — GPT-3는 ChatGPT인가?

아니다.

GPT-3는 대규모 Pre-trained Language Model이다.

ChatGPT처럼 User Instruction을 안정적으로 따르는 Assistant를 만들기 위해서는 추가적인 Post-training이 필요하다.

---

# 101. 자주 헷갈리는 점 ② — Next-token Prediction만 잘하면 Instruction도 자동으로 잘 따르는가?

보장되지 않는다.

Next-token Prediction Objective는

```text
다음에 어떤 Token이 자연스러운가?
```

를 학습한다.

Instruction Following은

```text
User가 원하는 행동은 무엇인가?
```

를 학습해야 한다.

그래서 Instruction Tuning이 추가된다.

---

# 102. 자주 헷갈리는 점 ③ — Instruction Tuning은 Unsupervised Learning인가?

아니다.

강의에서는 기본적으로 **Supervised Fine-tuning**으로 설명한다.

Instruction과 적절한 Target Response Pair가 필요하다.

---

# 103. 자주 헷갈리는 점 ④ — 기존 Fine-tuning과 Instruction Tuning은 Algorithm이 완전히 다른가?

학습 방식 자체는 유사한 Supervised Fine-tuning이다.

핵심 차이는

```text
한 Task 전용 Model
```

이 아니라

```text
다양한 Task를
Natural Language Instruction 형태로
하나의 Model에 함께 학습
```

한다는 점이다.

---

# 104. 자주 헷갈리는 점 ⑤ — Instruction Tuning은 Task를 그냥 많이 외우게 하는 것인가?

목표는 그것이 아니다.

많은 Task를 경험시켜

> **Instruction 자체를 해석하고 그에 맞는 행동을 선택하는 Meta Capability**

를 배우도록 유도한다.

---

# 105. 자주 헷갈리는 점 ⑥ — 평가 Dataset만 Training에서 제외하면 충분한가?

Instruction Generalization을 제대로 평가하려면 그렇지 않을 수 있다.

같은 종류의 Task를 다른 Dataset에서 이미 봤다면 Task 자체를 배웠을 수 있다.

그래서 강의에서는 **Task-level Split**을 강조한다.

---

# 106. 자주 헷갈리는 점 ⑦ — Preference Learning에서는 한 Response가 틀렸다고 Labeling하는가?

반드시 그렇지 않다.

여러 Response가 모두 유효할 수 있다.

그중

```text
어느 것이 더 좋은가?
```

라는 상대적 Preference를 학습한다.

---

# 107. 자주 헷갈리는 점 ⑧ — Human이 Response A/B/C/D를 전부 직접 작성하는가?

강의의 Preference Learning 구조에서는 LLM이 여러 Candidate Response를 만들고 Human이 Ranking하는 방식이 핵심이다.

---

# 108. 자주 헷갈리는 점 ⑨ — Reward Model이 Response를 생성하는가?

아니다.

Reward Model은 생성 Model이 아니라

```text
Prompt + Response
↓
Score
```

를 출력하는 **평가 Model**이다.

---

# 109. 자주 헷갈리는 점 ⑩ — Reward Model Score 자체가 정답 Label인가?

중요한 것은 절대적인 숫자보다 **Human Preference와 같은 Ranking을 갖는가**다.

---

# 110. 자주 헷갈리는 점 ⑪ — RLHF Step 3에서도 Human이 매번 점수를 매기는가?

아니다.

Human Preference를 학습한 Reward Model이 매 Response를 평가한다.

다만 전체 Training 과정의 Monitoring이나 Checkpoint Evaluation에는 사람이 개입할 수 있다.

---

# 111. 자주 헷갈리는 점 ⑫ — RLHF는 Instruction Tuning을 대체하는가?

강의의 InstructGPT Pipeline에서는 아니다.

먼저

```text
SFT / Instruction Tuning
```

을 수행한 뒤 Preference / Reward Model / RL 단계가 이어진다.

---

# 112. 자주 헷갈리는 점 ⑬ — PPO가 RLHF의 핵심 개념인가?

강의에서 세부 Algorithm보다 중요한 것은

```text
Policy Model이 Response 생성
↓
Reward Model이 평가
↓
높은 Reward 방향으로 Policy Update
```

라는 구조다.

PPO는 이 Update를 구현하는 구체적인 Reinforcement Learning Algorithm이다.

---

# 113. 자주 헷갈리는 점 ⑭ — Alignment는 Safety만 의미하는가?

아니다.

강의에서는

- User Intent
    
- Helpfulness
    
- Response Quality
    
- Safety
    
- Human Preference
    

등을 모두 포함하는 방향으로 설명한다.

---

# 114. 자주 헷갈리는 점 ⑮ — Post-training은 Model을 착하게만 만드는 과정인가?

아니다.

Reasoning 같은 Capability 자체를 향상하기 위한 Reinforcement Learning Post-training도 가능하다.

---

# 117. 이번 강의에서 반드시 기억할 핵심

### 1. GPT-3는 강의에서 본격적인 LLM의 출발점으로 설명된다.

### 2. GPT-3의 가장 큰 Model은 약 175B Parameters 규모였다.

### 3. GPT-3의 기본 Pre-training Objective는 여전히 Next-token Prediction이었다.

### 4. Model과 Training Data Scale 증가가 GPT-3의 중요한 특징이었다.

### 5. GPT-3는 Web Data뿐 아니라 Books, Wikipedia 등 Quality가 높은 Data도 함께 활용했다.

### 6. Pre-training만으로는 User Instruction을 안정적으로 따르는 Assistant를 만들기 어렵다.

### 7. Pre-trained Model은 Harmful/Unsafe Response를 만들 수도 있다.

### 8. 따라서 Pre-training 이후 Post-training 과정이 필요하다.

### 9. Alignment Training의 목적은 Model Response를 User Intent와 Human Preference/Value에 더 잘 맞추는 것이다.

### 10. 강의에서는 Alignment의 핵심 예로 Instruction Tuning과 Preference Learning을 구분한다.

### 11. Instruction Tuning은 Instruction에 따라 적절한 Response를 생성하도록 학습한다.

### 12. Instruction Tuning 자체는 Supervised Fine-tuning 방식이다.

### 13. 기존 Fine-tuning은 Task마다 별도 Model을 만들었지만 Instruction Tuning은 많은 Task를 하나의 Model에 동시에 학습시킨다.

### 14. 서로 다른 Task는 Natural Language Instruction이라는 공통 Format으로 변환한다.

### 15. Instruction Tuning의 중요한 목표는 Task를 암기하는 것이 아니라 Instruction을 이해하는 능력을 학습하는 것이다.

### 16. 하나의 Task에도 여러 Instruction Template을 만들 수 있으며 이러한 다양성이 Generalization에 도움이 될 수 있다.

### 17. Instruction Tuning에서는 Task Diversity가 중요하다.

### 18. 진짜 새로운 Task에 대한 Generalization을 평가하려면 Dataset-level이 아니라 Task-level Train/Test Split이 중요할 수 있다.

### 19. FLAN은 대표적인 Multi-task Instruction Tuning 연구로 소개된다.

### 20. 강의에서는 충분히 큰 Model에서 Instruction Tuning 효과가 훨씬 강하게 나타났다고 설명한다.

### 21. Natural Language 형태의 Instruction이 효과적이었다고 설명한다.

### 22. Instruction Following만으로 Human-aligned Model이 완성되는 것은 아니다.

### 23. 자연어 Generation에서는 한 Input에 여러 유효한 Response가 있을 수 있다.

### 24. Preference Learning은 여러 Response 중 어느 것이 더 좋은지를 학습한다.

### 25. LLM이 여러 Candidate Response를 만들고 Human이 Ranking할 수 있다.

### 26. Human Preference를 모방하는 Model이 Reward Model이다.

### 27. Reward Model은 Prompt와 Response를 입력받아 Response Quality를 나타내는 Scalar Score를 출력한다.

### 28. Reward Model의 핵심은 Human Preference Ranking을 따라가는 것이다.

### 29. RLHF는 Reinforcement Learning from Human Feedback의 약자다.

### 30. InstructGPT RLHF는 Pre-training 이후 크게 SFT → Reward Model → Reinforcement Learning 순으로 진행된다.

### 31. Step 1에서는 Instruction-following Model을 만든다.

### 32. Step 2에서는 Human Preference Data를 이용해 Reward Model을 학습한다.

### 33. Step 3에서는 Policy Model이 생성한 Response를 Reward Model이 평가하고 높은 Reward 방향으로 Policy를 Update한다.

### 34. 강의에서는 Step 3의 대표 Algorithm으로 PPO를 언급하지만 세부 Algorithm보다 전체 구조가 중요하다고 설명한다.

### 35. RL 단계에서는 Human이 모든 Sample을 직접 평가하지 않고 Reward Model이 Human Preference를 대신 근사한다.

### 36. 다만 Training Monitoring이나 Checkpoint Evaluation에는 사람이 개입할 수 있다.

### 37. Reward가 무엇을 평가하느냐에 따라 Model의 발전 방향도 달라진다.

### 38. Safety Preference를 Reward하면 Safety 특화 Model을 만들 수 있다.

### 39. Correctness를 Reward하면 Reasoning/Problem-solving 능력을 강화할 수 있다.

### 40. 강의에서는 InstructGPT가 GPT-3보다 Human Evaluation, Safety, Hallucination 등에서 개선된 결과를 보였다고 설명한다.

### 41. RLHF Framework는 이후 여러 LLM의 대표적인 Post-training 방식으로 확산됐다.

# 118. 이번 강의 핵심 한 문장

> **거대 언어 모델은 대규모 Next-token Prediction 사전학습만으로는 언어와 지식을 잘 학습할 수 있어도 사용자의 지시를 안정적으로 따르고 사람이 선호하는 안전한 응답을 만든다는 보장은 없기 때문에, 사전학습 이후 다양한 Task를 자연어 지시 형태로 학습해 Instruction Following 능력을 만드는 Instruction Tuning과 여러 후보 응답에 대한 Human Preference를 학습하는 Preference Learning을 수행하며, RLHF에서는 이러한 사람의 선호를 Reward Model로 근사한 뒤 Reinforcement Learning을 통해 사람이 더 선호하는 응답을 생성하도록 Model을 추가 학습한다.**

가장 짧게 기억하면 다음과 같다.

```text
Pre-training
= 말을 잘하고 지식을 많이 아는 Model

Instruction Tuning
= 시키는 일을 이해하는 Model

Preference Learning
= 어떤 답이 더 좋은지 아는 Model

RLHF
= Human Preference를 Reward로 삼아
  실제 행동을 그 방향으로 강화하는 과정
```

그리고 시험에서 RLHF 순서를 물으면 반드시 다음 순서로 기억한다.

```text
Step 0
Pre-training
      ↓
Step 1
Instruction Tuning / SFT
      ↓
Step 2
Human Preference
→ Reward Model
      ↓
Step 3
Reward Model Feedback
→ Reinforcement Learning
→ Policy 개선
```
