## 시험 범위에 포함되는 내용

| **비선형 활성화 함수**          | 선형 층만 여러 개 쌓으면 하나의 선형 변환과 같아지는 문제와 ReLU를 넣어 비선형성을 만드는 이유를 설명한다.                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **1×1 Convolution 연산량** | MobileNet의 Pointwise Conv를 `C²HW`로 계산하고 일반 Conv와 연산량을 비교한다.                                                      |
| **CNN·FC 파라미터 계산**      | Conv의 파라미터를 `Cin × K × K × Cout + Cout`으로 계산하고, FC의 거대한 weight matrix와 파라미터 증가 문제도 설명한다.                         |
| **1×1 Convolution의 특징** | 공간 해상도를 유지하면서 채널 수를 조절하거나 채널 정보를 섞는 역할, ResNet bottleneck과 MobileNet 활용을 설명한다.                                   |
| **Max Pooling**         | 2×2 Max Pooling 계산, 해상도 감소, 위치 변화 강건성, 학습 파라미터가 없다는 점과 정보 손실까지 설명한다.                                             |
| **CNN 수용영역**            | Receptive Field의 정의와 여러 Conv layer를 쌓으면 입력 기준 수용영역이 커지는 이유를 설명한다.                                                |
| **Feature Map 메모리**     | Activation Map의 원소 수와 데이터 타입의 byte 수를 이용해 메모리 사용량을 직접 계산한다.                                                      |
| **CNN Inductive Bias**  | `이미지의 공간 구조 보존 → 작은 local filter → 계층적 feature`라는 CNN 고유의 구조적 가정을 상세히 설명한다. 시험 토픽의 용어 자체보다는 **구조와 원리로 설명**되어 있다. |

### 강사 및 강의 배경

- 강사: KAIST 김재철 AI대학원 심현정 교수
    
- 주요 연구 분야: **컴퓨터 비전**

- 강의에서는 기술적인 원리뿐 아니라 **산업 현장에서 실제로 어떻게 활용되는가**까지 함께 다룬다.

라는 발전 흐름을 이해하는 것이 중요하다.

# 1. 지금도 CNN을 공부해야 하는 이유

최근의 GPT, Gemini, Claude, HyperCLOVA 같은 대규모 멀티모달 AI 모델은 매우 높은 성능과 고차원적인 지능을 보여준다.

그렇다면 CNN은 최신 거대 모델의 핵심 구조도 아닌데 왜 여전히 배워야 할까?

## 1.1 모든 문제에 거대 모델이 필요한 것은 아니다

거대한 AI 모델은 강력하지만 **특정한 이미지 작업 하나만 수행하기 위한 최적의 모델은 아닐 수 있다.**

### 예: PCB 불량 검출

PCB에서 작은 스크래치나 불량을 찾는다고 생각해보자.

이 작업에서 필요한 것은

- PCB의 아주 작은 지역적 특징
    
- 정상과 불량을 구별하는 능력
    

이다.

고차원적인 추론 능력을 가진 거대한 AI 모델을 이런 단순하고 국소적인 작업에 사용하는 것은 필요 이상의 자원을 사용하는 셈이다.

즉,

> **문제의 복잡도에 맞는 모델을 선택해야 한다.**

거대한 모델은 높은 비용과 많은 연산 자원을 요구하므로 단순한 비전 과업에서는 비용 효율적이지 않을 수 있다.

## 1.2 Edge / On-device 환경

CNN이 특히 중요한 두 번째 이유는 다음과 같은 환경이다.

- IoT 기기
    
- 가전제품
    
- 스마트 글래스
    
- 기타 edge/on-device AI
    

이러한 환경에서는

- 빠른 inference
    
- 낮은 전력 소비
    
- 제한된 연산 능력
    

이 중요하다.

강사는 스마트 글래스 연구 사례를 들며, 이러한 장치에서는 거대한 Transformer 계열 모델보다 CNN이 현실적인 선택이 될 수 있다고 설명한다.

따라서 CNN은 반드시 최고의 절대 성능을 내는 모델이 아니더라도,

> **산업 현장에서 빠르고 가볍게 동작해야 하는 이미지 모델에서는 여전히 매우 현실적인 선택지다.**

# 2. 이미지를 FC로 처리하면 어떻게 되는가?

CNN을 이해하기 위해 먼저 Fully Connected Layer와 비교한다.

## 2.1 이미지의 데이터 구조

예를 들어 하나의 컬러 이미지가

`32 × 32 × 3`

이라고 하자.

- 32 × 32 : 이미지의 공간 해상도
    
- 3 : RGB에 해당하는 색상 채널
    

즉 이미지는 단순한 숫자 나열이 아니라

> **높이 × 너비 × 채널**

이라는 공간 구조를 가진 데이터다.

## 2.2 FC에 이미지를 입력하는 방식

Fully Connected Layer에 이미지를 그대로 넣을 수 없으므로 이미지의 모든 값을 한 줄로 펼친다.

이를 **Flattening**이라고 한다.

```text
32 × 32 × 3
        ↓ Flatten
3072-dimensional vector
```

즉 이미지의 공간적 배치를 제거하고 3072개의 숫자로 된 1차원 벡터로 변환한다.

이 벡터를 `x`라고 하면 FC는 학습된 행렬 `W`를 이용하여

`y = Wx`

형태의 변환을 수행한다.

예를 들어 출력이 10차원이라면

```text
3072차원 입력
     ↓ W
10차원 출력
```

이 된다.

출력의 각 위치는 하나의 클래스에 대응한다.

예를 들어

- 첫 번째 출력값이 크다 → 1번 클래스일 가능성이 높음
    
- 두 번째 출력값이 크다 → 2번 클래스일 가능성이 높음
    

과 같이 해석할 수 있다.

---

# 3. CNN은 FC와 무엇이 다른가?

가장 중요한 차이는

> **CNN은 이미지의 공간 구조를 없애지 않는다.**

FC에서는 이미지를 1차원으로 flatten했지만 CNN에서는 원래의

`32 × 32 × 3`

구조를 유지한다.

그리고 거대한 `W` 행렬 하나를 사용하는 대신 **작은 필터(filter/kernel)** 를 이미지 위에서 움직인다.

예를 들어 필터가

`5 × 5 × 3`

이라고 하자.

이 작은 필터를 이미지의 특정 위치에 올린 뒤, 필터가 덮는 이미지 영역과 필터 사이의 내적을 계산한다.

그 다음 필터를 옆으로 이동시키고 같은 계산을 반복한다.

이 반복 연산이 **Convolution**이다.

```text
이미지
┌─────────────────┐
│  ┌─────┐        │
│  │filter│ → → → │
│  └─────┘        │
└─────────────────┘
```

Convolution 자체는 CNN과 함께 처음 등장한 개념은 아니다.

이미 오래전부터

- 이미지 처리
    
- 이미지 필터
    
- 신호 처리
    

등에서 사용되던 수학적 연산이며, CNN은 이를 신경망 구조에 활용한 것이다.

---

# 4. Convolution Filter의 구조

## 4.1 입력 채널과 필터 채널은 같아야 한다

입력이

`32 × 32 × 3`

이라면 필터 역시 깊이 방향으로 입력 전체를 덮어야 한다.

따라서 예를 들어 공간 크기가 5×5인 필터라면

`5 × 5 × 3`

이어야 한다.

핵심은

> **필터의 channel 수 = 입력의 channel 수**

라는 것이다.

그렇지 않으면 필터와 입력을 완전히 겹쳐 내적할 수 없기 때문에 연산이 성립하지 않는다.

반면 공간 크기는

- 3×3
    
- 5×5
    
- 7×7
    

등으로 설계할 수 있다.

---

# 5. Convolution 연산

필터가 덮고 있는 이미지 영역을 꺼낸 후,

- 필터의 값들을 1차원으로 펼치고
    
- 이미지의 해당 영역도 1차원으로 펼친 뒤
    
- 두 벡터를 내적한다.
    

개념적으로

`W · x + b`

와 같이 생각할 수 있다.

여기서

- `W` : 필터의 학습 파라미터
    
- `x` : 필터가 현재 보고 있는 입력 영역
    
- `b` : bias
    

이다.

하나의 필터에는 따라서

- filter weight `W`
    
- bias `b`
    

가 존재한다.

---

# 6. 이미지 경계에서 발생하는 문제

필터를 이미지의 가장 모서리에 중심을 맞추면 필터의 일부가 이미지 밖으로 나간다.

이미지 밖에는 대응할 pixel이 없기 때문에 정상적인 내적을 수행할 수 없다.

가장 단순한 방법은

> **필터 전체가 이미지 안에 들어오는 위치에서만 convolution을 수행하는 것**

이다.

이렇게 하면 이미지의 가장자리에서는 연산을 수행하지 않는다.

하지만 그 결과 출력 크기가 입력보다 작아진다.

예:

```text
Input : 32 × 32
Kernel: 5 × 5
Output: 28 × 28
```

필터가 이동하면서 만들어낸 모든 결과값을 모은 출력 맵을 **Activation Map**이라고 한다.

---

# 7. Convolution의 실제 계산 예시

강의에서는 흑백 이미지와 하나의 필터를 이용하여 convolution이 어떻게 수행되는지를 설명한다.

필터를 한 칸씩 이동하면서 해당 영역과 필터의 내적을 계산한다.

예를 들어 특정 영역에 유효한 값이 하나만 포함되어 있다면 출력이 10,

두 개 포함되면

`10 + 10 = 20`

세 개라면

`30`

과 같이 출력값이 만들어진다.

이를 이미지 전체에 반복하면 새로운 activation map이 만들어진다.

여기서 중요한 것은 convolution 결과가 단순한 하나의 값이 아니라

> **필터가 이미지의 각 위치에서 해당 특징에 얼마나 반응했는지를 나타내는 공간적인 맵**

이라는 것이다.

---

# 8. 하나의 Convolution Layer에는 여러 필터가 존재한다

실제 CNN에서는 하나의 convolution layer에 필터 하나만 사용하는 경우가 거의 없다.

예를 들어 6개의 filter가 있다면 6개의 filter가 각각 독립적으로 학습된다.

각 filter가 하나의 activation map을 만든다면

```text
1 filter → 1 activation map
6 filters → 6 activation maps
```

가 된다.

각 activation map의 크기가 28×28이라면 전체 출력은

`6 × 28 × 28`

이 된다.

따라서 중요한 규칙은

> **출력 채널 수 = 해당 convolution layer의 filter 수**

이다.

---

# 9. Convolution 출력 크기

Stride가 1이고 padding이 없는 기본 convolution의 경우 강의에서는 출력 해상도를 다음과 같이 계산한다.

`출력 크기 = 입력 크기 - 필터 크기 + 1`

예:

```text
Input  = 32
Kernel = 5

32 - 5 + 1 = 28
```

또 다른 예:

```text
Input  = 10
Kernel = 3

10 - 3 + 1 = 8
```

---

# 10. Padding

Convolution을 수행하면 이미지의 가장자리가 사라지면서 activation map이 계속 작아질 수 있다.

입력과 출력의 공간 해상도를 유지하고 싶다면 **Padding**을 사용할 수 있다.

강의에서는 대표적으로 두 방법을 소개한다.

## Zero Padding

이미지 주변의 존재하지 않는 값을 `0`으로 채운다.

## Replication Padding

가장 가까운 실제 값을 복사해서 경계 영역을 채운다.

Padding을 적절히 사용하면

```text
32 × 32
   ↓ convolution
32 × 32
```

처럼 입력과 같은 공간 해상도를 유지할 수 있다.

---

# 11. Batch 차원

실제로 neural network에는 이미지 하나만 들어오는 것이 아니라 여러 이미지가 한 번에 입력되는 경우가 많다.

이를 **Batch**라고 한다.

일반적으로 입력 구조를

`N × C × H × W`

와 같이 생각할 수 있다.

- `N` : batch size
    
- `C` : input channel
    
- `H` : height
    
- `W` : width
    

Convolution 이후에는

`N × C' × H' × W'`

형태가 된다.

여기서

- `N`은 그대로 유지
    
- `C'`는 filter 개수에 의해 결정
    
- `H', W'`는 kernel, padding, stride 등에 의해 결정
    

된다.

---

# 12. 왜 Convolution Layer를 여러 개 쌓는가?

CNN은 convolution layer 하나만 사용하지 않고 여러 layer를 깊게 쌓는다.

한 가지 이유는 **모델의 학습 파라미터를 증가시켜 더 복잡한 함수를 표현하기 위해서**다.

하지만 단순한 선형 layer만 여러 번 쌓는 것은 의미가 없다.

예를 들어

`W3(W2(W1x))`

라는 연산이 있다고 하자.

모두 선형 변환이라면

`W = W3W2W1`

이라는 하나의 행렬로 합칠 수 있다.

결국

`Wx`

와 동일하다.

즉,

> **선형 변환만 반복하면 아무리 layer를 많이 쌓아도 하나의 선형 변환과 본질적으로 같다.**

---

# 13. ReLU와 비선형성

이 문제를 해결하기 위해 layer 사이에 **non-linear activation function**을 넣는다.

대표적인 것이 ReLU다.

강의의 설명:

```text
x < 0 → 0
x > 0 → x
```

ReLU가 들어가면 여러 layer를 하나의 `W`로 합쳐 표현할 수 없게 된다.

따라서 여러 layer를 쌓는 것이 실제 모델의 표현 능력을 증가시키게 된다.

---

# 14. FC는 무엇을 학습하는가? — Template 관점

단일 FC 기반 이미지 분류기를 생각해보자.

`y = Wx`

에서 `W`의 각 row를 다시 이미지 형태로 복원해서 시각화하면 해당 클래스의 대표 이미지처럼 보이는 패턴이 나타날 수 있다.

예를 들어

- 비행기 클래스 → 대표적인 비행기 형태
    
- 자동차 클래스 → 대표적인 자동차 형태
    
- 개구리 클래스 → 대표적인 개구리 형태
    

와 같은 것이다.

즉 하나의 선형 classifier에서 `W`는

> **각 클래스의 대표 template**

역할을 한다고 해석할 수 있다.

## 단일 Template의 한계

하지만 자동차는 항상 같은 모습이 아니다.

- 앞에서 볼 수도 있고
    
- 뒤에서 볼 수도 있고
    
- 옆에서 볼 수도 있고
    
- 회전되어 있을 수도 있고
    
- 색상이 다를 수도 있다.
    

하나의 대표 template만 가진 선형 모델은 이런 다양한 형태를 충분히 표현하기 어렵다.

따라서 일반화에 한계가 있다.

---

# 15. 여러 FC Layer + 비선형성

FC layer를 여러 개 쌓고 그 사이에 nonlinear activation을 넣으면 여러 개의 template을 표현할 수 있다.

예를 들어 자동차에 대해서도

- 서로 다른 색
    
- 서로 다른 방향
    
- 서로 다른 회전
    
- 서로 다른 위치
    

를 나타내는 여러 template을 학습할 수 있다.

즉

```text
단일 Linear FC
→ 클래스당 대표적인 하나의 template

여러 FC + Nonlinearity
→ 더 다양한 template
```

로 확장된다.

---

# 16. CNN의 Template은 FC와 어떻게 다른가?

CNN의 가장 중요한 특징은 **계층에 따라 서로 다른 수준의 특징을 학습한다는 것**이다.

## 입력에 가까운 Low-level Layer

매우 작은 지역적 특징을 학습한다.

예:

- 경계(edge)
    
- 색상 변화
    
- 격자 또는 방향성 패턴
    
- 몇 pixel 수준의 local pattern
    

## 중간 Layer

조금 더 큰 영역을 본다.

예:

- blob
    
- 부분적인 형태
    
- 객체의 일부
    

## 출력에 가까운 High-level Layer

훨씬 큰 영역을 보면서

- object 수준
    
- image 전체 수준
    
- semantic한 의미
    
- 문맥
    

을 표현한다.

즉 CNN은

```text
Local pattern
      ↓
Part / Blob
      ↓
Object
      ↓
Image / Semantic context
```

의 계층적 특징을 추출한다.

이것이 CNN이 이미지에 강한 핵심적인 이유다.

---

# 17. 왜 Local Feature가 중요한가?

### PCB 불량 검출

불량과 정상의 차이가 매우 작은 영역에 있다면 전체적인 대표 template보다 작은 local feature를 정확히 확인하는 CNN이 유리하다.

### 비슷한 새를 분류하는 문제

만약 클래스가

- 참새
    
- 비둘기
    
- 까치
    

처럼 모두 비슷한 형태라면 전체 실루엣만으로 구별하기 어렵다.

대신

- 부리 색깔
    
- 날개 색깔
    
- 비율
    
- 작은 형태 차이
    

를 확인해야 한다.

CNN은 작은 local difference부터 전체 semantic difference까지 여러 scale을 동시에 계층적으로 표현할 수 있다.

---

# 18. FC와 CNN 비교

|모델|특징|
|---|---|
|Linear FC|각 클래스의 대표적인 하나의 template|
|FC + nonlinear layers|여러 종류의 template|
|CNN|여러 template뿐 아니라 local → part → object → semantic으로 이어지는 계층적 특징|

---

# 19. Receptive Field(수용 영역)

CNN의 계층적 특징과 직접 관련되는 개념이 **Receptive Field**다.

Receptive Field란

> **특정 layer의 하나의 출력이 원본 입력 이미지에서 어느 정도 크기의 영역을 보고 만들어졌는가**

를 의미한다.

예를 들어 첫 convolution에서 3×3 kernel을 사용한다면 첫 번째 layer의 출력 하나는 입력 이미지의

`3 × 3`

영역을 보고 만들어진다.

따라서 초기 receptive field는 3×3이다.

그러나 layer가 깊어지면 이전 layer의 여러 출력값을 다시 조합하게 되므로 원본 이미지 기준으로 볼 수 있는 영역이 점점 커진다.

즉,

```text
초기 Layer
→ 작은 영역

깊은 Layer
→ 큰 영역

마지막 Layer
→ 이미지의 상당 부분 또는 전체
```

가 된다.

Receptive field는 일종의 **network의 시야**라고 생각할 수 있다.

이미지의 넓은 영역을 볼 수 있을수록 더 많은 문맥을 고려할 수 있기 때문에 network 설계에서는 receptive field를 넓히는 것이 중요하게 다뤄진다.

---

# 20. Layer를 깊게 쌓으면 Receptive Field가 넓어진다

강의에서는 여러 3×3 convolution을 순차적으로 적용하는 예로 이를 설명한다.

첫 layer의 출력은 입력 이미지의 작은 3×3 영역만 본다.

하지만 다음 layer의 하나의 출력은 첫 layer의 여러 출력값을 함께 본다.

각각의 첫 layer 출력이 다시 원본 이미지의 서로 다른 3×3 영역을 보고 있기 때문에 최종적으로 두 번째 layer는 원본 이미지의 훨씬 넓은 영역의 정보를 가지게 된다.

따라서

> **작은 kernel을 사용하더라도 여러 layer를 깊게 쌓으면 receptive field를 넓힐 수 있다.**

---

# 21. Pooling

Pooling은 activation map의 공간 해상도를 줄이는 연산이다.

여러 pooling 방법이 있지만 강의에서는 **Max Pooling**을 중심으로 설명한다.

예를 들어 2×2 max pooling이라면 2×2 영역에서 가장 큰 값 하나만 남긴다.

```text
[1 2]
[3 6]

→ 6
```

4×4 입력에 2×2 max pooling을 적용하면 각각의 2×2 영역에서 하나의 값만 남기므로 공간 크기가 크게 감소한다.

## Pooling의 장점

### 1. 연산량 감소

공간 해상도가 줄어들기 때문에 뒤의 layer에서 처리해야 하는 값이 줄어든다.

### 2. 위치 변화에 대한 강건성

이미지가 한두 pixel 정도 이동하더라도 pooling을 거치면 비슷한 결과가 남을 수 있다.

따라서 작은 좌우/상하 이동에 덜 민감해진다.

### 3. 학습 Parameter가 없다

Pooling은 정해진 규칙에 따라 수행되는 연산이다.

따라서 convolution처럼 학습할 weight를 가지고 있지 않다.

---

# 22. Pooling의 문제

Pooling은 값을 직접 버린다.

예를 들어 2×2 max pooling에서는 4개 중 하나만 남기므로 나머지 3개의 정보가 사라진다.

그리고 어떤 값을 버릴 것인지에 대해 모델이 학습할 수도 없다.

즉,

> **고정된 rule에 의해 정보가 손실된다.**

이 문제를 보완하면서 해상도를 줄이는 방법으로 **Strided Convolution**이 사용된다.

---

# 23. Strided Convolution

기본 convolution에서는 filter가 한 칸씩 이동한다.

Stride `S`를 사용하면 filter를 `S`칸씩 이동한다.

예:

```text
Stride = 1
→ 한 칸씩 이동

Stride = 2
→ 두 칸씩 이동
```

두 칸씩 이동하면 계산되는 위치 자체가 줄기 때문에 activation map의 해상도도 자연스럽게 감소한다.

즉,

> **Convolution과 downsampling을 동시에 수행한다.**

## Pooling보다 Strided Convolution이 가지는 장점

Pooling은 고정된 방식으로 값을 버린다.

반면 strided convolution은

> **어떤 간격으로 정보를 축소할 것인지 알고 있는 상태에서 convolution filter 자체가 학습된다.**

따라서 정보 보존 측면에서 더 유리할 수 있다.

강의에서는 고도화된 CNN에서 pooling보다 strided convolution을 많이 사용하는 경향이 있다고 설명한다.

---

# 24. 일반적인 Convolution 출력 크기 공식

강의에서 이후 AlexNet을 설명하면서 일반화한 공식은 다음 구조다.

`Output = (Input - Kernel + 2 × Padding) / Stride + 1`

각 기호를 다음처럼 볼 수 있다.

- Input: 입력 해상도
    
- Kernel: kernel 크기
    
- Padding: 한쪽에 추가하는 padding 크기
    
- Stride: filter 이동 간격
    

Padding에 2를 곱하는 이유는 양쪽에 padding이 추가되기 때문이다.

---

# 25. CNN 발전의 역사적 배경

강의에서는 2010년대 초반부터 약 2017년 사이의 CNN 발전사를 살펴본다.

ImageNet의 Top-5 error를 기준으로 보면 error가 빠르게 줄어들었다.

2010~2011년경에는 아직 deep learning이 지금과 같은 형태로 정립되지 않았고,

```text
Feature extractor 설계
+
Classifier 설계
```

를 서로 분리해서 고민하는 방식이 일반적이었다.

그러나 2012년 AlexNet의 등장으로 ImageNet error가 급격하게 떨어졌고 이후 CNN 모델들이 빠르게 발전하기 시작했다.

강사는 이후 모델이 사람과 비교할 만한 수준까지 ImageNet classification 성능을 높였다고 설명한다.

다만 이것을 단순히

> “AI가 인간을 이겼다.”

라고 해석하면 안 된다.

그 결과는 **ImageNet이라는 잘 정의된 1,000-class classification task에서의 결과**이며 인간의 전반적인 시각 지능을 능가했다는 뜻은 아니다.

---

# 26. AlexNet

## 26.1 AlexNet의 의미

AlexNet은 최초의 성공적인 deep CNN 모델 중 하나로 강의에서 소개된다.

구조는 총 8개의 주요 layer:

- 5개의 convolution layer
    
- 3개의 fully connected layer
    

로 구성된다.

이

> **5 Conv + 3 FC**

구조는 이후 한동안 CNN 설계의 강력한 기준처럼 사용되었다.

AlexNet은 단지 이미지 분야에서 성공한 모델일 뿐 아니라 이후 많은 deep learning 연구에 큰 영향을 미쳤다는 점에서도 중요한 모델이다.

---

# 27. AlexNet의 입출력

강의에서는 입력을

`227 × 227 × 3`

RGB image로 설명한다.

ImageNet classification을 위한 출력은 최종적으로 class에 대응하는 값을 만든다.

학습 시 label은 **One-hot Vector** 형태로 표현한다.

예:

```text
Class 1
[1, 0, 0, 0, ...]

Class 5
[0, 0, 0, 0, 1, ...]
```

즉 정답 class 위치 하나만 1이고 나머지는 0이다.

모델의 출력값은 각각 해당 class에 속할 가능성으로 해석할 수 있도록 만들어진다.

---

# 28. AlexNet 당시의 하드웨어 제약

초기의 AlexNet 연구 당시 GPU memory가 매우 제한적이었다.

강의에서는 GTX 580의 약 3GB GPU memory 환경 때문에 GPU 두 개를 사용하여 병렬로 연산했다고 설명한다.

그래서 중간 activation을 GPU 사이에서 교환하는 등 구현상의 여러 trick이 필요했다.

이 점은 AlexNet의 초기 network design에도 영향을 주었다.

현재의 GPU에서는 당시보다 훨씬 큰 memory를 사용할 수 있으므로 이러한 제약은 상당히 줄어들었다.

---

# 29. AlexNet Layer 구조

## 첫 번째 Convolution

Input:

`227 × 227 × 3`

Kernel:

`11 × 11 × 3`

Kernel 개수:

`96`

Stride:

`4`

따라서 출력:

`55 × 55 × 96`

이 된다.

채널이 96인 이유는 filter가 96개이기 때문이다.

## Max Pooling

그 뒤 3×3 max pooling과 stride 2를 적용하여 공간 해상도를 줄인다.

강의에서 설명한 흐름은 대략 다음과 같다.

```text
227×227×3
    ↓ Conv 11×11, stride 4
55×55×96
    ↓ Max Pool
27×27×96
    ↓ Conv 5×5
...
    ↓ Conv 3×3
...
    ↓ Pool
6×6×256
```

최종 convolution feature map을 flatten하면

`6 × 6 × 256 = 9216`

개의 값이 된다.

이후 FC를 적용하여

```text
9216
 ↓ FC
4096
 ↓ FC
4096
 ↓ FC
class output
 ↓ Softmax
probability-like output
```

으로 처리한다.

---

# 30. AlexNet의 설계 의도

AlexNet은 초반에

- 큰 kernel
    
- 큰 stride
    

를 사용한다.

그 이유 중 하나는 초기에 해상도를 빠르게 줄여 연산과 memory 부담을 감소시키기 위해서다.

당시 GPU memory가 매우 제한되어 있었기 때문에 이러한 설계가 현실적으로 중요했다.

그 이후에는 channel 수를 증가시키면서 다양한 feature를 추출한다.

강의의 관점에서 channel이 많다는 것은

> **더 많은 종류의 feature template을 추출하는 것**

이라고 볼 수 있다.

Convolution 부분에서는

```text
Local feature
→ Mid-level feature
→ Object / Image-level feature
```

를 추출하고,

후반 FC layer는 **classifier** 역할을 담당한다.

마지막에는 Softmax를 사용하여 class별 출력을 확률처럼 해석할 수 있는 형태로 바꾼다.

---

# 31. Convolution 출력 크기 계산 — AlexNet 예제

AlexNet의 첫 convolution을 예로 들면

- Input = 227
    
- Kernel = 11
    
- Padding = 0
    
- Stride = 4
    

이다.

따라서

`(227 - 11 + 0) / 4 + 1`

`= 216 / 4 + 1`

`= 54 + 1`

`= 55`

가 된다.

Filter가 96개이므로 최종 출력은

`55 × 55 × 96`

이다.

---

# 32. Activation Memory 계산

Convolution의 출력 activation이 얼마나 memory를 사용하는지를 계산할 수 있다.

먼저 출력 원소 개수를 계산한다.

AlexNet 첫 layer라면

`96 × 55 × 55`

이다.

각 값을 float32로 저장한다면 하나의 값이 4byte를 사용한다.

따라서

`96 × 55 × 55 × 4 bytes`

로 activation memory를 계산할 수 있다.

강의에서는 이를 약 1,134KB 수준으로 설명한다.

---

# 33. Convolution Parameter 수 계산

AlexNet 첫 layer의 하나의 filter는

`3 × 11 × 11`

개의 weight를 가진다.

Filter는 96개이므로 weight 수는

`3 × 11 × 11 × 96`

이다.

그리고 filter마다 bias가 존재하므로 bias 96개를 추가한다.

일반화하면

`Parameter = Cin × K × K × Cout + Cout`

로 이해할 수 있다.

여기서

- `Cin` : input channel
    
- `Cout` : output channel = filter 수
    
- `K` : kernel size
    

이다.

---

# 34. Convolution 연산량

강의에서는 곱셈만 고려해 연산량을 계산한다.

하나의 출력 위치를 계산하기 위해서는 kernel 전체와 input patch의 곱셈이 필요하다.

따라서 대략

`Hout × Wout × Cout × Cin × K × K`

의 곱셈이 필요하다.

덧셈까지 함께 계산한다면 추가적인 연산을 고려해야 한다.

이 수치를 FLOPs 관점에서 사용한다.

---

# 35. AlexNet의 Memory / Parameter / FLOPs 특성

AlexNet에서는 세 종류의 비용이 서로 다른 위치에 집중된다.

## Activation Memory

초기 layer에서 많이 사용된다.

초기에는 공간 해상도가 크기 때문이다.

## Parameter

후반 FC에서 매우 많다.

예를 들어

`4096 × 4096`

과 같이 거대한 weight matrix가 필요하다.

## FLOPs

Convolution layer에서 많이 발생한다.

Convolution은 동일한 kernel을 이미지의 여러 위치에서 반복적으로 적용하기 때문이다.

따라서

> **Parameter가 많다고 반드시 계산량도 가장 많은 것은 아니다.**

AlexNet에서는

- Parameter → FC에 집중
    
- Computation → Conv에 집중
    

되는 특징이 있다.

---

# 36. VGGNet

AlexNet이

> “깊은 CNN이 실제로 강력하게 동작한다.”

는 것을 보여주었다면 VGG는 여기에 더 명확한 **Network Design Philosophy**를 제시했다.

대표적으로 VGG16과 VGG19가 있다.

- VGG16 → 16개 주요 layer
    
- VGG19 → 19개 주요 layer
    

AlexNet의 8개 layer보다 훨씬 깊다.

VGG의 중요한 메시지는

> **CNN은 더 깊게 쌓을수록 성능을 향상시킬 수 있다.**

는 흐름을 강하게 보여준 것이다.

---

# 37. VGG의 규칙적인 구조

AlexNet은

- 11×11
    
- 5×5
    
- 3×3
    

등 서로 다른 kernel을 사용하고 channel 수도 다소 경험적으로 결정되어 구조의 규칙성이 낮았다.

반면 VGG는 매우 규칙적이다.

## 핵심 규칙

### 1. 거의 모든 convolution을 3×3으로 통일

큰 kernel을 다양하게 사용하지 않는다.

### 2. Stride = 1

### 3. Padding = 1

3×3 convolution을 사용하면서 padding 1을 사용하면 공간 해상도를 유지할 수 있다.

### 4. Max Pooling으로 해상도를 줄임

### 5. Pooling으로 해상도를 줄일 때 channel을 2배로 증가

예:

```text
64
 ↓ pooling
128
 ↓ pooling
256
 ↓ pooling
512
```

즉

> **공간 정보는 줄이고 feature 종류는 늘리는 구조**

다.

---

# 38. VGG의 핵심 철학 — 작은 Kernel을 깊게 쌓는다

AlexNet에서는 5×5 또는 11×11 같은 큰 kernel을 사용했다.

VGG의 핵심적인 아이디어는

> **큰 kernel 하나보다 작은 3×3 kernel을 여러 개 깊게 쌓는 것이 좋다.**

는 것이다.

---

# 39. 5×5 Conv 하나 vs 3×3 Conv 두 개

Input channel과 output channel이 모두 `C`라고 가정한다.

## 5×5 Convolution 하나

Parameter:

`25C²`

FLOPs:

`25C²HW`

## 3×3 Convolution 두 개

하나의 3×3 convolution:

`9C²`

두 개이므로

`18C²`

FLOPs:

`18C²HW`

이 된다.

그런데 두 개의 3×3 convolution을 쌓으면 receptive field 측면에서는 큰 kernel과 유사하게 더 넓은 영역을 볼 수 있다.

따라서 강의에서 강조하는 장점은

1. 비슷한 receptive field 확보
    
2. parameter 감소
    
3. FLOPs 감소
    
4. network depth 증가
    

이다.

즉

> **더 깊어지면서 오히려 계산량과 parameter를 줄일 수 있다.**

이것이 이후 CNN architecture에 큰 영향을 미친 VGG의 중요한 design principle이다.

---

# 40. VGG의 해상도와 Channel 균형

VGG는 공간 해상도를 감소시키는 대신 channel 수를 증가시킨다.

예:

```text
Spatial resolution ↓
Channel            ↑
```

이를 통해 특정 layer에 computation이 과도하게 몰리지 않도록 비교적 규칙적인 구조를 만든다.

강의에서는 이를 전체적인 연산량을 여러 layer에 분배하려는 철학으로 설명한다.

---

# 41. AlexNet과 VGG 비교

VGG는 AlexNet보다

- layer가 많고
    
- intermediate feature channel이 많고
    
- 더 많은 activation memory를 사용하며
    
- parameter도 더 많고
    
- computation도 상당히 많다.
    

하지만 구조가 단순하고 규칙적이기 때문에 각 layer가 어떤 역할을 하는지 해석하기 쉽다.

그래서 VGG의 intermediate feature는 이후 다양한 image task에서 **feature extractor**로 널리 활용되었다.

또한 transfer learning의 강력한 baseline으로 사용되었다.

단점은

- 많은 parameter
    
- 무거운 model
    
- 높은 computation cost
    

이다.

---

# 42. ResNet

VGG가

> **작은 filter를 사용해 network를 더 깊게 만들자**

는 방향을 보여주었다면 ResNet은 이를 훨씬 더 극단적으로 확장했다.

VGG는 약 16~19 layer 정도였고 GoogLeNet은 22 layer 수준까지 깊어졌다.

ResNet에서는 50 layer를 넘어 100 layer 이상의 매우 깊은 network까지 가능해졌다.

이를 가능하게 만든 핵심이 **Residual Connection / Residual Block**이다.

---

# 43. Network를 무조건 깊게 하면 왜 안 되는가?

Batch Normalization 등의 기술이 등장하면서 20 layer 정도까지는 비교적 안정적으로 학습할 수 있었다.

그런데 layer를 더 깊게 만들자 예상과 다른 문제가 나타났다.

### 예상

Parameter가 증가한다.

그러면 적어도 training data는 더 잘 외울 수 있을 것이다.

따라서 training error는 감소해야 할 것처럼 보인다.

### 실제

Network를 너무 깊게 만들면 **training error 자체가 증가했다.**

이는 단순한 overfitting과는 다르다.

Overfitting이라면

```text
Training error ↓
Test error     ↑
```

이어야 한다.

하지만 여기서는

```text
Training error ↑
Test error     ↑
```

가 나타났다.

즉 단순한 일반화 문제가 아니라

> **깊은 network 자체가 제대로 optimization되지 않는 문제**

가 발생한 것이다.

---

# 44. Residual Block의 등장 아이디어

이미 20-layer network는 잘 동작한다고 하자.

그렇다면 50-layer network를 만들더라도 최소한 20-layer network 수준의 성능은 보장할 수 있어야 하지 않을까?

추가된 layer가 도움이 되지 않는다면

> **그 layer가 아무것도 하지 않고 입력을 그대로 통과시키면 된다.**

이 아이디어에서 Residual Connection이 등장한다.

---

# 45. Residual Connection

Residual block에서는 입력 `x`를 두 경로로 보낸다.

```text
       ┌──── F(x) ────┐
x ─────┤              ├─ + → output
       └──── x ───────┘
```

즉 output은

`F(x) + x`

형태가 된다.

한 경로에서는 convolution과 ReLU를 통과하여 새로운 변환 `F(x)`를 학습한다.

다른 경로에서는 입력 `x`를 그대로 전달한다.

이를

- shortcut connection
    
- skip connection
    
- residual connection
    

의 개념으로 이해할 수 있다.

만약 추가된 layer가 도움이 되지 않는다면 `F(x)`가 0에 가까워지도록 학습하면

`F(x) + x ≈ x`

가 된다.

즉 새로운 layer가 기존 표현을 망가뜨리는 대신 **최소한 identity mapping을 수행할 수 있는 길을 열어준다.**

이것이 강의에서 설명하는 Residual Block의 핵심 직관이다.

---

# 46. Basic Residual Block

기본 residual block은 여러 convolution과 ReLU를 거친 `F(x)`를 원래 입력 `x`와 더한다.

강의에서는 3×3 convolution 두 개를 이용한 block을 설명한다.

대략적인 구조:

```text
x
│
├──────────────────────────┐
│                          │
↓                          │
3×3 Conv                    │
↓                          │
ReLU                        │
↓                          │
3×3 Conv                    │
↓                          │
F(x) ────────────────────── + 
                             ↓
                          Output
```

입력과 `F(x)`를 더하려면 두 tensor의 shape이 같아야 한다.

따라서 residual connection에서는 input/output spatial size와 channel을 맞추는 것이 중요하다.

---

# 47. Bottleneck Residual Block

보다 발전된 residual block에서는 3개의 convolution을 사용한다.

```text
1×1 Conv
   ↓
3×3 Conv
   ↓
1×1 Conv
```

핵심은 **1×1 Convolution**이다.

## 첫 번째 1×1 Conv

공간 해상도는 유지하면서 channel 수를 줄인다.

```text
많은 Channel
     ↓ 1×1
적은 Channel
```

이렇게 가운데 channel이 좁아지는 모습을 **Bottleneck**이라고 부른다.

## 가운데 3×3 Conv

줄어든 channel에서 spatial feature를 처리한다.

## 마지막 1×1 Conv

Channel을 다시 증가시켜 residual input과 더할 수 있는 shape으로 복원한다.

```text
Wide
 ↓
Narrow     ← Bottleneck
 ↓
Wide
```

---

# 48. Bottleneck의 장점

## 1. 연산량 감소

가장 비싼 3×3 convolution을 적은 channel에서 수행하기 때문에 연산량이 크게 감소한다.

## 2. Network Depth 증가

Basic block에서는 2개 layer를 사용했다면 bottleneck에서는 3개 layer를 사용할 수 있다.

따라서 효율성을 유지하면서 network를 더 깊게 만들 수 있다.

강의에서는 이 구조 덕분에 ResNet이

- 100 layer
    
- 150 layer 이상
    

으로 확장될 수 있었다고 설명한다.

따라서 ResNet-50 같은 모델은 이후에도 매우 강력한 CNN baseline으로 사용된다.

---

# 49. ResNet의 Stem

ResNet은 network의 앞부분에서 공간 해상도를 빠르게 줄이는 **Stem 구조**도 사용한다.

큰 해상도를 그대로 유지하면 많은 연산이 필요하기 때문에 초기에 해상도를 줄여 전체 계산량을 감소시킨다.

---

# 50. Global Average Pooling

초기 CNN에서는 마지막에 여러 개의 큰 FC layer를 사용했다.

하지만 FC는 parameter 수가 매우 많다.

ResNet에서는 이를 줄이기 위해 **Global Average Pooling**을 사용한다.

예를 들어 마지막 feature map이

`7 × 7 × C`

라고 하자.

각 channel의 7×7 = 49개 값을 평균내면

`1 × 1 × C`

가 된다.

즉 공간 차원은 사라지고 channel 정보만 남는다.

```text
7 × 7 × C
     ↓ Global Average Pool
1 × 1 × C
     ↓
C-dimensional vector
```

이후 하나의 FC layer를 사용하여 최종 classification을 수행할 수 있다.

장점은

- 공간 크기 축소
    
- 대규모 FC layer 제거
    
- parameter 감소
    

이다.

---

# 51. ResNet의 효율성

강의에서는 VGG와 ResNet을 비교하며 ResNet이

- 더 깊지만
    
- computation은 더 적을 수 있고
    
- 정확도는 더 높을 수 있다
    

는 점을 설명한다.

즉 ResNet의 핵심은 단순히 network depth만 늘린 것이 아니다.

> **더 깊은 network를 실제로 학습할 수 있게 만들면서 computation efficiency도 개선했다.**

---

# 52. 실무에서 자주 사용하는 ResNet

강의에서 언급한 대표적인 모델:

- ResNet-18
    
- ResNet-34
    
- ResNet-50
    

### ResNet-18

상대적으로 가볍다.

### ResNet-34

강력한 practical baseline.

### ResNet-50

Bottleneck 구조를 사용하는 대표적인 강력한 baseline.

CNN 기반 모델을 처음 구성할 때 ResNet-34 또는 ResNet-50은 매우 중요한 기준점으로 사용할 수 있다.

---

# 53. ResNet 학습 Recipe

강의에서는 ResNet을 사용할 때 자주 함께 사용되는 학습 방법도 소개한다.

### Batch Normalization

Convolution layer와 함께 적극적으로 사용.

### Initialization

ReLU를 사용한다면 He initialization 등을 고려.

### Optimizer

SGD를 많이 사용하며 momentum을 함께 사용할 수 있다.

### Learning Rate

초기 learning rate를 설정하고 validation 성능이 정체되면 decay를 통해 learning rate를 감소시킨다.

### Weight Decay

Regularization을 위해 사용.

### Dropout

강의에서는 ResNet을 포함한 CNN convolution 부분에서는 dropout을 적극적으로 사용하지 않는 편이라고 설명한다.

Dropout은 특히 FC 계열에서 많이 사용되던 방법이라는 설명이다.

---

# 54. ResNet의 의의

ResNet의 핵심적인 의미는

> **100층 이상의 매우 깊은 CNN을 실제로 학습할 수 있다는 것을 보여준 것**

이다.

또 당시 다양한 image task에서 매우 강력한 성능을 보이며 하나의 architecture가 여러 task에서 강력한 baseline이 될 수 있음을 보여주었다.

강의에서는 ResNet을 이미지 분야의 가장 중요한 baseline 중 하나로 평가한다.

---

# 55. MobileNet의 등장 배경

ResNet까지 CNN 연구의 주요 관심사는

> **어떻게 더 깊고 강력한 모델을 만들 것인가**

였다.

하지만 실제 산업과 mobile/embedded device에서 모델을 사용하려고 하면서 다른 문제가 중요해졌다.

- 연산량
    
- latency
    
- power consumption
    
- memory
    
- model size
    

즉 질문이

> “어떻게 더 정확한 모델을 만들까?”

에서

> **“어떻게 정확하면서도 실제 device에서 구동 가능한 모델을 만들까?”**

로 확장된다.

MobileNet은 이러한 **efficient CNN**을 목표로 등장한다.

---

# 56. 일반 Convolution의 문제

일반 convolution은 한 번의 연산에서

1. 공간 방향의 정보를 섞고
    
2. channel 방향의 정보도 섞는다.
    

예를 들어 input channel과 output channel이 모두 `C`, kernel이 3×3이라고 하면 연산량은 대략

`9C²HW`

가 된다.

Channel 수가 커질수록 `C²`에 비례하여 연산량이 크게 증가한다.

---

# 57. MobileNet 핵심 — Depthwise Separable Convolution

MobileNet의 핵심 아이디어는

> **공간 연산과 channel 연산을 분리한다.**

일반 convolution에서는 두 가지를 동시에 했다면 MobileNet에서는

1. Depthwise Convolution
    
2. Pointwise Convolution
    

으로 나눈다.

---

# 58. Depthwise Convolution

각 channel별로 독립적으로 3×3 convolution을 수행한다.

즉 서로 다른 channel을 섞지 않는다.

```text
Channel 1 → 3×3 Conv
Channel 2 → 3×3 Conv
Channel 3 → 3×3 Conv
...
```

따라서 이 단계에서는

> **각 channel 내부에서 공간적인 정보가 서로 섞인다.**

연산량:

`9CHW`

정도다.

---

# 59. Pointwise Convolution

Depthwise convolution 이후 1×1 convolution을 사용한다.

1×1 convolution에서는 같은 공간 위치의 여러 channel을 조합한다.

즉

> **공간은 그대로 두고 channel 사이의 정보를 섞는다.**

연산량:

`C²HW`

정도다.

따라서 두 연산을 합치면

`9CHW + C²HW`

가 된다.

---

# 60. 일반 Conv와 MobileNet 연산량 비교

일반 3×3 convolution:

`9C²HW`

Depthwise + Pointwise:

`9CHW + C²HW`

두 연산량의 비율을 비교하면 강의에서는

`9C / (9 + C)`

형태로 설명한다.

Channel `C`가 매우 커지면

`C >> 9`

이므로 이 값은 약 9에 수렴한다.

즉 조건에 따라

> **일반 convolution보다 연산량을 최대 약 9배 수준까지 줄일 수 있다.**

Parameter 역시 크게 감소한다.

---

# 61. MobileNet의 의미

MobileNet은

> **가볍고 빠른 CNN을 어떻게 설계할 것인가**

에 대한 효과적인 답을 제시했다.

이후에도

- mobile model
    
- embedded model
    
- edge AI
    
- efficient network
    

분야에서 연산 효율적인 architecture에 대한 연구가 계속 이어졌다.

---

# 62. CNN 발전사의 흐름

강의에서 정리한 CNN의 발전 흐름은 다음과 같다.

```text
AlexNet
   ↓
VGG
   ↓
GoogLeNet
   ↓
ResNet
   ↓
MobileNet
```

강의에서 집중적으로 설명한 모델은

- AlexNet
    
- VGG
    
- ResNet
    
- MobileNet
    

이며 GoogLeNet은 중간의 역사적 모델로 언급된다.

각 모델을 등장 목적 중심으로 보면 다음과 같다.

### AlexNet

**“일단 deep CNN이 실제로 강력하게 동작하도록 만들자.”**

### VGG

**“CNN을 더 규칙적이고 이해하기 쉬운 설계 철학으로 만들자.”**

### ResNet

**“Network를 훨씬 더 깊게 만들어 실제로 학습시키자.”**

### MobileNet

**“이제 실제 mobile/edge device에서도 사용할 수 있게 가볍게 만들자.”**

---

# 63. 강의에서 정리한 CNN의 기본 구조

전통적인 CNN은 대체로

```text
Convolution
    ↓
Activation
    ↓
Pooling
    ↓
반복
    ↓
Fully Connected Layer
```

의 형태를 가진다.

단, 현대적인 CNN에서는 pooling 대신 **strided convolution**을 사용하는 경우도 많다.

---

# 64. CNN에서 각 부분의 역할

## Convolution Layer

계층적인 feature template을 추출한다.

```text
Local template
      ↓
Blob / Part template
      ↓
Object template
      ↓
Image / Semantic template
```

Layer가 깊어지면서 receptive field가 커지고 더 넓은 문맥을 이해한다.

## Activation Function

Non-linearity를 추가해 여러 layer가 실제로 복잡한 함수를 표현할 수 있도록 한다.

## Pooling / Strided Convolution

Spatial resolution을 감소시킨다.

- computation 감소
    
- 더 깊은 network 구성에 도움
    

## Fully Connected Layer

최종적인 classification 역할을 담당한다.

---

# 65. 강의에서 다시 강조한 주요 개념

## Filter / Kernel

이미지의 local feature를 검출하는 학습 가능한 weight.

## Activation Map

Filter를 이미지 전체에 적용해서 얻은 출력 map.

## Receptive Field

특정 output이 원본 이미지에서 보고 있는 영역의 크기.

## Padding

경계를 추가하여 출력 해상도를 조절하는 방법.

## Stride

Filter가 한 번에 이동하는 pixel 수.

## Pooling

정해진 규칙으로 해상도를 축소하는 방법.

## Strided Convolution

Convolution 자체의 stride를 증가시켜 학습 가능한 방식으로 downsampling하는 방법.

## 1×1 Convolution

공간 해상도를 유지하면서 channel 방향의 정보를 조합하거나 channel 수를 조정하는 방법.

대표 활용:

- ResNet bottleneck의 channel reduction/expansion
    
- MobileNet의 pointwise convolution
    

---

# 66. 모델별 설계 철학 비교

|모델|해결하려는 문제|핵심 아이디어|결과|
|---|---|---|---|
|Linear FC|이미지를 class로 분류|클래스 대표 template|다양한 local variation 표현에 한계|
|Multi-layer FC|하나의 template 한계|nonlinear layer로 여러 template|다양한 형태 표현|
|CNN|이미지 공간 구조 활용|local convolution + hierarchical feature|지역→객체→semantic feature|
|AlexNet|Deep CNN의 실질적 성공|5 Conv + 3 FC, 큰 kernel/stride|CNN 성능의 가능성 증명|
|VGG|복잡한 설계의 규칙화|3×3 Conv를 깊게 반복|단순하고 확장 가능한 설계|
|ResNet|깊은 network의 optimization 문제|Residual/skip connection|100층 이상의 deep network|
|MobileNet|Mobile/edge 계산 비용|Depthwise + Pointwise Conv|대폭 감소한 연산량|

# 67. 계산 공식 모음

## Flatten

`H × W × C → HWC`

예:

`32 × 32 × 3 = 3072`

---

## Padding 없는 Stride 1 Convolution

`Output = Input - Kernel + 1`

---

## 일반 Convolution 출력 크기

`Output = (Input - Kernel + 2P) / S + 1`

- `P`: padding
    
- `S`: stride
    

---

## 출력 Channel

`Cout = Number of Filters`

---

## Convolution Parameter

`Cin × K × K × Cout + Cout(bias)`

---

## Activation Memory

`Hout × Wout × Cout × bytes per element`

float32라면 element당 4byte.

---

## Convolution Multiplication Cost

`Hout × Wout × Cout × Cin × K × K`

---

## VGG의 큰 Kernel 분해

5×5 Conv:

`25C²`

3×3 Conv × 2:

`18C²`

---

## MobileNet

일반 3×3 convolution:

`9C²HW`

Depthwise:

`9CHW`

Pointwise:

`C²HW`

합:

`9CHW + C²HW`

# 68. 강의 마지막 확인 문제에서 강조한 내용

### Q1. CNN 발전 순서

강의에서 제시한 흐름:

`AlexNet → VGG → GoogLeNet → ResNet → MobileNet`

### Q2. 다음 중 CNN과 관련 없는 설명

> “이미지의 모든 pixel을 연결하여 하나의 1차원 vector로 만들어 입력한다.”

이것은 CNN이 아니라 **Fully Connected 방식에서 이미지를 flatten하는 설명**이다.

### Q3. Pooling의 특징

Pooling은

- 공간 해상도를 줄이고
    
- 작은 위치 변화에 강건하게 만들 수 있지만
    
- **학습 가능한 parameter를 가지지 않는다.**
    

따라서 pooling에 학습 parameter가 있다는 설명은 잘못된 설명이다.

# 69. 이 강의의 전체 논리

이번 강의에서 가장 중요한 흐름을 연결하면 다음과 같다.

```text
이미지는 공간 구조를 가진다.
        ↓
FC는 이미지를 flatten하므로 공간 구조를 직접 활용하지 못한다.
        ↓
CNN은 작은 filter를 이미지 위에서 이동시키며
local feature를 추출한다.
        ↓
여러 convolution layer를 쌓으면
local → part → object → semantic 특징으로 발전한다.
        ↓
깊어질수록 receptive field도 넓어진다.
        ↓
하지만 깊은 network는 계산량과 학습 난도가 증가한다.
        ↓
Pooling / Stride로 공간 해상도를 줄인다.
        ↓
AlexNet:
Deep CNN이 실제로 뛰어난 성능을 낼 수 있음을 보여준다.
        ↓
VGG:
작은 3×3 filter를 규칙적으로 깊게 쌓는 설계 철학을 제시한다.
        ↓
ResNet:
Residual connection으로 매우 깊은 network를 학습할 수 있게 한다.
        ↓
MobileNet:
공간 연산과 channel 연산을 분리하여
mobile/edge에서 사용할 수 있을 정도로 계산량을 줄인다.
```

따라서 이 강의를 관통하는 핵심 질문은 단순히 **“CNN이 무엇인가?”**가 아니다.

보다 정확하게는

> **이미지의 공간적인 특성을 어떻게 neural network 구조에 반영하고, 더 많은 특징을 추출하기 위해 network를 깊게 만들면서도 학습 가능성과 연산 효율성을 어떻게 유지할 것인가?**

이며, AlexNet → VGG → ResNet → MobileNet의 발전은 이 질문에 대한 서로 다른 시대의 답이라고 볼 수 있다.
