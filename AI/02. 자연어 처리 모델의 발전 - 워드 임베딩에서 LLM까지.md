

> [!info] 이 문서를 읽는 방법
>
> - 본문은 자연어 처리 모델이 해결하려 한 문제와 발전 과정을 하나의 흐름으로 설명한다.
> - `질문` 콜아웃에는 본문을 읽다가 헷갈리기 쉬운 원리와 추가 설명을 담는다.
> - 수식·세부 비교·예외는 전체 흐름을 이해한 뒤 확인할 수 있도록 본문과 분리한다.

컴퓨터가 자연어를 처리하려면 먼저 단어를 계산 가능한 수치로 바꾸어야 한다. 그러나 단어를 숫자로 구별하는 것만으로는 의미의 유사성을 알 수 없고, 단어의 의미를 표현하더라도 문장 안의 순서와 문맥까지 이해할 수 있는 것은 아니다. 자연어 처리 모델의 발전은 이처럼 한 문제를 해결한 뒤 드러난 다음 문제를 해결하는 과정이었다.

이 문서는 단어를 벡터로 표현하는 방법에서 출발한다. 이어서 RNN과 LSTM이 순서와 기억을 어떻게 다루었는지, Seq2Seq와 Attention이 문장을 생성하고 필요한 입력을 선택적으로 참조하는 구조를 어떻게 만들었는지 살펴본다. 마지막으로 Self-Attention과 Transformer가 순환 구조를 대체하고, 대규모 사전학습과 결합해 BERT·T5·GPT 및 In-Context Learning으로 확장된 흐름을 따라간다.

$$
\text{One-hot·Embedding}
\rightarrow \text{RNN·LSTM}
\rightarrow \text{Seq2Seq·Attention}
\rightarrow \text{Self-Attention·Transformer}
\rightarrow \text{BERT·T5·GPT}
\rightarrow \text{In-Context Learning}
$$

이 흐름은 모든 모델이 역사적으로 바로 앞 모델을 대체했다는 뜻은 아니다. 워드 임베딩과 RNN처럼 서로 다른 문제를 해결하는 기술도 있다. 여기서는 자연어 처리에 필요한 능력이 **단어 표현 → 순서와 기억 → 시퀀스 변환 → 선택적 참조 → 전역 상호작용 → 대규모 사전학습과 문맥 기반 수행**으로 확장되는 과정을 중심으로 연결한다.

## 1. 단어의 의미에서 문장의 문맥으로 — 워드 임베딩, RNN, LSTM

자연어 처리의 출발점은 언어를 수치로 표현하는 것이다. 초기의 원-핫 인코딩은 단어를 서로 구별하는 데에는 충분했지만, 단어 사이의 의미 관계를 표현하지 못했다. 분포가설과 워드 임베딩은 이 문제를 해결하여 비슷한 문맥에서 쓰이는 단어가 비슷한 벡터를 갖게 했다.

그러나 개별 단어의 의미를 벡터에 담았다고 해서 문장 전체를 이해할 수 있는 것은 아니다. 문장은 단어가 놓인 순서에 따라 의미가 달라지고, 앞부분의 정보가 한참 뒤의 해석에 영향을 주기도 한다. 따라서 단어의 표현을 넘어 시간에 따라 문맥을 전달하는 구조가 필요해졌고, 이를 위해 RNN이 사용되었다. RNN은 순서를 처리했지만 먼 과거의 정보를 학습하기 어려웠으며, LSTM은 정보 전달 경로와 게이트를 추가해 이 한계를 완화했다.

> [!info] 학습 목표
> 
> - 단어를 숫자로 표현하는 기본 아이디어들을 이해한다
> - 언어에서 '순서(문맥)'의 중요성을 설명할 수 있다
> - RNN의 기본 구조와 역할을 이해한다
> - LSTM의 핵심 아이디어를 설명할 수 있다

> [!question] 이 단원에서 답할 질문
> 
> 1. 언어를 어떻게 숫자로 표현할까? — One-hot encoding, word embedding 등 기본 아이디어
> 2. 언어에서 '순서(문맥)'는 왜 중요하고 어떻게 다뤄야 할까? — 단어 순서와 의미의 연결성
> 3. 순환 신경망(RNNs, LSTMs 등)은 어떻게 동작할까? — 기본 구조와 역할 / 장기 의존성 문제와 LSTM의 핵심 아이디어

### 1.1 단어를 숫자로 표현하기: 워드 임베딩

신경망은 문자열 자체를 계산할 수 없으므로 단어를 벡터로 바꾸어야 한다. 가장 단순한 방법은 각 단어에 고유한 자리를 하나씩 배정하는 것이다. 원-핫 인코딩은 이 방식으로 단어를 명확하게 구별했지만, 단어가 가진 의미까지 표현하지는 못했다.

#### 원-핫 인코딩 (One-hot Encoding)

원-핫 인코딩은 각 단어를 서로 구별되는 기호로 취급하여 **한 원소만 1이고 나머지는 0**인 벡터로 표현한다. 단어마다 하나의 자리가 필요하므로 벡터 차원은 단어 사전의 크기와 같다. 예를 들어 음성 데이터에서는 약 2만, PTB에서는 약 5만, Google 1T 코퍼스에서는 약 1,300만 차원까지 커질 수 있다.

#### 원-핫 인코딩의 문제점

원-핫 인코딩의 첫 번째 문제는 **유사도를 측정할 수 없다는 것**이다. 서로 다른 단어는 항상 벡터의 다른 위치에 1이 있으므로 두 벡터의 내적은 0이 된다. 그 결과 "핸드폰"과 "스마트폰"처럼 의미가 비슷한 단어도 계산상 완전히 무관한 대상으로 처리된다.

> [!question]+ 벡터의 내적이란? 왜 내적으로 의미 유사도를 판단하는가
> 
> **내적(dot product)**은 같은 위치의 원소를 곱해 모두 더한 값이다.
>
> $$
> \mathbf a\cdot\mathbf b=a_1b_1+a_2b_2+\cdots+a_nb_n
> =\lVert\mathbf a\rVert\lVert\mathbf b\rVert\cos\theta
> $$
>
> 벡터의 크기가 같거나 정규화되어 있다면 내적은 두 벡터 방향의 유사성을 반영한다.
> 
> - 같은 방향(0°) → $\cos\theta=1$ → 내적 최대(양수)
> - 직각(90°) → $\cos\theta=0$ → 내적 = **0**
> - 반대 방향(180°) → $\cos\theta=-1$ → 내적 음수
> 
> 단어 벡터가 의미가 비슷할수록 비슷한 방향을 갖도록 학습된다면, 내적이나 코사인 유사도로 의미적 관련성을 측정할 수 있다.
> 
> - 의미 비슷한 단어("핸드폰"-"스마트폰") → 비슷한 방향 → 내적 큼(양수)
> - 관련 없는 단어 → 다른 방향 → 내적 작거나 0
> 
> 원-핫 벡터는 서로 다른 인덱스에만 1을 가지므로 서로 직교한다. 따라서 서로 다른 단어의 내적은 의미와 관계없이 항상 0이다.
> 
> → 다음에 다룰 **워드 임베딩**은, 직교하게 고정된 원-핫 벡터 대신 **학습을 통해 의미가 비슷한 단어일수록 벡터가 비슷한 방향을 가리키도록** 만드는 방법일 것으로 예상 가능

두 번째 문제는 **차원의 저주(Curse of Dimensionality)**다. 사전이 커질수록 벡터 차원도 함께 커지고, 값의 대부분이 0인 희소(sparse) 벡터가 되어 많은 메모리를 사용한다. 무엇보다 원-핫 벡터에는 의미적 정보가 없어서 "은행"과 "금융"처럼 가까운 개념도 관련 없는 벡터로 취급된다. 단어를 구별하는 것을 넘어 의미 관계까지 계산하려면 새로운 표현 방법이 필요했다.

#### 분포가설(Distributional Hypothesis)

이 문제를 해결하는 핵심 발상은 **비슷한 문맥에 등장하는 단어는 비슷한 의미를 갖는다**는 분포가설(Distributional Hypothesis)이다. 예를 들어 "은행 대출 규제", "은행 상담 서비스"에서 "은행" 주변에 등장하는 "대출", "규제", "상담" 같은 단어를 관찰하면 은행의 의미를 어느 정도 유추할 수 있다. 분포가설은 단어의 의미를 미리 정의하는 대신 실제 사용 문맥에서 학습할 수 있게 했으며, 현대 통계적 자연어 처리의 핵심 아이디어가 되었다.

#### 워드 임베딩이란

워드 임베딩은 분포가설을 이용해 단어를 **밀집되고 연속적인 분산 벡터**로 표현한다. 원-핫 벡터와 달리 여러 차원에 의미 정보가 분산되어 있으며, "은행"과 "금융"처럼 비슷한 단어는 벡터 공간에서도 가까운 위치를 갖도록 학습된다.

벡터의 각 값을 사람이 직접 정하는 것은 아니다. 모델이 "은행"으로부터 "정부", "위기", "규제", "돈" 같은 주변 단어를 예측하는 문제를 풀면서, 예측에 유용한 방향으로 벡터 값을 조정한다. 그 결과 단어를 구별하는 표현이 문맥과 의미 관계를 반영하는 표현으로 바뀐다.

#### Word2Vec

2013년에 발표된 Word2Vec은 이 발상을 구현한 대표적인 워드 임베딩 기법이다. 단어와 주변 단어의 관계를 예측하는 과제를 통해 단어 벡터를 학습하며, 예측 방향에 따라 Skip-gram과 CBOW라는 두 가지 알고리즘으로 나뉜다.

#### Skip-gram (SG)

Skip-gram은 **중심 단어로 주변 단어를 예측**한다. 중심 단어의 앞뒤에서 몇 개의 단어를 문맥으로 볼지는 윈도우 크기(window size)로 정한다. 예를 들어 윈도우가 2일 때 `... turning into banking crises as ...`에서 중심 단어가 `banking`이라면, `turning`, `into`, `crises`, `as`가 주변 단어가 된다. 모델은 중심 단어로부터 $P(w_{t-1}\mid w_t)$, $P(w_{t+1}\mid w_t)$와 같은 주변 단어의 확률을 각각 예측한다.

#### CBOW (Continuous Bag of Words)

CBOW는 반대로 **여러 주변 단어를 이용해 중심 단어를 예측**한다. Skip-gram이 하나의 중심 단어에서 여러 문맥 단어로 뻗어 나간다면, CBOW는 문맥 단어들의 정보를 하나로 모아 가운데 단어를 맞힌다.

> [!question]+ CBOW와 Skip-gram의 구조 차이 — 다중입력/다중출력 신경망과의 연결
> 
> - **CBOW**: 입력이 $w(t-2),w(t-1),w(t+1),w(t+2)$ 여러 개 → 하나로 합쳐서(SUM) → 출력은 $w(t)$ 하나 (다중입력·단일출력)
> - **Skip-gram**: 입력이 $w(t)$ 하나 → 출력이 $w(t-2)\sim w(t+2)$ 여러 개 (단일입력·다중출력)
> - 앞서 신경망 단원(6.1.4)에서 배운 "다중 입력/출력 신경망" 구조가 그대로 적용된 사례

#### Skip-gram vs CBOW 비교

||장점|한계|
|---|---|---|
|Skip-gram|적은 데이터에도 잘 동작, 희귀 단어·구 표현에 강함|학습 속도 느림|
|CBOW|학습 속도 빠름, 자주 나오는 단어에 강함|희귀 단어 표현에 약함|

> [!question]+ 왜 이런 장단점 차이가 나는가 — "한 번 등장할 때 학습 신호를 몇 번 뽑아내는가"의 차이
> 
> **예시**: "챗봇"이 코퍼스에 한 번 등장 — "인공지능 기반 **챗봇**이 은행 상담 서비스에 도입되었다" (윈도우=2, 주변 단어={인공지능, 기반, 은행, 상담})
> 
> **학습 샘플 개수**
> 
> - CBOW: ${인공지능,기반,은행,상담}\to챗봇$ → 이 문장에서 학습 샘플 **1개**
> - Skip-gram: $챗봇\to인공지능$, $챗봇\to기반$, $챗봇\to은행$, $챗봇\to상담$ → 학습 샘플 **4개**
> 
> **희귀 단어에 대한 학습 신호 차이**
> 
> - CBOW: 여러 문맥 단어를 하나의 표현으로 합쳐 중심 단어를 한 번 예측하므로, 개별 문맥 단어와 중심 단어의 관계는 직접 분리되지 않는다.
> - Skip-gram: 중심 단어와 각 문맥 단어의 쌍을 별도 학습 샘플로 사용하므로, 한 번 등장해도 여러 번의 예측 신호를 얻는다.
> 
> 희귀 단어는 등장 횟수가 적으므로 한 번의 등장으로 여러 단어 쌍을 학습하는 Skip-gram이 상대적으로 유리하다. CBOW는 문맥을 합쳐 한 번 예측하므로 학습은 빠르지만 희귀 단어의 세부 관계를 학습할 기회가 적다.
> 
> **학습 속도 차이의 원인**: 순수한 계산량 문제. CBOW는 윈도우 하나당 예측 **1번**, Skip-gram은 윈도우 크기만큼(예: **4번**) 예측 → 같은 데이터라도 Skip-gram이 처리해야 할 학습 샘플(순전파+역전파) 수가 몇 배 많아 **학습이 느림**

### 1.2 언어는 순서가 중요하다: 순차적 데이터의 특징

워드 임베딩은 단어의 의미를 수치 공간에 담았지만, 각 단어가 문장 안에서 어떤 순서로 사용되었는지는 별도의 문제로 남았다. "나는 너를 사랑해"와 "너는 나를 사랑해"는 같은 단어를 사용하지만 순서가 달라 의미도 달라진다. 자연어를 문장 단위로 처리하려면 개별 단어의 벡터뿐 아니라 단어가 이어지는 순서와 그 사이의 관계까지 모델링해야 한다.

#### 순차적 데이터란

순차적 데이터는 데이터가 입력되는 **순서**와 그 순서로 형성되는 데이터 사이의 관계가 중요한 데이터다. 오디오는 파형 조각이 시간 순서대로 이어지고, 텍스트는 `Natural-Language-Process`처럼 단어가 특정 순서로 나열되며, 비디오는 프레임이 시간에 따라 이어진다. 구성 요소가 같더라도 순서가 달라지면 전체 의미가 달라질 수 있다.

> [!question]+ "시퀀스(Sequence)"란 정확히 무엇인가
> 
> **시퀀스는 순서가 정해진 요소들의 나열**이다. 원소의 포함 여부만 중요한 집합(set)과 달리, 각 요소의 위치가 의미에 영향을 준다.
> 
> 예를 들어 "나는 너를 사랑해"는 `[나는, 너를, 사랑해]`라는 단어 시퀀스다. 이후의 입력 시퀀스, 출력 시퀀스, 시퀀스 길이도 모두 이 정의를 따른다.

#### 순차적 데이터의 3가지 특징

순차적 데이터에는 세 가지 특징이 있다. 첫째, 순서가 바뀌면 의미가 달라진다. 둘째, 멀리 떨어진 과거의 정보가 현재나 미래에 영향을 주는 **장기 의존성(Long-term Dependency)**이 존재한다. 예를 들어 "여러 개의 문 중 **파란** 문을 열고 안으로 들어가면, 너는 (?)를 찾게 될 거야"를 해석하려면 문장 앞부분의 "파란"이라는 정보를 끝까지 유지해야 한다. 셋째, 문장마다 단어 수가 다르듯이 입력의 길이가 일정하지 않은 **가변 길이(Variable Length)**를 가진다.

#### 고정 입력 모델의 한계와 Sequential Model의 필요성

선형 회귀와 일반적인 MLP는 고정된 크기의 입력을 한 번에 처리하며, 순서와 가변 길이를 구조적으로 모델링하지 않는다. 단어를 위치별로 고정해 넣거나 위치 정보를 추가할 수는 있지만, 문장 길이가 달라질 때마다 별도 처리가 필요하고 같은 패턴을 서로 다른 위치에 재사용하기도 어렵다. 따라서 입력을 순서대로 처리하면서 이전까지의 상태를 다음 계산에 재사용하는 **Sequential Model**이 필요해졌다. RNN과 LSTM은 순환 구조로 이를 해결하고, 뒤에서 다룰 Transformer는 순환 없이 전체 시퀀스의 관계를 계산한다.

> [!question]+ 왜 기존 모델(MLP)로는 "순서"를 처리할 수 없는가
> 
> 기본 MLP에 순차 데이터를 입력하는 대표적인 방법은 다음 두 가지이며, 각각 한계가 있다.
> 
> **방법 1 — 단어 벡터의 합이나 평균 사용**: 덧셈은 순서에 영향을 받지 않으므로 동일한 단어로 구성된 두 문장은 같은 표현이 된다. 따라서 단어 순서에 따른 의미 차이를 구별할 수 없다.
> 
> **방법 2 — 각 단어를 순서대로 고정된 자리에 배치** $x=[\text{나는},\text{너를},\text{사랑해}]$처럼 위치별로 고정해서 넣으면 순서는 구별되지만 새로운 문제 발생:
> 
> - **가변 길이**: MLP는 입력 크기가 고정되어야 하므로 최대 길이를 정하고 짧은 문장을 padding하는 등의 별도 처리가 필요하다.
> - **위치마다 완전히 다른 파라미터를 씀**: 1번째 자리와 2번째 자리를 처리하는 가중치가 서로 다른 별개의 파라미터라, 같은 단어("사랑해")가 문장마다 다른 위치에 오면 배운 패턴이 재사용되지 않음 — "이 단어가 뭔지"를 위치와 무관하게 일반화해서 이해하지 못함
> 
> **핵심 한계**: 기본 MLP에는 이전 입력에서 계산한 상태를 다음 입력 처리에 재사용하는 순환 구조가 없다. 따라서 순차적 상태 전달을 위해서는 입력 길이와 위치를 미리 고정하거나 별도의 구조를 설계해야 한다.
> 
> RNN은 같은 가중치를 모든 시점에서 재사용하고 이전 hidden state를 다음 시점으로 전달하여 이 문제를 구조적으로 해결한다.

### 1.3 RNN: 문맥을 기억하는 신경망

순차적 데이터를 처리하려면 현재 단어만 보는 것이 아니라 앞에서 어떤 단어들이 입력되었는지도 함께 반영해야 한다. RNN은 이전 시점의 계산 결과를 현재 시점으로 전달하는 순환 구조를 도입하여 이 요구를 구현했다.

#### 전통적인 신경망의 한계 (재확인)

전통적인 MLP와 CNN은 일반적으로 고정된 길이의 입력을 받아 하나의 출력을 만드는 데 적합하다. 예를 들어 MNIST 이미지 분류는 784개의 픽셀로 이루어진 고정 입력 하나를 받아 숫자 분류 결과 하나를 내는 **one-to-one** 구조다. 반면 문장은 길이가 일정하지 않고 앞선 입력이 뒤의 해석에 영향을 주므로, 같은 방식만으로 처리하기 어렵다.

#### RNN이란

RNN은 입력을 한 시점씩 처리하면서 이전 시점의 정보를 다음 시점으로 넘긴다. 같은 계산을 반복하므로 가변 길이의 입력을 받을 수 있고, 이전 입력이 남긴 상태를 현재 계산에 반영할 수 있다. 감성 분석에서는 길이가 서로 다른 문장을 단어별로 입력받은 뒤 마지막에 긍정 또는 부정 하나를 출력하는 **many-to-one** 구조로 사용할 수 있다.

#### RNN 아키텍처

RNN에서 문맥을 전달하는 핵심은 **hidden state** $h_t$다. $h_t$는 이전 시점까지 처리한 정보를 담고 있으며, 현재 입력 $x_t$와 함께 다음 hidden state를 만드는 데 사용된다.

$$
h_t=f_W(h_{t-1},x_t)
$$

이를 구체적으로 나타내면 $h_t=\tanh(W_{hh}h_{t-1}+W_{xh}x_t)$이며, 각 시점의 출력은 $y_t=W_{hy}h_t$로 계산할 수 있다. 학습할 때는 각 시점의 손실 $L_1,L_2,\ldots,L_T$를 더해 전체 손실을 구한다.

중요한 점은 문장이 길어져도 새로운 셀이 계속 추가되는 것이 아니라, **동일한 가중치 $W$를 모든 시점에서 재사용한다는 것**이다. 따라서 시점 수가 늘어나도 파라미터 수는 그대로이며, 서로 다른 위치에 나타난 같은 패턴을 같은 방식으로 처리할 수 있다.

> [!question]+ 활성화 함수(tanh)가 필요한 이유, 그리고 왜 하필 tanh인가
> 
> **왜 활성화 함수가 필요한가 — 6.1.2 원리가 RNN에도 그대로 적용** 활성화 함수 없이 $h_t=W_{hh}h_{t-1}+W_{xh}x_t$만 반복하면 여러 시점의 연산도 결국 선형변환으로 합성된다. 따라서 문법 구조, 반전, 조합적 의미와 같은 비선형 문맥 패턴을 표현할 수 없다.
> 
> **RNN에서의 추가 역할**: 동일한 순환 가중치가 시점마다 반복 적용되므로 hidden state가 불안정해질 수 있다. tanh는 출력을 $[-1,1]$ 범위로 제한해 순전파에서 hidden state 값이 무한히 커지는 현상을 억제한다. 다만 역전파의 기울기 소실·폭발까지 해결하는 것은 아니다.
> 
> **왜 하필 tanh인가**
> 
> - sigmoid(0~1): 출력이 항상 양수라 0을 중심으로 대칭이 아님 → 기울기 흐름이 한쪽으로 치우쳐 학습 비효율적
> - **tanh(-1~1)**: 0을 중심으로 대칭 → 정보를 "강화"하는 것과 "약화"하는 것을 둘 다 자연스럽게 표현 가능
> - ReLU: 양수 구간의 출력에 상한이 없어 반복 순환 과정에서 hidden state가 커질 수 있음
>
> 따라서 전통적인 RNN에서는 tanh를 사용해 비선형성을 추가하면서 hidden state의 값 범위를 제한한다.

#### RNN의 특징

RNN은 한 번에 하나의 요소를 처리하고 hidden state를 다음 시점으로 전달한다. 이를 시간축으로 펼치면 여러 셀이 연결된 것처럼 보이지만, 실제로는 서로 다른 레이어가 아니라 **같은 파라미터를 공유하는 셀 연산이 시점마다 반복된 계산 그래프**다. 이 구조 덕분에 가변 길이의 데이터를 처리할 수 있으며, 현재 출력이 과거 입력의 영향을 받는다. 이것이 각 입력을 독립적으로 처리하는 feedforward 신경망과의 결정적인 차이다.

> [!question]+ RNN "셀(Cell)"이란 정확히 무엇이고, 역전파는 어떻게 이루어지는가
> 
> **셀의 구조**: RNN 셀은 현재 입력 $x_t$와 이전 hidden state $h_{t-1}$로 새로운 hidden state $h_t$를 계산하는 반복 단위이다. 필요하면 $h_t$로 출력 $y_t$도 계산한다. 셀은 레이어와 동일한 용어가 아니며, 하나의 RNN 레이어가 같은 셀 연산을 모든 시점에 반복 적용한다고 이해할 수 있다.
> 
> **언롤링 = 같은 셀의 반복 실행**: 언롤링은 셀이 여러 개 새로 생기는 게 아니라, **가중치가 동일한 셀 하나가 시점 수만큼 반복 실행**된 것을 시간 축으로 펼쳐 그린 것이다. `for`문으로 같은 함수를 seq_len번 호출하는 것과 같은 구조.
> 
> **역전파(BPTT, Backpropagation Through Time)**: 가중치는 모든 시점에 공유되지만 언롤링된 계산 그래프에는 셀 연산이 $T$번 나타난다. 각 시점에서 공유 파라미터에 대한 기울기를 계산하고 이를 합산하여 최종 기울기를 구한다.
> 
> $$\frac{\partial L}{\partial W_h}=\sum_t \frac{\partial L}{\partial W_h}\bigg|_t$$
> 
> → 이는 아래 "기울기 소실" 설명(매 시점마다 작은 값이 반복 **곱해져서** 기울기 값 자체가 작아짐)과는 다른 지점을 짚는 내용이다: 기울기 소실 = "그 기울기 값이 왜 작아지는가", 위 합산 = "공유 가중치의 최종 기울기가 어떻게 만들어지는가" — 서로 보완적인 설명

#### RNN의 한계: 기울기 소실(Vanishing Gradient) 문제

RNN은 순서를 처리했지만, 정보가 여러 시점을 통과할수록 먼 과거의 영향을 학습하기 어려웠다. 역전파가 시간축을 거슬러 진행될 때 1보다 작은 미분값이 반복해서 곱해지면, 과거 시점으로 전달되는 기울기가 0에 가까워진다. 이를 **기울기 소실(Vanishing Gradient)**이라고 한다.

기울기가 작아지면 현재의 손실을 줄이기 위해 과거 시점의 파라미터를 어떻게 바꿔야 하는지에 대한 신호도 약해진다. 그 결과 RNN은 가까운 단어 사이의 단기 의존성은 포착할 수 있지만, 문장 앞부분의 정보가 뒤쪽 예측에 영향을 주는 장기 의존성은 충분히 학습하지 못한다. 순서를 전달하는 데 성공한 구조가 이제는 **어떻게 정보를 오래 보존할 것인가**라는 다음 문제를 드러낸 것이다.

> [!question]+ 왜 "작은 기울기"가 장기 의존성을 학습 못하게 만드는가
> 
> 기울기는 6.3(역전파)에서 배웠듯 **"이 파라미터를 조금 바꾸면 손실이 얼마나 바뀌는가"**를 알려주는 신호. 이 신호가 0에 가까우면, 학습 알고리즘은 "이 부분을 바꿔도 결과에 아무 영향 없다"고 착각하게 됨
> 
> **장기 의존성 예시로 구체화**: "**파란** 문을 열고 들어가면, 너는 (?)를 찾게 될거야"를 학습한다는 건, "1번째 단어(파란)의 정보가 마지막 시점(빈칸) 예측에 영향을 주도록 파라미터가 조정된다"는 뜻. 그런데 역전파로 그 조정 신호(기울기)를 뒤에서 앞으로 전달할 때, 매 시점을 거칠 때마다 작은 값(1보다 작은 tanh 미분값 × $W_{hh}$)이 반복해서 곱해짐 → 문장이 길수록 곱셈이 여러 번 반복되어, "1번째 단어가 마지막 예측에 미치는 영향"을 나타내는 기울기가 사실상 0으로 소멸
> 
> **기울기가 작으면 왜 장기 의존성을 학습하기 어려운가**: 앞 시점의 파라미터가 현재 손실에 미치는 영향이 거의 0으로 계산되면, 경사하강법이 해당 파라미터를 충분히 갱신하지 못한다. 그 결과 먼 과거 정보를 유지하는 방향으로 학습하기 어렵다.
> 
> 결과적으로 먼 과거 입력과 현재 손실 사이의 기울기가 매우 작아지면, 경사하강법은 장기 의존성을 반영하도록 파라미터를 충분히 조정하지 못한다. 이 한계를 완화하기 위해 LSTM이 등장했다.

### 1.4 LSTM: 더 오래 기억하는 신경망

RNN의 가장 큰 문제는 **장기 의존성(Long-term dependency)**을 학습하기 어렵다는 것이다.

RNN에서는 과거의 정보가 현재까지 전달되기 위해 매 시점마다 hidden state를 거치며, 역전파에서도 여러 시점의 미분값이 반복해서 곱해진다. 이 과정에서 기울기가 점점 작아져 **기울기 소실(Vanishing Gradient)**이 발생하고, 결국 아주 오래전 정보가 현재의 예측에 영향을 주도록 학습하기 어려워진다.

LSTM(Long Short-Term Memory)은 이러한 문제를 완화하기 위해 **정보를 전달하는 경로를 별도로 만들고, 어떤 정보를 버리고·저장하고·출력할지를 게이트로 조절하는 RNN 구조**이다. 모든 정보를 매 시점 완전히 새로 계산하는 대신, 오래 보존할 정보가 비교적 직접적으로 이어질 수 있는 통로를 제공한다.

### 1.4.1 LSTM 전체 구조

LSTM을 이해하는 가장 중요한 핵심은 **상태(state)를 두 개로 분리했다는 것**이다.

**hidden state $h_t$**는 현재 시점에서 외부로 드러나는 표현으로, 다음 시점의 계산과 현재 출력에 사용된다. **cell state $C_t$**는 장기적으로 보존할 정보를 전달하는 별도의 메모리 경로다.

RNN은 하나의 hidden state를 이용해 정보를 계속 전달하지만, LSTM은 **장기 기억용 통로(cell state)**와 **현재 출력용 상태(hidden state)**를 분리한다.

> [!question]+ RNN과 LSTM의 가장 중요한 차이는 무엇인가?
> 
> RNN:  
> $$h_t=\tanh(W_{hh}h_{t-1}+W_{xh}x_t)$$
> 
> 하나의 hidden state 안에서 이전 정보와 현재 정보를 계속 섞어 전달한다.
> 
> LSTM:
> 
> - hidden state $h_t$
>     
> - cell state $C_t$
>     
> 
> 두 상태를 분리하여 관리하고, **게이트를 이용해 각 정보를 얼마나 유지할지 결정한다.**
> 
> → 즉, LSTM의 핵심은 단순히 "기억을 더 많이 하는 RNN"이 아니라,  
> **"기억을 전달하는 통로와 현재 출력을 분리하고, 그 흐름을 학습 가능한 게이트로 조절하는 구조"**이다.

#### Cell state가 장기 기억에 유리한 이유

LSTM의 cell state는 구조적으로 매우 특징적인 경로를 가진다.

그림에서 cell state는 보통 위쪽의 **긴 수평선**으로 표현된다.

$$  
C_{t-1}  
\longrightarrow  
C_t  
$$

이 경로에서는 매 시점마다 hidden state처럼 **tanh를 거쳐 완전히 새로운 상태로 변환하는 것이 아니라**, 주로 **element-wise 곱셈과 덧셈**을 통해 정보를 전달한다.

즉,

$$ C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t $$

와 같이 이전 cell state를 그대로 이어받으면서 필요한 정보만 조절한다.

> [!question]+ 이것이 왜 기울기 소실 완화에 도움이 되는가
> 
> RNN에서는 정보가 시점을 지날 때마다 반복적으로 비선형 변환을 거치기 때문에 역전파에서도 미분값이 계속 곱해진다.
> 
> 반면 LSTM의 cell state에는 **정보를 비교적 직접적으로 전달할 수 있는 경로**가 존재한다.
> 
> 특히 cell state 업데이트에서
> 
> $$C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$$
> 
> 처럼 **이전 상태를 곱하고 새로운 정보를 더하는(additive) 구조**를 사용한다.
> 
> 따라서 필요한 정보에 대해 gradient가 장거리로 전달될 수 있는 통로가 만들어진다.
> 
> → **LSTM이 기울기 소실 문제를 완전히 제거한다는 뜻은 아니지만, RNN보다 장기 의존성을 학습하기 훨씬 유리한 구조를 제공한다.**

---

### 1.4.2 LSTM의 세 가지 게이트

LSTM은 cell state를 아무렇게나 바꾸지 않는다.

현재 입력 $x_t$와 이전 hidden state $h_{t-1}$를 참고하여 **세 개의 게이트(gate)**를 계산하고, 이를 이용해 정보의 흐름을 조절한다.

Forget gate는 기존 정보 중 무엇을 얼마나 유지할지 결정하고, Input gate는 새로운 정보 중 무엇을 얼마나 저장할지 결정한다. 마지막으로 Output gate는 저장된 정보 중 현재 시점의 hidden state로 무엇을 내보낼지 선택한다.

세 게이트는 모두 **sigmoid 함수 $\sigma$**를 사용한다.

$$  
\sigma(x)\in(0,1)  
$$

sigmoid의 출력이 0에 가까우면 해당 정보를 차단하고, 1에 가까우면 거의 그대로 통과시킨다. 중간 값은 정보의 일부만 반영한다.

게이트 값은 각 차원의 정보를 얼마나 통과시킬지 정하는 **학습 가능한 조절 계수**이다.

이 값은 고정되어 있지 않으며, 매 시점의 입력에 따라 달라진다.

각 시점마다

$$  
[h_{t-1},x_t]  
$$

를 바탕으로 새롭게 계산된다.

따라서 LSTM의 게이트는 입력 문맥에 따라 매 시점 새로 계산되는 **동적 게이트(dynamic gate)**이다.

---

### 1.4.3 Forget gate — 이전 기억 중 무엇을 버릴까?

Forget gate는 이전 cell state $C_{t-1}$의 각 정보를 **얼마나 유지할지** 결정한다.

$$  
f_t=\sigma(W_f[h_{t-1},x_t]+b_f)  
$$

여기서

$$  
[h_{t-1},x_t]  
$$

는 이전 hidden state와 현재 입력을 **concatenate(이어붙인 것)**이다.

이를 선형변환한 뒤 sigmoid에 넣으면 각 차원마다 $0\sim1$ 사이의 값이 나온다.

예를 들어

$$  
f_t=
[1.0,\;0.1,\;0.7]
$$

라면,

- 첫 번째 정보 → 거의 그대로 유지
    
- 두 번째 정보 → 거의 제거
    
- 세 번째 정보 → 일부 유지
    

라는 의미가 된다.

> [!question]+ Forget gate가 실제로 정보를 버리는 것은 언제인가?
> 
> 주의할 점은 **forget gate의 수식 자체가 정보를 버리는 연산은 아니라는 것**이다.
> 
> $$f_t=\sigma(W_f[h_{t-1},x_t]+b_f)$$
> 
> 이 단계에서는 단지 **"얼마나 유지할 것인가?"라는 비율을 계산**한다.
> 
> 실제로 이전 정보를 제거하는 것은 다음과 같은 **element-wise 곱**에서 일어난다.
> 
> $$f_t\odot C_{t-1}$$
> 
> 즉,
> 
> **Forget gate = 유지 비율 계산**
> 
> **$f_t\odot C_{t-1}$ = 이전 정보에 유지 비율을 적용하는 연산**
> 
> 으로 구분하면 된다.

---

### 1.4.4 Input gate — 새로운 정보 중 무엇을 저장할까?

새로운 정보를 cell state에 추가할 때는 두 가지를 계산한다.

#### ① Input gate

$$  
i_t=\sigma(W_i[h_{t-1},x_t]+b_i)  
$$

Input gate는 **새로운 정보를 얼마나 반영할지** 결정한다.

즉, candidate 정보의 각 차원을 cell state에 얼마나 반영할지 나타낸다.

#### ② Candidate cell state

$$
\tilde{C}_t=\tanh(W_C[h_{t-1},x_t]+b_C)
$$

$\tilde{C}_t$는 실제로 cell state에 **새롭게 추가할 수 있는 후보 정보(candidate)**이다.

즉,

- $i_t$ → **얼마나 넣을 것인가?**
    
- $\tilde{C}_t$ → **무엇을 넣을 것인가?**
    

이다.

> [!question]+ Input gate와 candidate의 차이
>
> - $i_t$: candidate 정보의 각 차원을 얼마나 반영할지 정하는 비율
> - $\tilde C_t$: 현재 입력과 이전 hidden state로 만든 새로운 후보 정보
>
> 두 벡터를 원소별로 곱해야 실제 추가할 정보가 결정된다.
> 
> 아직 두 값은 계산만 된 상태이고, 실제 반영은 다음 cell state 업데이트에서 이루어진다.
> 
> $$i_t\odot\tilde{C}_t$$

---

### 1.4.5 Cell state 업데이트 — 기억을 실제로 갱신한다

앞에서 계산한 Forget gate와 Input gate의 결과가 여기서 실제로 합쳐진다.

$$ C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t $$

이 식은 LSTM의 핵심 수식 중 하나이다.

#### ① 이전 기억에서 유지할 부분

$$  
f_t\odot C_{t-1}
$$

Forget gate를 이용하여 기존 cell state 중 필요한 정보만 남긴다.

- $f_t\approx1$ → 해당 정보 유지
    
- $f_t\approx0$ → 해당 정보 제거
    

#### ② 새로운 기억에서 추가할 부분

$$  
i_t\odot\tilde{C}_t
$$

새로운 정보 $\tilde{C}_t$ 중 Input gate가 허용한 만큼만 cell state에 추가한다.

#### ③ 두 정보를 더해서 새로운 기억 완성

$$ C_t = \underbrace{f_t \odot C_{t-1}}_{\text{기존 기억}} + \underbrace{i_t \odot \tilde{C}_t}_{\text{새로운 기억}} $$

즉, cell state는 다음 순서로 변한다.

$$
C_{t-1}
\xrightarrow{\odot f_t}
f_t\odot C_{t-1}
\xrightarrow{+\,i_t\odot\tilde C_t}
C_t
$$

> [!question]+ LSTM의 기억 업데이트를 한 문장으로 이해하면
> 
> **"예전 기억에서 필요한 것은 남기고(Forget), 새로운 정보 중 필요한 것을 추가해서(Input), 새로운 장기 기억 $C_t$를 만든다."**
> 
> 이 구조가 매 시점 반복되면서 LSTM은 문맥을 계속 관리한다.

---

### 1.4.6 Output gate — 장기 기억 중 무엇을 밖으로 보여줄까?

cell state $C_t$가 완성되었다고 해서 그 전체를 그대로 외부에 출력하는 것은 아니다.

LSTM은 Output gate를 이용하여 **현재 시점에서 cell state 중 어떤 정보를 hidden state로 내보낼지** 결정한다.

#### ① Output gate 계산

$$
o_t=\sigma(W_o[h_{t-1},x_t]+b_o)
$$

Output gate는 cell state의 각 차원을 hidden state에 얼마나 반영할지 결정한다.

#### ② cell state를 tanh로 변환

$$  
\tanh(C_t)  
$$

cell state의 값을 $-1\sim1$ 범위로 변환한다.

#### ③ Output gate와 곱하기

$$
h_t=o_t\odot\tanh(C_t)
$$

따라서 hidden state는 cell state 전체가 아니라 **output gate를 통과한 정보만 외부에 드러낸 결과**이다.

> [!question]+ Cell state와 hidden state의 관계
>
> - **Cell state $C_t$**: 장기 정보를 다음 시점으로 전달하는 내부 상태
> - **Hidden state $h_t$**: $C_t$를 가공하고 output gate로 선택한 현재 시점의 표현
>
> cell state는 장기 정보 전달 경로를 담당하고, hidden state는 다음 시점의 게이트 계산과 현재 출력에 사용된다.

---

### 1.4.7 LSTM 전체 동작 한 번에 보기

LSTM의 전체 흐름을 하나로 연결하면 다음과 같다.

#### Step 1. 이전 정보와 현재 입력을 확인

$$  
[h_{t-1},x_t]  
$$

#### Step 2. Forget gate로 기존 기억을 얼마나 유지할지 결정

$$  
f_t=\sigma(W_f[h_{t-1},x_t]+b_f)  
$$

#### Step 3. Input gate와 candidate로 새로운 기억을 결정

$$  
i_t=\sigma(W_i[h_{t-1},x_t]+b_i)  
$$

$$  
\tilde{C}_t=\tanh(W_C[h_{t-1},x_t]+b_C)
$$

#### Step 4. 기존 기억과 새로운 기억을 합쳐 cell state 갱신

$$ C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t $$

#### Step 5. Output gate로 현재 외부에 보여줄 정보를 결정

$$  
o_t=\sigma(W_o[h_{t-1},x_t]+b_o)
$$

#### Step 6. hidden state 생성

$$  
h_t=o_t\odot\tanh(C_t)
$$

전체를 흐름으로 보면:

$$  
\boxed{  
(h_{t-1},x_t)  
\rightarrow  
\begin{cases}
f_t & \text{이전 정보의 유지 비율}\\
i_t,\tilde{C}_t & \text{추가할 새 정보}\\
o_t & \text{현재 출력 비율}
\end{cases}  
\rightarrow  
C_t  
\rightarrow  
h_t  
}  
$$

---

> [!question]+ 세 게이트의 역할을 한 번에 정리하면?
>
> - **Forget gate**: 이전 cell state의 유지 비율 계산
> - **Input gate**: candidate 정보를 새 cell state에 반영할 비율 계산
> - **Cell state 업데이트**: 유지한 이전 정보와 선택한 새 정보를 더함
> - **Output gate**: 새 cell state에서 hidden state로 내보낼 비율 계산
>
> LSTM은 매 시점마다 `이전 정보 선택 → 새 정보 추가 → 현재 표현 출력`의 순서로 상태를 갱신한다.

---

### 1.4.8 RNN과 LSTM 비교

||RNN|LSTM|
|---|---|---|
|상태|hidden state $h_t$|hidden state $h_t$ + cell state $C_t$|
|기억 관리|hidden state에 직접 누적|별도의 cell state에서 관리|
|정보 제어|명시적인 게이트 없음|Forget / Input / Output gate|
|핵심 활성화|주로 tanh|gate: sigmoid, candidate/output: tanh|
|장기 의존성|학습이 어려움|더 잘 학습할 수 있도록 설계|
|기울기 소실|문제가 큼|완화된 구조|
|핵심 아이디어|이전 정보를 다음 시점으로 전달|**장기 기억 경로를 분리하고 정보 흐름을 게이트로 제어**|

### 1.4.9 이 단원에서 꼭 기억할 것

> **RNN의 문제**
> 
> → 모든 정보를 하나의 hidden state로 계속 전달  
> → 긴 시퀀스에서 기울기 소실 발생  
> → 오래된 정보를 학습하기 어려움
> 
> **LSTM의 해결 아이디어**
> 
> → hidden state와 cell state를 분리  
> → cell state에 장기 기억을 전달하는 경로를 마련  
> → 세 개의 게이트로 정보의 흐름을 조절
> 
> **세 게이트**
> 
> - Forget gate → 기존 기억을 얼마나 버릴까?
>     
> - Input gate → 새 정보를 얼마나 저장할까?
>     
> - Output gate → 기억 중 얼마나 밖으로 내보낼까?
>     
> 
> **핵심 수식**
> 
> Forget:  
> $$f_t=\sigma(W_f[h_{t-1},x_t]+b_f)$$
> 
> Input:  
> $$i_t=\sigma(W_i[h_{t-1},x_t]+b_i)$$
> 
> Candidate:  
> $$\tilde{C}_t=\tanh(W_C[h_{t-1},x_t]+b_C)$$
> 
> Cell state:  
> $$C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$$
> 
> Output:  
> $$o_t=\sigma(W_o[h_{t-1},x_t]+b_o)$$
> 
> Hidden state:  
> $$h_t=o_t\odot\tanh(C_t)$$
> 
> **한 문장 요약**
> 
> → **LSTM은 장기 기억을 위한 cell state를 별도로 두고, Forget/Input/Output gate를 이용해 무엇을 버리고, 무엇을 저장하고, 무엇을 출력할지 학습하는 RNN이다.**

LSTM은 RNN보다 장기 정보를 보존하기 유리했지만, 입력을 여전히 한 시점씩 순서대로 처리한다. 또한 하나의 시퀀스를 이해하는 것과, 그 이해를 바탕으로 길이가 다른 새로운 시퀀스를 생성하는 것은 별도의 문제다. 다음 장에서는 RNN과 LSTM을 Encoder와 Decoder로 나누어 입력 문장을 출력 문장으로 변환하는 Seq2Seq 구조를 살펴본다.

## 2. 문장 이해에서 시퀀스 생성으로 — Seq2Seq와 Attention

워드 임베딩은 단어의 의미를 수치로 표현하고, RNN·LSTM은 그 표현을 순서대로 처리한다. 다음 단계는 입력 시퀀스를 바탕으로 새로운 출력 시퀀스를 생성하는 것이다. Seq2Seq은 인코더와 디코더를 분리해 이 문제를 해결했고, Attention은 고정된 하나의 문맥 벡터에 모든 정보를 압축해야 하는 한계를 완화했다.

> [!info] 학습 목표
> 
> - 언어 모델의 개념과 역할을 설명할 수 있다
> - 언어 모델이 문맥을 바탕으로 단어의 확률을 예측하는 방식을 이해한다
> - Seq2Seq 구조의 기본 아이디어(인코더-디코더)를 설명할 수 있다
> - Attention 메커니즘의 개념과 필요성을 설명할 수 있다

> [!question] 이 단원에서 답할 질문
> 
> 1. 언어 모델이란 무엇일까? — 언어 모델의 정의와 역할 / 단어 예측을 통한 문맥 이해
> 2. Seq2Seq은 어떻게 작동할까? — 인코더-디코더 구조 / 입력과 출력 길이가 다른 시퀀스 처리
> 3. Attention은 왜 필요할까? — Bottleneck problem 해결 / 중요한 단어에 집중하는 메커니즘

### 2.1 언어 모델(Language Model)이란

문장을 생성하려면 모델은 지금까지 나온 단어를 바탕으로 다음에 어떤 단어가 이어질지를 판단해야 한다. 이 판단을 확률로 표현한 것이 언어 모델이다. 언어 모델은 특정 문장이 자연스러운지를 평가하는 도구이면서, 문장을 한 단어씩 만들어 가는 생성 모델의 기초가 된다.

#### 언어모델이란

언어 모델은 가능한 단어 시퀀스에 확률을 부여하여 문장의 자연스러움을 나타낸다. `It was the best of times, it was the worst of times`처럼 문법과 문맥에 맞는 문장에는 높은 확률을, 자연스럽지 않은 단어 나열에는 낮은 확률을 부여하도록 학습한다. 결국 인간의 언어 생성 능력을 **다음에 올 단어의 확률을 계산하는 문제**로 바꾼 모델이다.

#### 문장 확률을 조건부 확률의 곱으로 분해

$$
p(w_1,w_2,\ldots,w_N)
=p(w_1)\prod_{t=2}^{N}p(w_t\mid w_1,\ldots,w_{t-1})
$$

문장 전체의 확률을 직접 계산하는 대신, 이전 단어들이 주어졌을 때 다음 단어가 나올 **조건부 확률**을 순서대로 곱한다. 예를 들어 `the cat sat on the mat`의 확률은 다음과 같이 분해된다.

$$P(\text{the cat sat on the mat}) = P(\text{the})P(\text{cat}\mid\text{the})P(\text{sat}\mid\text{the cat})P(\text{on}\mid\text{the cat sat})P(\text{the}\mid\text{the cat sat on})P(\text{mat}\mid\text{the cat sat on the})$$

> [!question]+ 이 수식에서 "Implicit order"가 의미하는 것
> 
> 각 조건부 확률 $p(w_k|w_1,\ldots,w_{k-1})$은 **오직 이전 단어들만 보고 다음 단어를 예측**하는 구조이다. 즉 문장 확률을 분해하는 수식 자체에 "단어는 순서대로, 이전 문맥에 의존해서 나온다"는 순차적 데이터의 성질(1.2에서 다룬 순서의 중요성)이 이미 내재되어 있다.
> 
> → 언어모델은 결국 **"이전 문맥이 주어졌을 때 다음 단어를 예측하는 문제"를 문장 끝까지 반복해서 푸는 것**과 같다.

#### 일상 속의 언어모델

스마트폰 키보드가 `I'll meet you at the` 다음에 `cafe`, `airport`, `office`를 추천하거나, 검색창이 `what is the` 뒤에 이어질 표현을 자동 완성하는 것도 같은 원리다. 두 기능 모두 $p(w_N\mid w_1,\ldots,w_{N-1})$을 계산해 이전 문맥에서 확률이 높은 후보를 보여준다.

#### N-gram 언어모델

초기의 언어 모델은 긴 문맥 전체를 다루기 어려웠기 때문에, 연속된 $n$개의 단어 묶음인 **n-gram**의 빈도를 이용했다. `The`, `students`, `opened`, `their`를 각각 세면 unigram이고, `The students`, `students opened`, `opened their`처럼 연속된 두 단어를 묶으면 bigram이다. trigram과 four-gram은 같은 방식으로 세 단어와 네 단어를 하나의 단위로 본다. 모델은 코퍼스에서 각 묶음이 얼마나 자주 등장했는지를 세어 다음 단어의 확률을 추정한다.

**계산 방식** (4-gram 예시, 직전 3개 단어만 사용): $$P(w \mid \text{students opened their}) = \frac{\text{count}(\text{students opened their } w)}{\text{count}(\text{students opened their})}$$

- 코퍼스에서 "students opened their" 1000번 등장, 그 중 "students opened their books" 400번 → $P(\text{books}|\ldots)=0.4$
- "students opened their exams" 100번 등장 → $P(\text{exams}|\ldots)=0.1$

> [!question]+ N-gram 언어모델의 구조적 한계 — 왜 "직전 몇 개"만 보는가, 그리고 무엇을 놓치는가
> 
> N-gram 언어모델은 앞의 조건부 확률 분해식 $p(w_N|w_1,\ldots,w_{N-1})$을 그대로 쓰지 않고, **"직전 n-1개 단어만 본다"고 근사(approximation)**한 것이다. 예를 들어 4-gram이면 아무리 앞에 "as the proctor started the clock,"처럼 중요한 맥락(시험 상황이라는 단서)이 있어도, 그 부분은 계산에서 완전히 배제되고 오직 직전 3개 단어("students opened their")만 사용해서 다음 단어를 예측한다.
> 
> **왜 이런 근사가 필요한가**: 문장 전체 맥락을 다 반영하려 하면, 조건부의 조합이 문장이 길어질수록 기하급수적으로 다양해져서 코퍼스에서 그 조합이 등장한 횟수를 셀 수 있을 만큼 충분히 관측되기 어렵다(데이터 희소성). 그래서 "직전 n-1개만 본다"고 범위를 제한해 통계를 셀 수 있게 만든 것.
> 
> **대가**: 계산을 단순화한 대신 n-gram 범위를 벗어난 과거 정보는 확률 계산에 반영되지 않는다. RNN/LSTM은 hidden state와 cell state를 통해 과거 정보를 계속 전달하지만, n-gram은 정해진 범위 밖의 장기 의존성을 구조적으로 모델링하지 않는다.

#### 언어모델 활용 예시: Statistical Machine Translation (SMT)

1990년대부터 2010년대까지의 기계 번역은 주로 통계적 기계 번역(Statistical Machine Translation, SMT)으로 접근했다. 목표는 한국어 문장 $x$가 주어졌을 때 조건부 확률이 가장 높은 영어 문장 $y$를 찾는 것이다.

$$
\operatorname*{argmax}_y P(y\mid x)
$$

- Bayes 정리를 적용하면 번역모델과 언어모델로 분해할 수 있다. $P(x)$는 $y$와 무관하므로 최적화에서 제외한다.

$$
\operatorname*{argmax}_y P(y\mid x)
=
\operatorname*{argmax}_y
\underbrace{P(x\mid y)}_{\text{번역모델}}
\underbrace{P(y)}_{\text{언어모델}}
$$

- **번역모델** $P(x|y)$: 단어/구가 어떻게 번역되어야 하는지 모델링 → (한국어, 영어) 병렬 코퍼스로 학습
- **언어모델** $P(y)$: 유창한 영어 문장을 쓰는 방법을 모델링 → 영어 데이터만으로 학습

> [!question]+ 왜 번역 문제를 번역모델과 언어모델로 분해하는가
> 
> $P(y|x)$를 하나의 분포로 직접 모델링하는 대신 Bayes 정리로 분해하면, 번역의 **정확성**과 목표 언어의 **유창함**을 서로 다른 확률모형으로 다룰 수 있다.
> 
> Bayes rule로 $P(y|x) \propto P(x|y)P(y)$로 분리하면:
> 
> - $P(x|y)$(번역모델)는 "단어/구 대응"에만 집중 → (한국어, 영어) **병렬** 코퍼스가 필요
> - $P(y)$(언어모델)는 "영어다운 문장인가"에만 집중 → 영어 **단일** 코퍼스만 있어도 학습 가능
> 
> → 두 문제를 분리하면 각각 더 단순한 모델로 풀 수 있고, 특히 언어모델 쪽은 구하기 훨씬 쉬운 단일 언어 텍스트만으로 학습할 수 있어 데이터 확보 부담이 크게 줄어든다.

#### SMT의 한계

SMT는 번역 모델, 언어 모델, 정렬 규칙과 사전 같은 여러 요소를 별도로 구축해야 해서 구조가 복잡하고 수작업이 많이 필요했다. 또한 언어쌍이 바뀔 때마다 필요한 자원을 다시 준비해야 했으므로 유지와 확장이 어려웠다. 이러한 구성 요소를 하나의 신경망 안에서 함께 학습하려는 방향으로 연구가 이동했고, 그 결과 **Neural Machine Translation(NMT)**과 대표 구조인 **Seq2Seq**가 등장했다.

### 2.2 Seq2Seq: 인코더-디코더 구조

Seq2Seq의 핵심은 입력을 읽는 역할과 출력을 만드는 역할을 분리하는 것이다. Encoder는 입력 시퀀스의 의미를 하나의 표현으로 압축하고, Decoder는 그 표현을 출발점으로 새로운 시퀀스를 한 토큰씩 생성한다. 이 구조는 입력과 출력의 길이가 달라도 사용할 수 있으므로 번역 문제에 적합했다.

#### Neural Machine Translation(NMT)이란

NMT는 인공 신경망으로 번역 전체를 학습하는 방법이며, 2014년 이후 통계 기반 번역을 빠르게 대체했다. 이때 널리 사용된 Seq2Seq는 인코더와 디코더라는 두 개의 RNN 또는 LSTM으로 이루어진다. 인코더 셀과 디코더 셀은 각자의 구간에서 시점마다 재사용되지만 서로 다른 가중치를 사용한다. 이 구조는 2014년 Google의 Sutskever 등이 발표한 「Sequence to Sequence Learning with Neural Networks」에서 제안되었다.

#### Translation이 어려운 이유

번역에서는 입력과 출력의 길이가 다를 수 있다. 영어의 `the black cat drank milk`는 5개 단어지만, 프랑스어의 `le chat noir a bu du lait`는 7개 단어다. 따라서 번역 모델은 고정된 크기의 입력과 출력만 대응시키는 것이 아니라, 길이가 서로 다른 두 시퀀스 사이의 관계를 학습해야 한다.

#### Seq2Seq의 아이디어

Seq2Seq는 두 개의 LSTM을 사용한다. **Encoder**가 입력을 한 시점씩 읽어 고정 차원의 벡터 표현을 만들고, **Decoder**가 그 표현을 받아 출력 시퀀스를 생성한다. 입력의 길이와 출력의 길이는 서로 독립적이므로 번역뿐 아니라 요약, 대화, 코드 생성처럼 길이가 달라지는 변환 문제에 사용할 수 있다.

#### Seq2Seq Architecture

영어 인코더는 `<SOS> the black cat drank milk <EOS>`를 순서대로 읽어 $h_1,\ldots,h_7$을 만든다. 기본 Seq2Seq에서는 마지막 hidden state $h_7$을 입력 문장 전체의 압축된 표현으로 사용한다. 프랑스어 디코더는 이 벡터를 초기 상태로 받아 `<SOS>`에서 시작해 `le chat noir a bu du lait <EOS>`를 한 단어씩 생성한다.

> [!question]+ 컨텍스트 벡터(Context Vector)란 — 2.3 Attention의 context vector와 구분 주의
> 
> 위에서 말한 인코더의 마지막 hidden state($h_7$)를 **컨텍스트 벡터**라고도 부른다: $c=h_{\text{enc,last}}$. 입력 전체를 고정 차원의 벡터로 압축한 결과이며, 디코더의 초기 상태로 한 번 전달된다.
> 
> **주의**: 같은 "context vector"라는 이름이 뒤에 나올 **2.3 Attention에서는 다른 것**을 가리킨다.
> 
> ||정의|계산 시점|
> |---|---|---|
> |**기본 Seq2Seq의 컨텍스트 벡터**(여기)|인코더의 **마지막 hidden state 하나**($h_7$)|디코더 시작 전 **1번만** 계산, 이후 고정|
> |**Attention의 context vector**(2.3)|인코더 **모든** hidden state($h_1,\ldots,h_7$)를 attention 가중치로 **가중합**한 것: $a_t=\sum_i \alpha_i^t h_i$|디코더가 단어를 만들 **매 시점마다** 새로 계산|
> 
> 기본 Seq2Seq은 입력 전체를 고정된 벡터 하나로 압축하므로, 문장이 길어질수록 정보 손실이 커지는 **병목 문제(bottleneck problem)**가 발생한다. Attention은 디코더의 각 시점마다 인코더 상태의 가중합을 새로 계산해 이 한계를 완화한다.

> [!question]+ 디코더는 매 타임스텝마다 무엇을 입력으로 받는가 — Autoregressive 구조 이해하기
> 
> RNN 계열 모델은 매 시점 $x_t$를 입력받아 $h_t=f(h_{t-1},x_t)$를 계산한다(1.3 RNN 참고). 인코더는 이 $x_t$가 명확하다 — 원문 문장의 각 단어("the","black","cat",...)를 순서대로 넣으면 된다.
> 
> 그런데 디코더는 상황이 다르다. 디코더가 만들어야 하는 건 "아직 존재하지 않는" 번역 문장이기 때문에, 애초에 각 시점에 넣어줄 정해진 입력이 없다. 그래서 Seq2Seq 디코더는 **직전 시점에 자기 자신이 출력(예측)한 단어를 그대로 다음 시점의 입력 $x_t$로 재사용**한다 — 이런 구조를 **autoregressive(자기회귀적)**라 한다.
> 
> 흐름으로 보면:
> 
> 1. `<SOS>`를 입력받아 첫 단어 예측 → "le"
> 2. 방금 예측한 "le"를 다음 스텝의 입력으로 넣어서 → 다음 단어 예측 → "chat"
> 3. 다시 "chat"을 입력으로 넣어서 → 다음 단어 예측 → ...
> 
> **문제**: 학습 초반에는 모델이 서투르기 때문에 1번 스텝에서 "le" 대신 오답인 "chien"을 예측할 수 있다. 이 잘못된 예측이 그대로 2번 스텝의 입력으로 들어가버리면, 디코더는 "chien" 이후에 이어질 법한(원래 정답과는 무관한) 단어를 계속 생성하게 된다. 한 스텝의 오차가 다음 스텝의 입력 자체를 오염시키고, 그 오염된 입력이 또 다음 스텝을 오염시키는 식으로 **오차가 누적(compounding error)**되어 학습 신호가 매우 불안정해진다.
> 
> → 이 문제를 막기 위해 학습 시에는 모델의 예측 대신 **정답 단어를 강제로 다음 입력에 넣어주는 것**이 바로 아래의 Teacher Forcing이다.

> [!question]+ 인코더 벡터에 이미 원문 정보가 있는데, 왜 디코더는 자기 출력을 또 입력으로 넣는가
> 
> **핵심: 두 정보는 역할이 다르다**
> 
> ||담당하는 정보|전달 방식|
> |---|---|---|
> |**인코더 벡터($h_7$)**|번역할 원문의 내용|한 번, 디코더 시작점에 전달|
> |**디코더 자기 출력 재입력**|"지금까지 어디까지 번역했는가"|매 스텝마다 갱신되며 전달|
> 
> 번역 문장 생성도 언어모델의 조건부 확률 구조를 따른다.
>
> $$P(y_t\mid y_1,\ldots,y_{t-1},x)$$
> 
> - $x$(원문) → 인코더 벡터가 담당
> - $y_1,\ldots,y_{t-1}$(지금까지 만든 출력) → 인코더 벡터엔 없는 정보. 디코더가 자기 출력을 다시 입력으로 넣어야만 얻을 수 있음
> 
> "이 문장이 고양이에 관한 내용"이라는 정보만으로는 3번째 단어가 뭐가 와야 할지 알 수 없다. "le chat noir까지 이미 말했다"는 걸 알아야 "다음엔 동사가 와야겠다"는 판단이 가능하다.
> 
> **만약 이전 출력을 안 넣어주면**: 디코더가 매번 원문 요약 벡터만 보고 단어를 뽑으면, 자기가 방금 뭘 말했는지 모른 채 매 스텝 독립적으로 판단하게 됨 → 같은 단어 반복, 문법적으로 이어지지 않는 출력 등의 문제 발생 가능
> 
> → **인코더 벡터는 "무엇을"을 알려주고, 디코더의 자기 출력 재입력은 "어디까지 했는지"를 알려준다 — 겹치지 않는, 서로 보완하는 정보다.**

#### Teacher Forcing

디코더는 직전 출력 토큰을 다음 입력으로 사용하므로, 학습 초기에 한 번 틀리면 잘못된 입력이 이후 시점까지 이어질 수 있다. **Teacher Forcing**은 모델이 예측한 단어 대신 정답 단어를 다음 입력으로 제공하여 이러한 오차 누적을 막고 학습을 빠르고 안정적으로 만든다. 다만 정답을 알고 있는 학습 단계에서만 사용할 수 있으며, 실제 추론에서는 모델이 자신의 출력을 다시 입력해야 한다.

#### Seq2Seq의 다양한 적용

- Seq2Seq 구조는 기계번역 외에도 **"길이가 다른 시퀀스를 시퀀스로 변환"**하는 다양한 태스크에 적용 가능
    - **요약**: 긴 길이의 문서를 읽고, 짧은 길이의 문장으로 요약된 텍스트를 출력
    - **대화**: 사용자의 발화를 기반으로, 맥락에 맞는 대답(출력 텍스트)을 생성
    - **코드 생성**: 자연어로 작성된 설명·명령어를 입력받아, 대응하는 프로그래밍 코드나 쿼리를 출력

#### Seq2Seq 학습 — End-to-End 최적화

인코더와 디코더는 역할이 나뉘지만 하나의 통합 네트워크로 학습된다. 디코더에서 발생한 오차가 역전파를 통해 인코더까지 전달되므로, 입력을 표현하는 방법과 출력을 생성하는 방법이 **End-to-End로 함께 최적화**된다. 이것이 여러 통계 모형을 따로 만들던 SMT와의 중요한 차이다.

#### 추론 시 토큰 출력 방법 ① Greedy Inference

- 각 단계에서 **가장 확률이 높은 단어 하나만** 선택하는 방식
- 한계: **되돌리기가 불가능**
    - 예시: `le ___` → `le chien ___` → ... (오답이지만 되돌아갈 방법이 없음)

> [!question]+ Greedy Inference의 한계 — "매 순간 최선"이 "문장 전체의 최선"은 아닌 이유
> 
> Greedy는 각 시점에서 지역적(local)으로 가장 확률 높은 단어만 선택한다. 하지만 문장 전체 확률은 각 단어 확률의 곱(2.1의 조건부 확률 곱 구조와 동일)이기 때문에, 특정 시점에서 살짝 낮은 확률의 단어를 선택하는 편이 이후 단어들과 결합했을 때 전체 문장 확률은 오히려 더 높을 수도 있다. Greedy는 매 순간 후보 하나만 남기고 나머지는 모두 버리기 때문에, 이런 **전역적으로 더 나은 경로를 애초에 탐색할 기회조차 갖지 못한다.**

#### 추론 시 토큰 출력 방법 ② Beam Search

- 매 단계마다 **k개의 가장 유망한 후보**를 동시에 유지
    1. 매 단계마다 k개의 가장 유망한 후보 유지
    2. 후보가 `<EOS>`에 도달하면 완성된 문장으로 리스트에 추가
    3. `<EOS>` 문장이 충분히 모이면 탐색 종료
    4. 각 후보들의 점수를 **로그 확률의 합**으로 구해 최종 선택

> [!question]+ Beam Search에서 왜 "로그 확률의 합"으로 점수를 매기는가
> 
> 문장의 확률은 각 단어 확률의 곱 $P(w_1)\times P(w_2|w_1)\times\cdots$(2.1의 언어모델 확률 분해와 동일 구조)로 계산된다. 그런데 확률(0~1 사이 값)을 계속 곱하면 값이 기하급수적으로 작아져 컴퓨터가 정밀하게 표현하기 어려워진다(underflow). 로그를 취하면 $\log(ab)=\log a+\log b$이므로 곱셈이 덧셈으로 바뀌어, 값이 너무 작아지는 문제 없이 안정적으로 후보들의 점수를 계산·비교할 수 있다.
> 
> → Beam Search는 "매 순간 1등만 남기는" Greedy와 "가능한 모든 경우의 수를 다 보는" 완전탐색 사이의 절충안으로, k개의 후보를 유지해 오답 경로에 갇힐 위험을 줄이면서도 계산량은 감당 가능한 수준으로 유지한다.

### 2.3 Attention: Bottleneck 문제를 해결하는 메커니즘

Seq2Seq는 번역 과정을 하나의 신경망으로 통합했지만, 입력 문장 전체를 마지막 hidden state 하나에 담아야 했다. 문장이 길어져도 벡터의 크기는 변하지 않으므로, Encoder가 기억해야 할 정보만 늘어나면서 일부 정보가 손실되었다. Attention은 모든 내용을 하나로 압축하는 대신, Decoder가 토큰을 생성할 때마다 필요한 입력 위치를 다시 선택하도록 구조를 바꾸었다.

#### Seq2Seq의 한계: Bottleneck Problem

기본 Seq2Seq에서 인코더는 입력 전체를 마지막 hidden state $h_7$ 하나로 압축해 디코더에 전달한다. 문장이 길어져도 벡터의 크기는 고정되어 있으므로, 제한된 표현 안에 더 많은 정보를 담아야 하고 정보 손실이 발생할 수 있다. 이를 **병목 문제(Bottleneck Problem)**라고 한다.

#### Attention의 인사이트

Attention의 발상은 마지막 상태만 전달하지 말고 인코더의 모든 hidden state를 남겨 두는 것이다. 디코더는 토큰을 생성하는 매 시점마다 인코더의 어느 단어나 구절이 필요한지를 가중치로 계산하고, 필요한 부분을 직접 참조한다. 따라서 하나의 고정 벡터에 모든 정보를 미리 압축할 필요가 줄어든다.

#### Attention의 동작 과정

먼저 디코더의 현재 hidden state $s_t$와 인코더의 모든 hidden state $h_1,\ldots,h_7$ 사이의 유사도 점수 $A(t,i)$를 계산한다. 이 점수를 softmax에 통과시키면 각 입력 위치를 얼마나 참고할지를 나타내는 attention distribution이 된다. 마지막으로 이 값을 가중치로 사용해 인코더 상태를 가중합한다.

$$
a_t=\sum_i\alpha_i^t h_i
$$

이렇게 만든 $a_t$가 현재 시점의 context vector이며, 디코더 상태 $s_t$와 함께 출력 $y_t$를 예측하는 데 사용된다. 다음 토큰을 만들 때는 디코더 상태가 바뀌므로 attention 분포와 context vector도 다시 계산된다.

> [!question]+ Attention distribution(확률)이 디코더로 "그대로" 전달되는 게 아니라는 것 — 확률의 합 vs 가중합
> 
> $a_t=\sum_i\alpha_i^t h_i$라는 수식을 보고 "확률들의 합이 디코더로 전달된다"고 오해하기 쉽지만, 정확히는 **"확률(attention score)을 가중치로 삼아 인코더 벡터들을 섞은 새로운 벡터"**가 전달되는 것이다.
> 
> - $\alpha_1,\ldots,\alpha_n$ (attention distribution): 이 값들의 합은 항상 1(softmax 결과). 이건 "디코더가 지금 각 입력 단어를 얼마나 참고할지"의 **비율**일 뿐, 그 자체로는 아무 정보도 담고 있지 않다.
> - $h_1,\ldots,h_n$ (인코더 hidden state): 각 입력 단어가 실제로 담고 있는 **내용**.
> - $a_t=\alpha_1h_1+\alpha_2h_2+\cdots+\alpha_nh_n$: 비율($\alpha_i$)대로 내용($h_i$)을 섞어 만든 **새로운 벡터**. 만약 정말 확률들만 더한다면 결과는 그냥 숫자 1일 뿐이라 아무 의미가 없다.
> 
> 따라서 attention distribution은 참조 비율을 나타내고, context vector는 그 비율을 실제 정보 벡터에 적용한 결과이다. 디코더에 전달되는 것은 확률의 합이 아니라 가중합된 정보 벡터이다.

> [!question]+ Attention 분포가 매 타임스텝마다 다시 계산되는 이유
> 
> Attention은 디코더가 "le"를 만들 때와 "noir"를 만들 때 서로 다른 원문 부분에 집중한다(실제로 두 시점의 attention distribution 막대그래프 모양이 다르게 나타남). 각 출력 단어마다 필요한 원문 정보가 다르기 때문이다 — "le"(관사)를 만들 때 필요한 단서와 "noir"(형용사, "검은")를 만들 때 필요한 단서(원문의 "black")는 서로 다르다.
> 
> 그래서 Attention은 매 타임스텝 $t$마다 디코더의 현재 상태 $s_t$를 Query로 삼아, 인코더 전체를 처음부터 다시 훑어보며 "지금 이 단어를 만들려면 원문의 어디를 봐야 하나"를 새로 계산한다. 이는 Seq2Seq가 문장 전체를 $h_7$ 하나로 고정해서 넘겨주던 방식과 근본적으로 다른 지점이다 — attention에는 "한 번 압축해서 끝"이 아니라, "매번 다시 필요한 곳을 찾아가는" 동적인 참조 과정이 있다.

#### Attention의 효과

Attention은 Decoder가 필요한 입력에 집중하게 하여 번역 성능을 높였고, 모든 Encoder 상태에 직접 접근하게 하여 병목 문제를 완화했다. 또한 멀리 떨어진 정보 사이에 짧은 연결 경로를 추가하므로 RNN의 긴 순환 경로에서 발생하던 기울기 소실도 줄이는 데 도움이 된다.

> [!question]+ Attention이 왜 기울기 소실 문제를 완화하는가
> 
> 1.3에서 다룬 RNN의 기울기 소실은, 역전파 시 오차 신호가 시점 하나씩을 거칠 때마다 작은 값이 반복적으로 곱해지면서 결국 0에 가까워지는 문제였다. 예컨대 인코더 첫 단어("the")의 정보가 디코더 마지막 단어까지 영향을 주려면, 원래 구조라면 인코더 내부의 여러 시점 + 디코더 내부의 여러 시점을 모두 순차적으로 거쳐야 했다.
> 
> Attention은 디코더의 각 시점이 인코더의 **모든 hidden state에 직접 접근**하게 한다. 예를 들어 $h_1$의 정보는 $h_2,h_3,\ldots,h_7$을 모두 거치지 않고 가중합을 통해 디코더 출력에 반영된다. 역전파에서도 더 짧은 경로가 생기므로, 멀리 떨어진 단어 사이의 학습 신호가 상대적으로 잘 전달된다.

#### BLEU score로 본 Attention의 효과

- **BLEU score**: 기계 번역의 출력이 사람 번역과 얼마나 비슷한지 평가하는 지표
- **RNNenc**(attention 없이 고정 벡터만 사용): 문장 길이가 길어질수록 BLEU score가 급격히 하락
- **RNNsearch**(attention 사용): 문장이 길어져도 BLEU score가 비교적 안정적으로 유지
- → bottleneck problem이 실제 성능 저하로 이어짐을, attention이 이를 완화함을 실증적으로 보여주는 근거

#### Attention의 효과: 해석 가능성(Interpretability)

- Attention 분포를 시각화하면, decoder가 각 단어를 생성할 때 입력 문장의 어느 부분에 집중했는지 확인 가능
- 모델이 어느 입력 위치에 높은 가중치를 주었는지 확인할 수 있어 동작을 분석하는 단서를 제공한다. 다만 attention 가중치만으로 모델의 전체 판단 근거를 완전히 설명할 수 있는 것은 아니다.

#### Attention의 효과: 정렬(Alignment)

- 전통적인 기계번역에서는 단어 alignment 모델을 **별도로 학습**해야 했음
- Attention은 decoder가 필요한 입력 단어에 자동으로 집중하도록 학습되기 때문에, **별도 정렬 모델 없이도 단어와 단어 간의 매핑 관계를 자연스럽게 학습**함

#### Attention의 일반화: Query, Key, Value

Seq2Seq Attention에서 디코더 hidden state는 필요한 정보를 요청하는 **Query**, 인코더 hidden state는 관련도를 비교하는 **Key**이자 실제로 전달할 정보인 **Value**로 볼 수 있다. 이 관점으로 일반화하면 Attention은 세 단계로 정리된다. 먼저 Query와 Key의 유사도 점수를 계산하고, softmax로 참조 비율을 만든 뒤, 그 비율로 Value를 가중합해 Attention 출력을 생성한다.

**score 계산 방식**

- **Dot product**: $h\cdot s$ — 단순 내적, 추가 학습 파라미터 없음
- **Multiplicative**: $h^TWs$ — 학습 가능한 가중치 행렬 $W$를 사이에 끼워 유사도를 유연하게 학습
- **Additive**: $v^\top\tanh(W_h\,h+W_s\,s)$ — 두 상태를 별도로 변환해 더한 뒤 비선형 변환과 벡터 $v$를 적용해 스칼라 점수를 계산한다. 학습 파라미터와 연산량은 더 많다.

> [!question]+ Dot product·Multiplicative·Additive score의 공통점과 차이
> 
> Dot product는 Query와 Key의 내적으로 관련도를 계산한다. 학습 과정에서 관련된 Query와 Key의 내적이 커지도록 각 표현과 파라미터가 조정된다.
> 
> Multiplicative와 Additive는 여기에 학습 가능한 가중치를 추가한 버전이다. Multiplicative($h^TWs$)는 벡터를 곧바로 곱하기 전에 행렬 $W$로 한 번 변환을 거치게 해서, 단순 내적보다 더 유연하게 "무엇이 유사한 것으로 취급될지"를 학습으로 조정할 수 있게 한다. Additive는 두 벡터를 각각 다른 가중치로 변환한 뒤 더하고 비선형(tanh)까지 거치므로 표현력이 가장 크지만, 그만큼 계산량과 학습할 파라미터도 늘어난다.
> 
> 세 방식 모두 Query와 Key의 관련성을 스칼라 점수로 계산한다. 차이는 점수 함수에 학습 가능한 파라미터와 비선형 변환을 얼마나 사용하는가에 있다.

Attention은 Encoder와 Decoder 사이의 정보 전달 방식을 크게 개선했지만, 전체 구조에는 여전히 RNN이 남아 있었다. Encoder와 Decoder가 입력을 한 시점씩 처리해야 했기 때문에 학습을 시간축으로 병렬화하기 어려웠다. 그러나 Attention이 모든 입력 위치를 직접 연결할 수 있다는 사실은 한 가지 가능성을 보여주었다. **시퀀스를 이해하는 과정 자체도 순환 구조 없이 Attention만으로 처리할 수 있지 않을까?** 이 질문에서 Self-Attention과 Transformer의 흐름이 시작된다.

## 3. 순환 구조에서 전역 상호작용으로 — Self-Attention과 Transformer

Seq2Seq Attention은 디코더가 인코더의 모든 시점에 직접 접근할 수 있게 했다. 덕분에 멀리 떨어진 정보 사이에 짧은 전달 경로가 생겼지만, Encoder와 Decoder 자체는 여전히 RNN으로 구성되어 입력을 순서대로 처리했다. 앞 시점의 계산이 끝나야 다음 시점을 계산할 수 있었기 때문에 GPU의 병렬 연산 능력을 충분히 활용하기 어려웠다.

여기서 Attention을 단순한 보조 장치가 아니라 시퀀스를 처리하는 중심 연산으로 사용할 수 있다는 발상이 나왔다. Encoder와 Decoder 사이에서만 정보를 참조하는 대신, 같은 시퀀스의 모든 토큰이 서로를 직접 참조하도록 만든 것이 Self-Attention이다. Transformer는 이 메커니즘을 중심으로 순환 구조를 제거하고, 순서 정보와 깊은 학습에 필요한 여러 요소를 하나의 블록으로 결합했다.

> [!info] 학습 목표
> 
> - Transformer의 등장 배경과 필요성을 설명할 수 있다
> - Self-Attention의 기본 개념과 동작 원리를 이해한다
> - Transformer의 전체 구조(인코더·디코더 블록)를 설명할 수 있다

### 3.1 Self-Attention

Self-Attention이 해결하려 한 문제는 단순히 RNN의 기울기 소실만이 아니다. 핵심은 **정보 전달 경로의 길이**와 **계산 순서에 생기는 의존성**이다. 멀리 떨어진 단어끼리 직접 연결하고 모든 토큰을 동시에 계산할 수 있다면 장기 의존성과 학습 속도를 함께 개선할 수 있다.

#### RNN이 꼭 필요할까?

RNN은 정보를 hidden state에 담아 한 시점씩 전달함으로써 순서를 모델링한다. 반면 Attention은 필요한 정보가 있는 위치에 직접 접근한다. 그렇다면 순서를 처리하기 위해 반드시 hidden state를 차례대로 전달해야 하는지, 순환 구조 없이 Attention만으로 시퀀스를 처리할 수 있는지가 새로운 연구 문제가 되었다.

#### RNN의 한계점 1 — 장기 의존성

RNN은 왼쪽에서 오른쪽으로 전개되므로 멀리 떨어진 두 단어가 상호작용하려면 그 사이의 모든 시점을 거쳐야 한다. 예를 들어 "그 책은 오랫동안 방치되어 먼지가 많이 쌓인 탓에… 매우 **더러웠다**"에서 "책"의 정보가 "더러웠다"에 도달하려면 중간 단어를 차례대로 통과해야 한다. 이때 정보 전달 경로의 길이는 시퀀스 길이에 비례하는 **$O(n)$**이 되고, 경로가 길수록 기울기 소실이나 폭발로 장기 의존성을 학습하기 어려워진다.

#### RNN의 한계점 2 — 병렬화

두 번째 문제는 병렬화다. 현재 시점의 계산에 이전 hidden state가 필요하므로 순전파와 역전파 모두 시퀀스 길이만큼의 순차 단계가 필요하다. 여러 토큰이 있어도 시간축의 계산을 동시에 수행하기 어려워 GPU를 충분히 활용할 수 없었고, 이는 대규모 데이터 학습의 효율을 제한했다.

#### Self-Attention의 등장

Attention은 Query와 Key의 관련도를 계산하고, 그 결과로 Value를 가중합한다. Self-Attention은 이 연산을 Encoder와 Decoder 사이가 아니라 **하나의 시퀀스 내부**에 적용한다. 각 토큰이 Query가 되어 같은 문장의 모든 토큰 Key와 관련도를 계산하고, 필요한 Value를 가져온다.

그 결과 한 층 안의 모든 토큰 표현을 병렬로 계산할 수 있고, 서로 얼마나 멀리 떨어져 있든 한 번의 Attention 연산으로 직접 상호작용한다. 두 토큰 사이의 최대 정보 전달 경로가 **$O(1)$**이 되어 RNN의 $O(n)$ 경로보다 장기 의존성을 학습하기 유리해진다.

> [!note] 계산 경로와 계산량은 다르다
>
> O(1)은 두 토큰 사이의 **정보 전달 경로 길이**를 뜻한다. Self-Attention의 전체 점수 행렬은 모든 토큰 쌍을 비교하므로, 일반적인 계산량과 메모리 사용량은 시퀀스 길이 $n$에 대해 $O(n^2)$이다.

> [!question]+ Self-Attention이 왜 O(1)의 상호작용 거리를 갖는가 — RNN과의 결정적 차이
> 
> RNN에서 첫 단어와 마지막 단어가 상호작용하려면, 그 사이의 모든 시점을 순서대로 거쳐야 한다 — 즉 상호작용 거리가 시퀀스 길이에 비례(O(sequence length))한다.
> 
> 반면 Self-Attention은 특정 단어의 query를 **문장 내 모든 단어의 key와 한 번에** 비교해서 점수를 계산한다. 즉 몇 번째 단어든 상관없이, 단 한 층의 attention 계산만으로 문장 내 다른 모든 단어와 직접 연결된다. 중간 단어들을 순서대로 거칠 필요가 없으므로 상호작용 거리가 항상 상수(O(1))로 유지된다.
> 
> 이처럼 단어 사이의 정보 전달 경로가 짧아져 RNN보다 장거리 의존성을 학습하기 유리하다. 다만 깊은 네트워크 자체의 기울기 문제까지 완전히 사라지는 것은 아니므로 residual connection과 normalization을 함께 사용한다.

#### Seq2Seq Attention vs Self-Attention

Seq2Seq Attention은 출력 문장을 만드는 Decoder가 입력 문장의 Encoder 상태를 참조하므로 서로 다른 두 시퀀스를 연결한다. Self-Attention은 같은 문장 안에서 토큰끼리 서로를 참조한다. 예를 들어 "거기"라는 표현이 같은 문장의 "카페"에 높은 가중치를 주면서 두 단어가 같은 장소를 가리키는 관계를 표현할 수 있다.

#### Self-Attention의 계산 과정

먼저 각 단어의 임베딩에 학습 가능한 행렬 $W^Q$, $W^K$, $W^V$를 곱해 Query, Key, Value를 만든다. 특정 단어의 Query를 문장 안의 모든 Key와 비교하면 각 토큰과의 관련도 점수가 나온다. 이 점수를 정규화한 뒤 Value를 가중합하면 다른 단어와의 관계가 반영된 새로운 표현이 만들어진다.

예를 들어 "어제"의 Query에서 얻은 가중치가 $a_1,\ldots,a_6$이라면 새로운 표현은 $h_{\text{어제}}=a_1v_1+\cdots+a_6v_6$이 된다. 이 계산은 문장의 모든 토큰에 대해 독립적으로 수행할 수 있으므로 병렬화가 가능하다.

> [!question]+ 하나의 단어 임베딩이 왜 Q, K, V 세 가지로 나뉘는가
> 
> Seq2Seq attention에서는 query(디코더 상태)와 value(인코더 hidden state)가 애초에 서로 다른 시퀀스에서 나왔다. 그런데 Self-Attention은 **같은 문장의 단어들**끼리 서로를 참조해야 하므로, 하나의 단어 임베딩이 상황에 따라 세 가지 다른 역할을 동시에 수행해야 한다:
> 
> - **query(q)**: 현재 토큰이 다른 토큰에서 필요로 하는 정보의 기준
> - **key(k)**: 다른 query와 관련도를 계산할 때 사용하는 특징
> - **value(v)**: 관련도에 따라 실제로 전달되는 정보
> 
> 같은 임베딩 $e$에 서로 다른 가중치 행렬($W^Q,W^K,W^V$)을 적용하면, 관련도를 요청하는 표현·비교되는 표현·전달되는 표현을 서로 다른 부분공간에서 학습할 수 있다.

> [!question]+ Self-Attention에서 각 단어의 Query와 Key에는 구체적으로 어떤 정보가 담기는가
> 
> Cross-Attention(2.3, 3.2)과 달리 Self-Attention은 인코더/디코더 구분이 없으므로, **모든 단어가 예외 없이 자기 자신의 query와 key를 둘 다 가진다.**
> 
> - **Query**: 현재 토큰이 문맥을 구성할 때 필요한 정보의 기준을 담는다. 예를 들어 "거기"의 query는 장소를 나타내는 선행 표현과 높은 관련도를 갖도록 학습될 수 있다.
> - **Key**: 해당 토큰이 다른 토큰과 비교될 때 사용할 특징을 담는다. 예를 들어 "카페"의 key는 장소를 나타내는 표현과 잘 대응하도록 학습될 수 있다.
> 
> 다만 $W^Q,W^K$는 사람이 "장소면 이 숫자" 식으로 설계한 게 아니라 번역/생성 등 downstream 과제를 잘 풀도록 역전파로 학습된 가중치이므로, q·k 벡터의 각 숫자 하나하나가 무엇을 뜻하는지는 사람이 직접 짚어 말할 수 없다. 다만 결과적으로 **"문법적·의미적으로 관련된 단어끼리는 query·key의 내적이 커지도록"** 학습이 수렴한다는 것만 알 수 있다 — 3.2의 Multi-Head Attention 시각화(Head 1은 문맥적 관계, Head 2는 시제에 주목)가 이런 학습 결과를 사후적으로 관찰한 사례다.
> 
> **Self-Attention vs Cross-Attention 비교**
> 
> ||Query가 담는 것|Key가 담는 것|
> |---|---|---|
> |Self-Attention|"나(이 단어)는 같은 문장의 어떤 단어 정보가 필요한가"|"나(이 단어)는 어떤 특징으로 검색되는가" — **같은 단어가 둘 다 가짐**|
> |Cross-Attention|"디코더는 지금 원문의 어떤 정보가 필요한가"|"인코더의 이 단어는 어떤 특징을 갖고 있는가" — **서로 다른 시퀀스**|

> [!question]+ 가중합으로 얻은 새로운 표현 $h$는 무엇을 의미하는가
> 
> $h_{\text{어제}} = a_1v_1+\cdots+a_6v_6$는 단순히 "어제"라는 단어 자체가 아니라, **문장 내 다른 단어들과의 관계까지 반영된 문맥적 표현(contextualized representation)**이다. attention score $a_i$가 클수록 그 단어의 value가 더 많이 반영되므로, 결과적으로 $h$는 "이 문장 안에서 나(어제)와 관련이 깊은 단어들의 정보를 가중치대로 섞어 담은 벡터"가 된다.
> 
> 실제로 "어제", "카페", "갔었어" 각각을 기준으로 계산한 attention score를 보면 대체로 **자기 자신에 대한 점수($a_i$)가 가장 크게** 나타나면서도, 문맥상 관련 있는 다른 단어에도 어느 정도 점수가 분산되어 있다. 이 과정을 문장의 모든 단어에 대해 독립적으로(=병렬로) 수행하면, 각 단어마다 "이 문장 안에서 나와 관련된 다른 단어들의 정보를 반영한" 새로운 표현이 만들어진다.

#### Self-Attention 수식화 — Query, Key, Value

앞서 다룬 Q, K, V 생성 및 attention 계산 과정을 수식으로 정리하면 다음과 같다.

**① Q, K, V 벡터 생성**: 각 단어 $i$의 임베딩 $x_i$에 학습 가능한 가중치 행렬 $W^Q,W^K,W^V$를 각각 곱한다.

$$
q_i=W^Qx_i\quad(\text{query}),\qquad
k_i=W^Kx_i\quad(\text{key}),\qquad
v_i=W^Vx_i\quad(\text{value})
$$

**② Query와 Key 간 유사도 계산 후 softmax**

$$
e_{ij}=q_i^\top k_j,\qquad
\alpha_{ij}=\frac{\exp(e_{ij})}{\sum_{j'}\exp(e_{ij'})}
$$

- $e_{ij}$: 단어 $i$의 query와 단어 $j$의 key 사이의 유사도(내적) — 2.3의 dot-product score 방식과 동일한 형태
- $\alpha_{ij}$: softmax로 정규화된 attention 가중치(합이 1)

**③ Value의 가중합으로 출력 계산**

$$
o_i=\sum_j \alpha_{ij}v_j
$$

- Query와 Key로 계산된 score로 value와 가중합을 하여 단어의 출력을 계산한다.

#### Self-Attention의 한계

Self-Attention은 장거리 연결과 병렬화를 가능하게 했지만, 그 자체만으로 완전한 시퀀스 모델이 되는 것은 아니다. 토큰 사이의 관련도만 계산하면 입력 순서를 알 수 없고, Value를 가중합한 것만으로는 각 위치의 표현을 충분히 복잡하게 변환하기 어렵다. 또한 생성 모델의 학습에서는 아직 예측하지 않은 미래 토큰까지 참조할 수 있다는 문제가 생긴다. 이 세 문제는 각각 Positional Encoding, Feed-Forward Network, Masking으로 보완된다.

#### 순서 정보 부재 한계 해결 1 — Positional Encoding

Self-Attention은 토큰의 위치를 바꾸어도 같은 Query·Key 비교를 수행하므로 순서를 별도로 알려주어야 한다. Positional Encoding은 각 위치 $i$를 나타내는 벡터를 단어 임베딩에 더해, 모델이 단어의 의미와 위치를 함께 사용하도록 한다. 위치 벡터는 서로 다른 주기의 사인·코사인 함수로 만드는 **Sinusoidal Position Encoding**이나, 위치별 벡터를 파라미터로 직접 학습하는 **Learned Absolute Position Embedding**으로 만들 수 있다.

#### 비선형성 부족 한계 해결 2 — Feed-Forward Network 추가

Self-Attention은 서로 다른 위치의 정보를 관련도에 따라 결합하지만, 각 위치에서 만들어진 표현을 복잡하게 가공하는 능력은 제한적이다. 따라서 모든 토큰에 동일한 Feed-Forward Network를 독립적으로 적용한다. `Linear → 활성화 함수 → Linear` 구조가 각 위치의 표현을 비선형적으로 변환하여 모델의 표현력을 높인다.

> [!question]+ Self-Attention과 Feed-Forward Network는 각각 어떤 역할을 나누어 맡는가
> 
> Self-Attention 출력 $o_i=\sum_j\alpha_{ij}v_j$은 문장 내 다른 위치의 정보를 관련도에 따라 결합한다. Feed-Forward Network는 이렇게 모은 정보를 각 위치에서 독립적으로 비선형 변환한다.
> 
> 그래서 self-attention 층 바로 위에 각 단어별로 독립적인 Feed-Forward Network(및 ReLU 같은 비선형 활성화 함수)를 얹는다. 즉 self-attention이 "문장 내 어떤 단어의 정보를 얼마나 가져올지"를 결정하는 역할을 맡고, 그 위의 FF 네트워크는 "가져온 정보를 비선형적으로 가공해 더 복잡한 표현으로 변환"하는 역할을 맡는 식으로 **역할을 분업**한다.

> [!note]
> 
> - **같은 층 안에서**: 문장 속 모든 단어 위치가 **동일한** $W^Q,W^K,W^V$와 FFN 가중치를 공유해서 사용함 (단어마다 따로 계산은 하지만, 쓰는 파라미터는 같음)
> - **층과 층 사이에서**: 1층, 2층, ..., N층은 각각 **완전히 독립적인** attention·FFN 파라미터를 가짐 (전혀 공유 안 됨) → 그래서 층(layer)을 하나 쌓을 때마다 그 층 전용 파라미터 세트가 통째로 추가되는 셈이라, 층 수가 늘수록 전체 파라미터 수도 거의 비례해서 늘어남

#### 미래 참조 문제 한계 해결 3 — Masked Self-Attention

생성 모델은 이전 토큰만 보고 다음 토큰을 예측해야 하지만, 기본 Self-Attention은 학습 데이터의 모든 위치를 동시에 참조한다. 그대로 두면 현재 위치가 정답인 미래 토큰을 미리 보는 문제가 생긴다. Masked Self-Attention은 미래 위치의 Attention score를 $-\infty$로 설정하여 softmax 이후 가중치가 0이 되게 한다. 이로써 모든 위치를 병렬로 학습하면서도 각 위치가 과거와 현재 정보만 사용하도록 제한한다.

> [!question]+ Masked Self-Attention에서 왜 하필 $-\infty$로 설정하는가 — softmax와의 연결
> 
> 이는 softmax 공식 $\alpha_{ij}=\dfrac{\exp(e_{ij})}{\sum_{j'}\exp(e_{ij'})}$과 직접 연결된다. 여기에 $e_{ij}=-\infty$를 대입하면 $\exp(-\infty)=0$이 되어, 해당 위치의 attention 가중치 $\alpha_{ij}$가 정확히 0이 된다.
> 
> 가중치가 0이라는 건 곧 ③단계 가중합 $o_i=\sum_j\alpha_{ij}v_j$을 계산할 때 그 단어의 value가 **전혀 반영되지 않는다**는 뜻이다. 즉 "미래 단어를 아예 존재하지 않는 것처럼 취급"하는 효과를, 별도의 조건문 없이 attention score 계산 공식 안에서 자연스럽게 구현하는 방법이다.
> 
> **왜 하필 "$-\infty$"여야 하는가 — "0~1 범위 제한" 때문이 아니다**
> 
> 흔히 헷갈리는 지점인데, 이는 softmax 출력이 0~1 사이라는 일반적 성질 때문이 아니라 **지수함수가 $-\infty$를 정확히 0으로 만들어준다는 성질** 때문이다.
> 
> 수식에서는 $-\infty$로 표현하지만 실제 구현에서는 데이터 타입이 표현할 수 있는 매우 큰 음수를 사용한다. softmax 계산 후 해당 위치의 확률이 수치적으로 0이 되도록 만들어 미래 Value가 가중합에 반영되지 않게 한다.

#### Self-Attention 정리

- Self-Attention은 문장 내 모든 단어가 서로 직접 상호작용하여,

1. 장거리 의존성을 효율적으로 포착하고
2. 병렬 처리를 가능하게 하는 메커니즘

- 한계 해결 방법 총정리
    1. **순서 정보 부재 → Positional Encoding**: 단어 임베딩만으로는 몇 번째 단어인지 알 수 없으므로, 위치 $i$를 나타내는 위치 벡터를 만들어 단어 임베딩에 더한 뒤 입력으로 사용(Sinusoidal / Learned 두 방식)
    2. **비선형성 부족 → Feed-Forward Network 추가**: attention의 가중합 연산은 선형 결합에 불과해 복잡한 패턴을 표현하기 어려우므로, 각 단어 출력 벡터에 Fully Connected + ReLU 등을 추가해 비선형적으로 표현력을 확장
    3. **미래 참조 문제 → Masked Self-Attention**: 언어 생성은 왼쪽에서 오른쪽으로 순차 진행되어야 하는데 Self-Attention은 모든 단어를 동시에 보므로, 미래 단어에 해당하는 attention score를 $-\infty$로 설정해(softmax 결과 0이 되어) 아예 참조되지 않도록 차단
- 전체 구조를 쌓으면: $$\text{Inputs} \to \text{Embeddings}(+\text{Position Embeddings}) \to [\text{Masked Self-Attention} \to \text{Feed-Forward}]\times N \to \text{Linear} \to \text{Softmax} \to \text{Probabilities}$$
- 이 **"Masked Self-Attention + Feed-Forward를 한 블록으로 삼아 여러 번 쌓는 구조"**가 다음에 배울 **Transformer**의 핵심 구성 요소

### 3.2 Transformer

Self-Attention만으로는 순서 정보, 표현력, 안정적인 심층 학습을 모두 해결할 수 없다. Transformer는 Positional Encoding, Feed-Forward Network, Masking, Multi-Head Attention, Residual Connection, Layer Normalization을 하나의 블록 구조로 결합한다.

#### Attention Is All You Need

Transformer는 2017년 Google이 발표한 「Attention Is All You Need」에서 제안되었다. 제목이 나타내듯 RNN이나 CNN의 순환·합성곱 구조 대신 Self-Attention을 중심 연산으로 사용한다. 앞에서 본 Positional Encoding, Feed-Forward Network와 Masking에 깊은 네트워크를 안정적으로 학습하기 위한 구성 요소를 더해 완전한 Encoder-Decoder 아키텍처를 만들었다.

#### Transformer의 전체 구조

Transformer도 Seq2Seq처럼 Encoder와 Decoder로 나뉜다. Encoder는 입력 전체를 양방향으로 참조해 문맥적 표현을 만들고, Decoder는 Encoder의 표현과 지금까지 생성한 토큰을 사용해 다음 토큰을 예측한다. Decoder의 Masked Self-Attention은 2.1에서 본 $p(w_t\mid w_1,\ldots,w_{t-1})$의 조건부 확률 구조를 구현한다.

#### 여러 관계를 동시에 학습하는 Multi-Head Attention

하나의 Attention 분포만 사용하면 토큰 사이의 관계를 한 가지 표현 공간에서만 계산한다. 그러나 같은 단어도 문법적 관계, 시제, 의미적 참조처럼 여러 관계에 동시에 참여할 수 있다. 예를 들어 한 Head는 문맥적 관계에, 다른 Head는 시제에, 또 다른 Head는 명사와의 관계에 주목할 수 있다. Multi-Head Attention은 서로 다른 $W^Q$, $W^K$, $W^V$를 사용하는 여러 Head를 두어 이러한 관계를 병렬로 학습한다. 따라서 같은 토큰을 Query로 사용해도 Head마다 다른 Attention 분포가 만들어질 수 있다.

#### 큰 내적값을 안정화하는 Scaled Dot-Product Attention

Query와 Key의 차원이 커지면 내적의 분산도 커지는 경향이 있다. 큰 내적값이 softmax에 들어가면 하나의 항에 확률이 지나치게 몰리고 나머지 항은 거의 0이 되어 기울기가 약해질 수 있다. 예를 들어 $\text{softmax}([40,50,45])\approx[0.000045,0.99326,0.00669]$처럼 극단적인 분포가 만들어진다. Scaled Dot-Product Attention은 이를 막기 위해 내적을 Query·Key 차원 $d_k$의 제곱근으로 나눈다.

$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

- 전체 차원 $d$를 $h$개 head로 균등하게 나누면 일반적으로 head당 차원은 $d_k=d/h$이므로 $\sqrt{d/h}$와 같은 표현이 된다.
    - 같은 예시를 8로 나누면: $\text{softmax}([5.00,6.25,5.625]) \approx [0.1573,\ 0.5489,\ 0.2938]$
이 조정은 내적의 분산이 차원에 따라 커지는 현상을 상쇄하여 softmax가 지나치게 포화되지 않도록 하고 학습을 안정화한다.

> [!question]+ 왜 차원이 커지면 내적 값도 커지고, 그게 왜 문제가 되는가
> 
> 내적은 각 차원의 값을 곱해서 더하는 연산이다($q\cdot k=\sum_i q_ik_i$). 차원 수 $d$가 늘어나면 더해지는 항의 개수도 늘어나므로, 각 항이 평균적으로 비슷한 크기를 가진다고 가정할 때 내적 값의 절댓값(정확히는 분산)이 차원 수에 비례해서 커지는 경향이 있다.
> 
> 문제는 이 커진 내적 값이 그대로 softmax의 입력으로 들어간다는 것이다. softmax는 입력 값들의 차이를 지수적으로 증폭시키는 함수이기 때문에, 입력 값 자체가 크면(예: 40,50,45) 값들 사이의 상대적 차이도 함께 커져서 출력이 거의 원-핫에 가까운 극단적인 분포가 되어버린다(0.99326처럼 하나에 쏠림). 이렇게 극단적으로 뾰족한 분포에서는 대부분의 출력 항이 거의 0이나 1에 붙어버려, 역전파 시 그 항들의 기울기도 거의 0이 되어(포화 상태) 학습 신호가 사라진다 — 이것이 gradient vanishing이다.
> 
> $\sqrt{d_k}$로 나누면 내적 분산이 차원에 따라 커지는 현상을 상쇄하여 softmax가 지나치게 포화되는 것을 줄인다.

#### 깊은 네트워크의 학습을 돕는 Residual Connection

> Residual connection은 각 sublayer의 변환 결과에 해당 sublayer의 입력을 더하는 구조이며, 네트워크의 마지막이 아니라 각 블록에서 반복 적용된다.
> 
> 각 층에서: **층의 출력 = (원래 입력 x) + (x가 layer를 통과한 결과)** → 이 둘을 더한 값이 다음 층으로 넘어감
> 
> 즉 layer를 거치지 않은 원래 정보($x$)를 그대로 더해줌으로써, 층을 아무리 많이 쌓아도 원래 입력 정보가 유지되며 다음 층으로 전달된다.

- 깊은 신경망은 층이 깊어질수록 학습이 어려워짐(gradient vanishing/exploding)
- 단순히 layer의 출력만 사용하면 정보가 소실될 수 있음 → layer가 전체를 예측하는 대신, **기존 입력과의 차이(잔차)만 학습**하도록 하는 residual connection을 사용 $$X^{(i)} = X^{(i-1)} + \text{Layer}(X^{(i-1)})$$

> [!question]+ 왜 "전체를 예측"하는 대신 "차이(잔차)만 학습"하면 더 쉬워지는가
> 
> Layer가 $X^{(i-1)}$을 입력받아 $X^{(i)}$ 전체를 처음부터 새로 만들어내야 한다면, 층이 깊어질수록 각 층은 "지금까지의 모든 정보를 잃지 않고 다음 층으로 정확히 전달"하는 부담까지 함께 져야 한다. 조금이라도 정보를 잘못 변환하면 뒤 층으로 갈수록 오차가 누적된다.
> 
> 반면 $X^{(i)}=X^{(i-1)}+\text{Layer}(X^{(i-1)})$처럼 **입력을 그대로 다음 층까지 직접 이어주는 통로(identity shortcut)**를 만들어두면, Layer는 "입력을 얼마나 바꿔야 하는가(잔차)"만 학습하면 된다. 극단적으로 Layer가 아무것도 학습하지 못해 출력이 0이더라도, $X^{(i)}=X^{(i-1)}$이 되어 최소한 입력 정보는 그대로 보존된다. 즉 "정보를 보존하는 것"이 기본값이 되고 그 위에 "필요한 만큼만 수정"하는 것이 학습 목표가 되므로 훨씬 안정적으로 최적화된다.
> 
> 이는 3.1과 1.3에서 다룬 기울기 소실 문제와도 연결된다. Residual connection의 항등 경로는 역전파 시 기울기가 직접 전달되는 경로를 추가하므로, 깊은 네트워크의 최적화를 안정시키고 기울기 소실을 완화한다.

#### Layer Normalization

층이 깊어지면 hidden vector의 값 분포가 계속 변해 학습이 불안정해질 수 있다. Layer Normalization은 각 토큰 표현의 feature 차원을 기준으로 평균과 분산을 정규화한다. Transformer 도식에서는 Residual Connection과 Layer Normalization을 묶어 **Add & Norm**으로 표시한다.

#### Decoder 블록 구조

- Transformer의 decoder는 여러 개의 decoder 블록을 쌓아 만든 구조. 각 블록은:
    1. **Masked Self-Attention (Multi-Head)**: 미래 단어를 보지 않도록 마스크를 씌운 Multi-Head Self-Attention
    2. **Add & Norm** (Residual Connection + Layer Normalization)
    3. **Cross-Attention (Multi-Head)**: Decoder의 표현을 Query로, Encoder 출력을 Key·Value로 사용
    4. **Add & Norm** (Residual Connection + Layer Normalization)
    5. **Feed-Forward Network**: 각 위치별 비선형 변환
    6. **Add & Norm** (Residual Connection + Layer Normalization)
- → 언어 모델처럼 **단방향 문맥만 활용**

#### Encoder 블록 구조

Transformer Encoder는 입력 문장 전체를 표현하는 것이 목적이므로 미래를 가릴 필요가 없다. causal mask 없이 Self-Attention을 수행하여 각 토큰이 앞뒤 문맥을 모두 반영한 벡터로 인코딩된다. 반면 Decoder는 생성 중 미래를 볼 수 없으므로 Masked Self-Attention을 사용하며, Encoder의 출력까지 참조하기 위한 Cross-Attention sublayer를 추가한다.

#### Encoder-Decoder 연결: Cross-Attention

기계 번역에서 Decoder는 자신이 지금까지 만든 출력뿐 아니라 번역할 원문도 함께 참고해야 한다. 이를 위해 Cross-Attention은 Query를 Decoder에서 만들고, Key와 Value는 Encoder의 출력에서 가져온다. Decoder는 현재 생성 문맥으로 "원문의 어떤 정보가 필요한가"를 묻고, Encoder의 각 토큰 표현에서 관련된 정보를 선택해 가져온다.

> [!question]+ Encoder-Decoder에서 Decoder는 Query, Encoder는 Key/Value를 갖는다는 게 무슨 뜻인가 — Cross-Attention
> 
> Encoder-Decoder 구조에서는 Self-Attention과 달리 Query와 Key/Value의 출처가 나뉜다.
> 
> - **Decoder**: "지금 원문의 어떤 부분이 필요한가"를 묻는 **Query**
> - **Encoder**: 원문을 다 읽고 만들어둔 각 단어의 **Key/Value**("나는 이런 정보를 갖고 있어")
> 
> Decoder가 단어를 하나 생성할 때마다 Query를 만들고, 이를 Encoder의 각 Key와 내적해 유사도를 구한 뒤, 관련도가 높은 단어일수록 큰 가중치로 Value들을 **가중합**해서 필요한 원문 정보를 가져온다. 이 과정이 생성 스텝마다 반복된다.
> 
> |구분|Query 출처|Key/Value 출처|
> |---|---|---|
> |Self-Attention|같은 시퀀스|같은 시퀀스|
> |Cross-Attention|Decoder|Encoder|
> 
> **2.3 Seq2Seq Attention과의 관계**
> 
> 2.3의 Seq2Seq Attention(디코더 hidden state=Query, 인코더 hidden state=Key/Value)과 핵심 아이디어는 동일하다. Transformer의 Cross-Attention은 이를 별도로 학습된 $W^Q,W^K,W^V$, Scaled Dot-Product, Multi-Head 같은 정교한 도구로 구현한 버전이라는 점이 차이다.

> [!question]+ Cross-Attention의 residual connection은 어떤 정보를 결합하는가
> 
> Decoder의 Cross-Attention 출력은 Decoder Query와 Encoder Key의 관련도에 따라 Encoder Value를 가중합한 벡터다.
> 
> residual connection 공식(출력 = 원래 입력 + layer 통과 결과)을 대입하면:
> 
> - $x$(원래 입력) = Cross-Attention 이전의 **Decoder 상태**
> - $\text{Layer}(x)$ = Cross-Attention이 선택한 **Encoder 정보**
> 
> 두 표현을 더하면 Decoder가 현재까지 형성한 출력 문맥을 유지하면서, 입력 시퀀스에서 선택한 정보를 함께 반영할 수 있다.

#### Transformer의 놀라운 결과

Transformer는 기계 번역에서 당시 최고 수준의 BLEU 점수를 기록했으며, 기존 주요 모델보다 적은 학습 연산량으로 높은 성능을 보였다. 더 중요한 변화는 순환 구조를 제거해 대규모 병렬 학습에 적합한 기반을 만들었다는 점이다.

> [!warning] Transformer와 Neural Architecture Search의 구분
>
> Transformer는 학습 과정에서 RNN·CNN·MLP 중 하나의 구조를 자동으로 선택하는 Neural Architecture Search 모델이 아니다. Self-Attention과 Feed-Forward Network로 구성된 구조는 사람이 미리 정의한다. 학습되는 것은 그 구조 안의 가중치이며, attention head마다 번역 과제에 유용한 단어 관계와 표현을 서로 다르게 학습할 수 있다.

#### Transformer와 사전학습(pretraining)

Transformer의 병렬 처리 능력은 대규모 텍스트를 효율적으로 학습할 수 있게 했다. 각 태스크마다 작은 레이블 데이터로 모델을 처음부터 만드는 대신, 방대한 일반 텍스트에서 언어 구조를 먼저 학습하고 필요한 태스크에 적응시키는 사전학습 방식이 빠르게 표준이 되었다. DeBERTa, StructBERT, ALBERT, ERNIE, T5 등 GLUE 상위권 모델도 모두 Transformer와 사전학습을 결합한 구조다.

> [!question]+ "사전학습을 결합하도록 만들었다"는 것이 구체적으로 어떤 의미인가
> 
> Transformer 등장 이전에는 각 NLP task(번역, 감성분석 등)마다 필요한 만큼의 (레이블이 있는) 데이터로 모델을 **처음부터 학습**시키는 방식이 일반적이었다. 그런데 레이블이 붙은 데이터는 만들기 비싸고 양이 제한적이라, task별로 모델이 배울 수 있는 정보의 양에도 한계가 있었다.
> 
> Transformer는 병렬 처리가 가능해 레이블이 없는 대량의 텍스트(예: 인터넷 문서 전체)로도 효율적으로 학습할 수 있게 되면서, 다음과 같은 2단계 접근이 표준이 되었다:
> 
> 1. **사전학습(pretraining)**: 레이블 없는 방대한 텍스트로 "언어 자체"를 먼저 학습(예: 문장의 빈칸 채우기, 다음 단어 예측 등 — 2.1에서 다룬 언어모델의 확률 예측 방식과 같은 원리)
> 2. **미세조정(fine-tuning)**: 이렇게 언어에 대한 폭넓은 이해를 갖춘 모델을, 실제로 풀고 싶은 특정 task(번역, 분류 등)에 맞춰 비교적 적은 데이터로 추가 학습
> 
> 즉 매번 각 task마다 모델을 새로 처음부터 학습시키는 대신, **이미 사전학습된 Transformer를 가져와 fine-tuning만 하면 훨씬 적은 데이터로도 더 높은 성능**을 낼 수 있게 된 것이다. 이 "대규모 사전학습 + Transformer" 조합이 이후 BERT, GPT, T5 같은 대표적인 모델들의 공통된 접근법이 되었다.

---

## 4. 하나의 구조에서 여러 사전학습 모델로 — BERT, T5, GPT와 In-Context Learning

Transformer는 RNN의 순차 계산 제약을 제거하여 대규모 텍스트를 병렬로 학습하기에 적합했다. 이 계산 구조가 사전학습과 결합하면서 NLP의 개발 방식도 달라졌다. 과제마다 모델을 처음부터 만드는 대신, 방대한 텍스트에서 언어의 일반 패턴을 먼저 학습한 뒤 비교적 적은 데이터로 개별 과제에 적응시키는 방식이 표준이 되었다.

이후의 모델은 하나가 앞선 모델을 차례로 대체한 단일 계보라기보다, Transformer의 어느 부분을 사용하고 어떤 목표로 사전학습하는지에 따라 여러 갈래로 분화했다. BERT는 Encoder를 이용해 양방향 문맥 이해에 집중했고, T5는 Encoder와 Decoder를 모두 사용해 입력을 다른 텍스트로 변환했다. GPT는 Decoder의 다음 토큰 예측 능력을 확장해 생성에 집중했다. 모델과 데이터의 규모가 커지면서 GPT 계열에서는 파라미터를 다시 학습하지 않고 프롬프트의 예시만으로 과제를 수행하는 In-Context Learning도 두드러지기 시작했다.

> [!info] 학습 목표
> 
> - 사전학습(Pretraining)의 개념과 필요성을 설명할 수 있다
> - Encoder 기반 모델(예: BERT)의 구조와 주요 활용 사례를 이해한다
> - Encoder-Decoder 기반 모델(예: T5)의 특징과 응용 분야를 설명할 수 있다
> - Decoder 기반 모델(예: GPT)의 구조와 강점을 이해한다
> - In-Context Learning(ICL)이 등장하게 된 배경과 그 의미를 설명할 수 있다
> - ICL 능력을 끌어올리기 위한 대표적인 prompting 기법(CoT, Zero-shot CoT)을 이해한다

> [!question] 이 단원에서 답할 질문
> 
> 1. 사전학습(Pretraining)이란 무엇인가? 왜 중요한가? — 대규모 데이터 기반의 사전학습 개념과 필요성
> 2. 대표적 모델 유형은 어떻게 구분되는가? — Encoder 기반 / Encoder-Decoder 기반 / Decoder 기반
> 3. 각각 어떤 모델이 존재하는가? — BERT, T5, GPT 등 주요 모델 소개
> 4. In-Context Learning과 발전된 prompting 기법은 무엇인가? — ICL의 등장 배경과 의미 / Chain-of-Thought, Zero-shot CoT 등 대표 기법

**용어 정리**

|용어|의미|
|---|---|
|**사전학습(Pretraining)**|특정 다운스트림 태스크에 적용하기 전, 대규모 데이터와 사전학습 목적함수로 일반적인 표현과 패턴을 학습하는 단계|
|**다운스트림 태스크(Downstream Task)**|사전학습된 모델을 **실제로 적용하고 싶은 구체적인 문제**(예: 감정 분류, 개체명 인식, 질의응답, 문장 유사도 판단 등)|
|**파인튜닝(Fine-tuning)**|사전학습된 모델을, 그 다운스트림 태스크에 맞도록 **추가로 학습(조정)시키는 과정**|

### 4.1 사전학습(Pretraining)이란

레이블이 붙은 데이터는 만들기 어렵고 양도 제한적이다. 특정 과제의 데이터만으로 모델을 처음부터 학습하면 언어에 대한 일반적인 지식까지 그 작은 데이터에서 모두 배워야 한다. 사전학습은 이 부담을 두 단계로 나눈다. 먼저 대규모 텍스트에서 언어 자체의 패턴을 학습하고, 그다음 실제로 풀고 싶은 문제에 맞게 모델을 조정한다.

#### 사전학습(Pretraining)이란

사전학습은 대규모 데이터에서 일반적인 특징과 표현을 먼저 학습하는 과정이다. 언어 모델은 웹 문서, 책, 뉴스처럼 레이블이 없는 텍스트에서도 일부 토큰을 가리거나 다음 토큰을 예측하는 목표를 입력 자체에서 만들 수 있다. 이를 **자기지도학습(Self-Supervised Learning)**이라고 한다.

이 접근은 다양한 텍스트·이미지·음성 데이터로 하나의 범용 **Foundation Model**을 학습한 뒤, 질의응답·감성 분석·정보 추출과 같은 여러 태스크에 적응시키는 흐름으로 확장되었다.

#### 언어모델의 사전학습 방식

언어 모델은 대규모 텍스트 코퍼스에서 언어 모델링을 수행한 뒤 학습된 파라미터를 저장한다. 이 파라미터에는 단어 사용, 문장 구조, 문맥 관계와 같은 일반적인 패턴이 반영되어 있으며, 이후 여러 다운스트림 태스크의 출발점으로 재사용된다.

#### Pretrain → Fine-tuning 패러다임

첫 단계인 **Pretraining**에서는 방대한 텍스트로 일반적인 언어 패턴을 학습한다. 두 번째 단계인 **Fine-tuning**에서는 적은 양의 레이블 데이터로 모델을 특정 태스크에 맞게 조정한다. Fine-tuning은 사전학습된 backbone과 파라미터를 출발점으로 사용하며, 필요하면 분류기 같은 출력층을 추가한다. 따라서 언어를 처음부터 다시 배우는 대신 이미 형성된 표현을 실제 문제에 맞게 조정할 수 있다.

### 4.2 Encoder 모델

Transformer Encoder는 입력 전체를 동시에 보며 각 토큰의 양방향 문맥 표현을 만든다. 이 특성은 텍스트를 새로 생성하는 것보다 주어진 문장을 이해하고 분류하거나, 각 토큰의 역할을 판별하는 문제에 적합하다. 대표적인 Encoder-only 사전학습 모델이 BERT다.

#### Encoder / Encoder-Decoder / Decoder 모델 개요

Transformer 기반 사전학습 모델은 사용하는 블록 구성에 따라 Encoder-only, Encoder-Decoder, Decoder-only의 세 유형으로 나뉜다. 각 구조는 사용할 수 있는 문맥 범위와 적합한 태스크가 다르다.

||특징|
|---|---|
|**Encoders**|양방향 문맥을 활용할 수 있음|
|**Encoder-Decoders**|Encoder와 Decoder의 장점을 모두 결합|
|**Decoders**|전형적인 언어 모델 구조, 문장 생성에 유용(미래 단어 참조 불가)|

#### Encoder 모델의 사전학습 — Masked Language Model(MLM)

일반적인 자기회귀 언어 모델은 이전 토큰으로 다음 토큰을 예측한다. 반면 MLM은 입력 일부를 가리고 앞뒤 문맥으로 원래 토큰을 복원한다.

Encoder는 입력 전체의 양방향 문맥을 활용하므로, 왼쪽 문맥만 사용하는 다음 토큰 예측보다 마스킹된 위치를 앞뒤 문맥으로 복원하는 목표가 적합하다. 입력 일부를 `[MASK]`로 치환하고 원래 단어를 예측하도록 학습하는 방법을 **Masked Language Model(MLM)**이라고 한다. 이를 대표적으로 사용한 모델이 Google이 2018년에 공개한 BERT다.

#### BERT의 학습 방법 1 — Masked LM

BERT는 입력 토큰의 15%를 선택한다. 선택된 토큰 중 80%는 `[MASK]`로 바꾸고, 10%는 임의의 다른 토큰으로 바꾸며, 나머지 10%는 원래 토큰을 유지한다. 해당 위치의 Encoder 출력을 FFNN과 Softmax에 통과시켜 전체 단어 사전에 대한 확률분포를 만들고 원래 단어를 예측한다.

> [!question]+ 왜 [MASK]만 쓰지 않고 80/10/10 비율로 섞는가
> 
> [MASK]만 사용하면 모델이 "지금 [MASK] 토큰이니까 신경 써서 문맥을 보자"는 식으로 **[MASK]라는 신호 자체에만 반응하도록 편향**될 수 있다. 문제는 실제 downstream task(fine-tuning)에서는 입력에 [MASK]라는 토큰이 전혀 등장하지 않는다는 것 — 즉 사전학습과 실제 사용 환경 사이에 불일치가 생긴다.
> 
> 무작위 토큰과 원래 토큰을 일부 섞으면 예측 대상이 항상 [MASK]로 표시되지 않는다. 따라서 모델은 [MASK] 신호에만 의존할 수 없고, 실제 입력 토큰과 문맥을 함께 사용해야 한다. 핵심 목적은 사전학습에서만 등장하는 [MASK]와 fine-tuning·추론 시 실제 입력 사이의 불일치를 줄이는 것이다.

#### BERT의 학습 방법 2 — Next Sentence Prediction(NSP)

- BERT는 입력을 **두 개의 연속된 텍스트**로 받아, 두 번째 문장이 첫 번째 문장의 실제 다음 문장인지 여부를 예측하는 **NSP**를 MLM과 함께 수행
- **입력 구조**: `[CLS] 문장A [SEP] 문장B [SEP]`
    - 최종 입력 임베딩 = **Token Embeddings + Segment Embeddings + Position Embeddings**
    - Segment Embeddings($E_A/E_B$): 해당 토큰이 첫 번째 문장인지 두 번째 문장인지 구분
    - Position Embeddings: 3.1의 위치 정보(Positional Encoding)와 같은 역할
- **특수 토큰**: **[CLS]**(항상 맨 앞, 문장 전체를 대표) / **[SEP]**(두 세그먼트를 구분)
- **예시**: "the man went to [MASK] store [SEP] he bought a gallon [MASK] milk [SEP]" → IsNext(자연스럽게 이어짐) / "the man [MASK] to the store [SEP] penguin [MASK] are flightless birds [SEP]" → NotNext(관련 없음)
- 동작: **[CLS] 위치의 출력**을 FFNN+Softmax에 통과시켜 IsNext/NotNext 확률을 예측
- BERT는 MLM과 NSP를 **공동으로 학습**한다. NSP는 [CLS] 위치의 출력을 사용하고, MLM은 선택된 토큰 위치의 출력을 사용한다. 두 목적함수의 기울기는 Transformer 전체 표현에 함께 반영된다.

#### BERT의 다운스트림 태스크

|구분|의미|
|---|---|
|**다운스트림 태스크**|BERT를 파인튜닝해서 실제로 풀고자 하는 구체적 목표 — MNLI, QQP, SST2, SQuAD, NER 등|
|**Sentence Level / Token Level**|그 다운스트림 태스크들이 "BERT의 어떤 출력을 활용하는 방식인지"에 따라 묶은 **분류 기준(카테고리)**|

**Sentence Level (문장/문장쌍 수준 — [CLS] 출력 활용)**

- **두 문장 관계 분류**: MNLI(전제·가설 관계를 {함의, 모순, 중립}으로 분류), QQP(두 질문이 같은 의미인지 {중복, 비중복}으로 분류)
- **단일 문장 분류**: SST2(감성분석, {긍정, 부정})
- 입력 구조: Sentence(Pair) → **[CLS] 위치 출력**을 분류기에 넣어 문장(쌍) 수준 예측

**Token Level (토큰 수준 — 각 토큰 출력 활용)**

- **QA(SQuAD)**: Question [SEP] Paragraph를 입력받아, 문맥의 각 토큰 위치에서 정답의 **시작/끝 위치(Start/End Span)**를 예측
- **개체명 인식(NER, CoNLL 2003)**: 각 토큰마다 개체명 라벨 예측. 예: "John Smith lives in New York" → John(B-PER), Smith(I-PER), lives(O), in(O), New(B-LOC), York(I-LOC) — B-/I-는 각각 개체명의 시작 단어/나머지 단어를 구분

> [!question]+ 왜 어떤 태스크는 [CLS]만 쓰고, 어떤 태스크는 토큰별 출력을 쓰는가
> 
> 출력 선택은 다운스트림 태스크가 문장 전체의 판단을 요구하는지, 토큰별 판단을 요구하는지에 따라 결정된다.
> 
> - **[CLS] 출력**은 입력 전체를 attention으로 반영한 하나의 벡터이므로 문장·문장쌍 수준 분류에 사용하기 편리하다. 원래 BERT에서는 NSP 분류에도 이 위치를 사용했다.
> - **각 토큰의 출력**은 해당 위치의 문맥적 표현이므로 개체명 인식이나 정답 span 예측처럼 위치별 판단이 필요한 태스크에 사용한다.
> 
> 따라서 fine-tuning에서는 필요한 출력 단위에 맞춰 문장 전체 표현 또는 토큰별 표현을 선택한다.

#### BERT의 결과

핵심은 BERT가 하나의 사전학습 모델을 여러 이해 중심 태스크에 fine-tuning할 수 있는 범용성을 보여주었다는 점이다.

BERT는 하나의 사전학습 모델을 여러 이해 중심 태스크에 Fine-tuning할 수 있음을 보여주었다. GLUE 평균 점수는 기존 SOTA 74.0과 OpenAI GPT 75.1에 비해 BERT_BASE가 79.6, BERT_LARGE가 82.1을 기록했다. 또한 층 수, hidden state 크기, Attention Head 수가 커질수록 성능이 향상되는 경향이 관찰되었다. 예를 들어 3층 모델과 비교해 24층 모델에서는 perplexity가 낮아지고 MNLI·MRPC·SST-2 정확도가 꾸준히 높아졌다.

#### BERT의 한계

BERT는 입력 전체를 양방향으로 이해하도록 학습되었지만, 텍스트를 한 토큰씩 생성하는 구조는 아니다. 생성 태스크에서는 이전 출력만 보고 다음 토큰을 자기회귀적으로 예측해야 하는데, 양방향 문맥으로 `[MASK]` 위치를 복원하는 Encoder의 학습 방식은 이를 자연스럽게 구현하지 못한다. 따라서 BERT는 문장과 토큰을 이해하는 문제에 강하고, 순차 생성에는 Decoder나 Encoder-Decoder 구조가 더 적합하다.

### 4.3 Encoder-Decoder 모델

Encoder-only 모델은 입력 이해에 강하지만 출력 시퀀스를 직접 생성하는 데에는 한계가 있다. 입력 전체를 양방향으로 이해하면서도 새로운 텍스트를 자기회귀적으로 만들려면 Encoder와 Decoder를 함께 사용할 수 있다. T5는 이 구조를 사전학습하고 여러 NLP 태스크를 모두 텍스트 변환 문제로 통일했다.

#### Encoder-Decoder 모델이란

Encoder-Decoder 구조에서 Encoder는 입력 문장의 양방향 문맥을 파악하고, Decoder는 그 표현을 참조해 출력을 자기회귀적으로 생성한다. 입력 이해와 출력 생성을 모두 수행할 수 있지만, 두 구조를 함께 어떤 목표로 사전학습할지가 필요했다. T5는 손상된 입력을 원래 텍스트로 복원하게 하여 Encoder와 Decoder를 함께 훈련했다.

#### T5 (Text-to-Text Transfer Transformer)

T5(Text-to-Text Transfer Transformer)는 Google Research가 2019년에 공개한 Transformer Encoder-Decoder 모델이다. 핵심 발상은 번역, 문법성 판단, 문장 유사도, 요약처럼 출력 형식이 서로 다른 과제를 모두 **Text-to-Text** 형식으로 통일하는 것이다.

예를 들어 다음처럼 태스크를 나타내는 문구와 입력을 텍스트로 제공하고 결과도 텍스트로 출력한다.

- `"translate English to German: That is good."` → `"Das ist gut."` (번역)
- `"cola sentence: The course is jumping well."` → `"not acceptable"` (문법성 판단)
- `"stsb sentence1: ... sentence2: ..."` → `"3.8"` (문장 유사도 점수)
- `"summarize: state authorities dispatched..."` → 요약문

입력과 출력이 모두 텍스트이므로 태스크마다 별도의 분류기나 span 예측기를 새로 만들지 않고 동일한 모델 구조를 재사용할 수 있다.

#### T5의 학습 방법 — Span Corruption

Encoder-Decoder 구조를 함께 훈련하려면 Encoder가 손상된 입력을 읽고 Decoder가 사라진 내용을 생성하도록 만들 수 있다. T5는 개별 단어가 아니라 연속된 토큰 구간을 제거하는 **Span Corruption**을 사용한다.

과정은 다음과 같다.

1. 입력 문장에서 **연속된 토큰(span)**을 무작위로 선택해 제거한다.
2. 제거된 부분을 특수 placeholder 토큰으로 치환한다. 예: `<X>`, `<Y>`
3. Decoder는 각 placeholder에 해당하는 원래 span을 복원하도록 학습한다.

예를 들어 입력이 `Thank you <X> me to your party <Y> week.`라면 목표 출력은 `<X> for inviting <Y> last <Z>`가 된다.

> [!question]+ BERT의 MLM과 T5의 Span Corruption은 무엇이 다른가
> 
> - **BERT MLM**: 개별 토큰 하나하나를 무작위로 [MASK]로 치환하고, Encoder만으로 그 자리의 원래 단어를 양방향 문맥을 보고 **한 번에(비자기회귀적으로)** 예측
> - **T5 Span Corruption**: 여러 토큰이 이어진 **연속된 구간(span)** 전체를 하나의 placeholder로 치환하고, Decoder가 그 구간을 **자기회귀적으로(2.2) 순차 생성**해 복원
> - 즉 BERT의 목적함수는 "개별 단어를 문맥으로 채우기"에 특화되어 이해 능력 위주로 학습되는 반면, T5는 Decoder까지 함께 학습하므로 span 전체를 순서대로 만들어내는 **생성 능력**을 자연스럽게 훈련하게 됨
> - → 4.2에서 정리한 BERT의 한계("생성 태스크에 부적합")를, Encoder-Decoder 구조 + Span Corruption 학습법으로 보완한 것으로 이해할 수 있음

#### T5의 다운스트림 태스크와 성능

- **NLU**(GLUE, SuperGLUE), **QA**(SQuAD), **요약**(CNNDM), **번역**(En→De, En→Fr, En→Ro) 등 다양한 태스크에서 모두 좋은 성능을 보여 **범용적으로 활용될 수 있는 모델**임을 입증
- 아키텍처(Encoder-decoder / Language model / Prefix LM) × 목적함수(Denoising / LM) 조합을 비교한 실험에서, **"Denoising 목적함수 + Encoder-decoder 구조"**(같은 파라미터 수 2P 기준) 조합이 GLUE·SQuAD·SGLUE·번역 등 대부분의 지표에서 가장 우수한 성능을 기록

|아키텍처|목적함수|GLUE|SQuAD|SGLUE|
|---|---|---|---|---|
|**Encoder-decoder**|**Denoising**|**83.28**|**80.88**|**71.36**|
|Language model|Denoising|74.70|61.14|55.02|
|Encoder-decoder|LM|79.56|76.02|64.29|

(Denoising = Span Corruption 방식의 학습을 의미)

→ Encoder-Decoder 구조가 Encoder만 있는 구조(BERT류)와 Decoder만 있는 구조(GPT류) 각각의 한계를 보완하며, 범용적으로 강력한 성능을 낼 수 있음을 실증적으로 보여줌

### 4.4 Decoder 모델

Encoder-Decoder 구조는 입력과 출력이 모두 있는 변환 문제에 강하지만, 입력을 별도로 인코딩하지 않고 하나의 문맥을 계속 이어 쓰는 생성 문제에는 Decoder-only 구조만으로도 충분하다. Decoder는 이전 토큰만 볼 수 있도록 마스킹된 Self-Attention을 사용하고, 다음 토큰 예측이라는 단순한 목표로 대규모 텍스트를 학습한다. 이 방향을 확장한 대표적인 계열이 GPT다.

#### Decoder 모델이란 (재확인)

Decoder는 미래 토큰을 참조하지 않고 왼쪽에서 오른쪽으로 다음 토큰을 예측하는 전형적인 언어 모델 구조다. 양방향 문맥을 한 번에 이해하는 데에는 제약이 있지만, 사전학습과 실제 생성에서 같은 다음 토큰 예측 방식을 사용할 수 있다는 장점이 있다.

#### Finetuning Decoder

Transformer Decoder는 사전학습에서 **다음 토큰 예측(Next Token Prediction)**을 학습한다. 대화나 요약처럼 출력이 시퀀스인 태스크에서는 같은 목표로 Fine-tuning할 수 있어 생성에 자연스럽게 연결된다. 분류 태스크에서는 마지막 hidden state 위에 새로운 Linear Layer를 붙여 분류기로 사용하며, Fine-tuning할 때 이 출력층과 Decoder 전체가 함께 조정된다.

#### GPT-1

GPT-1은 OpenAI가 2018년에 공개한 Transformer Decoder 모델이다. 12개의 Decoder 블록을 쌓고 왼쪽 문맥으로 다음 단어를 예측하는 Autoregressive Language Modeling으로 사전학습했다.

#### GPT-2

GPT-2는 OpenAI가 2019년에 공개한 GPT-1의 확장 모델이다. 더 많은 데이터와 더 큰 파라미터를 사용하면서 자연스러운 장문 생성 능력이 크게 향상되었다. 사람이 유니콘 발견에 관한 짧은 도입부만 제공해도 그 문맥에 이어지는 후속 글을 생성할 수 있었고, 별도의 태스크별 Fine-tuning 없이도 입력 문맥이 모델의 수행 방식을 어느 정도 결정할 수 있음을 보여주었다. 이 가능성은 더 큰 GPT-3에서 In-Context Learning으로 분명하게 나타났다.

### 4.5 In-Context Learning

기존의 Pretrain–Fine-tuning 패러다임에서는 새로운 과제를 수행할 때 모델의 파라미터를 추가로 학습했다. 그러나 모델 규모가 커지자 파라미터를 바꾸지 않고도 프롬프트에 적힌 설명과 예시만으로 새로운 과제의 패턴을 파악하는 능력이 두드러졌다. 이를 In-Context Learning이라고 한다.

> [!info] Learning과 Training의 구분
>
> - **Training**: 손실을 계산하고 파라미터를 갱신하는 최적화 과정
> - **Learning**: 문맥에서 규칙이나 패턴을 파악해 문제 수행 방식이 달라지는 현상까지 포함하는 더 넓은 표현
>
> In-Context Learning은 추론 중 파라미터를 갱신하지 않으므로 training은 아니지만, 프롬프트의 예시에 따라 수행 규칙을 추론한다는 의미에서 learning이라 부른다.

#### GPT-3와 In-Context Learning

GPT-3는 OpenAI가 2020년에 공개한 1,750억 개 파라미터 규모의 모델이다. GPT-2보다 모델 크기를 크게 확장하면서, 별도의 Fine-tuning 없이 문맥 속 설명과 예시만 보고 새로운 태스크를 수행하는 능력이 뚜렷해졌다. 이 능력을 **In-Context Learning**이라고 한다.

#### In-Context Learning의 동작 방식

모델에 태스크의 설명과 예시를 함께 주면, 모델은 문맥에서 입출력 패턴을 찾아 같은 형식의 답을 생성한다. 예를 들어 `thanks→merci, hello→bonjour, mint→menthe, otter→`를 입력하면 `loutre`를 이어 생성할 수 있다.

여기에는 서로 다른 두 층위의 학습이 있다. 사전학습에서는 SGD를 통해 실제 파라미터가 갱신된다. 반면 In-Context Learning은 사전학습이 끝난 모델의 파라미터를 고정한 채 하나의 입력 문맥 안에서 패턴을 파악한다. 따라서 새로운 지식이 가중치에 저장되는 Training은 아니지만, 문맥에 따라 수행 방식이 달라진다는 의미에서 Learning이라고 부른다.

> [!question]+ In-Context Learning은 왜 "학습"이라고 부르는가 — 실제로 파라미터가 업데이트되는가
> 
> 아니다. In-context learning 도중에는 **gradient 업데이트가 전혀 일어나지 않는다.** 모델의 가중치는 프롬프트를 읽는 동안 그대로 고정되어 있다.
> 
> 그런데도 "학습"이라 부르는 이유는, 사전학습 단계에서 모델이 **"패턴을 완성하는 능력" 자체를 미리 학습**해두었기 때문이다. 사전학습 코퍼스에는 "번역 예시가 나열된 글", "질문-답 형식의 글", "규칙을 보여준 뒤 적용하는 글" 같은 패턴이 방대하게 섞여 있고, 모델은 다음 단어 예측을 통해 "이런 패턴 뒤에는 이런 종류의 답이 온다"는 것을 암묵적으로 체득한다.
> 
> 따라서 in-context learning은 추론 중 가중치를 갱신하는 방식이 아니다. 사전학습으로 형성된 패턴 처리 능력을 현재 프롬프트의 예시와 지시에 맞게 조건화하여 사용하는 방식이다.

#### Zero-shot / One-shot / Few-shot

- 셋 모두 **gradient 업데이트 없이**, 프롬프트에 태스크 설명(task description)과 예시를 얼마나 포함하는지에 따라 구분됨

|구분|설명|예시(`Translate English to French:`)|
|---|---|---|
|**Zero-shot**|태스크 설명만 주고 바로 예측|`cheese =>`|
|**One-shot**|태스크 설명 + 예시 1개|`sea otter => loutre de mer` 이후 `cheese =>`|
|**Few-shot**|태스크 설명 + 예시 여러 개|`sea otter=>..., peppermint=>..., plush girafe=>...` 이후 `cheese =>`|

#### 파라미터 크기 및 shot 수에 따른 성능

In-Context Learning은 모델이 커질수록 강하게 나타났으며 175B, 13B, 1.3B 순으로 zero-shot·one-shot·few-shot 성능 격차가 뚜렷했다. 같은 크기의 모델에서는 일반적으로 예시가 많을수록 성능이 높아져 **Zero-shot < One-shot < Few-shot**의 경향을 보였다. TriviaQA에서는 175B 모델의 few-shot 성능이 당시 Fine-tuned SOTA에 가까워졌다.

#### Chain-of-Thought(CoT) Prompting

In-Context Learning이 알려지면서 모델에 어떤 형식의 문맥을 제공하는지가 중요해졌다. 그러나 정답 예시만 제시하는 일반적인 Few-shot Prompting은 여러 계산 단계를 거쳐야 하는 문제에서 중간 과정을 생략하기 쉬웠다. 예를 들어 "민지는 4월에 친구 48명에게 연필을 팔았고, 5월에는 그 절반만큼 팔았다"는 문제를 풀려면 "절반 계산 → 두 값의 합"이라는 순서가 필요하다. **Chain-of-Thought(CoT) Prompting**은 예시의 답에 중간 풀이 과정을 포함하여, 모델도 새로운 문제에서 단계를 생성한 뒤 최종 답을 내도록 유도한다.

- **Standard prompting vs CoT prompting 비교**: 예시(few-shot)의 답을 어떻게 구성하느냐가 핵심 차이
    - Standard prompting: 예시의 답을 결과만 제시(`A: The answer is 11.`) → 새 문제에 적용 시 중간 계산을 생략하고 바로 답을 내다 오답(27) 발생
    - CoT prompting: 예시의 답에 **풀이 과정을 포함**(`Roger started with 5 balls. 2 cans of 3 tennis balls is 6. 5+6=11.`) → 모델이 이 패턴을 그대로 따라가며 새 문제도 단계별로 풀어 정답(9) 도출
- **성능**: 제시된 다단계 추론 벤치마크에서는 CoT prompting이 standard prompting보다 높은 성능을 보였으며, 일부 fine-tuning 기반 결과도 넘어섰다.
    - GSM8K(수학 문제) 기준: Fine-tuned GPT-3 175B(33%) < Prior best(55%) < PaLM 540B standard prompting(18%, 오히려 가장 낮음) < **PaLM 540B CoT prompting(57%, 최고)**

#### Zero-Shot Chain-of-Thought Prompting

기존 CoT는 풀이 과정이 포함된 Few-shot 예시를 직접 준비해야 했다. Zero-Shot CoT는 질문 뒤에 **`Let's think step by step`**을 추가하여 별도의 예시 없이도 모델이 중간 단계를 생성하도록 유도한다.

- 예: "저글러가 공 16개를 저글링할 수 있고, 그중 절반이 골프공, 골프공 중 절반이 파란색이면 파란 골프공은 몇 개인가?" + `Let's think step by step.` → 모델이 스스로 "16개 중 절반은 골프공(8개), 그중 절반은 파란색(4개)"이라는 단계를 생성하며 정답 도출
- **성능**: Zero-Shot CoT prompting을 통해, 별도의 예시 없이도 Few-Shot CoT에 견줄 만한 성능을 달성
    - Zero-Shot(17.7/10.4, MultiArith/GSM8K) → **Zero-Shot-CoT(78.7/40.7)**로 큰 폭 향상, Few-Shot-CoT(93.0/48.7) 수준에 근접
    - PaLM 540B 기준, Zero-Shot-CoT에 **self-consistency**(같은 문제를 여러 번 생성해 다수결로 답을 정함)를 결합하면 89.0/70.1까지 향상되어 표 안에서 가장 높은 성능을 기록

> [!summary] 전체 흐름 정리
>
> 1. **Word Embedding**은 단어를 의미 관계가 반영된 벡터로 표현하지만, 문장 안의 순서와 가변 길이를 직접 처리하지 않는다.
> 2. **RNN**은 이전 hidden state를 다음 시점으로 전달해 순서를 모델링하지만, 긴 경로에서 기울기 소실과 병렬화 제약이 발생한다.
> 3. **LSTM**은 cell state와 gate를 도입해 장기 정보 전달을 개선했지만, 순차 계산 구조는 그대로 유지된다.
> 4. **Seq2Seq**는 Encoder와 Decoder로 길이가 다른 시퀀스를 변환하지만, 입력 전체를 고정 벡터 하나로 압축하는 병목이 있다.
> 5. **Attention**은 Decoder가 Encoder의 모든 상태를 시점마다 가중합하게 하여 병목과 장거리 정보 전달 문제를 완화한다.
> 6. **Self-Attention**은 같은 시퀀스의 모든 토큰을 직접 연결하고, **Transformer**는 이를 중심으로 순환 구조를 제거해 병렬 학습을 가능하게 한다.
> 7. **BERT·T5·GPT**는 Transformer의 Encoder, Encoder-Decoder, Decoder 구조를 각각 사전학습하여 이해·변환·생성 태스크에 특화된 흐름을 형성했다.
> 8. 모델 규모와 사전학습 데이터가 커지면서 **In-Context Learning**이 두드러졌고, **CoT prompting**은 중간 풀이 단계를 유도해 다단계 추론 성능을 높였다.
>
> 핵심 변화는 정보를 표현하는 방법에서 시작해, **순서 전달 → 장기 기억 → 선택적 참조 → 전역 상호작용 → 대규모 사전학습과 프롬프트 기반 수행**으로 확장된 것이다.

자연어 처리 모델의 발전은 단순히 모델의 크기가 커진 과정이 아니다. 단어를 어떻게 표현할지에서 시작해, 문맥을 어떻게 전달하고 오래 보존할지, 필요한 정보를 어떻게 선택하며 모든 토큰을 어떻게 직접 연결할지에 대한 구조적 변화가 먼저 있었다. Transformer는 이 흐름을 대규모 사전학습과 결합했고, 그 결과 하나의 모델이 여러 태스크에 적응하거나 프롬프트의 문맥만으로 수행 방식을 바꾸는 단계까지 확장되었다.
